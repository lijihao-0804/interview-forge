# 给同一个改动选合适的 AI 编程方式

## 从光标旁的一行开始

假设你在维护排班系统，想把连续的值班日期合并成区间。函数签名、日期类型和排序规则已经写好，光标旁还放着一组输入输出。代码补全适合接着写循环。每接受一段，读一下它在哪里结束当前区间，再拿周五和下周一试一次。是否跨过周末也算连续，得由排班规则决定。

如果团队还在讨论区间该用闭区间还是半开区间，可以换成对话。让模型给两种表示法各举一个相邻区间的例子，你来判断哪种更容易和日历组件对接。此时即便一个文件都没改，也已经解决了具体的设计问题。

## 什么时候交给 Agent

等到需求变成“在导出报表里也显示连续区间”，就涉及页面、导出器和测试。给 Agent 一份简短的验收样例，让它从页面一路找到报表入口，复用已有的合并函数，运行两处测试。你最后检查界面与导出的日期是否一致，以及改动是否意外影响单日值班。

面试官如果问为什么不用 Agent 做第一步，可以谈反馈成本。一个小循环看完十行就能决定是否接受；跨文件任务则需要持续搜索、修改和运行程序，允许工具读取仓库、执行测试才真正省下往返。
