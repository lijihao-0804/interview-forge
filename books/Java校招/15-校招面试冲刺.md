周期口径：常规 3~4 周；压缩到 2 周时砍掉第 4 周扫尾，自测与项目并行。

### 0.1 时间分配

| 阶段 | 重点 | 产出 |

### 0.2 冲刺原则

- **二八法则**：高频八股（并发、JVM、MySQL、Redis、Spring、MQ、分布式）占 80% 面试，先保它们；
- **手写能力**：单例、线程池、LRU、生产者消费者、TopK 要能白板写；
- **项目是锚点**：每个八股都尽量往项目上挂，答“我在项目里怎么做的”比背定义加分；
- **复盘闭环**：每次模拟面试后记下卡壳点，第二天优先补。

## 2. 项目总结与简历

### 2.1 STAR 叙事法

```text
S 情境：项目背景与业务目标（为什么做）
T 任务：我负责的部分
A 行动：我怎么做（技术选型、方案设计、踩坑解决）
R 结果：量化产出（QPS、延迟、可用性、代码量）
```

反面例子：我做了个商城，用了 Spring Boot 和 Redis。  
正面例子：秒杀模块上线后瞬时 QPS 5000，我负责库存扣减：先用 Redis Lua 原子预扣 + MQ 异步落库，把 DB 写压力降到 200 QPS，超卖率从 0.5% 降到 0。

### 2.2 项目常见追问

- 为什么选这个技术而不是另一个？（对比要能说出来）
- 这个方案的瓶颈在哪？流量再翻十倍怎么改？
- 出过什么问题？怎么排查解决的？（讲真实踩坑）
- 数据一致性怎么保证？失败怎么补偿？
- 整个请求从进入到返回经过哪些组件？（画链路）

### 2.3 简历要点

- 每个项目写“背景 + 我的职责 + 技术亮点 + 量化结果”四行内讲清；
- 技术栈按熟练度分档，别把“看过文档”写成“精通”；
- 把项目与八股挂钩：项目里用了线程池，就准备线程池七参数；用了 Redis，就准备缓存一致性。

### 2.4 面试追问

- 问：你项目里最有挑战的问题？
- 答：选一个真实问题，按 STAR 讲：现象 → 定位过程 → 方案 → 结果，突出排查思路。
- 问：项目上线后出过线上问题吗？
- 答：诚实讲一次故障（如慢 SQL、缓存雪崩），重点在复盘和后续防护。

## 3. 系统设计题套路

### 3.1 答题框架

```text
1. 明确需求：功能、规模（QPS、数据量）、非功能（一致性、可用性）
2. 容量估算：QPS、存储、带宽，粗略数量级即可
3. 架构分层：客户端 → 网关 → 业务服务 → 存储（DB/缓存/MQ）
4. 核心链路：把一次请求完整走一遍
5. 关键点：缓存、MQ、分库分表、幂等、限流、高可用
6. 扩展演进：流量再大怎么扩容、哪些是瓶颈
```

### 3.2 母题一：秒杀（见《微服务与高并发》）

静态化 + 限流 → Redis 预热 + Lua 预扣 → MQ 异步 → DB 条件更新 → 隔离降级 → 对账。

### 3.3 母题二：短链系统

```text
需求：长链转短链，跳转还原；估算：亿级条目、千级 QPS
方案：发号器（号段/自增优先）生成唯一 ID → base62 编码成短码
存储：短码 → 长链映射表（MySQL + Redis 缓存）
跳转：一般用 302（301 会被浏览器/代理缓存，改映射不生效、统计失真），命中缓存直接跳
扩展：多机房发号分段，防止 ID 冲突；布隆过滤器挡无效码回源；短码过期清理
```

**关键技术矛盾**：雪花 ID 是 64 位，base62 编码后约 10~11 位，达不到行业惯例的 6~8 位；而亿级条目用 6~7 位 base62 就够（62⁶ ≈ 5.7×10¹⁰），所以主流是**号段/自增发号 → base62**，雪花留给需要趋势递增的分布式场景。

### 3.4 母题三：IM 聊天

```text
需求：单聊/群聊、消息收发、历史记录
方案：长连接（WebSocket）保在线；消息先落库/发 MQ
读扩散 vs 写扩散：群聊小群写扩散（每人一份）、大群读扩散（拉取最新）
历史记录：MySQL 分库或消息存储；未读数用 Redis 计数
可靠性：消息带 seq 去重；离线消息上线拉取
```

### 3.5 面试追问

- 问：设计题从哪开始？
- 答：先确认需求和量级，再画分层架构，最后讲关键点和扩展。
- 问：容量估算没数据怎么办？
- 答：说数量级即可：1 万日活 × 每人 10 次 = 10 万次/天，平均约 1~2 QPS；若假定**绝大部分流量（约九成）集中在 1% 时段**，峰值约 100~200 QPS（要说明这个集中假设；若只集中 10%，峰值只有约 10~20 QPS）。

## 4. 模拟面试问答

### 4.1 技术面高频

- 问：线程池核心线程数怎么定？
- 答：CPU 密集约 CPU 核数 +1；IO 密集约 核数 × (1 + 等待/计算)，等待占 90% 时约核数 × 10；还要看队列策略与拒绝策略，最终压测校准。
- 问：缓存和数据库一致性怎么保证？
- 答：Cache Aside 先更库再删缓存；延迟双删（先删缓存 → 更新 DB → 延迟 → 再删）缩窗口；Canal 订阅 binlog 最终一致；强一致不加缓存或锁串行。
- 问：MQ 消息丢了怎么办？
- 答：分三段排查：生产 confirm、Broker 副本持久化、消费手动 ACK；加上死信与对账。
- 问：HashMap 1.8 和 1.7 区别？
- 答：头插改尾插防死循环、数组+链表改数组+链表+红黑树、扩容优化。
- 问：MySQL 索引失效场景？
- 答：函数/隐式转换、最左前缀不满足、%前缀模糊、or 连接非索引列、范围后列失效。

### 4.2 HR 面高频

- 问：为什么选我们公司/这个岗位？
- 答：结合业务方向与自己的技术兴趣（提前看公司技术博客、招聘 JD），不要只说“平台大”。
- 问：期望薪资？
- 答：给区间并说明依据（城市、岗位、自身能力），表示可谈。
- 问：最快到岗时间？
- 答：真实情况 + 说明可协调，别为了过面乱承诺。
- 问：你最大的缺点？
- 答：说真实但不致命的问题 + 正在改进的方法（如“算法题不够稳，每天刷两道”）。

### 4.3 反问环节

- 团队主要技术栈和业务方向？
- 新人培养/导师机制？
- 这个岗位日常主要做什么、考核什么？
