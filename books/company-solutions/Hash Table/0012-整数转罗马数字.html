12. 整数转罗马数字

难度中等核心模式贪心匹配罗马数值表（含减法形式）时间复杂度O(1)空间复杂度O(1)

题目与约束

七个不同的符号代表罗马数字，其值如下：

        符号
        值

        I
        1

        V
        5

        X
        10

        L
        50

        C
        100

        D
        500

        M
        1000

罗马数字是通过添加从最高到最低的小数位值的转换而形成的。将小数位值转换为罗马数字有以下规则：

  • 如果该值不是以 4 或 9 开头，请选择可以从输入中减去的最大值的符号，将该符号附加到结果，减去其值，然后将其余部分转换为罗马数字。

  • 如果该值以 4 或 9 开头，使用 减法形式，表示从以下符号中减去一个符号，例如 4 是 5 (V) 减 1 (I): IV ，9 是 10 (X) 减 1 (I)：IX。仅使用以下减法形式：4 (IV)，9 (IX)，40 (XL)，90 (XC)，400 (CD) 和 900 (CM)。

  • 只有 10 的次方（I, X, C, M）最多可以连续附加 3 次以代表 10 的倍数。你不能多次附加 5 (V)，50 (L) 或 500 (D)。如果需要将符号附加4次，请使用 减法形式。

给定一个整数，将其转换为罗马数字。

示例 1：

输入：num = 3749

输出： "MMMDCCXLIX"

解释：

3000 = MMM 由于 1000 (M) + 1000 (M) + 1000 (M)
 700 = DCC 由于 500 (D) + 100 (C) + 100 (C)
  40 = XL 由于 50 (L) 减 10 (X)
   9 = IX 由于 10 (X) 减 1 (I)
注意：49 不是 50 (L) 减 1 (I) 因为转换是基于小数位

示例 2：

输入：num = 58

输出："LVIII"

解释：

50 = L
 8 = VIII

示例 3：

输入：num = 1994

输出："MCMXCIV"

解释：

1000 = M
 900 = CM
  90 = XC
   4 = IV

提示：

  • 1 <= num <= 3999

核心不变量

把 13 个"数值-符号"（7 个基本符号 + 6 个减法组合）严格按数值降序排成表，每次贪心地取不超过 num 的最大值，追加符号并减去该值，直到 num 归零。

完整推导

思路推导

  1. 直觉与痛点（按位硬编码太脆）

罗马数字是"每位独立转换"的：千位、百位、十位、个位各查一张表。硬编码四张表（如个位 {"", "I", "II", "III", "IV", "V", "VI", "VII", "VIII", "IX"}）也能做，但要写四套分支，稍不留神就漏掉 IV、IX、XL、XC、CD、CM 这些减法特例。

  1. 破局思路（统一的贪心表）

把所有可能用到的原子片段按从大到小排成一张表：

1000=M, 900=CM, 500=D, 400=CD, 100=C, 90=XC, 50=L, 40=XL, 10=X, 9=IX, 5=V, 4=IV, 1=I

然后从大到小扫描：只要 num >= value，就追加对应 symbol 并 num -= value，同一档可能重复多次（如 3000 会连续追加三个 M）。因为表里已经"预先内置"了所有减法组合（CM/CD/XC/XL/IX/IV），贪心永远正确，不需要任何特判。

以 num = 3749 为例：先减 3 次 1000 得 MMM、num=749；再减 700 得 DCC、num=49；减 40 得 XL、num=9；减 9 得 IX、num=0，拼出 MMMDCCXLIX。

  1. 关键追问（为什么贪心不会错？）

罗马数字的表示是"规范且唯一"的，且每个较大单位都严格大于所有更小单位之和的"可表示上界"。表按降序排列后，先用大单位能保证位数正确，且减法组合已作为独立条目存在，不存在"先用大单位导致后面无法表示"的冲突，所以贪心即最优。

Java 实现（intToRoman）

class Solution {
    public String intToRoman(int num) {
        // 数值与符号严格降序；6 个减法形式已内置于表中
        int[] values = {1000, 900, 500, 400, 100, 90, 50, 40, 10, 9, 5, 4, 1};
        String[] symbols = {"M", "CM", "D", "CD", "C", "XC", "L", "XL", "X", "IX", "V", "IV", "I"};

        StringBuilder sb = new StringBuilder();
        for (int i = 0; i < values.length; i++) {
            // 同一档可以重复使用（例如 3000 = MMM）
            while (num >= values[i]) {
                sb.append(symbols[i]);
                num -= values[i];
            }
        }
        return sb.toString();
    }
}

C++ 实现

#include <string>
#include <vector>
using namespace std;

class Solution {
public:
    string intToRoman(int num) {
        vector<int> values = {1000, 900, 500, 400, 100, 90, 50, 40, 10, 9, 5, 4, 1};
        vector<string> symbols = {"M", "CM", "D", "CD", "C", "XC", "L", "XL", "X", "IX", "V", "IV", "I"};

        string res;
        for (int i = 0; i < (int)values.size(); i++) {
            // 同一档可重复使用
            while (num >= values[i]) {
                res += symbols[i];
                num -= values[i];
            }
        }
        return res;
    }
};

Python 实现

class Solution:
    def intToRoman(self, num: int) -> str:
        values = [1000, 900, 500, 400, 100, 90, 50, 40, 10, 9, 5, 4, 1]
        symbols = ["M", "CM", "D", "CD", "C", "XC", "L", "XL", "X", "IX", "V", "IV", "I"]

        res = []
        for value, symbol in zip(values, symbols):
            # 同一档可重复使用
            while num >= value:
                res.append(symbol)
                num -= value
        return "".join(res)

复杂度

  • 时间：O(1)。num <= 3999，表的长度固定为 13，循环次数有常数上界（最多几十次）。
  • 空间：O(1)。除输出字符串外只用了固定长度的两张表。
易错点与扩展（面试高频考点）
  1. 表里必须包含 6 个减法形式：缺了 IV 就会把 4 写成 IIII，缺了 CM 就把 900 写错。
  2. 表必须严格降序：顺序一旦乱掉，贪心就不再成立。
  3. while 而非 if：同一档要能重复多次（3000 = MMM、80 = LXXX），用 if 会少写。
  4. 范围约束 1 <= num <= 3999：不必处理 4000 及以上（那需要符号上加横线的扩展记法）。
  5. 对比"逐位查表"写法：逐位写法要维护四张子表、代码长且易错；统一贪心表更短更稳，面试中更推荐。
