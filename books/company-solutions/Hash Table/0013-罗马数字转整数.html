13. 罗马数字转整数

本次复习：
按 M 快速切换薄弱标记
遮住推导与代码，先自己想，再逐段揭示
难度简单核心模式相邻比较，小值在左则减时间复杂度O(n)空间复杂度O(1)

题目与约束

罗马数字包含以下七种字符: I， V， X， L，C，D 和 M。

字符          数值
I             1
V             5
X             10
L             50
C             100
D             500
M             1000

例如， 罗马数字 2 写做 II ，即为两个并列的 1 。12 写做 XII ，即为 X + II 。 27 写做 XXVII, 即为 XX + V + II 。

通常情况下，罗马数字中小的数字在大的数字的右边。但也存在特例，例如 4 不写做 IIII，而是 IV。数字 1 在数字 5 的左边，所表示的数等于大数 5 减小数 1 得到的数值 4 。同样地，数字 9 表示为 IX。这个特殊的规则只适用于以下六种情况：

  • I 可以放在 V (5) 和 X (10) 的左边，来表示 4 和 9。

  • X 可以放在 L (50) 和 C (100) 的左边，来表示 40 和 90。

  • C 可以放在 D (500) 和 M (1000) 的左边，来表示 400 和 900。

给定一个罗马数字，将其转换成整数。

示例 1:

输入: s = "III"
输出: 3

示例 2:

输入: s = "IV"
输出: 4

示例 3:

输入: s = "IX"
输出: 9

示例 4:

输入: s = "LVIII"
输出: 58
解释: L = 50, V= 5, III = 3.

示例 5:

输入: s = "MCMXCIV"
输出: 1994
解释: M = 1000, CM = 900, XC = 90, IV = 4.

提示：

  • 1 <= s.length <= 15

  • s 仅含字符 ('I', 'V', 'X', 'L', 'C', 'D', 'M')

  • 题目数据保证 s 是一个有效的罗马数字，且表示整数在范围 [1, 3999] 内

  • 题目所给测试用例皆符合罗马数字书写规则，不会出现跨位等情况。

  • IL 和 IM 这样的例子并不符合题目要求，49 应该写作 XLIX，999 应该写作 CMXCIX 。

  • 关于罗马数字的详尽书写规则，可以参考 罗马数字 - 百度百科。

核心不变量

从左往右扫描时，若当前字符代表的值小于它右边字符的值，则这一位应当做减法，否则做加法。

完整推导

思路推导

  1. 直觉与痛点（为什么不能简单地把字符值全加起来？）

如果把每个字符直接翻译成数值再求和，IV 会算成 1 + 5 = 6，而正确答案是 4。问题出在"小值在左"的减法特例上：IV、IX、XL、XC、CD、CM 这六种组合，实际含义是"大数减小数"。

痛点：如何在不建立六大特例映射表的情况下，统一处理加法与减法？

  1. 破局思路（用"看右边一位"替代枚举特例）

观察规律：所谓减法组合，本质就是当前字符的值比紧随其后的字符小。于是只要在扫描时多看一眼右边：

  • 若 value(s[i]) < value(s[i+1])，说明 s[i] 是被减的小数，本轮就减去 value(s[i])；
  • 否则 s[i] 是正常的大数位，本轮加上 value(s[i])；
  • 最后一个字符没有右边，直接加上即可。

以 MCMXCIV 为例：M(1000) 加、C(100) 因为 < M 减、M(1000) 加、X(10) 因为 < C 减、C(100) 加、I(1) 因为 < V 减、V(5) 加，合计 1000-100+1000-10+100-1+5 = 1994，完全正确。

  1. 关键追问（边界与写法）
  • 最后一个字符不能越界取 s[i+1]，循环只走到 n-2，末尾单独加。
  • 也可写成"预存前一个值"的滚动写法：用 pre 记住上一位，遇到更小的当前位就把 pre 记为减项。两种写法等价，滚动版可省一次 charAt。
  • 题目保证输入合法，因此不必校验非法字符，但 getValue 用 switch 返回 0 兜底是好习惯。

Java 实现（相邻比较法）

class Solution {
    public int romanToInt(String s) {
        int sum = 0;
        int n = s.length();
        // 从前往后扫描，每次比较当前字符与右邻字符
        for (int i = 0; i < n; i++) {
            int cur = value(s.charAt(i));
            // 只要右边还有字符，且当前值更小，就做减法
            if (i + 1 < n && cur < value(s.charAt(i + 1))) {
                sum -= cur;
            } else {
                sum += cur; // 否则正常做加法
            }
        }
        return sum;
    }

    // 字符到数值的映射
    private int value(char c) {
        switch (c) {
            case 'I': return 1;
            case 'V': return 5;
            case 'X': return 10;
            case 'L': return 50;
            case 'C': return 100;
            case 'D': return 500;
            case 'M': return 1000;
            default:  return 0;
        }
    }
}

C++ 实现

#include <string>
#include <unordered_map>
using namespace std;

class Solution {
public:
    int romanToInt(string s) {
        unordered_map<char, int> mp = {
            {'I', 1}, {'V', 5}, {'X', 10}, {'L', 50},
            {'C', 100}, {'D', 500}, {'M', 1000}
        };
        int sum = 0;
        int n = s.size();
        for (int i = 0; i < n; i++) {
            int cur = mp[s[i]];
            // 右边还有字符且当前值更小，则减
            if (i + 1 < n && cur < mp[s[i + 1]]) {
                sum -= cur;
            } else {
                sum += cur;
            }
        }
        return sum;
    }
};

Python 实现

class Solution:
    def romanToInt(self, s: str) -> int:
        values = {'I': 1, 'V': 5, 'X': 10, 'L': 50,
                  'C': 100, 'D': 500, 'M': 1000}
        total = 0
        for i, ch in enumerate(s):
            cur = values[ch]
            # 右边还有字符且当前值更小，则减；否则加
            if i + 1 < len(s) and cur < values[s[i + 1]]:
                total -= cur
            else:
                total += cur
        return total

复杂度

  • 时间：O(n)，其中 n = s.length()。每个字符只被访问常数次（自身与右邻各一次），总操作数与长度成正比。
  • 空间：O(1)。只用到几个整型变量与固定的字符映射，与输入规模无关。
易错点与扩展（面试高频考点）
  1. 把减法写成"遇到 IV/IX 就特殊判断"：这样要枚举六种组合，容易漏，且难以推广。用"右邻更大则减"一条规则即可覆盖全部特例。
  2. 最后一个字符越界：s[i+1] 在 i = n-1 时必须先判 i + 1 < n，否则数组越界。
  3. 误判加减方向：记住是"小数在左 → 减"，判断条件是 cur < 右邻，不要把不等号写反。
  4. 面试追问——反向题：把整数转成罗马数字（LeetCode 12）需要从大到小贪心匹配面值（含 900/400/90/40/9/4 特殊面值），思路正好相反，可与本题对照记忆。
  5. 映射表 vs switch：哈希表写法更通用，本题字符少且固定，switch 无哈希开销、更快，是更贴合面试现场的选择。
