# 570. 至少有5名直接下属的经理

| 题目信息 | 内容 |
|---|---|
| 难度 | 中等 |
| 核心模式 | 按 managerId 分组计数 + HAVING 过滤 |
| 时间复杂度 | O(n) |
| 空间复杂度 | O(m) |

## 题目与约束

表 `Employee`：

```
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| id          | int     |
| name        | varchar |
| department  | varchar |
| managerId   | int     |
+-------------+---------+
```

- `id` 是此表的主键（具有唯一值的列）。
- 该表的每一行表示雇员的名字、他们的部门和他们的经理的 `id`。
- 如果 `managerId` 为空，则该员工没有经理。
- 没有员工会成为自己的管理者。

编写一个解决方案，找出至少有**五个直接下属**的经理。以**任意顺序**返回结果表，查询结果格式如下所示。

**示例 1：**

```
输入:
Employee 表:
+-----+-------+------------+-----------+
| id  | name  | department | managerId |
+-----+-------+------------+-----------+
| 101 | John  | A          | Null      |
| 102 | Dan   | A          | 101       |
| 103 | James | A          | 101       |
| 104 | Amy   | A          | 101       |
| 105 | Anne  | A          | 101       |
| 106 | Ron   | B          | 101       |
+-----+-------+------------+-----------+
输出:
+------+
| name |
+------+
| John |
+------+
```

**提示：**

- `Employee` 中不包含重复的 `id`。
- 一个经理可以有零个或多个直接下属。
- 返回结果只用包含经理的 `name` 列。

## 核心不变量

> 某经理的**直接下属数** = 表中 `managerId` 等于其 `id` 的行数；该计数 ≥ 5 时，其 `name` 即为答案之一。

## 完整推导

### 思路推导

1. **看穿"直接下属"的含义**

   在 `Employee` 表里，每个员工一行，`managerId` 指向他的直属上级。因此"某个经理的直接下属"，就是所有 `managerId` 恰好等于该经理 `id` 的行。这是一个典型的一对多自引用关系。

2. **按经理分组数人数**

   把整张表按 `managerId` 分组，`COUNT(*)` 就是每个经理名下的直接下属数量。注意 `managerId` 为 `NULL` 的行（顶层老板）会在分组时被自动归入 `NULL` 组，不参与任何经理的统计，正好符合题意。

3. **只留下"≥ 5"的经理 id**

   分组后用 `HAVING COUNT(*) >= 5` 过滤，得到满足条件的经理 `id` 集合。这一步只产出 id，不是最终答案。

4. **回表把 id 换成 name**

   最终结果要求输出 `name`。用得到的一批经理 `id` 回查 `Employee`，取出对应 `name` 即可。写成子查询 `WHERE id IN (SELECT managerId ... HAVING ...)` 最直观。

   小例子：示例中 `managerId = 101` 的行有 102、103、104、105、106 共 5 行，故 101（John）入选；其余 `managerId` 均不足 5 行，输出只有 John。

### MySQL 实现（子查询 + GROUP BY + HAVING）

```sql
# Write your MySQL query statement below
SELECT name
FROM Employee
WHERE id IN (
    SELECT managerId
    FROM Employee
    GROUP BY managerId
    HAVING COUNT(*) >= 5
);
```

### 复杂度

- 时间：O(n)，n 为 `Employee` 行数；无论子查询的分组聚合还是外层回查，本质都是对表做常数次扫描 / 借助索引查找。
- 空间：O(m)，m 为不同 `managerId` 的数量，分组聚合需要维护这些分组键（哈希或排序结构）。

### 易错点与扩展（面试高频考点）

1. **结果要的是 `name` 不是 `id`**：`GROUP BY managerId` 后直接 `SELECT name` 在 `ONLY_FULL_GROUP_BY` 模式下会报错且语义不清，正确做法是先用子查询算出合格 `managerId`，再回表取 `name`。
2. **`COUNT(*)` 与 `COUNT(DISTINCT id)`**：由于 `id` 是主键、每行天然唯一，二者结果相同；若担心重复行可用 `COUNT(DISTINCT id)` 更稳妥。
3. **`NULL` 分组**：`managerId IS NULL` 的行不会被 `IN` 子查询匹配到，无需额外排除，但要理解它为何不影响答案。
4. **`>=` 与 `>` 的边界**：题目是"至少有 5 个"，必须用 `>= 5`，写成 `> 5` 会漏掉刚好 5 人的经理。
5. **自连接写法**：也可 `FROM Employee m JOIN Employee e ON e.managerId = m.id GROUP BY m.id, m.name HAVING COUNT(*) >= 5`，效果等价，面试可作对照展示。

## 力扣原题

[570. 至少有5名直接下属的经理](https://leetcode.cn/problems/managers-with-at-least-5-direct-reports/)

> 本题为数据库题，无算法语言实现；下面给出等价的 **Pandas** 与 **MS SQL Server（T-SQL）** 写法。

### Pandas 实现

```python
import pandas as pd


def find_managers(employee: pd.DataFrame) -> pd.DataFrame:
    # 统计每个 managerId 的直接下属数
    counts = employee.groupby("managerId").size().reset_index(name="cnt")
    # 保留下属数 >= 5 的经理 id
    qualified = counts.loc[counts["cnt"] >= 5, "managerId"]
    # 回表取这些经理的 name
    result = employee.loc[employee["id"].isin(qualified), ["name"]]
    return result
```

### MS SQL Server 实现

```sql
/* Write your T-SQL query statement below */

FROM Employee
WHERE id IN (
    SELECT managerId
    FROM Employee
    GROUP BY managerId
    HAVING COUNT(*) >= 5
);
```
