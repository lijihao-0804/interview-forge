# 292. Nim 游戏

| 题目信息 | 内容 |
|---|---|
| 难度 | 简单 |
| 核心模式 | 数学博弈（模 4 判断必败态） |
| 时间复杂度 | O(1) |
| 空间复杂度 | O(1) |

## 题目与约束

你和你的朋友，两个人一起玩 Nim 游戏：

- 桌子上有一堆石头。

- 你们轮流进行自己的回合， 你作为先手 。

- 每一回合，轮到的人拿掉 1 - 3 块石头。

- 拿掉最后一块石头的人就是获胜者。

假设你们每一步都是最优解。请编写一个函数，来判断你是否可以在给定石头数量为 `n` 的情况下赢得游戏。如果可以赢，返回 `true`；否则，返回 `false` 。

 

示例 1：

```
<strong>输入：</strong>n = 4
<strong>输出：</strong>false 
<strong>解释：</strong>以下是可能的结果:
1. 移除1颗石头。你的朋友移走了3块石头，包括最后一块。你的朋友赢了。
2. 移除2个石子。你的朋友移走2块石头，包括最后一块。你的朋友赢了。
3.你移走3颗石子。你的朋友移走了最后一块石头。你的朋友赢了。
在所有结果中，你的朋友是赢家。
```

示例 2：

```
<strong>输入：</strong>n = 1
<strong>输出：</strong>true
```

示例 3：

```
<strong>输入：</strong>n = 2
<strong>输出：</strong>true
```

 

提示：

- `1 <= n <= 231 - 1`

## 核心不变量

> `4` 的倍数是必败态：只要 `n % 4 == 0`，先手必输；否则先手必胜。

## 完整推导

### 思路推导

1. **直觉与痛点（能不能用 DP 模拟？）**

   可以按"剩余石子数"做博弈 DP，但 `n` 最大可达 `2^31 - 1`，根本开不出这么大的数组，DP 行不通。必须从规则里找出数学规律。

2. **关键观察（凑 4）**

   每回合可以拿 `1~3` 块。无论当前玩家拿几块，对手都可以把这一轮两人合计控制在 `4` 块：你拿 `x`，对手就拿 `4 - x`。

3. **必败态推导（4 的倍数）**

   若 `n` 是 `4` 的倍数，设你先拿 `x`（`1 ≤ x ≤ 3`），对手拿 `4 - x`，这一轮合计正好 `4`。于是每轮过后剩余仍是 `4` 的倍数，且不断减少。最终对手会把局面推到 `0`，也就是**对手拿走最后一块**，你必输。所以 `4` 的倍数对先手是必败态。

   若 `n` 不是 `4` 的倍数，你先拿 `n % 4` 块，把剩余的 `4` 的倍数丢给对手。此后对手拿 `x`，你就拿 `4 - x`，你总能把必败态留给他——最后一块由你拿走，你必胜。

4. **结论**

   `return n % 4 != 0;` 一行即可，`O(1)`。

### Java 实现（canWinNim）

```java
class Solution {
    public boolean canWinNim(int n) {
        // 只要不是 4 的倍数，先手必胜；4 的倍数必败
        return n % 4 != 0;
    }
}
```

### 复杂度

- 时间：`O(1)`，只做一次取模运算。
- 空间：`O(1)`，无额外空间。

### 易错点与扩展（面试高频考点）

1. **别用 DP / 模拟**：`n` 可达 `2^31 - 1`，必须直接推出模 4 的规律，`O(1)` 求解。
2. **方向别写反**：`n` 是 4 的倍数返回 `false`，否则返回 `true`。
3. **这是巴什博弈（Bash Game）特例**：每次可取 `1~m` 块时，必败态是 `(m + 1)` 的倍数；本题 `m = 3`，故必败态是 4 的倍数。
4. **先手优势**：只要初始不是必败态，先手总能一步把局面交给对手的必败态，因此非 4 倍数先手必胜。
5. **取模安全**：`n` 为正整数，`n % 4` 直接可用，无需特殊处理 `n = 0`（题目 `n ≥ 1`）。
