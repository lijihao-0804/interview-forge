题目信息 内容
难度 中等
核心模式 二分搜索定位长度为 k 的最优窗口左端点
时间复杂度 O(log(n-k) + k)
空间复杂度 O(k)

题目与约束

给定一个 排序好 的数组 arr ，两个整数 k 和 x ，从数组中找到最靠近 x（两数之差最小）的 k 个数。返回的结果必须要是按升序排好的。

整数 a 比整数 b 更接近 x 需要满足：

  • |a - x| < |b - x| 或者

  • |a - x| == |b - x| 且 a < b

示例 1：

<strong>输入：</strong>arr = [1,2,3,4,5], k = 4, x = 3
<strong>输出：</strong>[1,2,3,4]

示例 2：

<strong>输入：</strong>arr = [1,1,2,3,4,5], k = 4, x = -1
<strong>输出：</strong>[1,1,2,3]

提示：

  • 1 <= k <= arr.length

  • 1 <= arr.length <= 104

  • arr 按 升序 排列

  • -104 <= arr[i], x <= 104

核心不变量

答案一定是 arr 中一段长度为 k 的连续子数组（窗口），其左端点 lo 只在 [0, n-k] 范围内；比较窗口左端 arr[mid] 与右端外侧 arr[mid+k] 到 x 的距离，就能决定窗口该整体左移还是右移。

完整推导

思路推导

  1. 直觉（为什么是连续窗口）

arr 已排序，离 x 最近的 k 个数必然连成一片——不可能跳过中间某个元素去选更远的。因此答案是一段长度为 k 的连续子数组，问题变成"确认这段窗口的起点 lo"。

  1. 关键点（起点的取值范围）

窗口长度固定为 k，所以起点 lo ∈ [0, n-k]，共 n-k+1 个候选。暴力枚举每个窗口并比较边界，是 O(n)；我们可以用二分找最优 lo。

  1. 二分判据（谁被淘汰）

考虑候选起点 mid，窗口是 arr[mid .. mid+k-1]。此时窗口左端是 arr[mid]，右端再往外一格是 arr[mid+k]： - 若 x - arr[mid] > arr[mid+k] - x：左端离 x 更远，说明应该丢掉左端、窗口右移，令 lo = mid + 1； - 否则：右端更远或相等，窗口保留在左侧（相等时取更小的值，符合题目 a < b 规则），令 hi = mid。

不断收缩，最终 lo 就是最优窗口起点。

  1. 小例子（示例 1，arr = [1,2,3,4,5], k = 4, x = 3）

候选 lo ∈ [0, 1]。 - mid = 0：左端 arr[0]=1，右端外侧 arr[4]=5；3-1=2，5-3=2，相等 → hi = 0。 - 收缩后 lo = 0，窗口 arr[0..3] = [1,2,3,4]，即答案。

  1. 收尾（取出窗口）

得到 lo 后，把 arr[lo .. lo+k-1] 依次加入结果列表。因原数组有序，结果天然升序。

Java 实现（findClosestElements）

import java.util.ArrayList;
import java.util.List;

class Solution {
    public List<Integer> findClosestElements(int[] arr, int k, int x) {
        int lo = 0, hi = arr.length - k; // 窗口起点的可行区间，闭区间

        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;
            // 比较窗口左端 arr[mid] 与右端外侧 arr[mid+k] 到 x 的距离
            if (x - arr[mid] > arr[mid + k] - x) {
                lo = mid + 1; // 左端更远，窗口右移
            } else {
                hi = mid;     // 右端更远或相等，窗口左移/保留
            }
        }

        List<Integer> res = new ArrayList<>(k);
        for (int i = lo; i < lo + k; i++) {
            res.add(arr[i]);
        }
        return res;
    }
}

复杂度

  • 时间：O(log(n-k) + k)。二分在 n-k+1 个起点中定位，耗时 O(log(n-k))；最后顺序取 k 个元素 O(k)。
  • 空间：O(k)，额外空间只用于存放长度为 k 的结果列表（不计返回值则 O(1)）。

易错点与扩展（面试高频考点）

  1. 二分区间边界：起点范围是 [0, n-k] 的闭区间，hi = arr.length - k；若写成 arr.length - 1 或 arr.length 会越界或漏解。
  2. 判据方向：x - arr[mid] > arr[mid+k] - x 时窗口应右移（lo = mid + 1）；方向写反会导致结果偏移。
  3. 距离相等时向哪边：题目规定相等时取更小的值，所以 else 分支里 hi = mid 保留左侧窗口，不能反过来。
  4. 窗口右端下标：比较时用的是 arr[mid+k]（窗口外右侧一格），不是 arr[mid+k-1]，这是"淘汰边界"的关键。
  5. 其他解法：也可用双指针从数组两端向中间收缩，每次删掉离 x 更远的一端，直到剩 k 个，时间 O(n)；或用最大堆维护 k 个最近值 O(n log k)。二分写法在已排序前提下最优。

力扣原题

658. 找到 K 个最接近的元素

C++ 实现

class Solution {
public:
    vector<int> findClosestElements(vector<int>& arr, int k, int x) {
        int lo = 0, hi = (int)arr.size() - k; // 窗口起点闭区间 [0, n-k]

        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;
            // 左端比右端外侧更远 → 窗口右移
            if (x - arr[mid] > arr[mid + k] - x) {
                lo = mid + 1;
            } else {
                hi = mid;
            }
        }

        return vector<int>(arr.begin() + lo, arr.begin() + lo + k);
    }
};

Python 实现

class Solution:
    def findClosestElements(self, arr: List[int], k: int, x: int) -> List[int]:
        lo, hi = 0, len(arr) - k  # 窗口起点可行区间 [0, n-k]

        while lo < hi:
            mid = lo + (hi - lo) // 2
            # 左端比右端外侧更远 → 窗口右移
            if x - arr[mid] > arr[mid + k] - x:
                lo = mid + 1
            else:
                hi = mid

        return arr[lo:lo + k]
