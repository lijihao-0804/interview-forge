题目与约束

已知一个长度为 n 的数组，预先按照升序排列，经由 1 到 n 次 旋转 后，得到输入数组。例如，原数组 nums = [0,1,4,4,5,6,7] 在变化后可能得到：

  • 若旋转 4 次，则可以得到 [4,5,6,7,0,1,4]

  • 若旋转 7 次，则可以得到 [0,1,4,4,5,6,7]

注意，数组 [a[0], a[1], a[2], ..., a[n-1]] 旋转一次 的结果为数组 [a[n-1], a[0], a[1], a[2], ..., a[n-2]] 。

给你一个可能存在 重复 元素值的数组 nums ，它原来是一个升序排列的数组，并按上述情形进行了多次旋转。请你找出并返回数组中的 最小元素 。

你必须尽可能减少整个过程的操作步骤。

示例 1：

<strong>输入：</strong>nums = [1,3,5]
<strong>输出：</strong>1

示例 2：

<strong>输入：</strong>nums = [2,2,2,0,1]
<strong>输出：</strong>0

提示：

  • n == nums.length

  • 1 <= n <= 5000

  • -5000 <= nums[i] <= 5000

  • nums 原来是一个升序排序的数组，并进行了 1 至 n 次旋转

进阶：这道题与 寻找旋转排序数组中的最小值 类似，但 nums 可能包含重复元素。允许重复会影响算法的时间复杂度吗？会如何影响，为什么？

核心不变量

始终维护「最小值一定落在闭区间 [lo, hi] 内」；每轮让 nums[mid] 与右端点 nums[hi] 比较，相等时无法判断哪侧存在断层，只能 hi-- 保守收缩。

完整推导

思路推导

  1. 直觉与痛点（有重复，端点比较会失效）

不带重复的版本里，比较 nums[mid] 和 nums[hi]：若 nums[mid] > nums[hi]，说明最小值在右半段；否则在左半段（含 mid）。但一旦出现重复，比如 [2,2,2,0,1]，可能出现 nums[mid] == nums[hi]，此时无法判断最小值在左还是在右——这正是本题的难点，也是复杂度可能退化的根源。

  1. 破局思路（相等就砍掉一个右端点）

三路比较：

  • nums[mid] > nums[hi]：mid 及左侧都大于右端点，最小值只可能在 mid 右边，令 lo = mid + 1。
  • nums[mid] < nums[hi]：右半段是递增的，最小值在 mid 左侧（mid 本身也可能是最小值），令 hi = mid。
  • nums[mid] == nums[hi]：无法排除，但右端点 hi 与 mid 值相同，即便 hi 是最小值，mid 也能代表它，所以可以放心 hi--，只砍掉一个元素继续搜。

以 [2,2,2,0,1] 为例：lo=0, hi=4, mid=2，nums[2]=2 == nums[4]=1？不等，2 > 1，lo=3；再 mid=3，nums[3]=0 < nums[4]=1，hi=3；lo==hi 结束，返回 nums[3]=0。

  1. 为什么等号时能 hi--

因为 nums[hi] == nums[mid]，而 mid < hi。若最小值等于该值，则 mid 位置已经是这个最小值，丢掉 hi 不会丢答案；若最小值更小，那它必在 hi 左侧区间内，同样不该丢，丢弃 hi 也无损。所以 hi-- 是安全的。

Java 实现（三路二分）

class Solution {
    public int findMin(int[] nums) {
        int lo = 0, hi = nums.length - 1;

        // 区间收敛到只剩一个元素即为最小值
        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;

            if (nums[mid] > nums[hi]) {
                lo = mid + 1;      // 最小值在右半段
            } else if (nums[mid] < nums[hi]) {
                hi = mid;          // 最小值在左半段（含 mid）
            } else {
                hi--;              // 相等，无法判断，保守收缩一个元素
            }
        }
        return nums[lo];
    }
}

复杂度

  • 时间：平均 O(log n)，每轮区间减半。最坏 O(n)：当数组由大量相同元素构成（如 [2,2,2,2,0,2,2]），会频繁命中 nums[mid] == nums[hi]，每次只把 hi 减一，退化成线性扫描。
  • 空间：O(1)。只用了 lo、hi、mid 三个下标变量。

易错点与扩展（面试高频考点）

  1. 比较对象是右端点而不是左端点：习惯性写 nums[mid] 与 nums[lo] 比较在旋转数组里会出错，应固定与 nums[hi] 比较（或统一另一种等价框架）。
  2. hi = mid 而非 hi = mid - 1：当 nums[mid] < nums[hi] 时，mid 自身可能就是最小值，不能跳过它。
  3. 等号处理：nums[mid] == nums[hi] 时若误判成 hi = mid 或 lo = mid + 1 都可能漏掉最小值，正确做法是 hi--。
  4. 面试追问——重复元素对复杂度的影响：允许重复会让最坏情况退化为 O(n)，因为无法保证每轮稳定排除一半区间；这就是 153（无重复，严格 O(log n)）与 154 的核心区别。
  5. 边界与单元素：lo == hi 时循环结束直接返回，天然覆盖 n = 1 的情形，无需额外特判。

#include <vector>

class Solution {
public:
    int findMin(vector<int>& nums) {

            int mid = lo + (hi - lo) / 2;

            } else if (nums[mid] < nums[hi]) {
                hi = mid;          // 最小值在左侧（含 mid）
            } else {
                hi--;              // 相等，保守收缩
            }
        }

    }
};

Python 实现

class Solution:
    def findMin(self, nums: list[int]) -> int:
        lo, hi = 0, len(nums) - 1
        while lo < hi:
            mid = lo + (hi - lo) // 2
            if nums[mid] > nums[hi]:
                lo = mid + 1       # 最小值在右侧
            elif nums[mid] < nums[hi]:
                hi = mid           # 最小值在左侧（含 mid）
            else:
                hi -= 1            # 相等，保守收缩
