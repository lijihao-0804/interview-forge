# 81. 搜索旋转排序数组 II

| 题目信息 | 内容 |
|---|---|
| 难度 | 中等 |
| 核心模式 | 带重复的旋转数组二分查找 |
| 时间复杂度 | 平均 O(log n)，最坏 O(n) |
| 空间复杂度 | O(1) |

## 题目与约束

已知存在一个按非降序排列的整数数组 `nums` ，数组中的值不必互不相同。

在传递给函数之前，`nums` 在预先未知的某个下标 `k`（`0 <= k < nums.length`）上进行了**旋转**，使数组变为 `[nums[k], nums[k+1], ..., nums[n-1], nums[0], nums[1], ..., nums[k-1]]`（下标**从 0 开始**计数）。例如，`[0,1,2,4,4,4,5,6,6,7]` 在下标 `5` 处经旋转后可能变为 `[4,5,6,6,7,0,1,2,4,4]`。

给你**旋转后**的数组 `nums` 和一个整数 `target` ，请你编写一个函数来判断给定的目标值是否存在于数组中。如果 `nums` 中存在这个目标值 `target` ，则返回 `true` ，否则返回 `false` 。

你必须尽可能减少整个操作步骤。

**示例 1：**

```
输入：nums = [2,5,6,0,0,1,2], target = 0
输出：true
```

**示例 2：**

```
输入：nums = [2,5,6,0,0,1,2], target = 3
输出：false
```

**提示：**

- `1 <= nums.length <= 5000`
- `-10^4 <= nums[i] <= 10^4`
- 题目数据保证 `nums` 在预先未知的某个下标上进行了旋转
- `-10^4 <= target <= 10^4`

**进阶：**

- 此题与「搜索旋转排序数组」相似，但本题中的 `nums` 可能包含**重复**元素。这会影响到程序的时间复杂度吗？会有怎样的影响，为什么？

## 核心不变量

> 在任意时刻，`[left, right]` 这段区间要么整体有序，要么由两段各自有序的片段拼接而成；当 `nums[left] == nums[mid] == nums[right]` 时无法判断哪一半有序，只能两端同时内收一格再继续。

## 完整推导

### 思路推导

1. **直觉与痛点（能不能直接二分？）**

   旋转数组的特点是：取中点 `mid` 后，`[left, mid]` 与 `[mid, right]` 中**至少有一半是整体有序的**（因为整体只在一个位置"断开"）。只要找到有序的那一半，就能用普通的二分判断 `target` 是否落在它的值域里，从而决定丢掉哪一半。

2. **破局思路（先找有序半边，再判 target 落点）**

   比较 `nums[left]` 与 `nums[mid]`：

   - 若 `nums[left] <= nums[mid]`，说明**左半段 `[left, mid]` 有序**。此时若 `nums[left] <= target < nums[mid]`，目标必在左侧，`right = mid - 1`；否则去右侧 `left = mid + 1`。
   - 否则说明**右半段 `[mid, right]` 有序**。此时若 `nums[mid] < target <= nums[right]`，目标必在右侧，`left = mid + 1`；否则去左侧 `right = mid - 1`。

   以 `nums = [2,5,6,0,0,1,2], target = 0` 为例：`mid` 落在 `0` 附近时，判定左半有序、`0` 不在 `2..6` 区间，于是向右收缩，最终命中。

3. **关键追问（重复元素带来的"死结"）**

   当 `nums[left] == nums[mid] == nums[right]` 时（例如 `[1,1,1,1,1,1,1]` 这类全等段），既看不出左半是否有序，也看不出 `target` 在哪一边，只能保守地 `left++`、`right--`，把这两个"没法用"的端点扔掉。最坏情况下每个元素都要被这样淘汰一次，于是退化为 `O(n)`——这正是本题相对「搜索旋转排序数组」在复杂度上的差异。

4. **边界收尾**

   循环条件用 `left <= right`，一旦 `nums[mid] == target` 立即返回 `true`；循环结束仍未命中则返回 `false`。

### Java 实现（二分查找）

```java
class Solution {
    public boolean search(int[] nums, int target) {
        int left = 0, right = nums.length - 1;
        while (left <= right) {
            int mid = left + (right - left) / 2;
            if (nums[mid] == target) {
                return true; // 命中直接返回
            }
            // 三端点相等，无法判断哪一半有序，只能两端收缩
            if (nums[left] == nums[mid] && nums[mid] == nums[right]) {
                left++;
                right--;
            } else if (nums[left] <= nums[mid]) {
                // 左半段 [left, mid] 有序
                if (nums[left] <= target && target < nums[mid]) {
                    right = mid - 1;
                } else {
                    left = mid + 1;
                }
            } else {
                // 右半段 [mid, right] 有序
                if (nums[mid] < target && target <= nums[right]) {
                    left = mid + 1;
                } else {
                    right = mid - 1;
                }
            }
        }
        return false;
    }
}
```

### 复杂度

- 时间：平均 `O(log n)`，最坏 `O(n)`。正常情况下每次折半；但当大量重复元素使得三端点相等时，只能一格一格收缩，最坏退化为线性扫描。
- 空间：`O(1)`。只使用了 `left`、`right`、`mid` 三个下标变量，原地处理。

### 易错点与扩展（面试高频考点）

1. **忘记处理 `nums[left] == nums[mid] == nums[right]`**：这是本题与「搜索旋转排序数组」的核心区别，漏掉会导致在重复元素上判断错方向、死循环或漏解。
2. **有序半边的区间判断写成闭区间**：`target < nums[mid]` 与 `target <= nums[right]` 的开闭不能弄反，`nums[mid]` 已经在前面判过不相等，故可取严格边界，能少一次冗余比较。
3. **误以为复杂度仍是 `O(log n)`**：面试官常用进阶追问考察——重复元素使最坏情况退化为 `O(n)`，原因就是无法二分、只能逐个剔除。
4. **用 `left <= right` 还是 `left < right`**：本题在循环体内判断 `nums[mid] == target`，用闭区间 `left <= right` 更直观，注意收缩时 `mid±1` 避免死循环。
5. **扩展**：若数组无重复（LeetCode 33），可去掉三端点相等的分支，稳定做到 `O(log n)`；两者代码骨架完全一致，只差这一处退化处理。

## 力扣原题

[81. 搜索旋转排序数组 II](https://leetcode.cn/problems/search-in-rotated-sorted-array-ii/)

### C++ 实现

```cpp
#include <vector>
using namespace std;

class Solution {
public:
    bool search(vector<int>& nums, int target) {
        int left = 0, right = (int)nums.size() - 1;
        while (left <= right) {
            int mid = left + (right - left) / 2;
            if (nums[mid] == target) {
                return true;
            }
            // 三端点相等，无法判断哪半有序，两端收缩
            if (nums[left] == nums[mid] && nums[mid] == nums[right]) {
                left++;
                right--;
            } else if (nums[left] <= nums[mid]) {
                // 左半段有序
                if (nums[left] <= target && target < nums[mid]) {
                    right = mid - 1;
                } else {
                    left = mid + 1;
                }
            } else {
                // 右半段有序
                if (nums[mid] < target && target <= nums[right]) {
                    left = mid + 1;
                } else {
                    right = mid - 1;
                }
            }
        }
        return false;
    }
};
```

### Python 实现

```python
class Solution:
    def search(self, nums: list[int], target: int) -> bool:
        left, right = 0, len(nums) - 1
        while left <= right:
            mid = (left + right) // 2
            if nums[mid] == target:
                return True
            # 三端点相等，无法判断哪半有序，两端收缩
            if nums[left] == nums[mid] == nums[right]:
                left += 1
                right -= 1
            elif nums[left] <= nums[mid]:
                # 左半段有序
                if nums[left] <= target < nums[mid]:
                    right = mid - 1
                else:
                    left = mid + 1
            else:
                # 右半段有序
                if nums[mid] < target <= nums[right]:
                    left = mid + 1
                else:
                    right = mid - 1
        return False
```
