523. 连续的子数组和

本题学习状态正在读取学习记录…下次复习：—
本次复习：
按 M 快速切换薄弱标记
遮住推导与代码，先自己想，再逐段揭示
难度中等核心模式前缀和同余 + 哈希表（抽屉原理）时间复杂度O(n)空间复杂度O(min(n, k))

题目与约束

给你一个整数数组 nums 和一个整数 k ，如果 nums 有一个 好的子数组 返回 true ，否则返回 false：

一个 好的子数组 是：

  • 长度 至少为 2 ，且

  • 子数组元素总和为 k 的倍数。

注意：

  • 子数组 是数组中 连续 的部分。

  • 如果存在一个整数 n ，令整数 x 符合 x = n * k ，则称 x 是 k 的一个倍数。0 始终 视为 k 的一个倍数。

示例 1：

输入：nums = [23,2,4,6,7], k = 6
输出：true
解释：[2,4] 是一个大小为 2 的子数组，并且和为 6 。

示例 2：

输入：nums = [23,2,6,4,7], k = 6
输出：true
解释：[23, 2, 6, 4, 7] 是大小为 5 的子数组，并且和为 42 。
42 是 6 的倍数，因为 42 = 7 * 6 且 7 是一个整数。

示例 3：

输入：nums = [23,2,6,4,7], k = 13
输出：false

提示：

  • 1 <= nums.length <= 105

  • 0 <= nums[i] <= 109

  • 0 <= sum(nums[i]) <= 231 - 1

  • 1 <= k <= 231 - 1

核心不变量

若两个前缀和对 k 取余的结果相同，则它们之间的那段连续子数组之和必为 k 的倍数；只要两次同余出现位置的距离 ≥ 2，就命中答案。

完整推导

思路推导

  1. 直觉与痛点（暴力枚举 O(n²) 会超时）

n 最大 10^5，若枚举所有 (i, j) 子数组求和会超时。这类"连续子数组和"几乎都和前缀和有关，先把思路转到前缀和上。

  1. 破局思路（同余 ⇒ 差是 k 的倍数）

设前缀和 prefix[i] = nums[0] + ... + nums[i]。子数组 nums[l..r] 的和等于 prefix[r] - prefix[l-1]。它要是 k 的倍数，即：

prefix[r] ≡ prefix[l-1] (mod k)

换句话说：只要两个前缀和模 k 同余，它们之间的子数组和就是 k 的倍数。这由"抽屉原理"保证——模 k 只有 k 种余数，前缀一多必然撞上。

于是用一个哈希表记录"每个余数最早出现的下标"。遍历时若当前余数早已出现，且当前下标与最早下标相差 ≥ 2（长度至少 2），立即返回 true。

以 nums = [23,2,4,6,7], k = 6 为例： - prefix = 23，23 % 6 = 5，记录 5 → 0； - prefix = 25，25 % 6 = 1，记录 1 → 1； - prefix = 29，29 % 6 = 5，余数 5 曾在下标 0 出现，当前下标 2，距离 2 - 0 = 2 ≥ 2，返回 true（子数组 [2,4] 和为 6）。

  1. 关键追问（为什么必须记录"最早"下标？）

求的是"是否存在长度 ≥ 2 的子数组"，同一余数可能出现多次。用最早出现的下标去和后面比，得到的距离最大，最容易满足 ≥ 2，也保证不漏解。所以命中但距离不足 2 时，不覆盖已有下标。

Java 实现（同余 + 哈希表）

import java.util.HashMap;
import java.util.Map;

class Solution {
    public boolean checkSubarraySum(int[] nums, int k) {
        // 余数 -> 该余数最早出现的下标（前缀和下标）
        Map<Integer, Integer> remainderToIndex = new HashMap<>();
        remainderToIndex.put(0, -1); // 空前缀，余数 0 出现在下标 -1

        long prefix = 0; // 用 long 防止前缀和溢出
        for (int i = 0; i < nums.length; i++) {
            prefix += nums[i];
            int remainder = (int) (prefix % k);

            Integer prev = remainderToIndex.get(remainder);
            if (prev != null) {
                // 同一余数再次出现，说明中间这段和是 k 的倍数
                if (i - prev >= 2) {
                    return true; // 长度至少为 2
                }
                // 距离不足 2 时保留更早的下标，不覆盖
            } else {
                remainderToIndex.put(remainder, i);
            }
        }
        return false;
    }
}

C++ 实现

#include <vector>
#include <unordered_map>
using namespace std;

class Solution {
public:
    bool checkSubarraySum(vector<int>& nums, int k) {
        // 余数 -> 最早出现的下标
        unordered_map<int, int> remainderToIndex;
        remainderToIndex[0] = -1; // 空前缀

        long long prefix = 0;
        for (int i = 0; i < (int)nums.size(); i++) {
            prefix += nums[i];
            int remainder = (int)(prefix % k);

            auto it = remainderToIndex.find(remainder);
            if (it != remainderToIndex.end()) {
                if (i - it->second >= 2) {
                    return true; // 长度至少为 2
                }
                // 距离不足 2，保留更早下标
            } else {
                remainderToIndex[remainder] = i;
            }
        }
        return false;
    }
};

Python 实现

class Solution:
    def checkSubarraySum(self, nums: list[int], k: int) -> bool:
        # 余数 -> 最早出现的下标
        remainder_to_index = {0: -1}  # 空前缀
        prefix = 0

        for i, x in enumerate(nums):
            prefix += x
            r = prefix % k

            if r in remainder_to_index:
                if i - remainder_to_index[r] >= 2:
                    return True  # 长度至少为 2
                # 距离不足 2，保留更早下标
            else:
                remainder_to_index[r] = i
        return False

复杂度

  • 时间：O(n)。遍历一次数组，哈希表操作均摊 O(1)。
  • 空间：O(min(n, k))。哈希表最多存 min(n, k) 个不同余数。
易错点与扩展（面试高频考点）
  1. 长度必须 ≥ 2：最致命的坑。若只判断"同余出现过"，会把长度 1、本身为 k 倍数的单个元素误判为合法。必须检查 i - prev >= 2，并且命中但距离不足时不能覆盖最早下标。
  2. 空前缀的处理：初始 map.put(0, -1)，用来处理"从下标 0 开始的子数组"。如 nums = [6], k = 6，下标 0 余数 0，与 -1 距离 1，不足 2，正确返回 false。
  3. 前缀和溢出：sum(nums[i]) 可达 2^31 - 1，用 long 存累加和更安全（余数本身在 int 范围内）。
  4. 取模与负数：本题 nums[i] >= 0，前缀和非负，% 直接可用；若允许负数，需要 ((prefix % k) + k) % k 规范化。
  5. 对比 LeetCode 525（连续数组）：两题都是"前缀和 + 哈希表找相同特征值"，本题特征是"模 k 同余"，525 是"把 0 看成 -1 后的相同前缀和"，套路一脉相承。
