# 717. 1 比特与 2 比特字符

| 题目信息 | 内容 |
|---|---|
| 难度 | 简单 |
| 核心模式 | 从左到右贪心解码，看最后一个 0 是否恰好落在末尾独立成字符 |
| 时间复杂度 | O(n) |
| 空间复杂度 | O(1) |

## 题目与约束

有两种特殊字符：

- 第一种字符可以用一比特 `0` 表示

- 第二种字符可以用两比特（`10` 或 `11`）表示

给你一个以 `0` 结尾的二进制数组 `bits` ，如果最后一个字符必须是一个一比特字符，则返回 `true` 。

 

示例 1:

```
<strong>输入:</strong> bits = [1, 0, 0]
<strong>输出:</strong> true
<strong>解释:</strong> 唯一的解码方式是将其解析为一个两比特字符和一个一比特字符。
所以最后一个字符是一比特字符。
```

示例 2:

```
<strong>输入：</strong>bits = [1,1,1,0]
<strong>输出：</strong>false
<strong>解释：</strong>唯一的解码方式是将其解析为两比特字符和两比特字符。
所以最后一个字符不是一比特字符。
```

 

提示:

- `1 <= bits.length <= 1000`

- `bits[i]` 为 `0` 或 `1`

[🔗 前往力扣原题验证 →](https://leetcode.cn/problems/1-bit-and-2-bit-characters/)

## 核心不变量

> 解码方式唯一：遇到 `1` 必吃两位（`10` 或 `11`），遇到 `0` 必吃一位；从下标 0 一路贪心走到 `n-1` 时若恰好停在最后一格，则最后一位是独立的一比特字符。

## 完整推导

### 思路推导

1. **直觉与痛点（为什么不能从后往前硬猜）**

   字符编码有前缀性质：`0` 是一比特，`1` 开头的 `10/11` 是两比特。由于数组以 `0` 结尾，从左往右解析时每一步的"步长"是被当前位唯一确定的，不存在歧义，因此**不需要搜索、不需要回溯**。

2. **破局思路（模拟唯一解码过程）**

   维护指针 `i = 0`。只要 `i < n-1`（不越过最后一格）：
   - 如果 `bits[i] == 1`，它必然和后面一位组成两比特字符，`i += 2`；
   - 如果 `bits[i] == 0`，它单独是一个一比特字符，`i += 1`。

3. **关键判定（看落点）**

   扫描结束后，若 `i == n-1`，说明前面所有位刚好解码完，最后一格 `0` 没有被前面某个两比特字符"吞掉"，它就是一个独立的一比特字符 → 返回 `true`；若 `i` 越过到了 `n`，说明最后一位被并进了前一个两比特字符 → `false`。
   小例子：`[1,0,0]` → `i=0` 遇 1 跳到 2，`i=2=n-1` 停住 → `true`；`[1,1,1,0]` → `i=0`→2（遇 1），`i=2` 遇 1 跳到 4（越过 n-1=3）→ `false`。

### Java 实现（isOneBitCharacter）

```java
class Solution {
    public boolean isOneBitCharacter(int[] bits) {
        int n = bits.length;
        int i = 0;
        // 只需扫描到倒数第二个位置；最后一格是否被"吃掉"由落点决定
        while (i < n - 1) {
            if (bits[i] == 1) {
                i += 2; // 1 开头必是两比特字符
            } else {
                i += 1; // 0 是单独的一比特字符
            }
        }
        // 恰好停在最后一格，说明最后一位独立成为一比特字符
        return i == n - 1;
    }
}
```

### 复杂度

- 时间：O(n)。指针只向右移动，每步至少推进 1 位，最多扫描整个数组一次。
- 空间：O(1)。只用了若干整型变量。

### 易错点与扩展（面试高频考点）

1. **循环边界写成 `i < n`**：若写成 `i < n`，`i` 可能越界访问 `bits[i+1]`；本题只需 `i < n-1`，因为最后一格本身不需要再判断。
2. **把判定写成比较最后一个字符**：不能只看 `bits[n-2]`，因为前面的解码会改变"最后一位到底属于谁"，必须走完整条贪心路径。
3. **另一种等价写法**：也可以从尾部数连续 `1` 的个数，若连续 `1` 的个数为偶数则为 `true`（因为末尾的 `0` 前面成对的 `1` 都被两比特字符吃完）。但可读性不如从左贪心。
4. **扩展**：这类"编码前缀唯一 → 线性贪心"的思想，可迁移到字符串解码、变长编码校验等题目。

## 力扣原题

### C++ 实现

```cpp
#include <vector>
using namespace std;

class Solution {
public:
    bool isOneBitCharacter(vector<int>& bits) {
        int n = bits.size();
        int i = 0;
        while (i < n - 1) {
            i += (bits[i] == 1) ? 2 : 1;
        }
        return i == n - 1;
    }
};
```

### Python 实现

```python
class Solution:
    def isOneBitCharacter(self, bits: list[int]) -> bool:
        n = len(bits)
        i = 0
        while i < n - 1:
            i += 2 if bits[i] == 1 else 1
        return i == n - 1
```
