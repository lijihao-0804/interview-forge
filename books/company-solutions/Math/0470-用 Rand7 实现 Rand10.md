# 470. 用 Rand7() 实现 Rand10()

| 题目信息 | 内容 |
|---|---|
| 难度 | 中等 |
| 核心模式 | 拒绝采样（多维映射 + 舍去越界） |
| 时间复杂度 | O(1) 期望 |
| 空间复杂度 | O(1) |

## 题目与约束

给定方法 `rand7` 可生成 `[1,7]` 范围内的均匀随机整数，试写一个方法 `rand10` 生成 `[1,10]` 范围内的均匀随机整数。

你只能调用 `rand7()` 且不能调用其他方法。请不要使用系统的 `Math.random()` 方法。

每个测试用例将有一个内部参数 `n`，即你实现的函数 `rand10()` 在测试时将被调用的次数。请注意，这不是传递给 `rand10()` 的参数。

**示例 1:**

```
输入: 1
输出: [2]
```

**示例 2:**

```
输入: 2
输出: [2,8]
```

**示例 3:**

```
输入: 3
输出: [3,8,10]
```

**提示:**

- `1 <= n <= 10^5`

**进阶:**

- `rand7()` 调用次数的 **期望值** 是多少？
- 你能否尽量少调用 `rand7()`？

## 核心不变量

> 用两次 `rand7` 构造 `num = (rand7()-1)*7 + rand7()`，得到 `[1,49]` 上等概率的 49 个数；只接受其中 `1..40`，映射为 `(num-1)%10+1`，其余 9 个值拒绝并重采样。因为接受区是 10 的整数倍，10 个结果严格等概率。

## 完整推导

### 思路推导

1. **直觉与痛点（7 与 10 不整除）**：`rand7` 只给 7 个等概率结果，直接对 7 取模得到 1~10 会不均匀。要得到 10 个等概率结果，得先造出一个“个数能被 10 整除”的均匀分布。

2. **破局（两次 rand7 拼成 49 进制数）**：把两次 `rand7` 看成两位七进制数：`a` 是高位、`b` 是低位，`num = (a-1)*7 + b` 恰好在 `[1,49]` 上每个值等概率（`7 × 7 = 49` 个组合，一一对应）。

3. **拒绝采样（丢掉 41~49）**：取前 40 个数，映射 `(num-1) % 10 + 1`，让 `1..40` 均匀落到 `1..10`（每 4 个数对应一个结果：1,11,21,31→1；2,12,22,32→2……）。`41..49` 这 9 个数不满足整除，丢弃后重新采样。以 `num = 7` 为例，`(7-1)%10+1 = 7`；`num = 40` 得 `(39)%10+1 = 10`。

4. **为什么正确**：接收概率 `40/49`，条件在接收区内每个 `num` 等概率，每 10 个连续值恰好覆盖 `1..10` 各一次，所以 10 个输出等概率；被拒绝的样本不引入任何偏差，只是重来。

### Java 实现（rand10）

```java
/**
 * The rand7() API is already defined in the parent class SolBase.
 * public int rand7();
 * @return a random integer in the range 1 to 7
 */
class Solution extends SolBase {
    public int rand10() {
        while (true) {
            // 两次 rand7 组合成 [1, 49] 的均匀随机数
            int num = (rand7() - 1) * 7 + rand7();
            // 只接受 1..40，保证能被 10 整除、结果等概率
            if (num <= 40) {
                return (num - 1) % 10 + 1;
            }
            // 41..49 拒绝，重新采样
        }
    }
}
```

### 复杂度

- 时间：`O(1)` 期望。每次尝试接受概率 `40/49`，期望尝试次数 `49/40 ≈ 1.225`，每轮调用 2 次 `rand7`，故 `rand7` 期望调用次数 `2 × 49/40 = 2.45`。
- 空间：`O(1)`。只用了常数个整型变量。

### 易错点与扩展（面试高频考点）

1. **必须是 `(a-1)*7 + b` 而不是 `a*7 + b`**：若用 `a*7 + b`，范围是 `[8,56]` 且分布不均（`a` 与 `b` 的贡献不对等），一定要先减 1 再乘。
2. **接受区间必须能被 10 整除**：`1..40` 是 40 个值，正好 10 的倍数；如果贪心地接受 `1..49` 再取模，尾巴会不均。
3. **拒绝后要 `while(true)` 重采样**：不能只试一次就返回，否则 `41..49` 时返回错误结果；重采样不改变均匀性。
4. **边界检查**：`num = 40` 时 `(40-1)%10+1 = 10`，`num = 1` 时得 `1`，首尾都覆盖到，十个数一个不差。
5. **进阶优化**：可缓存“拒绝值”做更复杂映射，把期望调用次数从 2.45 降到更接近理论下界（约 2.19 次），或先构造 `[1,49]` 中的 40 个接受值；面试里答出“拒绝采样 + 期望 2.45 次”即可。也可对比另一常见写法：先 `(rand7()+rand7()-2)%10` 之类的做法会破坏均匀性，不能使用。
