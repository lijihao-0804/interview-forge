题目与约束

给定一个正整数 n ，将其拆分为 k 个 正整数 的和（ k >= 2 ），并使这些整数的乘积最大化。

返回 你可以获得的最大乘积 。

示例 1:

输入: n = 2
输出: 1
解释: 2 = 1 + 1, 1 × 1 = 1。

示例 2:

输入: n = 10
输出: 36
解释: 10 = 3 + 3 + 4, 3 × 3 × 4 = 36。

提示:

  • 2 <= n <= 58

🔗 前往力扣原题验证 →

核心不变量

只要剩余部分还能拆出 3 且不会剩下 1，就优先拆出 3；余 2 乘 2、余 4 原样保留（即 2+2 不拆成 3+1）。

完整推导

思路推导

  1. 直觉与痛点（是不是要枚举所有拆法？）

枚举所有拆分方式会爆炸。但乘积最大化其实有很强的规律：把整数拆得越"平均"越大，而且拆成小的正整数更划算。关键问题是：到底拆成几最好？

  1. 为什么是 3（局部比较法）

比较一下把某个因子继续拆开是否更划算：

  • 4 = 2 + 2，而 2 × 2 = 4，拆不拆一样；
  • 5：拆成 2 + 3 得 6 > 5，所以 5 应该拆；
  • 6：3 + 3 得 9 > 6，应拆；
  • 任何 x >= 5，都有 3 × (x-3) > x，所以只要还能拆，就拆出一个 3。

于是结论：尽量多拆 3。以 n = 10 为例：10 = 3 + 3 + 4，3 × 3 × 4 = 36，比 3+3+3+1（乘积 27）更好。

  1. 处理两种边界余数
  • 若最后剩下 2，直接保留（3 比 2 大，但再拆成 1+1 只会更差）；
  • 若最后剩下 1，说明上一步多拆了一个 3，应把 3 + 1 合并成 2 + 2（因为 3 × 1 = 3 < 2 × 2 = 4）。代码里用 while (n > 4) 就自然地避免了剩下 1 的情况。
  1. 特判小值：题目要求 k >= 2（必须拆），所以 n = 2 只能 1+1，返回 1；n = 3 只能 1+2，返回 2。这两个不能套用"尽量拆 3"。

Java 实现（integerBreak）

class Solution {
    public int integerBreak(int n) {
        // 题目要求至少拆成两个数，2 和 3 只能被迫拆成 1+1、1+2
        if (n == 2) return 1;
        if (n == 3) return 2;

        int res = 1;
        // 只要剩余部分还能"安全"拆出 3（剩 >= 5 才拆，剩 4 时保留 2+2 更优）
        while (n > 4) {
            res *= 3;
            n -= 3;
        }
        // 循环结束时 n 只会是 2、3 或 4，直接乘进结果
        return res * n;
    }
}

复杂度

  • 时间：O(n)，while 循环最多执行约 n/3 次。
  • 空间：O(1)，只用了常数个整型变量。

易错点与扩展（面试高频考点）

  1. 必须至少拆成两段：n = 2 返回 1、n = 3 返回 2，若不特判而直接"拆 3"会得到 2、3，都错。
  2. 余数为 1 的处理：用 while (n > 4) 而非 while (n >= 3)，可避免出现 ...×3×1 这种比 ...×2×2 更小的结果。
  3. 贪心正确性要能讲清：核心是 3 × (x-3) > x（对 x >= 5 成立），且 2+2 优于 3+1，所以拆 3 最优。
  4. DP 备选：面试也可给动态规划 dp[i] = max(j*(i-j), j*dp[i-j])，时间 O(n²)、空间 O(n)，思路更通用但不如贪心优雅。
  5. 数值范围：n <= 58 时结果在 int 范围内，无需 long；若上界放大则要注意溢出。

C++ 实现

class Solution {
public:
    int integerBreak(int n) {
        if (n == 2) return 1;
        if (n == 3) return 2;
        int res = 1;
        while (n > 4) {   // 剩 >= 5 才继续拆 3，剩 4 时保留 2+2
            res *= 3;
            n -= 3;
        }
        return res * n;
    }
};
