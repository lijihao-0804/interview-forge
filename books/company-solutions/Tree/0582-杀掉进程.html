核心不变量

杀掉 kill 等价于杀掉以 kill 为根的整棵进程子树——即 kill 自身加上它的全部（直接或间接）后代。

完整推导

思路推导

  1. 把进程关系建成树

每个进程只有唯一父进程，pid[i] 的父是 ppid[i]。用一个哈希表 children: 父ID -> [子ID,...] 把所有边存下来，就得到了进程树（无需真的建 Node 对象）。

  1. 从 kill 出发做遍历

杀一个进程会连带杀掉它的全部后代，这正好是以 kill 为起点的一次 DFS / BFS：访问到的每个节点都会被杀死，加入结果集。

  1. 用迭代栈代替递归

进程链可能很长（例如 1 万个进程首尾相连），递归可能导致栈溢出。用显式栈（或队列）逐层展开更稳妥。

  1. 小例子

children 为 {3:[1,5], 0:[3], 5:[10]}。从 5 出发：弹出 5 记录，压入 10；弹出 10 记录，无子节点。结果 [5,10]，正确。

Java 实现（killProcess）

import java.util.*;

class Solution {
    public List<Integer> killProcess(List<Integer> pid, List<Integer> ppid, int kill) {
        // 1. 建立 父 -> 子列表 的映射
        Map<Integer, List<Integer>> children = new HashMap<>();
        for (int i = 0; i < pid.size(); i++) {
            children.computeIfAbsent(ppid.get(i), k -> new ArrayList<>()).add(pid.get(i));
        }

        // 2. 从 kill 出发迭代遍历整棵子树
        List<Integer> res = new ArrayList<>();
        Deque<Integer> stack = new ArrayDeque<>();
        stack.push(kill);
        while (!stack.isEmpty()) {
            int cur = stack.pop();
            res.add(cur); // 当前进程被杀
            for (int child : children.getOrDefault(cur, Collections.emptyList())) {
                stack.push(child); // 子进程也要被杀
            }
        }
        return res;
    }
}

C++ 实现

class Solution {
public:
    vector<int> killProcess(vector<int>& pid, vector<int>& ppid, int kill) {
        unordered_map<int, vector<int>> children;
        for (size_t i = 0; i < pid.size(); ++i) {
            children[ppid[i]].push_back(pid[i]);
        }
        vector<int> res;
        stack<int> st;
        st.push(kill);
        while (!st.empty()) {
            int cur = st.top();
            st.pop();
            res.push_back(cur);
            for (int child : children[cur]) {
                st.push(child);
            }
        }
        return res;
    }
};

Python 实现

class Solution:
    def killProcess(self, pid: List[int], ppid: List[int], kill: int) -> List[int]:
        children = {}
        for p, pp in zip(pid, ppid):
            children.setdefault(pp, []).append(p)

        res = []
        stack = [kill]
        while stack:
            cur = stack.pop()
            res.append(cur)
            stack.extend(children.get(cur, []))
        return res

复杂度

  • 时间：O(n)，每个进程恰好入栈 / 出栈一次，建图也只需扫描一遍 pid。
  • 空间：O(n)，children 映射存储 n−1 条边，结果集与栈最坏也都是 O(n)。
易错点与扩展（面试高频考点）
  1. 忘记把 kill 本身计入结果：题目明确"杀掉进程自身"也算，遍历的起点必须先入栈并记录。
  2. 建图方向搞反：键应为 ppid、值为 pid（父 → 子），这样才能从父往下找后代。
  3. kill 不存在于任何 ppid 中：它可能是叶子，children.get 取不到时要用 getOrDefault 返回空列表，避免空指针。
  4. 递归爆栈：进程链退化成链表时递归深度可达 n≈10⁴~10⁵，建议用显式栈 / 队列的迭代写法。
  5. 结果顺序不限：不需要排序；若要稳定输出可按 ID 排序，但会额外增加 O(k log k)。
