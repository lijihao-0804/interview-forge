# 405. 数字转换为十六进制数

| 题目信息 | 内容 |
|---|---|
| 难度 | 简单 |
| 核心模式 | 位运算（每 4 位取一位十六进制） |
| 时间复杂度 | O(1) |
| 空间复杂度 | O(1) |

## 题目与约束

给定一个整数 `num`，编写一个算法将这个数转换为十六进制数。对于负整数，我们通常使用**补码运算**方法。

答案字符串中的所有字母都应该是小写字符，并且除了 `0` 本身之外，答案中不应该有任何前置零。

**注意：** 不允许使用任何由库提供的将数字直接转换或格式化为十六进制的方法来解决这个问题。

**示例 1：**

```
输入：num = 26
输出："1a"
```

**示例 2：**

```
输入：num = -1
输出："ffffffff"
```

**提示：**

- `-2^31 <= num <= 2^31 - 1`

## 核心不变量

> 一个 32 位整数在补码下，恰好由 8 个十六进制位表示；每次取最低 4 位（`num & 15`）就是一位十六进制数，再**无符号**右移 4 位继续处理。

## 完整推导

### 思路推导

1. **十六进制与二进制的天然关系**：一位十六进制数正好对应 4 个二进制位。所以把一个整数拆成十六进制，本质上就是「每 4 位一组」地取出数字。

2. **负数怎么办？** 计算机里整数以补码存储。Java 的 `int` 是 32 位，负数 `-1` 的补码就是 32 个 1，按 4 位一组正好是 8 个 `f`，即 `"ffffffff"`。因此我们不需要额外做「取反加一」，只要把内存里的 32 位直接按位读取即可。

3. **关键点是无符号右移**：如果用普通带符号右移 `>>`，负数右移会在高位补 1，永远不会变成 0，导致死循环。必须使用**无符号右移**（Java 的 `>>>`，C++ 中转成 `unsigned int`，Python 里先把负数加 `2^32` 转成对应的无符号整数）。

4. **处理 0 和去前导零**：`0` 需要单独返回 `"0"`；其余情况循环到 `num == 0` 停止，天然不会产生前导零。由于是从低位往高位取，最后要把结果反转。

小例子：`num = 26`。`26 & 15 = 10 → 'a'`，`26 >>>= 4` 得 1；`1 & 15 = 1 → '1'`，再移得 0 停止。反转后为 `"1a"`。

### Java 实现（逐位取模 + 无符号右移）

```java
class Solution {
    public String toHex(int num) {
        // 0 单独处理，避免返回空串
        if (num == 0) {
            return "0";
        }
        char[] map = "0123456789abcdef".toCharArray();
        StringBuilder sb = new StringBuilder();
        // 每轮取最低 4 位；>>> 无符号右移保证负数也能终止
        while (num != 0) {
            int digit = num & 15;          // 等价于 num % 16，但对负数也正确
            sb.append(map[digit]);
            num >>>= 4;                    // 无符号右移 4 位
        }
        return sb.reverse().toString();
    }
}
```

### 复杂度

- 时间：O(1)，32 位整数最多循环 8 次，是常数规模。
- 空间：O(1)，除答案字符串外只用常数级额外变量（结果串长度也固定 ≤ 8）。

### 易错点与扩展（面试高频考点）

1. **用了带符号右移导致死循环**：这是本题最经典的坑。负数用 `>>` 会一直补 1 永不归零。Java 必须写 `>>>`；C++ 用 `unsigned int`；Python 没有无符号类型，需 `num += 1 << 32` 手动转成无符号。

2. **忘记单独处理 0**：`while (num != 0)` 对 0 一次都不执行，会返回空字符串，而正确答案是 `"0"`。

3. **用了库函数**：`Integer.toHexString`、`std::to_string` 配 `%x`、Python 的 `hex()` 都被题目明令禁止，面试中这样写会被判定未答到考点。

4. **正负不要分开写两套逻辑**：很多人的直觉是「负数先转正数再取反加一」，其实补码天然统一，直接按位取即可，代码更短也更不易错。

5. **扩展：转成任意进制（2~16）**：把「15」和「4」换成 `base - 1` 和相应的位移/取模逻辑即可抽象出通用模板（不过非 2 的幂的进制无法用位移加速）。

## 力扣原题

[405. 数字转换为十六进制数](https://leetcode.cn/problems/convert-a-number-to-hexadecimal/)

### C++ 实现

```cpp
class Solution {
public:
    string toHex(int num) {
        if (num == 0) {
            return "0";
        }
        const char* digits = "0123456789abcdef";
        string res;
        // 转成无符号数后右移，天然按补码的 32 位处理，负数也能正确终止
        unsigned int n = static_cast<unsigned int>(num);
        while (n != 0) {
            res.push_back(digits[n & 0xf]);
            n >>= 4;
        }
        reverse(res.begin(), res.end());
        return res;
    }
};
```

### Python 实现

```python
class Solution:
    def toHex(self, num: int) -> str:
        if num == 0:
            return "0"
        # Python 的整数无固定位宽，负数需手动转成 32 位补码对应的无符号值
        if num < 0:
            num += 1 << 32
        digits = "0123456789abcdef"
        res = []
        while num:
            res.append(digits[num & 15])
            num >>= 4
        return "".join(reversed(res))
```
