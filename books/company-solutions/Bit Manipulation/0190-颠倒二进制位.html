190. 颠倒二进制位

难度简单核心模式逐位取出并反向拼接时间复杂度O(1)（固定 32 次迭代）空间复杂度O(1)

题目与约束

颠倒给定的 32 位有符号整数的二进制位。

示例 1：

输入：n = 43261596

输出：964176192

解释：

        整数
        二进制

        43261596
        00000010100101000001111010011100

        964176192
        00111001011110000010100101000000

示例 2：

输入：n = 2147483644

输出：1073741822

解释：

        整数
        二进制

        2147483644
        01111111111111111111111111111100

        1073741822
        00111111111111111111111111111110

提示：

  • 0 <= n <= 231 - 2

  • n 为偶数

进阶: 如果多次调用这个函数，你将如何优化你的算法？

核心不变量

循环中 res 始终是「已经处理过的那若干低位」逆序后的结果；每轮把 res 左移一位并追加 n 的当前最低位，n 再右移一位，32 轮后 res 恰为完整逆序位。

完整推导

思路推导

  1. 直觉与痛点（不能简单反转字符串）

最直白是把 32 位转成二进制字符串、反转、再转回整数，正确但低效且要处理前导零。我们希望直接在位级别操作。

  1. 破局思路（从低位取、往高位放）

准备结果 res = 0。重复 32 次：取 n 的最低位 n & 1，把它挂到 res 的末尾（res = (res << 1) | (n & 1)），然后把 n 逻辑右移一位（n >>>= 1）。这样 n 从最低位开始被依次取下，res 每次左移让先取到的位逐渐「沉」到更高的位置，最终顺序正好颠倒。

  1. 关键追问（为什么右移要用无符号？）

n 可能被当作有符号数，最高位为 1 时算术右移会补 1，导致高位被污染。Java 用 >>>（逻辑右移，补 0）；C++ 用 uint32_t 天然无符号；Python 的整数无固定位宽，右移补 0，天然安全。

  1. 收尾

循环固定 32 次（不是直到 n == 0），否则 n 高位为 0 时会少处理位数，结果错误。

Java 实现（reverseBits）

public class Solution {
    // you need treat n as an unsigned value
    public int reverseBits(int n) {
        int res = 0;
        for (int i = 0; i < 32; i++) {
            // 把当前 n 的最低位追加到 res 末尾
            res = (res << 1) | (n & 1);
            // 逻辑右移，高位补 0，避免符号位干扰
            n >>>= 1;
        }
        return res;
    }
}

C++ 实现

#include <cstdint>

class Solution {
public:
    uint32_t reverseBits(uint32_t n) {
        uint32_t res = 0;
        for (int i = 0; i < 32; ++i) {
            res = (res << 1) | (n & 1u);
            n >>= 1; // uint32_t 为无符号，右移补 0
        }
        return res;
    }
};

Python 实现

class Solution:
    def reverseBits(self, n: int) -> int:
        res = 0
        for _ in range(32):
            res = (res << 1) | (n & 1)
            n >>= 1
        return res

复杂度

  • 时间：O(1)。固定执行 32 次循环，与输入规模无关（位宽常数）。
  • 空间：O(1)。只用了 res、n 与循环变量。
易错点与扩展（面试高频考点）
  1. 必须循环 32 次：写成 while (n != 0) 会在 n 的高位 0 处提前结束，导致逆序结果的高位缺失。
  2. 用无符号/逻辑右移：Java 的 >> 是算术右移，会把符号位一路带下来；务必用 >>>。
  3. 返回值按位比较：res 可能超过 int 正数范围而变成负数，这没关系，LeetCode 按 32 位比特比较，返回 int 即正确。
  4. 不要用字符串反转：多次调用场景下字符串方案常数大，位运算方案更优。
  5. 扩展（分治 / 掩码交换）：进阶「多次调用」的思路是用 O(1) 的分治位交换：先交换相邻 1 位、再交换相邻 2 位、4 位、8 位、16 位，5 步完成。核心写法：n = ((n & 0x55555555) << 1) | ((n >>> 1) & 0x55555555); 再依次用 0x33333333、0x0F0F0F0F、0x00FF00FF、0x0000FFFF 掩码，正是标签里 Divide and Conquer 的体现。若有海量调用，还可预计算每 8 位的反转表缓存加速。
