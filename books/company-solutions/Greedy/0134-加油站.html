题目信息 内容
难度 中等
核心模式 贪心：全局净油量 + 局部起点重置
时间复杂度 O(n)
空间复杂度 O(1)

题目与约束

在一条环路上有 n 个加油站，其中第 i 个加油站有汽油 gas[i] 升。

你有一辆油箱容量无限的的汽车，从第 i 个加油站开往第 i+1 个加油站需要消耗汽油 cost[i] 升。你从其中的一个加油站出发，开始时油箱为空。

给定两个整数数组 gas 和 cost ，如果你可以按顺序绕环路行驶一周，则返回出发时加油站的编号，否则返回 -1 。如果存在解，则 保证 它是 唯一 的。

示例 1:

<strong>输入:</strong> gas = [1,2,3,4,5], cost = [3,4,5,1,2]
<strong>输出:</strong> 3
<strong>解释:
</strong>从 3 号加油站(索引为 3 处)出发，可获得 4 升汽油。此时油箱有 = 0 + 4 = 4 升汽油
开往 4 号加油站，此时油箱有 4 - 1 + 5 = 8 升汽油
开往 0 号加油站，此时油箱有 8 - 2 + 1 = 7 升汽油
开往 1 号加油站，此时油箱有 7 - 3 + 2 = 6 升汽油
开往 2 号加油站，此时油箱有 6 - 4 + 3 = 5 升汽油
开往 3 号加油站，你需要消耗 5 升汽油，正好足够你返回到 3 号加油站。
因此，3 可为起始索引。

示例 2:

<strong>输入:</strong> gas = [2,3,4], cost = [3,4,3]
<strong>输出:</strong> -1
<strong>解释:
</strong>你不能从 0 号或 1 号加油站出发，因为没有足够的汽油可以让你行驶到下一个加油站。
我们从 2 号加油站出发，可以获得 4 升汽油。 此时油箱有 = 0 + 4 = 4 升汽油
开往 0 号加油站，此时油箱有 4 - 3 + 2 = 3 升汽油
开往 1 号加油站，此时油箱有 3 - 3 + 3 = 3 升汽油
你无法返回 2 号加油站，因为返程需要消耗 4 升汽油，但是你的油箱只有 3 升汽油。
因此，无论怎样，你都不可能绕环路行驶一周。

提示:

  • n == gas.length == cost.length

  • 1 <= n <= 105

  • 0 <= gas[i], cost[i] <= 104

  • 输入保证答案唯一。

核心不变量

如果从某个加油站出发、累计到当前位置的净油量第一次变成负数，那么从这段区间内的任何加油站出发都无法走完这段路；又因为总净油量非负时答案必然存在，所以起点一定是这个"断点"的下一个加油站。

完整推导

思路推导

  1. 直觉与痛点（暴力枚举太慢）

最直接的做法是对每个起点都模拟绕行一圈，检查途中油箱会不会变负。单次模拟 O(n)，全部起点 O(n²)，在 n = 10^5 时会超时。我们需要一遍扫描就定出答案。

  1. 破局思路（把问题拆成两个独立问题）

记 diff[i] = gas[i] - cost[i]，表示到达第 i 站"加完油再开往下一站"的净收支。

  • 能不能绕完？ 整圈净油量 sum(diff) = Σgas - Σcost。如果它小于 0，无论从哪出发都必然亏空，直接返回 -1；如果它 ≥ 0，题目已保证答案存在且唯一，我们只需要找到那个起点。
  • 起点在哪？ 从某个起点开始累加 diff，一旦累计值跌到负数，说明"从当前起点到此处"这段路必然开不过去。
  1. 关键追问（为什么断点之前的点都作废？）

假设从 start 出发，走到 i 时累计值首次 < 0。考察 start 与 i 之间的任意加油站 j：从 start 到 j-1 都没断过，累计仍有剩余（≥ 0）；但把这剩余的油"送给" j 作为起始油箱，走过同一段到 i 的净收支完全相同，结果只会更差（起始更少）。因此 j 也不可能成功。

结论：整段 [start, i] 都排除，新起点直接从 i+1 开始，并把局部累计清零。这样每个点只被访问一次。

以 gas = [1,2,3,4,5]、cost = [3,4,5,1,2] 为例，diff = [-2,-2,-2,3,3]，总和 0 ≥ 0。从 0 出发：-2 → 断，起点改 1；继续 -2 → 断，起点改 2；继续 -2 → 断，起点改 3；从 3 累加 3、3 始终不为负，最终答案 3。

Java 实现（贪心一遍扫描）

class Solution {
    public int canCompleteCircuit(int[] gas, int[] cost) {
        int totalTank = 0;   // 整圈累计净油量，用于判断是否可能存在解
        int curTank = 0;     // 从当前候选起点出发的累计净油量
        int start = 0;       // 当前候选起点

        for (int i = 0; i < gas.length; i++) {
            int diff = gas[i] - cost[i];
            totalTank += diff;
            curTank += diff;

            // 从 start 到 i 无法走通，说明 [start, i] 内任何点都不能作为起点
            if (curTank < 0) {
                start = i + 1;  // 起点改到断点的下一站
                curTank = 0;    // 局部累计清零，重新开始
            }
        }

        // 总净油量为负则无解；否则 start 就是唯一答案
        return totalTank >= 0 ? start : -1;
    }
}

复杂度

  • 时间：O(n)。只需从左到右遍历数组一次，每次做常数次加减与比较。
  • 空间：O(1)。只用了 totalTank、curTank、start 三个变量，与输入规模无关。

易错点与扩展（面试高频考点）

  1. 忘记总净油量判定：只做局部累加而不检查 Σgas < Σcost，在无解时可能错误地返回某个下标。必须先看总和。
  2. 起点更新写成 i 而不是 i + 1：断点 i 本身已证明不可行，新起点应从下一站开始；写成 i 会重复考察断点。
  3. curTank 忘记清零：重置起点时必须把局部累计归零，否则残留的负数会污染后续判断。
  4. 答案唯一性的利用：题目保证解唯一，所以扫描结束后若总和 ≥ 0，残留的 start 就是答案，无需再验证一圈。
  5. 扩展——严格证明：可以用"前缀和最低点"的角度理解：把 diff 做前缀和，起点取最低前缀和的下一个位置即可，这与本题贪心完全等价。

C++ 实现

#include <vector>
using namespace std;

class Solution {
public:
    int canCompleteCircuit(vector<int>& gas, vector<int>& cost) {
        int totalTank = 0;
        int curTank = 0;
        int start = 0;
        for (int i = 0; i < (int)gas.size(); i++) {
            int diff = gas[i] - cost[i];
            totalTank += diff;
            curTank += diff;
            if (curTank < 0) {   // 从 start 到 i 走不通，起点后移
                start = i + 1;
                curTank = 0;
            }
        }
        return totalTank >= 0 ? start : -1;
    }
};

class Solution:

            diff = gas[i] - cost[i]
