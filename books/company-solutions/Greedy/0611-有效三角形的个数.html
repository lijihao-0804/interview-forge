611. 有效三角形的个数

本题学习状态正在读取学习记录…下次复习：—
本次复习：
按 M 快速切换薄弱标记
遮住推导与代码，先自己想，再逐段揭示
难度中等核心模式排序 + 双指针（固定最大边）时间复杂度O(n²)空间复杂度O(log n)（排序栈开销，可视为 O(1)）

题目与约束

给定一个包含非负整数的数组 nums ，返回其中可以组成三角形三条边的三元组个数。

示例 1:

输入: nums = [2,2,3,4]
输出: 3
解释:有效的组合是:
2,3,4 (使用第一个 2)
2,3,4 (使用第二个 2)
2,2,3

示例 2:

输入: nums = [4,2,3,4]
输出: 4

提示:

  • 1 <= nums.length <= 1000

  • 0 <= nums[i] <= 1000

🔗 前往力扣原题验证 →

核心不变量

排序后固定最大边 nums[k]，用双指针 i < j < k：当 nums[i] + nums[j] > nums[k] 时，i 到 j-1 之间的任意下标与 j 都能与 nums[k] 成三角形。

完整推导

思路推导

  1. 直觉与痛点（三重循环太慢）

三角形成立的充要条件是「任意两边之和大于第三边」，而排序后只需检验「最小的两边之和 > 最大边」。直接三重枚举是 O(n³)，n = 1000 时约 10^9，超时。需要把一层枚举降成双指针扫描。

  1. 破局思路（固定最大边 + 双指针）

先对数组升序排序。外层枚举最大边下标 k（从后往前或从 2 开始皆可）。问题变成：在 [0, k) 区间里选出两条边 i < j，使 nums[i] + nums[j] > nums[k]。

设 i = 0、j = k - 1：

  • 若 nums[i] + nums[j] > nums[k]：由于数组有序，只有 t ∈ [i, j-1] 才保证 nums[t] + nums[j] > nums[k]（因为 nums[t] >= nums[i]）。因此一次性增加 j - i 个合法三元组，然后 j--。
  • 否则：说明 nums[i] 太小，无论配谁都不行，i++。
  1. 小例子

以 nums = [2,2,3,4] 排序后仍是 [2,2,3,4]。取 k=3（最大边 4），i=0, j=2：2+3>4，计数 += j-i = 2（对应 (2,3,4) 两个 2 各一次），j--。此时 i=0, j=1：2+2=4 不大于 4，i++。最终 k=3 贡献 2 个。再取 k=2（最大边 3），i=0, j=1：2+2>3，计数 +=1。总共 2+1=3，与答案一致。

  1. 为什么不会漏解

每一对 (i, j) 只在一个确定的最大边 k 下被计入；双指针每一步要么 i 右移、要么 j 左移，恰好不重不漏地覆盖了 [0, k) 内所有可能的两边组合中被「批量计数」掉的部分。

Java 实现（排序 + 双指针）

import java.util.Arrays;

class Solution {
    public int triangleNumber(int[] nums) {
        Arrays.sort(nums);           // 升序排序，便于双指针与单调性判断
        int n = nums.length;
        int count = 0;

        // 枚举最大边 nums[k]，只需考虑 k >= 2
        for (int k = n - 1; k >= 2; k--) {
            int i = 0, j = k - 1;
            while (i < j) {
                if (nums[i] + nums[j] > nums[k]) {
                    // i..j-1 与 j 组合都合法，一次性计入
                    count += j - i;
                    j--;            // 换更小的第二边继续找
                } else {
                    i++;            // 最小边太小，右移
                }
            }
        }
        return count;
    }
}

C++ 实现

#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int triangleNumber(vector<int>& nums) {
        sort(nums.begin(), nums.end());   // 升序
        int n = nums.size();
        int count = 0;

        // 固定最大边 nums[k]
        for (int k = n - 1; k >= 2; k--) {
            int i = 0, j = k - 1;
            while (i < j) {
                if (nums[i] + nums[j] > nums[k]) {
                    count += j - i;       // 批量计入
                    j--;
                } else {
                    i++;
                }
            }
        }
        return count;
    }
};

Python 实现

class Solution:
    def triangleNumber(self, nums: list[int]) -> int:
        nums.sort()               # 升序
        n = len(nums)
        count = 0

        # 固定最大边 nums[k]
        for k in range(n - 1, 1, -1):
            i, j = 0, k - 1
            while i < j:
                if nums[i] + nums[j] > nums[k]:
                    count += j - i    # 批量计入
                    j -= 1
                else:
                    i += 1
        return count

复杂度

  • 时间：O(n²)。排序 O(n log n)；外层枚举最大边 O(n)，内层双指针在 [0, k) 内至多走 k 步，合计 O(n²)。
  • 空间：O(log n)。主要为排序的递归栈开销；若不计排序则为 O(1) 的常数变量。
易错点与扩展（面试高频考点）
  1. 必须排序：双指针的批量计数依赖「数组递增」这一单调性，不排序结果全错。
  2. 遗漏批量计数：当 nums[i]+nums[j] > nums[k] 时不是只 +1，而是 += j - i，这是本题 O(n²) 的关键。
  3. 含 0 的边界：nums[i] = 0 时永远无法与任何两边构成三角形，i++ 会自然跳过，无需特判，但要注意下标越界。
  4. 重复元素照常计数：题目按「下标三元组」计数，值相同的元素视为不同个体，不能用集合去重。
  5. 另一种解法对比：也可固定最大边后用二分查找找第一个满足 nums[i]+nums[j] > nums[k] 的 i，复杂度 O(n² log n)，比双指针慢，双指针是最优解。
