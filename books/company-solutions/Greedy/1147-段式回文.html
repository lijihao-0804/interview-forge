题目与约束

你会得到一个字符串 text。你应该把它分成 k 个子字符串 (subtext1, subtext2, …, subtextk)，要求满足：

  • subtexti 是 非空 字符串；
  • 所有子字符串的连接等于 text（即 subtext1 + subtext2 + ... + subtextk == text）；
  • 对于所有 i 的有效值（即 1 <= i <= k），subtexti == subtextk - i + 1 均成立。

返回 k 可能的最大值。

示例 1：

输入：text = "ghiabcdefhelloadamhelloabcdefghi"
输出：7
解释：我们可以把字符串拆分成 "(ghi)(abcdef)(hello)(adam)(hello)(abcdef)(ghi)"。

示例 2：

输入：text = "merchant"
输出：1
解释：我们可以把字符串拆分成 "(merchant)"。

示例 3：

输入：text = "antaprezatepzapreanta"
输出：11
解释：我们可以把字符串拆分成 "(a)(nt)(a)(pre)(za)(tep)(za)(pre)(a)(nt)(a)"。

提示：

  • 1 <= text.length <= 1000
  • text 仅由小写英文字符组成。

核心不变量

从当前未处理区间的两端出发，取"能让两端相等的最短前缀/后缀长度 l"作为一对段（贡献 2 段），剩下的中间部分继续递归；这样每一对贡献的段数最多，等价于让总段数最大。

完整推导

思路推导

  1. 把"回文段"翻译成"两端配对"

要求 subtexti == subtextk-i+1，本质就是：第一段等于最后一段、第二段等于倒数第二段……也就是从字符串两端向中间，成对地取"相同内容"的段。中间若剩下一截无法成对，它自己单独成一段（一个段天然是与自己对称的）。

  1. 为什么贪心取"最短"匹配是对的

假设当前两端能取到长度为 l 的相等前后缀。若改用更长的匹配 l' > l，会把本该拿来做更多对的字符"吞"进同一个大段里，只贡献 2 段；而先取最短的 l，剩余部分更长、还能继续拆出更多对。因此"能配上就取最短"是让总段数最大的贪心策略。

  1. 小例子（"ghiabcdefhelloadamhelloabcdefghi"）

两端字母 g 与 i 不等，gh 与 hi 不等，直到 ghi 与右端 ghi 相等 → 取 l=3，贡献 2 段，指针分别向内收缩 3。剩下 "abcdefhelloadamhelloabcdef"，同理两端最短匹配是 abcdef……如此反复，最终得到 7 段。

  1. 终止条件

当左右指针相遇或交叉（i > j）时结束。若某轮在剩余区间里找不到任何长度的相等前后缀（且区间长度 >= 2），说明中间这一整块只能单独作为一段，贡献 1 段后结束；若区间本来就只剩 1 个字符，同样贡献 1 段。

Java 实现（longestDecomposition）

class Solution {
    public int longestDecomposition(String text) {
        int n = text.length();
        int i = 0, j = n - 1; // 当前未处理区间的左右端点
        int ans = 0;

        while (i <= j) {
            boolean matched = false;
            int maxLen = (j - i + 1) / 2; // 段长最多取区间一半
            for (int l = 1; l <= maxLen; l++) {
                // 判断左端 text[i..i+l-1] 是否等于右端 text[j-l+1..j]
                if (text.regionMatches(i, text, j - l + 1, l)) {
                    ans += 2;   // 成功配对，贡献两段
                    i += l;
                    j -= l;
                    matched = true;
                    break;      // 取最短匹配即停
                }
            }
            if (!matched) {
                // 剩余中间部分单独成一段
                ans += 1;
                break;
            }
        }
        return ans;
    }
}

复杂度

  • 时间：O(n²)。最坏情况下每一轮都要逐一尝试多种段长、且每次字符串比较是 O(l)，字符串总长为 n，整体上界为 O(n²)（对 n <= 1000 足够快）。
  • 空间：O(n)。Java / C++ 的 regionMatches 只做原地比较、额外空间 O(1)；Python 切片比较会创建临时串，累计 O(n) 级别辅助空间。

易错点与扩展（面试高频考点）

  1. 必须贪心取"最短"匹配：若一上来就取最长相等前后缀，会把可拆的段合并、导致段数变少。循环里 break 的位置就是"取到第一个（最短）匹配立刻停止"。

  2. 剩余单段的处理：当区间长度 >= 2 但没有任何相等前后缀时，中间整块只能算 1 段，务必 ans += 1 后 break；漏掉会少算。

  3. 循环边界 i <= j：区间为空（i > j）时不应再计数；只剩一个字符（i == j）时应贡献 1 段，用 <= 恰好覆盖。maxLen = (j-i+1)/2 保证不会取到重叠的段。

  4. 字符串比较的写法：Java 用 regionMatches、C++ 用 string::compare(pos, len, other, pos, len)、Python 直接切片比较，三者语义一致，注意起始下标是 j - l + 1 而非 j - l。

  5. 扩展（滚动哈希 / DP）：标签里还有 Rolling Hash、Dynamic Programming。大 n 时可用双哈希把每次比较降到 O(1)，整体 O(n log n) 或 O(n)；也可用区间 DP dp[i][j] 表示 text[i..j] 的最大段数，枚举最短可匹配前缀转移，与贪心同源但更易证伪贪心的边界。

C++ 实现

#include <string>
using namespace std;

class Solution {
public:
    int longestDecomposition(string text) {
        int n = text.size();
        int i = 0, j = n - 1; // 当前未处理区间的左右端点
        int ans = 0;

        while (i <= j) {
            bool matched = false;
            int maxLen = (j - i + 1) / 2; // 段长最多取区间一半
            for (int l = 1; l <= maxLen; l++) {
                // 比较左端 text[i..i+l-1] 与右端 text[j-l+1..j]
                if (text.compare(i, l, text, j - l + 1, l) == 0) {
                    ans += 2;   // 成功配对，贡献两段
                    i += l;
                    j -= l;
                    matched = true;
                    break;      // 取最短匹配即停
                }
            }
            if (!matched) {
                // 剩余中间部分单独成一段
                ans += 1;
                break;
            }
        }
        return ans;
    }
};

Python 实现

class Solution:
    def longestDecomposition(self, text: str) -> int:
        n = len(text)
        i, j = 0, n - 1  # 当前未处理区间的左右端点
        ans = 0

        while i <= j:
            matched = False
            max_len = (j - i + 1) // 2  # 段长最多取区间一半
            for l in range(1, max_len + 1):
                # 比较左端 text[i:i+l] 与右端 text[j-l+1:j+1]
                if text[i:i + l] == text[j - l + 1:j + 1]:
                    ans += 2   # 成功配对，贡献两段
                    i += l
                    j -= l
                    matched = True
                    break      # 取最短匹配即停
            if not matched:
                # 剩余中间部分单独成一段
                ans += 1
                break
        return ans
