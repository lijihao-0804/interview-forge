题目与约束

给你一个整数数组 arr，只有可以将其划分为三个和相等的 非空 部分时才返回 true，否则返回 false。

形式上，如果可以找出索引 i + 1 < j 且满足 (arr[0] + arr[1] + ... + arr[i] == arr[i + 1] + arr[i + 2] + ... + arr[j - 1] == arr[j] + arr[j + 1] + ... + arr[arr.length - 1]) 就可以将数组三等分。

示例 1：

输入：arr = [0,2,1,-6,6,-7,9,1,2,0,1]
输出：true
解释：0 + 2 + 1 = -6 + 6 - 7 + 9 + 1 = 2 + 0 + 1

示例 2：

输入：arr = [0,2,1,-6,6,7,9,-1,2,0,1]
输出：false

示例 3：

输入：arr = [3,3,6,5,-2,2,5,1,-9,4]
输出：true
解释：3 + 3 = 6 = 5 - 2 + 2 + 5 + 1 - 9 + 4

提示：

  • 3 <= arr.length <= 5 * 104

  • -104 <= arr[i] <= 104

核心不变量

三段和相等 ⇒ 每段和必然是 总和 / 3；因此只要总和能被 3 整除，从左往右每累计到一次 target = 总和 / 3 就切出一段，切满 3 段即成功。

完整推导

思路推导

  1. 先算总账（必要条件） 设三段每段和为 target，那么 3 * target 必须等于数组总和 total。所以第一步先求 total，若 total % 3 != 0，无论怎么切都不可能，直接返回 false。

  2. 从左往右“凑够一段就切” 令 target = total / 3，用 cur 累加当前正在凑的这一段。一旦 cur == target，说明这一段合法，于是 count++ 并把 cur 清零，重新开始凑下一段。这就是贪心：每一段只关心“和恰好为 target”，越早切越不会影响后续，因为切点之前的元素已被消费，切点之后仍是一段连续区间。

  3. 小例子 arr = [3,3,6,5,-2,2,5,1,-9,4]，总和 18，target = 6。依次累加： 3→3，+3→6（恰好等于 6，切第一段，count=1，清零）； +6→6（切第二段，count=2，清零）； 接着 5→5，-2→3，+2→5，+5→10，+1→11，-9→2，+4→6（切第三段，count=3）。 共切出 3 段，返回 true。

  4. 为什么 count >= 3 就够 当第 3 段切完时，已累计的元素和正好是 3 * target = total；即使后面还有元素，它们的和也必然为 0，可以并入第三段而不改变其和，因此三段依然各自等于 target。用“恰好等于才切”的计数法，每计入一段前 cur 都从 0 开始且至少加入了一个元素，自然保证每段非空。所以只要 count >= 3 即返回 true。

Java 实现（一次遍历计数法）

class Solution {
    public boolean canThreePartsEqualSum(int[] arr) {
        int total = 0;
        for (int x : arr) {
            total += x;
        }
        // 三段和相等，总和必须能被 3 整除
        if (total % 3 != 0) {
            return false;
        }

        int target = total / 3;
        int count = 0;  // 已凑出的段数
        int cur = 0;    // 当前段的和

        for (int x : arr) {
            cur += x;
            // 只有恰好等于目标和才切一段（target 可能为 0，不能用 >=）
            if (cur == target) {
                count++;
                cur = 0;
            }
        }
        // 切出至少 3 段即可（全 0 / 尾部余 0 的情况也成立）
        return count >= 3;
    }
}

复杂度

  • 时间：O(n)。一次求总和、一次遍历计数，均为线性扫描。
  • 空间：O(1)。只用了 total / target / count / cur 几个变量。

易错点与扩展（面试高频考点）

  1. 忘记先判 total % 3：不整除时直接不可能，提前返回可避免后续无意义计算。
  2. target 可能为 0：此时必须“恰好等于才切”，写成 cur >= target 会导致全 0 数组判断错误。
  3. count >= 3 而不是 == 3：全 0 数组或尾部还有 0 时 count 会大于 3，用 >= 才正确。
  4. 元素可为负数：中途 cur 超过 target 并不代表失败，后面可能被负数拉回，必须继续扫描而非提前退出。
  5. 非空约束：计数法天然保证每段至少一个元素（每段都是从 cur = 0 起加入元素后才判断），无需额外检查。

C++ 实现

#include <vector>
using namespace std;

class Solution {
public:
    bool canThreePartsEqualSum(vector<int>& arr) {
        int total = 0;
        for (int x : arr) {
            total += x;
        }
        if (total % 3 != 0) {
            return false;               // 总和无法三等分
        }

        int target = total / 3;
        int count = 0, cur = 0;
        for (int x : arr) {
            cur += x;
            if (cur == target) {         // 恰好等于目标和就切一段
                count++;
                cur = 0;
            }
        }
        return count >= 3;
    }
};

Python 实现

class Solution:
    def canThreePartsEqualSum(self, arr: list[int]) -> bool:
        total = sum(arr)
        if total % 3 != 0:
            return False

        target = total // 3
        count = 0
        cur = 0
        for x in arr:
            cur += x
            if cur == target:      # 恰好等于目标和就切一段
                count += 1
                cur = 0
        return count >= 3
