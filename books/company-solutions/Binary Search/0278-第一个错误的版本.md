# 278. 第一个错误的版本

| 题目信息 | 内容 |
|---|---|
| 难度 | 简单 |
| 核心模式 | 二分查找（寻找第一个满足条件的边界） |
| 时间复杂度 | O(log n) |
| 空间复杂度 | O(1) |

## 题目与约束

你是产品经理，目前正在带领一个团队开发新的产品。不幸的是，你的产品的最新版本没有通过质量检测。由于每个版本都是基于之前的版本开发的，所以错误的版本之后的所有版本都是错的。

假设你有 `n` 个版本 `[1, 2, ..., n]`，你想找出导致之后所有版本出错的第一个错误的版本。

你可以通过调用 `bool isBadVersion(version)` 接口来判断版本号 `version` 是否在单元测试中出错。实现一个函数来查找第一个错误的版本。你应该尽量减少对调用 API 的次数。

 

示例 1：

```
<strong>输入：</strong>n = 5, bad = 4
<strong>输出：</strong>4
<strong>解释：</strong>
调用 isBadVersion(3) -> false 
调用 isBadVersion(5) -> true 
调用 isBadVersion(4) -> true
所以，4 是第一个错误的版本。
```

示例 2：

```
<strong>输入：</strong>n = 1, bad = 1
<strong>输出：</strong>1
```

 

提示：

- `1 <= bad <= n <= 231 - 1`

[🔗 前往力扣原题验证 →](https://leetcode.cn/problems/first-bad-version/)

## 核心不变量

> 版本好坏具有单调性：存在分界点 `k`，使得 `[1, k-1]` 全部是好的、`[k, n]` 全部是坏的。二分不断收缩区间，直到锁定这个分界点 `k`。

## 完整推导

### 思路推导

1. **直觉与痛点（线性扫描太慢）**

   从版本 1 开始逐个调用 `isBadVersion`，找到第一个 `true` 就停——最坏要调用 `n` 次。而 `n` 最大可达 `2^31 - 1`，线性扫描既慢又浪费调用次数。

2. **利用单调性**

   关键性质：一旦某个版本出错，它后面的所有版本都出错。于是坏版本的状态是一段连续的"后缀"：前面全好、后面全坏。问题就变成经典的**寻找第一个满足条件的元素**。

3. **二分收缩**

   令 `lo = 1`、`hi = n`。每次取中点 `mid`：
   - 若 `isBadVersion(mid)` 为真，说明 `mid` 是坏版本，答案在 `[lo, mid]` 之内（`mid` 本身可能就是答案），令 `hi = mid`；
   - 若为假，说明 `mid` 及之前都是好版本，答案在 `[mid+1, hi]`，令 `lo = mid + 1`。

   区间每次减半，当 `lo == hi` 时，`lo` 就是第一个坏版本。

4. **防溢出技巧**

   `mid = (lo + hi) / 2` 在 `lo + hi` 接近 `2^31` 时会整数溢出，应写成 `mid = lo + (hi - lo) / 2`。

### Java 实现（firstBadVersion）

```java
/* The isBadVersion API is defined in the parent class VersionControl.
      boolean isBadVersion(int version); */

public class Solution extends VersionControl {
    public int firstBadVersion(int n) {
        int lo = 1, hi = n;
        while (lo < hi) {
            // 防溢出写法，避免 (lo + hi) 超过 int 上限
            int mid = lo + (hi - lo) / 2;
            if (isBadVersion(mid)) {
                // mid 是坏版本，答案在 [lo, mid]，mid 可能就是答案
                hi = mid;
            } else {
                // mid 是好版本，答案只能在 mid 之后
                lo = mid + 1;
            }
        }
        return lo; // lo == hi，即第一个坏版本
    }
}
```

### 复杂度

- 时间：`O(log n)`，每次把搜索区间缩小一半，最多约 `log₂ n` 次 `isBadVersion` 调用。
- 空间：`O(1)`，只使用 `lo`、`hi`、`mid` 几个变量。

### 易错点与扩展（面试高频考点）

1. **`mid` 的溢出**：`(lo + hi) / 2` 在 `n` 接近 `2^31 - 1` 时会溢出，必须用 `lo + (hi - lo) / 2`。
2. **命中时 `hi = mid` 而非 `mid - 1`**：因为 `mid` 本身可能就是第一个坏版本，不能直接跳过。
3. **循环条件 `lo < hi`**：结束时 `lo == hi` 即为答案，返回 `lo`。
4. **初始 `lo = 1`**：版本编号从 1 开始，不是 0。
5. **这是"二分找左边界"模板**：与"找第一个 ≥ target 的位置"结构一致，是面试中必须背熟的边界二分写法。
