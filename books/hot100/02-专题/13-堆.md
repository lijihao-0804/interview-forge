## Java 模式：堆

### 识别信号

动态 Top K、数据流中位数、多路合并。

堆不负责全局排序，只负责随时给出当前候选中的极值。

### Java 核心不变量

> 堆只维护当前真正需要的候选集合。

### 下笔顺序

1. 先决定堆顶应该是谁
2. Top K 通常只保留 k 个
3. 对象比较器避免用减法造成溢出

### 工具箱

Top K、多路归并、双堆。完整模板见 [Hot 100 算法模板](../04-模板/01-Hot100算法模板.md)。

## Python 模式：堆

堆用于持续取得候选中的极值。先决定堆顶应是什么，再决定何时把不够好的元素挤出去。

### 小顶堆看守当前最有价值的 k 个候选

找 `[4,1,7,3,2]` 中第 2 大的数时，只维护容量 2 的最小堆：

| 读入 | 入堆后的堆顶 | 是否超容量 | 淘汰后保留 |
|---:|---:|---|---|
| 4 | 4 | 否 | `{4}` |
| 1 | 1 | 否 | `{1,4}` |
| 7 | 1 | 是，弹出 1 | `{4,7}` |
| 3 | 3 | 是，弹出 3 | `{4,7}` |
| 2 | 2 | 是，弹出 2 | `{4,7}` |

堆顶 4 就是当前第 2 大。较小的新值进入后只会暂时占据堆顶，随后立刻被淘汰；比堆顶大的值进入，原来的最小值离开。

347 题不是找第 k 大数值，而是找频次最高的 k 个键。把候选改成 `(frequency, value)` 后，堆顶仍是“当前保留项里频次最低、最容易淘汰”的那一个。

### 双堆维护中位数

295 题把较小的一半放进大顶堆，较大的一半放进小顶堆。插入后要恢复“两个堆顶有序、大小差不超过 1”的状态，答案才能直接由两个堆顶给出。

### Python 模板：容量为 k 的频次小顶堆

模板解决 347 题的前 k 个高频元素。堆按 `(频次, 数值)` 比较并只保留 k 项；题目未规定同频元素的先后时可返回其中任意一组。

> 参考来源：代码随想录（programmercarl.com）


```python
from collections import Counter
import heapq


def top_k_frequent(nums: list[int], k: int) -> list[int]:
    counts = Counter(nums)
    heap = []
    for value, frequency in counts.items():
        heapq.heappush(heap, (frequency, value))
        if len(heap) > k:
            heapq.heappop(heap)
    answer = [0] * k
    for index in range(k - 1, -1, -1):
        answer[index] = heapq.heappop(heap)[1]
    return answer
```


### 堆、排序与 Python 3.12

`heappush` 与 `heappop` 都维护堆性质，单次操作 O(log k)。流式扫描时不必保存完整前 k 候选；超过容量就淘汰堆顶。

判题环境限定为 Python 3.12 / CPython，标准库 `heapq` 以最小堆接口工作。需要最大堆时可存入负值，或使用自定义包装器。

模板最后从堆中连续弹出，并倒序写入答案。时间复杂度为计数 O(n)、维护堆 O(m log k)、输出 O(k log k)，额外空间为频次表和 O(k) 堆。
