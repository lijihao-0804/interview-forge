### 📝 算法笔记：3. 无重复字符的最长子串 (Longest Substring Without Repeating Characters)

------

- **📌 核心题意**：

  给定一个字符串 `s` ，请你找出其中不含有重复字符的 **最长 子串**的长度。

  **示例 1:**

  **输入:**s = "abcabcbb"
  **输出:**3 
  **解释:** 因为无重复字符的最长子串是 `"abc"`，所以其长度为 3。注意 "bca" 和 "cab" 也是正确答案。

  **示例 2:**

  **输入:**s = "bbbbb"
  **输出:**1
  **解释:**因为无重复字符的最长子串是 `"b"`，所以其长度为 1。

  **示例 3:**

  **输入:**s = "pwwkew"
  **输出:**3
  **解释:**因为无重复字符的最长子串是 `"wke"`，所以其长度为 3。
       请注意，你的答案必须是 **子串**的长度，`"pwke"` 是一个*子序列，*不是子串。

  **提示：**

  - `0 <= s.length <= 105`
  - `s` 由英文字母、数字、符号和空格组成

- **🧠 思考过程**：

  1. **直觉与痛点（暴力枚举）**：

     搞两个 `for` 循环找遍所有的子串，再写一个函数检查每个子串里有没有重复字符。

     **痛点**：时间复杂度高达 $O(N^3)$。字符串稍长一点就卡死。

  2. **破局思路（滑动窗口 + 哈希表）**：

     我们需要一个“窗口”在字符串上滑动。

     - **右边界（右指针）**：负责主动向右探索，把新的字符拉进窗口。
     - **左边界（左指针）**：负责在遇到危险（出现重复字符）时，向右收缩，把重复的字符踢出窗口。
     - **哈希表**：用来充当“查重神器”。更妙的是，如果哈希表里记录的不仅是字符，而是**字符最后一次出现的索引**，我们的左指针甚至不需要一步步往右挪，可以直接“瞬间跳跃”到重复字符的下一个位置！

  3. **逻辑推演（以 `s = "abcabcbb"` 为例）**：

     窗口起初是空的。`left = 0`, `right = 0`。

     - `right` 遇到 `a`，存入 Map：`{a:0}`。窗口是 `[a]`，长度 1。
     - `right` 遇到 `b`，存入 Map：`{a:0, b:1}`。窗口是 `[a,b]`，长度 2。
     - `right` 遇到 `c`，存入 Map：`{a:0, b:1, c:2}`。窗口是 `[a,b,c]`，长度 3。
     - **高能预警**：`right` 走到索引 3 遇到第二个 `a`。查 Map 发现 `a` 出现过，且位置在索引 0（在当前窗口内）。
     - **左指针跳跃**：为了把旧的 `a` 踢出去，`left` 直接跳到 `旧a的位置 + 1`，也就是索引 1。窗口变成了 `[b,c,a]`。更新 Map 中 `a` 的位置为 3。继续探索……

- **🛠️ Java 规范代码**：

```java
import java.util.HashMap;
import java.util.Map;

class Solution {
    public int lengthOfLongestSubstring(String s) {
        // 定义哈希表：Key 存字符，Value 存该字符最后一次出现的索引
        Map<Character, Integer> map = new HashMap<>();
        
        int maxLength = 0; // 全局最大长度
        int left = 0;      // 窗口的左边界
        
        // right 是窗口的右边界，主动向右扩张
        for (int right = 0; right < s.length(); right++) {
            char c = s.charAt(right);
            
            // 如果遇到了曾见过的字符，并且这个字符【还在我们当前的窗口内】
            if (map.containsKey(c) && map.get(c) >= left) {
                // 左边界直接跳跃到该重复字符上一次出现位置的下一个位置
                // 这样就把那个重复的字符彻底从窗口里“踢”出去了
                left = map.get(c) + 1;
            }
            
            // 记录（或更新）当前字符最新的索引位置
            map.put(c, right);
            
            // 计算当前窗口的长度，并挑战历史最大记录
            // 窗口长度公式：右边界 - 左边界 + 1
            maxLength = Math.max(maxLength, right - left + 1);
        }
        
        return maxLength;
    }
}
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：$O(N)$。右指针把字符串遍历了一次，左指针发生跳跃，没有任何回溯。哈希表的查询和插入都是 $O(1)$。
  - **空间复杂度**：$O(\Sigma)$。其中 $\Sigma$ 是字符集的大小（例如 ASCII 码表共有 128 个字符）。哈希表最多存储 $\Sigma$ 个键值对。

------

#### 💡 面试避坑与考点拓展

1. **致命陷阱（必考坑点）：为什么必须加 `map.get(c) >= left` 这个条件？只写 `map.containsKey(c)` 不行吗？**
   - **大错特错！** 这是无数人挂掉的地方。假设字符串是 `"abba"`。
   - 遍历到第一个 `b`，`left=0`。
   - 遍历到第二个 `b`，遇到重复，`left` 跳到 2。此时窗口里只有 `[b]`。
   - 遍历到最后的 `a`，你查 Map，发现 `a` 确实在 Map 里（之前在索引 0 存过）。如果你不加判断直接 `left = map.get('a') + 1`，你的 `left` 会**倒退**回索引 1！但此时那个旧的 `a` 早就已经被剔除出窗口了，根本不构成重复。
   - **结论**：`map.get(c) >= left` 这个条件是为了确保，**你遇到的这个“老熟人”，确实还赖在你当前的窗口里没走**。如果他在 `left` 左边，说明他早就在之前的收缩中被踢出去了，对当前窗口无影响，直接无视他。
   
2. **极致性能优化（降维打击）**：
   - 面试官问：“能把耗时从 5ms 压到 1ms 吗？”
   
   - 既然题目通常只包含 ASCII 字符，完全可以**用一个长度为 128 的整型数组 `int[]` 来代替 HashMap**。
   
   - 代码：`int[] index = new int[128];`（存的是字符的 ASCII 码对应的最新位置）。因为数组寻址是内存底层操作，比 HashMap 的哈希计算和对象创建快了无数倍。这叫“数组代替哈希表优化法”。

### 📝 算法笔记：438. 找到字符串中所有字母异位词 (Find All Anagrams in a String)

------

- **📌 核心题意**：

  给定两个字符串 `s` 和 `p`，找到 `s`中所有 `p`的 **异位词**的子串，返回这些子串的起始索引。不考虑答案输出的顺序。

  **示例 1:**

  **输入:**s = "cbaebabacd", p = "abc"
  **输出:**[0,6]
  **解释:**
  起始索引等于 0 的子串是 "cba", 它是 "abc" 的异位词。
  起始索引等于 6 的子串是 "bac", 它是 "abc" 的异位词。

  **示例 2:**

  **输入:**s = "abab", p = "ab"
  **输出:**[0,1,2]
  **解释:**
  起始索引等于 0 的子串是 "ab", 它是 "ab" 的异位词。
  起始索引等于 1 的子串是 "ba", 它是 "ab" 的异位词。
  起始索引等于 2 的子串是 "ab", 它是 "ab" 的异位词。

  **提示:**

  - `1 <= s.length, p.length <= 3 * 104`
  - `s` 和 `p` 仅包含小写字母

- **🧠 思考过程**：

  1. **直觉与痛点**：

     如果对 `s` 的每个子串都进行排序再和排序后的 `p` 比较，复杂度会爆炸。

  2. **破局思路（固定窗口 + 频次数组）**：

     - **频次数组**：由于题目说明仅包含小写字母，我们可以用长度为 26 的 `int[]` 数组来代替 HashMap，统计每个字母出现的次数。
     - **固定窗口**：窗口的宽度永远等于 `p.length()`。
     - **滑动逻辑**：窗口每向右移动一位，就“吃进”一个新字符，“吐出”一个旧字符。我们只需要实时维护窗口内的频次数组，并与 `p` 的频次数组进行比对。

  3. **逻辑推演（以 `s = "cbaebabacd", p = "abc"` 为例）**：

     - `p` 的频次数组：`{a:1, b:1, c:1}`。
     - 初始化窗口：前 3 个字符 `cba`。窗口数组：`{a:1, b:1, c:1}`。比对成功，记录索引 `0`。
     - 移动窗口：
       - 吃进 `e`，吐出 `c`。窗口变为 `bae`。比对失败。
       - 吃进 `b`，吐出 `b`。窗口变为 `aeb`（注意吐出的是最左边的字符）。比对失败。
       - ……以此类推。

- **🛠️ Java 规范代码**：

```java
import java.util.*;

class Solution {
    public List<Integer> findAnagrams(String s, String p) {
        List<Integer> result = new ArrayList<>();
        int sLen = s.length();
        int pLen = p.length();
        
        // 如果 s 比 p 还短，绝对不可能存在异位词
        if (sLen < pLen) return result;

        // 1. 定义两个频次数组：一个存标准答案 p，一个存滑动窗口内容
        int[] pCount = new int[26];
        int[] windowCount = new int[26];

        // 2. 初始化：统计 p 的频次，以及 s 中第一个窗口的频次
        for (int i = 0; i < pLen; i++) {
            pCount[p.charAt(i) - 'a']++;
            windowCount[s.charAt(i) - 'a']++;
        }

        // 3. 检查第一个窗口是否匹配
        if (Arrays.equals(pCount, windowCount)) {
            result.add(0);
        }

        // 4. 开始滑动窗口：从索引 pLen 开始遍历 s
        for (int i = pLen; i < sLen; i++) {
            // “吃进”右边的一个字符
            windowCount[s.charAt(i) - 'a']++;
            // “吐出”左边的一个字符（索引为 i - pLen）
            windowCount[s.charAt(i - pLen) - 'a']--;

            // 5. 比对两个数组：Arrays.equals 是 O(26)，即 O(1)
            if (Arrays.equals(pCount, windowCount)) {
                // 异位词的起始索引是吐出位置的下一个，即 i - pLen + 1
                result.add(i - pLen + 1);
            }
        }

        return result;
    }
}
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：$O(N)$。其中 $N$ 是 `s` 的长度。我们只遍历了一遍 `s`。虽然中间有 `Arrays.equals`，但数组长度固定为 26，比较时间是常数级的。
  - **空间复杂度**：$O(1)$。我们使用了两个长度为 26 的整数数组，空间开销不随输入规模增长。

------

#### 💡 面试避坑与考点拓展

- **避坑：千万别忘了处理 `sLen < pLen` 的情况**。如果 `s` 比 `p` 短，直接返回空列表。如果不处理，初始化窗口的循环可能会报越界错误（IndexOutOfBounds）。
- **优化追问：“如果字符集很大（比如 Unicode），不能开数组怎么办？”**
  - **回答**：那就必须用 `HashMap<Character, Integer>` 了。在滑动窗口时，如果某个字符的频率减为 0，记得手动从 Map 中 `remove` 掉那个 Key，否则两个 Map 永远不会相等（因为一个有 `count=0` 的 Key，另一个没有）。
