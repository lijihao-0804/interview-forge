215. 数组中的第K个最大元素

难度中等
Java 主方法大小为 k 的小顶堆 / 快选时间O(n log k)空间O(k)
Python 主方法随机化双指针快速选择时间平均 O(n)，最坏 O(n²)空间O(1) 额外空间

题目与约束

给定整数数组 nums 和整数 k，请返回数组中第 k 个最大的元素。

请注意，你需要找的是数组排序后的第 k 个最大的元素，而不是第 k 个不同的元素。

你必须设计并实现时间复杂度为 O(n) 的算法解决此问题。

示例 1:

输入: [3,2,1,5,6,4], k = 2
输出: 5

示例 2:

输入: [3,2,3,1,2,4,5,5,6],k = 4
输出: 4

提示：

  • 1 <= k <= nums.length <= 105
  • -104 <= nums[i] <= 104

Java 完整推导

Java 核心不变量

堆顶始终是当前前 k 大中的最小者。

解法 1：快速选择版

思路推导

  1. 直觉与痛点（全盘排序的浪费）：

    标准的快速排序或归并排序时间复杂度是 O(N log N)。

    痛点：面试官会问：“我只要第 K 个，你为什么要把所有元素都排好序？这不是杀鸡用牛刀吗？”

  2. 破局思路 1（职场黑客流：优先队列 / 小顶堆）：

    想象你在搞一个选秀节目，只需要选出前 K 强。

    我们可以建一个容量为 K 的小顶堆（Min-Heap）。遍历数组，把人往堆里塞。一旦堆里的人数超过 K 个，就把堆顶那个最弱的（最小的）踢出去。 等所有人都过了一遍，堆里剩下的就是全场最强的 K 个人，而此时的堆顶，正好就是这 K 个人里最弱的，也就是全场第 K 大的元素！

    时间复杂度：O(N log K)。虽然没有严格达到 O(N)，但在处理海量流式数据时，这是王牌解法。

  3. 破局思路 2（算法原教旨主义：快速选择 Quickselect）：

    这是面试官最想看到的 O(N) 终极解法。它脱胎于大名鼎鼎的快速排序（Quicksort）。

    快排的核心是 partition（划分）：随便找一个基准数（Pivot），把比它小的扔左边，比它大的扔右边。

    降维魔法：在排完一次后，基准数会落在一个固定的索引 p 上。

    • 如果 p 恰好等于我们要找的索引（第 K 大对应的索引是 N - K），直接收工！
    • 如果 p < N - K，说明目标在基准数的右边，左边那一半直接像垃圾一样全部丢弃，只去右边递归！
    • 如果 p > N - K，说明目标在左边，右边全部丢弃！

    Java 实现（满分 Quickselect 随机化版）

import java.util.Random;

class Solution {
    private Random random = new Random();

    public int findKthLargest(int[] nums, int k) {
        // 第 K 大的元素，如果把数组从小到大排序，它的目标索引其实是 N - K
        // 比如 6 个元素找第 2 大，排好序后它在索引 6 - 2 = 4 的位置
        int targetIndex = nums.length - k;
        return quickSelect(nums, 0, nums.length - 1, targetIndex);
    }

    private int quickSelect(int[] nums, int left, int right, int targetIndex) {
        // 🌟 致命防御：引入随机化！
        // 如果每次都固定取最右边的数做基准，遇到已经排好序的数组，时间复杂度会退化到 O(N^2)
        // 随机选一个基准，把它和最右边的数交换，可以完美避开极端测试用例的制裁
        int randomIndex = left + random.nextInt(right - left + 1);
        swap(nums, randomIndex, right);

        // 进行一次划分（把比基准小的扔左边，大的扔右边，返回基准最终的落脚点）
        int pivotIndex = partition(nums, left, right);

        // 开始“指哪打哪”的优化思路
        if (pivotIndex == targetIndex) {
            return nums[pivotIndex]; // 一发入魂，直接命中！
        } else if (pivotIndex < targetIndex) {
            // 基准落在目标的左边，说明目标在右半区，左半区彻底抛弃！
            return quickSelect(nums, pivotIndex + 1, right, targetIndex);
        } else {
            // 基准落在目标的右边，说明目标在左半区，右半区彻底抛弃！
            return quickSelect(nums, left, pivotIndex - 1, targetIndex);
        }
    }

    // 标准的快排 Partition 划分函数
    private int partition(int[] nums, int left, int right) {
        int pivot = nums[right]; // 以最右边的元素为基准
        int i = left; // i 指向小于基准的区域的下一个空位

        for (int j = left; j < right; j++) {
            if (nums[j] < pivot) {
                // 发现比基准小的，扔到 i 的位置去，然后 i 往前挪一步
                swap(nums, i, j);
                i++;
            }
        }
        // 最后把基准数换到它该在的中心位置 i 上
        swap(nums, i, right);
        return i; // 返回基准数的最终索引
    }

    private void swap(int[] nums, int i, int j) {
        int temp = nums[i];
        nums[i] = nums[j];
        nums[j] = temp;
    }
}

复杂度

  • 时间复杂度：平均情况 O(N)。第一次划分需要遍历 N 个元素，第二次只需要遍历约 N/2 个，第三次 N/4... 这是一个等比数列，求和极限就是 2N，所以是 O(N)。由于引入了随机化，最坏情况 O(N2) 的概率比被雷劈还小。
  • 空间复杂度：O(log N)。消耗在递归调用栈上。
易错点与扩展（面试的终极拷问）
  1. 面试追问 1：“Quickselect 和 Min-Heap，在实际工程场景中到底怎么选？” - 满分抢答：
    • 如果是静态数据（数组已经固定全部在内存里），选 Quickselect，因为它纯内存原地操作，不需要额外开辟对象，平均时间 O(N) 绝对最快。
    • 如果是动态数据 / 海量数据（Streaming Data）（比如服务器上持续涌入的日志，或者 1TB 的数据内存装不下），必须选 Min-Heap！只需维护一个大小为 K 的堆放在内存里，来一个处理一个，时间复杂度 O(N log K)，内存消耗极小。
  2. 踩坑警告：“第 K 大”与“索引”的转换 - 快排的分区通常是“从小到大”排（左小右大）。 - 面试极其容易在这翻车：如果你用从小到大排的 Partition，第 K 大的数字，它的目标索引必然是 nums.length - k！一定要在开头把这个索引算好，当作靶子传给递归函数。

解法 2：小顶堆版

📝 核心概念：为什么找“最大”反而要用“小顶堆”？

很多初学者的第一个认知陷阱是：“找第 K 大，是不是应该用大顶堆（Max-Heap）？”

Java 实现规范代码（小顶堆模板）

在 Java 中，堆的官方名字叫优先队列（PriorityQueue），默认就是小顶堆，写起来极其优雅：

import java.util.PriorityQueue;

class Solution {
    public int findKthLargest(int[] nums, int k) {
        // 创建一个小顶堆（PriorityQueue 默认就是小顶堆）
        PriorityQueue<Integer> minHeap = new PriorityQueue<>();

        // 让所有元素依次来 VIP 室踢馆
        for (int num : nums) {
            // 先不管三七二十一，让人先进去
            minHeap.offer(num);

            // 如果 VIP 室的人数超过了 K 个
            if (minHeap.size() > k) {
                // 就把最弱的（堆顶）给踢出去！
                minHeap.poll();
            }
        }

        // 踢馆结束，留在堆顶的就是第 K 大的元素
        return minHeap.peek();
    }
}

复杂度

  • 时间复杂度：O(N log K)。遍历 N 个元素，每次入堆/出堆调整的代价是 log K。
  • 空间复杂度：O(K)。这是堆解法最牛的地方！ 不管外面的世界有几十亿个数字，我的内存里永远只需要保存 K 个数字。

Python 完整推导

目标只落在一侧，另一侧就可以整段放弃

找第 k 大元素并不需要把整个数组完全排序。快速选择随机抽一个基准值 pivot，再用左右指针从当前区间两端相向扫描：左边跳过小于 pivot 的值，右边跳过大于 pivot 的值；两边都停下时交换，把较小值送向左侧、较大值送向右侧。

这里并没有另建 less/equal/greater 三个完整区间。与 pivot 相等的值可能留在左、右两侧；当指针交错后，若目标排名仍严格落在 j 与 i 之间，nums[j + 1] 正好是 pivot，否则只进入 target 所在的一侧继续划分。

以 [3, 2, 1, 5, 6, 4]、k = 2 走一次（假设抽到 4）

数组升序后的第 2 大对应下标 target = 6 - 2 = 4。

  1. 本次 pivot 为 4，区间 [0, 5]。i 从左越过 3、2、1，在下标 3 的 5 停下；j 从末尾停在 4。交换后数组为 [3, 2, 1, 4, 6, 5]，指针继续移动并在 i = 4, j = 3 交错。target 落在右段，所以保留区间 [4, 5]。
  2. 下一次假设抽到 pivot 6。区间值 6、5 交换，数组变成 [3, 2, 1, 4, 5, 6]；交错后得到 i = 5, j = 4，target 落在左段，保留区间缩成 [4, 4]。
  3. 最后抽到 pivot 5，它就在目标位置。交换同一个位置后得到 i = 5, j = 3；由于 j < target < i，返回 nums[j + 1] = 5。

不同随机过程会走不同分岔，但只要每轮只进入目标所在的一段，平均扫描量是 n + n/2 + n/4 + ...。若每次固定取某一端，已经有序的输入可能每轮只削掉一个元素，退化到 O(n²)；随机抽取降低了这种划分持续出现的可能。

算法会原地交换数组元素；调用方若还要保留原顺序，需要自行复制。

Python 实现

参考来源：经典解法实现

沿用旧项目“经典解法实现”中的随机快速选择 Python 代码；清理单行分号、补足循环换行，核心的双向双指针交换划分未更换。

import random
from typing import List


class Solution:
    def findKthLargest(self, nums: List[int], k: int) -> int:
        target = len(nums) - k
        left, right = 0, len(nums) - 1
        while True:
            pivot = nums[random.randint(left, right)]
            i, j = left, right
            while i <= j:
                while nums[i] < pivot:
                    i += 1
                while nums[j] > pivot:
                    j -= 1
                if i <= j:
                    nums[i], nums[j] = nums[j], nums[i]
                    i += 1
                    j -= 1

            if target <= j:
                right = j
            elif target >= i:
                left = i
            else:
                return nums[j + 1]

双指针交换分区的 Python 细节

random.randint(left, right) 两端都包含，正好覆盖当前搜索区间。内层扫描中，while nums[i] < pivot 寻找左侧第一个不应继续留在左边的值，while nums[j] > pivot 寻找右侧第一个不应继续留在右边的值；两端停住后交换并继续收缩。

当 i > j 时本轮结束。此时 target <= j 说明目标只在左段，target >= i 说明目标只在右段；若两者都不满足，就一定有 j < target < i，而中间这个位置的值等于 pivot，所以返回 nums[j + 1]。

复杂度边界

这是迭代式快速选择，不创建递归调用栈，额外空间 O(1)。平均时间是 O(n)，但随机化不提供最坏情况保证，最坏仍可能为 O(n²)。面试若强调确定的 O(n log k)，可改用容量 k 的最小堆；若强调流式输入，最小堆也更合适。

复杂度

  • 时间复杂度：平均 O(n)，最坏 O(n²)。
  • 空间复杂度：O(1) 额外空间。

随机划分的平均总扫描长度为 n+n/2+n/4+... = O(n)，最坏可能每轮只缩小一个位置而达到 O(n²)；整个过程只保存指针和 pivot，不创建递归或额外数据结构，额外空间 O(1)。

C++ 实现

实现来源：经典解法实现

  1. 快速选择：partition 后基准落在的位置即最终名次
  2. 基准下标 == 目标下标 → 直接得到答案
  3. 否则只递归包含目标的那一半（平均 O(n)）
class Solution {
public:
    int findKthLargest(vector<int>& nums, int k) {
        int target = nums.size() - k;              // 升序后目标下标
        int lo = 0, hi = nums.size() - 1;
        while (true) {
            int pivot = nums[lo]; int i = lo, j = hi;
            while (i < j) {
                while (i < j && nums[j] >= pivot) j--;
                while (i < j && nums[i] <= pivot) i++;
                swap(nums[i], nums[j]);
            }
            swap(nums[lo], nums[i]);
            if (i == target) return nums[i];
            i < target ? lo = i + 1 : hi = i - 1;
        }
    }
};

Go 实现

实现来源：经典解法实现

  1. 快速选择：partition 后基准落在的位置即最终名次
  2. 基准下标 == 目标下标 → 直接得到答案
  3. 否则只递归包含目标的那一半（平均 O(n)）
func findKthLargest(nums []int, k int) int {
    target := len(nums) - k
    lo, hi := 0, len(nums)-1
    for {
        pivot := nums[lo]
        i, j := lo, hi
        for i < j {
            for i < j && nums[j] >= pivot { j-- }
            for i < j && nums[i] <= pivot { i++ }
            nums[i], nums[j] = nums[j], nums[i]
        }
        nums[lo], nums[i] = nums[i], pivot
        if i == target { return nums[i] }
        if i < target { lo = i + 1 } else { hi = i - 1 }
    }
}

C 实现

实现来源：经典解法实现

  1. 快速选择：partition 后基准落在的位置即最终名次
  2. 基准下标 == 目标下标 → 直接得到答案
  3. 否则只递归包含目标的那一半（平均 O(n)）
int findKthLargest(int* nums, int numsSize, int k) {
    int target = numsSize - k, lo = 0, hi = numsSize - 1;
    while (1) {
        int pivot = nums[lo], i = lo, j = hi;
        while (i < j) {
            while (i < j && nums[j] >= pivot) j--;
            while (i < j && nums[i] <= pivot) i++;
            int t = nums[i]; nums[i] = nums[j]; nums[j] = t;
        }
        nums[lo] = nums[i]; nums[i] = pivot;
        if (i == target) return nums[i];
        if (i < target) lo = i + 1; else hi = i - 1;
    }
}
