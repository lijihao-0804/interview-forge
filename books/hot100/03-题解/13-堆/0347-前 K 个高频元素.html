题目信息 内容
难度 中等
核心模式 频次表 + 小顶堆
时间复杂度 O(n log k)
空间复杂度 O(n)

题目与约束

给你一个整数数组 nums 和一个整数 k ，请你返回其中出现频率前 k 高的元素。你可以按 任意顺序 返回答案。

示例 1：

输入：nums = [1,1,1,2,2,3], k = 2 输出：[1,2]

示例 2：

输入：nums = [1], k = 1 输出：[1]

示例 3：

输入：nums = [1,2,1,2,1,2,3,1,3,2], k = 2 输出：[1,2]

提示：

  • 1 <= nums.length <= 105
  • -104 <= nums[i] <= 104
  • k 的取值范围是 [1, 数组中不相同的元素的个数]
  • 题目数据保证答案唯一，换句话说，数组中前 k 个高频元素的集合是唯一的

进阶：你所设计算法的时间复杂度 必须 优于 O(n log n) ，其中 n是数组大小。

🔗 前往力扣原题验证 →

核心不变量

堆按频次比较，只保留频次最高的 k 个键。

完整推导

思路推导

  1. 直觉与痛点（先统后排）：

    第一步永远是毫无悬念的：用一个哈希表（HashMap）把每个数字出现的次数统计出来。

    痛点：拿到 <数字, 频率> 的映射后怎么排序？如果把所有条目拿出来做一个全局排序，时间复杂度会变成 O(NlogN)，直接被题目要求的硬性底线淘汰。

  2. 破局思路 1（VIP 选秀室重出江湖：小顶堆）：

    既然是找前 K 大（这里是频率的前 K 大），我们完全可以原封不动地照搬上一题的“容量为 k 的小顶堆”战术！

    把 HashMap 里的条目一个个往小顶堆里塞。注意：堆里比较的不再是数字本身的大小，而是数字对应的频率！

    如果堆里超过了 k 个人，就把频率最低的那个踢出去。遍历完 HashMap，堆里留下的就是频率最高的 k 个元素。

    时间复杂度：O(NlogK)，完美通关。

  3. 破局思路 2（面试终极魔法：桶排序 Bucket Sort）：

    面试官微笑地看着你：“O(NlogK) 不错，但你能做到极致的 O(N) 吗？”

    优化思路开始：频率这个东西，有一个天然的上限——一个数字出现的最高频率，撑死也就是数组的总长度 N（全数组都是同一个数字）！

    既然频率的值域这么窄（0 到 N），我们为什么不建一个长度为 N+1 的数组（这就是一组水桶）？

    • 数组的下标（Index）代表频率。

    • 数组里装的内容（Value）代表出现该频率的数字集合。

    这就等于把数据按频率自动归位了！然后我们只需要从后往前（从高频到低频）扫一遍这排水桶，收集到 k 个数字直接下班！

    Java 实现（满分桶排序版 O(N)）

    (在面试中，写出小顶堆算及格，写出桶排序是绝对的 Senior 级别)

import java.util.ArrayList;
import java.util.HashMap;
import java.util.List;
import java.util.Map;

class Solution {
    public int[] topKFrequent(int[] nums, int k) {
        // 1. 战前准备：用 HashMap 统计每个数字的出现频率
        Map<Integer, Integer> countMap = new HashMap<>();
        for (int num : nums) {
            countMap.put(num, countMap.getOrDefault(num, 0) + 1);
        }

        // 2. 建立桶数组：下标代表频率，值代表拥有该频率的数字列表
        // 🌟 致命细节：桶的数量必须是 nums.length + 1，因为如果有数字出现了 N 次，下标需要能取到 N
        List<Integer>[] buckets = new List[nums.length + 1];

        // 把 HashMap 里的数据倒进桶里
        for (Map.Entry<Integer, Integer> entry : countMap.entrySet()) {
            int num = entry.getKey();
            int freq = entry.getValue();

            // 如果这个频率的桶还没建好，先初始化一个 List
            if (buckets[freq] == null) {
                buckets[freq] = new ArrayList<>();
            }
            // 把数字扔进对应频率的桶里
            buckets[freq].add(num);
        }

        // 3. 逆向扫桶：从最高频率往下扫，收集前 k 个数字
        int[] res = new int[k];
        int index = 0;

        // 从最右边（最高频）开始往左看
        for (int i = buckets.length - 1; i >= 0 && index < k; i--) {
            // 如果这个频率的桶里有数字
            if (buckets[i] != null) {
                // 把桶里的数字全部收缴，直到收满 k 个为止
                for (int num : buckets[i]) {
                    res[index++] = num;
                    if (index == k) {
                        return res; // 🌟 收满 k 个，立刻准点下班！
                    }
                }
            }
        }

        return res;
    }
}

复杂度

  • 时间复杂度：O(N)。统计频率遍历一遍 N；把数据倒进水桶遍历一遍不同数字的个数（小于等于 N）；最后逆向扫一遍桶数组（长度为 N+1）。全程没有比较排序，纯正的线性时间！
  • 空间复杂度：O(N)。主要开销在 HashMap 和桶数组 buckets 上，它们的大小都不会超过数组的总长度 N。

易错点与扩展（面试的连环计）

  • 面试追问：“既然桶排序这么快，为什么上一题【第 K 大的元素】我们不用桶排序？”
  • 满分抢答（直击底层逻辑）：这取决于值域的跨度！
  • 在这道题里，我们要排序的维度是“频率”。频率的最小是 1，最大是数组长度 N，值域非常紧凑，所以可以开辟长度为 N+1 的桶数组，空间消耗极其合理。
  • 而在上一题里，我们要排序的维度是“数值本身”！如果数组里只有两个数字：[1, 2147483647]。为了这两个数字，难道我要在内存里开辟一个长度为 21 亿的桶数组吗？内存当场就炸毁了。
  • 一句话总结：值域紧凑且有明确上限，优先用桶排序（计数排序）；值域跨度巨大或存在负数/浮点数，老老实实用堆（优先级队列）或快速选择。
