## 题目与约束

**中位数**是有序整数列表中的中间值。如果列表的大小是偶数，则没有中间值，中位数是两个中间值的平均值。

  - 例如 `arr = [2,3,4]` 的中位数是 `3` 。
  - 例如 `arr = [2,3]` 的中位数是 `(2 + 3) / 2 = 2.5` 。

  实现 MedianFinder 类:

  - `MedianFinder()` 初始化 `MedianFinder` 对象。
  - `void addNum(int num)` 将数据流中的整数 `num` 添加到数据结构中。
  - `double findMedian()` 返回到目前为止所有元素的中位数。与实际答案相差 `10-5` 以内的答案将被接受。

  **示例 1：**

  **输入**
  ["MedianFinder", "addNum", "addNum", "findMedian", "addNum", "findMedian"]
  [[], [1], [2], [], [3], []]
  **输出**
  [null, null, null, 1.5, null, 2.0]

  **解释**
  MedianFinder medianFinder = new MedianFinder();
  medianFinder.addNum(1);    // arr = [1]
  medianFinder.addNum(2);    // arr = [1, 2]
  medianFinder.findMedian(); // 返回 1.5 ((1 + 2) / 2)
  medianFinder.addNum(3);    // arr[1, 2, 3]
  medianFinder.findMedian(); // return 2.0

  **提示:**

  - `-105 <= num <= 105`
  - 在调用 `findMedian` 之前，数据结构中至少有一个元素
  - 最多 `5 * 104` 次调用 `addNum` 和 `findMedian`

- **时间复杂度**：
  - `addNum`：$O(\log N)$。每次插入和弹出操作都是对二叉堆的调整，代价是对数级别的。
  - `findMedian`：$O(1)$。中位数永远就在两个堆的嘴尖上（堆顶），看一眼直接返回，极速响应。
- **空间复杂度**：$O(N)$。需要两个堆合力装下数据流里的所有数字。

## 完整推导

### 思路推导
1. **直觉与痛点（动态排序的绝望）**：

   中位数把所有数字分成了“左边较小的一半”和“右边较大的一半”。

   如果用动态数组 `ArrayList` 维护，新来一个数，为了保持有序，我们需要用二分查找找到位置并插入，移动元素需要 $O(N)$ 的时间。数据量一旦大起来，动态插入会彻底卡死。

2. **降维破局（双堆对顶，各据一方）**：

   我们其实**根本不需要让所有数字都严格有序**！我们只需要牢牢把控住“左半区的最大值”和“右半区的最小值”。

### 易错点与扩展（面试高频连环追问）

- **面试进阶追问 1：“如果数据流中 99% 的数字都在 0 到 100 之间，你还用双堆吗？”**
  - **满分抢答（计数排序大显神威）**：这时候用堆就亏大了！既然数字范围极度紧凑（[0, 100]），我们应该直接开辟一个长度为 101 的**计数数组（Bucket）**！
  - 每次来一个数，对应的频次加 1（`count[num]++`），耗时 $O(1)$。
  - 寻找中位数时，我们维护一个全局总数 `N`，直接从 0 到 100 累加频次，找到第 $N/2$ 个数字对应的位置。因为桶的长度只有 101，这个遍历也是 $O(1)$ 的常数级！空间更是压缩到了极点。
- **面试进阶追问 2：“如果 99% 的数字在 0 到 100 之间，但有 1% 的数字是不可预测的巨大超级大离群点（Outliers）呢？”**
  - **高级风控架构方案**：我们可以把两个方案缝合起来！
  - 用一个长度为 101 的数组记录 [0, 100] 内的正常数字，并记录低于 0 的个数和高于 100 的个数。
  - 对于那些极少数越界的超级大离群点，我们单独用**两个小规模的双堆**去挂载在两头。在寻找中位数时，先排除两边的离群点数量，再定位到中央的计数数组中。这种“主仓+边缘流控”的设计思想，直接对齐现代分布式大数据的风控模型。
