## 题目与约束

给定一个整数数组 `temperatures` ，表示每天的温度，返回一个数组 `answer` ，其中 `answer[i]` 是指对于第 `i` 天，下一个更高温度出现在几天后。如果气温在这之后都不会升高，请在该位置用 `0` 来代替。

  **示例 1:**

  **输入:** temperatures = [73,74,75,71,69,72,76,73]<br>**输出:** [1,1,4,2,1,1,0,0]

  **示例 2:**

  **输入:** temperatures = [30,40,50,60]<br>**输出:** [1,1,1,0]

  **示例 3:**

  **输入:** temperatures = [30,60,90]<br>**输出:**[1,1,0]

  **提示：**

  - `1 <= temperatures.length <= 105`
  - `30 <= temperatures[i] <= 100`

## 完整推导

### 思路推导
  1. **直觉与痛点（暴力的代价）**：

     最直观的做法是两层 `for` 循环：站在今天，向后一天一天地看，直到找到一个比今天热的日子。

     **痛点**：如果气温是连降一个月，最后一天才突然升温（比如 `[100, 99, 98, ..., 1, 101]`），每次查找都要遍历后面的所有日子，时间复杂度直接飙升到 $O(N^2)$，在庞大的数据量下面试必挂。

  2. **破局思路（引入“悬而未决等待室”）**：

     我们换个思路：与其站在今天往**未来**看，不如站在今天向**过去**看！

     我们可以准备一个**栈（等待室）**。那些还没找到更暖和日子的天数，都在这个等待室里排队。

     - 假设等待室里坐着 `75度`、`71度`、`69度`（从老到新，温度越来越低，都在苦苦等待升温）。
     - 突然，今天来了一个 **`72度`** 的日子！
     - 此时，等待室里最外面的 `69度` 激动地跳起来：“我等到了！比我暖和的日子来了！”于是 `69度` 结算距离，离开等待室。
     - 接着 `71度` 也跳起来：“我也等到了！”结算，离开。
     - 再往里面看，`75度` 叹了口气：“72 还是没我高，我接着等吧。”
     - 结算完毕后，今天的 `72度` 也坐进等待室，因为属于它的更高温度还没来。

  3. **核心微操（存索引而不是存温度）**：

     题目要求返回的是“**几天后**（天数差）”。

     如果我们在栈里只存温度 `71`，等升温时，我们根本不知道 `71` 是哪一天存进去的！

     **致命技巧**：栈里面**只存数组的索引（日子的编号）**！用索引不仅能通过 `temperatures[index]` 查到当天的温度，还能在出栈时直接用 `当前索引 - 栈顶索引` 算出等待了几天！
### Java 实现（满分单调栈模板）
```Java
import java.util.ArrayDeque;
import java.util.Deque;

class Solution {
    public int[] dailyTemperatures(int[] temperatures) {
        int n = temperatures.length;
        int[] answer = new int[n];

        // 🌟 核心利器：单调栈（Monotonic Stack）
        // 栈里存的是【索引】，并且这些索引对应的温度，从栈底到栈顶是【严格递减】的
        Deque<Integer> stack = new ArrayDeque<>();

        for (int i = 0; i < n; i++) {
            // 当前这天的温度
            int currentTemp = temperatures[i];

            // 只要栈没空，并且【今天的温度】打败了【栈顶索引对应的历史温度】
            // 说明栈顶的那个日子，终于等到了它的升温日！
            while (!stack.isEmpty() && currentTemp > temperatures[stack.peek()]) {
                // 弹出栈顶的倒霉蛋（历史索引）
                int prevIndex = stack.pop();
                // 结算它等了多少天：今天(i) - 历史(prevIndex)
                answer[prevIndex] = i - prevIndex;
            }

            // 历史的恩怨结算完了（或者今天比栈顶还冷），把今天也关进等待室接着等
            stack.push(i);
        }

        // 循环结束后，栈里可能还有剩下的索引。
        // 它们等到了最后一天也没等来升温，answer 数组初始化默认就是 0，所以不需要额外处理了！
        return answer;
    }
}
```
### 复杂度
  - **时间复杂度**：$O(N)$。很多初学者看到 `for` 里面套了个 `while` 就以为是 $O(N^2)$。大错特错！请注意，数组中的每一个元素，**最多入栈一次，出栈一次**。没有任何元素会被重复操作，所以总的时间复杂度是严丝合缝的线性时间。这也是单调栈的降维威力！
  - **空间复杂度**：$O(N)$。在最坏的情况下（比如气温一直下降，没人能出栈），栈的深度等于数组的长度。

### 易错点与扩展（面试的底层拷问）

1. **面试追问 1：“为什么这个数据结构叫【单调栈】？”**
   - **满分回答**：因为在任何时刻，栈内元素保持着极其严格的**单调性**。在这道题里，如果当前元素比栈顶小，它直接入栈；如果比栈顶大，它会像贪吃蛇一样把比自己小的元素全部“吃掉（弹出）”后才入栈。这就保证了从栈底到栈顶，温度一定是严格递减（单调递减）的。
2. **面试追问 2：“如果我要求找【上一个更冷的元素】，栈该怎么维护？”**
   - **秒杀口诀**：这是单调栈的终极规律，建议死记硬背加理解：
     - 找 **下一个更大**（本题）：从左到右遍历，维护一个**单调递减栈**。
     - 找 **下一个更小**：从左到右遍历，维护一个**单调递增栈**。
     - 找 **上一个更大/更小**：改变思维，本质上就是当前元素在被弹出时，把它弹出的那个元素，或者它压在底下的那个元素。

## Python 完整推导

### 思路推导

站在今天，向后一天一天地找，当然能找到比今天更暖的日子。但假如温度一直下降，每一天都要把后面重新看一遍，很多查找就重复了。

我们换个方向：**今天的温度，能不能替前面那些还在等待的日子揭晓答案？**

准备一个栈，把它当成“等待室”。里面只放还没找到下一次升温的日子。

假设等待室里从里到外坐着 `75℃、71℃、69℃`。今天来了 `72℃`：

1. 最外面的 `69℃` 等到了升温，算出相隔几天，离开等待室。
2. 接着 `71℃` 也等到了，同样结算、离开。
3. 再往里看是 `75℃`，今天还没有它暖，先停下。
4. 今天的 `72℃` 也进去等待，因为属于它的下一次升温还没来。

这就是为什么一次比较之后要继续用 `while`：**今天可能同时给好几个过去的日子带来答案。**

### 跟着一个完整例子走

输入为 `temperatures = [73, 74, 75, 71, 69, 72, 76, 73]`。日期编号从 `0` 开始。

栈里不能只存温度。假如弹出来一个 `71`，我们还得知道它是哪一天，才能计算等待天数。因此，**存日期编号，用 `temperatures[编号]` 查温度**。下表中的栈都按“栈底 → 栈顶”列出。

| 今天 | 温度 | 今天做了什么 | 处理完后，等待室里的日期编号 |
|---|---|---|---|
| 0 | 73 | 没有过去的日子要结算，自己入栈 | `[0]` |
| 1 | 74 | 比第 0 天暖，填 `answer[0] = 1 - 0 = 1`；第 1 天入栈 | `[1]` |
| 2 | 75 | 比第 1 天暖，填 `answer[1] = 2 - 1 = 1`；第 2 天入栈 | `[2]` |
| 3 | 71 | 不比栈顶的 75 暖，先进去等 | `[2, 3]` |
| 4 | 69 | 不比栈顶的 71 暖，也进去等 | `[2, 3, 4]` |
| 5 | 72 | 先结算第 4 天，等了 `5 - 4 = 1` 天；再结算第 3 天，等了 `5 - 3 = 2` 天；遇到 75 停下 | `[2, 5]` |
| 6 | 76 | 先结算第 5 天，等了 1 天；再结算第 2 天，等了 `6 - 2 = 4` 天 | `[6]` |
| 7 | 73 | 没有超过栈顶的 76，第 7 天入栈 | `[6, 7]` |

最后，第 6、7 天都没有等来更暖的日子。答案一开始就全是 `0`，它们保持原样即可。

得到结果：`[1, 1, 4, 2, 1, 1, 0, 0]`。

### 为什么找到的是“下一次”升温？

我们按日期从左往右走。一个日子还在栈里，就说明前面已经经过的这些天，都没能让它升温；今天第一次把它弹出来，今天自然就是它等到的第一个更暖的日子。

### Python 实现

> 参考来源：代码随想录（programmercarl.com）
>
> 代码采用项目原收录的代码随想录实现；按原 Java 叙述整理循环、变量及注释，算法未改变。

```python
from typing import List


class Solution:
    def dailyTemperatures(self, temperatures: List[int]) -> List[int]:
        answer = [0] * len(temperatures)
        stack = []  # 保存还没等到升温的日期编号

        for i, temperature in enumerate(temperatures):
            while stack and temperature > temperatures[stack[-1]]:
                previous = stack.pop()
                answer[previous] = i - previous

            stack.append(i)

        return answer
```

### 这几行 Python 对应什么动作？

- `stack[-1]`：看看等待室最外面的日期，不把它取走。
- `stack.pop()`：取出并移除最外面的日期。它现在等到了答案，后面不用再管。
- `stack.append(i)`：把今天放到等待室最外面。
- `while stack and ...`：先确认栈不为空，再读取 `stack[-1]`。`and` 的短路求值会在空栈时停止，不会越界。

### 两个容易写错的地方

**相同温度不算升温。** 比较要写 `>`，不能写 `>=`。例如 `[70, 70, 71]`，前两天都要等到 `71`，结果应为 `[2, 1, 0]`。也正因为相等温度可以同时留在栈中，栈中温度是非递增的，而不是严格递减。

**填答案用的是日期差。** `i - previous` 是等了几天；温度之差不是本题要求的答案。

### 复杂度

- 时间复杂度：`O(n)`。
- 空间复杂度：`O(n)`。

每个日期只入栈一次、最多出栈一次，所有 while 迭代总数不超过 n，因此时间 O(n)；最坏情况下所有日期都留在栈中，额外空间 O(n)，不计返回的答案数组。

## C++ 实现

> 实现来源：代码随想录（programmercarl.com）



```cpp
// 版本一
class Solution {
public:
    vector<int> dailyTemperatures(vector<int>& T) {
        // 递增栈
        stack<int> st;
        vector<int> result(T.size(), 0);
        st.push(0);
        for (int i = 1; i < T.size(); i++) {
            if (T[i] < T[st.top()]) {                       // 情况一
                st.push(i);
            } else if (T[i] == T[st.top()]) {               // 情况二
                st.push(i);
            } else {
                while (!st.empty() && T[i] > T[st.top()]) { // 情况三
                    result[st.top()] = i - st.top();
                    st.pop();
                }
                st.push(i);
            }
        }
        return result;
    }
};
```

```go
func dailyTemperatures(t []int) []int {
    var res []int
    for i := 0; i < len(t)-1; i++ {
        j := i + 1
        for ; j < len(t); j++ {
            // 如果之后出现更高，说明找到了
            if t[j] > t[i] {
                res = append(res, j-i)
                break
            }
        }
        // 找完了都没找到
        if j == len(t) {
            res = append(res, 0)
        }
    }
    // 最后一个肯定是 0
    return append(res, 0)
}
```

## C 实现

> 实现来源：代码随想录（programmercarl.com）



```c
/**
 * Note: The returned array must be malloced, assume caller calls free().
 */
int* dailyTemperatures(int* temperatures, int temperaturesSize, int* returnSize) {
    int len = temperaturesSize;
    *returnSize = len;

    int *result = (int *)malloc(sizeof(int) * len);
    memset(result, 0x00, sizeof(int) * len);

    int stack[len];
    memset(stack, 0x00, sizeof(stack));
    int top = 0;

    for (int i = 1; i < len; i++) {
        if (temperatures[i] <= temperatures[stack[top]]) { /* push */
            stack[++top] = i;
        } else {
            while (top >= 0 && temperatures[i] > temperatures[stack[top]]) { /* stack not empty */
                result[stack[top]] = i - stack[top];
                top--; /* pop */
            }
            stack[++top] = i; /* push */
        }
    }
    return result;
}
```
