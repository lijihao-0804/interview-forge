难度 简单
核心模式 栈保存期待的右括号
时间复杂度 O(n)
空间复杂度 O(n)

题目与约束

给定一个只包括 '('，')'，'{'，'}'，'['，']' 的字符串 s ，判断字符串是否有效。

有效字符串需满足：

  1. 左括号必须用相同类型的右括号闭合。
  2. 左括号必须以正确的顺序闭合。
  3. 每个右括号都有一个对应的相同类型的左括号。

示例 1：

输入：s = "()" 输出：true

示例 2：

输入：s = "()[]{}" 输出：true

示例 3：

输入：s = "(]" 输出：false

示例 4：

输入：s = "([])" 输出：true

示例 5：

输入：s = "([)]" 输出：false

提示：

  • 1 <= s.length <= 104
  • s 仅由括号 '()[]{}' 组成

核心不变量

遇到右括号时必须与栈顶期待值一致。

完整推导

思路推导

  1. 直觉与痛点（为什么不能用计数器？）：

    有的同学第一反应是：我数一下左括号和右括号的数量不就行了？保证数量相等。

    痛点：数量相等不代表顺序对！比如 ([)]，数量完全相等，但它是错的，因为最内层的 [ 还没闭合，就被外层的 ) 给强行截胡了。

    所以，这个问题的核心在于顺序和最近匹配原则：“最后出现的左括号，必须最先闭合”。

  2. 破局思路（引入“栈”结构）：

    “最后出现的必须最先处理”——这简直就是把身份证拍在桌子上，大喊一声：“我是后进先出（LIFO - Last In First Out），我需要一个栈（Stack）！”

    我们可以把左括号看作是“未满足的期待”，把右括号看作是“回应期待”。

    • 我们从左到右扫描字符串。
    • 遇到任何左括号，说明来了一个新的期待，不管三七二十一，直接压入栈底（Push）。
    • 遇到任何右括号，说明要回应期待了。此时我们看向栈顶（Top），也就是我们刚刚接到的“最近的一个期待”。如果这个右括号刚好能和栈顶的左括号配对，太棒了，把栈顶元素弹出（Pop）（这就是消消乐）。
    • 如果不配对，或者栈已经空了（说明右括号多出来了），直接判死刑，返回 false。

  3. 核心微操（绝妙的入栈反转法）：

    常规写法是：遇到 ( 入栈 (，遇到 ) 则检查栈顶是不是 (。

    进阶的极简写法：遇到 (，我们直接在栈里压入它对应的右括号 )！

    这样一来，当我们遇到右括号时，只需要极其简单的一步：if (当前字符 != 栈顶弹出的字符) return false;。这简直是极简美学的巅峰。

    Java 实现（极简反转消消乐版）

import java.util.ArrayDeque;
import java.util.Deque;

class Solution {
    public boolean isValid(String s) {
        // 奇数长度的字符串，绝对不可能完美闭合，直接提前剪枝
        if (s.length() % 2 != 0) {
            return false;
        }

        // 🌟 致命细节：在 Java 中，推荐使用 Deque (ArrayDeque) 来代替过时的 Stack 类
        Deque<Character> stack = new ArrayDeque<>();

        for (int i = 0; i < s.length(); i++) {
            char c = s.charAt(i);

            // 遇到左括号，把它的“另一半”压入栈中，等待未来的重逢
            if (c == '(') {
                stack.push(')');
            } else if (c == '[') {
                stack.push(']');
            } else if (c == '{') {
                stack.push('}');
            }
            // 遇到右括号了！
            else {
                // 如果栈已经空了（说明右括号多了，没人等它）
                // 或者栈顶弹出的字符和当前的右括号不相等（类型不匹配）
                if (stack.isEmpty() || stack.pop() != c) {
                    return false;
                }
            }
        }

        // 字符串全扫完了，如果栈也刚好空了，说明所有的括号都完美消除了！
        // 如果栈没空（说明左括号多了），返回 false
        return stack.isEmpty();
    }
}

复杂度

  • 时间复杂度：O(N)。只需从头到尾遍历一次字符串，每一次的入栈（push）和出栈（pop）操作时间都是常数级的 O(1)。
  • 空间复杂度：O(N)。在最坏的情况下（比如字符串全是左括号 "((((((("），所有的字符都会被压入栈中，栈的深度等于字符串的长度。

易错点与扩展（面试的底层拷问）

  1. 面试追问 1：“我看你代码里用了 Deque<Character> stack = new ArrayDeque<>();，为什么不用 Stack<Character> stack = new Stack<>(); 呢？”
  • 满分抢答（直击 Java 源码）：在 Java 早期的设计中，Stack 是继承自 Vector 的。Vector 里的每一个方法（包括 push 和 pop）都加了 synchronized 同步锁！这使得 Stack 在单线程环境下性能极其拉垮（因为要频繁获取和释放没用的锁）。
  • 后来 Java 官方都看不下去了，在官方文档里强烈建议使用 Deque 接口（通常实例化为 ArrayDeque）来代替 Stack。ArrayDeque 基于循环数组实现，没有线程同步的额外开销，速度飞快，是现代 Java 工程师的标配。
  1. 面试追问 2：“这道题你能总结出一共有哪几种失败的情况吗？”

  • 满分总结（三种死法）：

    1. 左边多余：遍历完了，栈里面还有剩余的括号没被消除掉。例如 ({}。

    2. 右边多余：遍历到右括号时，栈竟然已经空了。例如 ([{}])))。

    3. 中途不匹配：遍历到右括号时，栈顶拿出来的右括号跟当前的手里的右括号长得不一样。例如 ([)]。

      只要你能清晰地把这三种情况说出来，面试官就知道你对栈的生命周期了如指掌。
