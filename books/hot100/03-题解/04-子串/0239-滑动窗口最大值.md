# 239. 滑动窗口最大值

[← 子串专题](../../02-专题/04-子串.md) · [总目录](../../../../README.md) · [复习清单](../../00-总览/03-复习清单.md)

| 题目信息 | 内容 |
|---|---|
| 难度 | 困难 |
| 核心模式 | 单调队列 |
| 时间复杂度 | O(n) |
| 空间复杂度 | O(k) |


## 题目与约束

给你一个整数数组 `nums`，有一个大小为 `k` 的滑动窗口从数组的最左侧移动到最右侧。你只可以看到在滑动窗口内的 `k` 个数字。滑动窗口每次只向右移动一位。返回滑动窗口中的最大值。

[🔗 前往力扣原题验证 →](https://leetcode.cn/problems/sliding-window-maximum/?envType=study-plan-v2&envId=top-100-liked)

## 核心不变量

> 队列保存有效下标，且对应值从队首到队尾递减。

## 完整推导

### 思路推导
  1. **直觉与痛点（大根堆）**：

     想找最值，第一反应是优先队列（堆）。

     **痛点**：Java 的 `PriorityQueue` 移除特定元素的时间复杂度是 $O(k)$，导致总复杂度退化为 $O(n \cdot k)$。即使配合延迟删除，复杂度也是 $O(n \log n)$。而题目要求 $O(n)$。

  2. **破局思路（单调队列）**：

     我们需要一个队列，它能随着窗口滑动：

     - **入队**：新元素进来时，把前面所有**比它小**的元素全部踢走。
     - **原因**：如果 $A$ 比 $B$ 后进来，且 $A$ 还比 $B$ 大，那么只要 $A$ 在窗口里，$B$ 永远不可能成为最大值。$B$ 已经没用了，可以直接“退伍”。
     - **出队**：当窗口移走了某个元素，如果它恰好是队列里的最大值，才将其弹出。
     - **查询**：队列的头部永远存放着当前窗口的最大值。

  3. **逻辑推演**：

     假设窗口大小 $k=3$，数组 `[1, 3, -1, -3, 5, 3]`：

     - `1` 入队：`[1]`
     - `3` 入队：`3` 比 `1` 大，`1` 没用了，踢走。队列：`[3]`
     - `-1` 入队：`-1` 比 `3` 小，留着，万一 `3` 走了，`-1` 可能是老二。队列：`[3, -1]`
     - **此时窗口满 3 个**，最大值是队头 `3`。
     - `-3` 入队：队列：`[3, -1, -3]`。最大值 `3`。
     - `5` 入队：`5` 把前面的 `3, -1, -3` 全踢走。队列：`[5]`。最大值 `5`。
### Java 实现
```java
import java.util.ArrayDeque;
import java.util.Deque;

class Solution {
    public int[] maxSlidingWindow(int[] nums, int k) {
        if (nums == null || nums.length == 0) return new int[0];

        int n = nums.length;
        int[] res = new int[n - k + 1];
        int idx = 0;

        // 双端队列，存储的是元素的【下标】而非数值
        // 存储下标是为了方便判断队头元素是否已经超出了窗口范围
        Deque<Integer> deque = new ArrayDeque<>();

        for (int i = 0; i < n; i++) {
            // 1. 入队准备：如果新来的数比队尾的大，队尾的数永远没机会出头了，弹出
            while (!deque.isEmpty() && nums[deque.peekLast()] <= nums[i]) {
                deque.pollLast();
            }

            // 2. 入队：存入当前下标
            deque.offerLast(i);

            // 3. 维护窗口：如果队头下标已经不在 [i-k+1, i] 范围内了，弹出
            if (deque.peekFirst() == i - k) {
                deque.pollFirst();
            }

            // 4. 记录答案：当窗口形成（i >= k-1）时，队头就是当前窗口最大值的下标
            if (i >= k - 1) {
                res[idx++] = nums[deque.peekFirst()];
            }
        }

        return res;
    }
}
```
### 复杂度
  - **时间复杂度**：$O(n)$。虽然有 `while` 嵌套，但每个元素最多进队一次、出队一次，总操作数是 $2n$。
  - **空间复杂度**：$O(k)$。双端队列中最多同时存放 $k$ 个元素的下标。

### 易错点与扩展

1. **为什么用 `ArrayDeque` 而不用 `LinkedList`？**
   - **回答**：在 Java 中，`ArrayDeque` 是基于循环数组实现的，`LinkedList` 是基于双向链表（对象）实现的。`ArrayDeque` 在作为栈或队列使用时，内存更紧凑，没有频繁的节点对象创建和销毁，性能通常比 `LinkedList` 高出数倍。
2. **单调队列的通用性**：
   - 这是一种固定的套路：**求窗口最值用单调队列，求下一个更大元素（Next Greater Element）用单调栈**。
3. **下标 vs 数值**：
   - 队列里建议存**下标**。因为下标既能让你通过 `nums[i]` 拿到值，又能让你通过 `i - deque.peekFirst() >= k` 判断窗口是否过期。只存数值无法判断是否过期。

#### 1. LinkedList：链式结构的“长蛇阵”

`LinkedList` 是 Java 中最老牌的集合之一。

- **底层实现**：它是一个**双向链表**。每一个元素都被封装在一个 `Node` 对象中。
- **结构细节**：
  - 每个 `Node` 除了存储数据，还存了两个指针：`prev`（指向前一个节点）和 `next`（指向后一个节点）。
  - 内存分布是**离散**的，节点之间通过地址引用连接。
- **特点**：
  - **插入/删除**：如果在头部或尾部操作，时间复杂度是 $O(1)$。
  - **随机访问**：如果想找第 $i$ 个元素，必须从头（或尾）开始数，时间复杂度是 $O(n)$。
  - **内存开销**：很大。因为每个数据都要额外存两个指针，且频繁地 `new Node` 会给垃圾回收（GC）带来压力。

#### 2. ArrayDeque：循环数组的“高效环”

`ArrayDeque` 是 Java 1.6 引入的，它是目前 Java 官方**最推荐**的栈和队列实现。

- **底层实现**：它是一个**可变长的循环数组**。
- **结构细节**：
  - 它维护了一个数组和两个索引：`head`（头）和 `tail`（尾）。
  - 当 `tail` 走到数组末尾时，它会绕回到数组开头继续使用（只要开头有空位）。这就是所谓的“循环”。
  - 内存分布是**连续**的。
- **特点**：
  - **插入/删除**：在两端操作的时间复杂度也是均摊 $O(1)$。
  - **内存开销**：很小。它只存数据本身，没有指针开销。
  - **缓存友好**：因为数组是连续内存，CPU 读取速度比链表快得多（计算机组成原理中的 Cache Locality）。
  - **禁忌**：它**不允许存储 null 元素**。

#### 3. 巅峰对决：我该选哪一个？

在刷力扣（LeetCode）时，我们通常需要一个容器来充当**栈（Stack）**或**队列（Queue）**。

| **特性**              | **LinkedList**     | **ArrayDeque**       |
| --------------------- | ------------------ | -------------------- |
| **底层**              | 双向链表           | 循环数组             |
| **作为栈/队列性能**   | 一般（对象创建多） | **极高（数组操作）** |
| **随机访问 (get(i))** | $O(n)$             | 不支持（只能看头尾） |
| **内存占用**          | 较高（节点对象多） | **较低（紧凑数组）** |
| **Null 支持**         | 支持               | **不支持**           |

#### 👨‍🏫 老师的总结与建议

在算法面试中，除非题目明确要求你操作链表节点，否则：

1. **如果你需要一个“栈” (Stack)**：
   - **千万不要用** `java.util.Stack` 类（它由于历史原因，带了同步锁，性能极低）。
   - **请使用** `Deque<Integer> stack = new ArrayDeque<>();`。
2. **如果你需要一个“普通队列” (Queue)**：
   - **请使用** `Deque<Integer> queue = new ArrayDeque<>();`。
3. **如果你需要一个“单调队列” (如题目 239)**：
   - **必选** `ArrayDeque`。在高并发或大数据量下，它的速度远超 `LinkedList`。

**为什么 ArrayDeque 速度快这么多？**

简单来说，`LinkedList` 每次添加元素都要在堆内存里 `new` 一个对象，而 `ArrayDeque` 只是在数组里改一个数字。在计算机底层，**操作数组永远比操作对象快得多**。

在 Java 中，`Deque`（全称 Double Ended Queue，双端队列）之所以强大，正是因为它有一套极其丰富（甚至有点让人眼花缭乱）的方法库。很多初学者会被 `add`、`offer`、`poll`、`pop`、`remove` 这些词搞晕。

今天，老师就传授给你一份“Deque 方法命名密码本”，只要理解了底层的命名逻辑，你都不用死记硬背！

#### 🔑 第一层密码：方向词（First vs Last）

`Deque` 是一根两头通的管子。

- **First（头）**：代表管子的左端（前端）。
- **Last（尾）**：代表管子的右端（后端）。

以你问到的几个方法为例：

1. **`deque.peekFirst()`**：**“偷看”一眼队头元素**。只是看看，不把它拿走。如果队列是空的，它会默默返回一个 `null`，不会报错。
2. **`deque.pollFirst()`**：**“拔出”队头元素**。把最左边的元素拿出来并从队列中删掉。如果队列为空，返回 `null`。
3. **`deque.pollLast()`**：**“拔出”队尾元素**。把最右边的元素拿出来并删掉。如果队列为空，返回 `null`。

*(对应的，当然还有 `peekLast()`，也就是偷看一眼队尾。)*

#### 🔑 第二层密码：行为词（报错派 vs 佛系派）

这是面试和实战中最容易踩坑的地方！Java 为同一种操作提供了**两套名字**。一套性格暴躁（出错就抛异常抛死你），一套性格佛系（出错就返回特殊值，通常是 null 或 false）。

**强烈建议：在刷力扣时，永远优先使用“佛系派”方法（`offer`, `poll`, `peek`），这样可以避免不小心触发异常导致代码崩溃！**

| **操作类型** | **暴躁派（出错会抛出 Exception）** | **佛系派（出错返回特殊值 null / false） ⭐️推荐** |
| ------------ | ---------------------------------- | ----------------------------------------------- |
| **插入头部** | `addFirst(e)`                      | `offerFirst(e)`                                 |
| **插入尾部** | `addLast(e)`                       | `offerLast(e)`                                  |
| **删除头部** | `removeFirst()`                    | `pollFirst()`                                   |
| **删除尾部** | `removeLast()`                     | `pollLast()`                                    |
| **查看头部** | `getFirst()`                       | `peekFirst()`                                   |
| **查看尾部** | `getLast()`                        | `peekLast()`                                    |

#### 🔑 第三层密码：角色扮演（化身栈与队列）

`Deque` 之所以被称为“全能王”，是因为它可以完美地**伪装**成“栈（Stack）”或者“普通队列（Queue）”。为了让你写代码时更符合直觉，Java 还为它起了一些“别名”方法。

#### 🎭 场景一：当你要把 Deque 当作“普通队列 (FIFO)”用

普通队列是“排队买票”，队伍尾部进，队伍头部出。

- **入队**：`deque.offer(e)` （其实底层就是调用的 `offerLast`，加到队尾）
- **出队**：`deque.poll()` （其实底层就是调用的 `pollFirst`，从队头拿走）
- **看一眼队头是谁**：`deque.peek()` （其实底层就是调用的 `peekFirst`）

#### 🎭 场景二：当你要把 Deque 当作“栈 (LIFO)”用

栈是“叠盘子”，最后放上去的盘子，最先拿下来。我们规定只在头部（First）进行操作。

- **压栈**：`deque.push(e)` （其实底层就是调用的 `addFirst`，放在最上面）
- **弹栈**：`deque.pop()` （其实底层就是调用的 `removeFirst`，把最上面的拿走）
- *注意：栈的传统方法 `push` 和 `pop` 属于“暴躁派”，如果空栈 `pop` 会报错。所以在安全要求高的场景，我们依然喜欢手动用 `offerFirst` 和 `pollFirst` 来当栈用。*

#### 📝 老师的终极记忆卡片（可以直接复制到笔记）

```java
// 1. 初始化
Deque<Integer> deque = new ArrayDeque<>();

// --------------------------------------------------
// 【场景 A：我想用双端队列 / 单调队列（两头都要操作）】
// --------------------------------------------------
deque.offerLast(1);  // 尾部进
deque.pollFirst();   // 头部出
deque.pollLast();    // 尾部出
deque.peekLast();    // 看尾部

// --------------------------------------------------
// 【场景 B：我想把它当纯正的“普通队列”用】
// --------------------------------------------------
deque.offer(2);      // 排队（进尾巴）
deque.poll();        // 叫号（出头部）
deque.peek();        // 看一眼谁排在最前面

// --------------------------------------------------
// 【场景 C：我想把它当纯正的“栈”用】
// --------------------------------------------------
deque.push(3);       // 压入（放头上）
deque.pop();         // 弹出（拿头上，如果空会报错!）
// 替代方案（更安全）：
deque.offerFirst(3); // 安全压栈
deque.pollFirst();   // 安全弹栈
```

在刚才那道“滑动窗口最大值”（239题）中，为什么我们用到了 `pollLast` 和 `pollFirst`？

- 因为当新的大数字进来时，我们要把前面所有没用的小数字从**尾部**踢掉，所以用了 `pollLast()`。
- 当窗口划过，把最左边的过期数字丢掉时，我们要从**头部**踢掉它，所以用了 `pollFirst()`。

这套 API 体系清楚了吗？只要记住“offer / poll / peek 佛系三剑客”**加上**“First / Last 方向词”，你就能在面试中写出极其稳健的代码！
