题目与约束

给你一个整数数组 nums 和一个整数 k ，请你统计并返回 该数组中和为 k的子数组的个数。

子数组是数组中元素的连续非空序列。

示例 1：

输入：nums = [1,1,1], k = 2
输出：2

示例 2：

输入：nums = [1,2,3], k = 3
输出：2

提示：

  • 1 <= nums.length <= 2 * 104
  • -1000 <= nums[i] <= 1000
  • -107 <= k <= 107

Java 完整推导

Java 核心不变量

当前前缀为 pre 时，需要此前出现过 pre - k。

完整推导

思路推导

  1. 直觉与痛点（暴力枚举）：

    枚举所有的子数组起点 i 和终点 j，计算它们之间元素的总和。

    痛点：即便使用前缀和预处理，枚举所有组合也需要 O(N2)。如果数组长度是 105，计算量会达到 100 亿次，绝对超时。

  2. 破局思路（前缀和的逆向思维）：

    设 PreSum[i] 是数组前 i 个元素的和。

    那么，子数组 [j, i] 的和可以表示为：Sum(j, i) = PreSum[i] - PreSum[j-1]。

    我们要找的是 Sum(j, i) = k，等价于寻找满足条件的索引 j：

    PreSum[i]-PreSum[j-1]=k⇒PreSum[j-1]=PreSum[i]-k

    结论：当我们遍历到位置 i 时，我们只需要知道：在此之前，有多少个前缀和等于 PreSum[i] - k。

  3. 哈希表加速：

    我们可以维护一个哈希表 Map<前缀和的值, 该值出现的次数>。

    遍历数组时，一边计算当前的前缀和，一边去 Map 里查 target = currSum - k 出现了几次。

    Java 实现

import java.util.HashMap;
import java.util.Map;

class Solution {
    public int subarraySum(int[] nums, int k) {
        // 1. 定义哈希表：Key 为前缀和的值，Value 为该前缀和出现的频次
        Map<Integer, Integer> preSumMap = new HashMap<>();

        // 2. 极其重要：初始化，表示前缀和为 0 已经出现了 1 次（处理从索引 0 开始就等于 k 的情况）
        preSumMap.put(0, 1);

        int count = 0;   // 结果计数器
        int currSum = 0; // 当前累加的前缀和

        for (int num : nums) {
            // 计算当前前缀和
            currSum += num;

            // 3. 核心查找逻辑：
            // 我们在找是否有之前的 PreSum 等于 (currSum - k)
            if (preSumMap.containsKey(currSum - k)) {
                // 如果有，说明这两个前缀和之间的那段子数组之和正好是 k
                // 加上它出现的频次
                count += preSumMap.get(currSum - k);
            }

            // 4. 将当前前缀和存入（或更新）Map，供后续元素查找
            preSumMap.put(currSum, preSumMap.getOrDefault(currSum, 0) + 1);
        }

        return count;
    }
}

复杂度

  • 时间复杂度：O(N)。只需遍历一次数组，Map 的操作均为 O(1)。
  • 空间复杂度：O(N)。哈希表最坏情况下会存储 N 个不同的前缀和。
易错点与扩展（灵魂考点）
  1. 为什么一定要 map.put(0, 1)？ - 原因：如果数组第一个数正好就是 k，此时 currSum = k。计算 currSum - k 得到 0。如果不预存 (0, 1)，我们就无法发现这个“从头开始且长度为 1”的合法子数组。这本质上是处理边界情况。
  2. 这道题能用滑动窗口吗？ - 致命坑点：不能！（除非题目说明数组全是正数）。 - 解析：滑动窗口的核心在于“单调性”。如果数组里有负数，窗口右移时和可能变小，窗口左移时和可能变大。这种不确定性会导致窗口无法正确收缩。因此，有负数且求和问题，首选前缀和 + 哈希表。

Python 完整推导

把区间和改写成两个前缀和之差

当前位置前缀和为 prefix。若某个更早的前缀和是 prefix - k，两者之间的连续元素和就是 k。

字典 count 保存此前每个前缀和出现了几次。初始放入 {0: 1}，表示空前缀，使从下标 0 开始的区间也能被找到。

每读一个数，先更新 prefix，再查询 prefix - k 的频次并加入答案；最后才登记当前前缀，避免把当前状态提前用于自己。

用 [1, 1, 1], k=2 走一遍

  • 第 1 个 1 后，prefix=1，查找 -1，次数为 0。
  • 第 2 个 1 后，prefix=2，命中旧前缀 0 一次，答案加 1。
  • 第 3 个 1 后，prefix=3，命中旧前缀 1 一次，答案变为 2。

对应区间分别是下标 [0,1] 和 [1,2]。

Python 实现

参考来源：代码随想录（programmercarl.com）

保留旧 Python 的前缀和频次实现，整理变量与签名；算法未改变。

from typing import List


class Solution:
    def subarraySum(self, nums: List[int], k: int) -> int:
        count = {0: 1}
        prefix = 0
        answer = 0
        for value in nums:
            prefix += value
            answer += count.get(prefix - k, 0)
            count[prefix] = count.get(prefix, 0) + 1
        return answer

为什么不只保存“是否出现”

同一个前缀和可能在多个位置出现，每个位置都代表一个合法起点。count[prefix] 保存的是次数，因此查询命中后要加上整份频次。

查询必须早于登记

若先把当前 prefix 写入字典，再查询 prefix - k，当 k=0 时会把长度 0 的区间也算进去。当前顺序保证查到的都是更早位置。

负数输入

[1, -1, 0], k=0 的前缀依次是 1、0、0。第二个元素形成区间 [0,1]，第三个元素既形成 [0,2]，也形成单个 [2]，总数为 3。滑动窗口在含负数时没有单调性，所以这里保留前缀和哈希。

复杂度

  • 时间复杂度：O(n)。
  • 空间复杂度：O(n)。

一次线性扫描，每次平均常数次哈希操作；最坏有 n+1 个不同前缀和。

C++ 实现

实现来源：站内标准实现

class Solution {
public:
    int subarraySum(vector<int>& nums, int k) {
        unordered_map<long long, int> cnt{{0, 1}}; // 前缀和出现次数
        long long sum = 0;
        int ans = 0;
        for (int x : nums) {
            sum += x;
            auto it = cnt.find(sum - k);
            if (it != cnt.end()) ans += it->second;
            ++cnt[sum];
        }
        return ans;
    }
};

Go 实现

实现来源：站内标准实现

func subarraySum(nums []int, k int) int {
    cnt := map[int]int{0: 1}
    sum, ans := 0, 0
    for _, x := range nums {
        sum += x
        ans += cnt[sum-k]
        cnt[sum]++
    }
    return ans
}
