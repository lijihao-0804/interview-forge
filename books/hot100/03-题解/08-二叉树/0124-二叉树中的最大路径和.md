# 124. 二叉树中的最大路径和

[← 二叉树专题](../../02-专题/08-二叉树.md) · [总目录](../../../../README.md) · [复习清单](../../00-总览/03-复习清单.md)

| 题目信息 | 内容 |
|---|---|
| 难度 | 困难 |
| 核心模式 | 后序最大贡献 |
| 时间复杂度 | O(n) |
| 空间复杂度 | O(h) |


## 题目与约束

二叉树中的**路径**被定义为一条节点序列，序列中每对相邻节点之间都存在一条边。同一个节点在一条路径序列中至多出现一次。该路径**至少包含一个**节点，且不一定经过根节点。

**路径和**是路径中各节点值的总和。给你一个二叉树的根节点 `root` ，返回其最大路径和。

## 核心不变量

> 向上只能贡献一条支路，更新答案时可以同时取左右支路。

## 完整推导

### 思路推导
1. **直觉与痛点（毒瘤负数与分叉陷阱）**：

   这题有两大痛点。第一，节点的值可能是**负数**！如果你顺着路径往下走，加了一个 `-100`，不仅没收益，还会把你原本的数字拖垮。第二，路径可能是一个“倒 V 字形（拐弯的）”，比如从左子树上来，穿过根节点，再下到右子树。

2. **破局思路 A（贪心斩断负收益）**：

   当我们向左小弟和右小弟要他们子树的最大路径和时，如果小弟汇报的数字是**负数**，我们该怎么办？

   **果断斩断联系（当作 0）！** 既然你是个拖油瓶，那我干脆不带你玩了，我自己单干或者只带另一个正数小弟玩。

### 题目与约束
  二叉树中的**路径** 被定义为一条节点序列，序列中每对相邻节点之间都存在一条边。同一个节点在一条路径序列中 **至多出现一次** 。该路径**至少包含一个**节点，且不一定经过根节点。

  **路径和** 是路径中各节点值的总和。

  给你一个二叉树的根节点 `root` ，返回其 **最大路径和** 。

  **示例 1：**

  ![](https://__LC_IMG_ROOT__/lc-1f9021039fea28.jpg)

  **输入：**root = [1,2,3]<br>**输出：**6<br>**解释：**最优路径是 2 -> 1 -> 3 ，路径和为 2 + 1 + 3 = 6

  **示例 2：**

  **输入：**root = [-10,9,20,null,null,15,7]<br>**输出：**42<br>**解释：**最优路径是 15 -> 20 -> 7 ，路径和为 15 + 20 + 7 = 42

  **提示：**

  - 树中节点数目范围是 `[1, 3 * 104]`
  - `-1000 <= Node.val <= 1000`
### Java 实现（贪心 + 后序遍历）
```java
/**
 * Definition for a binary tree node.
 * public class TreeNode {
 * int val;
 * TreeNode left;
 * TreeNode right;
 * TreeNode() {}
 * TreeNode(int val) { this.val = val; }
 * TreeNode(int val, TreeNode left, TreeNode right) {
 * this.val = val;
 * this.left = left;
 * this.right = right;
 * }
 * }
 */
class Solution {
    // 全局告示牌：记录所有节点中，拼凑出的最大“倒 V 字形”路径和
    // 🌟 致命细节：千万不能初始化为 0！如果整棵树全是负数（比如 [-3]），初始化为 0 会导致返回 0，但正确答案应该是 -3。
    int maxSum = Integer.MIN_VALUE;

    public int maxPathSum(TreeNode root) {
        dfs(root);
        return maxSum;
    }

    // 辅助函数：计算以当前节点为最高顶点，向下延伸所能提供的最大“单线收益”
    private int dfs(TreeNode node) {
        // 1. 终止条件：空节点的收益为 0
        if (node == null) {
            return 0;
        }

        // 2. 深入敌后，获取左右小弟的单线收益
        // 🌟 贪心奥义：如果小弟汇报的收益是负数，直接无视（与 0 取最大值），相当于剪断这条废柴分支！
        int leftGain = Math.max(0, dfs(node.left));
        int rightGain = Math.max(0, dfs(node.right));

        // 3. 【私】计算以我自己为拐点的“倒 V 型”路径总收益
        // 既然负数已经被过滤成 0 了，这里放心大胆地加起来就行
        int currentMaxPath = node.val + leftGain + rightGain;

        // 刷新全局历史最高记录
        maxSum = Math.max(maxSum, currentMaxPath);

        // 4. 【公】向上级汇报工作
        // 向上级汇报的只能是一条“单线（不分叉）”，所以我只能挑左右两边里最大的那个收益，带上我自己传上去
        return node.val + Math.max(leftGain, rightGain);
    }
}
```
### 复杂度
  - **时间复杂度**：$O(N)$。依然是标准的后序遍历，我们对每个节点都只访问了一次，做了一次常数时间的比较操作。
  - **空间复杂度**：$O(H)$。其中 $H$ 是二叉树的高度。空间消耗来自于系统调用栈。

### 易错点与扩展（面试高频考点）

1. **踩坑警告：`maxSum` 初始化陷阱**
   - 很多同学在做惯了普通题后，习惯性地写上 `int maxSum = 0;`。
   - 当遇到测试用例 `[-10]` 或者 `[-2, -1]` 时，由于所有节点都是负数，你的 `maxSum` 如果是 `0`，它就永远不会被更新。最后你的代码输出是 `0`，但这棵树里根本没有能凑出 `0` 的路径，标准答案应该是 `-1`（只能选值最大的那个负数节点本身）。所以必须初始化为 `Integer.MIN_VALUE`！
2. **关键追问：“为什么算局部最大值时要加上左和右，向上汇报时却只能选左或右？”**
   - 这是面试官最爱抓的逻辑点。你可以坚定地回答：“因为题目定义的是**路径（Path）**！一条路径不能出现岔路口。当我把当前节点当做最高拐点时，左子树上来，经过我，再下到右子树，这是一条完美的不回头路径。但是，当我作为一个子节点依附在父节点之下时，如果父节点顺着我往下走，我只能给他指**一条**道（要么左要么右），我不可能同时带他走两条道，所以汇报时必须取 `max(left, right)`！”

###  二叉树破局心法总纲：万变不离其宗的三大范式

刷二叉树的题目，本质上就是在练习“如何在非线性结构中游走与传递信息”。 当你拿到一道二叉树的新题时，不要慌，立刻在脑海中过一遍这三大范式，看看它属于哪一种。

### 范式一：自顶向下，层层递进（前序遍历 / BFS）

这一类题目的核心特征是：**“父节点在把任务交派给子节点之前，需要先处理好自己的事情，或者把一些状态/限制条件传递下去。”**

#### 1. 深度优先搜索（DFS）的向下传递

- **适用场景**：路径相关问题（求从根到叶子的路径总和、验证路径）、需要向下传递约束条件的问题。

- **核心思想**：带着“历史包袱”或“尚方宝剑”往下走。

- **代表题目**：

  - **「98. 验证二叉搜索树」**：父节点把 `(min, max)` 的上下界紧箍咒传递给左右小弟，严防死守。
  - **「112. 路径总和」**：父节点把自己这层的值从 `targetSum` 中扣除，然后问小弟：“你们能凑出剩下的数字吗？”

- **代码套路 (前序遍历 中-左-右)**：

```
void traverse(TreeNode root, int target, ...) {
    if (root == null) return;
    // 【中】先处理自己，或者更新传给子节点的状态
    int newTarget = target - root.val;

    // 【左、右】带着新状态往下走
    traverse(root.left, newTarget, ...);
    traverse(root.right, newTarget, ...);
}
```

#### 2. 广度优先搜索（BFS）的雷达扫描

- **适用场景**：所有明确要求“按层处理”的问题（求树的最小深度、右视图、层平均值、之字形遍历）。

- **核心思想**：利用**队列 (Queue)** 保证先进先出，并且用 `levelSize` 锁死每一层的人数。

- **代表题目**：

  - **「102. 二叉树的层序遍历」**：母题，完美的分层装篮子。
  - **「199. 二叉树的右视图」**：层序遍历，只收集每一层队列最后弹出的那个节点。

- **代码套路 (BFS 黄金模板)**：

```
Queue<TreeNode> q = new LinkedList<>();
q.offer(root);
while (!q.isEmpty()) {
    int size = q.size(); // 🌟 必须锁死当前层的数量
    for (int i = 0; i < size; i++) {
        TreeNode node = q.poll();
        // 处理 node...
        if (node.left != null) q.offer(node.left);
        if (node.right != null) q.offer(node.right);
    }
}
```

### 范式二：自底向上，汇聚情报（后序遍历）

这是二叉树中**最难、也是最常考**的范式（特别是 Hard 题）。 它的核心特征是：**“父节点像个光杆司令，必须眼巴巴地等着左右两个小弟把活干完，向它汇报结果后，它才能决定自己该怎么办。”**

- **适用场景**：树的高度/深度问题、找公共祖先问题、需要子树提供数据的最优化问题。

- **核心思想**：分而治之，层层汇报，在根节点完成最终的逻辑拼装。

- **代表题目**：

  - **「104. 二叉树的最大深度」**：左边报高度，右边报高度，父节点取个最大值加 1。
  - **「236. 二叉树的最近公共祖先」**：左边报有没有找到，右边报有没有找到，父节点根据两边的情报决定是截胡还是继续上报。
  - **「124. 二叉树中的最大路径和」**：小弟汇报单线最大收益，父节点私下算“倒 V 形”总收益，然后对外只汇报一条更粗的单线。

- **代码套路 (后序遍历 左-右-中)**：

```
ReturnType traverse(TreeNode root) {
    if (root == null) return baseValue;

    // 【左、右】深入敌后，等待小弟的汇报
    ReturnType leftResult = traverse(root.left);
    ReturnType rightResult = traverse(root.right);

    // 【中】拿到小弟的情报了！结合我自己的情况，开始做决策
    ReturnType myResult = combine(leftResult, rightResult, root.val);

    // 向上级汇报我的最终成果
    return myResult;
}
```

### 范式三：优化思路，压路机模式（中序遍历）

这个范式几乎是为**二叉搜索树（BST）**量身定制的进阶武器。 它的核心特征是：**“不要把它当成树，把它看作一个隐藏的有序数组。”**

- **适用场景**：判断是否是有效的 BST、在 BST 中找第 K 大/小的元素、BST 转双向链表。

- **核心思想**：二叉搜索树的中序遍历结果是一个**严格递增的序列**。通过维护一个外部变量（如指针、计数器），在遍历过程中实时进行比较或计数。

- **代表题目**：

  - **「98. 验证二叉搜索树 (降维版)」**：维护一个 `pre` 指针，边走边查当前节点是否大于 `pre`。
  - **「230. 二叉搜索树中第 K 小的元素」**：维护一个 `count` 计数器，中序遍历走到第 K 个直接报警退出。

- **代码套路 (中序遍历 左-中-右)**：

```
TreeNode pre = null; // 全局或类变量，用于比较
int count = 0;       // 全局或类变量，用于计数

void traverse(TreeNode root) {
    if (root == null) return;

    // 【左】一路向左
    traverse(root.left);

    // 【中】处理核心逻辑，这里就相当于在遍历一个有序数组！
    if (pre != null && root.val <= pre.val) { return false; } // 例：验证 BST
    pre = root;

    count++; if (count == K) { return root.val; } // 例：找第 K 小

    // 【右】转向右侧
    traverse(root.right);
}
```

### 💎 高级综合绝招：跨界融合与微操

当你熟练掌握了三大范式后，面试官会考你一些“组合拳”或“微操”。

1. **全局告示牌（夹带私货）**：
   - 在范式二（后序遍历）中，父节点只能返回一个值给它的上级。但如果我们需要计算一些全局的极值（如「543. 二叉树的直径」），我们可以在类的层级挂一个 `int globalMax = 0`。在遍历的过程中，“顺手”把局部算出的极大值更新到这个全局告示牌上。
2. **空间极度压缩（原地修改）**：
   - 不给你 O(N) 的空间，要求改变树的结构。这要求你深刻理解引用的传递（如「114. 二叉树展开为链表」中的子树嫁接，以及利用反前序遍历的神仙写法）。
3. **与其他数据结构跨界**：
   - 树 + 前缀和 + 哈希表回溯（如「437. 路径总和 III」）。本质上是把一维数组的高级技巧生搬硬套到树的分岔路径上。
   - 树 + HashMap 索引查找（如「105. 从前序与中序遍历构造二叉树」）。用 O(1) 的空间换取巨大的时间提升。

#### 结语

面对任何一棵二叉树，**闭上眼睛，想象水流**：

- 水从上面浇下来，带着颜色染透整棵树 —— 这是**前序**。
- 水滴落到最底层，化成水汽一层层蒸腾上来汇报情况 —— 这是**后序**。
- 水压路机从左到右平推过去 —— 这是 BST 的**中序**。
- 水波纹一圈圈荡漾散开 —— 这是队列模拟的**层序 (BFS)**。

掌握了水流的方向，所有的二叉树题，都不过是在水流必经的节点上，安插你的检票员罢了。
