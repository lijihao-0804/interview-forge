## 题目与约束

给你一个整数数组 `coins` ，表示不同面额的硬币；以及一个整数 `amount` ，表示总金额。

  计算并返回可以凑成总金额所需的 **最少的硬币个数** 。如果没有任何一种硬币组合能组成总金额，返回 `-1` 。

  你可以认为每种硬币的数量是无限的。

  **示例 1：**

  **输入：**coins = `[1, 2, 5]`, amount = `11`<br>**输出：**`3` <br>**解释：**11 = 5 + 5 + 1

  **示例 2：**

  **输入：**coins = `[2]`, amount = `3`<br>**输出：**-1

  **示例 3：**

  **输入：**coins = [1], amount = 0<br>**输出：**0

  **提示：**

  - `1 <= coins.length <= 12`
  - `1 <= coins[i] <= 231 - 1`
  - `0 <= amount <= 104`

## 完整推导

### 思路推导
  1. **直觉与痛点（贪心的终极滑铁卢）**：

     人在现实生活中找零钱，本能用的是贪心算法：先找最大的面值，找不开再用小的。

     **痛点**：这种直觉在算法里是致命的！假设硬币面值是 `[1, 3, 4]`，你要凑的金额是 `6`。

     - **贪心法**：先拿最大的 `4`，还剩 `2`。`2` 只能用两个 `1` 凑。总共需要 **3 枚**硬币（`4 + 1 + 1`）。

     - **真实最优解**：拿两个 `3`！总共只需要 **2 枚**硬币（`3 + 3`）。

       贪心算法因为目光短浅，只看到了局部的最大面值，错失了全局的最优解。

  2. **降维破局（动态规划的全局视野）**：

     我们要凑出金额 `amount`，必须老老实实地从小到大推导。

     定义 `dp[i]` 为：**凑出金额 `i` 所需要的最少硬币数量**。

  3. **核心微操（状态转移方程）**：

     假设我们要算 `dp[6]`，我们手里有 `[1, 3, 4]` 三种硬币。

     如果要凑出 6 块钱，我们只有三种“最后一步”的选法：

     - 选 1 块钱：那剩下的 5 块钱怎么凑？答案早就存在 `dp[5]` 里了！总数就是 `dp[5] + 1`。

     - 选 3 块钱：剩下的 3 块钱怎么凑？看 `dp[3]`！总数是 `dp[3] + 1`。

     - 选 4 块钱：剩下的 2 块钱怎么凑？看 `dp[2]`！总数是 `dp[2] + 1`。

       所以：$dp[6] = \min(dp[5], dp[3], dp[2]) + 1$。

       推广到通用公式：$dp[i] = \min(dp[i],\ dp[i - coin] + 1)$
### Java 实现（满分防溢出技巧版）
```Java
import java.util.Arrays;

class Solution {
    public int coinChange(int[] coins, int amount) {
        // 边界防御
        if (amount == 0) return 0;

        // dp[i] 表示凑出金额 i 需要的最少硬币数量
        int[] dp = new int[amount + 1];

        // 🌟 核心工程技巧（防溢出魔法）：
        // 为什么不把初始值设为 Integer.MAX_VALUE？
        // 因为在状态转移时有 dp[i - coin] + 1。如果它是 MAX_VALUE，再加 1 就会【整型溢出】变成负数！
        // 因为凑成 amount 最多也就是全部用 1 块钱，需要 amount 个。
        // 所以 amount + 1 绝对是一个永远达不到的“安全无穷大”！
        int max = amount + 1;
        Arrays.fill(dp, max);

        // 基底状态：凑出 0 元需要 0 个硬币
        dp[0] = 0;

        // 外层循环：从小到大遍历所有要凑的金额 i
        for (int i = 1; i <= amount; i++) {
            // 内层循环：尝试每一种硬币
            for (int coin : coins) {
                // 只有当硬币面值小于等于当前要凑的金额时，才能用这个硬币
                if (coin <= i) {
                    // 状态转移：保持原样，或者用掉这枚硬币加上剩余金额的最优解
                    dp[i] = Math.min(dp[i], dp[i - coin] + 1);
                }
            }
        }

        // 如果最后金额 amount 的状态还是那个初始的“无穷大”，说明根本凑不出来，返回 -1
        return dp[amount] > amount ? -1 : dp[amount];
    }
}
```
### 复杂度
  - **时间复杂度**：$O(S \times n)$。其中 $S$ 是金额 `amount`，$n$ 是硬币的面额数。我们要计算从 1 到 $S$ 的所有金额，每个金额都要遍历一次硬币数组。
  - **空间复杂度**：$O(S)$。我们需要一个长度为 `amount + 1` 的 `dp` 数组来存储所有的子状态。

### 易错点与扩展（面试的关键细节）

1. **踩坑警告：为什么 `for` 循环的顺序是先遍历金额 `i`，再遍历硬币 `coin`？可以反过来吗？**
   - **满分避坑指南**：在这道题里，**完全可以反过来**！
   - 因为这道题求的是**硬币的最少个数**，而不是排列组合的种类数。不管你是“先拿 1 块再拿 3 块”，还是“先拿 3 块再拿 1 块”，总数都是 2 枚。
   - **拓展**：如果是力扣另一道题「518. 零钱兑换 II」（求凑出金额的**组合种类数**），那就**必须先遍历硬币，再遍历金额**，否则会把 `(1,3)` 和 `(3,1)` 算成两种不同的组合（变成排列数了）！这点一定要牢记。
2. **面试追问：“如果这道题我允许用 DFS（回溯）+ 贪心剪枝，能比 DP 快吗？”**
   - **高级风控对策**：可以！这是一个非常著名的优化策略。
   - 我们先对 `coins` 数组从大到小排序。然后用 DFS 去搜索，优先用最大的硬币去填。
   - 只要搜到一个合法的组合，就把它的硬币数记录下来作为 `minCoins`。
   - 接下来在其他分支搜索时，如果发现**当前的硬币数 + 剩下金额全用目前能用的最大面值去凑，都超过了 `minCoins`**，就立刻剪枝（放弃这条路）。这在某些特定的测试用例下，能比 DP 跑得更快，但代码实现难度极高，面试时优先手写 DP 稳妥过关。

## Python 完整推导

### 硬币可以重复使用，容量要正着走

`dp[x]` 表示凑出金额 `x` 所需的最少硬币数。若最后一枚硬币面值是 `coin`，前面的金额就是 `x - coin`；如果那个金额已经可达，就可以用 `dp[x-coin] + 1` 更新当前答案。

外层遍历硬币、内层让金额从 `coin` 正序增长，这是完全背包。正序时，刚用当前硬币更新过的较小金额还能继续参与更大的金额，因此同一枚硬币可以重复使用。

### 反例 `coins = [1, 3, 4]`、`amount = 6`

初始 `dp[0] = 0`，其余都是无效值。按迭代顺序：

- 处理硬币 1 后，`dp[0..6] = [0,1,2,3,4,5,6]`，全部用 1 元凑出。
- 处理硬币 3 后，`dp[3]` 由 3 降为 1，`dp[6]` 降为 `dp[3] + 1 = 2`，数组前七项变为 `[0,1,2,1,2,3,2]`。
- 处理硬币 4 时，`dp[4] = min(2, dp[0] + 1) = 1`，`dp[5] = min(3, dp[1] + 1) = 2`，最终 `dp[6]` 仍为 2，对应 `3 + 3`。

如果只贪心先拿 4，会得到 4+1+1 三枚，而 `3+3` 只要两枚。DP 同时保留所有最后硬币选择，不会被大面值诱导。

若某个金额从未可达，它始终保持安全无效值。返回前只检查 `dp[amount]` 是否仍等于该值，就得到 `-1`。

### Python 实现

> 参考来源：代码随想录（programmercarl.com）
>
> 沿用旧项目收录的《代码随想录》完全背包 Python 代码；删去重复的无穷大判断，使用安全无效值并整理变量与注释。

```python
from typing import List


class Solution:
    def coinChange(self, coins: List[int], amount: int) -> int:
        unreachable = amount + 1
        dp = [unreachable] * (amount + 1)
        dp[0] = 0
        for coin in coins:
            for total in range(coin, amount + 1):
                dp[total] = min(dp[total], dp[total - coin] + 1)
        return -1 if dp[amount] == unreachable else dp[amount]
```

### 无效值与状态转移

`unreachable = amount + 1` 比任何合法答案都大：哪怕全部用 1 元，也最多需要 `amount` 枚。Python 的 `inf + 1` 仍然是 `inf`，本身不会溢出；这里使用有限整数是为了让 dp 始终是整数，并使最后的失败判断更直接。

`range(coin, amount + 1)` 从当前硬币面值开始，因为比它更小的金额不可能把该硬币作为最后一项。正序范围让 `dp[total-coin]` 可能已经使用过当前硬币，于是自然允许重复取用。

### 边界

`dp[0] = 0` 表示凑出 0 元不需要硬币。`amount = 0` 时外层仍会遍历已有硬币，只是每个内层 `range(coin, 1)` 都为空，最后直接返回 0。`coin > amount` 时对应 range 同样为空，不产生状态。

### 复杂度

- 时间复杂度：`O(amount·coins)`。
- 空间复杂度：`O(amount)`。

每枚硬币让内层至多扫描 amount 个金额，时间 O(coins·amount)；一维 dp 含 amount+1 项，空间 O(amount)。

// 版本一
class Solution {
public:
    int coinChange(vector<int>& coins, int amount) {
        vector<int> dp(amount + 1, INT_MAX);
        dp[0] = 0;
        for (int i = 0; i < coins.size(); i++) { // 遍历物品
            for (int j = coins[i]; j <= amount; j++) { // 遍历背包
                if (dp[j - coins[i]] != INT_MAX) { // 如果dp[j - coins[i]]是初始值则跳过
                    dp[j] = min(dp[j - coins[i]] + 1, dp[j]);
                }
            }
        }
        if (dp[amount] == INT_MAX) return -1;
        return dp[amount];
    }
};
```

// 版本一, 先遍历物品,再遍历背包
func coinChange1(coins []int, amount int) int {
	dp := make([]int, amount+1)
	// 初始化dp[0]
	dp[0] = 0
	// 初始化为math.MaxInt32
	for j := 1; j <= amount; j++ {
		dp[j] = math.MaxInt32
	}

	// 遍历物品
	for i := 0; i < len(coins); i++ {
		// 遍历背包
		for j := coins[i]; j <= amount; j++ {
			if dp[j-coins[i]] != math.MaxInt32 {
				// 推导公式
				dp[j] = min(dp[j], dp[j-coins[i]]+1)
				//fmt.Println(dp,j,i)
			}
		}
	}
	// 没找到能装满背包的, 就返回-1
	if dp[amount] == math.MaxInt32 {
		return -1
	}
	return dp[amount]
}

// 版本二,先遍历背包,再遍历物品
func coinChange2(coins []int, amount int) int {
	dp := make([]int, amount+1)
	// 初始化dp[0]
	dp[0] = 0
	// 遍历背包,从1开始
	for j := 1; j <= amount; j++ {
		// 初始化为math.MaxInt32
		dp[j] = math.MaxInt32
		// 遍历物品
		for i := 0; i < len(coins); i++ {
			if j >= coins[i] && dp[j-coins[i]] != math.MaxInt32 {
				// 推导公式
				dp[j] = min(dp[j], dp[j-coins[i]]+1)
				//fmt.Println(dp)
			}
		}
	}
	// 没找到能装满背包的, 就返回-1
	if dp[amount] == math.MaxInt32 {
		return -1
	}
	return dp[amount]
}

func min(a, b int) int {
	if a < b {
		return a
	}
	return b
}
```

## C 实现

> 实现来源：站内标准实现



```c
int coinChange(int* coins, int coinsSize, int amount) {
    int* dp = malloc(sizeof(int) * (amount + 1));
    dp[0] = 0;
    for (int i = 1; i <= amount; ++i) dp[i] = amount + 1;
    for (int i = 1; i <= amount; ++i)
        for (int j = 0; j < coinsSize; ++j)
            if (coins[j] <= i && dp[i - coins[j]] + 1 < dp[i])
                dp[i] = dp[i - coins[j]] + 1;
    return dp[amount] > amount ? -1 : dp[amount];
}
```
