322. 零钱兑换

难度中等核心模式完全背包最小值时间复杂度O(amount·coins)空间复杂度O(amount)

题目与约束

给你一个整数数组 coins ，表示不同面额的硬币；以及一个整数 amount ，表示总金额。

计算并返回可以凑成总金额所需的 最少的硬币个数 。如果没有任何一种硬币组合能组成总金额，返回 -1 。

你可以认为每种硬币的数量是无限的。

示例 1：

输入：coins = [1, 2, 5], amount = 11
输出：3
解释：11 = 5 + 5 + 1

示例 2：

输入：coins = [2], amount = 3
输出：-1

示例 3：

输入：coins = [1], amount = 0
输出：0

提示：

  • 1 <= coins.length <= 12
  • 1 <= coins[i] <= 231 - 1
  • 0 <= amount <= 104

核心不变量

正序遍历容量允许同一枚硬币重复使用。

完整推导

思路推导

  1. 直觉与痛点（贪心的终极滑铁卢）：

    人在现实生活中找零钱，本能用的是贪心算法：先找最大的面值，找不开再用小的。

    痛点：这种直觉在算法里是致命的！假设硬币面值是 [1, 3, 4]，你要凑的金额是 6。

    • 贪心法：先拿最大的 4，还剩 2。2 只能用两个 1 凑。总共需要 3 枚硬币（4 + 1 + 1）。

    • 真实最优解：拿两个 3！总共只需要 2 枚硬币（3 + 3）。

    贪心算法因为目光短浅，只看到了局部的最大面值，错失了全局的最优解。

  2. 降维破局（动态规划的全局视野）：

    我们要凑出金额 amount，必须老老实实地从小到大推导。

    定义 dp[i] 为：凑出金额 i 所需要的最少硬币数量。

  3. 核心微操（状态转移方程）：

    假设我们要算 dp[6]，我们手里有 [1, 3, 4] 三种硬币。

    如果要凑出 6 块钱，我们只有三种“最后一步”的选法：

    • 选 1 块钱：那剩下的 5 块钱怎么凑？答案早就存在 dp[5] 里了！总数就是 dp[5] + 1。

    • 选 3 块钱：剩下的 3 块钱怎么凑？看 dp[3]！总数是 dp[3] + 1。

    • 选 4 块钱：剩下的 2 块钱怎么凑？看 dp[2]！总数是 dp[2] + 1。

    所以：dp[6]=min(dp[5],dp[3],dp[2])+1。

    推广到通用公式：dp[i]=min(dp[i],dp[i-coin]+1)

    C 实现

    实现来源：站内标准实现

    int coinChange(int* coins, int coinsSize, int amount) {
    int* dp = malloc(sizeof(int) * (amount + 1));
    dp[0] = 0;
    for (int i = 1; i <= amount; ++i) dp[i] = amount + 1;
    for (int i = 1; i <= amount; ++i)
        for (int j = 0; j < coinsSize; ++j)
            if (coins[j] <= i && dp[i - coins[j]] + 1 < dp[i])
                dp[i] = dp[i - coins[j]] + 1;
    return dp[amount] > amount ? -1 : dp[amount];
}

import java.util.Arrays;

class Solution {
    public int coinChange(int[] coins, int amount) {
        // 边界防御
        if (amount == 0) return 0;

        // dp[i] 表示凑出金额 i 需要的最少硬币数量
        int[] dp = new int[amount + 1];

        // 🌟 核心工程技巧（防溢出魔法）：
        // 为什么不把初始值设为 Integer.MAX_VALUE？
        // 因为在状态转移时有 dp[i - coin] + 1。如果它是 MAX_VALUE，再加 1 就会【整型溢出】变成负数！
        // 因为凑成 amount 最多也就是全部用 1 块钱，需要 amount 个。
        // 所以 amount + 1 绝对是一个永远达不到的“安全无穷大”！
        int max = amount + 1;
        Arrays.fill(dp, max);

        // 基底状态：凑出 0 元需要 0 个硬币
        dp[0] = 0;

        // 外层循环：从小到大遍历所有要凑的金额 i
        for (int i = 1; i <= amount; i++) {
            // 内层循环：尝试每一种硬币
            for (int coin : coins) {
                // 只有当硬币面值小于等于当前要凑的金额时，才能用这个硬币
                if (coin <= i) {
                    // 状态转移：保持原样，或者用掉这枚硬币加上剩余金额的最优解
                    dp[i] = Math.min(dp[i], dp[i - coin] + 1);
                }
            }
        }

        // 如果最后金额 amount 的状态还是那个初始的“无穷大”，说明根本凑不出来，返回 -1
        return dp[amount] > amount ? -1 : dp[amount];
    }
}

复杂度

  • 时间复杂度：O(S × n)。其中 S 是金额 amount，n 是硬币的面额数。我们要计算从 1 到 S 的所有金额，每个金额都要遍历一次硬币数组。
  • 空间复杂度：O(S)。我们需要一个长度为 amount + 1 的 dp 数组来存储所有的子状态。
易错点与扩展（面试的关键细节）
  1. 踩坑警告：为什么 for 循环的顺序是先遍历金额 i，再遍历硬币 coin？可以反过来吗？ - 满分避坑指南：在这道题里，完全可以反过来！ - 因为这道题求的是硬币的最少个数，而不是排列组合的种类数。不管你是“先拿 1 块再拿 3 块”，还是“先拿 3 块再拿 1 块”，总数都是 2 枚。 - 拓展：如果是力扣另一道题「518. 零钱兑换 II」（求凑出金额的组合种类数），那就必须先遍历硬币，再遍历金额，否则会把 (1,3) 和 (3,1) 算成两种不同的组合（变成排列数了）！这点一定要牢记。
  2. 面试追问：“如果这道题我允许用 DFS（回溯）+ 贪心剪枝，能比 DP 快吗？” - 高级风控对策：可以！这是一个非常著名的优化策略。 - 我们先对 coins 数组从大到小排序。然后用 DFS 去搜索，优先用最大的硬币去填。 - 只要搜到一个合法的组合，就把它的硬币数记录下来作为 minCoins。 - 接下来在其他分支搜索时，如果发现当前的硬币数 + 剩下金额全用目前能用的最大面值去凑，都超过了 minCoins，就立刻剪枝（放弃这条路）。这在某些特定的测试用例下，能比 DP 跑得更快，但代码实现难度极高，面试时优先手写 DP 稳妥过关。
