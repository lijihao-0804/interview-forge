136. 只出现一次的数字

难度简单核心模式异或消去时间复杂度O(n)空间复杂度O(1)

题目与约束

给你一个 非空 整数数组 nums ，除了某个元素只出现一次以外，其余每个元素均出现两次。找出那个只出现了一次的元素。

你必须设计并实现线性时间复杂度的算法来解决此问题，且该算法只使用常量额外空间。

示例 1 ：

输入：nums = [2,2,1] 输出：1

示例 2 ：

输入：nums = [4,1,2,1,2] 输出：4

示例 3 ：

输入：nums = [1] 输出：1

提示：

1 <= nums.length <= 3 * 104 -3 * 104 <= nums[i] <= 3 * 104 除了某个元素只出现一次以外，其余每个元素均出现两次。

🔗 前往力扣原题验证 →

核心不变量

x xor x = 0，且 0 xor x = x。

完整推导

思路推导

  1. 直觉与痛点（哈希表的空间陷阱）：

    绝大多数人的第一直觉是：搞一个 HashSet（集合）或者 HashMap（字典）。遍历数组，如果集合里没有这个数，就把它放进去；如果集合里已经有了，就把他们俩一起消掉。最后集合里剩下的那个孤儿，就是答案。

    痛点：极其完美的时间复杂度 O(N)，但致命伤是空间复杂度 O(N)！因为在最坏情况下（假设所有成对的数字都在前半段，单独的在最后），集合里会堆积大量的数字，直接违背了题目 O(1) 空间的铁律。

  2. 降维破局（异或 ⊕ 的魔法特性）：

    在二进制的世界里，有一个叫“异或 (XOR)”的运算符（在绝大多数语言中符号为 ^）。它的底层逻辑是：“相同为 0，相异为 1”。 基于这个物理特性，异或运算自带了三条仿佛为这道题量身定制的“黄金天规”：

    • 天规一（归零律）：任何数和自己异或，结果永远是 0。即 a⊕a=0。
    • 天规二（恒等律）：任何数和 0 异或，结果永远是它自己。即 a⊕0=a。
    • 天规三（交换律与结合律）：异或的顺序不影响最终结果。即 a⊕b⊕a=(a⊕a)⊕b=0⊕b=b。

  3. 核心微操（全员大混战）：

    有了这三条天规，解法简直呼之欲出：

    我们把数组里所有的数字全部异或在一起！

    因为异或满足交换律，那些出现了两次的数字，就像是有磁性一样，无论它们隔得多远，在异或的长链中最终都会互相抵消变成 0（天规一）。

    最后所有的 0 加在一起还是 0。而那个唯一出现的落单数字，它和 0 异或，依然是它自己（天规二）！

    Java 实现（满分极致极简版）

    C++ 实现

    实现来源：经典解法实现

    1. 异或三性质：x^x=0、x^0=x、交换律
    2. 全员依次异或，成对的互相抵消
    3. 剩余即只出现一次的数字，O(1) 空间
    class Solution {
public:
    int singleNumber(vector<int>& nums) {
        int x = 0;
        for (int n : nums) x ^= n;
        return x;
    }
};

    C 实现

    实现来源：经典解法实现

    1. 异或三性质：x^x=0、x^0=x、交换律
    2. 全员依次异或，成对的互相抵消
    3. 剩余即只出现一次的数字，O(1) 空间
    int singleNumber(int* nums, int numsSize) {
    int x = 0;
    for (int i = 0; i < numsSize; i++) x ^= nums[i];
    return x;
}

class Solution {
    public int singleNumber(int[] nums) {
        // 初始化一个累加器为 0
        int result = 0;

        // 遍历数组中的每一个数字
        for (int num : nums) {
            // 🌟 核心高光时刻：将当前数字与 result 进行异或操作
            // 成对的数字会在不断的运算中自我毁灭，只留下那个天选之子
            result ^= num;
        }

        return result;
    }
}

复杂度

  • 时间复杂度：O(N)。仅仅对数组进行了一次单向线性扫描，由于位运算直接在 CPU 寄存器层面执行，它是所有 O(N) 算法里常数时间最小、跑得最快的。
  • 空间复杂度：O(1)。我们仅仅申请了一个 result 整型变量，真正的极尽苛刻的内存压榨。
易错点与扩展（面试的高频连环位运算）
  1. 面试进阶追问 1：“如果数组里其他数字都出现了【三次】，只有一个数字出现了一次，怎么找？”（对应力扣 137 题：只出现一次的数字 II） - 满分优化思路（状态机/位计数法）：这时候直接异或就行不通了（三个相同的数异或会剩下自己，无法归零）。 - 破局思路：我们在大脑里建立一个长度为 32 的数组（代表整型的 32 个二进制位）。遍历所有数字，把它们在每一位上的 1 加起来。 - 既然绝大多数数字出现了三次，那么在每一位上，这些 1 的总数必定能被 3 整除！如果某一位的 1 的总数对 3 取模后余 1，说明那个“唯一落单的数字”在这一位上肯定是 1！把所有模 3 余 1 的位置拼接起来，就是终极答案。
  2. 面试进阶追问 2：“如果数组里有【两个】数字出现了一次，其余都出现了两次，怎么办？”（对应力扣 260 题：只出现一次的数字 III） - 满分抢答（异或分组法）：我们先把所有数字异或一遍，得到的结果肯定是那两个落单数字的异或值（设为 mask）。 - 既然这两个数字不同，mask 肯定不为 0，它的二进制里肯定至少有一位是 1。 - 这个 1 是怎么来的？说明在这两个落单数字中，一个在这一位是 1，另一个在这一位是 0！ - 我们就拿这一位当“照妖镜”，把原数组拆分成两组：这一位是 1 的分一组，是 0 的分一组。这样，两个落单的数字就被完美地分开了！其余成对的数字肯定会被分进同一组然后内部抵消。最后对这两组分别跑一次普通的异或求和，进阶！
