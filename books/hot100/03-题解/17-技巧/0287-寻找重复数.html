题目信息 内容
难度 中等
核心模式 Floyd 隐式链表
时间复杂度 O(n)
空间复杂度 O(1)

题目与约束

给定一个包含 n + 1 个整数的数组 nums ，其数字都在 [1, n] 范围内（包括 1 和 n）。

可知至少存在一个重复的整数。假设 nums 只有 一个重复的整数 ，返回这个重复的数。

极限约束：你必须不修改数组 nums 且只使用 O(1) 的额外空间。

🔗 前往力扣原题验证 →

核心不变量

把下标到数值看作 next 指针，重复值就是环入口。

完整推导

思路推导

  1. 直觉与痛点（全军覆没的常规武器）：

    • 哈希表：空间复杂度 O(N)，违规。
    • 排序后查相邻：会修改原数组，违规。
    • 原数组标记法（把遍历到的数字对应的索引位置标为负数）：也会修改原数组，违规。

  2. 降维破局（万物皆可为指针）：

    题目里有一个极其诡异但绝非偶然的条件：长度为 n + 1，数字范围在 1 到 n。

    这意味着：数组里的每一个值，都完美对应着数组里的一个有效索引！

    既然如此，我们可以把数组里的“值”，当成指向下一个“索引”的指针！

    比如 nums = [1, 3, 4, 2, 2]：

    • 站在索引 0，值是 1。说明下一步要去索引 1。
    • 站在索引 1，值是 3。说明下一步要去索引 3。
    • 站在索引 3，值是 2。说明下一步要去索引 2。
    • 站在索引 2，值是 4。说明下一步要去索引 4。
    • 站在索引 4，值是 2。说明下一步又要去索引 2！

    你发现了吗？因为有多个位置的值是同一个重复数字（比如例子里的 2），所以有多个指针会共同指向同一个索引！

    这在图论里意味着什么？必定会产生环（Cycle）！而产生环的“入口节点”，绝对就是那个重复的数字！

  3. 核心微操（龟兔赛跑找环入口）：

    这直接退化成了力扣 142 题（环形链表 II）。我们分为两个阶段：

    • 阶段一（证明有环）：派出一只乌龟（slow）和一只兔子（fast）。乌龟每次走一步（nums[slow]），兔子每次走两步（nums[nums[fast]]）。只要有环，兔子必然在环内某处追上乌龟。
    • 阶段二（寻找入口）：相遇后，把乌龟拎回起点（0），兔子留在相遇点。然后让它俩每次都只走一步。当它们再次相遇时，相遇的位置，就是绝对的环入口（也就是我们要找的重复数字）！

    Java 实现（满分 Floyd 判圈版）

class Solution {
    public int findDuplicate(int[] nums) {
        // 阶段 1：快慢指针出发，寻找相遇点
        // 初始位置设在索引 0 (相当于链表的 head)
        int slow = 0;
        int fast = 0;

        // 由于必定有环，使用 do-while 先走一步再判断
        do {
            // 乌龟走一步
            slow = nums[slow];
            // 兔子走两步
            fast = nums[nums[fast]];
        } while (slow != fast); // 直到在环内相遇

        // 阶段 2：寻找环的入口
        // 相遇后，将乌龟或者一个新的指针放回起点
        int finder = 0;

        // 此时 finder 从起点走，fast 从相遇点走，每次都只走一步
        while (finder != fast) {
            finder = nums[finder];
            fast = nums[fast];
        }

        // 再次相遇的地方，就是环的入口，也就是那个重复的数字！
        return finder;
    }
}

复杂度

  • 时间复杂度：O(N)。快慢指针最多在数组中跑两到三圈即可得出结果，标准的线性时间复杂度。
  • 空间复杂度：O(1)。我们仅仅用了 slow、fast 和 finder 三个整型指针变量，完全遵守了最严苛的内存限制。

易错点与扩展（面试的防守反击）

  • 面试面试官追问：“如果面试的时候，你恰好忘记了快慢指针的找环规律，或者一时半会儿没把数组往链表上想，你还有什么能在 O(1) 空间内解题的备用方案吗？”

  • 满分保命回答（二分查找的降维利用）：

    “面试官您好，如果在极端情况下忘了图论规律，我会使用二分查找法！

    注意，我们不是对数组的索引进行二分，而是对数值的范围 [1, n] 进行二分！

    假设 n = 4，数字范围是 [1, 4]。我们取中间值 mid = 2。

    我们去原数组里老老实实数一遍，有多少个数字是 ≤2 的？

    根据抽屉原理，如果不存在重复的 1 或 2，那么 ≤2 的数字最多只会有 2 个。

    如果我们数出来有 3 个甚至更多！说明重复数字一定在 [1, 2] 这个区间里；反之，重复数字就在 [3, 4] 区间里。

    每次二分缩小一半的数值范围，每次判定都需要遍历一遍数组 O(N)。所以整体时间复杂度是 O(NlogN)，空间复杂度依然是 O(1)，不修改原数组。虽然比快慢指针慢，但逻辑极其无懈可击！”
