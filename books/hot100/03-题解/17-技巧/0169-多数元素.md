## 题目与约束

给定一个大小为 `n` 的数组 `nums` ，返回其中的多数元素。多数元素是指在数组中出现次数 **大于** `n / 2` 的元素。

你可以假设数组是非空的，并且给定的数组总是存在多数元素。

## 完整推导

### 思路推导
1. **直觉与痛点（哈希表的空间消耗）**：

   绝大多数人的第一反应是开一个 `HashMap`，遍历数组把每个数字出现的次数存起来，谁的次数超过了 `n / 2` 谁就是答案。

   **痛点**：时间复杂度是极好的 $O(N)$，但空间复杂度也是 $O(N)$。面试官紧接着就会问：“你能把空间复杂度降到 $O(1)$ 吗？”

2. **降维破局（排序法的中间真理）**：

   既然这个数字出现的次数**大于一半**，那我们如果把数组排个序，**正中间的那个数字（索引为 `n / 2`）绝对、必定、一定是它！** 就算它全是全数组最小的数，它也能霸占前一半加中间的位置。

   **痛点**：空间复杂度降到了 $O(1)$，但排序的时间复杂度是 $O(N \log N)$，这还不够快。

3. **终极进阶（摩尔投票法 / 极限一换一）**：

   我们想象整个数组是一片战场，每一个数字代表一个来自不同阵营的士兵。

   因为“多数元素”的数量比**其他所有阵营的士兵总和还要多**。

   那么我们制定一个最惨烈的规则：**不同阵营的士兵相遇，直接同归于尽（极限一换一）！**

   既然你的兵力超过了半数，就算其他所有人全部联合起来打你，一对一消耗到最后，**站在战场上活下来的唯一阵营，必定是你！**

#### 🎮 核心微操（战场的两条铁律）：

我们在代码里只需要维护两个变量：

- `candidate`（当前站在台上的候选阵营）
- `count`（该阵营目前在台上的存活兵力 / 生命值）

遍历数组，依次拉出每一个数字：

1. **如果台上没人了（`count == 0`）**：不管新来的是谁，他直接占领高地，成为新的 `candidate`，并且兵力 `count = 1`。
2. **如果台上有自己人（当前数字 == `candidate`）**：太好了，援军到了！兵力增加 `count++`。
3. **如果台上是敌人（当前数字 != `candidate`）**：直接同归于尽！兵力减少 `count--`。
### Java 实现规范代码（满分摩尔投票版）
```java
class Solution {
    public int majorityElement(int[] nums) {
        // 候选人阵营
        int candidate = 0;
        // 当前候选人的存活兵力（生命值）
        int count = 0;

        // 士兵依次入场
        for (int num : nums) {
            // 如果台上已经没人了，新来的士兵直接占领阵地
            if (count == 0) {
                candidate = num;
            }

            // 🌟 核心战斗逻辑：
            // 如果来的是自己人，兵力 +1；如果来的是敌人，同归于尽（兵力 -1）
            if (num == candidate) {
                count++;
            } else {
                count--;
            }
        }

        // 最终活到最后的，必定是数量超过半数的那个“多数元素”
        return candidate;
    }
}
```
### 复杂度
  给定一个大小为 `n`的数组 `nums` ，返回其中的多数元素。多数元素是指在数组中出现次数 **大于** `⌊ n/2 ⌋` 的元素。

  你可以假设数组是非空的，并且给定的数组总是存在多数元素。

  **示例 1：**

  **输入：**nums = [3,2,3]<br>**输出：**3

  **示例 2：**

  **输入：**nums = [2,2,1,1,1,2,2]<br>**输出：**2

  **提示：**

  - `n == nums.length`
  - `1 <= n <= 5 * 104`
  - `-109 <= nums[i] <= 109`
  - 输入保证数组中一定有一个多数元素。

  **进阶：**尝试设计时间复杂度为 O(n)、空间复杂度为 O(1) 的算法解决此问题。

- **时间复杂度**：$O(N)$。仅仅对数组进行了一次极其流畅的单向遍历，速度拉满。
- **空间复杂度**：$O(1)$。我们仅仅用了 `candidate` 和 `count` 两个变量，直接把空间压榨到了常数级别的物理极限。

### 易错点与扩展（面试的关键连环追问）

- **面试追问 1：“题目里假设了『多数元素必定存在』。如果我去掉这个假设，有可能没有任何一个数字超过半数，你这个代码还能直接用吗？”**
  - **满分避坑回答（二次校验）**：绝不能直接用！如果数组是 `[1, 2, 3]`，摩尔投票法最后会随便选出一个幸存者（比如 3），但 3 的数量并没有超过一半。
  - **破局对策**：我们需要再加一次 $O(N)$ 的遍历！摩尔投票法选出来的只是“最有希望的嫌疑人”。选出来之后，我们再扫一遍数组，老老实实地数一下这个嫌疑人到底出现了几次。如果真的超过了 `n / 2`，再返回它；否则返回 -1。
- **面试终极进阶：“如果题目要求找出所有出现次数超过 `n / 3` 的元素呢？”（对应力扣 229 题：多数元素 II）**
  - **满分优化思路（双重摩尔投票）**：超过 `n / 3` 的数字，**最多只可能有 2 个**！
  - 我们直接在台上设 **2 个候选人**位置（`candidate1`, `candidate2`）和 **2 个兵力值**（`count1`, `count2`）。
  - 遍历数组：如果是自己人就加对应兵力；如果是完全无关的第三方敌人，**三个阵营一起极限一换一**（即 `count1--` 且 `count2--`）！
  - 最后活下来的最多两个嫌疑人，再二次遍历统计一遍次数即可。这就叫举一反三的架构级思维！

## Python 完整推导

### 不同阵营一对一抵消，多数派一定活到最后

多数元素出现次数严格超过一半。把当前候选与其支持者看作一方的净票数：遇到同值就加票，遇到不同值就减票；票数归零后，换下一个元素成为候选。不同值两两抵消时，多数元素的数量大于其余全部数量之和，因此不可能在抵消中完全消失。

### 用 `[2, 2, 1, 1, 1, 2, 2]` 逐项投票

1. 第一个 2：候选变为 2，票数 1。
2. 第二个 2：与候选相同，票数变为 2。
3. 第一个 1：不同，票数减为 1。
4. 第二个 1：不同，票数归零。
5. 第三个 1：票数为 0，先把它设为新候选，再记一票，票数 1。
6. 第一个末尾 2：与候选 1 不同，票数归零。
7. 最后一个 2：票数重新从 0 开始，候选设为 2，票数 1。

扫描结束，候选为 2。票数 1 不是数字 2 的真实总频次，它只表示抵消之后还剩一张净票。

若题目不保证多数元素存在，这个候选只能算嫌疑人，还需要再扫一遍验证频次是否超过 `n // 2`。本题输入保证存在，因此一次投票足够。

### Python 实现

> 参考来源：经典解法实现
>
> 沿用旧项目“经典解法实现”的摩尔投票 Python 代码；变量、分支换行和注释按本页整理。

```python
from typing import List


class Solution:
    def majorityElement(self, nums: List[int]) -> int:
        candidate = 0
        count = 0
        for value in nums:
            if count == 0:
                candidate = value
            if value == candidate:
                count += 1
            else:
                count -= 1
        return candidate
```

### 两步投票分支

每轮先检查 `count == 0`；为零时把当前值设成 `candidate`。随后再比较当前值是否等于 candidate，相同就加一，不同就减一。当前候选刚被设置时，本次元素会恰好贡献第一张支持票。

不要用 `candidate` 的初始值假设数组有某个数；count 为 0 时总会立即覆盖候选。题目保证数组非空。

### 时间与空间

数组只扫描一次，时间是 O(n)；候选和票数是两个标量，空间 O(1)。排序取中位数也能解题，但会改变 O(n log n) 的时间。

### 复杂度

- 时间复杂度：`O(n)`。
- 空间复杂度：`O(1)`。

一次扫描逐元素做常数次比较，时间 O(n)；只维护候选值和票数，空间 O(1)。

```cpp
class Solution {
public:
    int majorityElement(vector<int>& nums) {
        int cand = 0, count = 0;
        for (int n : nums) {
            if (count == 0) cand = n;
            count += (n == cand) ? 1 : -1;
        }
        return cand;
    }
};
```

## C 实现

<ol class="lang-steps"><li>摩尔投票：不同的数互相抵消，计数归零换候选人</li><li>出现次数超过 n/2 的元素必然存活到最后</li><li>候选人即多数元素</li></ol>

```c
int majorityElement(int* nums, int numsSize) {
    int cand = 0, count = 0;
    for (int i = 0; i < numsSize; i++) {
        if (count == 0) cand = nums[i];
        count += (nums[i] == cand) ? 1 : -1;
    }
    return cand;
}
```
