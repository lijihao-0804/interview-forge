## 题目与约束

给定一个包含 `n + 1` 个整数的数组 `nums` ，其数字都在 `[1, n]` 范围内（包括 `1` 和 `n`），可知至少存在一个重复的整数。

  假设 `nums` 只有 **一个重复的整数** ，返回 **这个重复的数** 。

  你设计的解决方案必须 **不修改** 数组 `nums` 且只用常量级 `O(1)` 的额外空间。

  **示例 1：**

  **输入：**nums = [1,3,4,2,2]<br>**输出：**2

  **示例 2：**

  **输入：**nums = [3,1,3,4,2]<br>**输出：**3

  **示例 3 :**

  **输入：**nums = [3,3,3,3,3]<br>**输出：**3

  **提示：**

  - `1 <= n <= 105`
  - `nums.length == n + 1`
  - `1 <= nums[i] <= n`
  - `nums` 中 **只有一个整数** 出现 **两次或多次** ，其余整数均只出现 **一次**

  **进阶：**

  - 如何证明 `nums` 中至少存在一个重复的数字?
  - 你可以设计一个线性级时间复杂度 `O(n)` 的解决方案吗？

## 完整推导

### 思路推导
  1. **直觉与痛点（全军覆没的常规武器）**：

     - **哈希表**：空间复杂度 $O(N)$，违规。
     - **排序后查相邻**：会修改原数组，违规。
     - **原数组标记法（把遍历到的数字对应的索引位置标为负数）**：也会修改原数组，违规。

  2. **降维破局（万物皆可为指针）**：

     题目里有一个极其诡异但绝非偶然的条件：**长度为 `n + 1`，数字范围在 `1` 到 `n`**。

     这意味着：**数组里的每一个值，都完美对应着数组里的一个有效索引！**

     既然如此，我们可以把数组里的“值”，当成指向下一个“索引”的**指针**！

     比如 `nums = [1, 3, 4, 2, 2]`：

     - 站在索引 `0`，值是 `1`。说明下一步要去索引 `1`。
     - 站在索引 `1`，值是 `3`。说明下一步要去索引 `3`。
     - 站在索引 `3`，值是 `2`。说明下一步要去索引 `2`。
     - 站在索引 `2`，值是 `4`。说明下一步要去索引 `4`。
     - 站在索引 `4`，值是 `2`。说明下一步又要去索引 `2`！

     你发现了吗？因为有多个位置的值是**同一个重复数字**（比如例子里的 `2`），所以有多个指针会**共同指向同一个索引**！

     这在图论里意味着什么？**必定会产生环（Cycle）！而产生环的“入口节点”，绝对就是那个重复的数字！**

  3. **核心微操（龟兔赛跑找环入口）**：

     这直接退化成了力扣 142 题（环形链表 II）。我们分为两个阶段：

     - **阶段一（证明有环）**：派出一只乌龟（`slow`）和一只兔子（`fast`）。乌龟每次走一步（`nums[slow]`），兔子每次走两步（`nums[nums[fast]]`）。只要有环，兔子必然在环内某处追上乌龟。
     - **阶段二（寻找入口）**：相遇后，把乌龟拎回起点（`0`），兔子留在相遇点。然后让它俩**每次都只走一步**。当它们再次相遇时，相遇的位置，就是绝对的环入口（也就是我们要找的重复数字）！
### Java 实现（满分 Floyd 判圈版）
```java
class Solution {
    public int findDuplicate(int[] nums) {
        // 阶段 1：快慢指针出发，寻找相遇点
        // 初始位置设在索引 0 (相当于链表的 head)
        int slow = 0;
        int fast = 0;

        // 由于必定有环，使用 do-while 先走一步再判断
        do {
            // 乌龟走一步
            slow = nums[slow];
            // 兔子走两步
            fast = nums[nums[fast]];
        } while (slow != fast); // 直到在环内相遇

        // 阶段 2：寻找环的入口
        // 相遇后，将乌龟或者一个新的指针放回起点
        int finder = 0;

        // 此时 finder 从起点走，fast 从相遇点走，每次都只走一步
        while (finder != fast) {
            finder = nums[finder];
            fast = nums[fast];
        }

        // 再次相遇的地方，就是环的入口，也就是那个重复的数字！
        return finder;
    }
}
```
### 复杂度
  - **时间复杂度**：$O(N)$。快慢指针最多在数组中跑两到三圈即可得出结果，标准的线性时间复杂度。
  - **空间复杂度**：$O(1)$。我们仅仅用了 `slow`、`fast` 和 `finder` 三个整型指针变量，完全遵守了最严苛的内存限制。

### 易错点与扩展（面试的防守反击）

- **面试面试官追问：“如果面试的时候，你恰好忘记了快慢指针的找环规律，或者一时半会儿没把数组往链表上想，你还有什么能在 $O(1)$ 空间内解题的备用方案吗？”**

  - **满分保命回答（二分查找的降维利用）**：

    “面试官您好，如果在极端情况下忘了图论规律，我会使用**二分查找法**！

    注意，我们不是对数组的索引进行二分，而是对**数值的范围 `[1, n]` 进行二分**！

    假设 `n = 4`，数字范围是 `[1, 4]`。我们取中间值 `mid = 2`。

    我们去原数组里老老实实数一遍，有多少个数字是 $\le 2$ 的？

    根据抽屉原理，如果不存在重复的 `1` 或 `2`，那么 $\le 2$ 的数字最多只会有 2 个。

    如果我们数出来有 3 个甚至更多！说明重复数字一定在 `[1, 2]` 这个区间里；反之，重复数字就在 `[3, 4]` 区间里。

    每次二分缩小一半的数值范围，每次判定都需要遍历一遍数组 $O(N)$。所以整体时间复杂度是 $O(N \log N)$，空间复杂度依然是 $O(1)$，不修改原数组。虽然比快慢指针慢，但逻辑极其无懈可击！”

## Python 完整推导

### 把下标到数值看成一条链表

题目数组长度为 `n+1`，每个值都在 1 到 n 之间，所以 `i -> nums[i]` 一定指向一个合法下标。某个重复值会被多个下标共同指向；沿这条映射往前走，最后一定进入一个环，而环的入口值正是重复数字。

这和判断环形链表入口相同。快慢指针先找环内相遇点；再把一个指针放回起点，双方每次走一步，第二次相遇的位置就是环入口。

### 用 `[1, 3, 4, 2, 2]` 看路径

映射为 `0→1`、`1→3`、`2→4`、`3→2`、`4→2`。从 0 出发的路径是 `0,1,3,2,4,2,...`，进入由 2 和 4 构成的环，入口是 2。

代码先把 slow 和 fast 都设为 `nums[0] = 1`。第一次循环中，slow 从 1 到 3，fast 走两步到 2；第二次循环中，slow 到 2，fast 从 2 出发走两步仍到 2，两者第一次相遇。

相遇后，把一个指针重置到 `nums[0] = 1`，另一个留在相遇点 2。两者都每次沿映射走一步：先分别到 3 和 4，再到 2 和 2，第二次相遇的位置是 2，它就是重复数字。

数组本身始终只读，没有标记或排序。

### Python 实现

> 参考来源：灵茶山艾府题解（MIT License）
>
> 沿用旧项目收录、标注灵茶山艾府的 Floyd 判圈 Python 代码；把第二阶段新指针命名为 `slow`，变量与注释按本页整理。

```python
from typing import List


class Solution:
    def findDuplicate(self, nums: List[int]) -> int:
        slow = nums[0]
        fast = nums[0]
        while True:
            slow = nums[slow]
            fast = nums[nums[fast]]
            if slow == fast:
                break

        slow = nums[0]
        while slow != fast:
            slow = nums[slow]
            fast = nums[fast]
        return slow
```

### 第一次相遇与第二次相遇

`slow = nums[slow]` 前进一个节点，`fast = nums[nums[fast]]` 前进两个节点。第一次 `while True` 必须用先走再判断的结构，因为两者初始都在起点，先比较会立刻误判为已经相遇。

相遇后执行 `slow = nums[0]`，fast 留在环内。第二阶段两者每次都走一步，`while slow != fast` 结束时，位置就是环入口。题目中入口值等于重复值。

### 为什么不能改数组

排序、负数标记和 visited 集合分别会修改输入或使用 O(n) 空间，都不符合本题进阶要求。Floyd 只保存两个下标，额外空间 O(1)；第二阶段也只需要两个指针。

### 复杂度

- 时间复杂度：`O(n)`。
- 空间复杂度：`O(1)`。

快指针在长度 O(n) 的函数图上进入环并相遇，第二阶段至多走 O(n) 步；只保存三个下标，额外空间 O(1)。

## C++ 实现

> 实现来源：灵茶山艾府题解（MIT License）



```cpp
// 代码逻辑同 142. 环形链表 II
class Solution {
public:
    int findDuplicate(vector<int>& nums) {
        int slow = 0, fast = 0; // 0 一定不在环上，适合作为起点
        while (true) {
            slow = nums[slow]; // 等价于 slow = slow.next
            fast = nums[nums[fast]]; // 等价于 fast = fast.next.next
            if (fast == slow) { // 快慢指针移动到同一个节点
                break;
            }
        }

        int head = 0; // 再用一个指针，从起点出发
        while (slow != head) {
            slow = nums[slow];
            head = nums[head];
        }
        return slow; // 入环口即重复元素
    }
};
```
