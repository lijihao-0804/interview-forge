3. 无重复字符的最长子串

难度中等
Java 主方法可变滑动窗口时间O(n)空间O(字符集)
Python 主方法最近位置哈希 + 滑动窗口时间O(n)空间O(min(n, Σ))

题目与约束

给定一个字符串 s ，请你找出其中不含有重复字符的 最长 子串的长度。

示例 1:

输入:s = "abcabcbb"
输出:3
解释: 因为无重复字符的最长子串是 "abc"，所以其长度为 3。注意 "bca" 和 "cab" 也是正确答案。

示例 2:

输入:s = "bbbbb"
输出:1
解释:因为无重复字符的最长子串是 "b"，所以其长度为 1。

示例 3:

输入:s = "pwwkew"
输出:3
解释:因为无重复字符的最长子串是 "wke"，所以其长度为 3。
请注意，你的答案必须是 子串的长度，"pwke" 是一个子序列，不是子串。

提示：

  • 0 <= s.length <= 105
  • s 由英文字母、数字、符号和空格组成

Java 完整推导

Java 核心不变量

窗口内始终无重复，left 只能向右不能回退。

完整推导

思路推导

  1. 直觉与痛点（暴力枚举）：

    搞两个 for 循环找遍所有的子串，再写一个函数检查每个子串里有没有重复字符。

    痛点：时间复杂度高达 O(N3)。字符串稍长一点就卡死。

  2. 破局思路（滑动窗口 + 哈希表）：

    我们需要一个“窗口”在字符串上滑动。

    • 右边界（右指针）：负责主动向右探索，把新的字符拉进窗口。
    • 左边界（左指针）：负责在遇到危险（出现重复字符）时，向右收缩，把重复的字符踢出窗口。
    • 哈希表：用来充当“查重神器”。更妙的是，如果哈希表里记录的不仅是字符，而是字符最后一次出现的索引，我们的左指针甚至不需要一步步往右挪，可以直接“瞬间跳跃”到重复字符的下一个位置！

  3. 逻辑推演（以 s = "abcabcbb" 为例）：

    窗口起初是空的。left = 0, right = 0。

    • right 遇到 a，存入 Map：{a:0}。窗口是 [a]，长度 1。
    • right 遇到 b，存入 Map：{a:0, b:1}。窗口是 [a,b]，长度 2。
    • right 遇到 c，存入 Map：{a:0, b:1, c:2}。窗口是 [a,b,c]，长度 3。
    • 高能预警：right 走到索引 3 遇到第二个 a。查 Map 发现 a 出现过，且位置在索引 0（在当前窗口内）。
    • 左指针跳跃：为了把旧的 a 踢出去，left 直接跳到 旧a的位置 + 1，也就是索引 1。窗口变成了 [b,c,a]。更新 Map 中 a 的位置为 3。继续探索……

    Java 实现

import java.util.HashMap;
import java.util.Map;

class Solution {
    public int lengthOfLongestSubstring(String s) {
        // 定义哈希表：Key 存字符，Value 存该字符最后一次出现的索引
        Map<Character, Integer> map = new HashMap<>();

        int maxLength = 0; // 全局最大长度
        int left = 0;      // 窗口的左边界

        // right 是窗口的右边界，主动向右扩张
        for (int right = 0; right < s.length(); right++) {
            char c = s.charAt(right);

            // 如果遇到了曾见过的字符，并且这个字符【还在我们当前的窗口内】
            if (map.containsKey(c) && map.get(c) >= left) {
                // 左边界直接跳跃到该重复字符上一次出现位置的下一个位置
                // 这样就把那个重复的字符彻底从窗口里“踢”出去了
                left = map.get(c) + 1;
            }

            // 记录（或更新）当前字符最新的索引位置
            map.put(c, right);

            // 计算当前窗口的长度，并挑战历史最大记录
            // 窗口长度公式：右边界 - 左边界 + 1
            maxLength = Math.max(maxLength, right - left + 1);
        }

        return maxLength;
    }
}

复杂度

  • 时间复杂度：O(N)。右指针把字符串遍历了一次，左指针发生跳跃，没有任何回溯。哈希表的查询和插入都是 O(1)。
  • 空间复杂度：O(Σ)。其中 Σ 是字符集的大小（例如 ASCII 码表共有 128 个字符）。哈希表最多存储 Σ 个键值对。
易错点与扩展

  1. 致命陷阱（必考坑点）：为什么必须加 map.get(c) >= left 这个条件？只写 map.containsKey(c) 不行吗？ - 大错特错！ 这是无数人挂掉的地方。假设字符串是 "abba"。 - 遍历到第一个 b，left=0。 - 遍历到第二个 b，遇到重复，left 跳到 2。此时窗口里只有 [b]。 - 遍历到最后的 a，你查 Map，发现 a 确实在 Map 里（之前在索引 0 存过）。如果你不加判断直接 left = map.get('a') + 1，你的 left 会倒退回索引 1！但此时那个旧的 a 早就已经被剔除出窗口了，根本不构成重复。 - 结论：map.get(c) >= left 这个条件是为了确保，你遇到的这个“老熟人”，确实还赖在你当前的窗口里没走。如果他在 left 左边，说明他早就在之前的收缩中被踢出去了，对当前窗口无影响，直接无视他。

  2. 极致性能优化（优化思路）： - 面试官问：“能把耗时从 5ms 压到 1ms 吗？”

  • 既然题目通常只包含 ASCII 字符，完全可以用一个长度为 128 的整型数组 int[] 来代替 HashMap。

  • 代码：int[] index = new int[128];（存的是字符的 ASCII 码对应的最新位置）。因为数组寻址是内存底层操作，比 HashMap 的哈希计算和对象创建快了无数倍。这叫“数组代替哈希表优化法”。

Python 完整推导

直觉：窗口向右探索，左边界只在必要时跳跃

用两个边界夹出一个没有重复字符的窗口。右边界负责向右探索，把新字符拉进来；左边界负责在出现重复时向右收缩，把旧的那个字符踢出去。

这里用一个字典 last 保存“字符最近一次出现在哪”。这样不必一步步删除窗口左侧的字符，重复发生时可以让 left 一次跳过一整段。关键在于：字典里的旧位置不一定还在当前窗口内，所以更新边界时要取 left = max(left, last[ch] + 1)。max 的作用是保住当前左边界，绝不允许它向左倒退。

以 abcabcbb 走一遍

初始为 left = 0、best = 0、last = {}。字符下标从 0 开始，best 记录目前找到的最长长度。

  1. 右边界拿到下标 0 的 a，没有重复。记下 last['a'] = 0，窗口是 a，best = 1。
  2. 拿到下标 1 的 b，还是没有重复。记下 last['b'] = 1，窗口扩成 ab，best = 2。
  3. 拿到下标 2 的 c，窗口扩成 abc，记下它的位置，best = 3。
  4. 下标 3 又来了一个 a！旧的 a 在下标 0，还在窗口里。让 left 跳到 0 + 1 = 1，把旧的 a 踢出去，再记下新位置 last['a'] = 3。窗口变成 bca，长度仍为 3。
  5. 下标 4 来了 b，旧的 b 在下标 1。让 left 跳到 2，更新 last['b'] = 4，窗口变成 cab。
  6. 下标 5 来了 c，旧的 c 在下标 2。让 left 跳到 3，更新 last['c'] = 5，窗口变成 abc。
  7. 下标 6 又是 b，这次旧的 b 在下标 4。让 left 从 3 直接跳到 5，窗口只剩 cb，再更新 last['b'] = 6。为了保持子串连续，旧 b 前面的 a 也一起离开窗口。
  8. 下标 7 还是 b，旧位置是 6。让 left 跳到 7，窗口只剩当前这个 b。

扫描结束，过程中最长的窗口长度是 3，因此返回 3。字典会不断更新字符的最近位置；它不需要随着窗口收缩逐项删除，下一节说明旧记录为什么不会干扰答案。

abba：为什么不能直接倒退

走到第三个字符 b 时，窗口右端是下标 2，last['b'] = 1，于是 left = max(0, 1 + 1) = 2，当前窗口只剩下标 2 的 b。

最后扫描下标 3 的 a 时，last['a'] 仍是 0。若直接写 left = last['a'] + 1，左边界会从 2 退到 1，重新把一个已经排除的 b 拉回窗口；正确的 max(2, 0 + 1) 仍得到 2，窗口是下标 [2, 3] 的 ba，答案保持 2。

Python 实现

参考来源：代码随想录（programmercarl.com）

代码采用项目原收录的代码随想录最近位置字典实现，只整理变量、注释与签名；算法未改变。

class Solution:
    def lengthOfLongestSubstring(self, s: str) -> int:
        last = {}  # 字符 -> 最近一次出现的下标
        left = 0
        best = 0

        for right, ch in enumerate(s):
            if ch in last:
                # 旧位置可能已经在 left 左侧，max 保证左边界只向右移动
                left = max(left, last[ch] + 1)

            last[ch] = right
            best = max(best, right - left + 1)

        return best

这段代码的 Python 细节

  • enumerate(s) 直接给出 right 和字符 ch，后续窗口长度也直接用 right - left + 1，不需要另起一个计数器。
  • 先用 ch in last 判断是否见过，再读取 last[ch]；这样不会对不存在的键取值。见过的旧位置即使已经落在当前窗口外，也会由 max 忽略，不必从字典删除。
  • 必须先把 left 调整好，再更新 last[ch] = right。如果顺序反过来，读到的最新位置就是当前位置，窗口会错误地缩短。
  • max 出现两次但含义不同：第一次守住左边界，第二次刷新历史最大长度。空字符串不会进入循环，best 仍为 0。

复杂度

  • 时间复杂度：O(n)。
  • 空间复杂度：O(min(n, Σ))。

right 只扫描一遍，left 只右移；字典查询和写入按平均 O(1) 计，字典最多保存字符集大小的键。

C++ 实现

实现来源：代码随想录（programmercarl.com）

class Solution {
public:
    int lengthOfLongestSubstring(string s) {
        // 滑动窗口：[l, r]
        int l = 0;              // 窗口左边界
        int result = 0;         // 记录最大长度

        // 哈希表：记录每个字符最近一次出现的位置（下标）
        unordered_map<char, int> umap;

        // r 作为窗口右边界，不断向右扩展
        for (int r = 0; r < (int)s.size(); r++) {

            // 如果 s[r] 曾经出现过，说明窗口可能出现重复
            // 需要把 l 移动到“上一次出现位置 + 1”
            if (umap.find(s[r]) != umap.end()) {
                // 注意：l 只能往右移动，不能往左回退
                // 因为可能出现：该字符的上次出现位置在窗口左边界 l 的左侧
                l = max(l, umap[s[r]] + 1);
            }

            // 更新 s[r] 最近一次出现的位置
            umap[s[r]] = r;

            // 当前窗口长度：r - l + 1
            result = max(result, r - l + 1);
        }

        return result;
    }
};

Go 实现

实现来源：代码随想录（programmercarl.com）

func lengthOfLongestSubstring(s string) int {
    last := make(map[byte]int) // char -> last index
    l, res := 0, 0

    for r := 0; r < len(s); r++ {
        ch := s[r]
        if idx, ok := last[ch]; ok {
            if idx+1 > l { // l 只能右移，不能回退
                l = idx + 1
            }
        }
        last[ch] = r
        if r-l+1 > res {
            res = r - l + 1
        }
    }
    return res
}
