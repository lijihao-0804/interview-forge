3. 无重复字符的最长子串

难度中等核心模式可变滑动窗口时间复杂度O(n)空间复杂度O(字符集)

题目与约束

给定一个字符串 s ，请你找出其中不含有重复字符的 最长 子串的长度。

示例 1:

输入:s = "abcabcbb"
输出:3
解释: 因为无重复字符的最长子串是 "abc"，所以其长度为 3。注意 "bca" 和 "cab" 也是正确答案。

示例 2:

输入:s = "bbbbb"
输出:1
解释:因为无重复字符的最长子串是 "b"，所以其长度为 1。

示例 3:

输入:s = "pwwkew"
输出:3
解释:因为无重复字符的最长子串是 "wke"，所以其长度为 3。
请注意，你的答案必须是 子串的长度，"pwke" 是一个子序列，不是子串。

提示：

  • 0 <= s.length <= 105
  • s 由英文字母、数字、符号和空格组成

核心不变量

窗口内始终无重复，left 只能向右不能回退。

完整推导

思路推导

  1. 直觉与痛点（暴力枚举）：

    搞两个 for 循环找遍所有的子串，再写一个函数检查每个子串里有没有重复字符。

    痛点：时间复杂度高达 O(N3)。字符串稍长一点就卡死。

  2. 破局思路（滑动窗口 + 哈希表）：

    我们需要一个“窗口”在字符串上滑动。

    • 右边界（右指针）：负责主动向右探索，把新的字符拉进窗口。
    • 左边界（左指针）：负责在遇到危险（出现重复字符）时，向右收缩，把重复的字符踢出窗口。
    • 哈希表：用来充当“查重神器”。更妙的是，如果哈希表里记录的不仅是字符，而是字符最后一次出现的索引，我们的左指针甚至不需要一步步往右挪，可以直接“瞬间跳跃”到重复字符的下一个位置！

  3. 逻辑推演（以 s = "abcabcbb" 为例）：

    窗口起初是空的。left = 0, right = 0。

    • right 遇到 a，存入 Map：{a:0}。窗口是 [a]，长度 1。
    • right 遇到 b，存入 Map：{a:0, b:1}。窗口是 [a,b]，长度 2。
    • right 遇到 c，存入 Map：{a:0, b:1, c:2}。窗口是 [a,b,c]，长度 3。
    • 高能预警：right 走到索引 3 遇到第二个 a。查 Map 发现 a 出现过，且位置在索引 0（在当前窗口内）。
    • 左指针跳跃：为了把旧的 a 踢出去，left 直接跳到 旧a的位置 + 1，也就是索引 1。窗口变成了 [b,c,a]。更新 Map 中 a 的位置为 3。继续探索……

import java.util.HashMap;
import java.util.Map;

class Solution {
    public int lengthOfLongestSubstring(String s) {
        // 定义哈希表：Key 存字符，Value 存该字符最后一次出现的索引
        Map<Character, Integer> map = new HashMap<>();

        int maxLength = 0; // 全局最大长度
        int left = 0;      // 窗口的左边界

        // right 是窗口的右边界，主动向右扩张
        for (int right = 0; right < s.length(); right++) {
            char c = s.charAt(right);

            // 如果遇到了曾见过的字符，并且这个字符【还在我们当前的窗口内】
            if (map.containsKey(c) && map.get(c) >= left) {
                // 左边界直接跳跃到该重复字符上一次出现位置的下一个位置
                // 这样就把那个重复的字符彻底从窗口里“踢”出去了
                left = map.get(c) + 1;
            }

            // 记录（或更新）当前字符最新的索引位置
            map.put(c, right);

            // 计算当前窗口的长度，并挑战历史最大记录
            // 窗口长度公式：右边界 - 左边界 + 1
            maxLength = Math.max(maxLength, right - left + 1);
        }

        return maxLength;
    }
}

复杂度

  • 时间复杂度：O(N)。右指针把字符串遍历了一次，左指针发生跳跃，没有任何回溯。哈希表的查询和插入都是 O(1)。
  • 空间复杂度：O(Σ)。其中 Σ 是字符集的大小（例如 ASCII 码表共有 128 个字符）。哈希表最多存储 Σ 个键值对。
易错点与扩展

  1. 致命陷阱（必考坑点）：为什么必须加 map.get(c) >= left 这个条件？只写 map.containsKey(c) 不行吗？ - 大错特错！ 这是无数人挂掉的地方。假设字符串是 "abba"。 - 遍历到第一个 b，left=0。 - 遍历到第二个 b，遇到重复，left 跳到 2。此时窗口里只有 [b]。 - 遍历到最后的 a，你查 Map，发现 a 确实在 Map 里（之前在索引 0 存过）。如果你不加判断直接 left = map.get('a') + 1，你的 left 会倒退回索引 1！但此时那个旧的 a 早就已经被剔除出窗口了，根本不构成重复。 - 结论：map.get(c) >= left 这个条件是为了确保，你遇到的这个“老熟人”，确实还赖在你当前的窗口里没走。如果他在 left 左边，说明他早就在之前的收缩中被踢出去了，对当前窗口无影响，直接无视他。

  2. 极致性能优化（优化思路）： - 面试官问：“能把耗时从 5ms 压到 1ms 吗？”

  • 既然题目通常只包含 ASCII 字符，完全可以用一个长度为 128 的整型数组 int[] 来代替 HashMap。

  • 代码：int[] index = new int[128];（存的是字符的 ASCII 码对应的最新位置）。因为数组寻址是内存底层操作，比 HashMap 的哈希计算和对象创建快了无数倍。这叫“数组代替哈希表优化法”。
