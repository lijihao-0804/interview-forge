## 题目与约束

给定一个长度为 `n` 的 **0 索引**整数数组 `nums`。初始位置在下标 0。

  每个元素 `nums[i]` 表示从索引 `i` 向后跳转的最大长度。换句话说，如果你在索引 `i` 处，你可以跳转到任意 `(i + j)` 处：

  - `0 <= j <= nums[i]` 且
  - `i + j < n`

  返回到达 `n - 1` 的最小跳跃次数。测试用例保证可以到达 `n - 1`。

  **示例 1:**

  **输入:** nums = [2,3,1,1,4]<br>**输出:** 2<br>**解释:** 跳到最后一个位置的最小跳跃数是 `2`。<br>     从下标为 0 跳到下标为 1 的位置，跳 `1` 步，然后跳 `3` 步到达数组的最后一个位置。

  **示例 2:**

  **输入:** nums = [2,3,0,1,4]<br>**输出:** 2

  **提示:**

  - `1 <= nums.length <= 104`
  - `0 <= nums[i] <= 1000`
  - 题目保证可以到达 `n - 1`

## 完整推导

### 思路推导
  1. **直觉与痛点（过早决策的陷阱）**：

     假设数组是 `[2, 3, 1, 1, 4]`。站在索引 0（数字 2），你可以跳到索引 1 或索引 2。

     你应该跳到哪里？如果你短视地直接跳到索引 2，你会发现那里是个 1，接下来举步维艰；如果你跳到索引 1，那里是个 3，可以直接带你飞到终点。

     **痛点**：如果你每次都盲目地“跳最大步数”，或者用 DFS 去穷举，都会陷入效率陷阱。

  2. **破局思路（引入“阶段性结界”）**：

     我们不仅要维护一个“历史能探测到的最远距离（`maxReach`）”，还要额外维护一个“当前这一跳能管辖的极限边界（`currentEnd`）”。

     - 站在起点，我们获得第一阶段的极限边界。
     - 我们开始在边界内巡逻（遍历）。在巡逻的过程中，我们不断东张西望，把沿途所有起跳点能到达的更远距离都记录在 `maxReach` 里。这叫“蓄力”。
     - **什么时候必须起跳？** 当我们一步步走到当前阶段的极限边界 `currentEnd` 时，说明这一步的红利彻底吃干榨净了！此时，我们**被迫起跳（跳跃次数 `+1`）**，并将边界更新为我们刚才蓄力攒下的 `maxReach`，开启下一阶段的巡逻！
### Java 实现（满分延迟决策版）
```Java
class Solution {
    public int jump(int[] nums) {
        // 如果数组长度只有 1，你已经在终点了，不需要跳
        if (nums.length == 1) return 0;

        // 记录跳跃的次数
        int jumps = 0;
        // 记录当前这一跳所能管辖的最远边界
        int currentEnd = 0;
        // 记录在遍历过程中，探路雷达发现的全局最远距离
        int maxReach = 0;

        // 🌟 致命细节：为什么只遍历到 nums.length - 2（即 i < nums.length - 1）？
        // 因为如果你遍历到了最后一个元素，并且恰好 currentEnd 就是最后一个元素，
        // 算法会傻乎乎地再加一次 jump，但其实你已经到终点了！
        for (int i = 0; i < nums.length - 1; i++) {

            // 1. 沿途巡逻，疯狂蓄力：看看在当前边界内，谁能跳得最远
            maxReach = Math.max(maxReach, i + nums[i]);

            // 2. 撞南墙了：当前这一跳的红利吃光了，被迫起跳！
            if (i == currentEnd) {
                jumps++; // 真实地跳出一步
                currentEnd = maxReach; // 边界扩张为刚刚蓄力攒下的最远距离

                // 性能优化（剪枝）：如果更新后的边界已经能盖住终点了，提前下班！
                if (currentEnd >= nums.length - 1) {
                    break;
                }
            }
        }

        return jumps;
    }
}
```
### 复杂度
  - **时间复杂度**：**$O(N)$**。我们只需要从头到尾遍历数组一次，在边界处做一下交接，没有多余的循环。
  - **空间复杂度**：**$O(1)$**。全程只维护了 `jumps`, `currentEnd`, `maxReach` 三个变量。

### 易错点与扩展（面试的关键陷阱）

1. **极度高频坑点：“为什么循环条件是 `i < nums.length - 1`，而不是 `i < nums.length`？”**
   - **面试面试官最爱抓的细节**：假设数组是 `[2, 3, 1]`。
   - 起点 `i=0`：`maxReach = 2`，此时 `i == currentEnd (0)`，被迫起跳，`jumps` 变成 1，`currentEnd` 变成 2。
   - 接着走到 `i=1`：`maxReach = 4`。
   - 走到 `i=2`（最后一个元素）：如果你的循环包含最后一个元素，此时发现 `i == currentEnd (2)`，程序会**错误地再次触发起跳**，让 `jumps` 变成 2！
   - **真相**：只要你抵达了最后一步，你就赢了，绝对不需要在终点线上再起跳一次！所以我们要把最后一个元素排除在循环之外。
2. **升华总结：“BFS (广度优先搜索) 的降维”**
   - 其实，这道题的贪心逻辑，本质上是 **隐式的广度优先搜索 (BFS)**。
   - 起点 `[0]` 是第 0 层。
   - 起点能跳到的 `[1, 2]` 是第 1 层。
   - `[1, 2]` 能跳到的更远的地方是第 2 层。
   - `currentEnd` 其实就是 BFS 每一层的分界线！每次走到 `currentEnd`，就是遍历完了一层，步数（层数）+1。如果你能在面试中点破“贪心其实是优化后的 BFS”，面试官会直接给你打出 SSP（特级 Offer）的评分！

## Python 完整推导

### 把贪心决策推迟到一层走完

从某个位置起跳后，会得到一组下一步能到达的位置，这些位置组成“下一层”。在扫描当前层的过程中，不需要马上决定落到哪一格，只需记录下一层最远能到哪里。扫描完当前层所有位置，确定最远边界后再增加一步。

`current_end` 是当前步数能覆盖的右端，`next_end` 是从当前层内任意位置继续跳能到达的最远下标。它们像两层之间的门槛。

### 用 `[2, 3, 1, 1, 4]` 看层次

初始已走 0 步，当前层右端 `current_end = 0`，下一层最远 `next_end = 0`。

1. 扫描下标 0，值为 2：`next_end = 2`。此时走到当前层边界 0，意味着第 1 步必须落地；`steps = 1`，新层覆盖下标 `[1, 2]`，`current_end = 2`。
2. 扫描下标 1，值为 3：可达 `1 + 3 = 4`，`next_end` 变为 4。
3. 扫描下标 2，值为 1：`2 + 1 = 3`，不及 4。此时到达当前层右端 2，第 2 步必须落地；`steps = 2`，`current_end = 4`。
4. 终点下标 4 已被覆盖，循环只需处理到 `n - 2`，不会在终点再误加一步。

答案为 2。虽然第一步可以直接跳到下标 2，但算法在扫完整个第一层后发现下标 1 的 3 能走得更远，于是把这层所有潜力都纳入下一次起跳。

### Python 实现

> 参考来源：灵茶山艾府题解（MIT License）
>
> 沿用旧项目收录的灵茶山艾府 Python“桥的右端点”实现；变量语义、注释和测试按本页整理，层次贪心算法未更换。

```python
from typing import List


class Solution:
    def jump(self, nums: List[int]) -> int:
        steps = 0
        current_end = 0
        next_end = 0
        for index in range(len(nums) - 1):
            next_end = max(next_end, index + nums[index])
            if index == current_end:
                current_end = next_end
                steps += 1
        return steps
```

### 为什么循环只到 `n - 2`

`range(len(nums) - 1)` 产生 `0` 到 `n-2`。如果包含最后一个下标，到达它时可能刚好等于 `current_end`，程序会错误地把“已经抵达终点”算成还需要再跳一步。

每轮先更新 `next_end`，再判断 `index == current_end`。这个判断表示当前层的所有可选位置已经扫描完，必须采用一次跳跃；把 `current_end` 推进到 `next_end` 后，继续处理下一层。

### 输入边界

`[0]` 的长度为 1，循环范围为空，直接返回 0。题目保证终点总能到达，因此不需要额外模拟不可达情况；这与第 55 题只判断可达性不同。

### 复杂度

- 时间复杂度：`O(n)`。
- 空间复杂度：`O(1)`。

每个非终点位置只扫描一次，边界更新和比较为常数时间；只保存三个整数，空间 O(1)。

```cpp
class Solution {
public:
    int jump(vector<int>& nums) {
        int ans = 0;
        int cur_end = 0; // 已建造的桥的右端点
        int next_end = 0; // 下一座桥的右端点的最大值
        for (int i = 0; i + 1 < nums.size(); i++) {
            // 遍历的过程中，记录下一座桥的最远点
            next_end = max(next_end, i + nums[i]);
            if (i == cur_end) { // 无路可走，必须建桥
                cur_end = next_end; // 建桥后，最远可以到达 next_end
                ans++;
            }
        }
        return ans;
    }
};
```
