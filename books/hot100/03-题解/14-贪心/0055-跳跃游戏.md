## 题目与约束

给你一个非负整数数组 `nums` ，你最初位于数组的 **第一个下标** 。数组中的每个元素代表你在该位置可以跳跃的最大长度。

  判断你是否能够到达最后一个下标，如果可以，返回 `true` ；否则，返回 `false` 。

  **示例 1：**

  **输入：**nums = [2,3,1,1,4]<br>**输出：**true<br>**解释：**可以先跳 1 步，从下标 0 到达下标 1, 然后再从下标 1 跳 3 步到达最后一个下标。

  **示例 2：**

  **输入：**nums = [3,2,1,0,4]<br>**输出：**false<br>**解释：**无论怎样，总会到达下标为 3 的位置。但该下标的最大跳跃长度是 0 ， 所以永远不可能到达最后一个下标。

  **提示：**

  - `1 <= nums.length <= 104`
  - `0 <= nums[i] <= 105`

## 完整推导

### 思路推导
  1. **直觉与痛点（DFS 的死局）**：

     很多同学刚做完回溯题，第一反应是：我站在位置 0，可以跳 1 步、2 步、3 步... 我挨个递归去试，只要有一条路通了就返回 true。

     **痛点**：这种尝试所有跳跃组合的方法时间复杂度是 $O(2^N)$，遇到极长数组绝对会超时（TLE）。而且，题目根本不关心你是“怎么跳过去”的，它只关心“能不能过去”。

  2. **破局思路（格局打开：看覆盖范围）**：

     我们引入一个极其霸道的全局变量：**`maxReach`（当前能到达的最远距离 / 覆盖雷达）**。

     - 假设当前我们在索引 `i`，这里的数字是 `nums[i]`，那么在这个点，我们能把雷达向前推进到的最远距离就是 `i + nums[i]`。
     - 我们从左到右遍历数组，不断用 `i + nums[i]` 去更新 `maxReach`。
     - **只要 `maxReach` 大于等于了最后一个位置的索引，就说明我们赢了！**

  3. **核心微操（致命的断崖）**：

     有一个致命前提：**你必须能走到当前这个点，才能享受这个点带来的跳跃距离加成**。

     如果当前遍历到的索引 `i`，已经**大于**了我们的 `maxReach`，说明什么？说明我们就算拼了老命，也走不到索引 `i` 这里！前面出现了无法逾越的鸿沟（比如一堆 0），此时直接判死刑，返回 `false`。
### Java 实现（极简贪心覆盖版）
```Java
class Solution {
    public boolean canJump(int[] nums) {
        // 记录当前能够覆盖到的最远索引
        int maxReach = 0;

        for (int i = 0; i < nums.length; i++) {
            // 🌟 致命校验：如果你连当前的索引 i 都够不到，说明你被困在前面了，死局！
            if (i > maxReach) {
                return false;
            }

            // 如果能走到当前位置，那就看看当前位置能不能让我们的覆盖雷达更远一点
            maxReach = Math.max(maxReach, i + nums[i]);

            // 🌟 性能优化（剪枝）：如果雷达的覆盖范围已经达到甚至超越了终点，直接胜利下班！
            if (maxReach >= nums.length - 1) {
                return true;
            }
        }

        return true;
    }
}
```
### 复杂度
  - **时间复杂度**：$O(N)$。我们只需要从头到尾扫一遍数组，每次循环里只做一次加法和一次比较，没有比这更快的了。
  - **空间复杂度**：$O(1)$。全局只维护了一个 `maxReach` 变量，真正的原神级极致空间。

### 易错点与扩展（面试连环进阶）

- **面试追问：“如果保证你一定能跳到终点，但我现在要求你用【最少的跳跃次数】到达终点，你怎么写？”（对应力扣 45 题：跳跃游戏 II）**
  - **满分优化思路（贪心进阶版）**：这也是极其高频的连环题！如果要求最少跳跃次数，我们就不光要维护“最远覆盖距离（`maxReach`）”，还要维护一个“当前这一步能管辖的边界（`currentEnd`）”。
  - 每次遍历时依然更新 `maxReach`，但**只有当游标 `i` 走到了 `currentEnd` 时，我们才不得不被迫起跳（跳跃次数 `+1`）**，然后把 `currentEnd` 更新为当前攒下的最大 `maxReach`。这是一种极其美妙的“不到万不得已绝不开大招”的贪心策略，同样是 $O(N)$ 解决！

## Python 完整推导

### 不必记录具体怎么跳，只需知道最远能到哪里

从位置 0 出发，每个已经能到达的位置都可能把可达右端继续向右推。维护 `farthest`，表示扫描过的位置所能覆盖的最右下标。遍历到下标 `i` 时，如果 `i > farthest`，说明这个位置本身已经站在断崖之外，无法到达它，更无法使用它的跳跃长度，返回 `False`。

### 失败样例 `[3, 2, 1, 0, 4]`

1. 下标 0 的跳跃值是 3，`farthest = max(0, 0 + 3) = 3`。
2. 下标 1：仍在 3 以内，`1 + 2 = 3`，最远边界不变。
3. 下标 2：`2 + 1 = 3`，仍不变。
4. 下标 3：`3 + 0 = 3`，边界照旧。
5. 下标 4：`4 > 3`，说明中间没有任何位置能跨过下标 3，终点无法到达，返回 `False`。

### 成功样例 `[2, 3, 1, 1, 4]`

下标 0 先让 `farthest = 2`；到下标 1 时，`1 + 3 = 4`，覆盖到终点下标 4，可以立即返回 `True`。这里并没有决定是“先跳两步还是先跳一步再跳三步”，只验证了终点落在可达区间里。

单元素数组没有断点，起点就是终点，因此最终会返回 `True`。

### Python 实现

> 参考来源：代码随想录（programmercarl.com）
>
> 沿用旧项目收录的《代码随想录》覆盖范围贪心；从旧实现的 while 循环整理为 `enumerate + max`，算法未更换。

```python
from typing import List


class Solution:
    def canJump(self, nums: List[int]) -> bool:
        farthest = 0
        for index, jump in enumerate(nums):
            if index > farthest:
                return False
            farthest = max(farthest, index + jump)
            if farthest >= len(nums) - 1:
                return True
        return True
```

### `enumerate` 和 `max` 如何对应边界

`for index, jump in enumerate(nums)` 同时获得当前位置和跳跃长度。进入循环先检查 `index > farthest`，只有能到达当前位置时，`index + jump` 才是有效的新覆盖范围。

`farthest = max(farthest, index + jump)` 合并“旧范围仍然有效”和“当前位置把范围推得更远”两种情况。一旦覆盖到 `len(nums) - 1`，后面位置已经包含在可达范围内，可以提前返回。

### 边界

题目保证数组非空。不要从下标 1 开始，因为起点自身可能已经带足够大的跳跃覆盖终点；从 0 开始才能完整处理。

### 复杂度

- 时间复杂度：`O(n)`。
- 空间复杂度：`O(1)`。

最坏扫描每个位置一次，每次常数次比较；只维护一个最远下标。

```cpp
class Solution {
public:
    bool canJump(vector<int>& nums) {
        int cover = 0;
        if (nums.size() == 1) return true; // 只有一个元素，就是能达到
        for (int i = 0; i <= cover; i++) { // 注意这里是小于等于cover
            cover = max(i + nums[i], cover);
            if (cover >= nums.size() - 1) return true; // 说明可以覆盖到终点了
        }
        return false;
    }
};
```

// 贪心
func canJump(nums []int) bool {
    cover := 0
    n := len(nums)-1
    for i := 0; i <= cover; i++ { // 每次与覆盖值比较
        cover = max(i+nums[i], cover) //每走一步都将 cover 更新为最大值
        if cover >= n {
            return true
        }
    }
    return false
}
func max(a, b int ) int {
    if a > b {
        return a
    }
    return b
}
```

bool canJump(int* nums, int numsSize) {
    int farthest = 0;
    for (int i = 0; i < numsSize; ++i) {
        if (i > farthest) return false;
        if (i + nums[i] > farthest) farthest = i + nums[i];
        if (farthest >= numsSize - 1) return true;
    }
    return true;
}
```
