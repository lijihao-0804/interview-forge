55. 跳跃游戏

题目信息 内容
难度 中等
核心模式 维护最远可达位置
时间复杂度 O(n)
空间复杂度 O(1)

题目与约束

给你一个非负整数数组 nums ，你最初位于数组的 第一个下标 。数组中的每个元素代表你在该位置可以跳跃的最大长度。

判断你是否能够到达最后一个下标，如果可以，返回 true ；否则，返回 false 。

示例 1：

输入：nums = [2,3,1,1,4]
输出：true
解释：可以先跳 1 步，从下标 0 到达下标 1, 然后再从下标 1 跳 3 步到达最后一个下标。

示例 2：

输入：nums = [3,2,1,0,4]
输出：false
解释：无论怎样，总会到达下标为 3 的位置。但该下标的最大跳跃长度是 0 ， 所以永远不可能到达最后一个下标。

提示：

  • 1 <= nums.length <= 104
  • 0 <= nums[i] <= 105

核心不变量

遍历位置必须不超过 farthest。

完整推导

思路推导

  1. 直觉与痛点（DFS 的死局）：

    很多同学刚做完回溯题，第一反应是：我站在位置 0，可以跳 1 步、2 步、3 步... 我挨个递归去试，只要有一条路通了就返回 true。

    痛点：这种尝试所有跳跃组合的方法时间复杂度是 O(2N)，遇到极长数组绝对会超时（TLE）。而且，题目根本不关心你是“怎么跳过去”的，它只关心“能不能过去”。

  2. 破局思路（格局打开：看覆盖范围）：

    我们引入一个极其霸道的全局变量：maxReach（当前能到达的最远距离 / 覆盖雷达）。

    • 假设当前我们在索引 i，这里的数字是 nums[i]，那么在这个点，我们能把雷达向前推进到的最远距离就是 i + nums[i]。
    • 我们从左到右遍历数组，不断用 i + nums[i] 去更新 maxReach。
    • 只要 maxReach 大于等于了最后一个位置的索引，就说明我们赢了！

  3. 核心微操（致命的断崖）：

    有一个致命前提：你必须能走到当前这个点，才能享受这个点带来的跳跃距离加成。

    如果当前遍历到的索引 i，已经大于了我们的 maxReach，说明什么？说明我们就算拼了老命，也走不到索引 i 这里！前面出现了无法逾越的鸿沟（比如一堆 0），此时直接判死刑，返回 false。

    Java 实现（极简贪心覆盖版）

class Solution {
    public boolean canJump(int[] nums) {
        // 记录当前能够覆盖到的最远索引
        int maxReach = 0;

        for (int i = 0; i < nums.length; i++) {
            // 🌟 致命校验：如果你连当前的索引 i 都够不到，说明你被困在前面了，死局！
            if (i > maxReach) {
                return false;
            }

            // 如果能走到当前位置，那就看看当前位置能不能让我们的覆盖雷达更远一点
            maxReach = Math.max(maxReach, i + nums[i]);

            // 🌟 性能优化（剪枝）：如果雷达的覆盖范围已经达到甚至超越了终点，直接胜利下班！
            if (maxReach >= nums.length - 1) {
                return true;
            }
        }

        return true;
    }
}

复杂度

  • 时间复杂度：O(N)。我们只需要从头到尾扫一遍数组，每次循环里只做一次加法和一次比较，没有比这更快的了。
  • 空间复杂度：O(1)。全局只维护了一个 maxReach 变量，真正的原神级极致空间。

易错点与扩展（面试连环进阶）

  • 面试追问：“如果保证你一定能跳到终点，但我现在要求你用【最少的跳跃次数】到达终点，你怎么写？”（对应力扣 45 题：跳跃游戏 II）
  • 满分优化思路（贪心进阶版）：这也是极其高频的连环题！如果要求最少跳跃次数，我们就不光要维护“最远覆盖距离（maxReach）”，还要维护一个“当前这一步能管辖的边界（currentEnd）”。
  • 每次遍历时依然更新 maxReach，但只有当游标 i 走到了 currentEnd 时，我们才不得不被迫起跳（跳跃次数 +1），然后把 currentEnd 更新为当前攒下的最大 maxReach。这是一种极其美妙的“不到万不得已绝不开大招”的贪心策略，同样是 O(N) 解决！
