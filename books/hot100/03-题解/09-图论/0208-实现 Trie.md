# 208. 实现 Trie

## 题目与约束

**[Trie](https://baike.baidu.com/item/字典树/9825209?fr=aladdin)**（发音类似 "try"）或者说 **前缀树** 是一种树形数据结构，用于高效地存储和检索字符串数据集中的键。这一数据结构有相当多的应用情景，例如自动补全和拼写检查。

  请你实现 Trie 类：

  - `Trie()` 初始化前缀树对象。
  - `void insert(String word)` 向前缀树中插入字符串 `word` 。
  - `boolean search(String word)` 如果字符串 `word` 在前缀树中，返回 `true`（即，在检索之前已经插入）；否则，返回 `false` 。
  - `boolean startsWith(String prefix)` 如果之前已经插入的字符串 `word` 的前缀之一为 `prefix` ，返回 `true` ；否则，返回 `false` 。

  **示例：**

  **输入**<br>["Trie", "insert", "search", "search", "startsWith", "insert", "search"]<br>[[], ["apple"], ["apple"], ["app"], ["app"], ["app"], ["app"]]<br>**输出**<br>[null, null, true, false, true, null, true]<br><br>**解释**<br>Trie trie = new Trie();<br>trie.insert("apple");<br>trie.search("apple");   // 返回 True<br>trie.search("app");     // 返回 False<br>trie.startsWith("app"); // 返回 True<br>trie.insert("app");<br>trie.search("app");     // 返回 True

  **提示：**

  - `1 <= word.length, prefix.length <= 2000`
  - `word` 和 `prefix` 仅由小写英文字母组成
  - `insert`、`search` 和 `startsWith` 调用次数 **总计** 不超过 `3 * 104` 次

## 核心不变量

> 路径表示前缀，结束标记区分完整单词与前缀。

## 完整推导

### 思路推导
  1. **直觉与痛点（为什么不用 HashSet？）**：

     如果只用 `HashSet<String>`，确实能实现 $O(L)$（$L$ 是单词长度）的快速精准查找。

     **痛点**：如果你想做**前缀匹配**（比如：输入 "app"，找出所有以 "app" 开头的单词），`HashSet` 就会瞬间抓瞎，只能去遍历所有的单词，时间复杂度飙升到 $O(N \times L)$，在海量数据（如搜索引擎关键词联想）面前会彻底瘫痪。

  2. **破局思路（字母分岔与空间复用）**：

     Trie 树的节点本身**不存储字母**，字母藏在指向下一个节点的指针（路径）上。

     因为只有 26 个小写字母，所以每个节点最多有 26 个分岔。我们可以用一个长度为 26 的数组 `TrieNode[] children` 来代表这 26 个分岔。

     - 比如：`children[0]` 不为空，代表有一条通往字母 `'a'` 的路；`children[1]` 不为空，代表有一条通往字母 `'b'` 的路。

  3. **灵魂印记（如何区分 "app" 和 "apple"？）**：

     当你往树里插入了 "apple" 后，这棵树上天然就存在了 "a"、"ap"、"app"、"appl"、"apple" 这几条路径。

     如果此时用户查 "app" 是否存在，虽然路径通，但 "app" 并不是一个独立的单词。

     **解决办法**：每个节点必须自带一个布尔标记 `boolean isEnd`。只有当一个单词在此处**完美收尾**时，才把这里的 `isEnd` 染成 `true`。
### Java 实现（经典标准版）
```Java
class Trie {
    // 1. 内部类：定义前缀树的节点结构
    private class TrieNode {
        // 26个指针分岔，映射 a-z
        private TrieNode[] children;
        // 标记是否有单词在此节点结束
        private boolean isEnd;

        public TrieNode() {
            children = new TrieNode[26];
            isEnd = false;
        }
    }

    // 根节点，本身不含任何字母，纯粹作为大门
    private TrieNode root;

    public Trie() {
        root = new TrieNode();
    }

    // 插入一个单词
    public void insert(String word) {
        TrieNode curr = root;
        for (int i = 0; i < word.length(); i++) {
            char ch = word.charAt(i);
            int index = ch - 'a'; // 转换为 0-25 的索引

            // 如果这个字母的分岔路还没修过，立刻建一个新节点（修路）
            if (curr.children[index] == null) {
                curr.children[index] = new TrieNode();
            }
            // 顺着这条路走下去
            curr = curr.children[index];
        }
        // 整个单词走完了，把末尾节点盖上“终点印章”
        curr.isEnd = true;
    }

    // 精准查找：单词必须存在，且结尾必须是终点
    public boolean search(String word) {
        TrieNode node = searchPrefix(word);
        // 不仅路径要通，而且该路径的终点必须被标记过 isEnd
        return node != null && node.isEnd;
    }

    // 前缀查找：只要路径通了就行，是不是独立的单词无所谓
    public boolean startsWith(String prefix) {
        return searchPrefix(prefix) != null;
    }

    // 抽象公共函数：顺着字符串在树里摸索路径
    private TrieNode searchPrefix(String s) {
        TrieNode curr = root;
        for (int i = 0; i < s.length(); i++) {
            char ch = s.charAt(i);
            int index = ch - 'a';

            // 只要发现中途某一步无路可走，直接宣告失败
            if (curr.children[index] == null) {
                return null;
            }
            curr = curr.children[index];
        }
        // 顺利走完，返回停驻的最后一个节点
        return curr;
    }
}

/**
 * Your Trie object will be instantiated and called as such:
 * Trie obj = new Trie();
 * obj.insert(word);
 * boolean param_2 = obj.search(word);
 * boolean param_3 = obj.startsWith(prefix);
 */
```
### 复杂度
  - **时间复杂度**：
    - `insert`、`search`、`startsWith`：**均为 $O(L)$**，其中 $L$ 是目标字符串的长度。不管树里已经塞了几千万个单词，查找速度**只跟当前输入的词有多长有关**！这就是前缀树最恐怖、最迷人的地方。
  - **空间复杂度**：$O(T \times 26)$。其中 $T$ 是所有插入单词组成的节点总数。由于大量共享公共前缀（比如 "app" 和 "apple" 共享了前三个节点），实际消耗的空间往往远小于暴力存储。

### 易错点与扩展（面试降维提问）

1. **面试追问 1：“如果输入不仅仅包含小写字母，而是包含全世界所有的 unicode 字符呢？你还用 `new TrieNode[26]` 吗？”**
   - **满分抢答**：绝对不行！如果字符集极大，固定大小的数组会导致极其恐怖的**内存荒废（很多格子是 null）**。
   - **终极优化方案**：我们可以把结构里的 `TrieNode[] children` 降维重构为 **`HashMap<Character, TrieNode> children`**！
   - 虽然 `HashMap` 带来了一点点常数时间的哈希开销，但它做到了“有几个字母就开辟几个分岔”，内存利用率达到完美的 100%，完美适配多语言、全字符集的工业级场景。
2. **面试追问 2：“生产环境中，大量的 `new TrieNode()` 导致内存碎片化严重，GC（垃圾回收）压力巨大，怎么解决？”**
   - **高级工程回答**：这是典型的工业级痛点。在实际开发中，我们通常不会用链式指针，而是采用“扁平化数组（Trie 数组压缩技术）”。
   - 我们开辟一个超级大的一维数组 `int[][] trie`，用行号代表节点编号，用列号代表字母。这样整棵树在内存中是**一块连续的内存大数组**，不仅对 CPU 缓存（Cache）极其友好，速度拉满，而且完全规避了频繁垃圾回收的困境。
