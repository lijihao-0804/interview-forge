# 207. 课程表

## 题目与约束

你必须修完 `numCourses` 门课程。给你一个数组 `prerequisites`，其中 `prerequisites[i] = [ai, bi]` 表示如果你想修课程 `ai`，必须先修课程 `bi`。

  判断你是否可能修完所有课程？（能则返回 `true`，存在循环依赖则返回 `false`）。

[🔗 前往力扣原题验证 →](https://leetcode.cn/problems/course-schedule/?envType=study-plan-v2&envId=top-100-liked)

## 核心不变量

> 每学完一门课就减少后继入度，最终处理数应等于课程数。

## 完整推导

### 思路推导
  1. **直觉与痛点（循环死锁）**：

     如果想学 A 必须先学 B，想学 B 必须先学 C，而想学 C 又必须先学 A。这三个课程就形成了一个**死循环（环）**。只要图里有环，你就一门课也学不了。所以，**这道题的本质就是：在一个有向图中，判断是否存在环。**

  2. **破局思路（Kahn 算法 / BFS 入度表法）**：

     想象一下，全学校的学生都在挑课。哪些课是大家可以直接报名的？**显然是那些“不需要任何先修课”的清流课程。**

     在图论中，一个节点被指向的边数叫做**入度（In-degree）**。不需要先修课，就意味着它的**入度为 0**。

     - **第一步（建账本）**：我们统计出所有课程的入度，并把所有入度为 0 的课程推进一个队列（Queue）里。
     - **第二步（毕业一门，解锁一批）**：从队列里弹出一门入度为 0 的课（代表你修完了这门课）。既然你修完了它，那么所有**以它为先修课的后续课程**，压力都减轻了！我们将这些后续课程的**入度全部减 1**。
     - **第三步（接力跑）**：在减 1 的过程中，如果发现某门后续课程的入度也变成了 0（代表它的所有先修课你都修完了），那就立刻把它也推进队列。
     - **结算**：当队列空了，数一数你一共修完了多少门课。如果等于总课程数，皆大欢喜（返回 `true`）；如果小于总课程数，说明剩下的课掉进了循环依赖的死锁里，谁也无法变成 0（返回 `false`）。
### Java 实现（邻接表 + 入度表 BFS 满分版）
```Java
import java.util.ArrayList;
import java.util.LinkedList;
import java.util.List;
import java.util.Queue;

class Solution {
    public boolean canFinish(int numCourses, int[][] prerequisites) {
        // 1. 准备数据结构
        // inDegree 数组：记录每门课的入度（需要多少门先修课）
        int[] inDegree = new int[numCourses];
        // adj 邻接表：记录每门课是哪些课的先修课（主修课 -> 后续课列表）
        List<List<Integer>> adj = new ArrayList<>();
        for (int i = 0; i < numCourses; i++) {
            adj.add(new ArrayList<>());
        }

        // 2. 灌入数据，初始化邻接表和入度表
        for (int[] req : prerequisites) {
            int course = req[0];
            int pre = req[1];
            adj.get(pre).add(course); // pre -> course
            inDegree[course]++;       // 想要学 course，入度加 1
        }

        // 3. 将所有入度为 0（无须先修课）的课程放进队列
        Queue<Integer> queue = new LinkedList<>();
        for (int i = 0; i < numCourses; i++) {
            if (inDegree[i] == 0) {
                queue.offer(i);
            }
        }

        // 记录成功修完的课程数量
        int count = 0;

        // 4. 开始 BFS 拓扑排序
        while (!queue.isEmpty()) {
            int curr = queue.poll();
            count++; // 修完一门，计数加 1

            // 拿到当前课程的所有后续课程
            for (int nextCourse : adj.get(curr)) {
                inDegree[nextCourse]--; // 后续课程的先修条件达成一个，入度减 1

                // 如果入度被减到了 0，说明所有先修课都修完了，可以入队
                if (inDegree[nextCourse] == 0) {
                    queue.offer(nextCourse);
                }
            }
        }

        // 5. 如果修完的课程数等于总课程数，说明图里无环，可以全部修完
        return count == numCourses;
    }
}
```
### 复杂度
  - **时间复杂度**：$O(V + E)$。其中 $V$ 是课程数（顶点），$E$ 是先修关系数（边）。建图需要遍历一遍所有边，BFS 过程中每个顶点进出队一次，每条边被剥离一次，是标准且极其高效的图遍历时间。
  - **空间复杂度**：$O(V + E)$。邻接表占用 $O(V + E)$ 的空间，入度数组占用 $O(V)$，队列最多占用 $O(V)$。

### 易错点与扩展（面试变体局）

1. **面试追问 1：“如果我不单单想知道能不能修完，我还想让你【返回一种合理的修课顺序】，该怎么改？”（对应力扣 210 题：课程表 II）**
   - **满分抢答**：极其简单！上面的代码框架**一个字都不用改**。我们只需要把那个 `int count` 计数器，改成一个长为 `numCourses` 的一维数组 `int[] order`。每次从队列里 `poll()` 出一个节点时，顺手按顺序填进 `order` 数组里。最后判断如果填进去的课数等于 `numCourses`，返回 `order`，否则返回空数组。这就是拓扑排序的完全体！
2. **面试追问 2：“这道题除了 BFS，能用 DFS（深度优先搜索）做吗？”**
   - **满分抢答**：完全可以。DFS 做这道题的本质是**染色标记法（三色标记法）**。
   - 我们对每个节点定义三种状态：`0`（未访问）、`1`（正在访问中）、`2`（已经安全访问完毕）。
   - 顺着某条路径一条道走到黑。如果 DFS 过程中撞见了一个状态为 `1` 的节点，说明**它在当前这条递归路径里自己碰到了自己**，当场捕获一个环，直接终止并返回 `false`。如果一条路顺利走到头，就把沿途节点染成 `2`（安全）。
