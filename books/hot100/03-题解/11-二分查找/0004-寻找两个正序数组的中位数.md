# 4. 寻找两个正序数组的中位数

[← 二分查找专题](../../02-专题/11-二分查找.md) · [总目录](../../../../README.md) · [复习清单](../../00-总览/03-复习清单.md)

| 题目信息 | 内容 |
|---|---|
| 难度 | 困难 |
| 核心模式 | 短数组上二分分割线 |
| 时间复杂度 | O(log min(m,n)) |
| 空间复杂度 | O(1) |


## 题目与约束

给定两个大小分别为 `m` 和 `n` 的正序（从小到大）数组 `nums1` 和 `nums2`。请你找出并返回这两个正序数组的 **中位数** 。

  算法的时间复杂度应该为 `O(log (m+n))` 。

  **示例 1：**

  **输入：**nums1 = [1,3], nums2 = [2]
  **输出：**2.00000
  **解释：**合并数组 = [1,2,3] ，中位数 2

  **示例 2：**

  **输入：**nums1 = [1,2], nums2 = [3,4]
  **输出：**2.50000
  **解释：**合并数组 = [1,2,3,4] ，中位数 (2 + 3) / 2 = 2.5

  **提示：**

  - `nums1.length == m`
  - `nums2.length == n`
  - `0 <= m <= 1000`
  - `0 <= n <= 1000`
  - `1 <= m + n <= 2000`
  - `-106 <= nums1[i], nums2[i] <= 106`

[🔗 前往力扣原题验证 →](https://leetcode.cn/problems/median-of-two-sorted-arrays/?envType=study-plan-v2&envId=top-100-liked)

## 核心不变量

> 正确分割满足左半最大值不大于右半最小值。

## 完整推导

### 思路推导
  1. **直觉与痛点（二分到底在分什么？）**：

     $O(\log(m+n))$ 强制我们必须用二分。但是，两个数组错综复杂，我们该对谁做二分？二分的目标又是什么？

     **痛点**：如果你试图在两个数组里直接去“找”那个中位数的具体数值，你会陷入极其痛苦的边界比较中，因为你不知道这个数字到底在 `nums1` 还是 `nums2` 里。

  2. **降维破局（寻找那条“完美的割线”）**：

     中位数的本质是什么？它是将一个集合划分为**长度相等的上下两部分**，并且**上半部分的最大值 $\le$ 下半部分的最小值**。

     既然有两个数组，那我们就分别在 `nums1` 和 `nums2` 中各切一刀（划一条割线）。

     - 我们要求：**左半边的元素总个数，恰好等于右半边的元素总个数**（如果是奇数，让左边多一个）。
     - 这意味着，只要我们在 `nums1` 中切了一刀，由于总人数固定，`nums2` 中的那一刀也就**自动确定了！**

  3. **核心微操（交叉验证法）**：

     假设 `nums1` 切在位置 `i`，`nums2` 切在位置 `j`。

     割线左边的两个元素我们叫 `A_left` 和 `B_left`，右边的叫 `A_right` 和 `B_right`。

     为了保证左半边全体 $\le$ 右半边全体，由于数组本身是有序的，我们只需要**交叉验证**：

     - `A_left <= B_right` （A 的左边必须小于 B 的右边）

     - `B_left <= A_right` （B 的左边必须小于 A 的右边）

       **二分逻辑**：

     - 如果 `B_left > A_right`：说明 B 左边的数字太大了！这意味着我们在 B 里划的数字太多，而在 A 里划的数字太少。所以，**A 的割线必须向右移（增大 `i`）**。

     - 反之，向左移。当交叉验证通过时，我们就找到了那条完美的割线！
### Java 实现（满分虚拟极值版）
```Java
class Solution {
    public double findMedianSortedArrays(int[] nums1, int[] nums2) {
        // 🌟 核心技巧 1：保证 nums1 永远是那个比较短的数组！
        // 因为我们在较短的数组上做二分，不仅速度更快，而且可以防止 nums2 越界
        if (nums1.length > nums2.length) {
            return findMedianSortedArrays(nums2, nums1);
        }

        int m = nums1.length;
        int n = nums2.length;

        // 分割线左边需要的总元素个数（向上取整，奇数时左边多一个）
        int totalLeft = (m + n + 1) / 2;

        // 在短数组 nums1 的区间 [0, m] 里寻找最完美的割线 i
        int left = 0;
        int right = m;

        while (left <= right) {
            // i 是 nums1 的割线位置（表示 nums1 左半边有 i 个元素）
            int i = left + (right - left) / 2;
            // j 是 nums2 的割线位置（剩下的元素全归 nums2 凑齐 totalLeft）
            int j = totalLeft - i;

            // 🌟 核心技巧 2：处理边界问题（利用无穷大/无穷小虚拟补位）
            // 如果切在最左边，左边没元素了，用 MIN_VALUE 代替；切在最右边，用 MAX_VALUE 代替
            int A_left  = (i == 0) ? Integer.MIN_VALUE : nums1[i - 1];
            int A_right = (i == m) ? Integer.MAX_VALUE : nums1[i];
            int B_left  = (j == 0) ? Integer.MIN_VALUE : nums2[j - 1];
            int B_right = (j == n) ? Integer.MAX_VALUE : nums2[j];

            // 交叉验证
            if (A_left <= B_right && B_left <= A_right) {
                // 完美割线找到了！
                // 如果总长度是奇数，中位数就是左半边的最大值
                if ((m + n) % 2 != 0) {
                    return Math.max(A_left, B_left);
                }
                // 如果总长度是偶数，中位数是 (左半边最大值 + 右半边最小值) / 2.0
                else {
                    return (Math.max(A_left, B_left) + Math.min(A_right, B_right)) / 2.0;
                }
            } else if (B_left > A_right) {
                // B 的左边太大了，A 的割线必须往右走，多吃一点元素进来
                left = i + 1;
            } else {
                // A 的左边太大了，A 的割线必须往左走
                right = i - 1;
            }
        }

        return 0.0; // 正常情况下代码不会走到这里
    }
}
```
### 复杂度
  - **时间复杂度**：$O(\log(\min(m, n)))$。由于我们强制对较短的数组进行二分查找，查找空间就是 $\min(m, n)$，完全符合题目的极致性能要求。
  - **空间复杂度**：$O(1)$。我们仅仅用了几个游标变量来记录割线和边缘的数值。

### 易错点与扩展（面试生死狙击）

1. **踩坑警告：为什么要写 `totalLeft = (m + n + 1) / 2`？**
   - 这个 `+1` 是个极其精妙的数学统筹。
   - 假设总长度是偶数（例如 4），`(4 + 1) / 2 = 2`，左半边分到 2 个。
   - 假设总长度是奇数（例如 5），`(5 + 1) / 2 = 3`，左半边分到 3 个。
   - 它完美地统一了奇偶数情况，并且保证了当长度为奇数时，**中位数永远只会出现在左半边的最大值里**（即 `Math.max(A_left, B_left)`），省去了极多冗余的条件判断。
2. **面试追问：“遇到数组极度倾斜（比如 `A` 为空，或者 `A` 完全大于 `B`），这个算法会越界报错吗？”**
   - **满分抢答（优雅的哨兵模式）**：绝不会报错！因为我们采用了 `Integer.MIN_VALUE` 和 `Integer.MAX_VALUE` 作为“哨兵（Sentinel）”。
   - 比如 `A` 如果一刀切在最左侧（`i = 0`），意味着 `A` 没有任何元素分给左半边。程序直接给 `A_left` 赋值为负无穷，负无穷去比较任何真实的数字，都会顺利通过 `<= B_right` 的交叉验证。这正是工业级代码对于“边界消解”的最高级手法！
