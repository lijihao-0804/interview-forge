153. 寻找旋转排序数组中的最小值

难度中等

Python 主方法与右端比较的二分逼近最小值时间O(log n)空间O(1)

题目与约束

已知一个长度为 n 的数组，预先按照升序排列，经由 1 到 n 次 旋转 后，得到输入数组。例如，原数组 nums = [0,1,2,4,5,6,7] 在变化后可能得到：

  • 若旋转 4 次，则可以得到 [4,5,6,7,0,1,2]
  • 若旋转 7 次，则可以得到 [0,1,2,4,5,6,7]

注意，数组 [a[0], a[1], a[2], ..., a[n-1]] 旋转一次 的结果为数组 [a[n-1], a[0], a[1], a[2], ..., a[n-2]] 。

给你一个元素值 互不相同 的数组 nums ，它原来是一个升序排列的数组，并按上述情形进行了多次旋转。请你找出并返回数组中的 最小元素 。

你必须设计一个时间复杂度为 O(log n) 的算法解决此问题。

示例 1：

输入：nums = [3,4,5,1,2]
输出：1
解释：原数组为 [1,2,3,4,5] ，旋转 3 次得到输入数组。

示例 2：

输入：nums = [4,5,6,7,0,1,2]
输出：0
解释：原数组为 [0,1,2,4,5,6,7] ，旋转 4 次得到输入数组。

示例 3：

输入：nums = [11,13,15,17]
输出：11
解释：原数组为 [11,13,15,17] ，旋转 4 次得到输入数组。

提示：

  • n == nums.length
  • 1 <= n <= 5000
  • -5000 <= nums[i] <= 5000
  • nums 中的所有整数 互不相同
  • nums 原来是一个升序排序的数组，并进行了 1 至 n 次旋转

Java 完整推导

Java 核心不变量

nums[mid] > nums[right] 时最小值一定在右侧。

完整推导

思路推导

  1. 直觉与痛点（找断点）：

    最小值其实就是这个旋转数组的“断崖点”。我们怎么用二分法判断这个断崖点在左边还是右边呢？

  2. 破局思路（寻找绝对的参照物）：

    在 33 题中，我们通过比较 nums[left] 和 nums[mid] 来判断左半边是否有序。但这道题，最佳的参照物是 nums[right]！

    我们将 nums[mid] 和最右边的数字 nums[right] 进行火星撞地球般的对比：

    • 场景 A (nums[mid] > nums[right])：比如 [4, 5, 6, 7, 0, 1, 2]，mid 是 7，right 是 2。中间的值居然比最右边的值还大！这违背了升序规律，说明断崖（最小值）必定在右半边！ 于是，我们大手一挥：left = mid + 1。
    • 场景 B (nums[mid] < nums[right])：比如 [6, 7, 0, 1, 2, 4, 5]，mid 是 1，right 是 5。中间值比右边小，说明从 mid 到 right 这一段是完美升序的，没有任何断崖！ 既然这一段是升序的，那么最小值绝对不可能在 mid 的右边。它要么是 mid 本身，要么在 mid 的左边。于是，我们谨慎收缩：right = mid。

  3. 核心微操（循环终止的奥秘）：

    既然每次都在逼近，那什么时候停下？

    当 left == right 时，搜索区间只剩下一个元素了，这个元素就是我们要找的最小值！所以循环条件是 while (left < right)。

    Java 实现（绝美逼近版）

class Solution {
    public int findMin(int[] nums) {
        int left = 0;
        int right = nums.length - 1;

        // 🌟 致命细节 1：这里是 left < right，不是 <=
        // 因为我们不需要像找 target 那样去检查最后一个元素是否匹配
        // 当 left == right 时，它们共同指向的就是那个被逼入死角的最小值！
        while (left < right) {
            int mid = left + (right - left) / 2;

            // 拿中间值和【右边界】做比较
            if (nums[mid] > nums[right]) {
                // 中间比右边大，说明断崖在右半边，最小值必定在 mid 之后
                left = mid + 1;
            } else {
                // 🌟 致命细节 2：这里是 right = mid，绝对不能是 mid - 1！
                // 因为 nums[mid] 可能是真正的最小值（比如 [7, 0, 1, 2] 中的 0）
                // 如果写成 mid - 1，就会把真正的最小值给扔掉！
                right = mid;
            }
        }

        // 循环结束时，left 和 right 重合，这就是最小值的位置
        return nums[left];
    }
}

复杂度

  • 时间复杂度：O(log N)。经典的二分查找，每次无情排除一半的空间。
  • 空间复杂度：O(1)。只使用了常数级别的游标变量。
易错点与扩展（面试的关键追问）
  1. 关键追问 1：“为什么比较的参照物是 nums[right]，能不能用 nums[left]？” - 满分避坑指南：强烈不建议用 left！ * 假设给你一个完全没有旋转（或者旋转了 N 次）的原始升序数组，比如 [1, 2, 3, 4, 5]。 - 如果你用 nums[mid] > nums[left] (3 > 1) 来判断，你会误以为断崖在右边，从而让 left = mid + 1，直接把真正的最小值 1 给丢掉了！ - 而如果你用 nums[right]，3 < 5，程序会执行 right = mid，慢慢向左收缩，最终完美定格在 1 上。用 right 作为参照物，可以完美兼容“数组未发生旋转”的边界情况！
  2. 面试追问 2：“如果数组里有重复元素呢？比如 [2, 2, 2, 0, 1, 2]，这个算法还能跑吗？”（对应力扣 154 题：寻找旋转排序数组中的最小值 II - Hard 难度） - 满分优化思路：如果有重复元素，就会出现 nums[mid] == nums[right] 的情况（比如上面例子中 mid 指向 2，right 也指向 2）。 - 此时你根本不知道断崖在左边还是右边。怎么办？ - 绝境求生法：既然 nums[mid] 和 nums[right] 一样大，那我们保留 mid 就够了，直接把 right 砍掉一格（right--），缩小范围继续试！这就是那道 Hard 题的全部核心代码，仅仅多了一行 else if (nums[mid] == nums[right]) right--;，极其优美！

Python 完整推导

比较 middle 和右端，寻找下降断崖

旋转后的最小值就是升序链被扭断的位置。nums[middle] 若比 nums[right] 大，说明从 middle 到右端跨过了断崖，最小值一定在 middle 右边，并且 middle 自己太大，可以排除。

反过来，若 nums[middle] <= nums[right]，从 middle 到 right 这段有序，断崖不在这一段的内部，最小值只可能在左边，或者就是 middle；因此保留 middle，right = middle。

在 [4,5,6,7,0,1,2] 中走一遍

  1. middle=3，值为 7，右端为 2。7 > 2，断崖在右侧，排除 0 到 3，left=4。
  2. 区间 [4,6]，middle=5，值为 1，小于右端 2，说明 [1,2] 有序，最小值在左侧或 middle，right=5。
  3. 区间 [4,5]，middle=4，值为 0，小于右端 1，right=4。left 与 right 重合，返回 0。

未旋转的 [1,2,3] 也会不断执行 right = middle，最终停在 1，不会像“与 left 比较”那样误把最小值排除。

长度为一的数组直接跳过循环，返回唯一元素；长度为二且已旋转的 [2,1] 第一轮 middle 为 0、右端为 1，会排除 2 并保留 1。

Python 实现

参考来源：经典解法实现

沿用项目旧 Python 的右端比较二分与旧 Java 的断崖比喻；仅整理变量、导入和注释。

from typing import List


class Solution:
    def findMin(self, nums: List[int]) -> int:
        left = 0
        right = len(nums) - 1

        while left < right:
            middle = (left + right) // 2
            if nums[middle] > nums[right]:
                left = middle + 1
            else:
                right = middle
        return nums[left]

半开候选边界

虽然初始两端都指向元素，循环却使用 left < right。每轮 middle 落在两者之间，保证至少有一个可收缩方向；left 等于 right 时只剩唯一候选，候选值无需再比较。

right = middle 与 left = middle + 1 的不对称来自事实判断：中间值大于右端时可以确定 middle 不为最小值；不大于时不能排除 middle。

复杂度

  • 时间复杂度：O(log n)。
  • 空间复杂度：O(1)。

每次比较后区间至少缩小一半，直到 left 与 right 重合，时间 O(log n)；只使用两个边界与中点，空间 O(1)。

C++ 实现

实现来源：经典解法实现

  1. 旋转数组最小值是「断崖点」：比较 mid 与 hi
  2. nums[mid] > nums[hi] → 最小值在右半（lo = mid+1）
  3. 否则最小值在左半含 mid（hi = mid）
  4. lo == hi 即答案
class Solution {
public:
    int findMin(vector<int>& nums) {
        int lo = 0, hi = nums.size() - 1;
        while (lo < hi) {
            int mid = (lo + hi) / 2;
            if (nums[mid] > nums[hi]) lo = mid + 1;  // 断崖在右半
            else hi = mid;                           // 最小值在左半含 mid
        }
        return nums[lo];
    }
};

func findMin(nums []int) int {
    lo, hi := 0, len(nums)-1
    for lo < hi {
        mid := (lo + hi) / 2
        if nums[mid] > nums[hi] { lo = mid + 1 } else { hi = mid }
    }
    return nums[lo]
}
