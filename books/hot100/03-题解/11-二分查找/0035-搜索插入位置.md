# 35. 搜索插入位置

[← 二分查找专题](../../02-专题/11-二分查找.md) · [总目录](../../../../README.md) · [复习清单](../../00-总览/03-复习清单.md)

| 题目信息 | 内容 |
|---|---|
| 难度 | 简单 |
| 核心模式 | lower_bound |
| 时间复杂度 | O(log n) |
| 空间复杂度 | O(1) |


## 题目与约束

给定一个排序数组和一个目标值，在数组中找到目标值，并返回其索引。如果目标值不存在于数组中，返回它将会被按顺序插入的位置。

  请必须使用时间复杂度为 `O(log n)` 的算法。

  **示例 1:**

  **输入:** nums = [1,3,5,6], target = 5<br>**输出:** 2

  **示例 2:**

  **输入:** nums = [1,3,5,6], target = 2<br>**输出:** 1

  **示例 3:**

  **输入:** nums = [1,3,5,6], target = 7<br>**输出:** 4

  **提示:**

  - `1 <= nums.length <= 104`
  - `-104 <= nums[i] <= 104`
  - `nums` 为 **无重复元素**的 **升序**排列数组
  - `-104 <= target <= 104`

## 核心不变量

> 寻找第一个大于等于 target 的下标。

## 完整推导

---

### 思路推导
  1. **直觉与痛点（为什么不用 `for` 循环？）**：

     一个 `for` 循环从头扫到尾，遇到第一个大于等于目标值的数字就返回它的索引。这叫**线性查找**，时间复杂度是 $O(N)$。在几千万的数据量下，会被面试立刻判为不合格。

     只要看到“有序数组”**和**“$O(\log n)$”这两个关键词，你的大脑必须条件反射般地弹出四个大字：**二分查找！**

  2. **破局思路（逼近与夹击）**：

     设两个指针，`left` 指向数组开头，`right` 指向数组末尾。

     每次算出中间位置 `mid`，拿 `nums[mid]` 和目标值 `target` 比大小：

     - 如果 `nums[mid] == target`，皆大欢喜，直接返回 `mid`。
     - 如果 `nums[mid] < target`，说明目标值在右半边，立刻让 `left = mid + 1`。
     - 如果 `nums[mid] > target`，说明目标值在左半边，立刻让 `right = mid - 1`。

  3. **核心微操（致命的边界与返回值）**：

     最让人头疼的是：如果目标值不在数组里，循环结束时我该返回什么？

     **黄金定律：当 `while(left <= right)` 循环打破时，`left` 和 `right` 必然错位（即 `left = right + 1`）。此时，`right` 指向的是最后一个小于 `target` 的元素，而 `left` 指向的是第一个大于 `target` 的元素！**

     既然是要插入目标值，当然应该插在“第一个大于它的元素”的位置上。所以，**永远返回 `left`！**
### Java 实现（二分查找无死角模板）
```Java
class Solution {
    public int searchInsert(int[] nums, int target) {
        int left = 0;
        int right = nums.length - 1;

        // 🌟 核心细节 1：必须是 <=。因为当 left == right 时，那个唯一的元素还没被检查！
        while (left <= right) {
            // 🌟 核心细节 2：防溢出的 mid 写法
            // 不要写 (left + right) / 2，如果左右指针特别大，相加会超出 int 的最大范围
            int mid = left + (right - left) / 2;

            if (nums[mid] == target) {
                // 找到了，直接返回索引
                return mid;
            } else if (nums[mid] < target) {
                // 目标值在右边，把左边界拉过来
                left = mid + 1;
            } else {
                // 目标值在左边，把右边界拉过来
                right = mid - 1;
            }
        }

        // 🌟 核心细节 3：如果没找到，循环结束时 left 必然大于 right
        // 此时 left 指向的就是目标值理应插入的正确位置！
        return left;
    }
}
```
### 复杂度
  - **时间复杂度**：$O(\log N)$。每次循环都会砍掉一半的搜索空间。如果数组有 40 亿个数字，最多只需要找 32 次就能出结果！这就是二分查找的恐怖威力。
  - **空间复杂度**：$O(1)$。我们仅仅用了 `left`、`right` 和 `mid` 三个整型变量，完全是原地操作。

### 易错点与扩展（进阶的底层细节）

1. **踩坑警告：防溢出的 `mid` 写法**
   - 很多新手习惯写 `int mid = (left + right) / 2;`。在 LeetCode 早期，这个写法坑死了无数人。因为当 `left` 和 `right` 都是接近 `2147483647` 的大数字时，两者相加会直接变成负数，导致数组越界报错。
   - **满分习惯**：永远写成 `int mid = left + (right - left) / 2;`。或者在追求极致性能的面试（比如 C++ 岗），可以直接写位运算：`int mid = left + ((right - left) >> 1);`，面试官看了绝对会给你竖大拇指。
2. **关键追问：“为什么插入位置一定是 `left`，不是 `right`？”**
   - 闭上眼睛想象一下最后一步：此时 `left == right`，假设它们都指向数字 `5`，而你要找的 `target` 是 `6`。
   - `nums[mid]` 是 `5`，比 `6` 小。程序会执行 `left = mid + 1`。
   - 此时循环结束（`left > right`）。你看，`left` 已经往前走了一步，恰好指向了 `5` 的后面！这就完美地留出了插入 `6` 的空位。所以返回 `left` 绝对精准。
