# 23. 合并 K 个升序链表

[← 链表专题](../../02-专题/07-链表.md) · [总目录](../../../../README.md) · [复习清单](../../00-总览/03-复习清单.md)

| 题目信息 | 内容 |
|---|---|
| 难度 | 困难 |
| 核心模式 | 最小堆多路归并 |
| 时间复杂度 | O(N log k) |
| 空间复杂度 | O(k) |


## 题目与约束

给你一个链表数组 `lists`，每个链表都已经按升序排列。

  请你将所有链表合并到一个升序链表中，返回合并后的链表。

[🔗 前往力扣原题验证 →](https://leetcode.cn/problems/merge-k-sorted-lists/?envType=study-plan-v2&envId=top-100-liked)

## 核心不变量

> 堆中始终只放每条链表当前最小的头节点。

## 完整推导

### 思路推导
  1. **直觉与痛点（顺序合并的惨剧）**：

     既然我会“合并两个链表”，那我能不能先合并 1 和 2，把结果再去跟 3 合并，结果再去跟 4 合并……？

     **痛点**：极其低效！假设每个链表长度都是 $n$。第一次合并长度变成 $2n$，第二次变成 $3n$…… 第一个链表的节点会被反复遍历 $k-1$ 次。时间复杂度飙升到 $O(k^2 \cdot n)$，面对庞大的数据绝对会超时。

  2. **破局思路 A（利用数据结构：最小堆 / 优先队列）**：

     想象我们在举办一场**多兵团比武**。有 $k$ 个排好序的队伍。

     - **擂台（最小堆）**：我们只需要把这 $k$ 个队伍的当前队长（头节点）叫到擂台上。
     - **打擂**：裁判（优先队列）瞬间挑出这 $k$ 个人里最弱（值最小）的一个，把他提出来，编入最终的结果链表。
     - **替补**：这个最弱的人被调走后，他所在队伍的**下一个人**顶上来，站到擂台上继续比较。
     - 如此循环，直到所有队伍的人都被抽空！

  3. **破局思路 B（算法降维：分治法 Divide & Conquer）**：

     参考体育比赛的**淘汰赛赛程表**。

     不需要一个个轮流上。让这 $k$ 个链表两两配对，进行“合并两个链表”的比赛。

     第一轮过后，$k$ 个链表变成了 $k/2$ 个；第二轮变成 $k/4$ 个…… 直到最后合并成 1 个总冠军！
### Java 实现（优先级队列 / 最小堆版）
  *(这是面试中最受欢迎、最能体现你熟练掌握高级数据结构的解法)*

```java
import java.util.PriorityQueue;

/**
 * Definition for singly-linked list.
 * public class ListNode {
 *     int val;
 *     ListNode next;
 *     ListNode() {}
 *     ListNode(int val) { this.val = val; }
 *     ListNode(int val, ListNode next) { this.val = val; this.next = next; }
 * }
 */
class Solution {
    public ListNode mergeKLists(ListNode[] lists) {
        // 防御性编程：处理空数组的极端情况
        if (lists == null || lists.length == 0) {
            return null;
        }

        // 1. 创建一个最小堆（优先队列），容量初始化为 k
        // 核心逻辑：按照节点的值（val）从小到大排序
        PriorityQueue<ListNode> pq = new PriorityQueue<>(
            lists.length,
            (a, b) -> Integer.compare(a.val, b.val)
        );

        // 2. 初始化擂台：把所有非空链表的头节点（各队队长）请上擂台
        for (ListNode head : lists) {
            if (head != null) {
                pq.offer(head);
            }
        }

        // 3. 祭出老朋友：虚拟头节点
        ListNode dummy = new ListNode(-1);
        ListNode curr = dummy;

        // 4. 擂台赛开始！只要擂台上还有人，就一直打
        while (!pq.isEmpty()) {
            // 裁判挑出当前擂台上最小的节点
            ListNode minNode = pq.poll();

            // 把最小的节点接到大部队后面
            curr.next = minNode;
            curr = curr.next;

            // 如果这个队伍后面还有人，让他顶替刚才离开的队长，上擂台！
            if (minNode.next != null) {
                pq.offer(minNode.next);
            }
        }

        // 5. 返回总链表的车头
        return dummy.next;
    }
}
```
### 复杂度
  - **时间复杂度**：$O(N \log k)$。其中 $N$ 是所有链表节点的总数，$k$ 是链表的条数。每个节点都会且仅会进出堆一次。堆的插入和删除操作时间复杂度是 $O(\log k)$，所以总时间是 $N \log k$。
  - **空间复杂度**：$O(k)$。优先队列（擂台）里最多只会同时存在 $k$ 个节点（每队各一人）。

### 易错点与扩展（进阶的细节）

1. **踩坑警告：空链表的背刺**
   - 题目给的 `lists` 数组里，可能存在 `null` （比如 `[[], [1], []]`）。如果你在初始化堆的时候不加 `if (head != null)` 的判断，直接把 `null` 塞进 `PriorityQueue`，运行时会直接抛出 **`NullPointerException`**。
2. **面试追问：“如果让你用【分治法】写，时间复杂度是多少？空间复杂度呢？”**
   - **秒答**：分治法的时间复杂度同样是 **$O(N \log k)$**。因为每次合并两个链表是 $O(N)$，总共要合并 $\log k$ 轮（树的高度）。
   - **进阶对比**：分治法的**空间复杂度更优**！如果是迭代版的分治法，不需要优先队列的 $O(k)$ 空间，空间复杂度可以压缩到极致的 **$O(1)$**。但**最小堆解法**在工程扩展性上更好（比如处理无限数据流（Data Stream）的合并，你无法一开始拿到所有链表进行分治，只能用堆实时处理）。

#### 📝 补充知识点：PriorityQueue (优先队列 / 最小堆)
### 思路推导
  - **普通队列 (Queue)**：就像在超市排队结账，讲究“先来后到”（FIFO：先进先出）。
  - **优先队列 (Priority Queue)**：就像医院的急诊室，不看你什么时候来的，而是看“谁的病情最重”。优先级最高的人永远第一个被叫号！
  - **在 Java 中的默认设定**：Java 的 `PriorityQueue` 默认是一个“最小堆（Min-Heap）”。也就是说，无论你怎么乱序把数字扔进去，只要你往外拿（出队），**永远是最小的那个数第一个出来！**
### 思路推导
  先来看看我们在上一题中写的那句稍微有点复杂的代码：

```java
PriorityQueue<ListNode> pq = new PriorityQueue<>(
    lists.length,
    (a, b) -> Integer.compare(a.val, b.val)
);
```

  如果你只写 `PriorityQueue<Integer> pq = new PriorityQueue<>();`，Java 知道怎么比较整数大小，一切正常。

  **但是，在这个算法里，我们要往里面扔的是 `ListNode`（链表节点）！**

  Java 会懵逼：“你扔给我一堆节点，我怎么知道哪个节点更大、哪个节点更小？” 如果你不告诉它规则，程序运行时直接抛出报错（`ClassCastException`）。
### 思路推导
  1. `lists.length`：这是**初始容量**。告诉漏斗大概要装多少个元素（这里最多装 $k$ 个队长），避免底层数组频繁扩容，提升性能。
  2. `(a, b) -> Integer.compare(a.val, b.val)`：这就是大名鼎鼎的比较器（Comparator）的 Lambda 简写。
     - 这句话是在教 Java 做人：“当你拿节点 `a` 和节点 `b` 比较时，不要管别的，请直接取出它们的里面的数字 `a.val` 和 `b.val` 进行比较！谁的 `val` 小，谁的优先级就高！”

### 补充：掌握它，只需要记住 3 个核心方法（API）

把 `PriorityQueue` 想象成一个带有自动排序魔法的盲盒。你只需要记住以下三个动作：

1. **扔进去：`pq.offer(node)`**
   - 把一个节点扔进堆里。不管你扔进去的是什么，它会在底层自动调整位置。
   - *时间复杂度*：$O(\log k)$（底层是在一棵二叉树上顺着找位置，非常快）。
2. **拿出来：`pq.poll()`**
   - 这是最爽的一步。直接调用 `poll()`，它会把当前堆里**最小的那个节点**拿出来，并且从堆里**删掉**。
   - *时间复杂度*：$O(\log k)$（拿走最顶上的元素后，它底层会自动把第二小的元素顶上来）。
3. **看看不拿：`pq.peek()`**
   - 仅仅是偷看一下目前最小的元素是谁，但不把它从堆里删掉。
   - *时间复杂度*：$O(1)$（瞬间瞄一眼最顶上的元素）。
4. **是否为空：`pq.isEmpty()`**
   - 判断堆里还有没有人。

**👨‍🏫 老师的总结：**

为什么在“合并 K 个链表”中，`PriorityQueue` 被称为神兵利器？

假设你有 10000 个链表（$k = 10000$）。

如果你每次都用一个 `for` 循环去这 10000 个节点里找最小值，找一次就要看 10000 眼，时间复杂度是 $O(k)$。

但如果你用 `PriorityQueue`，你把 10000 个节点扔进去，由于它是树形结构，每次找最小值并重排，只需要走 $\log_2(10000)$ 步，也就是**大约 14 步**！

从 10000 步优化思路到 14 步，这就是**数据结构的魅力**，也是这道题被称为 Hard 的原因！掌握了它，以后所有的“前 K 个最大/最小元素（Top K）”问题，对你来说都是小菜一碟！
