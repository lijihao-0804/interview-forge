39. 组合总和

难度中等核心模式排序 + 可重复选择时间复杂度指数级空间复杂度O(target)

题目与约束

给你一个 无重复元素 的整数数组 candidates 和一个目标整数 target ，找出 candidates 中可以使数字和为目标数 target 的 所有不同组合 ，并以列表形式返回。你可以按 任意顺序 返回这些组合。

candidates 中的 同一个 数字可以 无限制重复被选取 。如果至少一个数字的被选数量不同，则两种组合是不同的。

对于给定的输入，保证和为 target 的不同组合数少于 150 个。

示例 1：

输入：candidates = [2,3,6,7], target = 7
输出：[[2,2,3],[7]]
解释：
2 和 3 可以形成一组候选，2 + 2 + 3 = 7 。注意 2 可以使用多次。
7 也是一个候选， 7 = 7 。
仅有这两种组合。

示例 2：

输入:candidates = [2,3,5], target = 8
输出:[[2,2,2,2],[2,3,3],[3,5]]

示例 3：

输入:candidates = [2], target = 1
输出:[]

提示：

  • 1 <= candidates.length <= 30
  • 2 <= candidates[i] <= 40
  • candidates 的所有元素 互不相同
  • 1 <= target <= 40

核心不变量

允许复用当前数，因此下一层仍从 i 开始。

完整推导

思路推导

  1. 直觉与痛点（无限选取带来的死循环）：

    既然可以无限制选取，那我遇到 2，我就一直选 2, 2, 2, 2...。

    痛点：如果不加限制，这棵树会无限深地长下去（死循环）。所以我们必须有一个明确的终止条件：当口袋里数字的总和 >= target 时，这条路就必须掐断。

  2. 破局思路（破解“可重复”与“不回头”的矛盾）：

    题目要求结果不能重复（[2,3] 和 [3,2] 算同一个）。按照老规矩，防止产生 [3,2] 这种倒车路线，我们必须使用 startIndex 控制法。

    • 如果当前层的 startIndex 是 1（指向数字 3），那么下一层绝对不能从 0（指向数字 2）开始挑。
    • 高能反转：在「78. 子集」题里，下一层是从 i + 1 开始挑的，因为每个数字只能用一次。
    • 但是本题允许重复使用当前数字！所以，当你这一层挑了索引为 i 的数字，下一层依然可以从 i 开始挑！
    • 结论：传给下一层的参数不是 i + 1，而是 i 本身！这就完美解决了“允许重复”与“不走回头路”的矛盾。

    C 实现

    实现来源：代码随想录（programmercarl.com）

    int* path;
int pathTop;
int** ans;
int ansTop;
//记录每一个和等于target的path数组长度
int* length;

import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

class Solution {
    List<List<Integer>> res = new ArrayList<>();

    public List<List<Integer>> combinationSum(int[] candidates, int target) {
        List<Integer> currentPath = new ArrayList<>();

        // 🌟 核心优化：为了后续能够高效剪枝，必须先对数组进行排序！
        // 如果不排序，遇到稍微大一点的数据就会超时。
        Arrays.sort(candidates);

        // 开始在决策树上游走
        // 初始参数：目标值(不断递减)，起始索引(0)，当前路径
        backtrack(candidates, target, 0, currentPath);

        return res;
    }

    private void backtrack(int[] candidates, int remainTarget, int startIndex, List<Integer> currentPath) {
        // 1. 终止条件
        if (remainTarget == 0) {
            // 目标达成！把口袋里的数字快照保存下来
            res.add(new ArrayList<>(currentPath));
            return;
        }

        // 2. 遍历所有的选择，从 startIndex 开始，绝不回头
        for (int i = startIndex; i < candidates.length; i++) {
            // 🌟 终极剪枝操作（因为数组已经排过序了）：
            // 如果当前的数字已经比剩下的目标值还要大了，
            // 那么它后面的数字（比它更大）绝对不可能凑成目标值，直接 break 砍掉整个后面的分支！
            if (candidates[i] > remainTarget) {
                break;
            }

            // --- 做选择 ---
            currentPath.add(candidates[i]);

            // --- 递归进入下一层 ---
            // 🌟 注意：这里的参数是 i，不是 i + 1！
            // 因为当前数字 candidates[i] 还可以被无限次重复使用
            backtrack(candidates, remainTarget - candidates[i], i, currentPath);

            // --- 撤销选择（回溯） ---
            currentPath.remove(currentPath.size() - 1);
        }
    }
}

复杂度

  • 时间复杂度：O(S)，其中 S 为所有可行解的长度之和。回溯算法的时间复杂度通常很难精确计算，因为它高度依赖于剪枝的效果和目标值的大小。最坏情况下（没有剪枝），如果最小元素是 1，树的最大深度可以达到 target，每一层都有多个分支，是个松散的指数级。
  • 空间复杂度：O(target)。空间消耗主要在递归调用栈的深度上。如果每次都选最小的数字，最坏情况下的深度为 target / min(candidates)。
易错点与扩展（进阶的底层细节）
  1. 致命踩坑点：是 remainTarget < 0 还是 break？
  • 很多同学不喜欢排序，他们会把终止条件写成：
if (remainTarget < 0) return; // 发现超标了，退货
if (remainTarget == 0) { ... return; }

  • 这样做逻辑是对的，但在 LeetCode 上执行时间会慢很多！

  • 为什么？因为你每试一个错的数字，都要往下走一层（开销了一次函数调用），然后在下一层才发现超标并返回。

  • 如果你提前排好序，在 for 循环里加上 if (candidates[i] > remainTarget) break;。这意味着你连下一层都不进，直接在路口就把后面所有的大数字全给拒了，这是真正的大面积枝叶修剪，面试官极其看重这种细节！

  1. 面试追问：“如果数组里有重复的数字，并且每个数字只能使用一次，该怎么写？”（对应力扣 40 题：组合总和 II）
  • 满分抢答：这是子集 II 和本题的结合体。
  • 必须排序。
  • 传给下一层的是 i + 1（因为每个数字只能用一次）。
  • 加入树层去重逻辑：if (i > startIndex && candidates[i] == candidates[i - 1]) continue;。
