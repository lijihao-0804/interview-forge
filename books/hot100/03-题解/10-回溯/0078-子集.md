# 78. 子集

| 难度 | 中等 |

## 题目与约束

给你一个整数数组 `nums` ，数组中的元素 **互不相同** 。返回该数组所有可能的子集（幂集）。

  解集 **不能** 包含重复的子集。你可以按 **任意顺序** 返回解集。

  **示例 1：**

  **输入：**nums = [1,2,3]
  **输出：**[[],[1],[2],[1,2],[3],[1,3],[2,3],[1,2,3]]

  **示例 2：**

  **输入：**nums = [0]
  **输出：**[[],[0]]

  **提示：**

  - `1 <= nums.length <= 10`
  - `-10 <= nums[i] <= 10`
  - `nums` 中的所有元素 **互不相同**

[🔗 前往力扣原题验证 →](https://leetcode.cn/problems/subsets/?envType=study-plan-v2&envId=top-100-liked)

## 核心不变量

> 每个递归节点本身就是一个合法子集。

## 完整推导

### 思路推导
  1. **直觉与痛点（排列 vs 子集的本质区别）**：

     全排列找的是**叶子节点**（一定要等口袋装满了 3 个数字才算一个结果）。

     但子集找的是**树上的所有节点**！甚至连一开始什么都没装的空树根 `[]`，也是一个合法的子集。所以，我们走到任何一个节点，都要把它放进结果集里。

  2. **破局思路（不走回头路的 `startIndex`）**：

     怎么避免收集了 `[1, 2]` 之后，又跑去收集 `[2, 1]` 呢？

     答案是：**永远只向后看！**

     - 当你抓了 `1` 之后，你面前的选项只剩下它后面的 `[2, 3]`。

     - 当你抓了 `2` 之后，你面前的选项只剩下它后面的 `[3]`。（绝对不允许再回头去抓 `1`）

     - 当你抓了 `3` 之后，后面没数字了，这条路就结束了。

       为了实现这个“只向后看”的机制，我们在回溯函数里加一个参数 `startIndex`。每次向下一层递归时，告诉下一层：“你只能从 `startIndex + 1` 开始挑数字哦！”
### Java 实现（子集黄金模板）
```Java
import java.util.ArrayList;
import java.util.List;

class Solution {
    List<List<Integer>> res = new ArrayList<>();

    public List<List<Integer>> subsets(int[] nums) {
        List<Integer> currentPath = new ArrayList<>();
        // 从索引 0 开始挑选
        backtrack(nums, 0, currentPath);
        return res;
    }

    private void backtrack(int[] nums, int startIndex, List<Integer> currentPath) {
        // 🌟 核心差异 1：收集树上的【所有节点】
        // 不需要写终止条件才收集，来到一个新节点，二话不说先把它装进结果集！
        res.add(new ArrayList<>(currentPath));

        // 🌟 核心差异 2：用 startIndex 控制遍历的起点，不走回头路
        for (int i = startIndex; i < nums.length; i++) {
            // --- 做选择 ---
            currentPath.add(nums[i]);

            // --- 递归进入下一层 ---
            // 注意！这里传给下一层的是 i + 1，意思是：
            // 如果我这一层挑了索引为 i 的数字，下一层只能从 i 的后面开始挑！
            backtrack(nums, i + 1, currentPath);

            // --- 撤销选择（回溯） ---
            currentPath.remove(currentPath.size() - 1);
        }
    }
}
```
### 复杂度
  - **时间复杂度**：$O(N \times 2^N)$。一个包含 $N$ 个元素的集合，它的子集一共有 $2^N$ 个。每个子集加入结果集时都需要拷贝一次（拷贝时间与子集长度有关，平均为 $N/2$），所以总时间复杂度是 $O(N \times 2^N)$。
  - **空间复杂度**：$O(N)$。主要消耗在递归调用栈的深度和 `currentPath` 数组上，最大深度为 $N$。

### 易错点与扩展（面试高频连环问）

1. **踩坑警告：`used` 数组和 `startIndex` 到底怎么选？**

   - 记住这个口诀：**排列问题用 `used`，组合/子集问题用 `startIndex`。**
   - 全排列讲究顺序（[1,2] 和 [2,1] 不同），所以每次都要从头开始扫整个数组，靠 `used` 数组来跳过已经选过的数。
   - 子集/组合不讲究顺序，为了去重，必须强制规定选取的顺序（比如只能从前往后选），所以靠 `startIndex` 挡住后面的递归回头看。

2. **面试追问：“如果给你的 `nums` 数组里面有【重复数字】（例如 `[1, 2, 2]`），你该怎么修改代码，保证子集不重复？”（对应力扣 90 题：子集 II）**

   - **满分抢答**：依然是**排序 + 剪枝**！

   - 先对数组排序：`[1, 2, 2]`。

   - 在 `for` 循环里加入极其经典的树层剪枝代码：

     `if (i > startIndex && nums[i] == nums[i - 1]) continue;`

   - *解释*：注意这里是 `i > startIndex` 而不是全排列里的 `i > 0`。它的意思是：在**同一个树层（同一层 for 循环）**中，如果当前数字和前一个数字一样，说明前一个数字已经把包含该数字的所有子集都找过了，直接跳过。但如果是**树枝向下（递归到了下一层）**，是可以选重复数字的（比如允许出现 `[2, 2]`）。
