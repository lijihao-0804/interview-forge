题目信息 内容
难度 中等
核心模式 计数约束剪枝
时间复杂度 O(Cₙ)
空间复杂度 O(n)

题目与约束

数字 n 代表生成括号的对数，请你设计一个函数，用于能够生成所有可能的并且 有效的括号组合。

示例 1：

输入：n = 3
输出：["((()))","(()())","(())()","()(())","()()()"]

示例 2：

输入：n = 1
输出：["()"]

提示：

  • 1 <= n <= 8

核心不变量

任意前缀中右括号数不能超过左括号数。

完整推导

思路推导

  1. 直觉与痛点（暴力的代价）：

    最暴力的做法是：总共需要放 2n 个字符，每个位置要么放 ( 要么放 )。我们不管三七二十一，用回溯法生成所有 22n 种组合，最后写个函数挨个检查它们是不是合法的括号。

    痛点：极其浪费算力！当生成出 )( 作为开头时，其实就已经死局了，但暴力法还会傻乎乎地把它后面的所有组合生成完。

  2. 破局思路（边生成边校验的双指针）：

    我们要把事后的“尸检”，变成事前的“体检”。

    我们在回溯的时候，手里拿着两个计数器：leftCount（左括号用了几个） 和 rightCount（右括号用了几个）。

    然后，死死盯住两条黄金天规：

    • 天规一（左括号的底线）：只要左括号的数量还没达到 n（leftCount < n），你随时随地都可以放左括号。
    • 天规二（右括号的红线）：右括号绝对不能比左括号多！所以，只有当目前放的右括号比左括号少时（rightCount < leftCount），你才有资格放一个右括号。

  3. 逻辑推演：

    拿着这两条天规去走迷宫，但凡违反任何一条，连路口都不让进（完美剪枝）。当 leftCount == n 且 rightCount == n 时，一条完美的合法括号链就诞生了。

    Java 实现（满分规则剪枝版）

import java.util.ArrayList;
import java.util.List;

class Solution {
    List<String> res = new ArrayList<>();

    public List<String> generateParenthesis(int n) {
        StringBuilder path = new StringBuilder();
        // 初始状态：左括号 0 个，右括号 0 个
        backtrack(n, 0, 0, path);
        return res;
    }

    private void backtrack(int n, int leftCount, int rightCount, StringBuilder path) {
        // 1. 终止条件：当左括号和右括号都用完了，说明找到了一组合法的括号
        if (leftCount == n && rightCount == n) {
            res.add(path.toString());
            return;
        }

        // 2. 尝试放置【左括号】
        // 天规一：只要左括号没用完，就可以一直放
        if (leftCount < n) {
            path.append("("); // 做选择
            backtrack(n, leftCount + 1, rightCount, path); // 进入下一层
            path.deleteCharAt(path.length() - 1); // 撤销选择（回溯）
        }

        // 3. 尝试放置【右括号】
        // 天规二：只有目前右括号比左括号少，才能放右括号，否则就会出现 ())( 的非法情况
        if (rightCount < leftCount) {
            path.append(")"); // 做选择
            backtrack(n, leftCount, rightCount + 1, path); // 进入下一层
            path.deleteCharAt(path.length() - 1); // 撤销选择（回溯）
        }
    }
}

复杂度

  • 这道题的时间复杂度和空间复杂度非常特殊，它涉及到一个极其著名的数学数列——卡特兰数 (Catalan Number)。
  • 时间复杂度：O(4nn)。第 n 个卡特兰数决定了合法括号的组合总数。因为我们使用了完美的剪枝，算法的时间复杂度严格等于解的数量，没有浪费一丝一毫的算力。
  • 空间复杂度：O(n)。除了存储结果的列表外，递归调用栈的深度以及 StringBuilder 的长度最大均为 2n。

易错点与扩展（面试的终极拷问）

  1. 面试追问：“如果我想偷懒，把传入参数直接写成 String path，不写撤销操作，可以吗？” - 回答：可以，因为 String 是不可变的。每次 path + "(" 都会生成一个新的字符串传给下一层，当前层的 path 并没有被修改，所以自然就不需要撤销。 - 灵魂暴击：但是！在追求极致性能的工业界或面试面试中，每次拼接都会产生新的字符串对象，造成大量内存碎片。虽然这题的 n 最大只有 8，用 String 不会超时，但使用 StringBuilder 并在最后 deleteCharAt 是最高级的工程品味，它体现了你对内存控制的严谨。
  2. 面试追问：“你能用【动态规划】来解这道题吗？” - 这是一道绝佳的思考题。如果有 n 对括号，其实可以分解为：( + a 对括号的合法组合 + ) + b 对括号的合法组合。其中 a + b = n - 1。 - 通过遍历 a 从 0 到 n-1，我们可以利用之前算好的子结果，拼凑出当前的答案。这证明了回溯题有时候可以用 DP 来降维！
