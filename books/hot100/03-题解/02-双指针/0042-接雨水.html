题目与约束

给定一个非负整数数组，每个元素代表一块宽度为 1 的柱子的高度。求当下雨后，这些柱子中间最多能接多少单位的雨水。

🔗 前往力扣原题验证 →

核心不变量

较低一侧的蓄水量已由该侧最大边界确定。

完整推导

思路推导

  1. 直觉与痛点（竖向切片法）：

    不要横向看，我们要一列一列地看。对于任意一个位置 i，它能装多少水，完全取决于它左边最高的柱子（leftMax）和它右边最高的柱子（rightMax）。

    原理（木桶效应）：位置 i 的水面高度 = min(leftMax, rightMax)。

    位置 i 的水量 = 水面高度 - 柱子本身的高度（如果算出来是负数，就是 0）。

    痛点：如果对每个柱子都向左、向右扫描一遍找最高点，时间复杂度是 O(N2)，太慢了！如果用两个数组把每个位置的 leftMax 和 rightMax 提前存起来（动态规划法），时间是 O(N)，但空间复杂度也是 O(N)。能不能把空间也压榨到 O(1)？

  2. 破局思路（双指针 + 动态极值）：

    我们用两个指针 left 和 right 分别站在数组的两端，相向而行。

    同时，我们维护两个变量：leftMax（记录左指针走过的最大高度）和 rightMax（记录右指针走过的最大高度）。

  3. 逻辑推演（核心灵魂：谁小结算谁）：

    当你站在两端时，比较 leftMax 和 rightMax：

    • 如果 leftMax < rightMax：

    对于左指针 left 当前所在的柱子来说，它的右边一定存在一个高度至少为 rightMax 的“高墙”。既然右边有靠山，那 left 这个位置能装多少水，就唯一取决于较矮的 leftMax！我们就可以放心地结算 left 位置的水量，然后 left++。

    • 如果 leftMax >= rightMax：

    同理，对于右指针 right 来说，它的左边有靠山（leftMax），所以它能装多少水，唯一取决于 rightMax！我们结算 right 位置的水量，然后 right--。

    Java 实现

class Solution {
    public int trap(int[] height) {
        // 应对极端情况：数组为空或长度不足以形成凹槽
        if (height == null || height.length < 3) {
            return 0;
        }

        // 1. 初始化双指针
        int left = 0;
        int right = height.length - 1;

        // 2. 初始化左右两端走过的历史最高柱子
        int leftMax = 0;
        int rightMax = 0;

        int totalWater = 0; // 记录总装水量

        // 3. 左右指针相向而行，直到相遇
        while (left < right) {
            // 先更新当前的左右两端最大值
            leftMax = Math.max(leftMax, height[left]);
            rightMax = Math.max(rightMax, height[right]);

            // 4. 核心逻辑：谁的瓶颈低，就结算谁，并向前移动
            if (leftMax < rightMax) {
                // 左边的历史最高比右边的历史最高矮
                // 说明 left 位置的短板一定是 leftMax，右边再怎么起伏也漏不出去
                totalWater += leftMax - height[left];
                left++;
            } else {
                // 右边的历史最高较矮（或相等）
                // 说明 right 位置的短板一定是 rightMax
                totalWater += rightMax - height[right];
                right--;
            }
        }

        return totalWater;
    }
}

复杂度

  • 时间复杂度：O(N)。左右指针只把整个数组遍历了一遍，每次比较和计算都是常数时间操作。
  • 空间复杂度：O(1)。只使用了几个变量，没有任何额外的数组开销。这是面试官最想看到的终极形态。

易错点与扩展（关键追问）

  • 面试官追问：“在 leftMax < rightMax 时，你凭什么断定 left 右边没有更矮的板子导致漏水？”

  • 满分回答：因为 rightMax 是从最右侧扫描过来的历史最高点。即使 left 和 right 中间存在非常深的坑洞或者极其高耸的山峰，都不会影响 left 位置的储水能力。

    • 如果中间有山峰，那未来的 rightMax 会更大，left 的水面依旧由 leftMax 决定。

    • 如果中间是深坑，深坑不会拉低右侧已知的 rightMax 这个物理屏障。

    因此，只要我们手握左右两端的历史最高记录，我们就可以断言：水是从短板溢出的，只要确认了哪边是绝对的短板，就可以直接结算那一列的水量。
