15. 三数之和

← 双指针专题 · 总目录 · 复习清单

难度中等
Java 主方法排序 + 固定一点 + 双指针时间O(n²)空间O(log n)
Python 主方法排序 + 固定首项 + 双指针时间O(n²)空间O(n)（Timsort 最坏临时缓冲；不含输出）

题目与约束

给你一个整数数组 nums ，判断是否存在三元组 [nums[i], nums[j], nums[k]] 满足 i != j、i != k 且 j != k ，同时还满足 nums[i] + nums[j] + nums[k] == 0 。请你返回所有和为 0 且不重复的三元组。

注意：答案中不可以包含重复的三元组。

示例 1：

输入：nums = [-1,0,1,2,-1,-4]
输出：[[-1,-1,2],[-1,0,1]]
解释：
nums[0] + nums[1] + nums[2] = (-1) + 0 + 1 = 0 。
nums[1] + nums[2] + nums[4] = 0 + 1 + (-1) = 0 。
nums[0] + nums[3] + nums[4] = (-1) + 2 + (-1) = 0 。
不同的三元组是 [-1,0,1] 和 [-1,-1,2] 。
注意，输出的顺序和三元组的顺序并不重要。

示例 2：

输入：nums = [0,1,1]
输出：[]
解释：唯一可能的三元组和不为 0 。

示例 3：

输入：nums = [0,0,0]
输出：[[0,0,0]]
解释：唯一可能的三元组和为 0 。

提示：

  • 3 <= nums.length <= 3000
  • -105 <= nums[i] <= 105

Java 完整推导

Java 核心不变量

固定第一数后夹逼，并在三层位置正确去重。

完整推导

思路推导

  1. 直觉与痛点（哈希表硬干）：

    之前做“两数之和”用了哈希表，那“三数之和”能不能套两层循环，第三个数去哈希表里找？

    痛点：可以做，但去重简直是地狱！因为数组没排序，你很难判断新找到的三元组是不是之前已经找过。如果强行把三元组排序后放进 Set 里去重，不仅代码奇丑无比，甚至会超时。

  2. 破局思路（排序 + 定一动二）：

    面对“去重”和“组合”问题，第一步永远是：把数组排个序！

    排序后，相同的数字全挨在一起，去重变得轻而易举。同时，有序数组天然适合双指针。

    核心策略：先固定一个数（设为 nums[i]），那么问题就瞬间优化思路，变成了：在 i 后面的有序数组里，用双指针寻找“两数之和等于 -nums[i]”的组合。

  3. 逻辑推演（以 [-1, 0, 1, 2, -1, -4] 为例）：

    • 第一步排序：变成 [-4, -1, -1, 0, 1, 2]。
    • 遍历固定 i：
    • 当 i 指向 -4 时，我们需要在后面找两数之和为 4。左指针 L 指向 -1，右指针 R 指向 2。加起来才 1，太小了，L 右移...
    • 当 i 指向第一个 -1 时，需要找两数之和为 1。找到 [-1, 0, 1]。
    • 去重高光时刻：当 i 指向第二个 -1 时，如果不跳过它，又会找出一遍 [-1, 0, 1]。所以遇到和前一个数相同的 i，直接 continue 跳过！双指针 L 和 R 遇到重复数字也是同理跳过。

    Java 实现

import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

class Solution {
    public List<List<Integer>> threeSum(int[] nums) {
        List<List<Integer>> result = new ArrayList<>();

        // 1. 灵魂步骤：对数组进行全面排序
        Arrays.sort(nums);

        // 2. 遍历数组，固定第一个数 nums[i]
        for (int i = 0; i < nums.length - 2; i++) {
            // 极致剪枝：如果当前排好序的最小数已经大于 0，那后面再怎么加也不可能等于 0 了，直接结束
            if (nums[i] > 0) {
                break;
            }

            // i 的去重逻辑：如果现在的 i 和上一个 i 的值一样，说明这个数字作为“基准”已经搜过了，跳过
            if (i > 0 && nums[i] == nums[i - 1]) {
                continue;
            }

            // 3. 优化思路：在 i 之后的区间内，用双指针寻找两数之和等于 -nums[i]
            int left = i + 1;
            int right = nums.length - 1;

            while (left < right) {
                int sum = nums[i] + nums[left] + nums[right];

                if (sum == 0) {
                    // 找到了一组，加入结果集
                    result.add(Arrays.asList(nums[i], nums[left], nums[right]));

                    // L 和 R 的去重逻辑：跨过所有相同的数字，避免产生重复的三元组
                    while (left < right && nums[left] == nums[left + 1]) {
                        left++;
                    }
                    while (left < right && nums[right] == nums[right - 1]) {
                        right--;
                    }

                    // 去重完毕后，双指针双双向内收缩，继续寻找下一组
                    left++;
                    right--;
                } else if (sum < 0) {
                    // 和太小，说明左边的数小了，左指针右移
                    left++;
                } else {
                    // 和太大，说明右边的数大了，右指针左移
                    right--;
                }
            }
        }

        return result;
    }
}

复杂度

  • 时间复杂度：O(N2)。数组排序的时间复杂度是 O(N log N)。外层遍历 i 需要 O(N)，内部双指针相向而行遍历剩余数组也需要 O(N)。嵌套起来是 O(N2)。综合来看取最高阶 O(N2)。
  • 空间复杂度：O(log N) 或 O(N)。这取决于 Java Arrays.sort() 底层使用的排序算法（快排或 TimSort）所带来的递归栈空间开销。（注意：不计算用来存放结果的 result 列表的空间）。
易错点与扩展
  1. 致命陷阱：i 的去重为什么是 nums[i] == nums[i - 1] 而不是 nums[i] == nums[i + 1]？ - 这是无数人栽跟头的地方！假设数组是 [-1, -1, 2]。 - 如果是看后面：nums[i] == nums[i + 1]。当 i=0 时，你发现 -1 == -1，你跳过了第一个 -1。结果导致你错失了合法的 [-1, -1, 2] 组合！ - 如果是看前面：nums[i] == nums[i - 1]。当 i=1 时，你发现它和前面的 i=0 长得一样，说明以 -1 打头阵的所有组合都在上一步找过了，此时跳过。这才是真正的去重！
  2. 双指针去重时机的考究 - 在代码中，L 和 R 的去重操作是在 sum == 0 的大括号内部执行的。为什么不在 sum < 0 或 sum > 0 的时候也用 while 去重？ - 回答：因为没必要。如果 sum < 0，你写 left++ 即使遇到了相同的数字，下一步计算 sum 依然 < 0，循环会自然而然地让它继续 left++，所以不需要单独写一层 while 去跳过，让外层的大 while 自己转就行，代码更简洁。

Python 完整推导

排序后固定一个数，再找另外两个

数组排序后，相同数字相邻，去重有了统一规则；同时数组具有单调性。

固定 value = nums[i] 后，问题变成在右侧寻找和为 -value 的两个数。left 增大时和只会增大，right 减小时和只会减小，因此可以相向收缩。

用 [-1, 0, 1, 2, -1, -4] 走一遍

排序得到 [-4, -1, -1, 0, 1, 2]。

  • 固定第一个 -1，left 指向第二个 -1，right 指向 2，得到 [-1, -1, 2]。
  • 两指针向中间移动，得到 [-1, 0, 1]。
  • 第二个 -1 作为首项时与前一位置相同，直接跳过，避免重复记录。
  • 固定 0 时，右侧最小值已非负，找不到新的零和组合。

最终得到 [[-1, -1, 2], [-1, 0, 1]]。

Python 实现

参考来源：代码随想录（programmercarl.com）

保留旧 Python 的排序加双指针实现，整理去重分支和变量；算法未改变。

from typing import List


class Solution:
    def threeSum(self, nums: List[int]) -> List[List[int]]:
        nums.sort()
        answer = []
        for i, value in enumerate(nums):
            if value > 0:
                break
            if i > 0 and value == nums[i - 1]:
                continue
            left, right = i + 1, len(nums) - 1
            while left < right:
                total = value + nums[left] + nums[right]
                if total < 0:
                    left += 1
                elif total > 0:
                    right -= 1
                else:
                    answer.append([value, nums[left], nums[right]])
                    left += 1
                    right -= 1
                    while left < right and nums[left] == nums[left - 1]:
                        left += 1
                    while left < right and nums[right] == nums[right + 1]:
                        right -= 1
        return answer

三条去重规则

  • 外层 value == nums[i - 1] 跳过后一个相同首项。
  • 命中答案后先同时移动 left、right，再跳过新位置上与前一位相同的值。
  • 首项大于 0 时直接结束，因为后续数都不小于它，三数和不可能回到 0。

指针分支

当前和小于 0 时只能增大，所以 left += 1；当前和大于 0 时只能减小，所以 right -= 1。第一步移动后再检查重复，比较条件始终是当前一对尚未检查的下标。

输入与空结果

nums.sort() 会原地改变输入列表。题目输入不足三个数时，left < right 不会成立，函数返回空列表。

复杂度

  • 时间复杂度：O(n²)。
  • 空间复杂度：O(n)（Timsort 最坏临时缓冲；不含输出）。

排序 O(n log n)，固定 n 个首项时内部双指针合计 O(n²)，取较高阶为 O(n²)。Python Timsort 最坏需要 O(n) 额外缓冲。

C++ 实现

实现来源：站内标准实现

class Solution {
public:
    vector<vector<int>> threeSum(vector<int>& nums) {
        vector<vector<int>> ans;
        sort(nums.begin(), nums.end());
        int n = nums.size();
        for (int i = 0; i < n - 2 && nums[i] <= 0; ++i) {
            if (i > 0 && nums[i] == nums[i - 1]) continue;
            int left = i + 1, right = n - 1;
            while (left < right) {
                long long s = (long long)nums[i] + nums[left] + nums[right];
                if (s < 0) ++left;
                else if (s > 0) --right;
                else {
                    ans.push_back({nums[i], nums[left], nums[right]});
                    while (left < right && nums[left] == nums[left + 1]) ++left;
                    while (left < right && nums[right] == nums[right - 1]) --right;
                    ++left; --right;
                }
            }
        }
        return ans;
    }
};

Go 实现

实现来源：代码随想录（programmercarl.com）

func threeSum(nums []int) [][]int {
    sort.Ints(nums)
    result := make([][]int, 0)

    for i := 0; i < len(nums); i++ {
        if nums[i] > 0 {
            break
        }

        if i > 0 && nums[i] == nums[i-1] { // 对第一个数去重
            continue
        }

        left, right := i+1, len(nums)-1
        for left < right {
            sum := nums[i] + nums[left] + nums[right]

            if sum > 0 {
                right--
            } else if sum < 0 {
                left++
            } else {
                result = append(result, []int{nums[i], nums[left], nums[right]})

                // 先记录答案，再对第二、第三个数去重
                for left < right && nums[left] == nums[left+1] {
                    left++
                }
                for left < right && nums[right] == nums[right-1] {
                    right--
                }

                left++
                right--
            }
        }
    }

    return result
}
