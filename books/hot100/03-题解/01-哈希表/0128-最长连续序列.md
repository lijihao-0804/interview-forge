## 题目与约束

给定一个未排序的整数数组 `nums`，找出数字连续的最长序列（不要求序列元素在原数组中连续）的长度。

  **致命要求**：算法的时间复杂度必须是 $O(N)$。

[🔗 前往力扣原题验证 →](https://leetcode.cn/problems/longest-consecutive-sequence/?envType=study-plan-v2&envId=top-100-liked)

## 核心不变量

> 只从不存在 x - 1 的数字开始向右扩展。

## 完整推导

### 思路推导
  1. **直觉与痛点（排序法）**：

     最直观的想法是先把数组排个序，然后遍历一遍数连在一起的数字有多少个。

     **痛点**：任何基于比较的排序算法（如快排、归并）时间复杂度下限都是 $O(N \log N)$，直接违反了题目 $O(N)$ 的硬性要求。

  2. **破局思路（哈希表 + 智能起点寻找）**：

     既然不能排序，我们要想在 $O(1)$ 时间内知道某个数“是否存在”，就必须把所有数字扔进 **HashSet**。

     有了 HashSet，我们可以随便挑一个数 $x$，然后不断去查 $x+1, x+2, x+3$ 在不在集合里。

     **核心难题**：如果对每个数都往上查一遍，最坏情况（比如数组是 `[5, 4, 3, 2, 1]`）会退化成 $O(N^2)$。怎么优化？

  3. **逻辑推演（掐头去尾法）**：

     其实我们**只需要从每个连续序列的“起点”开始往上数即可**。

     怎么判断一个数是不是“起点”？**只要 `x-1` 不在哈希表里，那 `x` 就是一个序列的开头！**

     - 假设输入：`[100, 4, 200, 1, 3, 2]`
     - 全部放入 Set。
     - 遇到 `100`：查到 `99` 不在 Set 里，它是起点！开始往上数，发现 `101` 不在，序列长度 1。
     - 遇到 `4`：查到 `3` 在 Set 里。说明 `4` **绝对不是起点**，直接跳过它（因为我们迟早会从 `1` 开始数，一路数到 `4`，现在没必要做无用功）。
     - 遇到 `1`：查到 `0` 不在，它是起点！开始数：有 `2`，有 `3`，有 `4`。序列长度 4。更新最大长度。
### Java 实现
```java
import java.util.HashSet;
import java.util.Set;

class Solution {
    public int longestConsecutive(int[] nums) {
        // 如果数组为空，直接返回 0
        if (nums == null || nums.length == 0) {
            return 0;
        }

        // 1. 将所有数字放入 HashSet 中，去重并提供 O(1) 的查询能力
        Set<Integer> numSet = new HashSet<>();
        for (int num : nums) {
            numSet.add(num);
        }

        int longestStreak = 0;

        // 2. 遍历 HashSet 中的每一个数字
        for (int num : numSet) {
            // 3. 核心剪枝逻辑：只有当 num-1 不存在时，当前 num 才是序列的“起点”
            if (!numSet.contains(num - 1)) {
                int currentNum = num;
                int currentStreak = 1; // 当前序列长度初始化为 1

                // 4. 从起点开始，不断去 Set 里寻找下一个连续的数字
                while (numSet.contains(currentNum + 1)) {
                    currentNum += 1;
                    currentStreak += 1;
                }

                // 5. 更新历史最长序列记录
                longestStreak = Math.max(longestStreak, currentStreak);
            }
        }

        return longestStreak;
    }
}
```
### 复杂度
  - **时间复杂度**：**$O(N)$**。虽然代码里有一层 `for` 循环嵌套了一层 `while` 循环，但千万不要被骗了！因为有了 `if (!numSet.contains(num - 1))` 这个剪枝条件，**数组中的每个数字实际上最多只会被 `while` 循环访问一次**。外层循环 $O(N)$，内层 `while` 的总执行次数也是 $O(N)$，加起来还是 $O(N)$。
  - **空间复杂度**：$O(N)$。我们需要一个 HashSet 来存储数组中的所有数字。

### 易错点与扩展

1. **避坑：为什么外层循环遍历的是 `numSet` 而不是原数组 `nums`？**
   - 遍历 `nums` 也是对的，结果一样。但是遍历 `numSet` **效率更高**。因为 `nums` 中可能包含大量重复元素（比如十万个 `1`），扔进 Set 后去重了。遍历 `numSet` 可以直接省去处理大量重复数字的时间。
2. **逻辑陷阱：千万别漏了 `!numSet.contains(num - 1)`**
   - 如果没有这行 `if` 判断，遇到 `[5, 4, 3, 2, 1]` 这样的倒序数组时，算法会对每一个数都往后遍历查一遍，时间复杂度会瞬间飙升到 $O(N^2)$，面试直接挂掉。这行代码是整道题的**灵魂**。
