## 题目与约束

给定一个整数数组 `nums` 和一个整数目标值 `target`，请你在该数组中找出 **和为目标值***`target`*  的那 **两个** 整数，并返回它们的数组下标。

  你可以假设每种输入只会对应一个答案，并且你不能使用两次相同的元素。

  你可以按任意顺序返回答案。

  **示例 1：**

  **输入：**nums = [2,7,11,15], target = 9<br>**输出：**[0,1]<br>**解释：**因为 nums[0] + nums[1] == 9 ，返回 [0, 1] 。

  **示例 2：**

  **输入：**nums = [3,2,4], target = 6<br>**输出：**[1,2]

  **示例 3：**

  **输入：**nums = [3,3], target = 6<br>**输出：**[0,1]

  **提示：**

  - `2 <= nums.length <= 104`
  - `-109 <= nums[i] <= 109`
  - `-109 <= target <= 109`
  - **只会存在一个有效答案**

  **进阶：**你可以想出一个时间复杂度小于 `O(n2)` 的算法吗？

## Java 完整推导



### Java 核心不变量



> 先查 target - x，再记录 x，避免元素与自身匹配。

## 完整推导

### 思路推导
  1. **直觉与痛点（暴力解法）**：

     第一反应是用两个嵌套的 `for` 循环遍历所有的数字对，看看哪对加起来等于 `target`。

     **痛点**：找数字太慢了！假设当前数字是 $x$，我们需要在剩下的数组里找是否存在 `target - x`。数组的线性查找时间是 $O(N)$，导致总时间复杂度高达 $O(N^2)$。当数组很大时，直接超时。

  2. **破局思路（引入哈希表）**：

     我们需要一个能瞬间（$O(1)$ 时间）告诉我们“某个数字存不存在，以及它在哪”的数据结构。**哈希表（HashMap）**就是完美选择。 **核心思想**：与其先全部存起来再找，不如**“边遍历，边查找，边记录”**。

  3. **逻辑推演（以 `nums = [2, 7, 11, 15]`, `target = 9` 为例）**：

     我们准备一个空的哈希表 `Map<数值, 对应下标>`。

     - **来到索引 `0`**，数字是 `2`。我们想要凑齐 `9`，所以到处找 `7` (即 `9 - 2`)。看一眼哈希表，空的，没找到 `7`。那就把自己的信息登记一下：存入 `Map: {2: 0}`。
     - **来到索引 `1`**，数字是 `7`。我们想要凑齐 `9`，所以到处找 `2` (即 `9 - 7`)。看一眼哈希表，**发现哈希表里正好有 `2`**，而且它在索引 `0`！
     - 匹配成功，直接返回结果 `[0, 1]`。
### Java 实现
```java
import java.util.HashMap;
import java.util.Map;

class Solution {
    public int[] twoSum(int[] nums, int target) {
        // 定义哈希表：Key 存数组中的数字，Value 存数字对应的下标
        // 为什么要把数字做 Key？因为我们要根据数值去快速查找下标！
        Map<Integer, Integer> map = new HashMap<>();

        for (int i = 0; i < nums.length; i++) {
            // 计算当前数字的“配对者”应该是多少
            int complement = target - nums[i];

            // 如果哈希表里已经有这个“配对者”了，说明我们找到了答案
            if (map.containsKey(complement)) {
                // 返回配对者的下标，以及当前数字的下标
                return new int[] { map.get(complement), i };
            }

            // 如果没找到，就把当前数字和它的下标存入哈希表，供后面的数字查找
            map.put(nums[i], i);
        }

        // 如果找不到匹配的（虽然题目说一定有解，但为了保证编译通过，需要有默认返回值）
        throw new IllegalArgumentException("No two sum solution");
    }
}
```
### 复杂度
  - **时间复杂度**：$O(N)$。我们只把数组遍历了一遍。在哈希表中查询（`containsKey`）和插入（`put`）的时间复杂度平均都是 $O(1)$。所以总共是 $N \times O(1) = O(N)$。
  - **空间复杂度**：$O(N)$。我们开辟了一个哈希表，最坏的情况下（比如答案在数组的最后两个），我们需要把前面的 $N-1$ 个数字全存入哈希表。

### 易错点与扩展

1. **避坑：为什么不“先用一个 for 循环把所有元素存入 Map，再用一个 for 循环去查”？（两遍哈希）**
   - **缺点 1**：效率略低，必须要遍历两次数组。
   - **缺点 2（致命）**：题目规定“同一个元素不能使用两遍”。如果 `target = 6`，数组是 `[3, 2, 4]`，两遍哈希在查 `3` 的时候，会在 Map 里发现 `3`，从而错误地返回 `[0, 0]`。
   - **我们的做法（一遍哈希）完美避开了这个问题**：因为每次我们都是先查 `complement`，查不到才把当前的数放进去。这保证了匹配到的数一定是在当前数**之前**出现的数，绝对不会自己匹配到自己。
2. **高频追问：如果给定的是一个「已经排好序」的数组，你还会用哈希表吗？**
   - **标准回答**：不会。如果数组已经有序（例如 LeetCode 167 题），我会使用**双指针（头尾指针）**。一个指针指向开头，一个指向结尾，根据两数之和与 target 的大小关系来向中间收缩。双指针解法的空间复杂度只有 **$O(1)$**，比哈希表的 $O(N)$ 空间更优。

这篇笔记的核心在于理解**为什么哈希表的 Key 必须是数字的值，而不是数组下标**——因为我们是“顺藤摸瓜”，我们拿着想要的数值去找位置。

## Python 完整推导

### 直觉：别再为每个数重新找一遍

暴力解法每遇到一个数 `x`，都要再扫一遍数组找 `target - x`，大量重复搜索让时间来到平方级。真正有用的是记住“刚才走过哪些数，它们各在下标几”。

于是用字典 `seen` 记录已经访问过的元素：键是数值，值是对应下标。当前值是 `x` 时，只要补数 `target - x` 已经在 `seen` 里，就立刻找到了一组答案；否则把当前数登记下来，留给后面的元素查找。

### 用具体输入走一遍

### `nums = [2, 7, 11, 15]`，`target = 9`

- 初始 `seen = {}`。
- 下标 `0`，当前元素是 `2`，需要的补数是 `9 - 2 = 7`。`7` 还不在 `seen` 里，因此登记当前元素：`seen = {2: 0}`。
- 下标 `1`，当前元素是 `7`，需要的补数是 `9 - 7 = 2`。`2` 正在 `seen` 里，对应下标是 `0`，所以返回 `[0, 1]`。

### `nums = [3, 3]`，`target = 6`

- 初始 `seen = {}`。
- 下标 `0`，当前元素是 `3`，需要的补数是 `6 - 3 = 3`。此时字典还是空的，所以先登记：`seen = {3: 0}`。
- 下标 `1`，当前元素仍是 `3`，需要的补数也是 `3`。这次查询命中了下标 `0` 的那个 `3`，返回 `[0, 1]`。

第二例能成功，靠的是“先查、后存”：查到的是此前放进去的下标 `0`，当前下标 `1` 的 `3` 还没进入字典，因此不会拿同一个元素和自己配对。

### Python 实现

> 参考来源：代码随想录（programmercarl.com）
>
> 代码采用项目原收录的代码随想录 Python 实现，只整理变量、注释与导入；算法未改变。

```python
from typing import List


class Solution:
    def twoSum(self, nums: List[int], target: int) -> List[int]:
        seen = {}
        for index, value in enumerate(nums):
            need = target - value
            if need in seen:
                return [seen[need], index]
            seen[value] = index  # 没找到搭档，先记下当前数的下标
        return []
```

### 这段 Python 代码要留意的细节

- `enumerate(nums)` 每轮同时给出 `(下标, 数值)`，这里按 `index, value` 的顺序接住，正好符合返回答案时需要的信息。
- `need in seen` 判断的是字典键，也就是某个数值是否曾经出现。它比先取下标再处理 `KeyError` 更直接。
- 两行顺序不能交换。如果先执行 `seen[value] = index`，在 `[3, 3], target = 6` 中处理下标 `0` 时就会立刻查到自己，错误地返回 `[0, 0]`。
- 这里没有承诺保留重复值的最早下标。某个重复值如果未命中补数，后续的 `seen[value] = index` 会覆盖旧值；题目只要求返回任意一组合法下标，这不影响一次遍历解法。

### 复杂度

- 时间复杂度：`O(n)`。
- 空间复杂度：`O(n)`。

每个元素至多执行一次补数查询和一次字典写入，平均 O(1) 一次；最坏保存 n 个值。

## C++ 实现

> 实现来源：代码随想录（programmercarl.com）



```cpp
class Solution {
public:
    vector<int> twoSum(vector<int>& nums, int target) {
        unordered_map<int, int> map; // key: 元素值, value: 下标
        for (int i = 0; i < nums.size(); i++) {
            auto iter = map.find(target - nums[i]); // 查找之前是否出现过配对元素
            if (iter != map.end()) {
                return {iter->second, i};
            }
            map.insert(pair<int, int>(nums[i], i)); // 没找到，把当前元素存入map
        }
        return {};
    }
};
```

```go
func twoSum(nums []int, target int) []int {
    m := make(map[int]int)
    for i, num := range nums {
        complement := target - num
        if index, found := m[complement]; found { // 查找之前是否出现过配对元素
            return []int{index, i}
        }
        m[num] = i // 没找到，把当前元素存入map
    }
    return nil
}
```
