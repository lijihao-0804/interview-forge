189. 轮转数组

← 普通数组专题 · 总目录 · 复习清单

难度中等核心模式三次反转时间复杂度O(n)空间复杂度O(1)

题目与约束

给定一个整数数组 nums，将数组中的元素向右轮转 k个位置，其中 k是非负数。

示例 1:

输入: nums = [1,2,3,4,5,6,7], k = 3
输出: [5,6,7,1,2,3,4]
解释:
向右轮转 1 步: [7,1,2,3,4,5,6]
向右轮转 2 步: [6,7,1,2,3,4,5]
向右轮转 3 步: [5,6,7,1,2,3,4]

示例 2:

输入：nums = [-1,-100,3,99], k = 2
输出：[3,99,-1,-100]
解释:
向右轮转 1 步: [99,-1,-100,3]
向右轮转 2 步: [3,99,-1,-100]

提示：

  • 1 <= nums.length <= 105
  • -231 <= nums[i] <= 231 - 1
  • 0 <= k <= 105

进阶：

  • 尽可能想出更多的解决方案，至少有 三种 不同的方法可以解决这个问题。
  • 你可以使用空间复杂度为 O(1) 的 原地算法解决这个问题吗？

核心不变量

整体反转后再分别恢复前 k 段和后 n-k 段的顺序。

完整推导

思路推导

  1. 直觉与痛点（额外数组）：

    最简单的办法是开辟一个同样大小的新数组，把原数组的每个元素放到 (i + k) % n 的新位置上，最后再把新数组复制回原数组。

    痛点：空间复杂度是 O(N)，不够优雅，面试官会让你优化。

  2. 破局思路（三次局部翻转）：

    向右轮转 k 个位置，本质上就是把数组最后面的 k 个元素，整体搬到数组的最前面，同时保持它们内部的相对顺序不变。

    如何不开辟新空间做到这一点？

    • 第一步：把整个数组全部翻转。这时候，原本在最后的 k 个元素就跑到了最前面，但是它们内部的顺序颠倒了。
    • 第二步：把前面那 k 个元素再翻转一次。这样它们的顺序就恢复正常了！
    • 第三步：把剩下后面的 n - k 个元素也翻转一次。它们的顺序也恢复正常了！

  3. 逻辑推演（以 nums = [1,2,3,4,5,6,7], k = 3 为例）：

    • 目标：把最后的 [5, 6, 7] 挪到最前面，变成 [5, 6, 7, 1, 2, 3, 4]。
    • 原数组：[1, 2, 3, 4, 5, 6, 7]
    • 第一翻（整体翻转）：[7, 6, 5, 4, 3, 2, 1]。此时前 3 个数 7, 6, 5 已经在前面了，但顺序反了。
    • 第二翻（翻转前 3 个）：[5, 6, 7, 4, 3, 2, 1]。前 3 个搞定了。
    • 第三翻（翻转后 4 个）：[5, 6, 7, 1, 2, 3, 4]。大功告成！

    Java 实现

class Solution {
    public void rotate(int[] nums, int k) {
        int n = nums.length;
        // 1. 致命细节：如果 k 大于数组长度，相当于多转了几圈，直接取模
        k = k % n;

        // 如果数组只有一个元素，或者根本不需要转，直接返回
        if (k == 0 || n <= 1) return;

        // 2. 第一步：翻转整个数组
        reverse(nums, 0, n - 1);

        // 3. 第二步：翻转前半部分（前 k 个元素）
        reverse(nums, 0, k - 1);

        // 4. 第三步：翻转后半部分（剩下的 n-k 个元素）
        reverse(nums, k, n - 1);
    }

    // 辅助方法：原地翻转数组指定区间 [start, end] 的元素
    private void reverse(int[] nums, int start, int end) {
        while (start < end) {
            // 前后双指针交换
            int temp = nums[start];
            nums[start] = nums[end];
            nums[end] = temp;
            start++;
            end--;
        }
    }
}

复杂度

  • 时间复杂度：O(N)。所有元素加起来正好被遍历（翻转）了两次。第一次是整体翻转 O(N)，第二次是两段局部翻转合计也是 O(N)。总共 O(2N) 即 O(N)。
  • 空间复杂度：O(1)。我们仅仅用了一个额外的变量 temp 在原数组上进行元素交换，完美达到进阶要求。
易错点与扩展

  1. 必考坑点：为什么要写 k = k % n？ - 假设数组长度 n = 7，让你转 k = 10 步。其实转一圈（7步）后数组就恢复原样了，剩下的 3 步才是真正有效的。如果你不取模，直接传 k = 10 进去翻转，reverse(nums, 0, k - 1) 这里的 k-1 就会越界抛出 ArrayIndexOutOfBoundsException！

  2. 是否有其他 O(1) 空间解法？ - 有，叫“环状替换法”。每个元素直接跳到目标位置 (i+k)%n，把那个位置原本的数挤出来，再继续跳。但这需要处理“循环成环”的情况（当 n 和 k 有最大公约数时，会陷入死循环，需要通过外层遍历或者计算最大公约数来解）。代码极易写错，面试强烈不推荐。这道题写“三次翻转”就是性价比最高的标准答案。

class Solution {
public:
    void rotate(vector<int>& nums, int k) {
        k = k % nums.size();
        reverse(nums.begin(), nums.end());
        reverse(nums.begin(), nums.begin() + k);
        reverse(nums.begin() + k, nums.end());

Python 实现

实现来源：代码随想录（programmercarl.com）

class Solution:
    def rotate(self, A: List[int], k: int) -> None:
        def reverse(i, j):
            while i < j:
                A[i], A[j] = A[j], A[i]
                i += 1
                j -= 1
        n = len(A)
        k %= n
        reverse(0, n - 1)
        reverse(0, k - 1)
        reverse(k, n - 1)

Go 实现

实现来源：代码随想录（programmercarl.com）

func rotate(nums []int, k int)  {
    l:=len(nums)
    index:=l-k%l
    reverse(nums)
    reverse(nums[:l-index])
    reverse(nums[l-index:])
}
func reverse(nums []int){
    l:=len(nums)
    for i:=0;i<l/2;i++{
        nums[i],nums[l-1-i]=nums[l-1-i],nums[i]
    }
}
