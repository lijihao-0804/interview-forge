### 📝 算法笔记：1. 两数之和 (Two Sum)

------

- **📌 核心题意**：

  给定一个整数数组 `nums` 和一个整数目标值 `target`，请你在该数组中找出 **和为目标值***`target`*  的那 **两个** 整数，并返回它们的数组下标。

  你可以假设每种输入只会对应一个答案，并且你不能使用两次相同的元素。

  你可以按任意顺序返回答案。

  **示例 1：**

  **输入：**nums = [2,7,11,15], target = 9
  **输出：**[0,1]
  **解释：**因为 nums[0] + nums[1] == 9 ，返回 [0, 1] 。

  **示例 2：**

  **输入：**nums = [3,2,4], target = 6
  **输出：**[1,2]

  **示例 3：**

  **输入：**nums = [3,3], target = 6
  **输出：**[0,1]

  **提示：**

  - `2 <= nums.length <= 104`
  - `-109 <= nums[i] <= 109`
  - `-109 <= target <= 109`
  - **只会存在一个有效答案**

  **进阶：**你可以想出一个时间复杂度小于 `O(n2)` 的算法吗？

- **🧠 思考过程**：

  1. **直觉与痛点（暴力解法）**：

     第一反应是用两个嵌套的 `for` 循环遍历所有的数字对，看看哪对加起来等于 `target`。

     **痛点**：找数字太慢了！假设当前数字是 $x$，我们需要在剩下的数组里找是否存在 `target - x`。数组的线性查找时间是 $O(N)$，导致总时间复杂度高达 $O(N^2)$。当数组很大时，直接超时。

  2. **破局思路（引入哈希表）**：

     我们需要一个能瞬间（$O(1)$ 时间）告诉我们“某个数字存不存在，以及它在哪”的数据结构。**哈希表（HashMap）\**就是完美选择。 \*\*核心思想\*\*：与其先全部存起来再找，不如\**“边遍历，边查找，边记录”**。

  3. **逻辑推演（以 `nums = [2, 7, 11, 15]`, `target = 9` 为例）**：

     我们准备一个空的哈希表 `Map<数值, 对应下标>`。

     - **来到索引 `0`**，数字是 `2`。我们想要凑齐 `9`，所以到处找 `7` (即 `9 - 2`)。看一眼哈希表，空的，没找到 `7`。那就把自己的信息登记一下：存入 `Map: {2: 0}`。
     - **来到索引 `1`**，数字是 `7`。我们想要凑齐 `9`，所以到处找 `2` (即 `9 - 7`)。看一眼哈希表，**发现哈希表里正好有 `2`**，而且它在索引 `0`！
     - 匹配成功，直接返回结果 `[0, 1]`。

- **🛠️ Java 规范代码**：

```java
import java.util.HashMap;
import java.util.Map;

class Solution {
    public int[] twoSum(int[] nums, int target) {
        // 定义哈希表：Key 存数组中的数字，Value 存数字对应的下标
        // 为什么要把数字做 Key？因为我们要根据数值去快速查找下标！
        Map<Integer, Integer> map = new HashMap<>();
        
        for (int i = 0; i < nums.length; i++) {
            // 计算当前数字的“配对者”应该是多少
            int complement = target - nums[i];
            
            // 如果哈希表里已经有这个“配对者”了，说明我们找到了答案
            if (map.containsKey(complement)) {
                // 返回配对者的下标，以及当前数字的下标
                return new int[] { map.get(complement), i };
            }
            
            // 如果没找到，就把当前数字和它的下标存入哈希表，供后面的数字查找
            map.put(nums[i], i);
        }
        
        // 如果找不到匹配的（虽然题目说一定有解，但为了保证编译通过，需要有默认返回值）
        throw new IllegalArgumentException("No two sum solution");
    }
}
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：$O(N)$。我们只把数组遍历了一遍。在哈希表中查询（`containsKey`）和插入（`put`）的时间复杂度平均都是 $O(1)$。所以总共是 $N \times O(1) = O(N)$。
  - **空间复杂度**：$O(N)$。我们开辟了一个哈希表，最坏的情况下（比如答案在数组的最后两个），我们需要把前面的 $N-1$ 个数字全存入哈希表。

------

#### 💡 面试避坑与考点拓展

1. **避坑：为什么不“先用一个 for 循环把所有元素存入 Map，再用一个 for 循环去查”？（两遍哈希）**
   - **缺点 1**：效率略低，必须要遍历两次数组。
   - **缺点 2（致命）**：题目规定“同一个元素不能使用两遍”。如果 `target = 6`，数组是 `[3, 2, 4]`，两遍哈希在查 `3` 的时候，会在 Map 里发现 `3`，从而错误地返回 `[0, 0]`。
   - **我们的做法（一遍哈希）完美避开了这个问题**：因为每次我们都是先查 `complement`，查不到才把当前的数放进去。这保证了匹配到的数一定是在当前数**之前**出现的数，绝对不会自己匹配到自己。
2. **高频追问：如果给定的是一个「已经排好序」的数组，你还会用哈希表吗？**
   - **标准回答**：不会。如果数组已经有序（例如 LeetCode 167 题），我会使用**双指针（头尾指针）**。一个指针指向开头，一个指向结尾，根据两数之和与 target 的大小关系来向中间收缩。双指针解法的空间复杂度只有 **$O(1)$**，比哈希表的 $O(N)$ 空间更优。

------

这篇笔记的核心在于理解**为什么哈希表的 Key 必须是数字的值，而不是数组下标**——因为我们是“顺藤摸瓜”，我们拿着想要的数值去找位置。

### 📝 算法笔记：49. 字母异位词分组 (Group Anagrams)

------

- **📌 核心题意**：

  给你一个字符串数组，请你将 字母异位词 组合在一起。可以按任意顺序返回结果列表。

  **示例 1:**

  **输入:** strs = ["eat", "tea", "tan", "ate", "nat", "bat"]
  **输出:**[["bat"],["nat","tan"],["ate","eat","tea"]]
  **解释：**

  在 strs 中没有字符串可以通过重新排列来形成 `"bat"`。
  字符串 `"nat"` 和 `"tan"` 是字母异位词，因为它们可以重新排列以形成彼此。
  字符串 `"ate"` ，`"eat"` 和 `"tea"` 是字母异位词，因为它们可以重新排列以形成彼此。

  **示例 2:**

  **输入:** strs = [""]
  **输出:**[[""]]

  **示例 3:**

  **输入:** strs = ["a"]
  **输出:**[["a"]]

  **提示：**

  - `1 <= strs.length <= 104`
  - `0 <= strs[i].length <= 100`
  - `strs[i]` 仅包含小写字母

- **🧠 思考过程**：

  1. **直觉与痛点**：字母异位词就像同一副扑克牌的不同洗牌顺序。难点在于，面对两个长相不同的单词（如 `eat` 和 `tea`），如何快速让计算机知道它们是“同类”？

  2. **破局思路**：引入 **哈希表 (HashMap)**，并为每一类单词提取统一的 **“防伪特征码”（Signature）** 作为 Key。最简单的方法是**排序**：无论字母原本怎么排列，只要按字典序重新排序，异位词最终的长相绝对一模一样（都会变成 `aet`）。

  3. **逻辑推演**：

     - 遍历单词数组，拿到 `eat`。
     - 将其打散为字符并排序：`e,a,t` $\rightarrow$ `a,e,t`。
     - 将 `aet` 作为键（Key），去哈希表里找对应的抽屉（List）。
     - 把原单词 `eat` 扔进这个抽屉。
     - 最后把哈希表里所有的抽屉全倒出来，就是最终的分组结果。

     ### 💡 1. 核心直觉 (Core Intuition)

     **一句话破局**：字母异位词就像是同一组扑克牌的不同洗牌顺序。无论怎么洗，牌的组成是不变的。我们要做的，就是**为它们提取出一个统一的“防伪特征码”（Signature）作为哈希表的键（Key），把拥有相同特征码的单词扔进同一个数组（Value）里。**

     提取特征码最直观的方法就是**排序**。既然字母异位词包含的字母完全一样，那么只要把它们按字典序重新排队，长相就绝对一模一样了。

     ------

     ### 🧠 2. 逻辑推演 (Visualization)

     假设输入数组为：`["eat", "tea", "tan", "ate", "nat", "bat"]`

     我们准备一个空的哈希表 `Map`，然后开始流水线作业：

     1. 拿到 `"eat"` $\rightarrow$ 字符排序变成 `"aet"` $\rightarrow$ 哈希表里没有 `"aet"`，开个新抽屉 $\rightarrow$ `{"aet": ["eat"]}`
     2. 拿到 `"tea"` $\rightarrow$ 字符排序变成 `"aet"` $\rightarrow$ 发现 `"aet"` 抽屉已存在，直接塞进去 $\rightarrow$ `{"aet": ["eat", "tea"]}`
     3. 拿到 `"tan"` $\rightarrow$ 字符排序变成 `"ant"` $\rightarrow$ 开新抽屉 $\rightarrow$ `{"ant": ["tan"]}`
     4. 拿到 `"ate"` $\rightarrow$ 排序为 `"aet"` $\rightarrow$ 塞入对应抽屉 $\rightarrow$ `{"aet": ["eat", "tea", "ate"]}`
     5. 拿到 `"nat"` $\rightarrow$ 排序为 `"ant"` $\rightarrow$ 塞入对应抽屉 $\rightarrow$ `{"ant": ["tan", "nat"]}`
     6. 拿到 `"bat"` $\rightarrow$ 排序为 `"abt"` $\rightarrow$ 开新抽屉 $\rightarrow$ `{"abt": ["bat"]}`

     **最后一步**：把哈希表里所有的抽屉（Values）整个倒出来，就是我们要的结果。

- **🛠️ Java 规范代码**：

```java
import java.util.*;

class Solution {
    public List<List<String>> groupAnagrams(String[] strs) {
        // 定义哈希表：Key 是排序后的特征字符串，Value 是属于该特征的原单词列表
        Map<String, List<String>> map = new HashMap<>();
        
        for (String s : strs) {
            // 1. 将字符串打散成字符数组并排序
            char[] chars = s.toCharArray();
            Arrays.sort(chars);
            
            // 2. 将排序后的字符重新组合成字符串，作为哈希表的 Key
            String key = new String(chars);
            
            // 3. 核心 API：查找 Key，若不存在则新建 ArrayList 并放入 Map，最后将原单词追加到 List 中
            map.computeIfAbsent(key, k -> new ArrayList<>()).add(s);
        }
        
        // 4. 将 Map 中所有的 Value（即一个个的 List）提取出来放入总 List 返回
        return new ArrayList<>(map.values());
    }
}
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：$O(N \cdot K \log K)$。其中 $N$ 是单词的数量，$K$ 是最长单词的长度。遍历数组需要 $O(N)$，每次遍历内部需要对字符串进行排序 $O(K \log K)$。
  - **空间复杂度**：$O(N \cdot K)$。哈希表需要存储所有的字符串数据。

------

#### 🙋 我的疑问点：深度拆解 `computeIfAbsent`

- **疑问**：`map.computeIfAbsent(key, k -> new ArrayList<>()).add(s);` 这句代码到底是怎么运作的？
- **解答**：这是 Java 8 的核心 API，用于替代过去冗长的 `if-else` 判空逻辑。它分为三个连贯的动作：
  1. **查找**：`computeIfAbsent` 去哈希表里找当前的 `key`。
  2. **生成与存入（缺席时触发）**：如果 `key` **不存在**，它会执行 Lambda 表达式 `k -> new ArrayList<>()`，现场造一个空的 ArrayList。**关键点**：它不仅造出来，还会自动把这个 `<key, 空List>` 存进 Map 里，然后把这个 List 返回给你。
  3. **追加**：拿到返回的 List 引用后，直接调用 `.add(s)` 将单词放入。全程最多只查一次哈希表，效率极高。

------

#### 💡 面试避坑与考点拓展（可能会被追问）

1. **API 踩坑：不能用 `getOrDefault` 替代**

   - **错误写法**：`map.getOrDefault(key, new ArrayList<>()).add(s);`
   - **原因**：`getOrDefault` 虽然也能在 Key 不存在时给你一个空 List，**但它不会把这个新 List 存回哈希表里**！你的数据加进去就丢失了，原 Map 不受任何影响。必须用 `computeIfAbsent`。

2. **性能优化：如何将时间复杂度降到 $O(N \cdot K)$？（高频追问）**

   - **思路**：如果字符串极长，排序 $O(K \log K)$ 会成为瓶颈。既然题目说明只包含小写字母，可以抛弃排序，改用**计数法**。
   - **做法**：新建一个长度为 26 的 `int[]` 数组，统计单词中 `a-z` 出现的频次。然后将这个频次数组转换为字符串（例如 `1#0#2#...`）作为 Key。统计频次只需 $O(K)$，整体时间复杂度降为 $O(N \cdot K)$。

   这道题是哈希表进阶的绝对经典！它在面试中出现频率极高，因为它考察了一个非常核心的思维：**如何利用哈希表将看似必须 $O(N \log N)$ 的时间复杂度硬生生降到 $O(N)$。**

   ### 📝 算法笔记：128. 最长连续序列 (Longest Consecutive Sequence)

   ------

- **📌 核心题意**：

  给定一个未排序的整数数组 `nums` ，找出数字连续的最长序列（不要求序列元素在原数组中连续）的长度。

  请你设计并实现时间复杂度为 `O(n)`的算法解决此问题。

  **示例 1：**

  **输入：**nums = [100,4,200,1,3,2]
  **输出：**4
  **解释：**最长数字连续序列是 [1, 2, 3, 4]。它的长度为 4。

  **示例 2：**

  **输入：**nums = [0,3,7,2,5,8,4,6,0,1]
  **输出：**9

  **示例 3：**

  **输入：**nums = [1,0,1,2]
  **输出：**3

  **提示：**

  - `0 <= nums.length <= 105`
  - `-109 <= nums[i] <= 109`
