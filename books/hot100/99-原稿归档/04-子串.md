### 📝 算法笔记：560. 和为 K 的子数组 (Subarray Sum Equals K)

------

- **📌 核心题意**：

  给你一个整数数组 `nums` 和一个整数 `k` ，请你统计并返回 *该数组中和为 `k`的子数组的个数*。

  子数组是数组中元素的连续非空序列。

  **示例 1：**

  **输入：**nums = [1,1,1], k = 2
  **输出：**2

  **示例 2：**

  **输入：**nums = [1,2,3], k = 3
  **输出：**2

  **提示：**

  - `1 <= nums.length <= 2 * 104`
  - `-1000 <= nums[i] <= 1000`
  - `-107 <= k <= 107`

- **🧠 思考过程**：

  1. **直觉与痛点（暴力枚举）**：

     枚举所有的子数组起点 $i$ 和终点 $j$，计算它们之间元素的总和。

     **痛点**：即便使用前缀和预处理，枚举所有组合也需要 $O(N^2)$。如果数组长度是 $10^5$，计算量会达到 100 亿次，绝对超时。

  2. **破局思路（前缀和的逆向思维）**：

     设 $PreSum[i]$ 是数组前 $i$ 个元素的和。

     那么，子数组 $[j, i]$ 的和可以表示为：$Sum(j, i) = PreSum[i] - PreSum[j-1]$。

     我们要找的是 $Sum(j, i) = k$，等价于寻找满足条件的索引 $j$：

     $$PreSum[i] - PreSum[j-1] = k \implies PreSum[j-1] = PreSum[i] - k$$

     **结论**：当我们遍历到位置 $i$ 时，我们只需要知道：**在此之前，有多少个前缀和等于 $PreSum[i] - k$。**

  3. **哈希表加速**：

     我们可以维护一个哈希表 `Map<前缀和的值, 该值出现的次数>`。

     遍历数组时，一边计算当前的前缀和，一边去 Map 里查 `target = currSum - k` 出现了几次。

- **🛠️ Java 规范代码**：

```java
import java.util.HashMap;
import java.util.Map;

class Solution {
    public int subarraySum(int[] nums, int k) {
        // 1. 定义哈希表：Key 为前缀和的值，Value 为该前缀和出现的频次
        Map<Integer, Integer> preSumMap = new HashMap<>();
        
        // 2. 极其重要：初始化，表示前缀和为 0 已经出现了 1 次（处理从索引 0 开始就等于 k 的情况）
        preSumMap.put(0, 1);
        
        int count = 0;   // 结果计数器
        int currSum = 0; // 当前累加的前缀和
        
        for (int num : nums) {
            // 计算当前前缀和
            currSum += num;
            
            // 3. 核心查找逻辑：
            // 我们在找是否有之前的 PreSum 等于 (currSum - k)
            if (preSumMap.containsKey(currSum - k)) {
                // 如果有，说明这两个前缀和之间的那段子数组之和正好是 k
                // 加上它出现的频次
                count += preSumMap.get(currSum - k);
            }
            
            // 4. 将当前前缀和存入（或更新）Map，供后续元素查找
            preSumMap.put(currSum, preSumMap.getOrDefault(currSum, 0) + 1);
        }
        
        return count;
    }
}
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：$O(N)$。只需遍历一次数组，Map 的操作均为 $O(1)$。
  - **空间复杂度**：$O(N)$。哈希表最坏情况下会存储 $N$ 个不同的前缀和。

------

#### 💡 面试避坑与考点拓展（灵魂考点）

1. **为什么一定要 `map.put(0, 1)`？**
   - **原因**：如果数组第一个数正好就是 $k$，此时 `currSum = k`。计算 `currSum - k` 得到 $0$。如果不预存 `(0, 1)`，我们就无法发现这个“从头开始且长度为 1”的合法子数组。这本质上是处理**边界情况**。
2. **这道题能用滑动窗口吗？**
   - **致命坑点**：**不能！**（除非题目说明数组全是正数）。
   - **解析**：滑动窗口的核心在于“单调性”。如果数组里有负数，窗口右移时和可能变小，窗口左移时和可能变大。这种不确定性会导致窗口无法正确收缩。因此，**有负数且求和问题，首选前缀和 + 哈希表**。

### 📝 算法笔记：239. 滑动窗口最大值 (Sliding Window Maximum)

------

- **📌 核心题意**：

  给你一个整数数组 `nums`，有一个大小为 `k`的滑动窗口从数组的最左侧移动到数组的最右侧。你只可以看到在滑动窗口内的 `k` 个数字。滑动窗口每次只向右移动一位。

  返回 *滑动窗口中的最大值*。

  **示例 1：**

  **输入：**nums = [1,3,-1,-3,5,3,6,7], k = 3
  **输出：**[3,3,5,5,6,7]
  **解释：**
  滑动窗口的位置                最大值
  ---------------               -----
  [1  3  -1] -3  5  3  6  7       **3**
   1 [3  -1  -3] 5  3  6  7       **3**
   1  3 [-1  -3  5] 3  6  7      **5**
   1  3  -1 [-3  5  3] 6  7       **5**
   1  3  -1  -3 [5  3  6] 7       **6**
   1  3  -1  -3  5 [3  6  7]      **7**

  **示例 2：**

  **输入：**nums = [1], k = 1
  **输出：**[1]

  **提示：**

  - `1 <= nums.length <= 105`
  - `-104 <= nums[i] <= 104`
  - `1 <= k <= nums.length`

- **🧠 思考过程**：

  1. **直觉与痛点（大根堆）**：

     想找最值，第一反应是优先队列（堆）。

     **痛点**：Java 的 `PriorityQueue` 移除特定元素的时间复杂度是 $O(k)$，导致总复杂度退化为 $O(n \cdot k)$。即使配合延迟删除，复杂度也是 $O(n \log n)$。而题目要求 $O(n)$。

  2. **破局思路（单调队列）**：

     我们需要一个队列，它能随着窗口滑动：

     - **入队**：新元素进来时，把前面所有**比它小**的元素全部踢走。
     - **原因**：如果 $A$ 比 $B$ 后进来，且 $A$ 还比 $B$ 大，那么只要 $A$ 在窗口里，$B$ 永远不可能成为最大值。$B$ 已经没用了，可以直接“退伍”。
     - **出队**：当窗口移走了某个元素，如果它恰好是队列里的最大值，才将其弹出。
     - **查询**：队列的头部永远存放着当前窗口的最大值。

  3. **逻辑推演**：

     假设窗口大小 $k=3$，数组 `[1, 3, -1, -3, 5, 3]`：

     - `1` 入队：`[1]`
     - `3` 入队：`3` 比 `1` 大，`1` 没用了，踢走。队列：`[3]`
     - `-1` 入队：`-1` 比 `3` 小，留着，万一 `3` 走了，`-1` 可能是老二。队列：`[3, -1]`
     - **此时窗口满 3 个**，最大值是队头 `3`。
     - `-3` 入队：队列：`[3, -1, -3]`。最大值 `3`。
     - `5` 入队：`5` 把前面的 `3, -1, -3` 全踢走。队列：`[5]`。最大值 `5`。

- **🛠️ Java 规范代码**：

```java
import java.util.ArrayDeque;
import java.util.Deque;

class Solution {
    public int[] maxSlidingWindow(int[] nums, int k) {
        if (nums == null || nums.length == 0) return new int[0];
        
        int n = nums.length;
        int[] res = new int[n - k + 1];
        int idx = 0;
        
        // 双端队列，存储的是元素的【下标】而非数值
        // 存储下标是为了方便判断队头元素是否已经超出了窗口范围
        Deque<Integer> deque = new ArrayDeque<>();
        
        for (int i = 0; i < n; i++) {
            // 1. 入队准备：如果新来的数比队尾的大，队尾的数永远没机会出头了，弹出
            while (!deque.isEmpty() && nums[deque.peekLast()] <= nums[i]) {
                deque.pollLast();
            }
            
            // 2. 入队：存入当前下标
            deque.offerLast(i);
            
            // 3. 维护窗口：如果队头下标已经不在 [i-k+1, i] 范围内了，弹出
            if (deque.peekFirst() == i - k) {
                deque.pollFirst();
            }
            
            // 4. 记录答案：当窗口形成（i >= k-1）时，队头就是当前窗口最大值的下标
            if (i >= k - 1) {
                res[idx++] = nums[deque.peekFirst()];
            }
        }
        
        return res;
    }
}
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：$O(n)$。虽然有 `while` 嵌套，但每个元素最多进队一次、出队一次，总操作数是 $2n$。
  - **空间复杂度**：$O(k)$。双端队列中最多同时存放 $k$ 个元素的下标。

#### 💡 面试避坑与考点拓展

1. **为什么用 `ArrayDeque` 而不用 `LinkedList`？**
   - **回答**：在 Java 中，`ArrayDeque` 是基于循环数组实现的，`LinkedList` 是基于双向链表（对象）实现的。`ArrayDeque` 在作为栈或队列使用时，内存更紧凑，没有频繁的节点对象创建和销毁，性能通常比 `LinkedList` 高出数倍。
2. **单调队列的通用性**：
   - 这是一种固定的套路：**求窗口最值用单调队列，求下一个更大元素（Next Greater Element）用单调栈**。
3. **下标 vs 数值**：
   - 队列里建议存**下标**。因为下标既能让你通过 `nums[i]` 拿到值，又能让你通过 `i - deque.peekFirst() >= k` 判断窗口是否过期。只存数值无法判断是否过期。

------

### 1. LinkedList：链式结构的“长蛇阵”

`LinkedList` 是 Java 中最老牌的集合之一。

- **底层实现**：它是一个**双向链表**。每一个元素都被封装在一个 `Node` 对象中。
- **结构细节**：
  - 每个 `Node` 除了存储数据，还存了两个指针：`prev`（指向前一个节点）和 `next`（指向后一个节点）。
  - 内存分布是**离散**的，节点之间通过地址引用连接。
- **特点**：
  - **插入/删除**：如果在头部或尾部操作，时间复杂度是 $O(1)$。
  - **随机访问**：如果想找第 $i$ 个元素，必须从头（或尾）开始数，时间复杂度是 $O(n)$。
  - **内存开销**：很大。因为每个数据都要额外存两个指针，且频繁地 `new Node` 会给垃圾回收（GC）带来压力。

------

### 2. ArrayDeque：循环数组的“高效环”

`ArrayDeque` 是 Java 1.6 引入的，它是目前 Java 官方**最推荐**的栈和队列实现。

- **底层实现**：它是一个**可变长的循环数组**。
- **结构细节**：
  - 它维护了一个数组和两个索引：`head`（头）和 `tail`（尾）。
  - 当 `tail` 走到数组末尾时，它会绕回到数组开头继续使用（只要开头有空位）。这就是所谓的“循环”。
  - 内存分布是**连续**的。
- **特点**：
  - **插入/删除**：在两端操作的时间复杂度也是均摊 $O(1)$。
  - **内存开销**：很小。它只存数据本身，没有指针开销。
  - **缓存友好**：因为数组是连续内存，CPU 读取速度比链表快得多（计算机组成原理中的 Cache Locality）。
  - **禁忌**：它**不允许存储 null 元素**。

------

### 3. 巅峰对决：我该选哪一个？

在刷力扣（LeetCode）时，我们通常需要一个容器来充当**栈（Stack）\**或\**队列（Queue）**。

| **特性**              | **LinkedList**     | **ArrayDeque**       |
| --------------------- | ------------------ | -------------------- |
| **底层**              | 双向链表           | 循环数组             |
| **作为栈/队列性能**   | 一般（对象创建多） | **极高（数组操作）** |
| **随机访问 (get(i))** | $O(n)$             | 不支持（只能看头尾） |
| **内存占用**          | 较高（节点对象多） | **较低（紧凑数组）** |
| **Null 支持**         | 支持               | **不支持**           |

### 👨‍🏫 老师的总结与建议

在算法面试中，除非题目明确要求你操作链表节点，否则：

1. **如果你需要一个“栈” (Stack)**：
   - **千万不要用** `java.util.Stack` 类（它由于历史原因，带了同步锁，性能极低）。
   - **请使用** `Deque<Integer> stack = new ArrayDeque<>();`。
2. **如果你需要一个“普通队列” (Queue)**：
   - **请使用** `Deque<Integer> queue = new ArrayDeque<>();`。
3. **如果你需要一个“单调队列” (如题目 239)**：
   - **必选** `ArrayDeque`。在高并发或大数据量下，它的速度远超 `LinkedList`。

**为什么 ArrayDeque 速度快这么多？**

简单来说，`LinkedList` 每次添加元素都要在堆内存里 `new` 一个对象，而 `ArrayDeque` 只是在数组里改一个数字。在计算机底层，**操作数组永远比操作对象快得多**。

### 🔑 第一层密码：方向词（First vs Last）

`Deque` 是一根两头通的管子。

- **First（头）**：代表管子的左端（前端）。
- **Last（尾）**：代表管子的右端（后端）。

以你问到的几个方法为例：

1. **`deque.peekFirst()`**：**“偷看”一眼队头元素**。只是看看，不把它拿走。如果队列是空的，它会默默返回一个 `null`，不会报错。
2. **`deque.pollFirst()`**：**“拔出”队头元素**。把最左边的元素拿出来并从队列中删掉。如果队列为空，返回 `null`。
3. **`deque.pollLast()`**：**“拔出”队尾元素**。把最右边的元素拿出来并删掉。如果队列为空，返回 `null`。

*(对应的，当然还有 `peekLast()`，也就是偷看一眼队尾。)*

------

### 🔑 第二层密码：行为词（报错派 vs 佛系派）

这是面试和实战中最容易踩坑的地方！Java 为同一种操作提供了**两套名字**。一套性格暴躁（出错就抛异常抛死你），一套性格佛系（出错就返回特殊值，通常是 null 或 false）。

**强烈建议：在刷力扣时，永远优先使用“佛系派”方法（`offer`, `poll`, `peek`），这样可以避免不小心触发异常导致代码崩溃！**

| **操作类型** | **暴躁派（出错会抛出 Exception）** | **佛系派（出错返回特殊值 null / false） ⭐️推荐** |
| ------------ | ---------------------------------- | ----------------------------------------------- |
| **插入头部** | `addFirst(e)`                      | `offerFirst(e)`                                 |
| **插入尾部** | `addLast(e)`                       | `offerLast(e)`                                  |
| **删除头部** | `removeFirst()`                    | `pollFirst()`                                   |
| **删除尾部** | `removeLast()`                     | `pollLast()`                                    |
| **查看头部** | `getFirst()`                       | `peekFirst()`                                   |
| **查看尾部** | `getLast()`                        | `peekLast()`                                    |

------

### 🔑 第三层密码：角色扮演（化身栈与队列）

`Deque` 之所以被称为“全能王”，是因为它可以完美地**伪装**成“栈（Stack）”或者“普通队列（Queue）”。为了让你写代码时更符合直觉，Java 还为它起了一些“别名”方法。

#### 🎭 场景一：当你要把 Deque 当作“普通队列 (FIFO)”用

普通队列是“排队买票”，队伍尾部进，队伍头部出。

- **入队**：`deque.offer(e)` （其实底层就是调用的 `offerLast`，加到队尾）
- **出队**：`deque.poll()` （其实底层就是调用的 `pollFirst`，从队头拿走）
- **看一眼队头是谁**：`deque.peek()` （其实底层就是调用的 `peekFirst`）

#### 🎭 场景二：当你要把 Deque 当作“栈 (LIFO)”用

栈是“叠盘子”，最后放上去的盘子，最先拿下来。我们规定只在头部（First）进行操作。

- **压栈**：`deque.push(e)` （其实底层就是调用的 `addFirst`，放在最上面）
- **弹栈**：`deque.pop()` （其实底层就是调用的 `removeFirst`，把最上面的拿走）
- *注意：栈的传统方法 `push` 和 `pop` 属于“暴躁派”，如果空栈 `pop` 会报错。所以在安全要求高的场景，我们依然喜欢手动用 `offerFirst` 和 `pollFirst` 来当栈用。*

### 📝 老师的终极记忆卡片（可以直接复制到笔记）

```java
// 1. 初始化
Deque<Integer> deque = new ArrayDeque<>();

// --------------------------------------------------
// 【场景 A：我想用双端队列 / 单调队列（两头都要操作）】
// --------------------------------------------------
deque.offerLast(1);  // 尾部进
deque.pollFirst();   // 头部出
deque.pollLast();    // 尾部出
deque.peekLast();    // 看尾部

// --------------------------------------------------
// 【场景 B：我想把它当纯正的“普通队列”用】
// --------------------------------------------------
deque.offer(2);      // 排队（进尾巴）
deque.poll();        // 叫号（出头部）
deque.peek();        // 看一眼谁排在最前面

// --------------------------------------------------
// 【场景 C：我想把它当纯正的“栈”用】
// --------------------------------------------------
deque.push(3);       // 压入（放头上）
deque.pop();         // 弹出（拿头上，如果空会报错!）
// 替代方案（更安全）：
deque.offerFirst(3); // 安全压栈
deque.pollFirst();   // 安全弹栈
```

在刚才那道“滑动窗口最大值”（239题）中，为什么我们用到了 `pollLast` 和 `pollFirst`？

- 因为当新的大数字进来时，我们要把前面所有没用的小数字从**尾部**踢掉，所以用了 `pollLast()`。
- 当窗口划过，把最左边的过期数字丢掉时，我们要从**头部**踢掉它，所以用了 `pollFirst()`。

这套 API 体系清楚了吗？只要记住“offer / poll / peek 佛系三剑客”**加上**“First / Last 方向词”，你就能在面试中写出极其稳健的代码！

### 📝 算法笔记：76. 最小覆盖子串 (Minimum Window Substring)

------

- **📌 核心题意**：

  给定两个字符串 `s` 和 `t`，长度分别是 `m` 和 `n`，返回 s 中的 **最短窗口 子串**，使得该子串包含 `t` 中的每一个字符（**包括重复字符**）。如果没有这样的子串，返回空字符串`""`。

  测试用例保证答案唯一。

  **示例 1：**

  **输入：**s = "ADOBECODEBANC", t = "ABC"
  **输出：**"BANC"
  **解释：**最小覆盖子串 "BANC" 包含来自字符串 t 的 'A'、'B' 和 'C'。

  **示例 2：**

  **输入：**s = "a", t = "a"
  **输出：**"a"
  **解释：**整个字符串 s 是最小覆盖子串。

  **示例 3:**

  **输入:** s = "a", t = "aa"
  **输出:** ""
  **解释:** t 中两个字符 'a' 均应包含在 s 的子串中，
  因此没有符合条件的子字符串，返回空字符串。

  **提示：**

  - `m == s.length`
  - `n == t.length`
  - `1 <= m, n <= 105`
  - `s` 和 `t` 由英文字母组成

  **进阶：**

  `O(m + n)`

- **🧠 思考过程**：

  1. **直觉与痛点**：

     暴力法是枚举 `s` 的所有子串，然后逐个检查是否包含了 `t` 的所有字符。时间复杂度高达 $O(N^3)$。

  2. **破局思路（双端哈希表 + 滑动窗口）**：

     我们需要两个哈希表（或频次数组）：

     - `need`：记录字符串 `t` 中每个字符需要的数量（目标值）。
     - `window`：记录当前滑动窗口中这些目标字符的数量（当前值）。
     - **灵魂变量 `valid`**：记录窗口中**已经满足要求的字符种类数**。比如 `t="AABC"`，一共有 3 种字符。当窗口里的 A>=2, B>=1, C>=1 时，`valid` 就等于 3。

  3. **逻辑推演（扩张与收缩的艺术）**：

     - **第一步（扩张）**：不断增加 `right` 指针，把新字符加入 `window`。如果某个字符的数量达到了 `need` 的要求，`valid++`。
     - **第二步（收缩）**：当 `valid == need.size()` 时，说明我们已经找到了一个合法的覆盖子串！此时，我们先记录下这个子串的长度和位置，然后试图**优化**它。怎么优化？把 `left` 指针往右移，把没用的字符（或者多余的目标字符）踢出去，直到 `valid` 变小（不再合法）。
     - **第三步（循环）**：破坏了合法性后，继续移动 `right` 寻找下一个合法窗口。

- **🛠️ Java 规范代码**：

```java
import java.util.HashMap;
import java.util.Map;

class Solution {
    public String minWindow(String s, String t) {
        // 记录目标字符串 t 中每个字符需要的数量
        Map<Character, Integer> need = new HashMap<>();
        // 记录当前窗口中目标字符的数量
        Map<Character, Integer> window = new HashMap<>();
        
        for (char c : t.toCharArray()) {
            need.put(c, need.getOrDefault(c, 0) + 1);
        }
        
        int left = 0, right = 0;
        int valid = 0; // 记录窗口中满足 need 条件的字符【种类】数量
        
        // 记录最小覆盖子串的起始索引及长度
        int start = 0, minLen = Integer.MAX_VALUE;
        
        while (right < s.length()) {
            // c 是将移入窗口的字符
            char c = s.charAt(right);
            right++; // 右指针主动右移
            
            // 进行窗口内数据的一系列更新
            if (need.containsKey(c)) {
                window.put(c, window.getOrDefault(c, 0) + 1);
                // 注意 Integer 比较要用 equals，如果用 == 可能会因为常量池问题报错
                if (window.get(c).equals(need.get(c))) {
                    valid++;
                }
            }
            
            // 判断左侧窗口是否要收缩（当所有需要的字符种类都达标时）
            while (valid == need.size()) {
                // 在这里更新最小覆盖子串的答案
                if (right - left < minLen) {
                    start = left;
                    minLen = right - left;
                }
                
                // d 是将移出窗口的字符
                char d = s.charAt(left);
                left++; // 左指针被动右移，开始“榨干水分”
                
                // 进行窗口内数据的一系列更新
                if (need.containsKey(d)) {
                    // 如果踢出的字符刚好破坏了某个字符的数量要求
                    if (window.get(d).equals(need.get(d))) {
                        valid--; // 达标的字符种类减少
                    }
                    window.put(d, window.get(d) - 1);
                }
            }
        }
        
        // 返回最小覆盖子串
        return minLen == Integer.MAX_VALUE ? "" : s.substring(start, start + minLen);
    }
}
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：$O(|S| + |T|)$。虽然代码里有两个嵌套的 `while` 循环，但 `left` 和 `right` 指针最多都只把字符串 `s` 遍历了一遍（不会回退），总共 $2|S|$ 步。加上初始化 `need` 表的 $|T|$ 步，总体是线性的。
  - **空间复杂度**：$O(\Sigma)$ 或 $O(1)$。哈希表最多存储字符集大小的键值对（ASCII 为 128），可视作常数空间。

#### 💡 面试避坑与考点拓展（极其重要）

1. **为什么 `window.get(c).equals(need.get(c))` 必须用 `.equals()`？**
   - **连环夺命坑**：很多同学在这里写 `window.get(c) == need.get(c)`。在 Java 中，`Map.get()` 返回的是 `Integer` 对象。Java 对 `-128` 到 `127` 之间的整数做了缓存，用 `==` 没问题；但如果测试用例极大，某个字符出现了 200 次，`200 == 200` 比较的是对象内存地址，结果为 `false`！直接导致死循环或答案错误。必须用 `.equals()` 比较数值。
2. **极致优化（大厂真题）**：
   - 面试官：“用 HashMap 慢了点，能优化吗？”
   - **回答**：因为题目通常只包含英文字母（甚至只是 ASCII 字符），完全可以抛弃 HashMap，用两个 `int[128]` 数组来替代 `need` 和 `window`。不仅避免了对象创建的开销，也避免了 `.equals()` 的装箱拆箱陷阱。

为什么会这么快？

1. **没有装箱拆箱**：`HashMap<Character, Integer>` 每次操作都会产生 `Integer` 对象，带来巨大的内存分配和垃圾回收开销。数组直接操作基本数据类型 `int`。
2. **内存寻址极快**：数组在底层是连续内存，通过 ASCII 码作为下标（`O(1)` 时间）直接访问，没有任何哈希冲突计算。

### 📝 算法笔记：76. 最小覆盖子串 (数组单维度极限优化版)

------

- **📌 核心题意**：

  给定两个字符串 `s` 和 `t`，长度分别是 `m` 和 `n`，返回 s 中的 **最短窗口 子串**，使得该子串包含 `t` 中的每一个字符（**包括重复字符**）。如果没有这样的子串，返回空字符串`""`。

  测试用例保证答案唯一。

  **示例 1：**

  **输入：**s = "ADOBECODEBANC", t = "ABC"
  **输出：**"BANC"
  **解释：**最小覆盖子串 "BANC" 包含来自字符串 t 的 'A'、'B' 和 'C'。

  **示例 2：**

  **输入：**s = "a", t = "a"
  **输出：**"a"
  **解释：**整个字符串 s 是最小覆盖子串。

  **示例 3:**

  **输入:** s = "a", t = "aa"
  **输出:** ""
  **解释:** t 中两个字符 'a' 均应包含在 s 的子串中，
  因此没有符合条件的子字符串，返回空字符串。

  **提示：**

  - `m == s.length`
  - `n == t.length`
  - `1 <= m, n <= 105`
  - `s` 和 `t` 由英文字母组成

  **进阶：**

  `O(m + n)`

- **📌 核心思想（单数组魔法）**：

  题目中说明字符串仅由英文字母组成，而所有大小写英文字母的 ASCII 码都在 0~127 之间。因此，我们只需要一个大小为 128 的整型数组 `int[] hash = new int[128]` 即可。

- **🧠 降维逻辑（资产与欠债）**：

  在这个极致优化的版本中，我们不记录“字符种类数”，而是记录“还缺多少个有效字符 (`count`)”。

  - **初始化**：先遍历 `t`，把需要的字符数量记录在 `hash` 数组中。比如缺 2 个 'A'，`hash['A'] = 2`。此时 `count = t.length()`。
  - **右指针入局（还债）**：`right` 遍历 `s`。遇到任何字符 `c`，我们都让 `hash[c]--`（把它装进窗口）。
    - *关键点*：如果减之前 `hash[c] > 0`，说明这是我们**真正需要的**字符！于是 `count--`（缺的有效字符减少了）。
    - *注*：不需要的字符（或者多余的目标字符）被减去后，`hash[c]` 会变成**负数**，这代表我们在该字符上“产能过剩”了。
  - **左指针出局（丢弃）**：当 `count == 0` 时，说明窗口合法了！开始移动 `left` 试图缩小窗口。每次踢出一个字符 `d`，我们让 `hash[d]++`（把它拿出窗口）。
    - *关键点*：如果加之后 `hash[d] > 0`，说明我们刚刚踢掉了一个**不可或缺**的字符，导致原本足够的库存变得不够了！于是 `count++`（窗口破裂，重新进入扩张阶段）。

- **🛠️ Java 极限规范代码**：

```java
class Solution {
    public String minWindow(String s, String t) {
        // 应对极端情况
        if (s == null || t == null || s.length() < t.length()) {
            return "";
        }

        // 1. 将字符串转为字符数组，避免循环中频繁调用 charAt() 带来的方法栈开销
        char[] sChars = s.toCharArray();
        char[] tChars = t.toCharArray();

        // 2. 初始化大小为 128 的哈希数组，默认全为 0
        int[] hash = new int[128];
        
        // 统计目标字符串 t 中每个字符需要的数量
        for (char c : tChars) {
            hash[c]++;
        }

        int left = 0, right = 0;
        // count 表示：当前窗口“还差多少个”字符才能完全覆盖 t
        int count = tChars.length;
        
        int start = 0, minLen = Integer.MAX_VALUE;

        // 3. 开始滑动窗口
        while (right < sChars.length) {
            char c = sChars[right];
            
            // 如果 hash[c] > 0，说明这个字符是我们真正需要的
            if (hash[c] > 0) {
                count--; // 还差的有效字符数减一
            }
            // 不管需不需要，只要进了窗口，就消耗掉一个配额（不需要的字符会变成负数）
            hash[c]--;
            right++; // 右指针右移

            // 4. 当 count == 0 时，说明当前窗口已经包含了 t 中的所有字符
            while (count == 0) {
                // 尝试更新最小覆盖子串的记录
                if (right - left < minLen) {
                    minLen = right - left;
                    start = left;
                }

                // 准备把左边界踢出窗口
                char d = sChars[left];
                
                // 无论如何，踢出窗口配额就要加回来（负数加向 0 靠拢，0 加变正数）
                hash[d]++;
                
                // 如果加完后 hash[d] > 0，说明这个字符是不可或缺的，被踢出后窗口不再合法了
                if (hash[d] > 0) {
                    count++; // 还差的有效字符数增加，强制退出内部 while，继续向右扩张
                }
                left++; // 左指针右移，完成收缩
            }
        }

        return minLen == Integer.MAX_VALUE ? "" : s.substring(start, start + minLen);
    }
}
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：$O(|S| + |T|)$。转化为 `char[]` 和遍历都只有线性复杂度，且去掉了 `HashMap` 底层的运算，实际运行速度极快。
  - **空间复杂度**：$O(1)$。我们只用了一个固定大小为 128 的 `int` 数组（以及常数个临时变量），无论字符串多长，内存消耗恒定不变。
