### 📝 算法笔记：136. 只出现一次的数字 (Single Number)

-----

- **📌 核心题意**：

  给你一个 **非空** 整数数组 `nums` ，除了某个元素只出现一次以外，其余每个元素均出现两次。找出那个只出现了一次的元素。

  *致命硬性要求*：你必须设计并实现线性时间复杂度（$O(N)$）的算法来解决此问题，且该算法**只使用常量额外空间（$O(1)$）**。

- **🧠 思考过程**：

  1. **直觉与痛点（哈希表的空间陷阱）**：

     绝大多数人的第一直觉是：搞一个 `HashSet`（集合）或者 `HashMap`（字典）。遍历数组，如果集合里没有这个数，就把它放进去；如果集合里已经有了，就把他们俩一起消掉。最后集合里剩下的那个孤儿，就是答案。

     **痛点**：极其完美的时间复杂度 $O(N)$，但致命伤是空间复杂度 $O(N)$！因为在最坏情况下（假设所有成对的数字都在前半段，单独的在最后），集合里会堆积大量的数字，直接违背了题目 $O(1)$ 空间的铁律。

  2. **降维破局（异或 $\oplus$ 的魔法特性）**：

     在二进制的世界里，有一个叫“异或 (XOR)”**的运算符（在绝大多数语言中符号为 `^`）。它的底层逻辑是：“相同为 0，相异为 1”。 基于这个物理特性，异或运算自带了三条仿佛为这道题量身定制的**“黄金天规”：

     - **天规一（归零律）**：任何数和自己异或，结果永远是 0。即 $a \oplus a = 0$。
     - **天规二（恒等律）**：任何数和 0 异或，结果永远是它自己。即 $a \oplus 0 = a$。
     - **天规三（交换律与结合律）**：异或的顺序不影响最终结果。即 $a \oplus b \oplus a = (a \oplus a) \oplus b = 0 \oplus b = b$。

  3. **核心微操（全员大混战）**：

     有了这三条天规，解法简直呼之欲出：

     我们把数组里**所有的数字全部异或在一起**！

     因为异或满足交换律，那些出现了两次的数字，就像是有磁性一样，无论它们隔得多远，在异或的长链中最终都会互相抵消变成 `0`（天规一）。

     最后所有的 `0` 加在一起还是 `0`。而那个唯一出现的落单数字，它和 `0` 异或，依然是它自己（天规二）！

- **🛠️ Java 规范代码（满分极致极简版）**：
```java
class Solution {
    public int singleNumber(int[] nums) {
        // 初始化一个累加器为 0
        int result = 0;
        
        // 遍历数组中的每一个数字
        for (int num : nums) {
            // 🌟 核心高光时刻：将当前数字与 result 进行异或操作
            // 成对的数字会在不断的运算中自我毁灭，只留下那个天选之子
            result ^= num;
        }
        
        return result;
    }
}
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：$O(N)$。仅仅对数组进行了一次单向线性扫描，由于位运算直接在 CPU 寄存器层面执行，它是所有 $O(N)$ 算法里常数时间最小、跑得最快的。
  - **空间复杂度**：$O(1)$。我们仅仅申请了一个 `result` 整型变量，真正的极尽苛刻的内存压榨。

#### 💡 面试避坑与考点拓展（大厂的夺命连环位运算）

1. **大厂进阶追问 1：“如果数组里其他数字都出现了【三次】，只有一个数字出现了一次，怎么找？”（对应力扣 137 题：只出现一次的数字 II）**
   - **满分降维打击（状态机/位计数法）**：这时候直接异或就行不通了（三个相同的数异或会剩下自己，无法归零）。
   - **破局思路**：我们在大脑里建立一个长度为 32 的数组（代表整型的 32 个二进制位）。遍历所有数字，把它们在每一位上的 `1` 加起来。
   - 既然绝大多数数字出现了三次，那么在每一位上，这些 `1` 的总数必定能被 3 整除！如果某一位的 `1` 的总数对 3 取模后余 1，说明那个“唯一落单的数字”在这一位上肯定是 1！把所有模 3 余 1 的位置拼接起来，就是终极答案。
2. **大厂进阶追问 2：“如果数组里有【两个】数字出现了一次，其余都出现了两次，怎么办？”（对应力扣 260 题：只出现一次的数字 III）**
   - **满分抢答（异或分组法）**：我们先把所有数字异或一遍，得到的结果肯定是那两个落单数字的异或值（设为 `mask`）。
   - 既然这两个数字不同，`mask` 肯定不为 0，它的二进制里肯定至少有一位是 `1`。
   - 这个 `1` 是怎么来的？说明在这两个落单数字中，一个在这一位是 1，另一个在这一位是 0！
   - 我们就拿这一位当“照妖镜”，把原数组拆分成两组：这一位是 1 的分一组，是 0 的分一组。这样，两个落单的数字就被完美地分开了！其余成对的数字肯定会被分进同一组然后内部抵消。最后对这两组分别跑一次普通的异或求和，绝杀！

### 📝 算法笔记：169. 多数元素 (Majority Element)

-----

#### 📌 核心题意：

给定一个大小为 `n` 的数组 `nums` ，返回其中的多数元素。多数元素是指在数组中出现次数 **大于** `n / 2` 的元素。

你可以假设数组是非空的，并且给定的数组总是存在多数元素。

#### 🧠 思考过程：

1. **直觉与痛点（哈希表的空间消耗）**：

   绝大多数人的第一反应是开一个 `HashMap`，遍历数组把每个数字出现的次数存起来，谁的次数超过了 `n / 2` 谁就是答案。

   **痛点**：时间复杂度是极好的 $O(N)$，但空间复杂度也是 $O(N)$。面试官紧接着就会问：“你能把空间复杂度降到 $O(1)$ 吗？”

2. **降维破局（排序法的中间真理）**：

   既然这个数字出现的次数**大于一半**，那我们如果把数组排个序，**正中间的那个数字（索引为 `n / 2`）绝对、必定、一定是它！** 就算它全是全数组最小的数，它也能霸占前一半加中间的位置。

   **痛点**：空间复杂度降到了 $O(1)$，但排序的时间复杂度是 $O(N \log N)$，这还不够快。

3. **终极绝杀（摩尔投票法 / 极限一换一）**：

   我们想象整个数组是一片战场，每一个数字代表一个来自不同阵营的士兵。

   因为“多数元素”的数量比**其他所有阵营的士兵总和还要多**。

   那么我们制定一个最惨烈的规则：**不同阵营的士兵相遇，直接同归于尽（极限一换一）！**

   既然你的兵力超过了半数，就算其他所有人全部联合起来打你，一对一消耗到最后，**站在战场上活下来的唯一阵营，必定是你！**

#### 🎮 核心微操（战场的两条铁律）：

我们在代码里只需要维护两个变量：

- `candidate`（当前站在台上的候选阵营）
- `count`（该阵营目前在台上的存活兵力 / 生命值）

遍历数组，依次拉出每一个数字：

1. **如果台上没人了（`count == 0`）**：不管新来的是谁，他直接占领高地，成为新的 `candidate`，并且兵力 `count = 1`。
2. **如果台上有自己人（当前数字 == `candidate`）**：太好了，援军到了！兵力增加 `count++`。
3. **如果台上是敌人（当前数字 != `candidate`）**：直接同归于尽！兵力减少 `count--`。

### 🛠️ Java 规范代码（满分摩尔投票版）
```java
class Solution {
    public int majorityElement(int[] nums) {
        // 候选人阵营
        int candidate = 0;
        // 当前候选人的存活兵力（生命值）
        int count = 0;

        // 士兵依次入场
        for (int num : nums) {
            // 如果台上已经没人了，新来的士兵直接占领阵地
            if (count == 0) {
                candidate = num;
            }
            
            // 🌟 核心战斗逻辑：
            // 如果来的是自己人，兵力 +1；如果来的是敌人，同归于尽（兵力 -1）
            if (num == candidate) {
                count++;
            } else {
                count--;
            }
        }

        // 最终活到最后的，必定是数量超过半数的那个“多数元素”
        return candidate;
    }
}
```

#### ⏱️ 复杂度分析

- **时间复杂度**：$O(N)$。仅仅对数组进行了一次极其流畅的单向遍历，速度拉满。
- **空间复杂度**：$O(1)$。我们仅仅用了 `candidate` 和 `count` 两个变量，直接把空间压榨到了常数级别的物理极限。

#### 💡 面试避坑与考点拓展（大厂的死亡连环追问）

- **大厂追问 1：“题目里假设了『多数元素必定存在』。如果我去掉这个假设，有可能没有任何一个数字超过半数，你这个代码还能直接用吗？”**
  - **满分避坑回答（二次校验）**：绝不能直接用！如果数组是 `[1, 2, 3]`，摩尔投票法最后会随便选出一个幸存者（比如 3），但 3 的数量并没有超过一半。
  - **破局对策**：我们需要再加一次 $O(N)$ 的遍历！摩尔投票法选出来的只是“最有希望的嫌疑人”。选出来之后，我们再扫一遍数组，老老实实地数一下这个嫌疑人到底出现了几次。如果真的超过了 `n / 2`，再返回它；否则返回 -1。
- **大厂终极绝杀：“如果题目要求找出所有出现次数超过 `n / 3` 的元素呢？”（对应力扣 229 题：多数元素 II）**
  - **满分降维打击（双重摩尔投票）**：超过 `n / 3` 的数字，**最多只可能有 2 个**！
  - 我们直接在台上设 **2 个候选人**位置（`candidate1`, `candidate2`）和 **2 个兵力值**（`count1`, `count2`）。
  - 遍历数组：如果是自己人就加对应兵力；如果是完全无关的第三方敌人，**三个阵营一起极限一换一**（即 `count1--` 且 `count2--`）！
  - 最后活下来的最多两个嫌疑人，再二次遍历统计一遍次数即可。这就叫举一反三的架构级思维！

### 📝 算法笔记：75. 颜色分类 (Sort Colors)

-----

- **📌 核心题意**：

  给定一个包含红色、白色和蓝色、共 `n` 个元素的数组 `nums`，**原地**对它们进行排序，使得相同颜色的元素相邻，并按照红色、白色、蓝色顺序排列。

  我们使用整数 `0`、`1` 和 `2` 分别表示红色、白色和蓝色。

  *终极挑战*：你必须仅使用常数空间的一趟扫描算法（$O(N)$ 时间，一次遍历）。

- **🧠 思考过程**：

  1. **直觉与痛点（两趟扫描的平庸）**：

     最简单的做法是计数排序：第一遍数出有多少个 0、1、2；第二遍直接把对应数量的 0、1、2 填进数组。

     **痛点**：这需要遍历数组**两次**。如果这个数组特别大，或者数组里的元素其实是带着巨大属性的复杂对象（不仅仅是数字），重写两次的代价会非常高昂。

  2. **降维破局（三路划分的艺术）**：

     我们要在一趟遍历中完成排序，就必须在数组中动态划定三个“势力范围”。

     我们引入三个指针：

     - **`p0`（0 的边界）**：它指向的位置，是**下一个 `0` 应该待的地方**。
     - **`p2`（2 的边界）**：它指向的位置，是**下一个 `2` 应该待的地方**。
     - **`i`（探索者/游标）**：负责从左到右去前线探路。

  3. **核心微操（遇到不同的敌人，怎么甩？）**：

     当探索者 `i` 遇到不同的数字时，执行不同的策略：

     - **遇到 `1`（白色）**：最省心。`1` 本来就该待在中间，所以 `i` 直接跳过，继续往前走（`i++`）。
     - **遇到 `0`（红色）**：红色的归宿在最左边！我们把 `nums[i]` 和 `nums[p0]` 互换。换完之后，左边的 0 阵营多了一名大将（`p0++`），并且游标也可以安心向前走（`i++`）。
     - **遇到 `2`（蓝色）**：蓝色的归宿在最右边！我们把 `nums[i]` 和 `nums[p2]` 互换。右边的 2 阵营多了一名大将（`p2--`）。
     - **💥 致命陷阱预警**：遇到 2 交换完之后，游标 `i` **绝对不能前进（绝不能 `i++`）**！为什么？因为你从右边 `p2` 换过来的那个数字，`i` 还没看过它呢！它可能是一个刺客（比如换过来一个 `0` 或者另一个 `2`），你必须停在原地，下一轮继续审视它！

- **🛠️ Java 规范代码（满分一次遍历版）**：
```java
class Solution {
    public void sortColors(int[] nums) {
        // p0 指向下一个 0 应该存放的位置
        int p0 = 0;
        // p2 指向下一个 2 应该存放的位置
        int p2 = nums.length - 1;
        // i 是正在遍历的游标
        int i = 0;

        // 🌟 致命细节：循环条件必须是 i <= p2
        // 因为 p2 指向的位置及其右边，已经被确认为全是 2 了
        // 当 i 越过 p2 时，说明所有的未知区域都已探索完毕，战斗结束！
        while (i <= p2) {
            if (nums[i] == 0) {
                // 遇到 0：扔给左边 p0。换过来的肯定是处理过的 1 或者自己，所以 i 可以放心前进
                swap(nums, i, p0);
                p0++;
                i++;
            } else if (nums[i] == 2) {
                // 遇到 2：扔给右边 p2。换过来的数字是未知的！所以 i 必须留在原地继续考察！
                swap(nums, i, p2);
                p2--;
                // 注意这里没有 i++ ！！！
            } else {
                // 遇到 1：完美，直接跳过
                i++;
            }
        }
    }

    // 辅助函数：交换数组元素
    private void swap(int[] nums, int a, int b) {
        int temp = nums[a];
        nums[a] = nums[b];
        nums[b] = temp;
    }
}
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：$O(N)$。游标 `i` 从左向右走，`p2` 从右向左走，每次循环至少有一个指针在收缩。当 `i > p2` 时立即停止，所有的元素严格只会被看一次。
  - **空间复杂度**：$O(1)$。全程只用了 `p0`、`p2`、`i` 三个指针，没有任何额外的数据结构。

#### 💡 面试避坑与考点拓展（大厂的魔鬼细节）

1. **最强高频翻车点：“为什么遇到 `0` 交换后可以 `i++`，遇到 `2` 交换后却不能 `i++`？”**

   - **满分保命大白话**：

     “因为游标 `i` 是从左往右走的！当我们执行 `swap(i, p0)` 时，`p0` 指向的那个元素，**肯定是被游标 `i` 提前扫过并验证过的**。在正确的运行逻辑下，`p0` 那个位置要么是 `0`（它俩重合），要么是已经被跳过的 `1`。把一个无害的 `1` 换到 `i` 的位置上，`i` 当然可以放心前进！”

     “但是！当我们执行 `swap(i, p2)` 时，`p2` 是从右边未知的黑暗区域拉过来的元素。这个新换过来的元素到底是 0、1 还是 2？游标 `i` 根本不知道。如果不留在原地查验它就直接 `i++`，就会把一个可能需要分类的错误元素遗漏在数组中间！”

     （只要你能在面试中极其流利地把这段话说出来，面试官的眼神绝对会充满赞赏。）

2. **大厂进阶追踪：“这个『三路划分』的思想，在著名的排序算法里也用到过，你知道是哪个吗？”**

   - **满分架构级抢答**：这是快速排序（Quick Sort）的极致优化版——三路快排（3-Way Quicksort）的核心思想！
   - 当数组里有大量重复元素时，普通的快排每次只能把一个基准元素（Pivot）放到正确位置，递归效率会退化到 $O(N^2)$。
   - 而引入了 Dijkstra 的三路划分思想后，我们以 Pivot 为准，一次性把数组切分成“小于 Pivot”、“等于 Pivot”、“大于 Pivot”三段。所有等于 Pivot 的元素直接一次性就位，大大减少了递归深度，在处理大量重复数据时，可以说是降维打击级的提速！

### 📝 算法笔记：31. 下一个排列 (Next Permutation)

-----

- **📌 核心题意**：

  整数数组的一个 **排列** 就是将其所有成员以序列或线性顺序排列。

  例如，`[1, 2, 3]` 的下一个排列是 `[1, 3, 2]`。

  给你一个整数数组 `nums` ，请你将数组原地修改为**字典序中下一个更大的排列**。如果不存在下一个更大的排列（即整个数组已经是降序），则将其重排为字典序最小的排列（即升序排列）。

  *终极挑战*：必须 **原地** 修改，只允许使用 $O(1)$ 的额外空间。

- **🧠 思考过程**：

  1. **直觉与痛点（全排列的噩梦）**：

     最暴力的想法是：把所有排列都生成出来，排个序，找当前排列的下一个。

     **痛点**：全排列的时间复杂度是 $O(N!)$（阶乘级），如果数组长度是 20，这辈子也算不完。

  2. **降维破局（尽可能小的变大）**：

     我们要寻找“下一个”排列，这就意味着我们需要把数组变得**比现在大一点点，但又不能太大**。

     怎么才能让它只大一点点呢？

     - **原则 1**：我们应该尽量修改靠右边（低位）的数字，保留靠左边（高位）的数字不动。
     - **原则 2**：我们需要把右边的一个**小数字**和它后面的一个**大数字**交换。

  3. **核心微操（悬崖寻宝四步曲）**：

     假设数组是 `[1, 3, 5, 4, 2]`。我们把数字想象成一座座山峰。

     - **第一步（找悬崖底）**：从右往左扫描，找到第一个**不再递增**的数字。

       `2 -> 4 -> 5` 都是一路走高的。走到 `3` 的时候，突然跌落了（`3 < 5`）。这个 `3`（索引为 `i`）就是我们要替换的“小数”！

     - **第二步（找接班人）**：既然要把 `3` 换掉，换成谁呢？要找一个比 `3` 大，但又是**尽可能小的数**。

       因为 `i` 右边的数字 `[5, 4, 2]` 绝对是**降序**的，所以我们再次从右往左扫，找到第一个比 `3` 大的数字，发现是 `4`（索引为 `j`）。

     - **第三步（完成交接）**：把 `3` 和 `4` 交换。数组变成了 `[1, 4, 5, 3, 2]`。

       现在数字变大了吗？确实变大了（前缀从 `13` 变成了 `14`）。

     - **第四步（完美掉头）**：现在是最小的变大吗？不是！因为交换后的后缀 `[5, 3, 2]` 仍然是降序（极大值）。为了让整个数字尽可能小，我们需要把这个后缀变成升序（极小值）。怎么把降序变成升序？**直接反转（Reverse）即可！**

       后缀反转后变成 `[2, 3, 5]`，最终结果 `[1, 4, 2, 3, 5]`，完美破局！

- **🛠️ Java 规范代码（满分四步法）**：
```java
class Solution {
    public void nextPermutation(int[] nums) {
        if (nums == null || nums.length <= 1) return;
        
        // 1. 从右向左找第一个下降的数字（悬崖底）
        int i = nums.length - 2;
        while (i >= 0 && nums[i] >= nums[i + 1]) {
            i--;
        }
        
        // 如果 i >= 0，说明找到了这个悬崖底；
        // 如果 i < 0，说明整个数组完全是降序的（比如 [3, 2, 1]），它是最大的排列。
        // 对于完全降序，我们跳过第 2 和 3 步，直接进入第 4 步将其全部反转即可。
        if (i >= 0) {
            // 2. 再次从右向左，在 i 的右侧寻找第一个比 nums[i] 大的数字（接班人）
            int j = nums.length - 1;
            while (j >= 0 && nums[j] <= nums[i]) {
                j--;
            }
            
            // 3. 交换这两个数字
            swap(nums, i, j);
        }
        
        // 4. 将 i 之后的全部元素反转（从降序变成升序，达到局部极小值）
        reverse(nums, i + 1, nums.length - 1);
    }
    
    // 辅助函数：交换数组元素
    private void swap(int[] nums, int a, int b) {
        int temp = nums[a];
        nums[a] = nums[b];
        nums[b] = temp;
    }
    
    // 辅助函数：双指针反转指定区间的数组
    private void reverse(int[] nums, int start, int end) {
        while (start < end) {
            swap(nums, start, end);
            start++;
            end--;
        }
    }
}
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：$O(N)$。在最坏情况下，我们只需要对数组进行至多两次单向扫描，外加一次局部反转，这都是极其迅速的线性操作。
  - **空间复杂度**：$O(1)$。我们仅仅用了 `i` 和 `j` 两个整型指针，所有的交换和反转都在原数组上就地（In-place）完成，满足了最苛刻的内存要求。

#### 💡 面试避坑与考点拓展（大厂的死亡细节）

1. **极度高频坑点：“如果有重复元素怎么办？比如 `[1, 1, 5]`，你的代码会死循环或者找错吗？”**
   - **满分保命细节**：绝对不会！请死死盯住第一步的 `nums[i] >= nums[i + 1]` 和第二步的 `nums[j] <= nums[i]`，这里的**等号 `=`** 是这道题的定海神针！
   - 因为有等号的存在，我们在遇到重复元素时会毫不犹豫地继续往左滑。这保证了我们找到的 `i` 一定是严格小于后面的某个数，找到的 `j` 一定是严格大于 `nums[i]` 的数，完美规避了重复元素互相交换导致的无效操作。
2. **大厂追问：“为什么要用 Reverse（反转）而不是 Sort（排序）？”**
   - **架构师级抢答**：这是这道题最闪光的灵魂！因为我们在第一步找 `i` 时，`i` 右边的数字序列一定是一个严格单调递减（或包含相等）的序列！即使在第三步交换了 `i` 和 `j` 之后，由于 `j` 是刚好大于 `i` 的数，换上去之后，整个右侧依然保持着递减的特性。
   - 既然一个序列已经是降序的，把它变成升序还需要调用 $O(K \log K)$ 的 Sort 吗？完全不需要！只需要双指针从两头向中间靠拢，做一次 $O(K)$ 的 Reverse 即可！用 Reverse 代替 Sort，是把时间复杂度降维到 $O(N)$ 的核心之钥。

### 📝 算法笔记：287. 寻找重复数 (Find the Duplicate Number)

-----

- **📌 核心题意**：

  给定一个包含 `n + 1` 个整数的数组 `nums` ，其数字都在 `[1, n]` 范围内（包括 1 和 n）。

  可知至少存在一个重复的整数。假设 `nums` 只有 **一个重复的整数** ，返回这个重复的数。

  *极限约束*：你必须**不修改**数组 `nums` 且只使用 $O(1)$ 的额外空间。

- **🧠 思考过程**：

  1. **直觉与痛点（全军覆没的常规武器）**：

     - **哈希表**：空间复杂度 $O(N)$，违规。
     - **排序后查相邻**：会修改原数组，违规。
     - **原数组标记法（把遍历到的数字对应的索引位置标为负数）**：也会修改原数组，违规。

  2. **降维破局（万物皆可为指针）**：

     题目里有一个极其诡异但绝非偶然的条件：**长度为 `n + 1`，数字范围在 `1` 到 `n`**。

     这意味着：**数组里的每一个值，都完美对应着数组里的一个有效索引！**

     既然如此，我们可以把数组里的“值”，当成指向下一个“索引”的**指针**！

     比如 `nums = [1, 3, 4, 2, 2]`：

     - 站在索引 `0`，值是 `1`。说明下一步要去索引 `1`。
     - 站在索引 `1`，值是 `3`。说明下一步要去索引 `3`。
     - 站在索引 `3`，值是 `2`。说明下一步要去索引 `2`。
     - 站在索引 `2`，值是 `4`。说明下一步要去索引 `4`。
     - 站在索引 `4`，值是 `2`。说明下一步又要去索引 `2`！

     你发现了吗？因为有多个位置的值是**同一个重复数字**（比如例子里的 `2`），所以有多个指针会**共同指向同一个索引**！

     这在图论里意味着什么？**必定会产生环（Cycle）！而产生环的“入口节点”，绝对就是那个重复的数字！**

  3. **核心微操（龟兔赛跑找环入口）**：

     这直接退化成了力扣 142 题（环形链表 II）。我们分为两个阶段：

     - **阶段一（证明有环）**：派出一只乌龟（`slow`）和一只兔子（`fast`）。乌龟每次走一步（`nums[slow]`），兔子每次走两步（`nums[nums[fast]]`）。只要有环，兔子必然在环内某处追上乌龟。
     - **阶段二（寻找入口）**：相遇后，把乌龟拎回起点（`0`），兔子留在相遇点。然后让它俩**每次都只走一步**。当它们再次相遇时，相遇的位置，就是绝对的环入口（也就是我们要找的重复数字）！

- **🛠️ Java 规范代码（满分 Floyd 判圈版）**：

```java
class Solution {
    public int findDuplicate(int[] nums) {
        // 阶段 1：快慢指针出发，寻找相遇点
        // 初始位置设在索引 0 (相当于链表的 head)
        int slow = 0;
        int fast = 0;
        
        // 由于必定有环，使用 do-while 先走一步再判断
        do {
            // 乌龟走一步
            slow = nums[slow];
            // 兔子走两步
            fast = nums[nums[fast]];
        } while (slow != fast); // 直到在环内相遇
        
        // 阶段 2：寻找环的入口
        // 相遇后，将乌龟或者一个新的指针放回起点
        int finder = 0;
        
        // 此时 finder 从起点走，fast 从相遇点走，每次都只走一步
        while (finder != fast) {
            finder = nums[finder];
            fast = nums[fast];
        }
        
        // 再次相遇的地方，就是环的入口，也就是那个重复的数字！
        return finder;
    }
}
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：$O(N)$。快慢指针最多在数组中跑两到三圈即可得出结果，标准的线性时间复杂度。
  - **空间复杂度**：$O(1)$。我们仅仅用了 `slow`、`fast` 和 `finder` 三个整型指针变量，完全遵守了最严苛的内存限制。

#### 💡 面试避坑与考点拓展（大厂的防守反击）

- **大厂面试官追问：“如果面试的时候，你恰好忘记了快慢指针的找环规律，或者一时半会儿没把数组往链表上想，你还有什么能在 $O(1)$ 空间内解题的备用方案吗？”**

  - **满分保命回答（二分查找的降维利用）**：

    “面试官您好，如果在极端情况下忘了图论规律，我会使用**二分查找法**！

    注意，我们不是对数组的索引进行二分，而是对**数值的范围 `[1, n]` 进行二分**！

    假设 `n = 4`，数字范围是 `[1, 4]`。我们取中间值 `mid = 2`。

    我们去原数组里老老实实数一遍，有多少个数字是 $\le 2$ 的？

    根据抽屉原理，如果不存在重复的 `1` 或 `2`，那么 $\le 2$ 的数字最多只会有 2 个。

    如果我们数出来有 3 个甚至更多！说明重复数字一定在 `[1, 2]` 这个区间里；反之，重复数字就在 `[3, 4]` 区间里。

    每次二分缩小一半的数值范围，每次判定都需要遍历一遍数组 $O(N)$。所以整体时间复杂度是 $O(N \log N)$，空间复杂度依然是 $O(1)$，不修改原数组。虽然比快慢指针慢，但逻辑极其无懈可击！”
