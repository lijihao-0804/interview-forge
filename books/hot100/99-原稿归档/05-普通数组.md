### 📝 算法笔记：53. 最大子数组和 (Maximum Subarray)

------

- **📌 核心题意**：

  给你一个整数数组 `nums` ，请你找出一个具有最大和的连续子数组（子数组最少包含一个元素），返回其最大和。

  **子数组**是数组中的一个连续部分。

  **示例 1：**

  **输入：**nums = [-2,1,-3,4,-1,2,1,-5,4]
  **输出：**6
  **解释：**连续子数组 [4,-1,2,1] 的和最大，为 6 。

  **示例 2：**

  **输入：**nums = [1]
  **输出：**1

  **示例 3：**

  **输入：**nums = [5,4,-1,7,8]
  **输出：**23

  **提示：**

  - `1 <= nums.length <= 105`
  - `-104 <= nums[i] <= 104`

  **进阶：**如果你已经实现复杂度为 `O(n)` 的解法，尝试使用更为精妙的 **分治法** 求解。

- **🧠 思考过程**：

  1. **直觉与痛点（暴力枚举）**：

     两层 `for` 循环，枚举所有的起点和终点，计算区间和。时间复杂度 $O(N^2)$，在面对巨大数组时必然超时。

  2. **破局思路（“资产”与“负债”的贪心抉择）**：

     假设我们正从左到右遍历数组，手里攒着一个“当前累加和 (`currentSum`)”。

     每走到一个新的数字面前，我们都面临一个灵魂拷问：**是要把它加入之前的队伍，还是让它自立门户？**

     - **评判标准**：看看我们手里的 `currentSum` 是正数还是负数。
     - 如果 `currentSum > 0`：它是**资产**。带着它，总和会变得更大。所以果断让新数字加入队伍。
     - 如果 `currentSum <= 0`：它是**负债**。带上它只会拖累新数字（哪怕新数字也是负数，加个负债只会更加负）。所以果断**抛弃历史包袱**，让新数字从自己开始“自立门户”。

  3. **逻辑推演（以 `[-2, 1, -3, 4, -1, 2, 1, -5, 4]` 为例）**：

     - `num = -2`：起步，`currentSum = -2`，`maxSum = -2`。
     - `num = 1`：之前的 `currentSum` 是 `-2`（负债），果断抛弃！自立门户，`currentSum` 重新变成 `1`。`maxSum` 更新为 `1`。
     - `num = -3`：之前的 `currentSum` 是 `1`（资产），带着！`currentSum = 1 + (-3) = -2`。`maxSum` 还是 `1`。
     - `num = 4`：之前的 `currentSum` 是 `-2`（负债），抛弃！自立门户，`currentSum` 变成 `4`。`maxSum` 更新为 `4`。
     - `num = -1`：带着（因为 4 是资产）。`currentSum = 3`。
     - `num = 2`：带着。`currentSum = 5`。`maxSum` 更新为 `5`。
     - `num = 1`：带着。`currentSum = 6`。`maxSum` 更新为 `6`。
     - ……以此类推，最终找到最大和 `6`（对应子数组 `[4, -1, 2, 1]`）。

- **🛠️ Java 规范代码**：

```java
class Solution {
    public int maxSubArray(int[] nums) {
        // 如果数组为空，理论上应该抛出异常，但力扣题目保证至少有 1 个元素
        
        // 记录当前的连续子数组和
        int currentSum = 0;
        // 记录全局见过的最大和，初始化为极小值（或直接用 nums[0]）
        int maxSum = Integer.MIN_VALUE;
        
        for (int num : nums) {
            // 核心抉择逻辑：
            // 如果历史累加和 <= 0，说明是“负债”，对后续的求和毫无帮助，直接丢弃，从当前数字重新开始。
            if (currentSum <= 0) {
                currentSum = num;
            } else {
                // 如果历史累加和 > 0，说明是“资产”，加上当前数字继续走。
                currentSum += num;
            }
            
            // 每次抉择完，都尝试去打破历史最高记录
            maxSum = Math.max(maxSum, currentSum);
        }
        
        return maxSum;
    }
}
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：$O(N)$。我们只需要把数组从头到尾遍历一次即可，时间复杂度达到理论最优。
  - **空间复杂度**：$O(1)$。全程只使用了两个变量 `currentSum` 和 `maxSum`，不需要额外开辟数组。

------

#### 💡 面试避坑与考点拓展

1. **代码的极致精简版（动态规划视角）**：

   - 上面的 `if-else` 是贪心思想的体现，如果在动态规划视角下，代码可以精简得连 `if` 都不需要：

     ```java
     int currentSum = 0, maxSum = nums[0];
     for (int x : nums) {
         // 状态转移方程：要么自立门户 (x)，要么加入前驱 (currentSum + x)，取较大者
         currentSum = Math.max(currentSum + x, x);
         maxSum = Math.max(maxSum, currentSum);
     }
     ```

     *这两种写法本质完全一样，但 `if-else` 的“资产/负债”说辞在面试时讲出来更容易让面试官眼前一亮。*

2. **高频追问：“如果我还想知道这个最大子数组的具体起始和结束位置呢？”**

   - **回答思路**：只需要额外维护两个指针 `start` 和 `end`。当 `currentSum <= 0` 决定“自立门户”时，把临时起点 `tempStart` 更新为当前下标 `i`；当 `currentSum > maxSum` 破纪录时，把真正的 `start` 更新为 `tempStart`，把 `end` 更新为当前的下标 `i`。

### 📝 算法笔记：56. 合并区间 (Merge Intervals)

------

- **📌 核心题意**：

  以数组 `intervals` 表示若干个区间的集合，其中单个区间为 `intervals[i] = [starti, endi]` 。请你合并所有重叠的区间，并返回 *一个不重叠的区间数组，该数组需恰好覆盖输入中的所有区间* 。

  **示例 1：**

  **输入：**intervals = [[1,3],[2,6],[8,10],[15,18]]
  **输出：**[[1,6],[8,10],[15,18]]
  **解释：**区间 [1,3] 和 [2,6] 重叠, 将它们合并为 [1,6].

  **示例 2：**

  **输入：**intervals = [[1,4],[4,5]]
  **输出：**[[1,5]]
  **解释：**区间 [1,4] 和 [4,5] 可被视为重叠区间。

  **示例 3：**

  **输入：**intervals = [[4,7],[1,4]]
  **输出：**[[1,7]]
  **解释：**区间 [1,4] 和 [4,7] 可被视为重叠区间。

  **提示：**

  - `1 <= intervals.length <= 104`
  - `intervals[i].length == 2`
  - `0 <= starti <= endi <= 104`

- **🧠 思考过程**：

  1. **直觉与痛点（无序的混乱）**：

     如果区间是乱序的（比如先给你 `[15,18]`，再给你 `[1,3]`，最后给 `[2,6]`），你很难判断当前区间到底要和谁合并，因为能和它合并的区间可能在很后面。每次都要回头找，逻辑极其混乱。

  2. **破局思路（先排序，后贪心）**：

     - **第一步（排序）**：既然乱，我们就给它定个规矩。**将所有区间按照“起点”从小到大排序**。
     - **第二步（贪心合并）**：排序后，所有能合并的区间**一定都是连续挨在一起的**！我们只需要拿一个“当前正在合并的区间（`current`）”，去和下一个区间比对。

  3. **逻辑推演（以 `[[1,3], [2,6], [8,10], [15,18]]` 为例，已排序）**：

     - **准备**：拿第一个区间 `[1, 3]` 作为 `current`，放入结果集。
     - **下一个是 `[2, 6]`**：
       - 判断：它的起点 `2` $\le$ `current` 的终点 `3`，说明有重叠！
       - 合并：起点不用变，终点变成两者终点的最大值 `max(3, 6) = 6`。于是结果集里的 `current` 更新为 `[1, 6]`。
     - **下一个是 `[8, 10]`**：
       - 判断：它的起点 `8` $>$ `current` 的终点 `6`，说明断开了，不可能再重叠了（因为后面的区间起点只会越来越大）。
       - 操作：把 `[8, 10]` 作为新的 `current` 放入结果集。
     - **下一个是 `[15, 18]`**：同理，断开，作为新区间放入。

- **🛠️ Java 规范代码**：

```java
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

class Solution {
    public int[][] merge(int[][] intervals) {
        // 边界条件：如果没有区间，直接返回空
        if (intervals == null || intervals.length == 0) {
            return new int[0][0];
        }
        
        // 1. 灵魂操作：按区间的起点（start）从小到大进行排序
        // 注意：使用 Integer.compare 可以有效防止 a[0] - b[0] 导致的整型溢出风险
        Arrays.sort(intervals, (a, b) -> Integer.compare(a[0], b[0]));
        
        List<int[]> merged = new ArrayList<>();
        
        // 先把排序后的第一个区间放入结果集中，作为“当前合并区间”的初始基准
        merged.add(intervals[0]);
        
        // 2. 从第二个区间开始遍历
        for (int i = 1; i < intervals.length; i++) {
            // 获取当前正在试图扩充的区间（即结果集中的最后一个区间）
            int[] current = merged.get(merged.size() - 1);
            int[] next = intervals[i];
            
            // 3. 核心判断逻辑
            if (next[0] <= current[1]) {
                // 有重叠！更新当前区间的终点为两者的最大值
                // 为什么不更新起点？因为我们已经按起点排过序了，current 的起点一定是最小的
                current[1] = Math.max(current[1], next[1]);
            } else {
                // 没有重叠！说明 current 已经扩充到极限了，将 next 作为新的独立区间加入结果集
                merged.add(next);
            }
        }
        
        // 4. 将 List 转换为二维数组返回
        return merged.toArray(new int[merged.size()][]);
    }
}
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：$O(N \log N)$。遍历区间只需要 $O(N)$ 的时间，但之前的排序步骤需要 $O(N \log N)$。在算法中，取最高阶，因此总时间复杂度为 $O(N \log N)$。
  - **空间复杂度**：$O(\log N)$ 或 $O(N)$。取决于底层排序算法的空间开销（Java 中对象排序通常是 TimSort，基本类型是 Dual-Pivot Quicksort，有递归栈空间）。如果算上用来装结果的 `merged` 列表，最坏情况下不重叠的空间为 $O(N)$。

------

#### 💡 面试避坑与考点拓展（可能会被追问）

1. **踩坑点：`a[0] - b[0]` 的溢出陷阱**
   - 很多人在写自定义比较器时喜欢偷懒写 `(a, b) -> a[0] - b[0]`。
   - **面试官必问**：如果 `a[0]` 是 `-2147483648`，`b[0]` 是 `2147483647` 呢？相减会产生**整数溢出**，导致排序完全错乱！
   - **满分解法**：老老实实写 `Integer.compare(a[0], b[0])`，这是极其专业且严谨的工程体现。
2. **细微逻辑：为什么是取 `max` 而不是直接等于 `next[1]`？**
   - 假设有区间 `[1, 5]` 和 `[2, 3]`。排序后顺序是对的。
   - 当合并时，`2 <= 5` 重叠了。此时终点应该是 `max(5, 3)` 也就是 `5`。`[1, 5]` 完全“吞噬”了 `[2, 3]`。如果直接等于 `next[1]`，终点反而会缩水变成 3。

### 📝 算法笔记：189. 轮转数组 (Rotate Array)

------

- **📌 核心题意**：

  给定一个整数数组 `nums`，将数组中的元素向右轮转 `k`个位置，其中 `k`是非负数。

  **示例 1:**

  **输入:** nums = [1,2,3,4,5,6,7], k = 3
  **输出:** `[5,6,7,1,2,3,4]`
  **解释:**
  向右轮转 1 步: `[7,1,2,3,4,5,6]`
  向右轮转 2 步: `[6,7,1,2,3,4,5]
  `向右轮转 3 步: `[5,6,7,1,2,3,4]`

  **示例 2:**

  **输入：**nums = [-1,-100,3,99], k = 2
  **输出：**[3,99,-1,-100]
  **解释:** 
  向右轮转 1 步: [99,-1,-100,3]
  向右轮转 2 步: [3,99,-1,-100]

  **提示：**

  - `1 <= nums.length <= 105`
  - `-231 <= nums[i] <= 231 - 1`
  - `0 <= k <= 105`

  **进阶：**

  - 尽可能想出更多的解决方案，至少有 **三种** 不同的方法可以解决这个问题。
  - 你可以使用空间复杂度为 `O(1)` 的 **原地**算法解决这个问题吗？

- **🧠 思考过程**：

  1. **直觉与痛点（额外数组）**：

     最简单的办法是开辟一个同样大小的新数组，把原数组的每个元素放到 `(i + k) % n` 的新位置上，最后再把新数组复制回原数组。

     **痛点**：空间复杂度是 $O(N)$，不够优雅，面试官会让你优化。

  2. **破局思路（三次局部翻转）**：

     向右轮转 `k` 个位置，本质上就是**把数组最后面的 `k` 个元素，整体搬到数组的最前面**，同时保持它们内部的相对顺序不变。

     如何不开辟新空间做到这一点？

     - **第一步**：把整个数组**全部翻转**。这时候，原本在最后的 `k` 个元素就跑到了最前面，但是它们内部的顺序颠倒了。
     - **第二步**：把前面那 `k` 个元素再**翻转一次**。这样它们的顺序就恢复正常了！
     - **第三步**：把剩下后面的 `n - k` 个元素也**翻转一次**。它们的顺序也恢复正常了！

  3. **逻辑推演（以 `nums = [1,2,3,4,5,6,7]`, `k = 3` 为例）**：

     - 目标：把最后的 `[5, 6, 7]` 挪到最前面，变成 `[5, 6, 7, 1, 2, 3, 4]`。
     - 原数组：`[1, 2, 3, 4, 5, 6, 7]`
     - **第一翻（整体翻转）**：`[7, 6, 5, 4, 3, 2, 1]`。此时前 3 个数 `7, 6, 5` 已经在前面了，但顺序反了。
     - **第二翻（翻转前 3 个）**：`[5, 6, 7, 4, 3, 2, 1]`。前 3 个搞定了。
     - **第三翻（翻转后 4 个）**：`[5, 6, 7, 1, 2, 3, 4]`。大功告成！

- **🛠️ Java 规范代码**：

```java
class Solution {
    public void rotate(int[] nums, int k) {
        int n = nums.length;
        // 1. 致命细节：如果 k 大于数组长度，相当于多转了几圈，直接取模
        k = k % n; 
        
        // 如果数组只有一个元素，或者根本不需要转，直接返回
        if (k == 0 || n <= 1) return;
        
        // 2. 第一步：翻转整个数组
        reverse(nums, 0, n - 1);
        
        // 3. 第二步：翻转前半部分（前 k 个元素）
        reverse(nums, 0, k - 1);
        
        // 4. 第三步：翻转后半部分（剩下的 n-k 个元素）
        reverse(nums, k, n - 1);
    }
    
    // 辅助方法：原地翻转数组指定区间 [start, end] 的元素
    private void reverse(int[] nums, int start, int end) {
        while (start < end) {
            // 前后双指针交换
            int temp = nums[start];
            nums[start] = nums[end];
            nums[end] = temp;
            start++;
            end--;
        }
    }
}
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：$O(N)$。所有元素加起来正好被遍历（翻转）了两次。第一次是整体翻转 $O(N)$，第二次是两段局部翻转合计也是 $O(N)$。总共 $O(2N)$ 即 $O(N)$。
  - **空间复杂度**：$O(1)$。我们仅仅用了一个额外的变量 `temp` 在原数组上进行元素交换，完美达到进阶要求。

------

#### 💡 面试避坑与考点拓展

1. **必考坑点：为什么要写 `k = k % n`？**
   - 假设数组长度 `n = 7`，让你转 `k = 10` 步。其实转一圈（7步）后数组就恢复原样了，剩下的 3 步才是真正有效的。如果你不取模，直接传 `k = 10` 进去翻转，`reverse(nums, 0, k - 1)` 这里的 `k-1` 就会越界抛出 `ArrayIndexOutOfBoundsException`！
   
2. **是否有其他 $O(1)$ 空间解法？**
   - 有，叫“环状替换法”**。每个元素直接跳到目标位置 `(i+k)%n`，把那个位置原本的数挤出来，再继续跳。但这需要处理“循环成环”的情况（当 $n$ 和 $k$ 有最大公约数时，会陷入死循环，需要通过外层遍历或者计算最大公约数来解）。代码极易写错，面试**强烈不推荐。这道题写“三次翻转”就是性价比最高的标准答案。

### 📝 算法笔记：238. 除自身以外数组的乘积 (Product of Array Except Self)

------

- **📌 核心题意**：

  给你一个整数数组 `nums`，返回 数组 `answer` ，其中 `answer[i]` 等于 `nums` 中除了 `nums[i]` 之外其余各元素的乘积 。

  题目数据 **保证** 数组 `nums`之中任意元素的全部前缀元素和后缀的乘积都在  **32 位** 整数范围内。

  请 **不要使用除法，**且在 `O(n)` 时间复杂度内完成此题。

  **示例 1:**

  **输入:** nums = `[1,2,3,4]`
  **输出:** `[24,12,8,6]`

  **示例 2:**

  **输入:** nums = [-1,1,0,-3,3]
  **输出:** [0,0,9,0,0]

  **提示：**

  - `2 <= nums.length <= 105`
  - `-30 <= nums[i] <= 30`
  - 输入 **保证** 数组 `answer[i]` 在  **32 位** 整数范围内

  **进阶：**你可以在 `O(1)` 的额外空间复杂度内完成这个题目吗？（ 出于对空间复杂度分析的目的，输出数组 **不被视为**额外空间。）

- **🧠 思考过程**：

  1. **直觉与痛点（除法与零的陷阱）**：

     原本最简单的想法是求出所有数字的总乘积，然后遍历数组，对于位置 `i`，答案就是 `总乘积 / nums[i]`。

     **痛点**：首先，题目严禁使用除法；其次，如果数组里包含 `0`，除以 `0` 就会直接报错；如果不止一个 `0`，逻辑会变得极其繁琐。

  2. **破局思路（左右乘积分解法）**：

     既然不能除，那就只能乘。除 `nums[i]` 以外的乘积，其实可以完美地拆分成两部分：

     **`answer[i] = (i 左边所有数字的乘积) × (i 右边所有数字的乘积)`**

     因此，我们只需要计算出每个位置的“左前缀乘积”和“右后缀乘积”，然后两两相乘即可。

  3. **逻辑推演（空间压缩的艺术）**：

     - *常规做法（$O(N)$ 空间）*：开辟两个新数组 `L` 和 `R`。`L[i]` 存 `i` 左边的乘积，`R[i]` 存 `i` 右边的乘积。最后 `answer[i] = L[i] * R[i]`。
     - *终极优化（$O(1)$ 空间）*：题目说明输出数组不计入空间复杂度。我们可以直接把 `answer` 数组当成 `L` 数组来用！
       - **第一遍扫描（从左到右）**：计算左侧乘积，存入 `answer` 中。
       - **第二遍扫描（从右到左）**：用一个动态变化的单个变量 `R` 来维护右侧乘积。一边维护 `R`，一边把它乘到 `answer[i]` 里。

- **🛠️ Java 规范代码**：

```java
class Solution {
    public int[] productExceptSelf(int[] nums) {
        int n = nums.length;
        int[] answer = new int[n];
        
        // 1. 第一遍扫描：计算每个位置【左边】所有数字的乘积
        // 对于下标 0，它的左边没有数字，所以左乘积的初始基准值为 1
        answer[0] = 1;
        for (int i = 1; i < n; i++) {
            // 当前位置的左乘积 = 前一个位置的左乘积 * 前一个位置的数字
            answer[i] = answer[i - 1] * nums[i - 1];
        }
        
        // 2. 第二遍扫描：计算每个位置【右边】所有数字的乘积，并直接与 answer 相乘
        // R 用于实时记录当前位置右边所有数字的乘积，最右边元素的右侧没有数字，基准值为 1
        int R = 1;
        // 从右往左遍历
        for (int i = n - 1; i >= 0; i--) {
            // 此时 answer[i] 里存的是左乘积，R 里存的是右乘积
            // 两者相乘，就是最终答案
            answer[i] = answer[i] * R;
            
            // 更新 R：将当前数字乘入 R，供前一个元素（左边的元素）使用
            R = R * nums[i];
        }
        
        return answer;
    }
}
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：$O(N)$。我们仅仅对数组进行了两次遍历（一次从左到右，一次从右到左），总操作次数约为 $2N$，属于线性时间复杂度。
  - **空间复杂度**：$O(1)$。我们除了作为返回结果的 `answer` 数组之外，只使用了一个常数级别的整型变量 `R` 来实时更新后缀乘积。（*注：力扣官方规定，作为返回结果的数组不计入空间复杂度分析*）。

#### 💡 面试避坑与考点拓展

1. **面试官追问：为什么题目要刻意限制你不让你用除法？仅仅是为了增加难度吗？**
   - **满分回答**：不完全是。在真实的底层开发和数值计算中，**除法运算的 CPU 周期消耗远大于乘法**。更重要的是，除法天然存在除数为 0（Division by zero）的致命异常风险，需要写大量的 `if-else` 分支去处理数组中存在 1 个 0 还是 2 个 0 的情况。而这种“前缀乘后缀”的思想，无论是正数、负数还是 0，逻辑统一，天然免疫 0 的干扰，代码更加健壮。
2. **动态规划视角的降维**：
   - 你可以把这种做法看作是动态规划中“状态压缩”的一种体现。原本我们需要两个状态表 `L[]` 和 `R[]`。但因为我们在计算 `R` 的时候，只需依赖上一步的 `R`，所以把一维的 `R[]` 压缩成了一个单变量 `R`，极大地节约了内存。

### 📝 算法笔记：41. 缺失的第一个正数 (First Missing Positive)

------

- **📌 核心题意**：

  给你一个未排序的整数数组 `nums` ，请你找出其中没有出现的最小的正整数。

  `O(n)`

  **示例 1：**

  **输入：**nums = [1,2,0]
  **输出：**3
  **解释：**范围 [1,2] 中的数字都在数组中。

  **示例 2：**

  **输入：**nums = [3,4,-1,1]
  **输出：**2
  **解释：**1 在数组中，但 2 没有。

  **示例 3：**

  **输入：**nums = [7,8,9,11,12]
  **输出：**1
  **解释：**最小的正数 1 没有出现。

  **提示：**

  - `1 <= nums.length <= 105`
  - `-231 <= nums[i] <= 231 - 1`

- **🧠 思考过程**：

  1. **直觉与痛点**：

     想找缺失的数字，直觉上放进 HashSet 里，然后从 1 开始往上数，谁不在 HashSet 里就是谁。但这样空间复杂度是 $O(N)$，不符合要求。

  2. **破局思路（鸽巢原理/萝卜一个坑）**：

     - 假设数组长度为 $N$。那么缺失的第一个正数**绝对不可能大于 $N+1$**。
       - *为什么？* 因为就算数组里塞满了最紧凑的正整数 `[1, 2, 3, ..., N]`，缺失的也就是 $N+1$。如果数组里有乱七八糟的负数或大数，缺失的数字只会更小。
     - 既然答案一定在 $[1, N]$ 这个范围内，我们手里刚好有一个长度为 $N$ 的数组！
     - **灵魂操作**：我们把数组本身当成一个哈希表！**让数字 `x` 回到它该去的索引位置 `x - 1` 上。**（即数字 1 放在索引 0，数字 2 放在索引 1... 数字 $N$ 放在索引 $N-1$）。

  3. **逻辑推演（以 `[3, 4, -1, 1]` 为例，N = 4）**：

     - 遍历数组：
     - 遇到 `3`：它应该待在索引 `2` 的位置。把它和索引 `2` 的数字（`-1`）交换。数组变成 `[-1, 4, 3, 1]`。
     - 遇到 `-1`：它是负数，直接无视（不属于 $[1, N]$ 的范围）。
     - 遇到 `4`：应该待在索引 `3`。把它和索引 `3` 的数字（`1`）交换。数组变成 `[-1, 1, 3, 4]`。
     - 新换过来的 `1`：应该待在索引 `0`。把它和索引 `0` 的数字（`-1`）交换。数组变成 `[1, -1, 3, 4]`。
     - 最后，遍历整理好的数组：
       - 索引 0 是 1（正确）
       - 索引 1 是 -1（**错误！这里本该是 2**）
       - 所以，缺失的最小正整数就是 `2`！

- **🛠️ Java 规范代码**：

```java
class Solution {
    public int firstMissingPositive(int[] nums) {
        int n = nums.length;
        
        // 第一步：原地哈希（把数字放到对应的索引坑位上）
        for (int i = 0; i < n; i++) {
            // 核心判断：
            // 1. nums[i] > 0 且 nums[i] <= n：只处理范围在 [1, n] 内的有效数字
            // 2. nums[nums[i] - 1] != nums[i]：目标位置上的数字如果和当前数字不一样，才需要交换
            // （注意这里必须用 while，因为换过来的新数字可能还需要继续被交换走）
            while (nums[i] > 0 && nums[i] <= n && nums[nums[i] - 1] != nums[i]) {
                // 将 nums[i] 交换到它该去的位置：下标为 nums[i] - 1 的地方
                int temp = nums[nums[i] - 1];
                nums[nums[i] - 1] = nums[i];
                nums[i] = temp;
            }
        }
        
        // 第二步：遍历寻找第一个“没坑里萝卜”的位置
        for (int i = 0; i < n; i++) {
            // 如果索引 i 的位置没有放数字 i+1，说明 i+1 就是缺失的最小正数
            if (nums[i] != i + 1) {
                return i + 1;
            }
        }
        
        // 极端情况：如果数组是完美的 [1, 2, 3, ..., n]，那缺失的就是 n + 1
        return n + 1;
    }
}
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：$O(N)$。虽然代码里有 `for` 嵌套 `while`，但每次进入 `while` 都会把一个正确的数字放到正确的坑位上，这个过程对每个坑位最多发生一次。所以总的交换次数最多是 $N$ 次。摊销下来时间复杂度就是 $O(N)$。
  - **空间复杂度**：$O(1)$。全程只用了一个额外的 `temp` 变量，完全在原数组上折腾。

#### 💡 面试避坑与考点拓展（极易写错的陷阱）

1. **致命陷阱：为什么要用 `while` 而不是 `if`？**
   - 当我们把当前位置 `i` 的数字交换出去后，换回来的**新数字**可能依然属于 $[1, N]$ 的范围，并且没有待在正确的位置上！如果用 `if`，我们就错过了一次让新数字“回老家”的机会。用 `while` 才能保证当前坑位拿到完美的萝卜（或者换来废弃的负数/超大数）才会停下。
2. **死循环防范：`nums[nums[i] - 1] != nums[i]` 极其重要！**
   - 如果数组是 `[1, 1]`。当前索引 0 的数字是 1，待在正确位置。索引 1 的数字是 1，它该去索引 0。
   - 如果你不加这行判断，代码会不断地把索引 1 的 `1` 和索引 0 的 `1` 互相交换，产生**死循环**！这行代码既是交换条件，也是对重复数字的去重过滤。
