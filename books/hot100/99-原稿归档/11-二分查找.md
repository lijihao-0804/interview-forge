### 📝 算法笔记：35. 搜索插入位置 (Search Insert Position)
---

- **📌 核心题意**：

  给定一个排序数组和一个目标值，在数组中找到目标值，并返回其索引。如果目标值不存在于数组中，返回它将会被按顺序插入的位置。

  **硬性要求**：必须使用时间复杂度为 $O(\log n)$ 的算法。

- **🧠 思考过程**：

  1. **直觉与痛点（为什么不用 `for` 循环？）**：

     一个 `for` 循环从头扫到尾，遇到第一个大于等于目标值的数字就返回它的索引。这叫**线性查找**，时间复杂度是 $O(N)$。在几千万的数据量下，会被大厂立刻判为不合格。

     只要看到“有序数组”**和**“$O(\log n)$”这两个关键词，你的大脑必须条件反射般地弹出四个大字：**二分查找！**

  2. **破局思路（逼近与夹击）**：

     设两个指针，`left` 指向数组开头，`right` 指向数组末尾。

     每次算出中间位置 `mid`，拿 `nums[mid]` 和目标值 `target` 比大小：

     - 如果 `nums[mid] == target`，皆大欢喜，直接返回 `mid`。
     - 如果 `nums[mid] < target`，说明目标值在右半边，立刻让 `left = mid + 1`。
     - 如果 `nums[mid] > target`，说明目标值在左半边，立刻让 `right = mid - 1`。

  3. **核心微操（致命的边界与返回值）**：

     最让人头疼的是：如果目标值不在数组里，循环结束时我该返回什么？

     **黄金定律：当 `while(left <= right)` 循环打破时，`left` 和 `right` 必然错位（即 `left = right + 1`）。此时，`right` 指向的是最后一个小于 `target` 的元素，而 `left` 指向的是第一个大于 `target` 的元素！**

     既然是要插入目标值，当然应该插在“第一个大于它的元素”的位置上。所以，**永远返回 `left`！**

- **🛠️ Java 规范代码（二分查找无死角模板）**：
```Java
class Solution {
    public int searchInsert(int[] nums, int target) {
        int left = 0;
        int right = nums.length - 1;

        // 🌟 核心细节 1：必须是 <=。因为当 left == right 时，那个唯一的元素还没被检查！
        while (left <= right) {
            // 🌟 核心细节 2：防溢出的 mid 写法
            // 不要写 (left + right) / 2，如果左右指针特别大，相加会超出 int 的最大范围
            int mid = left + (right - left) / 2;

            if (nums[mid] == target) {
                // 找到了，直接返回索引
                return mid;
            } else if (nums[mid] < target) {
                // 目标值在右边，把左边界拉过来
                left = mid + 1;
            } else {
                // 目标值在左边，把右边界拉过来
                right = mid - 1;
            }
        }

        // 🌟 核心细节 3：如果没找到，循环结束时 left 必然大于 right
        // 此时 left 指向的就是目标值理应插入的正确位置！
        return left;
    }
}
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：$O(\log N)$。每次循环都会砍掉一半的搜索空间。如果数组有 40 亿个数字，最多只需要找 32 次就能出结果！这就是二分查找的恐怖威力。
  - **空间复杂度**：$O(1)$。我们仅仅用了 `left`、`right` 和 `mid` 三个整型变量，完全是原地操作。

#### 💡 面试避坑与考点拓展（大神的底层细节）

1. **踩坑警告：防溢出的 `mid` 写法**
   - 很多新手习惯写 `int mid = (left + right) / 2;`。在 LeetCode 早期，这个写法坑死了无数人。因为当 `left` 和 `right` 都是接近 `2147483647` 的大数字时，两者相加会直接变成负数，导致数组越界报错。
   - **满分习惯**：永远写成 `int mid = left + (right - left) / 2;`。或者在追求极致性能的大厂（比如 C++ 岗），可以直接写位运算：`int mid = left + ((right - left) >> 1);`，面试官看了绝对会给你竖大拇指。
2. **灵魂拷问：“为什么插入位置一定是 `left`，不是 `right`？”**
   - 闭上眼睛想象一下最后一步：此时 `left == right`，假设它们都指向数字 `5`，而你要找的 `target` 是 `6`。
   - `nums[mid]` 是 `5`，比 `6` 小。程序会执行 `left = mid + 1`。
   - 此时循环结束（`left > right`）。你看，`left` 已经往前走了一步，恰好指向了 `5` 的后面！这就完美地留出了插入 `6` 的空位。所以返回 `left` 绝对精准。

### 📝 算法笔记：74. 搜索二维矩阵 (Search a 2D Matrix)

-----

- **📌 核心题意**：

  编写一个高效的算法来判断 `m x n` 矩阵中，是否存在一个目标值。该矩阵具有如下特性：

  1. 每行中的整数从左到右按升序排列。

  2. 每行的第一个整数大于前一行的最后一个整数。

     **硬性要求**：时间复杂度必须是 $O(\log(m \times n))$。

- **🧠 思考过程**：

  1. **直觉与痛点（被二维表象欺骗）**：

     如果把矩阵一层层拆开，你会发现第一行结尾是 7，第二行开头是 10；第二行结尾 20，第三行开头 23。

     这说明什么？这说明如果**把每一行首尾相连拼起来，它就是一个完完全全严格递增的“一维数组”！**

  2. **破局思路（虚拟的一维数组）**：

     假如矩阵有 `m` 行 `n` 列，里面一共有 `m * n` 个元素。

     我们可以假设有一个长度为 `m * n` 的一维数组。用最标准的二分查找模板：`left = 0`，`right = m * n - 1`。

     每次算出 `mid`。

  3. **核心微操（时空折叠：一维到二维的坐标映射）**：

     算法最大的难点在于：我们没有真的去创建一个一维数组（因为那会白白消耗 $O(M \times N)$ 的空间）。我们在内存里面对的依然是二维矩阵。

     当算出虚拟的一维索引 `mid` 时，怎么知道它对应二维矩阵里的第几行、第几列呢？

     **黄金公式（死记硬背）：**

     - **行号 `row` = `mid / n`** （即 `mid / 列数`，看看 `mid` 里面包含了几个完整的行）
     - **列号 `col` = `mid % n`** （即 `mid % 列数`，看看除掉完整行后，剩下的余数偏移量）

- **🛠️ Java 规范代码（完美的降维二分版）**：
```Java
class Solution {
    public boolean searchMatrix(int[][] matrix, int target) {
        // 边界防御：严谨的工程师永远会先检查空指针和空矩阵
        if (matrix == null || matrix.length == 0 || matrix[0].length == 0) {
            return false;
        }

        int m = matrix.length;       // 行数
        int n = matrix[0].length;    // 列数

        // 虚拟一维数组的左右边界
        int left = 0;
        int right = m * n - 1;

        // 标准的二分查找模板
        while (left <= right) {
            int mid = left + (right - left) / 2;
            
            // 🌟 降维打击的核心魔法：将 1D 索引映射回 2D 坐标
            int midValue = matrix[mid / n][mid % n];

            if (midValue == target) {
                return true; // 命中目标，大吉大利！
            } else if (midValue < target) {
                left = mid + 1; // 目标在右半边
            } else {
                right = mid - 1; // 目标在左半边
            }
        }

        // 循环结束也没找到，说明真没有
        return false;
    }
}
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：$O(\log(m \times n))$。直接对总元素个数进行二分，完美达到理论最优极速。
  - **空间复杂度**：$O(1)$。我们只用了 `left`、`right`、`mid` 几个整型变量，所有的“一维数组”都是通过坐标映射在脑海中虚拟出来的。

#### 💡 面试避坑与考点拓展（大厂连环绝杀题）

- **大厂终极追问：“如果我把这道题的条件改一下，【每行的第一个整数 不一定 大于前一行的最后一个整数】，仅仅保证【每行从左到右递增，每列从上到下递增】，你还能用二分吗？”（对应力扣 240 题：搜索二维矩阵 II）**

  - **满分降维打击（右上角破局法 / BST法）**：

    一旦失去首尾相连递增的特性，你就**不能**再把它拍平当一维数组处理了！

    但此时有另一种极其惊艳的 $O(M + N)$ 解法：我们把目光锁定在矩阵的**右上角**！

    - 站在右上角，向左走，数字越来越小；向下走，数字越来越大。

    - **这难道不就是一棵把根节点放在右上角的 二叉搜索树（BST） 吗？！**

    - 拿右上角的数字和目标比：如果比目标大，就向左走一步（排除一列）；如果比目标小，就向下走一步（排除一行）。一路贪心，走到越界还没找到就是 false。

      如果你能在面试时顺嘴提一句这个变种和它的右上角（或左下角）走迷宫解法，面试官会直接在你的简历上画个大大的优！

### 📝 算法笔记：33. 搜索旋转排序数组 (Search in Rotated Sorted Array)

-----

- **📌 核心题意**：

  整数数组 `nums` 按升序排列，数组中的值 **互不相同**。

  在传递给函数之前，`nums` 在预先未知的某个下标处进行了 **旋转**（例如， `[0,1,2,4,5,6,7]` 可能变为 `[4,5,6,7,0,1,2]`）。

  给你旋转后的数组 `nums` 和一个整数 `target` ，如果 `nums` 中存在这个目标值 `target` ，则返回它的下标，否则返回 `-1`。

  **硬性要求**：必须设计一个时间复杂度为 $O(\log n)$ 的算法。

- **🧠 思考过程**：

  1. **直觉与痛点（被扭断的数组）**：

     $O(\log n)$ 的要求直接封死了 `for` 循环线性查找的退路，逼着我们必须用二分。

     **痛点**：二分查找的精髓是“拿中间的值和目标比，决定去左边还是右边”。但现在数组被扭断了，`[4,5,6,7,0,1,2]` 的中间是 7，目标如果是 0，它既比 7 小，又在 7 的右边！传统的比大小逻辑彻底失效。

  2. **破局思路（局部有序定理）**：

     仔细观察这个被扭断的数组，无论你从哪个位置把它一分为二（切一刀），**它的左半边和右半边，必定有一半是完全单调递增的！**

     - 比如 `[4,5,6,7, 0,1,2]`，切在 7：左半边 `[4,5,6,7]` 是完全有序的！右半边包含断点。
     - 比如 `[6,7,0,1, 2,4,5]`，切在 1：右半边 `[1,2,4,5]` 是完全有序的！左半边包含断点。

  3. **核心微操（指哪打哪）**：

     既然总有一半是有序的，那事情就好办了。

     每次算出 `mid` 后，我们先**判断哪一半是有序的**：

     - **如果左半边有序**：我们利用有序的特性，看看 `target` 是不是落在 `[left, mid)` 的闭区间内。如果在，那必定在左边（`right = mid - 1`）；如果不在，那必定在右边那个乱序的半区里（`left = mid + 1`）。
     - **如果右半边有序**：同理，看看 `target` 是不是落在 `(mid, right]` 内。如果在，去右边找（`left = mid + 1`）；不在，去左边找（`right = mid - 1`）。

- **🛠️ Java 规范代码（局部有序判断满分版）**：
```Java
class Solution {
    public int search(int[] nums, int target) {
        int left = 0;
        int right = nums.length - 1;

        while (left <= right) {
            int mid = left + (right - left) / 2;

            if (nums[mid] == target) {
                return mid; // 运气好，直接命中
            }

            // 🌟 核心判断：左半边是否完全有序？
            // 致命细节：这里必须是 <=，不能是 <。因为当 left == mid 时（数组只剩一两个元素），它也是一个合法的“有序区间”！
            if (nums[left] <= nums[mid]) {
                // 进入了“左半边完全单调递增”的分支
                // 既然它单调递增，那我们就看看 target 是否老老实实呆在这个区间里
                if (nums[left] <= target && target < nums[mid]) {
                    // target 在这个有序区间内，向左压缩
                    right = mid - 1;
                } else {
                    // target 不在这个有序区间内，肯定在右边那个带有断点的半区，向右压缩
                    left = mid + 1;
                }
            } 
            // 否则，右半边必定完全有序
            else {
                // 进入了“右半边完全单调递增”的分支
                // 看看 target 是否老老实实呆在右半边有序区间里
                if (nums[mid] < target && target <= nums[right]) {
                    // target 在右边，向右压缩
                    left = mid + 1;
                } else {
                    // target 不在右边，肯定在左边那个带有断点的半区，向左压缩
                    right = mid - 1;
                }
            }
        }

        return -1; // 搜遍了全图也没找到
    }
}
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：$O(\log N)$。虽然里面多了一层判断，但我们每次依然是无情地**砍掉一半**的数据，完美的二分效率。
  - **空间复杂度**：$O(1)$。只动用了常数级别的指针变量。

#### 💡 面试避坑与考点拓展（大厂细节生死线）

1. **踩坑警告（致命错误）：为什么是 `nums[left] <= nums[mid]`，漏掉等于号会怎样？**
   - 假设数组是 `[3, 1]`，我们要找 `1`。
   - 第一轮：`left = 0`, `right = 1`, `mid = 0`。此时 `nums[left] == 3`, `nums[mid] == 3`。
   - 如果你写的是 `nums[left] < nums[mid]`，它会认为左半边无序，从而跳进 `else`（右半边有序）分支。
   - 然后它判断 `target (1)` 是否在右半边 `(nums[mid], nums[right]]` 即 `(3, 1]` 内。这显然是个假命题，于是错误地执行 `right = mid - 1`，导致错过了正确答案！
   - **结论**：在计算机里，**只包含一个元素的区间 `[3]` 是天然有序的**，所以必须要有 `=` 号，承认 `left == mid` 时的有序合法性。
2. **大厂追问：“如果数组里允许有【重复的数字】，比如 `[1, 0, 1, 1, 1]` 找 `0`，这个算法还能用吗？”（对应力扣 81 题：搜索旋转排序数组 II）**
   - **满分抢答（直击退化痛点）**：不能直接用！
   - 如果有重复数字，可能会遇到 `nums[left] == nums[mid] == nums[right]` 的情况（比如 `left` 测出是 1，`mid` 是 1，`right` 也是 1）。此时你根本不知道断点在左边还是右边，局部有序定理在这里失效了！
   - **破局办法**：遇到这种情况，只能暴力把 `left` 往前挪一步（`left++`），或者 `right` 往后挪一步（`right--`），跳过重复干扰项，直到这三个数不全相等，再重新启动二分。这也是为什么如果有重复数字，算法最坏会退化成 $O(N)$ 的原因。

### 📝 算法笔记：153. 寻找旋转排序数组中的最小值 (Find Minimum in Rotated Sorted Array)3

-----

- **📌 核心题意**：

  已知一个长度为 `n` 的数组，预先按照升序排列，经由 `1` 到 `n` 次 **旋转** 后，得到输入数组。

  请找出并返回数组中的 **最小元素** 。数组中的所有整数都是 **唯一** 的。

  **硬性要求**：你必须设计一个时间复杂度为 $O(\log n)$ 的算法解决此问题。

- **🧠 思考过程**：

  1. **直觉与痛点（找断点）**：

     最小值其实就是这个旋转数组的“断崖点”。我们怎么用二分法判断这个断崖点在左边还是右边呢？

  2. **破局思路（寻找绝对的参照物）**：

     在 33 题中，我们通过比较 `nums[left]` 和 `nums[mid]` 来判断左半边是否有序。但这道题，**最佳的参照物是 `nums[right]`**！

     我们将 `nums[mid]` 和最右边的数字 `nums[right]` 进行火星撞地球般的对比：

     - **场景 A (`nums[mid] > nums[right]`)**：比如 `[4, 5, 6, 7, 0, 1, 2]`，`mid` 是 `7`，`right` 是 `2`。中间的值居然比最右边的值还大！这违背了升序规律，说明**断崖（最小值）必定在右半边！** 于是，我们大手一挥：`left = mid + 1`。
     - **场景 B (`nums[mid] < nums[right]`)**：比如 `[6, 7, 0, 1, 2, 4, 5]`，`mid` 是 `1`，`right` 是 `5`。中间值比右边小，说明**从 `mid` 到 `right` 这一段是完美升序的，没有任何断崖！** 既然这一段是升序的，那么最小值绝对不可能在 `mid` 的右边。它要么是 `mid` 本身，要么在 `mid` 的左边。于是，我们谨慎收缩：**`right = mid`**。

  3. **核心微操（循环终止的奥秘）**：

     既然每次都在逼近，那什么时候停下？

     当 `left == right` 时，搜索区间只剩下一个元素了，这个元素就是我们要找的最小值！所以循环条件是 **`while (left < right)`**。

- **🛠️ Java 规范代码（绝美逼近版）**：
```Java
class Solution {
    public int findMin(int[] nums) {
        int left = 0;
        int right = nums.length - 1;

        // 🌟 致命细节 1：这里是 left < right，不是 <=
        // 因为我们不需要像找 target 那样去检查最后一个元素是否匹配
        // 当 left == right 时，它们共同指向的就是那个被逼入死角的最小值！
        while (left < right) {
            int mid = left + (right - left) / 2;

            // 拿中间值和【右边界】做比较
            if (nums[mid] > nums[right]) {
                // 中间比右边大，说明断崖在右半边，最小值必定在 mid 之后
                left = mid + 1;
            } else {
                // 🌟 致命细节 2：这里是 right = mid，绝对不能是 mid - 1！
                // 因为 nums[mid] 可能是真正的最小值（比如 [7, 0, 1, 2] 中的 0）
                // 如果写成 mid - 1，就会把真正的最小值给扔掉！
                right = mid;
            }
        }

        // 循环结束时，left 和 right 重合，这就是最小值的位置
        return nums[left];
    }
}
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：$O(\log N)$。经典的二分查找，每次无情排除一半的空间。
  - **空间复杂度**：$O(1)$。只使用了常数级别的游标变量。

#### 💡 面试避坑与考点拓展（大厂的灵魂拷问）

1. **灵魂拷问 1：“为什么比较的参照物是 `nums[right]`，能不能用 `nums[left]`？”**
   - **满分避坑指南**：**强烈不建议用 `left`！** * 假设给你一个完全没有旋转（或者旋转了 $N$ 次）的原始升序数组，比如 `[1, 2, 3, 4, 5]`。
   - 如果你用 `nums[mid] > nums[left]` (`3 > 1`) 来判断，你会误以为断崖在右边，从而让 `left = mid + 1`，直接把真正的最小值 `1` 给丢掉了！
   - 而如果你用 `nums[right]`，`3 < 5`，程序会执行 `right = mid`，慢慢向左收缩，最终完美定格在 `1` 上。**用 `right` 作为参照物，可以完美兼容“数组未发生旋转”的边界情况！**
2. **大厂追问 2：“如果数组里有重复元素呢？比如 `[2, 2, 2, 0, 1, 2]`，这个算法还能跑吗？”（对应力扣 154 题：寻找旋转排序数组中的最小值 II - Hard 难度）**
   - **满分降维打击**：如果有重复元素，就会出现 `nums[mid] == nums[right]` 的情况（比如上面例子中 `mid` 指向 `2`，`right` 也指向 `2`）。
   - 此时你根本不知道断崖在左边还是右边。怎么办？
   - **绝境求生法**：既然 `nums[mid]` 和 `nums[right]` 一样大，那我们保留 `mid` 就够了，直接把 `right` 砍掉一格（**`right--`**），缩小范围继续试！这就是那道 Hard 题的全部核心代码，仅仅多了一行 `else if (nums[mid] == nums[right]) right--;`，极其优美！

### 📝 算法笔记：4. 寻找两个正序数组的中位数

-----

- **📌 核心题意**：

  给定两个大小分别为 `m` 和 `n` 的正序（从小到大）数组 `nums1` 和 `nums2`。请你找出并返回这两个正序数组的 **中位数** 。

  **硬性要求**：算法的时间复杂度应该为 **$O(\log (m+n))$**。

- **🧠 思考过程**：

  1. **直觉与痛点（二分到底在分什么？）**：

     $O(\log(m+n))$ 强制我们必须用二分。但是，两个数组错综复杂，我们该对谁做二分？二分的目标又是什么？

     **痛点**：如果你试图在两个数组里直接去“找”那个中位数的具体数值，你会陷入极其痛苦的边界比较中，因为你不知道这个数字到底在 `nums1` 还是 `nums2` 里。

  2. **降维破局（寻找那条“完美的割线”）**：

     中位数的本质是什么？它是将一个集合划分为**长度相等的上下两部分**，并且**上半部分的最大值 $\le$ 下半部分的最小值**。

     既然有两个数组，那我们就分别在 `nums1` 和 `nums2` 中各切一刀（划一条割线）。

     - 我们要求：**左半边的元素总个数，恰好等于右半边的元素总个数**（如果是奇数，让左边多一个）。
     - 这意味着，只要我们在 `nums1` 中切了一刀，由于总人数固定，`nums2` 中的那一刀也就**自动确定了！**

  3. **核心微操（交叉验证法）**：

     假设 `nums1` 切在位置 `i`，`nums2` 切在位置 `j`。

     割线左边的两个元素我们叫 `A_left` 和 `B_left`，右边的叫 `A_right` 和 `B_right`。

     为了保证左半边全体 $\le$ 右半边全体，由于数组本身是有序的，我们只需要**交叉验证**：

     - `A_left <= B_right` （A 的左边必须小于 B 的右边）

     - `B_left <= A_right` （B 的左边必须小于 A 的右边）

       **二分逻辑**：

     - 如果 `B_left > A_right`：说明 B 左边的数字太大了！这意味着我们在 B 里划的数字太多，而在 A 里划的数字太少。所以，**A 的割线必须向右移（增大 `i`）**。

     - 反之，向左移。当交叉验证通过时，我们就找到了那条完美的割线！

- **🛠️ Java 规范代码（满分虚拟极值版）**：
```Java
class Solution {
    public double findMedianSortedArrays(int[] nums1, int[] nums2) {
        // 🌟 核心技巧 1：保证 nums1 永远是那个比较短的数组！
        // 因为我们在较短的数组上做二分，不仅速度更快，而且可以防止 nums2 越界
        if (nums1.length > nums2.length) {
            return findMedianSortedArrays(nums2, nums1);
        }

        int m = nums1.length;
        int n = nums2.length;
        
        // 分割线左边需要的总元素个数（向上取整，奇数时左边多一个）
        int totalLeft = (m + n + 1) / 2;
        
        // 在短数组 nums1 的区间 [0, m] 里寻找最完美的割线 i
        int left = 0;
        int right = m;

        while (left <= right) {
            // i 是 nums1 的割线位置（表示 nums1 左半边有 i 个元素）
            int i = left + (right - left) / 2;
            // j 是 nums2 的割线位置（剩下的元素全归 nums2 凑齐 totalLeft）
            int j = totalLeft - i;

            // 🌟 核心技巧 2：处理边界问题（利用无穷大/无穷小虚拟补位）
            // 如果切在最左边，左边没元素了，用 MIN_VALUE 代替；切在最右边，用 MAX_VALUE 代替
            int A_left  = (i == 0) ? Integer.MIN_VALUE : nums1[i - 1];
            int A_right = (i == m) ? Integer.MAX_VALUE : nums1[i];
            int B_left  = (j == 0) ? Integer.MIN_VALUE : nums2[j - 1];
            int B_right = (j == n) ? Integer.MAX_VALUE : nums2[j];

            // 交叉验证
            if (A_left <= B_right && B_left <= A_right) {
                // 完美割线找到了！
                // 如果总长度是奇数，中位数就是左半边的最大值
                if ((m + n) % 2 != 0) {
                    return Math.max(A_left, B_left);
                }
                // 如果总长度是偶数，中位数是 (左半边最大值 + 右半边最小值) / 2.0
                else {
                    return (Math.max(A_left, B_left) + Math.min(A_right, B_right)) / 2.0;
                }
            } else if (B_left > A_right) {
                // B 的左边太大了，A 的割线必须往右走，多吃一点元素进来
                left = i + 1;
            } else {
                // A 的左边太大了，A 的割线必须往左走
                right = i - 1;
            }
        }
        
        return 0.0; // 正常情况下代码不会走到这里
    }
}
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：$O(\log(\min(m, n)))$。由于我们强制对较短的数组进行二分查找，查找空间就是 $\min(m, n)$，完全符合题目的极致性能要求。
  - **空间复杂度**：$O(1)$。我们仅仅用了几个游标变量来记录割线和边缘的数值。

#### 💡 面试避坑与考点拓展（大厂生死狙击）

1. **踩坑警告：为什么要写 `totalLeft = (m + n + 1) / 2`？**
   - 这个 `+1` 是个极其精妙的数学统筹。
   - 假设总长度是偶数（例如 4），`(4 + 1) / 2 = 2`，左半边分到 2 个。
   - 假设总长度是奇数（例如 5），`(5 + 1) / 2 = 3`，左半边分到 3 个。
   - 它完美地统一了奇偶数情况，并且保证了当长度为奇数时，**中位数永远只会出现在左半边的最大值里**（即 `Math.max(A_left, B_left)`），省去了极多冗余的条件判断。
2. **大厂追问：“遇到数组极度倾斜（比如 `A` 为空，或者 `A` 完全大于 `B`），这个算法会越界报错吗？”**
   - **满分抢答（优雅的哨兵模式）**：绝不会报错！因为我们采用了 `Integer.MIN_VALUE` 和 `Integer.MAX_VALUE` 作为“哨兵（Sentinel）”。
   - 比如 `A` 如果一刀切在最左侧（`i = 0`），意味着 `A` 没有任何元素分给左半边。程序直接给 `A_left` 赋值为负无穷，负无穷去比较任何真实的数字，都会顺利通过 `<= B_right` 的交叉验证。这正是工业级代码对于“边界消解”的最高级手法！
