### 📝 算法笔记：215. 数组中的第K个最大元素

-----

- **📌 核心题意**：

  给定整数数组 `nums` 和整数 `k`，请返回数组中第 `k` 个最大的元素。

  请注意，你需要找的是数组排序后的第 `k` 个最大的元素，而不是第 `k` 个不同的元素。

  你必须设计并实现时间复杂度为 `O(n)` 的算法解决此问题。

  **示例 1:**

  **输入:** `[3,2,1,5,6,4],` k = 2
  **输出:** 5

  **示例 2:**

  **输入:** `[3,2,3,1,2,4,5,5,6], `k = 4
  **输出:** 4

  **提示：**

  - `1 <= k <= nums.length <= 105`
  - `-104 <= nums[i] <= 104`

- **🧠 思考过程**：

  1. **直觉与痛点（全盘排序的浪费）**：

     标准的快速排序或归并排序时间复杂度是 $O(N \log N)$。

     **痛点**：面试官会问：“我只要第 $K$ 个，你为什么要把所有元素都排好序？这不是杀鸡用牛刀吗？”

  2. **破局思路 1（职场黑客流：优先队列 / 小顶堆）**：

     想象你在搞一个选秀节目，只需要选出前 $K$ 强。

     我们可以建一个**容量为 $K$ 的小顶堆（Min-Heap）**。遍历数组，把人往堆里塞。一旦堆里的人数超过 $K$ 个，就把堆顶那个**最弱的（最小的）\**踢出去。 等所有人都过了一遍，堆里剩下的就是全场最强的 $K$ 个人，而\**此时的堆顶，正好就是这 $K$ 个人里最弱的，也就是全场第 $K$ 大的元素！**

     *时间复杂度：$O(N \log K)$*。虽然没有严格达到 $O(N)$，但在处理海量流式数据时，这是王牌解法。

  3. **破局思路 2（算法原教旨主义：快速选择 Quickselect）**：

     这是面试官最想看到的 $O(N)$ 终极解法。它脱胎于大名鼎鼎的**快速排序（Quicksort）**。

     快排的核心是 `partition`（划分）：随便找一个基准数（Pivot），把比它小的扔左边，比它大的扔右边。

     **降维魔法**：在排完一次后，基准数会落在一个固定的索引 `p` 上。

     - 如果 `p` 恰好等于我们要找的索引（第 $K$ 大对应的索引是 $N - K$），直接收工！
     - 如果 `p < N - K`，说明目标在基准数的**右边**，左边那一半直接像垃圾一样**全部丢弃**，只去右边递归！
     - 如果 `p > N - K`，说明目标在**左边**，右边全部丢弃！

- **🛠️ Java 规范代码（满分 Quickselect 随机化版）**：
```Java
import java.util.Random;

class Solution {
    private Random random = new Random();

    public int findKthLargest(int[] nums, int k) {
        // 第 K 大的元素，如果把数组从小到大排序，它的目标索引其实是 N - K
        // 比如 6 个元素找第 2 大，排好序后它在索引 6 - 2 = 4 的位置
        int targetIndex = nums.length - k;
        return quickSelect(nums, 0, nums.length - 1, targetIndex);
    }

    private int quickSelect(int[] nums, int left, int right, int targetIndex) {
        // 🌟 致命防御：引入随机化！
        // 如果每次都固定取最右边的数做基准，遇到已经排好序的数组，时间复杂度会退化到 O(N^2)
        // 随机选一个基准，把它和最右边的数交换，可以完美避开极端测试用例的制裁
        int randomIndex = left + random.nextInt(right - left + 1);
        swap(nums, randomIndex, right);

        // 进行一次划分（把比基准小的扔左边，大的扔右边，返回基准最终的落脚点）
        int pivotIndex = partition(nums, left, right);

        // 开始“指哪打哪”的降维打击
        if (pivotIndex == targetIndex) {
            return nums[pivotIndex]; // 一发入魂，直接命中！
        } else if (pivotIndex < targetIndex) {
            // 基准落在目标的左边，说明目标在右半区，左半区彻底抛弃！
            return quickSelect(nums, pivotIndex + 1, right, targetIndex);
        } else {
            // 基准落在目标的右边，说明目标在左半区，右半区彻底抛弃！
            return quickSelect(nums, left, pivotIndex - 1, targetIndex);
        }
    }

    // 标准的快排 Partition 划分函数
    private int partition(int[] nums, int left, int right) {
        int pivot = nums[right]; // 以最右边的元素为基准
        int i = left; // i 指向小于基准的区域的下一个空位

        for (int j = left; j < right; j++) {
            if (nums[j] < pivot) {
                // 发现比基准小的，扔到 i 的位置去，然后 i 往前挪一步
                swap(nums, i, j);
                i++;
            }
        }
        // 最后把基准数换到它该在的中心位置 i 上
        swap(nums, i, right);
        return i; // 返回基准数的最终索引
    }

    private void swap(int[] nums, int i, int j) {
        int temp = nums[i];
        nums[i] = nums[j];
        nums[j] = temp;
    }
}
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：平均情况 **$O(N)$**。第一次划分需要遍历 $N$ 个元素，第二次只需要遍历约 $N/2$ 个，第三次 $N/4$... 这是一个等比数列，求和极限就是 $2N$，所以是 $O(N)$。由于引入了随机化，最坏情况 $O(N^2)$ 的概率比被雷劈还小。
  - **空间复杂度**：$O(\log N)$。消耗在递归调用栈上。

#### 💡 面试避坑与考点拓展（大厂的终极拷问）

1. **大厂追问 1：“Quickselect 和 Min-Heap，在实际工程场景中到底怎么选？”**
   - **满分抢答**：
     - 如果是**静态数据**（数组已经固定全部在内存里），选 **Quickselect**，因为它纯内存原地操作，不需要额外开辟对象，平均时间 $O(N)$ 绝对最快。
     - 如果是**动态数据 / 海量数据（Streaming Data）**（比如服务器上持续涌入的日志，或者 1TB 的数据内存装不下），**必须选 Min-Heap**！只需维护一个大小为 $K$ 的堆放在内存里，来一个处理一个，时间复杂度 $O(N \log K)$，内存消耗极小。
2. **踩坑警告：“第 $K$ 大”与“索引”的转换**
   - 快排的分区通常是“从小到大”排（左小右大）。
   - 面试极其容易在这翻车：如果你用从小到大排的 Partition，**第 $K$ 大的数字，它的目标索引必然是 `nums.length - k`**！一定要在开头把这个索引算好，当作靶子传给递归函数。

### 📝 算法笔记：215. 数组中的第K个最大元素
-----

#### 📝 核心概念：为什么找“最大”反而要用“小顶堆”？

很多初学者的第一个认知陷阱是：“找第 $K$ 大，是不是应该用大顶堆（Max-Heap）？”

- **📌 核心题意**：

  给定整数数组 `nums` 和整数 `k`，请返回数组中第 `k` 个最大的元素。

  请注意，你需要找的是数组排序后的第 `k` 个最大的元素，而不是第 `k` 个不同的元素。

  你必须设计并实现时间复杂度为 `O(n)` 的算法解决此问题。

  **示例 1:**

  **输入:** `[3,2,1,5,6,4],` k = 2
  **输出:** 5

  **示例 2:**

  **输入:** `[3,2,3,1,2,4,5,5,6], `k = 4
  **输出:** 4

  **提示：**

  - `1 <= k <= nums.length <= 105`
  - `-104 <= nums[i] <= 104`

- **大顶堆的笨办法**：你可以把数组里的 $N$ 个元素全都扔进一个大顶堆里。堆顶就是第 1 大，然后你 `pop` 出去 $K-1$ 个，此时堆顶就是第 $K$ 大。

  - **缺点**：你需要维护一个容量为 $N$ 的超级大堆！如果数据是 10 个 T，你的内存直接就爆了，空间复杂度是 $O(N)$，毫无工程价值。

- **小顶堆的封神玩法（VIP 选秀室模型）**：

  找第 $K$ 大，最完美的做法是维护一个**容量仅仅为 $K$ 的小顶堆（Min-Heap）**。

  你可以把这个小顶堆想象成一个**只有 $K$ 个座位的 VIP 选秀室**。

  1. 既然是小顶堆，那么坐在堆顶（门口第一个座位）的人，永远是这 $K$ 个人里**最弱的（最小的）**。
  2. 大门敞开，让所有人依次来踢馆。
  3. 如果门外来了一个新人，他只要跟门口那个“最弱的”比一下：
     - 如果新人比最弱的还弱，直接淘汰，下一个！
     - **如果新人比最弱的强**，那就一脚把最弱的踢出去，自己坐进 VIP 室！然后 VIP 室内重新洗牌，再选出一个新的最弱的坐到门口。
  4. 等全世界的人都踢馆完毕，VIP 室里留下的是谁？毫无疑问，是全场最强的 $K$ 个人！
  5. 此时，**坐在门口的那个最弱的人（小顶堆的堆顶），正好就是这 $K$ 个人里垫底的——也就是全场第 $K$ 大的元素！**

#### 🛠️ Java 规范代码（小顶堆模板）

在 Java 中，堆的官方名字叫**优先队列（PriorityQueue）**，默认就是小顶堆，写起来极其优雅：
```Java
import java.util.PriorityQueue;

class Solution {
    public int findKthLargest(int[] nums, int k) {
        // 创建一个小顶堆（PriorityQueue 默认就是小顶堆）
        PriorityQueue<Integer> minHeap = new PriorityQueue<>();

        // 让所有元素依次来 VIP 室踢馆
        for (int num : nums) {
            // 先不管三七二十一，让人先进去
            minHeap.offer(num);
            
            // 如果 VIP 室的人数超过了 K 个
            if (minHeap.size() > k) {
                // 就把最弱的（堆顶）给踢出去！
                minHeap.poll();
            }
        }

        // 踢馆结束，留在堆顶的就是第 K 大的元素
        return minHeap.peek();
    }
}
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：$O(N \log K)$。遍历 $N$ 个元素，每次入堆/出堆调整的代价是 $\log K$。
  - **空间复杂度**：$O(K)$。**这是堆解法最牛的地方！** 不管外面的世界有几十亿个数字，我的内存里永远只需要保存 $K$ 个数字。

### 📝 算法笔记：347. 前 K 个高频元素 (Top K Frequent Elements)

-----

- **📌 核心题意**：

  给你一个整数数组 `nums` 和一个整数 `k` ，请你返回其中出现频率前 `k` 高的元素。你可以按 **任意顺序** 返回答案。

  **示例 1：**

  **输入：**nums = [1,1,1,2,2,3], k = 2
  **输出：**[1,2]

  **示例 2：**

  **输入：**nums = [1], k = 1
  **输出：**[1]

  **示例 3：**

  **输入：**nums = [1,2,1,2,1,2,3,1,3,2], k = 2
  **输出：**[1,2]

  **提示：**

  - `1 <= nums.length <= 105`
  - `-104 <= nums[i] <= 104`
  - `k` 的取值范围是 `[1, 数组中不相同的元素的个数]`
  - 题目数据保证答案唯一，换句话说，数组中前 `k` 个高频元素的集合是唯一的

  **进阶：**你所设计算法的时间复杂度 **必须** 优于 `O(n log n)` ，其中 `n`是数组大小。

- **🧠 思考过程**：

  1. **直觉与痛点（先统后排）**：

     第一步永远是毫无悬念的：用一个哈希表（HashMap）把每个数字出现的次数统计出来。

     **痛点**：拿到 `<数字, 频率>` 的映射后怎么排序？如果把所有条目拿出来做一个全局排序，时间复杂度会变成 $O(N \log N)$，直接被题目要求的硬性底线淘汰。

  2. **破局思路 1（VIP 选秀室重出江湖：小顶堆）**：

     既然是找前 K 大（这里是频率的前 K 大），我们完全可以原封不动地照搬上一题的“容量为 `k` 的小顶堆”战术！

     把 HashMap 里的条目一个个往小顶堆里塞。**注意：堆里比较的不再是数字本身的大小，而是数字对应的频率！**

     如果堆里超过了 `k` 个人，就把频率最低的那个踢出去。遍历完 HashMap，堆里留下的就是频率最高的 `k` 个元素。

     *时间复杂度：$O(N \log K)$，完美通关。*

  3. **破局思路 2（大厂终极魔法：桶排序 Bucket Sort）**：

     面试官微笑地看着你：“$O(N \log K)$ 不错，但你能做到极致的 $O(N)$ 吗？”

     **降维打击开始**：频率这个东西，有一个天然的上限——一个数字出现的最高频率，撑死也就是数组的总长度 $N$（全数组都是同一个数字）！

     既然频率的值域这么窄（$0$ 到 $N$），我们为什么不建一个**长度为 $N+1$ 的数组（这就是一组水桶）**？

     - **数组的下标（Index）代表频率**。

     - **数组里装的内容（Value）代表出现该频率的数字集合**。

       这就等于把数据按频率自动归位了！然后我们只需要从后往前（从高频到低频）扫一遍这排水桶，收集到 `k` 个数字直接下班！

- **🛠️ Java 规范代码（满分桶排序版 $O(N)$）**：

  *(在面试中，写出小顶堆算及格，写出桶排序是绝对的 Senior 级别)*
```Java
import java.util.ArrayList;
import java.util.HashMap;
import java.util.List;
import java.util.Map;

class Solution {
    public int[] topKFrequent(int[] nums, int k) {
        // 1. 战前准备：用 HashMap 统计每个数字的出现频率
        Map<Integer, Integer> countMap = new HashMap<>();
        for (int num : nums) {
            countMap.put(num, countMap.getOrDefault(num, 0) + 1);
        }

        // 2. 建立桶数组：下标代表频率，值代表拥有该频率的数字列表
        // 🌟 致命细节：桶的数量必须是 nums.length + 1，因为如果有数字出现了 N 次，下标需要能取到 N
        List<Integer>[] buckets = new List[nums.length + 1];
        
        // 把 HashMap 里的数据倒进桶里
        for (Map.Entry<Integer, Integer> entry : countMap.entrySet()) {
            int num = entry.getKey();
            int freq = entry.getValue();
            
            // 如果这个频率的桶还没建好，先初始化一个 List
            if (buckets[freq] == null) {
                buckets[freq] = new ArrayList<>();
            }
            // 把数字扔进对应频率的桶里
            buckets[freq].add(num);
        }

        // 3. 逆向扫桶：从最高频率往下扫，收集前 k 个数字
        int[] res = new int[k];
        int index = 0;
        
        // 从最右边（最高频）开始往左看
        for (int i = buckets.length - 1; i >= 0 && index < k; i--) {
            // 如果这个频率的桶里有数字
            if (buckets[i] != null) {
                // 把桶里的数字全部收缴，直到收满 k 个为止
                for (int num : buckets[i]) {
                    res[index++] = num;
                    if (index == k) {
                        return res; // 🌟 收满 k 个，立刻准点下班！
                    }
                }
            }
        }

        return res;
    }
}
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：**$O(N)$**。统计频率遍历一遍 $N$；把数据倒进水桶遍历一遍不同数字的个数（小于等于 $N$）；最后逆向扫一遍桶数组（长度为 $N+1$）。全程没有比较排序，纯正的线性时间！
  - **空间复杂度**：$O(N)$。主要开销在 HashMap 和桶数组 `buckets` 上，它们的大小都不会超过数组的总长度 $N$。

#### 💡 面试避坑与考点拓展（大厂的连环计）

- **大厂追问：“既然桶排序这么快，为什么上一题【第 K 大的元素】我们不用桶排序？”**
  - **满分抢答（直击底层逻辑）**：这取决于**值域的跨度**！
  - 在这道题里，我们要排序的维度是“频率”。频率的最小是 1，最大是数组长度 $N$，值域非常紧凑，所以可以开辟长度为 $N+1$ 的桶数组，空间消耗极其合理。
  - 而在上一题里，我们要排序的维度是“数值本身”！如果数组里只有两个数字：`[1, 2147483647]`。为了这两个数字，难道我要在内存里开辟一个长度为 21 亿的桶数组吗？内存当场就炸毁了。
  - **一句话总结**：值域紧凑且有明确上限，优先用桶排序（计数排序）；值域跨度巨大或存在负数/浮点数，老老实实用堆（优先级队列）或快速选择。

### 📝 算法笔记：295. 数据流的中位数 (Find Median from Data Stream)

-----

#### 🧠 思考过程：

1. **直觉与痛点（动态排序的绝望）**：

   中位数把所有数字分成了“左边较小的一半”和“右边较大的一半”。

   如果用动态数组 `ArrayList` 维护，新来一个数，为了保持有序，我们需要用二分查找找到位置并插入，移动元素需要 $O(N)$ 的时间。数据量一旦大起来，动态插入会彻底卡死。

2. **降维破局（双堆对顶，各据一方）**：

   我们其实**根本不需要让所有数字都严格有序**！我们只需要牢牢把控住“左半区的最大值”和“右半区的最小值”。

   由此，我们创造出两个大本营：

- **📌 核心题意**：

  **中位数**是有序整数列表中的中间值。如果列表的大小是偶数，则没有中间值，中位数是两个中间值的平均值。

  - 例如 `arr = [2,3,4]` 的中位数是 `3` 。
  - 例如 `arr = [2,3]` 的中位数是 `(2 + 3) / 2 = 2.5` 。

  实现 MedianFinder 类:

  - `MedianFinder()` 初始化 `MedianFinder` 对象。
  - `void addNum(int num)` 将数据流中的整数 `num` 添加到数据结构中。
  - `double findMedian()` 返回到目前为止所有元素的中位数。与实际答案相差 `10-5` 以内的答案将被接受。

  **示例 1：**

  **输入**
  ["MedianFinder", "addNum", "addNum", "findMedian", "addNum", "findMedian"]
  [[], [1], [2], [], [3], []]
  **输出**
  [null, null, null, 1.5, null, 2.0]

  **解释**
  MedianFinder medianFinder = new MedianFinder();
  medianFinder.addNum(1);    // arr = [1]
  medianFinder.addNum(2);    // arr = [1, 2]
  medianFinder.findMedian(); // 返回 1.5 ((1 + 2) / 2)
  medianFinder.addNum(3);    // arr[1, 2, 3]
  medianFinder.findMedian(); // return 2.0

  **提示:**

  - `-105 <= num <= 105`
  - 在调用 `findMedian` 之前，数据结构中至少有一个元素
  - 最多 `5 * 104` 次调用 `addNum` 和 `findMedian`

- **时间复杂度**：
  - `addNum`：$O(\log N)$。每次插入和弹出操作都是对二叉堆的调整，代价是对数级别的。
  - `findMedian`：$O(1)$。中位数永远就在两个堆的嘴尖上（堆顶），看一眼直接返回，极速响应。
- **空间复杂度**：$O(N)$。需要两个堆合力装下数据流里的所有数字。

#### 💡 面试避坑与考点拓展（大厂夺命连环追问）

- **大厂进阶追问 1：“如果数据流中 99% 的数字都在 0 到 100 之间，你还用双堆吗？”**
  - **满分抢答（计数排序大显神威）**：这时候用堆就亏大了！既然数字范围极度紧凑（[0, 100]），我们应该直接开辟一个长度为 101 的**计数数组（Bucket）**！
  - 每次来一个数，对应的频次加 1（`count[num]++`），耗时 $O(1)$。
  - 寻找中位数时，我们维护一个全局总数 `N`，直接从 0 到 100 累加频次，找到第 $N/2$ 个数字对应的位置。因为桶的长度只有 101，这个遍历也是 $O(1)$ 的常数级！空间更是压缩到了极点。
- **大厂进阶追问 2：“如果 99% 的数字在 0 到 100 之间，但有 1% 的数字是不可预测的巨大超级大离群点（Outliers）呢？”**
  - **高级风控架构方案**：我们可以把两个方案缝合起来！
  - 用一个长度为 101 的数组记录 [0, 100] 内的正常数字，并记录低于 0 的个数和高于 100 的个数。
  - 对于那些极少数越界的超级大离群点，我们单独用**两个小规模的双堆**去挂载在两头。在寻找中位数时，先排除两边的离群点数量，再定位到中央的计数数组中。这种“主仓+边缘流控”的设计思想，直接对齐现代分布式大数据的风控模型。
