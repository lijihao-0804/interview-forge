### 📝 算法笔记：70. 爬楼梯 (Climbing Stairs)

-----

- **📌 核心题意**：

  假设你正在爬楼梯。需要 `n` 阶你才能到达楼顶。

  每次你可以爬 `1` 或 `2` 个台阶。你有多少种不同的方法可以爬到楼顶呢？

  **示例 1：**

  **输入：**n = 2
  **输出：**2
  **解释：**有两种方法可以爬到楼顶。
  1. 1 阶 + 1 阶
  2. 2 阶

  **示例 2：**

  **输入：**n = 3
  **输出：**3
  **解释：**有三种方法可以爬到楼顶。
  1. 1 阶 + 1 阶 + 1 阶
  2. 1 阶 + 2 阶
  3. 2 阶 + 1 阶

  **提示：**

  - `1 <= n <= 45`

- **🧠 思考过程**：

  1. **直觉与痛点（暴力的迷惘）**：

     很多人的第一反应是硬算组合数，或者用回溯去穷举所有可能（比如 `1,1,1`, `1,2`, `2,1`）。

     **痛点**：当 `n` 变大时（比如 `n = 45`），回溯树的规模会呈指数级爆炸，时间复杂度是 $O(2^n)$，你的程序会直接卡死。

  2. **降维破局（倒推法与重叠子问题）**：

     DP 的核心秘诀在于“向后看”**。 闭上眼睛想象一下：假如你现在已经神奇地站在了第 `n` 阶台阶上。请问，\**你是从哪里走过来的？\** 因为题目规定每次只能爬 1 阶或 2 阶，所以你**必定是从第 `n-1` 阶跨了 1 步上来，**或者**是从第 `n-2` 阶跨了 2 步上来！

     除了这两种可能，别无他法。

  3. **核心微操（状态转移方程的诞生）**：

     既然终局只有这两条路，那么：

     **爬到第 `n` 阶的方法总数 = 爬到第 `n-1` 阶的方法总数 + 爬到第 `n-2` 阶的方法总数！**

     这就是大名鼎鼎的状态转移方程：

     $dp[i] = dp[i-1] + dp[i-2]$

     这不就是斐波那契数列（Fibonacci sequence）吗？！我们只需要知道第 1 阶和第 2 阶的答案，就能像滚雪球一样，一路推导到第 `n` 阶！

- **🛠️ Java 规范代码（满分空间压缩版）**：
```Java
class Solution {
    public int climbStairs(int n) {
        // 边界防御：1 阶和 2 阶是基石，直接返回
        if (n <= 2) {
            return n;
        }

        // 传统 DP 需要开辟一个长度为 n+1 的数组，空间复杂度 O(n)
        // 但其实每次计算 dp[i]，我们只依赖它前面的【两个】状态！
        // 🌟 极致优化：我们只需要三个变量，交替滚动更新，将空间复杂度降维至 O(1)！
        
        int prev2 = 1; // 相当于 dp[1]：爬到第 1 阶有 1 种方法
        int prev1 = 2; // 相当于 dp[2]：爬到第 2 阶有 2 种方法 (1+1, 2)
        int current = 0; // 用来存当前阶数的方法总数

        // 从第 3 阶开始，一步步滚雪球到第 n 阶
        for (int i = 3; i <= n; i++) {
            current = prev1 + prev2; // 状态转移：当前 = 前一步 + 前两步
            
            // 准备进入下一轮循环，整体向前挪动一格
            prev2 = prev1; // 原来的 prev1 退位成 prev2
            prev1 = current; // 刚刚算出来的 current 成为新的 prev1
        }

        return current;
    }
}
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：$O(n)$。我们只需要一个简单的 `for` 循环，从 3 遍历到 `n`，极速出解。
  - **空间复杂度**：$O(1)$。这是这套代码最大的亮点。因为我们抛弃了 DP 数组，只用了 `prev1`, `prev2`, `current` 三个变量滚动，内存消耗恒定。

#### 💡 面试避坑与考点拓展（大厂的数学暴击）

1. **大厂追问 1：“如果我非要用递归写，怎么才能不超时？”**

   - **满分抢答（记忆化搜索）**：单纯的递归会产生海量的**重复计算**（比如算 `dp(5)` 时算了 `dp(3)`，算 `dp(4)` 时又算了一遍 `dp(3)`）。
   - 只要我们在递归外面挂一个**备忘录（数组或 HashMap）**。每次算出一个阶梯的答案，就记在备忘录里；下次再遇到，直接查表返回。这叫“带备忘录的自顶向下递归”，它的时间复杂度同样能优化到 $O(n)$。

2. **大厂终极绝杀：“你能把时间复杂度优化到 $O(\log n)$ 吗？”**

   - **满分降维打击（矩阵快速幂）**：如果你遇到字节跳动或者极致追求算法的面试官，抛出这个解法绝对封神。

   - 既然是斐波那契数列，我们可以将其转化为矩阵乘法的形式：

     $\begin{bmatrix} dp[n] \\ dp[n-1] \end{bmatrix} = \begin{bmatrix} 1 & 1 \\ 1 & 0 \end{bmatrix}^{n-2} \begin{bmatrix} dp[2] \\ dp[1] \end{bmatrix}$

   - 利用**快速幂算法**（类似二分法求 $x^n$），可以在 $O(\log n)$ 的时间内算出该矩阵的 `n-2` 次方！这在 $n$ 高达几百亿、要求取模的极速场景下，是降维打击。

### 📝 算法笔记：118. 杨辉三角 (Pascal's Triangle)

-----

- **📌 核心题意**：

  给定一个非负整数 *`numRows`，*生成「杨辉三角」的前 *`numRows`*行。

  在**「杨辉三角」**中，每个数是它左上方和右上方的数的和。

  **示例 1:**

  **输入:** numRows = 5
  **输出:** [[1],[1,1],[1,2,1],[1,3,3,1],[1,4,6,4,1]]

  **示例 2:**

  **输入:** numRows = 1
  **输出:** [[1]]

  **提示:**

  - `1 <= numRows <= 30`

- **🧠 思考过程**：

  1. **直觉与痛点（形与实的转换）**：

     杨辉三角在视觉上是一个等腰三角形，但在计算机内存中，我们很难直接建一个等腰三角形。

     **破局点**：把它全部**向左对齐**，变成一个“直角三角形”（也就是每一行长度不断加一的二维数组/嵌套列表）。

     排版后你会发现规律：

     `[1]`

     `[1, 1]`

     `[1, 2, 1]`

     `[1, 3, 3, 1]`

  2. **寻找规律（状态转移方程）**：

     经过左对齐后，我们可以极其清晰地总结出两条铁律：

     - **边界铁律**：每一行的第一位（索引 `0`）和最后一位（索引 `i`），永远是 `1`。

     - **内部铁律**：对于中间的任何一个数字，它的值等于**上一行的同一列**与**上一行的前一列**之和。

       转换为极其标准的状态转移方程：

       $dp[i][j] = dp[i-1][j-1] + dp[i-1][j]$

  3. **核心微操（两层循环，步步为营）**：

     外层循环 `i` 控制行数（从 0 到 `numRows - 1`）。

     内层循环 `j` 控制每一行里面的元素（从 0 到 `i`）。

     根据 `j` 是不是首尾位置，分别塞入 `1` 或者执行相加公式即可。

- **🛠️ Java 规范代码（满分嵌套列表版）**：
```Java
import java.util.ArrayList;
import java.util.List;

class Solution {
    public List<List<Integer>> generate(int numRows) {
        // 创建一个用于存储整个大三角的嵌套列表
        List<List<Integer>> triangle = new ArrayList<>();

        // 边界防御
        if (numRows == 0) {
            return triangle;
        }

        // 外层循环：逐行构建杨辉三角
        for (int i = 0; i < numRows; i++) {
            // 准备一个新列表，用来装当前这一行的数字
            List<Integer> row = new ArrayList<>();

            // 内层循环：逐个生成当前行的数字
            // 注意：第 i 行有 i + 1 个数字，所以 j <= i
            for (int j = 0; j <= i; j++) {
                // 边界铁律：每一行的开头和结尾必定是 1
                if (j == 0 || j == i) {
                    row.add(1);
                } 
                // 内部铁律：中间的数字等于上一行的 (j-1) 和 (j) 位置之和
                else {
                    // 🌟 核心状态转移：向上面的行去借数据
                    // previousRow 就是 triangle.get(i - 1)
                    List<Integer> previousRow = triangle.get(i - 1);
                    int leftParent = previousRow.get(j - 1);
                    int rightParent = previousRow.get(j);
                    
                    row.add(leftParent + rightParent);
                }
            }
            
            // 当前行构建完毕，装入大三角中
            triangle.add(row);
        }

        return triangle;
    }
}
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：$O(numRows^2)$。我们需要生成 $\frac{numRows \times (numRows + 1)}{2}$ 个元素，每个元素的计算时间是 $O(1)$ 的加法，属于完美的等差数列求和。
  - **空间复杂度**：$O(1)$（如果不考虑返回值的空间）。如果算上用来存放结果的嵌套列表，空间复杂度为 $O(numRows^2)$。

#### 💡 面试避坑与考点拓展（大厂的数学连环计）

1. **大厂追问 1：“如果我不需要整个三角形，我只想要第 `rowIndex` 行，并且【只允许你使用 $O(rowIndex)$ 的额外空间】，该怎么做？”（对应力扣 119 题：杨辉三角 II）**
   - **满分抢答（滚动数组的艺术）**：这也是大厂最爱考的 DP 空间压缩技巧！
   - 因为第 `i` 行的计算**仅仅依赖于第 `i-1` 行**，更早的行全都没用了。所以我们只需要一个一维数组。
   - **致命细节（倒序遍历）**：更新一维数组时，必须**从后往前遍历**（`j` 从 `i-1` 递减到 `1`）。因为如果你从前往后更新，你刚算出来的 `dp[j]` 覆盖了旧数据，等会儿算 `dp[j+1]` 需要用到旧的 `dp[j]` 时，数据已经被污染了！倒序遍历是原地压缩空间的神级手法。
2. **大厂终极绝杀：“你能用纯数学公式，在 $O(n)$ 时间内直接算出第 `rowIndex` 行的每一个数吗？”**
   - **满分降维打击（组合数学公式）**：杨辉三角的本质其实是**二项式展开的系数**，也就是大名鼎鼎的**组合数 $C_n^m$**！
   - 第 $n$ 行的第 $m$ 个数（索引从 0 开始），其值严格等于 $C_n^m$。
   - 根据组合数的递推公式：$C_n^m = C_n^{m-1} \times \frac{n - m + 1}{m}$。我们甚至不需要哪怕一次加法，直接用乘除法就能在 $O(n)$ 内顺推生成特定行的所有数字！

### 📝 算法笔记：198. 打家劫舍 (House Robber)

-----

- **📌 核心题意**：

  你是一个专业的小偷，计划偷窃沿街的房屋。每间房内都藏有一定的现金，影响你偷窃的唯一制约因素就是相邻的房屋装有相互连通的防盗系统，**如果两间相邻的房屋在同一晚上被小偷闯入，系统会自动报警**。

  给定一个代表每个房屋存放金额的非负整数数组，计算你**不触动警报装置的情况下**，一夜之内能够偷窃到的最高金额。

  **示例 1：**

  **输入：**[1,2,3,1]
  **输出：**4
  **解释：**偷窃 1 号房屋 (金额 = 1) ，然后偷窃 3 号房屋 (金额 = 3)。
       偷窃到的最高金额 = 1 + 3 = 4 。

  **示例 2：**

  **输入：**[2,7,9,3,1]
  **输出：**12
  **解释：**偷窃 1 号房屋 (金额 = 2), 偷窃 3 号房屋 (金额 = 9)，接着偷窃 5 号房屋 (金额 = 1)。
       偷窃到的最高金额 = 2 + 9 + 1 = 12 。

  **提示：**

  - `1 <= nums.length <= 100`
  - `0 <= nums[i] <= 400`

- **🧠 思考过程**：

  1. **直觉与痛点（贪心的滑铁卢）**：

     很多同学的第一反应是贪心法：我把奇数下标的房子全偷了，或者把偶数下标的房子全偷了，哪个大取哪个。

     **痛点**：这种“隔一个偷一个”的固定步长贪心是错误的！比如 `[2, 1, 1, 2]`，如果你按奇偶偷，最多只能拿到 `2+1=3`。但如果你偷第 0 个和第 3 个（不按固定步长），你能拿到 `2+2=4`。

  2. **降维破局（一切取决于今晚偷不偷）**：

     假设我们走到了第 `i` 间房子，面对这笔钱，小偷的脑海里会有两个小人打架：

     - **方案 A（今晚干一票）**：既然决定偷第 `i` 间房，那第 `i-1` 间房绝对不能碰。所以我能拿到的总金额是：**第 `i` 间房的钱 + 走到第 `i-2` 间房时的最高收益**。
     - **方案 B（今晚忍一手）**：我觉得第 `i-1` 间房太香了，我已经偷了。为了不报警，今天这间房我绝对不能偷。所以我能拿到的总金额是：**走到第 `i-1` 间房时的最高收益（维持原样）**。

  3. **核心微操（状态转移方程）**：

     究竟偷还是不偷？当然是看哪个收益大！

     这就得出了极度优美的状态转移方程：

     $dp[i] = \max(dp[i-1],\ dp[i-2] + nums[i])$

- **🛠️ Java 规范代码（满分滚动变量空间压缩版）**：
```Java
class Solution {
    public int rob(int[] nums) {
        // 边界防御：如果没有房子，一分钱也偷不到；只有一间房子，只能偷这一间
        if (nums == null || nums.length == 0) return 0;
        if (nums.length == 1) return nums[0];

        // 🌟 空间压缩技巧（同爬楼梯）：
        // 我们计算当前房子的最高收益时，只依赖于“前一间”和“前两间”的最高收益
        // 所以我们不需要开辟 O(N) 的 dp 数组，用两个变量滚动即可！
        
        int prev2 = nums[0]; // 相当于 dp[0]：只有第 0 间房时的最高收益
        int prev1 = Math.max(nums[0], nums[1]); // 相当于 dp[1]：有第 0 和 1 间房时的最高收益

        // 当前走到第 i 间房的最高收益
        int current = prev1;

        // 从第 2 间房开始，一路扫荡过去
        for (int i = 2; i < nums.length; i++) {
            // 核心状态转移：不偷这家(prev1) vs 偷这家(prev2 + 这家的钱)
            current = Math.max(prev1, prev2 + nums[i]);
            
            // 算完当前房子后，准备往前走一步，变量全体滚动
            prev2 = prev1;
            prev1 = current;
        }

        return current;
    }
}
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：$O(N)$。只需一次极其轻量的 `for` 循环遍历整条街。
  - **空间复杂度**：$O(1)$。没有使用 `dp` 数组，仅仅用了三个整型变量来保存历史状态。

#### 💡 面试避坑与考点拓展（大厂的连环计）

1. **大厂追问 1：“如果这些房子不是排成一条直线，而是围成了一个【首尾相连的环】呢？”（对应力扣 213 题：打家劫舍 II）**
   - **满分降维打击（破环成链）**：这绝对是面试里最喜欢连带考的一道题。
   - 既然首尾相连，说明**第一间房和最后一间房，你绝对不可能同时偷**。
   - 破局方法：把问题拆分成两个普通的直线打家劫舍！
     - **方案一**：我硬着头皮把第一间房纳入考虑范围，那最后一间房就当它不存在（算区间 `[0, n-2]` 的最高收益）。
     - **方案二**：我硬着头皮把最后一间房纳入考虑范围，那第一间房就当它不存在（算区间 `[1, n-1]` 的最高收益）。
   - 最后，比较这两个方案，谁大就选谁！只需要复用我们上面的代码逻辑跑两遍即可。
2. **大厂追问 2：“如果房子不是一条街，而是排成了一棵【二叉树】，并且相连的父子节点不能同时偷，怎么办？”（对应力扣 337 题：打家劫舍 III - 中等偏难）**
   - **满分抢答（树形 DP）**：这时候一维 DP 就不管用了。我们需要对二叉树进行**后序遍历**。
   - 每个节点返回一个长度为 2 的数组 `res`：
     - `res[0]` 表示**不偷当前节点**时，子树的最大收益（等于左孩子各种情况的最大值 + 右孩子各种情况的最大值）。
     - `res[1]` 表示**偷当前节点**时，子树的最大收益（等于当前节点的钱 + 不偷左孩子的收益 + 不偷右孩子的收益）。
   - 把“偷与不偷”的状态直接挂载在递归树的节点上，这是大厂极度偏爱的树形 DP 终极模板。

### 📝 算法笔记：279. 完全平方数 (Perfect Squares)

-----

- **📌 核心题意**：

  给你一个整数 `n` ，返回 *和为 `n` 的完全平方数的最少数量* 。

  **完全平方数** 是一个整数，其值等于另一个整数的平方；换句话说，其值等于一个整数自乘的积。例如，`1`、`4`、`9` 和 `16` 都是完全平方数，而 `3` 和 `11` 不是。

  **示例 1：**

  **输入：**n = `12`
  **输出：**3 
  **解释：**`12 = 4 + 4 + 4`

  **示例 2：**

  **输入：**n = `13`
  **输出：**2
  **解释：**`13 = 4 + 9`

  **提示：**

  - `1 <= n <= 104`

- **🧠 思考过程**：

  1. **直觉与痛点（贪心算法的滑铁卢）**：

     很多人的第一反应是**贪心法**：既然要数量最少，那我就每次挑**尽可能大的完全平方数**去减！

     比如 `n = 12`，比 12 小的最大平方数是 `9`。

     `12 - 9 = 3`。剩下的 `3` 只能用三个 `1` 来凑（`1+1+1`）。

     所以贪心法得出结论：需要 `4` 个数（$9 + 1 + 1 + 1$）。

     **痛点**：真的是 4 个吗？其实 `12 = 4 + 4 + 4`，只需要 **`3`** 个数！贪心法因为过于短视（只顾着眼前的最大数字 9），完美错过了全局最优解。

  2. **降维破局（动态规划的上帝视角）**：

     既然贪心会翻车，我们就必须老老实实地试探所有的可能性。

     这其实就是一个“换硬币”游戏（完全背包）：你手头有面值为 $1, 4, 9, 16...$ 的无限量硬币，怎么凑出金额 $n$ 使用的硬币最少？

     我们定义一个数组 `dp[i]`：**凑出数字 `i` 所需要的最少完全平方数**。

  3. **核心微操（状态转移方程）**：

     要算出 `dp[i]`，我们可以尝试从 `i` 中减去一个完全平方数 $j^2$（其中 $j^2 \le i$）。

     减去之后，剩下的数字就是 $i - j^2$。而凑出 $i - j^2$ 的最少数量，我们早就存在 `dp[i - j*j]` 里了！

     所以，我们只需遍历所有可能的 $j$，找出最小的那一个：

     $dp[i] = \min(dp[i],\ dp[i - j \times j] + 1)$

- **🛠️ Java 规范代码（满分完全背包版）**：
```java
import java.util.Arrays;

class Solution {
    public int numSquares(int n) {
        // dp[i] 表示：和为 i 的完全平方数的最少数量
        int[] dp = new int[n + 1];
        
        // 🌟 初始化：因为要求最小值，所以先把所有位置填满“无穷大”
        // 只有 dp[0] = 0，因为凑出数字 0 不需要任何完全平方数
        Arrays.fill(dp, Integer.MAX_VALUE);
        dp[0] = 0;

        // 外层循环：遍历背包容量（我们要凑的数字 i，从 1 到 n）
        for (int i = 1; i <= n; i++) {
            // 内层循环：遍历物品（完全平方数 j*j，只要它不超过当前的背包容量 i）
            for (int j = 1; j * j <= i; j++) {
                // 🌟 核心状态转移方程：
                // 方案 A：保持原样 dp[i]
                // 方案 B：拿一个当前的平方数 j*j，剩下的数字交由历史结果 dp[i - j*j] 解决
                dp[i] = Math.min(dp[i], dp[i - j * j] + 1);
            }
        }

        return dp[n];
    }
}
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：$O(n \sqrt{n})$。外层循环执行 $n$ 次，内层循环对于每个 $i$，最多执行 $\sqrt{i}$ 次。总体时间复杂度极低，能够轻松应对百万级别的数据。
  - **空间复杂度**：$O(n)$。需要一个长度为 $n+1$ 的 `dp` 数组来记录历史状态。

#### 💡 面试避坑与考点拓展（大厂的数学暴击）

1. **大厂追问 1：“除了 DP，这道题能用图论解决吗？”**
   - **满分抢答（BFS 最短路径法）**：绝对可以！这其实是一个求**最短路径**的问题。
   - 我们把数字 `n` 当作起点，`0` 当作终点。每次可以走出的“步长”必须是完全平方数（1, 4, 9...）。
   - 用广度优先搜索（BFS），像水波纹一样一层层向外扩散。因为 BFS 天然具备“先找到的必定是最短层数”的特性，所以只要 BFS 到达了 0，当前的层数（步数）就是最少数量！
2. **大厂终极绝杀：“你能把时间复杂度降到 $O(\sqrt{n})$ 甚至 $O(1)$ 吗？”**
   - **满分降维打击（四平方和定理）**：如果你遇到的是极其硬核的算法官，抛出这个定理绝对能直接结束面试。
   - 数学界有一个著名的**拉格朗日四平方和定理**：任何一个正整数都可以表示为至多四个正整数的平方和。
   - 也就是说，这道题的答案**只可能是 1, 2, 3, 4** 中的一个！
     - **答案是 1**：如果 $n$ 本身就是完全平方数。
     - **答案是 4**：当且仅当 $n$ 满足勒让德三平方和定理的特殊形式 $n = 4^a(8b+7)$ 时。
     - **答案是 2**：枚举所有的 $j^2$，看看 $n - j^2$ 是不是完全平方数。
     - 排除以上所有情况，**答案就是 3**。
   - 用纯数学定理去秒杀，时间复杂度直接降维到 $O(\sqrt{n})$！

### 📝 算法笔记：322. 零钱兑换 (Coin Change)

-----

- **📌 核心题意**：

  给你一个整数数组 `coins` ，表示不同面额的硬币；以及一个整数 `amount` ，表示总金额。

  计算并返回可以凑成总金额所需的 **最少的硬币个数** 。如果没有任何一种硬币组合能组成总金额，返回 `-1` 。

  你可以认为每种硬币的数量是无限的。

  **示例 1：**

  **输入：**coins = `[1, 2, 5]`, amount = `11`
  **输出：**`3` 
  **解释：**11 = 5 + 5 + 1

  **示例 2：**

  **输入：**coins = `[2]`, amount = `3`
  **输出：**-1

  **示例 3：**

  **输入：**coins = [1], amount = 0
  **输出：**0

  **提示：**

  - `1 <= coins.length <= 12`
  - `1 <= coins[i] <= 231 - 1`
  - `0 <= amount <= 104`

- **🧠 思考过程**：

  1. **直觉与痛点（贪心的终极滑铁卢）**：

     人在现实生活中找零钱，本能用的是贪心算法：先找最大的面值，找不开再用小的。

     **痛点**：这种直觉在算法里是致命的！假设硬币面值是 `[1, 3, 4]`，你要凑的金额是 `6`。

     - **贪心法**：先拿最大的 `4`，还剩 `2`。`2` 只能用两个 `1` 凑。总共需要 **3 枚**硬币（`4 + 1 + 1`）。

     - **真实最优解**：拿两个 `3`！总共只需要 **2 枚**硬币（`3 + 3`）。

       贪心算法因为目光短浅，只看到了局部的最大面值，错失了全局的最优解。

  2. **降维破局（动态规划的全局视野）**：

     我们要凑出金额 `amount`，必须老老实实地从小到大推导。

     定义 `dp[i]` 为：**凑出金额 `i` 所需要的最少硬币数量**。

  3. **核心微操（状态转移方程）**：

     假设我们要算 `dp[6]`，我们手里有 `[1, 3, 4]` 三种硬币。

     如果要凑出 6 块钱，我们只有三种“最后一步”的选法：

     - 选 1 块钱：那剩下的 5 块钱怎么凑？答案早就存在 `dp[5]` 里了！总数就是 `dp[5] + 1`。

     - 选 3 块钱：剩下的 3 块钱怎么凑？看 `dp[3]`！总数是 `dp[3] + 1`。

     - 选 4 块钱：剩下的 2 块钱怎么凑？看 `dp[2]`！总数是 `dp[2] + 1`。

       所以：$dp[6] = \min(dp[5], dp[3], dp[2]) + 1$。

       推广到通用公式：$dp[i] = \min(dp[i],\ dp[i - coin] + 1)$

- **🛠️ Java 规范代码（满分防溢出技巧版）**：
```Java
import java.util.Arrays;

class Solution {
    public int coinChange(int[] coins, int amount) {
        // 边界防御
        if (amount == 0) return 0;
        
        // dp[i] 表示凑出金额 i 需要的最少硬币数量
        int[] dp = new int[amount + 1];
        
        // 🌟 核心工程技巧（防溢出魔法）：
        // 为什么不把初始值设为 Integer.MAX_VALUE？
        // 因为在状态转移时有 dp[i - coin] + 1。如果它是 MAX_VALUE，再加 1 就会【整型溢出】变成负数！
        // 因为凑成 amount 最多也就是全部用 1 块钱，需要 amount 个。
        // 所以 amount + 1 绝对是一个永远达不到的“安全无穷大”！
        int max = amount + 1;
        Arrays.fill(dp, max);
        
        // 基底状态：凑出 0 元需要 0 个硬币
        dp[0] = 0;
        
        // 外层循环：从小到大遍历所有要凑的金额 i
        for (int i = 1; i <= amount; i++) {
            // 内层循环：尝试每一种硬币
            for (int coin : coins) {
                // 只有当硬币面值小于等于当前要凑的金额时，才能用这个硬币
                if (coin <= i) {
                    // 状态转移：保持原样，或者用掉这枚硬币加上剩余金额的最优解
                    dp[i] = Math.min(dp[i], dp[i - coin] + 1);
                }
            }
        }
        
        // 如果最后金额 amount 的状态还是那个初始的“无穷大”，说明根本凑不出来，返回 -1
        return dp[amount] > amount ? -1 : dp[amount];
    }
}
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：$O(S \times n)$。其中 $S$ 是金额 `amount`，$n$ 是硬币的面额数。我们要计算从 1 到 $S$ 的所有金额，每个金额都要遍历一次硬币数组。
  - **空间复杂度**：$O(S)$。我们需要一个长度为 `amount + 1` 的 `dp` 数组来存储所有的子状态。

#### 💡 面试避坑与考点拓展（大厂的死亡细节）

1. **踩坑警告：为什么 `for` 循环的顺序是先遍历金额 `i`，再遍历硬币 `coin`？可以反过来吗？**
   - **满分避坑指南**：在这道题里，**完全可以反过来**！
   - 因为这道题求的是**硬币的最少个数**，而不是排列组合的种类数。不管你是“先拿 1 块再拿 3 块”，还是“先拿 3 块再拿 1 块”，总数都是 2 枚。
   - **拓展**：如果是力扣另一道题「518. 零钱兑换 II」（求凑出金额的**组合种类数**），那就**必须先遍历硬币，再遍历金额**，否则会把 `(1,3)` 和 `(3,1)` 算成两种不同的组合（变成排列数了）！这点一定要牢记。
2. **大厂追问：“如果这道题我允许用 DFS（回溯）+ 贪心剪枝，能比 DP 快吗？”**
   - **高级风控对策**：可以！这是一个非常著名的优化策略。
   - 我们先对 `coins` 数组从大到小排序。然后用 DFS 去搜索，优先用最大的硬币去填。
   - 只要搜到一个合法的组合，就把它的硬币数记录下来作为 `minCoins`。
   - 接下来在其他分支搜索时，如果发现**当前的硬币数 + 剩下金额全用目前能用的最大面值去凑，都超过了 `minCoins`**，就立刻剪枝（放弃这条路）。这在某些特定的测试用例下，能比 DP 跑得更快，但代码实现难度极高，面试时优先手写 DP 稳妥过关。

### 📝 算法笔记：139. 单词拆分 (Word Break)

-----

- **📌 核心题意**：

  给你一个字符串 `s` 和一个字符串列表 `wordDict` 作为字典。如果可以利用字典中出现的一个或多个单词拼接出 `s` 则返回 `true`。

  **注意：**不要求字典中出现的单词全部都使用，并且字典中的单词可以重复使用。

  **示例 1：**

  **输入:** s = "leetcode", wordDict = ["leet", "code"]
  **输出:** true
  **解释:** 返回 true 因为 "leetcode" 可以由 "leet" 和 "code" 拼接成。

  **示例 2：**

  **输入:** s = "applepenapple", wordDict = ["apple", "pen"]
  **输出:** true
  **解释:** 返回 true 因为 "applepenapple" 可以由 "apple" "pen" "apple" 拼接成。
       注意，你可以重复使用字典中的单词。

  **示例 3：**

  **输入:** s = "catsandog", wordDict = ["cats", "dog", "sand", "and", "cat"]
  **输出:** false

  **提示：**

  - `1 <= s.length <= 300`
  - `1 <= wordDict.length <= 1000`
  - `1 <= wordDict[i].length <= 20`
  - `s` 和 `wordDict[i]` 仅由小写英文字母组成
  - `wordDict` 中的所有字符串 **互不相同**

- **🧠 思考过程**：

  1. **直觉与痛点（DFS 回溯的灾难）**：

     很多人的直觉是写一个回溯算法：从头开始截取字符串，如果截取到的单词在字典里，就对剩下的字符串继续递归。

     **痛点**：假设 `s = "aaaaab"`，字典是 `["a", "aa", "aaa"]`。你会产生无数种组合（比如先切 `a` 再切 `aa`，或者先切 `aa` 再切 `a`），然后走到最后发现都没有 `b`，全部失败回溯。这种做法会产生极度庞大的**重叠子问题**，时间复杂度呈指数级 $O(2^N)$，必定超时。

  2. **破局思路（寻找“历史的锚点”）**：

     我们换个思路：与其漫无目的地往后切，不如“向后看”**。 假设字符串长度为 `i`。要想知道前 `i` 个字符能不能被成功拆分，我们只需要在 `0` 到 `i` 之间寻找一个**切割点 `j`**。 只要满足以下**两个条件同时成立，前 `i` 个字符就一定能被完美拆分：

     - **条件 1**：前 `j` 个字符构成的子串能够被成功拆分（这是历史记录，早就查好了！）。
     - **条件 2**：从 `j` 到 `i` 剩下的这段子串，刚好在字典里！

  3. **核心微操（状态转移方程）**：

     我们定义一个布尔数组 `dp[i]`：表示字符串 `s` 的前 `i` 个字符能否被拆分。

     状态转移方程：

     $dp[i] = \text{dp}[j] \ \&\&\ \text{wordDict.contains}(s[j..i])$

     只要在 `0` 到 `i` 之间找到**任何一个**满足条件的 `j`，`dp[i]` 就直接定为 `true`，并停止当前 `i` 的寻找（因为只要能切开就行，不需要穷举所有切法）。

- **🛠️ Java 规范代码（满分哈希表提速版）**：
```Java

import java.util.HashSet;
import java.util.List;
import java.util.Set;

class Solution {
    public boolean wordBreak(String s, List<String> wordDict) {
        // 1. 将字典转为 HashSet，把 O(N) 的查找时间降维到 O(1)
        Set<String> dict = new HashSet<>(wordDict);
        
        // dp[i] 表示：字符串 s 的前 i 个字符能否被成功拆分
        boolean[] dp = new boolean[s.length() + 1];
        
        // 🌟 边界初始化：空字符串被认为是“可以被拆分”的基石
        // 如果没有 dp[0] = true，后面的推导将无从借力
        dp[0] = true;
        
        // 外层循环：i 表示当前正在考察的字符串前缀长度
        for (int i = 1; i <= s.length(); i++) {
            // 内层循环：j 表示寻找的切割点
            // 从 0 遍历到 i-1，尝试把前 i 个字符切成 [0..j] 和 [j..i] 两半
            for (int j = 0; j < i; j++) {
                // 如果前半段是合法的，并且后半段在字典里
                if (dp[j] && dict.contains(s.substring(j, i))) {
                    dp[i] = true;
                    break; // 只要找到一种合法的切法，当前 i 就搞定了，直接 break
                }
            }
        }
        
        // 返回整个字符串能否被拆分
        return dp[s.length()];
    }
}
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：$O(N^3)$。外层循环 $N$ 次，内层循环 $N$ 次。在 Java 中，`s.substring(j, i)` 截取子串的操作底层需要复制字符，耗时 $O(N)$。所以整体是 $N \times N \times N = O(N^3)$。
  - **空间复杂度**：$O(N + M)$。`dp` 数组占用了 $O(N)$ 的空间，`HashSet` 占用了 $O(M)$ 的空间（$M$ 为字典中所有字符的总长度）。

#### 💡 面试避坑与考点拓展（大厂的性能压榨）

1. **踩坑警告：`s.substring(j, i)` 的隐形性能杀手**
   - 很多同学以为时间复杂度是 $O(N^2)$，因为看到了两层 `for` 循环。但在面试时，如果你不主动点出 `substring` 也有时间开销（$O(N)$），面试官会认为你对语言底层不够了解。
2. **大厂追问：“既然时间复杂度是 $O(N^3)$，如果字典里的单词都很短，但被拆分的字符串极其长，这段代码有优化空间吗？”**
   - **满分抢答（极速剪枝优化）**：绝对有！我们可以提前找出字典里“最长单词的长度（maxLength）”。
   - 在内层寻找切割点 `j` 时，根本不需要从 `0` 扫到 `i-1`！
   - 我们只需要检查从 `i - maxLength` 到 `i - 1` 的区间即可。因为如果后半段的长度超过了字典里最长的单词，那它绝对不可能在字典里！
   - 这个优化能把内层循环降维成一个常数（最大单词长度），从而将时间复杂度压榨到极尽完美的 $O(N^2)$。

### 📝 算法笔记：300. 最长递增子序列 (Longest Increasing Subsequence)

-----

- **📌 核心题意**：

  给你一个整数数组 `nums` ，找到其中最长严格递增子序列的长度。

  **子序列**是由数组派生而来的序列，删除（或不删除）数组中的元素而不改变其余元素的顺序。例如，`[3,6,2,7]` 是数组 `[0,3,1,6,2,2,7]` 的子序列。

  **示例 1：**

  **输入：**nums = [10,9,2,5,3,7,101,18]
  **输出：**4
  **解释：**最长递增子序列是 [2,3,7,101]，因此长度为 4 。

  **示例 2：**

  **输入：**nums = [0,1,0,3,2,3]
  **输出：**4

  **示例 3：**

  **输入：**nums = [7,7,7,7,7,7,7]
  **输出：**1

  **提示：**

  - `1 <= nums.length <= 2500`
  - `-104 <= nums[i] <= 104`

  **进阶：**

  - 你能将算法的时间复杂度降低到 `O(n log(n))` 吗?

- **🧠 思考过程**：

  1. **直觉与痛点（为什么不能纯贪心？）**：

     假设数组是 `[10, 9, 2, 5, 3, 7, 101, 18]`。

     如果纯贪心，遇到大的就选，你可能会选出 `[10, 101]`（长度 2），但这显然不是最长的。因为你过早地选了太大的数字，透支了未来的潜力。

  2. **破局思路（动态规划的“强制结尾”哲学）**：

     我们要寻找最长递增子序列，就必须回答一个核心问题：“当我们遇到数字 `nums[i]` 时，它能接在哪些历史数字的后面？”

     我们定义 `dp[i]` 为：**以 `nums[i]` 结尾的**最长递增子序列的长度。

     *注意*：一定要强制以 `nums[i]` 结尾！因为如果不指明结尾是谁，后面新来的数字根本不知道自己能不能拼上去。

  3. **核心微操（状态转移方程）**：

     假设我们走到了索引 `i`，数字是 `nums[i]`。

     我们回头看前面所有的索引 `j`（`0 <= j < i`）：

     只要前面的数字比我小（`nums[j] < nums[i]`），我就可以毫无顾忌地接在它后面！

     接上去之后，长度就是 `dp[j] + 1`。

     我们遍历前面所有能接的 `j`，找出能拼出的最大长度：

     $dp[i] = \max(dp[i], dp[j] + 1)$

- **🛠️ Java 规范代码（满分 DP 基础版）**：
```Java
import java.util.Arrays;

class Solution {
    public int lengthOfLIS(int[] nums) {
        if (nums == null || nums.length == 0) return 0;
        
        // dp[i] 表示以 nums[i] 结尾的最长递增子序列的长度
        int[] dp = new int[nums.length];
        // 初始化：每个数字本身自己就能构成一个长度为 1 的子序列
        Arrays.fill(dp, 1);
        
        int maxLength = 1;
        
        // 外层循环：确定当前要计算的 dp[i]（即以 nums[i] 结尾）
        for (int i = 1; i < nums.length; i++) {
            // 内层循环：回头看前面所有的历史数字
            for (int j = 0; j < i; j++) {
                // 如果当前数字大于历史数字，说明可以接在它后面！
                if (nums[i] > nums[j]) {
                    dp[i] = Math.max(dp[i], dp[j] + 1);
                }
            }
            // 挑战全局最长记录
            maxLength = Math.max(maxLength, dp[i]);
        }
        
        return maxLength;
    }
}
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：$O(N^2)$。两层 `for` 循环嵌套，对于每个元素，都要回头扫一遍前面的所有元素。
  - **空间复杂度**：$O(N)$。需要一个长度为 $N$ 的 `dp` 数组。

#### 💡 面试避坑与考点拓展（大厂的绝杀降维打击）

- **大厂终极追踪：“这道题的 $O(N^2)$ 只是及格，你能写出 $O(N \log N)$ 的解法吗？”**
  - **满分抢答（贪心 + 二分查找的“扑克牌算法”）**：
  - 核心哲学是：**“为了让子序列尽可能长，我们要让序列最后的一个数字尽可能小，这样才能给未来留下更大的上涨空间！”**
  - 我们维护一个名为 `tails` 的数组。`tails[i]` 存放的是：**长度为 `i+1` 的所有递增子序列中，结尾最小的那个数字。**
  - 遍历原数组 `nums`，对于每一个新来的数字 `x`：
    1. 如果 `x` 比 `tails` 里面所有的数字都大，太棒了，直接追加在 `tails` 后面，最长递增子序列的长度 `+1`。
    2. 🌟 如果 `x` 没有全部人大，那就**在 `tails` 里用二分查找，找到第一个大于等于 `x` 的数字，并用 `x` 替换掉它！**
  - **为什么可以替换？** 因为用一个更小的数字去替换原来的大数字，相当于“拉低了后续接盘的门槛”！序列长度没变，但未来更容易接上新数字了。
  - *致命纠错*：面试时一定要提醒面试官，`tails` 数组的最终形态**并不一定是真实的最长递增子序列**，它只是正确记录了最长子序列的**长度**！

### 📝 进阶算法笔记：300. 最长递增子序列 ($O(N \log N)$ 贪心+二分)

-----

- **🧠 核心哲学（降低门槛，留足后路）**：

  假设你正在收集递增的数字。

  如果你手里有一个长度为 3 的序列 `[2, 5, 9]`，这时候突然来了一个 `7`。

  你能把 `7` 接在 `9` 后面吗？不能。

  但是！如果你把序列里的 `9` **替换**成 `7`，变成 `[2, 5, 7]`，序列的长度依然是 3，可是你的**结尾门槛被拉低了**！

  未来如果来了一个 `8`，它接不上 `9`，但能接在 `7` 后面！

  **核心思想**：为了让子序列尽可能长，我们要让相同长度的子序列的**末尾数字尽可能小**。

- **🛠️ 数据结构（神奇的 `tails` 数组）**：

  我们维护一个 `tails` 数组。

  **`tails[i]` 的定义极其严谨：它是所有长度为 `i+1` 的递增子序列中，结尾最小的那个数字。**

  *极其神奇的特性*：这个 `tails` 数组天然就是**严格递增**的！这也就意味着，我们可以对它使用极速的**二分查找**！

- **🎮 核心微操（两步走战略）**：

  遍历原数组 `nums`，对于每一个新来的数字 `num`：

  1. **如果它比 `tails` 里所有的数字都大**：太好了，它直接拓展了我们的最长纪录！把它追加在 `tails` 数组的最后面，总长度 `+1`。
  2. **如果它没有比所有人大**：在 `tails` 数组里，用**二分查找**找到**第一个大于等于 `num` 的数字**，并毫不留情地用 `num` 去**替换**掉它！（这就是前面说的“拉低门槛”操作）。

- **💻 Java 规范代码（满分二分查找版）**：
```Java
class Solution {
    public int lengthOfLIS(int[] nums) {
        // tails 数组存储：长度为 i+1 的最长递增子序列的最小结尾数字
        int[] tails = new int[nums.length];
        // res 记录当前 tails 数组的实际有效长度（也就是当前的最长子序列长度）
        int res = 0;
        
        for (int num : nums) {
            // 在 tails 数组的有效范围 [0, res) 内进行二分查找
            int left = 0;
            int right = res;
            
            while (left < right) {
                int mid = left + (right - left) / 2;
                if (tails[mid] < num) {
                    // 如果 mid 处的值比当前数字小，说明应该往右半区找
                    left = mid + 1;
                } else {
                    // 如果 mid 处的值大于等于当前数字，往左半区收缩
                    right = mid;
                }
            }
            
            // 🌟 核心操作：
            // 1. 如果 left 走到了 res（说明 num 比 tails 里所有的数都大），追加它！
            // 2. 如果 left 停在中间（说明找到了第一个大于等于 num 的数），替换它！
            tails[left] = num;
            
            // 如果是追加操作，我们的有效长度 res 就增加了
            if (left == res) {
                res++;
            }
        }
        
        // 最终 tails 数组的有效长度，就是最长递增子序列的长度
        return res;
    }
}
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：**$O(N \log N)$**。外层循环遍历 `nums` 数组，执行 $N$ 次；内层二分查找在 `tails` 数组中进行，每次耗时 $\log N$。完美结合。
  - **空间复杂度**：**$O(N)$**。我们开辟了一个长度为 $N$ 的 `tails` 数组。

#### 💡 面试避坑与考点拓展（大厂的死亡追问）

- **大厂面试官最爱挖的坑：“既然 `tails` 数组记录了最优状态，那遍历结束后，`tails` 数组里面存的就是那条真实的最长递增子序列吗？”**

  - **满分避坑回答（绝对不是！）**：

    千万不要掉进这个陷阱！`tails` 数组**只是长度正确，内容不一定对**！

    *举个例子*：原数组是 `[4, 5, 6, 3]`。

    1. 进 4：`tails = [4]`

    2. 进 5：`tails = [4, 5]`

    3. 进 6：`tails = [4, 5, 6]` (目前最长长度 3，真实序列是 4,5,6)

    4. 进 3：3 会替换掉 4，此时 `tails = [3, 5, 6]`。

       **看清楚了**！虽然长度依然是正确的 3，但 `[3, 5, 6]` 在原数组中根本不是一个合法的子序列（因为 3 出现在 5 和 6 的后面）！

       `tails` 数组的意义仅仅是：它记录了各种长度下的**最低门槛**，用以推断出最终的**最大长度**。如果面试官让你打印出真实的序列，这种纯粹的 $O(N \log N)$ 做法是做不到的，必须额外维护一个 parent 数组来回溯路径！

### 📝 算法笔记：152. 乘积最大子数组 (Maximum Product Subarray)

-----

- **📌 核心题意**：

  给你一个整数数组 `nums` ，请你找出数组中乘积最大的非空连续 子数组（该子数组中至少包含一个数字），并返回该子数组所对应的乘积。

  测试用例的答案是一个 **32-位** 整数。

  **请注意**，一个只包含一个元素的数组的乘积是这个元素的值。

  **示例 1:**

  **输入:** nums = [2,3,-2,4]
  **输出:** `6`
  **解释:** 子数组 [2,3] 有最大乘积 6。

  **示例 2:**

  **输入:** nums = [-2,0,-1]
  **输出:** 0
  **解释:** 结果不能为 2, 因为 [-2,-1] 不是子数组。

  **提示:**

  - `1 <= nums.length <= 2 * 104`
  - `-10 <= nums[i] <= 10`
  - `nums` 的任何子数组的乘积都 **保证** 是一个 **32-位** 整数

- **🧠 思考过程**：

  1. **直觉与痛点（为什么直接套用 Kadane 算法会翻车？）**：

     在求最大子数组**和**时，我们只要维护一个当前最大和 `maxSum`，遇到负数直接不要它就行了。

     **痛点**：在求**乘积**时，假设当前序列是 `[2, 3, -2, 4, -1]`。

     - 当走到 `4` 的时候，前面的连续乘积是 `-48`。如果按“及时止损”的逻辑，我们肯定丢弃 `-48`，从 `4` 重新开始。

     - 可是紧接着遇到了 **`-1`**！如果我们保留了刚才的深渊 `-48`，那么 `-48 * -1 = 48`，再乘以 `4` 就是 `192`！

       所以，**当前的最小值（绝对值很大的负数），有在未来翻盘成为最大值的巨大潜力**。

  2. **破局思路（同时记录“巅峰”与“深渊”）**：

     既然最小值能逆袭，那我们在动态规划迭代时，就**不能只贪心地记录最大值，必须同时把最小值也死死记下来**！

     我们维护两个动态规划状态：

     - `maxProd`：以当前数字结尾的子数组的**最大**乘积。
     - `minProd`：以当前数字结尾的子数组的**最小**乘积（保存可能翻盘的负数火种）。

  3. **核心微操（绝妙的太极阴阳反转）**：

     当新来的数字 `nums[i]` 是一个**负数**时：

     它乘以原来的最大值，会变成一个极小的负数（新深渊）；

     它乘以原来的最小值，会变成一个极大的正数（新巅峰）！

     **致命技巧**：只要发现 `nums[i] < 0`，我们直接**把 `maxProd` 和 `minProd` 互换**！然后顺理成章地用常规公式更新，代码逻辑直接干净一倍。

- **🛠️ Java 规范代码（空间压榨 $O(1)$ 版）**：
```Java
class Solution {
    public int maxProduct(int[] nums) {
        if (nums == null || nums.length == 0) return 0;

        // 初始化：由于必须包含至少一个数字，第一天的巅峰和深渊都是 nums[0]
        int maxProd = nums[0];
        int minProd = nums[0];
        // 记录全局出现过的最高巅峰
        int globalMax = nums[0];

        // 从第二个数字开始看滚动过山车
        for (int i = 1; i < nums.length; i++) {
            int num = nums[i];

            // 🌟 核心高光细节：如果当前数字是负数，最大和最小瞬间颠倒
            if (num < 0) {
                int temp = maxProd;
                maxProd = minProd;
                minProd = temp;
            }

            // 状态转移方程：
            // 到底是【自立门户（从 num 开始）】，还是【继承家业（跟前面的乘起来）】
            maxProd = Math.max(num, maxProd * num);
            minProd = Math.min(num, minProd * num);

            // 每一轮都把当前产生的最大值拿去挑战历史纪录
            globalMax = Math.max(globalMax, maxProd);
        }

        return globalMax;
    }
}
```

- **⏱️ Complexity 复杂度分析**：
  - **时间复杂度**：$O(N)$。只需对数组进行一次单向线性扫描，没有任何嵌套循环，效率极高。
  - **空间复杂度**：$O(1)$。我们极其敏锐地发现当前状态只和前一个状态有关，因此直接用 `maxProd` 和 `minProd` 滚动变量代替了 DP 数组，将空间压榨到了常数级别。

#### 💡 面试避坑与考点拓展（大厂的隐藏考点）

1. **极度高频坑点：数字 `0` 的拆台效应**
   - 数组里如果出现 `0`（比如 `[2, 3, 0, 4]`），由于任何数乘以 0 都是 0，它会让 `maxProd` 和 `minProd` 瞬间归零。
   - **无需特殊处理**：我们的代码里有 `Math.max(num, ...)` 和 `Math.min(num, ...)`。当走到 `0` 之后的 `4` 时，`Math.max(4, 0 * 4)` 会让代码果断选择 `4`，相当于自动完成了“原地复活，重新建队”的逻辑。这就是动态规划自适应的优美之处。
2. **大厂追问：“这道题除了双极值 DP，还有什么脑筋急转弯的双向解法吗？”**
   - **满分抢答（前后缀乘积双向奔赴法）**：这是一个非常惊艳的视角。
   - 如果一个子数组乘积最大，它要么从左边开始延伸，要么从右边开始延伸。除非中间被 `0` 截断。
   - 我们可以算一遍**前缀乘积**，再算一遍**后缀乘积**（遇到 0 就把乘积重置为 1 重新算）。这两波数据的全局最大值，必然就是最大乘积子数组！
   - 这种解法代码行数极少，而且完全不需要考虑繁琐的负负得正调换，是极具极简美学的面试加分答卷。

### 📝 算法笔记：416. 分割等和子集 (Partition Equal Subset Sum)

-----

- **📌 核心题意**：

  给你一个 **只包含正整数**的 **非空**数组 `nums` 。请你判断是否可以将这个数组分割成两个子集，使得两个子集的元素和相等。

  **示例 1：**

  **输入：**nums = [1,5,11,5]
  **输出：**true
  **解释：**数组可以分割成 [1, 5, 5] 和 [11] 。

  **示例 2：**

  **输入：**nums = [1,2,3,5]
  **输出：**false
  **解释：**数组不能分割成两个元素和相等的子集。

  **提示：**

  - `1 <= nums.length <= 200`
  - `1 <= nums[i] <= 100`

- **🧠 思考过程**：

  1. **直觉与痛点（回溯的灾难）**：

     最直观的想法是对每一个数字做抉择：“放入左集合”或“放入右集合”。这就是标准的回溯法（DFS）。

     **痛点**：每一个数字都有 2 种选择，时间复杂度高达 $O(2^N)$。如果数组长度超过 30，直接超时到天荒地老。

  2. **降维破局（数学转换 + 背包登场）**：

     怎么才能让两个集合的和相等？

     显然，整个数组的**总和必须是偶数**！如果总和是奇数，比如 11，你怎么可能把它平分成两个整数？直接判死刑返回 `false`。

     如果总和是偶数（假设是 22），那么目标就极其明确了：**我们只需要从数组里挑出几个数，让它们的和恰好等于总和的一半（11）即可。**

     一旦挑出了和为 11 的子集，剩下的数字自然而然和也是 11。

     这完美的契合了“0-1 背包”的模型：有一个容量为 `11` 的背包，每个数字是一件物品（重量和价值都是数字本身），每件物品只能用一次，问能不能刚好把背包塞满？

  3. **核心微操（状态转移方程）**：

     我们定义一个布尔数组 `dp[j]`：表示**能否从数组中挑出一些数字，使得它们的和恰好等于 `j`**。

     假设我们正准备考虑数字 `nums[i]`，要更新 `dp[j]` 时，我们有两种选择：

     - **不把 `nums[i]` 放入背包**：那能否凑出 `j`，完全取决于历史记录 `dp[j]` 本身是不是 `true`。

     - **把 `nums[i]` 放入背包**：那能否凑出 `j`，取决于我们在没放它之前，能否凑出 `j - nums[i]`。也就是看历史记录 `dp[j - nums[i]]` 是不是 `true`。

       只要这两种情况有一种为 `true`，现在的 `dp[j]` 就是 `true`。

       方程：$dp[j] = dp[j] \ ||\ dp[j - nums[i]]$

- **🛠️ Java 规范代码（满分空间压缩版）**：
```Java
class Solution {
    public boolean canPartition(int[] nums) {
        int sum = 0;
        for (int num : nums) {
            sum += num;
        }
        
        // 1. 致命剪枝：如果总和是奇数，绝对不可能平分
        if (sum % 2 != 0) {
            return false;
        }
        
        int target = sum / 2;
        
        // dp[j] 表示能否凑出和为 j 的子集
        boolean[] dp = new boolean[target + 1];
        
        // 🌟 初始化基石：凑出和为 0 是永远可以的（什么都不选就行）
        dp[0] = true;
        
        // 外层循环：遍历每一件“物品”（每个数字）
        for (int i = 0; i < nums.length; i++) {
            // 🌟 致命工程细节：内层循环【必须倒序遍历】！
            // 从 target 一直往回退，退到装不下当前物品 nums[i] 为止
            for (int j = target; j >= nums[i]; j--) {
                // 状态转移：要么不选当前物品（维持 dp[j]），要么选当前物品（依赖 dp[j - nums[i]]）
                dp[j] = dp[j] || dp[j - nums[i]];
            }
            
            // 性能优化（剪枝）：如果在遍历中途，dp[target] 已经变成 true 了，直接提前胜利下班！
            if (dp[target]) {
                return true;
            }
        }
        
        return dp[target];
    }
}
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：$O(N \times \text{target})$。其中 $N$ 是数组长度，$\text{target}$ 是总和的一半。典型的伪多项式时间复杂度。
  - **空间复杂度**：$O(\text{target})$。仅仅开辟了一个长度为 `target + 1` 的一维布尔数组，极致的空间压缩。

#### 💡 面试避坑与考点拓展（大厂的死亡拷问）

- **大厂面试官最爱抓的破绽：“在『完全背包』（如零钱兑换）里，内层循环是从小到大正序遍历的；为什么在这道『0-1 背包』里，内层循环【必须从大到小倒序遍历】？”**
  - **满分保命回答（时空倒流法则）**：
    - 如果我们**正序遍历**：假设当前物品是 `2`。我们在算 `dp[2]` 时用到了 `dp[0]` 变成了 `true`。紧接着算 `dp[4]` 时，会去查 `dp[2]`。此时的 `dp[2]` 刚刚被这件物品 `2` 染成了 `true`，导致 `dp[4]` 也变成了 `true`！这等于**把同一件物品 `2` 用了两次**！这就退化成了“完全背包”问题。
    - 如果我们**倒序遍历**：算 `dp[4]` 时去查 `dp[2]`，此时由于还没遍历到索引 2，所以这个 `dp[2]` 绝对是**上一轮历史留下来的干净数据**（没有被当前物品污染过）。倒序遍历完美保证了：**在更新当前层的 `dp` 时，依赖的永远是上一层的状态，从而确保每件物品严格只被使用一次！**

### 📝 算法笔记：32. 最长有效括号 (Longest Valid Parentheses)

-----

- **📌 核心题意**：

  给你一个只包含 `'('` 和 `')'` 的字符串，找出最长有效（格式正确且连续）括号 子串 的长度。

  左右括号匹配，即每个左括号都有对应的右括号将其闭合的字符串是格式正确的，比如 `"(()())"`。

  **示例 1：**

  **输入：**s = "(()"
  **输出：**2
  **解释：**最长有效括号子串是 "()"

  **示例 2：**

  **输入：**s = ")()())"
  **输出：**4
  **解释：**最长有效括号子串是 "()()"

  **示例 3：**

  **输入：**s = ""
  **输出：**0


  **提示：**

  `0 <= s.length <= 3 * 104`
  `s[i]` 为 `'('` 或 `')'`

- **🧠 思考过程**：

  1. **直觉与痛点（断裂的连续性）**：

     如果单纯用消消乐，遇到 `(` 入栈，遇到 `)` 出栈，当栈空了或者不匹配时，我们知道括号断了。

     **痛点**：断了之后怎么计算长度？比如 `()())()`，前面一段 `()` 长度是 4，后面一段 `()` 长度是 2。我们必须精准地知道**每一次完美的消除是从哪个索引开始，到哪个索引结束的**，并且还要把连续消除的长度累加起来。

  2. **破局思路（不存字符，存“索引”；引入“虚拟锚点”）**：

     为了计算长度，栈里**绝对不能存字符 `(`，必须存它们的【数组索引】**！

     更绝的是，为了处理边界情况（比如一上来就是个完美的 `()`），我们需要在栈底死死压入一个“虚拟地基”——索引 `-1`**！ 这个 `-1` 的含义是：**“当前这波连续消除的合法边界，是从 -1 之后开始的”。

  3. **核心微操（锚点的自我迭代）**：

     我们从左到右遍历字符串：

     - **遇到 `(`**：说明新一波的闭合期待开始了，直接把它的**索引 `i`** 压入栈中。
     - **遇到 `)`**：说明我们要尝试消除。不管三七二十一，先把栈顶弹出来（Pop）。
     - 弹完之后，看一眼栈：
       - **如果栈不为空**：说明刚刚触发了一次完美的消除！这时候，当前合法的连续括号长度就是：`当前索引 i - 此时最新的栈顶索引`。我们拿这个长度去挑战历史最大值。
       - **如果栈变空了**：高能预警！这意味着当前这个 `)` 是一个**多余的、把前面连续性彻底砸碎的破坏者**（比如 `()())` 最后一个右括号）。前面的连续性当场暴毙。但我们不能气馁，我们要把当前这个 `)` 的索引 `i` **强行压入栈底，作为下一波新连续区间的“全新虚拟地基（新锚点）”**！

- **🛠️ Java 规范代码（满分栈指针极速版）**：
```Java
import java.util.ArrayDeque;
import java.util.Deque;

class Solution {
    public int longestValidParentheses(String s) {
        if (s == null || s.length() < 2) {
            return 0;
        }

        int maxLen = 0;
        // 栈里不存字符，只存索引
        Deque<Integer> stack = new ArrayDeque<>();
        
        // 🌟 灵魂一步：先注入一个虚拟地基 -1
        // 这样如果第 0 和第 1 个字符是 "()"，弹出后栈底剩下 -1，1 - (-1) = 2，完美契合
        stack.push(-1);

        for (int i = 0; i < s.length(); i++) {
            char c = s.charAt(i);

            if (c == '(') {
                // 遇到左括号，无脑压入当前索引
                stack.push(i);
            } else {
                // 遇到右括号，先弹栈，表示尝试匹配
                stack.pop();
                
                if (stack.isEmpty()) {
                    // 如果弹完之后栈空了，说明这个右括号无家可归（多余了）
                    // 它成了新的“断裂点”，我们把它压入栈中，作为下一轮计算长度的全新底座（地基）
                    stack.push(i);
                } else {
                    // 如果栈不空，说明匹配成功！
                    // 当前有效括号的长度 = 当前索引 i - 弹栈后新的栈顶索引
                    maxLen = Math.max(maxLen, i - stack.peek());
                }
            }
        }

        return maxLen;
    }
}
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：$O(N)$。只需要对字符串进行一次单向的线性扫描，每个索引最多入栈一次出栈一次。
  - **空间复杂度**：$O(N)$。在最坏的情况下（比如全是左括号 `"(((((("`），栈的深度会达到 $N+1$。

#### 💡 面试避坑与考点拓展（大厂的终极审判）

1. **大厂追问 1：“我看你用栈实现了 $O(N)$ 空间。如果面试官要求【空间复杂度必须是 $O(1)$】，不准用任何栈和额外数组，你能破局吗？”**
   - **满分抢答（正反双向贪心扫描法）**：绝对可以！这是一个极其巧妙的脑筋急转弯。
   - 我们只需要准备两个变量 `left` 和 `right` 记录左右括号的数量。
   - **从左向右扫一遍**：遇到 `(` 则 `left++`，遇到 `)` 则 `right++`。只要 `left == right`，说明完美闭合，更新 `maxLen = 2 * right`；如果 `right > left`，说明右边多出来了，连续性断裂，直接把 `left` 和 `right` **全部清零重来**。
   - *致命细节*：光这么扫会漏掉一种情况，比如 `"(()"`（左边多余），扫完 `left=2, right=1`，永远不会触发 `left==right`。
   - **破局补刀**：我们只需要**从右向左再反向扫一遍**！逻辑完全对称：遇到 `(` 且 `left > right` 时清零。两次扫描双向奔赴，用 $O(1)$ 的神级空间即可完美通关！
2. **大厂追问 2：“这道题如果用动态规划（DP）该怎么定义状态？”**
   - **DP 状态思维**：定义 `dp[i]` 表示**以当前字符 `s[i]` 结尾的**最长有效括号长度。
   - 只有当 `s[i] == ')'` 时才有可能有值。如果 `s[i-1] == '('`，那很简单，`dp[i] = dp[i-2] + 2`。
   - 如果 `s[i-1] == ')'`（比如 `((...))`），我们需要跨过 `dp[i-1]` 算出来的这一整段有效安全区，去窥探它前方的那个字符 `s[i - dp[i-1] - 1]` 是不是 `(`。如果是，说明这一大段被完美闭合了，状态转移方程就会变成：`dp[i] = dp[i-1] + 2 + dp[i - dp[i-1] - 2]`。
   - *大厂点评*：DP 解法的边界条件极度容易写错（一不小心就数组越界），在面试有限的时间内，**上面的“栈锚点法”是容错率最高、最不容易写挂的教科书级代码**。
