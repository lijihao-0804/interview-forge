### 📝 算法笔记：20. 有效的括号 (Valid Parentheses)

-----

- **📌 核心题意**：

  给定一个只包括 `'('`，`')'`，`'{'`，`'}'`，`'['`，`']'` 的字符串 `s` ，判断字符串是否有效。

  有效字符串需满足：

  1. 左括号必须用相同类型的右括号闭合。
  2. 左括号必须以正确的顺序闭合。
  3. 每个右括号都有一个对应的相同类型的左括号。

  **示例 1：**

  **输入：**s = "()"
  **输出：**true

  **示例 2：**

  **输入：**s = "()[]{}"
  **输出：**true

  **示例 3：**

  **输入：**s = "(]"
  **输出：**false

  **示例 4：**

  **输入：**s = "([])"
  **输出：**true

  **示例 5：**

  **输入：**s = "([)]"
  **输出：**false

  **提示：**

  - `1 <= s.length <= 104`
  - `s` 仅由括号 `'()[]{}'` 组成

- **🧠 思考过程**：

  1. **直觉与痛点（为什么不能用计数器？）**：

     有的同学第一反应是：我数一下左括号和右括号的数量不就行了？保证数量相等。

     **痛点**：数量相等不代表顺序对！比如 `([)]`，数量完全相等，但它是错的，因为最内层的 `[` 还没闭合，就被外层的 `)` 给强行截胡了。

     所以，这个问题的核心在于**顺序和最近匹配原则**：**“最后出现的左括号，必须最先闭合”**。

  2. **破局思路（引入“栈”结构）**：

     “最后出现的必须最先处理”——这简直就是把身份证拍在桌子上，大喊一声：“我是**后进先出（LIFO - Last In First Out）**，我需要一个**栈（Stack）**！”

     我们可以把左括号看作是“未满足的期待”，把右括号看作是“回应期待”。

     - 我们从左到右扫描字符串。
     - 遇到任何**左括号**，说明来了一个新的期待，不管三七二十一，直接**压入栈底（Push）**。
     - 遇到任何**右括号**，说明要回应期待了。此时我们看向**栈顶（Top）**，也就是我们刚刚接到的“最近的一个期待”。如果这个右括号刚好能和栈顶的左括号配对，太棒了，把栈顶元素**弹出（Pop）**（这就是消消乐）。
     - 如果不配对，或者栈已经空了（说明右括号多出来了），直接判死刑，返回 `false`。

  3. **核心微操（绝妙的入栈反转法）**：

     常规写法是：遇到 `(` 入栈 `(`，遇到 `)` 则检查栈顶是不是 `(`。

     **大神的极简写法**：遇到 `(`，我们直接在栈里压入它**对应的右括号 `)`**！

     这样一来，当我们遇到右括号时，只需要极其简单的一步：`if (当前字符 != 栈顶弹出的字符) return false;`。这简直是极简美学的巅峰。

- **🛠️ Java 规范代码（极简反转消消乐版）**：
```Java
import java.util.ArrayDeque;
import java.util.Deque;

class Solution {
    public boolean isValid(String s) {
        // 奇数长度的字符串，绝对不可能完美闭合，直接提前剪枝
        if (s.length() % 2 != 0) {
            return false;
        }

        // 🌟 致命细节：在 Java 中，推荐使用 Deque (ArrayDeque) 来代替过时的 Stack 类
        Deque<Character> stack = new ArrayDeque<>();

        for (int i = 0; i < s.length(); i++) {
            char c = s.charAt(i);

            // 遇到左括号，把它的“另一半”压入栈中，等待未来的重逢
            if (c == '(') {
                stack.push(')');
            } else if (c == '[') {
                stack.push(']');
            } else if (c == '{') {
                stack.push('}');
            } 
            // 遇到右括号了！
            else {
                // 如果栈已经空了（说明右括号多了，没人等它）
                // 或者栈顶弹出的字符和当前的右括号不相等（类型不匹配）
                if (stack.isEmpty() || stack.pop() != c) {
                    return false;
                }
            }
        }

        // 字符串全扫完了，如果栈也刚好空了，说明所有的括号都完美消除了！
        // 如果栈没空（说明左括号多了），返回 false
        return stack.isEmpty();
    }
}
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：$O(N)$。只需从头到尾遍历一次字符串，每一次的入栈（`push`）和出栈（`pop`）操作时间都是常数级的 $O(1)$。
  - **空间复杂度**：$O(N)$。在最坏的情况下（比如字符串全是左括号 `"((((((("`），所有的字符都会被压入栈中，栈的深度等于字符串的长度。

#### 💡 面试避坑与考点拓展（大厂的底层拷问）

1. **大厂追问 1：“我看你代码里用了 `Deque<Character> stack = new ArrayDeque<>();`，为什么不用 `Stack<Character> stack = new Stack<>();` 呢？”**

   - **满分抢答（直击 Java 源码）**：在 Java 早期的设计中，`Stack` 是继承自 `Vector` 的。`Vector` 里的每一个方法（包括 `push` 和 `pop`）都加了 `synchronized` 同步锁！这使得 `Stack` 在单线程环境下性能极其拉垮（因为要频繁获取和释放没用的锁）。
   - 后来 Java 官方都看不下去了，在官方文档里强烈建议使用 `Deque` 接口（通常实例化为 `ArrayDeque`）来代替 `Stack`。`ArrayDeque` 基于循环数组实现，没有线程同步的额外开销，速度飞快，是现代 Java 工程师的标配。

2. **大厂追问 2：“这道题你能总结出一共有哪几种失败的情况吗？”**

   - **满分总结（三种死法）**：

     1. **左边多余**：遍历完了，栈里面还有剩余的括号没被消除掉。例如 `({}`。

     2. **右边多余**：遍历到右括号时，栈竟然已经空了。例如 `([{}])))`。

     3. **中途不匹配**：遍历到右括号时，栈顶拿出来的右括号跟当前的手里的右括号长得不一样。例如 `([)]`。

        只要你能清晰地把这三种情况说出来，面试官就知道你对栈的生命周期了如指掌。

### 📝 算法笔记：155. 最小栈 (Min Stack)

-----

- **📌 核心题意**：

  设计一个支持 `push` ，`pop` ，`top` 操作，并能在常数时间内检索到最小元素的栈。

  实现 `MinStack` 类:

  - `MinStack()` 初始化堆栈对象。
  - `void push(int value)` 将元素 `value` 推入堆栈。
  - `void pop()` 删除堆栈顶部的元素。
  - `int top()` 获取堆栈顶部的元素。
  - `int getMin()` 获取堆栈中的最小元素。

  **示例 1:**

  **输入：**<br>["MinStack","push","push","push","getMin","pop","top","getMin"]<br>[[],[-2],[0],[-3],[],[],[],[]]<br><br>**输出：**<br>[null,null,null,null,-3,null,0,-2]<br><br>**解释：**<br>MinStack minStack = new MinStack();<br>minStack.push(-2);<br>minStack.push(0);<br>minStack.push(-3);<br>minStack.getMin();   --> 返回 -3.<br>minStack.pop();<br>minStack.top();      --> 返回 0.<br>minStack.getMin();   --> 返回 -2.

  **提示：**

  - `-231 <= val <= 231 - 1`
  - `pop`、`top` 和 `getMin` 操作总是在 **非空栈** 上调用
  - `push`, `pop`, `top`, and `getMin`最多被调用 `3 * 104` 次

- **🧠 思考过程**：

  1. **直觉与痛点（为什么一个变量不行？）**：

     很多同学第一反应是：这简单啊，我在类里挂一个 `int minValue` 变量。每次 `push` 进来新数字，如果它比 `minValue` 小，我就更新 `minValue`。

     **痛点**：如果这个当前最小的数字被 `pop` 弹出了呢？比如栈里现在是 `[3, 5, 1]`，最小是 `1`。现在把 `1` 弹出了，请问剩下的数字里谁最小？变量已经失忆了，它不记得在 `1` 进来之前，历史最小是 `3`。

  2. **破局思路（留住历史的罪证：辅助栈）**：

     既然一个变量记不住历史，那我们就**用另一个栈来记录历史的每一次“最小状态”**。

     - **数据栈（Data Stack）**：老老实实装用户传进来的所有数字。
     - **最小栈（Min Stack）**：装**对应这一刻**，全栈的最小数字是谁。

  3. **核心微操（双栈同步战术）**：

     为了让逻辑最严谨、最不容易出错，我们采用“双栈完全同步”的标配打法：

     - **`push(val)`**：数据栈直接入栈 `val`。最小栈要看一眼：如果当前准备入栈的 `val` 比我自己的栈顶还要小，那没的说，`val` 入最小栈；如果 `val` 比我的栈顶还大，说明它动摇不了当前最小值的地位，那我就**把我自己现有的栈顶复制一份，再次压入栈**！
     - **`pop()`**：两个栈同时弹出栈顶。因为它们是绝对同步的，所以数据栈弹出的同时，最小栈也弹出了那一刻的历史最小值，两边的状态永远对称。
     - **`getMin()`**：直接看一眼最小栈的栈顶，那必然是当前的天下第一小。

- **🛠️ Java 规范代码（双栈同步满分版）**：
```Java
import java.util.ArrayDeque;
import java.util.Deque;

class MinStack {
    // 数据栈：存放实际数据
    private Deque<Integer> dataStack;
    // 辅助栈：存放每次入栈时，栈内的最小值状态
    private Deque<Integer> minStack;

    public MinStack() {
        dataStack = new ArrayDeque<>();
        minStack = new ArrayDeque<>();
    }
    
    public void push(int val) {
        dataStack.push(val);
        
        // 如果辅助栈为空，说明是第一个元素，直接作为最小值入栈
        // 否则，拿当前值 val 和辅助栈栈顶（当前最小值）比较，谁小就压入谁
        if (minStack.isEmpty()) {
            minStack.push(val);
        } else {
            int currentMin = minStack.peek();
            if (val < currentMin) {
                minStack.push(val);
            } else {
                // 🌟 核心工程细节：把老栈顶复制一份压进去，保持两个栈高度绝对一致
                minStack.push(currentMin);
            }
        }
    }
    
    public void pop() {
        // 两个栈必须同生共死，同时弹出
        if (!dataStack.isEmpty()) {
            dataStack.pop();
            minStack.pop();
        }
    }
    
    public int top() {
        // 获取数据栈的栈顶
        return dataStack.peek();
    }
    
    public int getMin() {
        // 🌟 O(1) 极速获取：直接看辅助栈的栈顶即可！
        return minStack.peek();
    }
}

/**
 * Your MinStack object will be instantiated and called as such:
 * MinStack obj = new MinStack();
 * obj.push(val);
 * obj.pop();
 * int param_3 = obj.top();
 * int param_4 = obj.getMin();
 */
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：`push`、`pop`、`top`、`getMin` **全部为 $O(1)$**。没有任何循环，纯粹是指针和栈顶的常规操作。
  - **空间复杂度**：$O(N)$。因为引入了一个和数据栈一样高、同步增长的辅助栈。

#### 💡 面试避坑与考点拓展（大厂夺命加分项）

1. **大厂追问 1：“我看你的最小栈在 `val > currentMin` 时，复制了老栈顶压进去。如果我不想浪费空间复制老栈顶，代码怎么改？”**
   - **满分抢答（异步不复制流派）**：可以改用“异步模式”。
   - `push` 时：只有当 `val <= minStack.peek()` 时，才把 `val` 压入最小栈。（注意一定要是 `<=`, 不能是 `<`，因为可能有相同的最小值）。
   - `pop` 时：只有当 `dataStack.peek() == minStack.peek()` 时，最小栈才跟着弹出。
   - *大厂点评*：这种写法节省了一部分空间。但在面试时，**需要非常小心空指针判断以及 `Integer` 对象的 `==` 比较坑点（Java 缓存机制中，超出 -128 到 127 必须用 `.equals()`）**。所以同步双栈依然是最推荐的、抗压稳健的写法。
2. **终极装杯追问：“如果面试官要求【空间复杂度必须是 $O(1)$】（不允许开辟任何辅助栈或额外数组），你还能玩得转吗？”**
   - **神仙写法（差值存储法）**：这是一个极其炫酷的 trick！
   - 我们的纯数据栈里，**不存原始数据，改存“差值（CurrentValue - CurrentMin）”**。
   - 同时在外部只用一个 `long minValue` 变量。
   - 当入栈一个更小的数时，栈里存入一个负数，并更新 `minValue`。通过这个负数和当前的 `minValue`，在 `pop` 的时候我们可以通过逆向数学公式，反推出**前一个历史最小值**是多少！
   - 这种解法不需要任何额外空间，如果你能在面试中把差值推导公式手写出来，面试官会直接起立为你鼓掌。

### 📝 算法笔记：394. 字符串解码 (Decode String)

-----

- **📌 核心题意**：

  给定一个经过编码的字符串，返回它解码后的字符串。

  编码规则为: `k[encoded_string]`，表示其中方括号内部的 `encoded_string` 正好重复 `k` 次。注意 `k` 保证为正整数。

  你可以认为输入字符串总是有效的；输入字符串中没有额外的空格，且输入的方括号总是符合格式要求的。

  此外，你可以认为原始数据不包含数字，所有的数字只表示重复的次数 `k` ，例如不会出现像 `3a` 或 `2[4]` 的输入。

  测试用例保证输出的长度不会超过 `105`。

  **示例 1：**

  **输入：**s = "3[a]2[bc]"<br>**输出：**"aaabcbc"

  **示例 2：**

  **输入：**s = "3[a2[c]]"<br>**输出：**"accaccacc"

  **示例 3：**

  **输入：**s = "2[abc]3[cd]ef"<br>**输出：**"abcabccdcdcdef"

  **示例 4：**

  **输入：**s = "abc3[cd]xyz"<br>**输出：**"abccdcdcdxyz"

  **提示：**

  - `1 <= s.length <= 30`
  - `s` 由小写英文字母、数字和方括号 `'[]'` 组成
  - `s` 保证是一个 **有效** 的输入。
  - `s` 中所有整数的取值范围为 `[1, 300]`

- **🧠 思考过程**：

  1. **直觉与痛点（为什么必须用栈？）**：

     字符串里有嵌套，比如 `3[a2[c]]`，我们必须先解码最内层的 `2[c]` 变成 `cc`，然后再和外面的 `a` 拼起来变成 `acc`，最后再把整个 `acc` 翻 3 倍。

     **痛点**：当我们读到 `3` 和 `a` 时，我们还不能处理它们，必须把它们“挂起（记住）”**，去处理内层。等内层处理完了，再把它们**“唤醒”**。这种“挂起当前状态，去处理子任务，然后再恢复状态”的机制，完美契合**栈（Stack）。

  2. **破局思路（双栈战术：数字栈 + 字符串栈）**：

     我们需要准备两个栈，以及两个全局变量：

     - `countStack`：专门存倍数（我要重复几次）。
     - `stringStack`：专门存**遇到 `[` 之前的那个半成品字符串**（我要把重复后的结果拼在谁的后面）。
     - `k`：记录当前正在计算的倍数。
     - `currStr`：记录当前括号里正在拼装的字符串。

  3. **核心微操（四个分支的精准打击）**：

     遍历字符串，遇到四种不同的字符，执行不同的战术：

     - **遇到数字**：因为数字可能是多位数（比如 `12[a]`），所以要用 `k = k * 10 + (c - '0')` 把数字完整拼出来。
     - **遇到 `[`（时空冻结）**：要把当前的倍数 `k` 压入 `countStack`，把当前的 `currStr` 压入 `stringStack`。然后**清空 `k` 和 `currStr`**，准备进入全新的内层世界。
     - **遇到字母**：直接追加到当前世界的 `currStr` 后面。
     - **遇到 `]`（时空缝合）**：当前内层世界拼装完毕了！从 `countStack` 弹出一个倍数，把 `currStr` 翻那么多倍。然后从 `stringStack` 弹出一个“前世”的字符串，把翻倍后的结果拼在它后面，重新赋给 `currStr`。

- **🛠️ Java 规范代码（满分双栈 StringBuilder 版）**：
```Java
import java.util.ArrayDeque;
import java.util.Deque;

class Solution {
    public String decodeString(String s) {
        // 存储倍数的栈
        Deque<Integer> countStack = new ArrayDeque<>();
        // 存储之前已经拼好的字符串前缀的栈
        Deque<StringBuilder> stringStack = new ArrayDeque<>();
        
        // 记录当前正在构建的字符串
        StringBuilder currStr = new StringBuilder();
        // 记录当前正在计算的倍数
        int k = 0;
        
        for (char c : s.toCharArray()) {
            if (Character.isDigit(c)) {
                // 🌟 致命细节：处理多位数字，比如 "100[a]"
                k = k * 10 + (c - '0');
            } else if (c == '[') {
                // 遇到左括号，立刻把当前的状态（k 和 currStr）存档（入栈）
                countStack.push(k);
                stringStack.push(currStr);
                
                // 存档完毕后，重置状态，准备迎接新括号里的内容
                k = 0;
                currStr = new StringBuilder();
            } else if (c == ']') {
                // 遇到右括号，说明当前层的 currStr 已经收集完毕，开始解码！
                // 1. 取出这一层需要翻倍的次数
                int repeatTimes = countStack.pop();
                
                // 2. 取出遇到 '[' 之前，上一个维度的老字符串
                StringBuilder prevStr = stringStack.pop();
                
                // 3. 把当前层的字符串翻倍，拼在老字符串的后面
                for (int i = 0; i < repeatTimes; i++) {
                    prevStr.append(currStr);
                }
                
                // 4. 更新 currStr，时空缝合完毕！
                currStr = prevStr;
            } else {
                // 普通字母，直接收集到当前层的字符串容器里
                currStr.append(c);
            }
        }
        
        return currStr.toString();
    }
}
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：$O(N)$。这里 $N$ 指的是**解码后结果字符串的长度**。虽然看起来只有一个 `for` 循环，但遇到 `]` 时的翻倍拼接操作会消耗时间，整体时间严格与最终输出的字符数量成正比。
  - **空间复杂度**：$O(S)$。$S$ 是字符串中左括号 `[` 的嵌套层数。栈的深度等于括号的最大嵌套深度。

#### 💡 面试避坑与考点拓展（大厂的底层拷问）

1. **踩坑警告：多位数字的陷阱**
   - 很多同学在写提取数字的代码时，习惯性地写成 `k = c - '0'`。
   - 如果测试用例是 `12[a]`，你的代码走到 `2` 的时候，就会把 `k` 覆盖成 2，丢掉了前面的 10！
   - **必记范式**：在任何需要连续读取数字字符的题里，提取完整数字的黄金公式永远是 `k = k * 10 + (c - '0')`。
2. **大厂追问：“除了用栈，这题能用【递归】写吗？哪种更好？”**
   - **满分抢答**：绝对能用递归！因为括号的嵌套本质就是一棵树的深度优先遍历（DFS）。我们可以写一个递归函数，只要遇到 `[` 就向下递归，遇到 `]` 就 `return` 当前层拼接好的字符串。
   - **两种对比**：
     - **栈写法（迭代）**：工程上更稳健，不会因为嵌套过深导致 `StackOverflowError`（系统栈溢出），所有的栈操作都在堆内存的 `Deque` 中完成，空间上限更大。
     - **递归写法**：代码更短、更符合人类数学直觉，但在工业界处理超长恶意嵌套字符串时存在爆栈风险。面试时能把栈的代码用 `StringBuilder` 写得滴水不漏，是最优选择。

### 📝 算法笔记：739. 每日温度 (Daily Temperatures)

-----

- **📌 核心题意**：

  给定一个整数数组 `temperatures` ，表示每天的温度，返回一个数组 `answer` ，其中 `answer[i]` 是指对于第 `i` 天，下一个更高温度出现在几天后。如果气温在这之后都不会升高，请在该位置用 `0` 来代替。

  **示例 1:**

  **输入:** temperatures = [73,74,75,71,69,72,76,73]<br>**输出:** [1,1,4,2,1,1,0,0]

  **示例 2:**

  **输入:** temperatures = [30,40,50,60]<br>**输出:** [1,1,1,0]

  **示例 3:**

  **输入:** temperatures = [30,60,90]<br>**输出:**[1,1,0]

  **提示：**

  - `1 <= temperatures.length <= 105`
  - `30 <= temperatures[i] <= 100`

- **🧠 思考过程**：

  1. **直觉与痛点（暴力的代价）**：

     最直观的做法是两层 `for` 循环：站在今天，向后一天一天地看，直到找到一个比今天热的日子。

     **痛点**：如果气温是连降一个月，最后一天才突然升温（比如 `[100, 99, 98, ..., 1, 101]`），每次查找都要遍历后面的所有日子，时间复杂度直接飙升到 $O(N^2)$，在庞大的数据量下面试必挂。

  2. **破局思路（引入“悬而未决等待室”）**：

     我们换个思路：与其站在今天往**未来**看，不如站在今天向**过去**看！

     我们可以准备一个**栈（等待室）**。那些还没找到更暖和日子的天数，都在这个等待室里排队。

     - 假设等待室里坐着 `75度`、`71度`、`69度`（从老到新，温度越来越低，都在苦苦等待升温）。
     - 突然，今天来了一个 **`72度`** 的日子！
     - 此时，等待室里最外面的 `69度` 激动地跳起来：“我等到了！比我暖和的日子来了！”于是 `69度` 结算距离，离开等待室。
     - 接着 `71度` 也跳起来：“我也等到了！”结算，离开。
     - 再往里面看，`75度` 叹了口气：“72 还是没我高，我接着等吧。”
     - 结算完毕后，今天的 `72度` 也坐进等待室，因为属于它的更高温度还没来。

  3. **核心微操（存索引而不是存温度）**：

     题目要求返回的是“**几天后**（天数差）”。

     如果我们在栈里只存温度 `71`，等升温时，我们根本不知道 `71` 是哪一天存进去的！

     **致命技巧**：栈里面**只存数组的索引（日子的编号）**！用索引不仅能通过 `temperatures[index]` 查到当天的温度，还能在出栈时直接用 `当前索引 - 栈顶索引` 算出等待了几天！

- **🛠️ Java 规范代码（满分单调栈模板）**：
```Java
import java.util.ArrayDeque;
import java.util.Deque;

class Solution {
    public int[] dailyTemperatures(int[] temperatures) {
        int n = temperatures.length;
        int[] answer = new int[n];
        
        // 🌟 核心利器：单调栈（Monotonic Stack）
        // 栈里存的是【索引】，并且这些索引对应的温度，从栈底到栈顶是【严格递减】的
        Deque<Integer> stack = new ArrayDeque<>();
        
        for (int i = 0; i < n; i++) {
            // 当前这天的温度
            int currentTemp = temperatures[i];
            
            // 只要栈没空，并且【今天的温度】打败了【栈顶索引对应的历史温度】
            // 说明栈顶的那个日子，终于等到了它的升温日！
            while (!stack.isEmpty() && currentTemp > temperatures[stack.peek()]) {
                // 弹出栈顶的倒霉蛋（历史索引）
                int prevIndex = stack.pop();
                // 结算它等了多少天：今天(i) - 历史(prevIndex)
                answer[prevIndex] = i - prevIndex;
            }
            
            // 历史的恩怨结算完了（或者今天比栈顶还冷），把今天也关进等待室接着等
            stack.push(i);
        }
        
        // 循环结束后，栈里可能还有剩下的索引。
        // 它们等到了最后一天也没等来升温，answer 数组初始化默认就是 0，所以不需要额外处理了！
        return answer;
    }
}
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：$O(N)$。很多初学者看到 `for` 里面套了个 `while` 就以为是 $O(N^2)$。大错特错！请注意，数组中的每一个元素，**最多入栈一次，出栈一次**。没有任何元素会被重复操作，所以总的时间复杂度是严丝合缝的线性时间。这也是单调栈的降维威力！
  - **空间复杂度**：$O(N)$。在最坏的情况下（比如气温一直下降，没人能出栈），栈的深度等于数组的长度。

#### 💡 面试避坑与考点拓展（大厂的底层拷问）

1. **大厂追问 1：“为什么这个数据结构叫【单调栈】？”**
   - **满分回答**：因为在任何时刻，栈内元素保持着极其严格的**单调性**。在这道题里，如果当前元素比栈顶小，它直接入栈；如果比栈顶大，它会像贪吃蛇一样把比自己小的元素全部“吃掉（弹出）”后才入栈。这就保证了从栈底到栈顶，温度一定是严格递减（单调递减）的。
2. **大厂追问 2：“如果我要求找【上一个更冷的元素】，栈该怎么维护？”**
   - **秒杀口诀**：这是单调栈的终极规律，建议死记硬背加理解：
     - 找 **下一个更大**（本题）：从左到右遍历，维护一个**单调递减栈**。
     - 找 **下一个更小**：从左到右遍历，维护一个**单调递增栈**。
     - 找 **上一个更大/更小**：改变思维，本质上就是当前元素在被弹出时，把它弹出的那个元素，或者它压在底下的那个元素。

### 📝 算法笔记：84. 柱状图中最大的矩形 (Largest Rectangle in Histogram)

-----

- **📌 核心题意**：

  给定 *n* 个非负整数，用来表示柱状图中各个柱子的高度。每个柱子彼此相邻，且宽度为 1 。

  求在该柱状图中，能够勾勒出来的矩形的最大面积。

  **示例 1:**

  ![](https://__LC_IMG_ROOT__/lc-ce07c4fa73a042.jpg)

  **输入：**heights = [2,1,5,6,2,3]<br>**输出：**10<br>**解释：**最大的矩形为图中红色区域，面积为 10

  **示例 2：**

  ![](https://__LC_IMG_ROOT__/lc-7e30fcbe92aff8.jpg)

  **输入：** heights = [2,4]<br>**输出：** 4

  **提示：**

  - `1 <= heights.length <=105`
  - `0 <= heights[i] <= 104`

- **🧠 思考过程**：

  1. **直觉与痛点（木桶效应的死局）**：

     矩形的面积 = 宽 $\times$ 高。如果我们选定某一个柱子作为矩形的“高度”，那么这个矩形能向左右延伸多远？

     **答案是：直到遇到比它矮的柱子为止（木桶效应）**。

     暴力解法就是遍历每一个柱子，向左向右寻找第一个比它矮的柱子。但在最坏情况下（比如数组呈倒 V 型），每次都要扫描两边，时间复杂度会退化到 $O(N^2)$，绝对超时。

  2. **破局思路（单调递增栈的降维打击）**：

     我们需要在 $O(N)$ 的时间里，一次性把每个柱子的“左边界”**和**“右边界”**都找出来。 我们维护一个**从栈底到栈顶严格递增的栈（存索引）：

     - 当新来的柱子比栈顶**高**时，直接入栈（因为栈顶的右边界还没找到，还能继续延伸）。
     - 🌟 当新来的柱子比栈顶**矮**时，高能预警！这说明**栈顶柱子的右边界找到了**（就是当前这个矮柱子）！
     - 此时，将栈顶柱子弹出。那么它的**左边界是谁**？就是它弹出后，**此时露出来的新的栈顶**！（因为栈是单调递增的，它下面压着的，必定是左边第一个比它矮的柱子）。
     - 高度有了，左右边界有了，面积立刻结算！

  3. **核心微操（惊为天人的“双哨兵”技巧）**：

     如果原数组是 `[2, 4, 6, 8]`（完全递增），那么所有柱子都会压入栈，最后没有矮柱子来触发结算，导致最后还要写个 `while` 循环去清空栈。

     如果在开头遇到极小的柱子，弹出栈顶后，栈空了，左边界怎么算？又要写大量的 `if-else`。

     **大厂绝杀技：首尾加哨兵（Sentinel）！**

     我们在原数组的最前面和最后面，各强行塞入一个高度为 `0` 的柱子！

     - **开头的 0**：保证栈永远不会空，省去了判断栈空的麻烦（它天然是所有元素的左边界）。
     - **结尾的 0**：保证遍历到最后时，所有的柱子都会因为比 0 高，被强制全部弹出并结算！

- **🛠️ Java 规范代码（满分双哨兵单调栈版）**：
```Java
import java.util.ArrayDeque;
import java.util.Deque;

class Solution {
    public int largestRectangleArea(int[] heights) {
        // 1. 数组扩容，首尾各加一个“0”作为哨兵
        int[] newHeights = new int[heights.length + 2];
        // 默认第一位和最后一位都是 0，把原数组的数据拷贝到中间
        System.arraycopy(heights, 0, newHeights, 1, heights.length);

        int maxArea = 0;
        // 单调栈，专门存放索引，且对应的高度从栈底到栈顶单调递增
        Deque<Integer> stack = new ArrayDeque<>();

        // 2. 开始遍历加了哨兵的新数组
        for (int i = 0; i < newHeights.length; i++) {
            // 🌟 核心逻辑：当前柱子比栈顶柱子矮，说明栈顶柱子的“右边界”找到了！
            // 开始“大清算”，把比当前柱子高的栈顶全弹出来结算面积
            while (!stack.isEmpty() && newHeights[i] < newHeights[stack.peek()]) {
                // 弹出栈顶，它就是我们当前要计算的矩形的高度
                int midIndex = stack.pop();
                int h = newHeights[midIndex];

                // 此时栈顶剩下的元素，就是弹出元素的“左边界”
                int leftIndex = stack.peek();
                // 当前柱子 i，就是弹出元素的“右边界”
                int rightIndex = i;

                // 计算宽度：右边界 - 左边界 - 1 （注意这里是开区间，不包含左右边界本身）
                int w = rightIndex - leftIndex - 1;

                // 挑战历史最大面积
                maxArea = Math.max(maxArea, h * w);
            }

            // 当前柱子处理完毕，入栈等待自己的右边界到来
            stack.push(i);
        }

        return maxArea;
    }
}
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：$O(N)$。加上首尾哨兵后，数组共有 $N+2$ 个元素。每个元素最多只会入栈一次、出栈一次。没有任何重复遍历，是极致的线性时间。
  - **空间复杂度**：$O(N)$。开辟了长度为 $N+2$ 的新数组 `newHeights`，以及一个最坏情况下深度为 $N+2$ 的单调栈。

#### 💡 面试避坑与考点拓展（大厂的连环计）

1. **极度高频坑点：宽度的计算公式到底为什么是 `w = right - left - 1`？**

   - 闭上眼睛想象：假设高度是 `[1, 5, 6, 2]`，栈里现在压着 `1, 5, 6`。
   - 遇到 `2` 的时候，比 `6` 矮，弹出 `6` 计算面积。
   - 此时 `6` 的右边界是 `2`（索引为 3），左边界是 `5`（索引为 1）。
   - 这说明包含 `6` 的矩形，**只能卡在索引 1 和索引 3 之间**，真正属于它的只有索引 2 本身！
   - $3 - 1 - 1 = 1$，宽度为 1。公式完美闭环。

2. **大厂终极追踪：“如果我把这个一维的柱状图，变成一个由 `0` 和 `1` 组成的【二维矩阵】，让你求里面最大的全为 `1` 的矩形面积，你该怎么做？”（对应力扣 85 题：最大矩形 - Hard 难度）**

   - **满分降维打击（矩阵压缩法）**：这也是大厂面试中最爱玩的套路——把新题降维成旧题。

   - 遇到二维矩阵，我们只需要**以每一行为地基，把上面的 `1` 累加起来，当做柱子的高度**。

   - 比如矩阵：

     `1 0 1 0 0` -> 这一层柱子是 `[1, 0, 1, 0, 0]`

     `1 0 1 1 1` -> 这一层柱子是 `[2, 0, 2, 1, 1]` (遇到 0 直接归零，遇到 1 累加)

     `1 1 1 1 1` -> 这一层柱子是 `[3, 1, 3, 2, 2]`

   - 我们只需要把每一层算出来的一维数组，**当做 84 题里的 `heights`，调用 $M$ 次（行数）上面写好的单调栈算法，取最大值即可**。这绝对是展现你算法体系融会贯通的最佳时刻！

### 📝 算法笔记：232. 用栈实现队列 (Implement Queue using Stacks)

-----

- **📌 核心题意**：

  请你仅使用两个栈实现先入先出队列。队列应当支持一般队列支持的所有操作（`push`、`pop`、`peek`、`empty`）：

  实现 `MyQueue` 类：

  - `void push(int x)` 将元素 x 推到队列的末尾
  - `int pop()` 从队列的开头移除并返回元素
  - `int peek()` 返回队列开头的元素
  - `boolean empty()` 如果队列为空，返回 `true` ；否则，返回 `false`

  **说明：**

  - 你 **只能** 使用标准的栈操作 —— 也就是只有 `push to top`, `peek/pop from top`, `size`, 和 `is empty` 操作是合法的。
  - 你所使用的语言也许不支持栈。你可以使用 list 或者 deque（双端队列）来模拟一个栈，只要是标准的栈操作即可。

  **示例 1：**

  **输入：**<br>["MyQueue", "push", "push", "peek", "pop", "empty"]<br>[[], [1], [2], [], [], []]<br>**输出：**<br>[null, null, null, 1, 1, false]<br><br>**解释：**<br>MyQueue myQueue = new MyQueue();<br>myQueue.push(1); // queue is: [1]<br>myQueue.push(2); // queue is: [1, 2] (leftmost is front of the queue)<br>myQueue.peek(); // return 1<br>myQueue.pop(); // return 1, queue is [2]<br>myQueue.empty(); // return false

  **提示：**

  - `1 <= x <= 9`
  - 最多调用 `100` 次 `push`、`pop`、`peek` 和 `empty`
  - 假设所有操作都是有效的 （例如，一个空的队列不会调用 `pop` 或者 `peek` 操作）

  **进阶：**

  - 你能否实现每个操作均摊时间复杂度为 `O(1)` 的队列？换句话说，执行 `n` 个操作的总时间复杂度为 `O(n)` ，即使其中一个操作可能花费较长时间。

- **🧠 思考过程**：

  1. **直觉与痛点（单向思维的死胡同）**：

     假设我们依次把 `1, 2, 3` 压入栈中，栈顶是 `3`。但是按照队列的规矩，第一个被弹出的应该是 `1`（在栈底）。

     **痛点**：一个栈必定会把顺序逆转。如果你每次为了拿底部的元素，都把上面的元素倒腾出来，拿完再塞回去，那每次 `pop` 都会导致 $O(N)$ 的时间复杂度，极其笨重。

  2. **破局思路（双桶倒水，负负得正）**：

     既然一个栈会逆转顺序（`1, 2, 3` 变成 `3, 2, 1`），那如果我们把这个栈里的东西，**一股脑儿倒进另一个栈里**呢？

     `3` 先进去，`2` 再进去，`1` 最后进去。此时第二个栈的从顶到底变成了 `1, 2, 3`！

     顺序奇迹般地恢复了原样！

  3. **核心微操（职责分离的输入栈与输出栈）**：

     我们准备两个栈：

     - **`inStack`（输入栈）**：专门负责接待新客。任何 `push` 操作，无脑往这里塞。
     - **`outStack`（输出栈）**：专门负责送客。任何 `pop` 或 `peek` 操作，只从这里拿。
     - **🌟 倒水触发机制（核心灵魂）**：当有人要出队（`pop`）时，我们去看一眼 `outStack`。如果里面有元素，直接弹栈顶；**只有当 `outStack` 空了的时候**，我们才把 `inStack` 里的所有元素一次性全部倾倒进 `outStack` 中！

- **🛠️ Java 规范代码（满分职责分离版）**：
```Java
import java.util.ArrayDeque;
import java.util.Deque;

class MyQueue {
    // 输入栈：只管存
    private Deque<Integer> inStack;
    // 输出栈：只管取
    private Deque<Integer> outStack;

    public MyQueue() {
        inStack = new ArrayDeque<>();
        outStack = new ArrayDeque<>();
    }
    
    // 入队操作：无脑压入输入栈
    public void push(int x) {
        inStack.push(x);
    }
    
    // 出队操作：从输出栈拿
    public int pop() {
        dumpInToOut();
        return outStack.pop();
    }
    
    // 查看队首元素：从输出栈看
    public int peek() {
        dumpInToOut();
        return outStack.peek();
    }
    
    // 判空：两个栈都空了，队列才是真的空了
    public boolean empty() {
        return inStack.isEmpty() && outStack.isEmpty();
    }

    // 🌟 辅助核心方法：把输入栈的水，倒进输出栈
    private void dumpInToOut() {
        // 致命细节：【只有当输出栈为空时】，才能去输入栈搬救兵！
        // 否则如果输出栈还有一半没处理完，你又倒新数据进去，顺序就全乱了！
        if (outStack.isEmpty()) {
            while (!inStack.isEmpty()) {
                outStack.push(inStack.pop());
            }
        }
    }
}

/**
 * Your MyQueue object will be instantiated and called as such:
 * MyQueue obj = new MyQueue();
 * obj.push(x);
 * int param_2 = obj.pop();
 * int param_3 = obj.peek();
 * boolean param_4 = obj.empty();
 */
```

- **⏱️ 复杂度分析（大厂面试高光时刻）**：
  - **空间复杂度**：$O(N)$。需要两个栈来存储元素。
  - **时间复杂度**：
    - `push` 和 `empty`：毫无疑问是 **$O(1)$**。
    - **`pop` 和 `peek`（重点！）**：虽然里面有个 `while` 循环，但面试官问你时间复杂度时，你一定要斩钉截铁地回答：**均摊时间复杂度是 $O(1)$**！

#### 💡 面试避坑与考点拓展（大神的底层逻辑）

- **大厂必考追问：“`pop` 里面明明有个 `while` 循环会遍历全部元素，凭什么说是 $O(1)$？”**

  - **满分抢答（均摊分析法）**：

    假设我们连续 `push` 了 $N$ 个元素进 `inStack`，然后执行一次 `pop`。这唯一的这一次 `pop` 确实触发了 `while` 循环，耗时 $O(N)$。

    **但是**，接下来的 $N-1$ 次 `pop`，因为 `outStack` 里已经有倒好的数据了，它们都不会触发 `while` 循环，耗时全都是纯粹的 $O(1)$！

    每一个元素，在其生命周期内，**最多只会被压入 `inStack` 一次，弹出 `inStack` 一次，压入 `outStack` 一次，弹出 `outStack` 一次**。

    这意味着一系列的搬运开销被平摊（Amortized）到了每一次出队操作上，所以平均下来，每次 `pop` 的均摊时间复杂度就是绝对的 **$O(1)$**。这就叫“平时不烧香，偶尔大搬家，长期来看依然很划算”。
