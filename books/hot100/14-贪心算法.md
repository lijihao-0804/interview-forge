### 📝 算法笔记：121. 买卖股票的最佳时机 (Best Time to Buy and Sell Stock)

-----

- **📌 核心题意**：

  给定一个数组 `prices` ，它的第 `i` 个元素 `prices[i]` 表示一支给定股票第 `i` 天的价格。

  你只能选择 **某一天** 买入这只股票，并选择在 **未来的某一个不同的日子** 卖出该股票。设计一个算法来计算你所能获取的最大利润。

  返回你可以从这笔交易中获取的最大利润。如果你不能获取任何利润，返回 `0` 。

  **示例 1：**

  **输入：**[7,1,5,3,6,4]
  **输出：**5
  **解释：**在第 2 天（股票价格 = 1）的时候买入，在第 5 天（股票价格 = 6）的时候卖出，最大利润 = 6-1 = 5 。
       注意利润不能是 7-1 = 6, 因为卖出价格需要大于买入价格；同时，你不能在买入前卖出股票。

  **示例 2：**

  **输入：**prices = [7,6,4,3,1]
  **输出：**0
  **解释：**在这种情况下, 没有交易完成, 所以最大利润为 0。

  **提示：**

  - `1 <= prices.length <= 105`
  - `0 <= prices[i] <= 104`

- **🧠 思考过程**：

  1. **直觉与痛点（先知模式的失败）**：

     最暴力的做法是用两层 `for` 循环：第一层遍历买入的时间，第二层遍历卖出的时间，找出差值最大的。时间复杂度 $O(N^2)$，在庞大的股市数据前必定超时。

     还有同学试图找“全局最低点”和“全局最高点”，但如果全局最高点出现在全局最低点之前呢？（比如 `[7, 1]`，你不能在第 2 天花 1 块钱买，然后穿越回第 1 天按 7 块钱卖）。

  2. **破局思路（底线思维 / 贪心策略）**：

     我们换一种思维：假设我**必须在今天卖出**，那我能赚多少钱？

     显然，只要我在**今天之前出现过的最低价格**买入，我今天卖出的利润就是最大的！

     所以，随着时间（游标）一天天往后走，我们根本不需要两层循环，只需要在遍历的过程中，死死记住两件事：

     - **`minPrice`（历史最低价）**：如果今天跌破了历史最低价，我就更新它（作为未来可能的买入点）。
     - **`maxProfit`（历史最高利润）**：如果今天没跌破历史最低价，我就算一下：如果今天卖，利润是多少（`今天价格 - 历史最低价`）？如果这个利润比我之前算出来的利润还要高，我就更新 `maxProfit`。

- **🛠️ Java 规范代码（满分一次遍历版）**：
```Java
class Solution {
    public int maxProfit(int[] prices) {
        // 边界防御：如果只有不到 2 天，根本没法买卖
        if (prices == null || prices.length < 2) {
            return 0;
        }

        // 记录历史最低价格，初始值设为第一天的价格（或者 Integer.MAX_VALUE）
        int minPrice = prices[0];
        // 记录历史最大利润，初始值为 0（即便亏本大不了我不操作，利润就是 0）
        int maxProfit = 0;

        // 时光游标，从第二天开始一天天往后走
        for (int i = 1; i < prices.length; i++) {
            // 如果今天的价格比历史最低价还要低，说明今天绝不是卖出的好时机，而是未来可能买入的好时机
            if (prices[i] < minPrice) {
                minPrice = prices[i];
            } 
            // 如果今天的价格没跌破底线，那我就试试今天卖出会怎样
            else {
                int currentProfit = prices[i] - minPrice;
                // 如果今天卖出的利润，比我之前记录的最大利润还要高，那就更新最高纪录！
                if (currentProfit > maxProfit) {
                    maxProfit = currentProfit;
                }
            }
        }

        return maxProfit;
    }
}
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：**$O(N)$**。我们只需要让时间游标顺着数组走一遍，每一步只做极简单的比较和减法运算，性能拉满。
  - **空间复杂度**：**$O(1)$**。仅仅用了 `minPrice` 和 `maxProfit` 两个整型变量，完全是常数级别的空间开销。

#### 💡 面试避坑与考点拓展（大厂的连环计）

1. **大厂追问 1：“如果我允许你买卖【无数次】，也就是买完可以卖，卖完立刻又能买，只要能赚差价就行，代码怎么改？”（对应力扣 122 题：买卖股票的最佳时机 II）**
   - **满分抢答（贪心极致）**：如果是买卖无数次，那就极其简单了！我们只需要关注**相邻两天**的价格差。只要明天的价格比今天高，我们就在今天买、明天卖，把所有微小的上涨波段全部吃掉（即使是 `A -> B -> C` 的连续上涨，`B-A + C-B` 也完美等于 `C-A`）。
   - 代码只需一行核心逻辑：`if (prices[i] > prices[i-1]) profit += prices[i] - prices[i-1];`。
2. **大厂追问 2：“这道题除了贪心，还有没有更系统的解法？”**
   - **架构师级回答**：这道题最正统的底层思想其实是**状态机 DP（动态规划）**。
   - 我们可以定义一个二维数组 `dp[i][0]` 表示第 `i` 天手里【没有】股票时的最大现金，`dp[i][1]` 表示第 `i` 天手里【持有】股票时的最大现金。
   - 虽然在这道题里用 DP 显得有些杀鸡用牛刀（因为它可以被压缩成上面那种贪心写法），但只要掌握了这种 DP 状态机的写法，后面那些什么“最多买卖 K 次”、“带手续费”、“带冷冻期”的股票 Hard 题，全都可以用同一个模板闭眼秒杀！

### 📝 算法笔记：55. 跳跃游戏 (Jump Game)

-----

- **📌 核心题意**：

  给你一个非负整数数组 `nums` ，你最初位于数组的 **第一个下标** 。数组中的每个元素代表你在该位置可以跳跃的最大长度。

  判断你是否能够到达最后一个下标，如果可以，返回 `true` ；否则，返回 `false` 。

  **示例 1：**

  **输入：**nums = [2,3,1,1,4]
  **输出：**true
  **解释：**可以先跳 1 步，从下标 0 到达下标 1, 然后再从下标 1 跳 3 步到达最后一个下标。

  **示例 2：**

  **输入：**nums = [3,2,1,0,4]
  **输出：**false
  **解释：**无论怎样，总会到达下标为 3 的位置。但该下标的最大跳跃长度是 0 ， 所以永远不可能到达最后一个下标。

  **提示：**

  - `1 <= nums.length <= 104`
  - `0 <= nums[i] <= 105`

- **🧠 思考过程**：

  1. **直觉与痛点（DFS 的死局）**：

     很多同学刚做完回溯题，第一反应是：我站在位置 0，可以跳 1 步、2 步、3 步... 我挨个递归去试，只要有一条路通了就返回 true。

     **痛点**：这种尝试所有跳跃组合的方法时间复杂度是 $O(2^N)$，遇到极长数组绝对会超时（TLE）。而且，题目根本不关心你是“怎么跳过去”的，它只关心“能不能过去”。

  2. **破局思路（格局打开：看覆盖范围）**：

     我们引入一个极其霸道的全局变量：**`maxReach`（当前能到达的最远距离 / 覆盖雷达）**。

     - 假设当前我们在索引 `i`，这里的数字是 `nums[i]`，那么在这个点，我们能把雷达向前推进到的最远距离就是 `i + nums[i]`。
     - 我们从左到右遍历数组，不断用 `i + nums[i]` 去更新 `maxReach`。
     - **只要 `maxReach` 大于等于了最后一个位置的索引，就说明我们赢了！**

  3. **核心微操（致命的断崖）**：

     有一个致命前提：**你必须能走到当前这个点，才能享受这个点带来的跳跃距离加成**。

     如果当前遍历到的索引 `i`，已经**大于**了我们的 `maxReach`，说明什么？说明我们就算拼了老命，也走不到索引 `i` 这里！前面出现了无法逾越的鸿沟（比如一堆 0），此时直接判死刑，返回 `false`。

- **🛠️ Java 规范代码（极简贪心覆盖版）**：
```Java
class Solution {
    public boolean canJump(int[] nums) {
        // 记录当前能够覆盖到的最远索引
        int maxReach = 0;
        
        for (int i = 0; i < nums.length; i++) {
            // 🌟 致命校验：如果你连当前的索引 i 都够不到，说明你被困在前面了，死局！
            if (i > maxReach) {
                return false;
            }
            
            // 如果能走到当前位置，那就看看当前位置能不能让我们的覆盖雷达更远一点
            maxReach = Math.max(maxReach, i + nums[i]);
            
            // 🌟 性能优化（剪枝）：如果雷达的覆盖范围已经达到甚至超越了终点，直接胜利下班！
            if (maxReach >= nums.length - 1) {
                return true;
            }
        }
        
        return true;
    }
}
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：$O(N)$。我们只需要从头到尾扫一遍数组，每次循环里只做一次加法和一次比较，没有比这更快的了。
  - **空间复杂度**：$O(1)$。全局只维护了一个 `maxReach` 变量，真正的原神级极致空间。

#### 💡 面试避坑与考点拓展（大厂连环绝杀）

- **大厂追问：“如果保证你一定能跳到终点，但我现在要求你用【最少的跳跃次数】到达终点，你怎么写？”（对应力扣 45 题：跳跃游戏 II）**
  - **满分降维打击（贪心进阶版）**：这也是极其高频的连环题！如果要求最少跳跃次数，我们就不光要维护“最远覆盖距离（`maxReach`）”，还要维护一个“当前这一步能管辖的边界（`currentEnd`）”。
  - 每次遍历时依然更新 `maxReach`，但**只有当游标 `i` 走到了 `currentEnd` 时，我们才不得不被迫起跳（跳跃次数 `+1`）**，然后把 `currentEnd` 更新为当前攒下的最大 `maxReach`。这是一种极其美妙的“不到万不得已绝不开大招”的贪心策略，同样是 $O(N)$ 解决！

### 📝 算法笔记：45. 跳跃游戏 II (Jump Game II)

-----

- **📌 核心题意**：

  给定一个长度为 `n` 的 **0 索引**整数数组 `nums`。初始位置在下标 0。

  每个元素 `nums[i]` 表示从索引 `i` 向后跳转的最大长度。换句话说，如果你在索引 `i` 处，你可以跳转到任意 `(i + j)` 处：

  - `0 <= j <= nums[i]` 且
  - `i + j < n`

  返回到达 `n - 1` 的最小跳跃次数。测试用例保证可以到达 `n - 1`。

  **示例 1:**

  **输入:** nums = [2,3,1,1,4]
  **输出:** 2
  **解释:** 跳到最后一个位置的最小跳跃数是 `2`。
       从下标为 0 跳到下标为 1 的位置，跳 `1` 步，然后跳 `3` 步到达数组的最后一个位置。

  **示例 2:**

  **输入:** nums = [2,3,0,1,4]
  **输出:** 2

  **提示:**

  - `1 <= nums.length <= 104`
  - `0 <= nums[i] <= 1000`
  - 题目保证可以到达 `n - 1`

- **🧠 思考过程**：

  1. **直觉与痛点（过早决策的陷阱）**：

     假设数组是 `[2, 3, 1, 1, 4]`。站在索引 0（数字 2），你可以跳到索引 1 或索引 2。

     你应该跳到哪里？如果你短视地直接跳到索引 2，你会发现那里是个 1，接下来举步维艰；如果你跳到索引 1，那里是个 3，可以直接带你飞到终点。

     **痛点**：如果你每次都盲目地“跳最大步数”，或者用 DFS 去穷举，都会陷入效率陷阱。

  2. **破局思路（引入“阶段性结界”）**：

     我们不仅要维护一个“历史能探测到的最远距离（`maxReach`）”，还要额外维护一个“当前这一跳能管辖的极限边界（`currentEnd`）”。

     - 站在起点，我们获得第一阶段的极限边界。
     - 我们开始在边界内巡逻（遍历）。在巡逻的过程中，我们不断东张西望，把沿途所有起跳点能到达的更远距离都记录在 `maxReach` 里。这叫“蓄力”。
     - **什么时候必须起跳？** 当我们一步步走到当前阶段的极限边界 `currentEnd` 时，说明这一步的红利彻底吃干榨净了！此时，我们**被迫起跳（跳跃次数 `+1`）**，并将边界更新为我们刚才蓄力攒下的 `maxReach`，开启下一阶段的巡逻！

- **🛠️ Java 规范代码（满分延迟决策版）**：



```Java
class Solution {
    public int jump(int[] nums) {
        // 如果数组长度只有 1，你已经在终点了，不需要跳
        if (nums.length == 1) return 0;
        
        // 记录跳跃的次数
        int jumps = 0;
        // 记录当前这一跳所能管辖的最远边界
        int currentEnd = 0;
        // 记录在遍历过程中，探路雷达发现的全局最远距离
        int maxReach = 0;
        
        // 🌟 致命细节：为什么只遍历到 nums.length - 2（即 i < nums.length - 1）？
        // 因为如果你遍历到了最后一个元素，并且恰好 currentEnd 就是最后一个元素，
        // 算法会傻乎乎地再加一次 jump，但其实你已经到终点了！
        for (int i = 0; i < nums.length - 1; i++) {
            
            // 1. 沿途巡逻，疯狂蓄力：看看在当前边界内，谁能跳得最远
            maxReach = Math.max(maxReach, i + nums[i]);
            
            // 2. 撞南墙了：当前这一跳的红利吃光了，被迫起跳！
            if (i == currentEnd) {
                jumps++; // 真实地跳出一步
                currentEnd = maxReach; // 边界扩张为刚刚蓄力攒下的最远距离
                
                // 性能优化（剪枝）：如果更新后的边界已经能盖住终点了，提前下班！
                if (currentEnd >= nums.length - 1) {
                    break;
                }
            }
        }
        
        return jumps;
    }
}
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：**$O(N)$**。我们只需要从头到尾遍历数组一次，在边界处做一下交接，没有多余的循环。
  - **空间复杂度**：**$O(1)$**。全程只维护了 `jumps`, `currentEnd`, `maxReach` 三个变量。

#### 💡 面试避坑与考点拓展（大厂的死亡陷阱）

1. **极度高频坑点：“为什么循环条件是 `i < nums.length - 1`，而不是 `i < nums.length`？”**
   - **大厂面试官最爱抓的细节**：假设数组是 `[2, 3, 1]`。
   - 起点 `i=0`：`maxReach = 2`，此时 `i == currentEnd (0)`，被迫起跳，`jumps` 变成 1，`currentEnd` 变成 2。
   - 接着走到 `i=1`：`maxReach = 4`。
   - 走到 `i=2`（最后一个元素）：如果你的循环包含最后一个元素，此时发现 `i == currentEnd (2)`，程序会**错误地再次触发起跳**，让 `jumps` 变成 2！
   - **真相**：只要你抵达了最后一步，你就赢了，绝对不需要在终点线上再起跳一次！所以我们要把最后一个元素排除在循环之外。
2. **升华总结：“BFS (广度优先搜索) 的降维”**
   - 其实，这道题的贪心逻辑，本质上是 **隐式的广度优先搜索 (BFS)**。
   - 起点 `[0]` 是第 0 层。
   - 起点能跳到的 `[1, 2]` 是第 1 层。
   - `[1, 2]` 能跳到的更远的地方是第 2 层。
   - `currentEnd` 其实就是 BFS 每一层的分界线！每次走到 `currentEnd`，就是遍历完了一层，步数（层数）+1。如果你能在面试中点破“贪心其实是优化后的 BFS”，面试官会直接给你打出 SSP（特级 Offer）的评分！

### 📝 算法笔记：763. 划分字母区间 (Partition Labels)

----

- **📌 核心题意**：

  给你一个字符串 `s` 。我们要把这个字符串划分为尽可能多的片段，同一字母最多出现在一个片段中。例如，字符串 `"ababcc"` 能够被分为 `["abab", "cc"]`，但类似 `["aba", "bcc"]` 或 `["ab", "ab", "cc"]` 的划分是非法的。

  注意，划分结果需要满足：将所有划分结果按顺序连接，得到的字符串仍然是 `s` 。

  返回一个表示每个字符串片段的长度的列表。

  **示例 1：**

  **输入：**s = "ababcbacadefegdehijhklij"
  **输出：**[9,7,8]
  **解释：**
  划分结果为 "ababcbaca"、"defegde"、"hijhklij" 。
  每个字母最多出现在一个片段中。
  像 "ababcbacadefegde", "hijhklij" 这样的划分是错误的，因为划分的片段数较少。

  **示例 2：**

  **输入：**s = "eccbbbbdec"
  **输出：**[10]

  **提示：**

  - `1 <= s.length <= 500`
  - `s` 仅由小写英文字母组成

- **🧠 思考过程**：

  1. **直觉与痛点（不可分割的羁绊）**：

     题目要求“同一个字母最多只能出现在一个片段中”。这意味着，如果你在片段里包容了字符 `'a'`，那么这个字符串里**所有的 `'a'`** 都必须被强行拉进这个片段里，一个都不能少！

     **痛点**：如果你边看边切，走到 `'a'` 刚想切一刀，结果发现后面很远的地方还有一个 `'a'`，你之前的切割就全部作废了。

  2. **破局思路（先做背调，再划结界）**：

     既然我们要保证包含所有的同类字符，我们为什么不先对所有字符做一次“背景调查”？

     - **第一遍扫描**：记录下每个字符在字符串中**最后一次出现的索引（Deadline）**。
     - **第二遍扫描**：我们开始从头划定“结界”（用 `start` 和 `end` 两个指针）。

     当我们遍历到字符 `c` 时，查一下它的 Deadline 在哪。为了包容它，我们的当前片段结界 `end` 必须**至少**扩展到它的 Deadline。

     如果在扩展的途中，又遇到了其他字符（比如 `'b'`），且 `'b'` 的 Deadline 比当前结界还要远，那对不起，结界 `end` 只能被迫继续向后扩张！

  3. **核心微操（贪心结算的瞬间）**：

     什么时候这个结界算彻底稳固了？

     **当你遍历的当前索引 `i`，恰好等于当前结界的极限边界 `end` 时！**

     这说明什么？说明在这个结界里，所有的字符都已经齐聚一堂，没有任何一个字符的“分身”流落在结界之外了！此时果断手起刀落，切出一段，然后开启下一个新结界。

- **🛠️ Java 规范代码（满分两次遍历版）**：
```Java
import java.util.ArrayList;
import java.util.List;

class Solution {
    public List<Integer> partitionLabels(String s) {
        // 1. 战前背调：记录每个字符最后一次出现的位置（Deadline）
        // 因为全是小写字母，用长度为 26 的数组完美替代 HashMap，极致提速
        int[] last = new int[26];
        for (int i = 0; i < s.length(); i++) {
            last[s.charAt(i) - 'a'] = i;
        }

        List<Integer> partitions = new ArrayList<>();
        int start = 0; // 当前片段的起始位置
        int end = 0;   // 当前片段的最远边界（结界）

        // 2. 遍历字符串，动态扩张结界
        for (int i = 0; i < s.length(); i++) {
            // 当前字符的 Deadline 可能会迫使我们的结界向后扩张
            end = Math.max(end, last[s.charAt(i) - 'a']);

            // 🌟 贪心高光时刻：游标 i 终于追赶上了结界的极限！
            // 说明 [start, end] 区间内的所有字符，都没有出现在这个区间之外
            if (i == end) {
                // 结算当前片段的长度
                partitions.add(end - start + 1);
                // 为下一个片段初始化起点
                start = i + 1;
            }
        }

        return partitions;
    }
}
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：$O(N)$。我们仅仅对字符串进行了两次完整的遍历。第一次找最后出现位置，第二次计算区间，非常完美的线性时间。
  - **空间复杂度**：$O(1)$。或者说是 $O(\Sigma)$，其中 $\Sigma = 26$ 是字符集的大小。数组 `last` 永远只占 26 个整型空间，与字符串长度无关。

#### 💡 面试避坑与考点拓展（大厂的底层逻辑）

- **大厂追问：“这道题其实是另一道极其经典的 Hard / Medium 题的特殊降维版，你能看出来是哪道题吗？”（对应力扣 56 题：合并区间）**
  - **满分架构师级回答**：这道题本质上就是“合并区间”！
  - 我们记录每个字符的第一次出现位置 `first` 和最后出现位置 `last`，那么每个字符就变成了一个区间 `[first, last]`。
  - 字符串里有 26 个字符，就等于有 26 个区间。题目要求“同一字母最多出现在一个片段中”，翻译过来就是：把所有有交集的区间全部合并起来！合并后剩下了几个互不相交的大区间，就是我们切出的片段。
  - 只不过因为字符串遍历的天然有序性，我们**省略了显式构建区间并对区间排序的过程**，直接在第二遍遍历中用 `end = Math.max` 隐式地完成了区间合并！点破这层本质，面试官会直接对你刮目相看。
