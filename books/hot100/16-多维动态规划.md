### 📝 算法笔记：62. 不同路径 (Unique Paths)

-----

- **📌 核心题意**：

  一个机器人位于一个 `m x n`网格的左上角 （起始点在下图中标记为 “Start” ）。

  机器人每次只能向下或者向右移动一步。机器人试图达到网格的右下角（在下图中标记为 “Finish” ）。

  问总共有多少条不同的路径？

  **示例 1：**

  ![](https://__LC_IMG_ROOT__/lc-8578560f533f4a.png)

  **输入：**m = 3, n = 7<br>**输出：**28

  **示例 2：**

  **输入：**m = 3, n = 2<br>**输出：**3<br>**解释：**<br>从左上角开始，总共有 3 条路径可以到达右下角。<br>1. 向右 -> 向下 -> 向下<br>2. 向下 -> 向下 -> 向右<br>3. 向下 -> 向右 -> 向下

  **示例 3：**

  **输入：**m = 7, n = 3<br>**输出：**28

  **示例 4：**

  **输入：**m = 3, n = 3<br>**输出：**6

  **提示：**

  - `1 <= m, n <= 100`
  - 题目数据保证答案小于等于 `2 * 109`

- **🧠 思考过程**：

  1. **直觉与痛点（DFS 穷举的死局）**：

     第一直觉往往是回溯法（DFS）：站在起点，要么往下走，要么往右走，一直试探到终点。

     **痛点**：随着网格变大，路径数量呈指数级爆炸。比如 20x20 的网格，路径数高达 353 亿条，DFS 会直接超时（TLE）到天荒地老。

  2. **降维破局（转移方程的推导）**：

     闭上眼睛想一想：机器人是怎么走到终点 `(i, j)` 的？

     因为规定了只能向右或向下，所以它**必定**是从上面一格 `(i-1, j)` 走下来的，**或者**是从左边一格 `(i, j-1)` 走过来的。

     这就意味着：**到达 `(i, j)` 的路径总数 = 到达上方格子的路径数 + 到达左方格子的路径数！**

     完美的状态转移方程诞生：

     $dp[i][j] = dp[i-1][j] + dp[i][j-1]$

  3. **核心微操（边界基石的奠定）**：

     有了公式，我们需要推导的“第一推动力”（基底状态）。

     - **第一行**：机器人要走到第一行的任何一个格子，只能死死地一直往右走。所以第一行所有的格子，路径数都是 **1**。
     - **第一列**：同理，走到第一列的任何一个格子，只能一直往下走。路径数也全都是 **1**。

- **🛠️ Java 规范代码（满分一维空间压缩版）**：

> 在常规解法中，我们会开辟一个 `m x n` 的二维数组。但大厂面试通常要求优化空间。
>
> **空间降维奥义**：我们在计算第 `i` 行的 `dp` 值时，其实只需要用到第 `i-1` 行（上一行）的数据和当前行刚刚算出的左边的数据。所以，我们**只需要一个一维数组在原地不断滚动更新**即可！
```Java
import java.util.Arrays;

class Solution {
    public int uniquePaths(int m, int n) {
        // dp 数组代表到达当前行各个列的路径数
        int[] dp = new int[n];
        
        // 🌟 边界初始化：第一行的所有格子，都只有 1 条路径（一直向右）
        Arrays.fill(dp, 1);
        
        // 从第二行（i = 1）开始，逐行向下计算
        for (int i = 1; i < m; i++) {
            // 从第二列（j = 1）开始，逐列向右计算
            // 注意：第一列永远是 1（一直向下），所以不用管它，直接从 j=1 开始
            for (int j = 1; j < n; j++) {
                // 核心状态转移方程在降维后的体现：
                // 此时的 dp[j] 在等号右边代表的是“上方格子的路径数”（旧数据还没被覆盖）
                // 此时的 dp[j-1] 代表的是“左方格子的路径数”（刚刚在这轮循环算出来的新数据）
                dp[j] = dp[j] + dp[j - 1];
            }
        }
        
        // 算到最后，数组最后一位就是右下角的终点答案
        return dp[n - 1];
    }
}
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：$O(m \times n)$。我们需要遍历整个网格的大部分格子。
  - **空间复杂度**：$O(n)$。我们极其优美地将二维数组压缩成了一个长度为 $n$ 的一维数组。

#### 💡 面试避坑与考点拓展（大厂的连环计）

1. **大厂追问 1：“如果网格里有一些【障碍物】（机器人走不过去），代码怎么改？”（对应力扣 63 题：不同路径 II）**
   - **满分抢答（障碍物结界）**：只需要在状态转移时加一个极简单的判断！
   - 遇到障碍物的格子，它的路径数直接强行设为 `0`（死路一条，无法通行）。
   - 其余的格子照常执行 $dp[i][j] = dp[i-1][j] + dp[i][j-1]$。因为障碍物已经是 0 了，它自然不会把路径数贡献给右边和下边的格子，DP 逻辑依然完美自洽！
2. **大厂终极绝杀：“你能不用动态规划，在 $O(m)$ 的时间复杂度内用纯数学方法算出答案吗？”**
   - **降维打击（组合数学）**：机器人从左上角走到右下角，无论怎么走，它**总共要走的步数是恒定的**。
   - 向下一定要走 $m - 1$ 步，向右一定要走 $n - 1$ 步。总步数是 $(m - 1) + (n - 1) = m + n - 2$ 步。
   - 这个问题就变成了：在总共 $m + n - 2$ 次移动中，**选出哪 $m - 1$ 次是向下走的？**（剩下的必然是向右走的）。
   - 这就是极其标准的组合数公式：$C_{m+n-2}^{m-1}$。
   - 在面试时如果你能先写出 DP，再抛出组合数学公式手写一个阶乘计算，面试官会直接认为你的算法和数学功底深不可测。

### 📝 算法笔记：64. 最小路径和 (Minimum Path Sum)

-----

- **📌 核心题意**：

  给定一个包含非负整数的 `m x n` 网格 `grid` ，请找出一条从左上角到右下角的路径，使得路径上的数字总和为最小。

  **说明：**每次只能向下或者向右移动一步。

  **示例 1：**

  ![](https://__LC_IMG_ROOT__/lc-7dc5d097a117cd.jpg)

  **输入：**grid = [[1,3,1],[1,5,1],[4,2,1]]<br>**输出：**7<br>**解释：**因为路径 1→3→1→1→1 的总和最小。

  **示例 2：**

  **输入：**grid = [[1,2,3],[4,5,6]]<br>**输出：**12

  **提示：**

  - `m == grid.length`
  - `n == grid[i].length`
  - `1 <= m, n <= 200`
  - `0 <= grid[i][j] <= 200`

- **🧠 思考过程**：

  1. **直觉与痛点（局部贪心的灾难）**：

     很多人的第一直觉是“走一步看一步”：每次站在一个格子里，对比下面和右边的数字，谁小就往谁走。

     **痛点**：这种纯贪心是致命的！比如面临向右是 1，向下是 2。你贪心选了 1，结果 1 的后面跟着一个巨大的 100；而 2 的后面全都是 0。贪心算法无法预知未来，必然掉进陷阱。

  2. **降维破局（全局视角的代价沉淀）**：

     我们要用动态规划的“上帝视角”来俯瞰全局。

     闭上眼睛想一想：到达坐标为 `(i, j)` 的格子，**只可能是从上面 `(i-1, j)` 走下来的，或者是从左边 `(i, j-1)` 走过来的**。

     既然只有这两条路，那我只要问：

     “上面那个格子，它一路走过来的历史最低成本是多少？”

     “左边那个格子，它一路走过来的历史最低成本是多少？”

     我从中挑一个**最小的**，然后加上我自己这个格子的过路费，就是到达我这里的最低总成本！

  3. **核心微操（状态转移方程与边界）**：

     状态转移方程极其优雅：

     $dp[i][j] = \min(dp[i-1][j], dp[i][j-1]) + grid[i][j]$

     **边界基石**：

     - 网格的左上角起点：起点就是自带的数字。
     - **第一行**：只能从左边一路走过来，不断累加。
     - **第一列**：只能从上面一路走下来，不断累加。

- **🛠️ Java 规范代码（满分一维空间压缩版）**：

> 同样的，我们可以将二维 DP 数组压缩成一个**一维的滚动数组**，来把空间复杂度降维打击到 $O(n)$。
```Java
class Solution {
    public int minPathSum(int[][] grid) {
        int m = grid.length;
        int n = grid[0].length;
        
        // dp 数组记录到达当前行每一列的最小路径和
        int[] dp = new int[n];
        
        // 1. 初始化第一行的状态（第一行只能从左往右走）
        dp[0] = grid[0][0];
        for (int j = 1; j < n; j++) {
            dp[j] = dp[j - 1] + grid[0][j];
        }
        
        // 2. 从第二行开始，逐行向下扫描
        for (int i = 1; i < m; i++) {
            // 当前行的第一列，只能从上一行的第一列走下来
            // 此时的 dp[0] 存的是上一行的值，直接累加即可
            dp[0] = dp[0] + grid[i][0];
            
            // 从当前行的第二列开始，进行真正的状态转移
            for (int j = 1; j < n; j++) {
                // 此时的 dp[j] 代表上方格子的最小路径和（旧数据）
                // 此时的 dp[j-1] 代表左方格子的最小路径和（刚刚算出的新数据）
                // 取两者较小值，加上当前格子的过路费
                dp[j] = Math.min(dp[j], dp[j - 1]) + grid[i][j];
            }
        }
        
        // 最终推导到一维数组的最后一位，就是右下角的最小路径和
        return dp[n - 1];
    }
}
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：$O(m \times n)$。我们需要遍历每一个格子一次来进行状态转移计算。
  - **空间复杂度**：$O(n)$。我们优化掉了二维数组，仅仅使用了一个长度为列数 $n$ 的一维滚动数组。

#### 💡 面试避坑与考点拓展（大厂的工程与算法博弈）

1. **大厂追问 1：“我看你用了一维数组，空间复杂度是 $O(n)$。你能把空间复杂度优化到极其绝对的 $O(1)$ 吗？”**
   - **满分抢答（原地修改原数组）**：绝对可以！因为原网格 `grid` 中的数据，我们在用过一次之后就不再需要它原本的“过路费”了。所以我们可以**直接在 `grid` 数组上原地修改**，让 `grid[i][j]` 变成到达该格子的最小路径和。
   - **架构师的高能反转（工程操守）**：但在面试中，你一定要紧接着补上一句：“**虽然这样可以做到 $O(1)$ 空间，但在实际工业级工程中，我们通常极其反对修改传入的输入参数（Input Mutation）。** 这会导致脏数据，破坏了函数的幂等性和调用方的状态。所以如果内存不紧缺，保留 $O(n)$ 的一维滚动数组是工程上最优雅的妥协。” —— 面试官听到这句话，绝对会在心里给你打上“Senior 工程师”的标签。
2. **大厂追问 2：“这道题规定了只能【向下】或【向右】走。如果我放开限制，允许你【上下左右】随便走，代码该怎么改？”**
   - **降维打击（知识领域跨越）**：这就不再是一道动态规划题了！因为如果能上下左右走，就会产生**环（Cycles）**，DP 的“无后效性”被彻底打破（当前状态会依赖未来状态）。
   - 此时，网格退化成了一张带权有向图，求最短路径。我们必须祭出图论领域的王牌：**Dijkstra 算法**（结合优先队列/小顶堆进行广度优先搜索最短路）。

### 📝 算法笔记：5. 最长回文子串 (Longest Palindromic Substring)

-----

- **📌 核心题意**：

  给你一个字符串 `s`，找到 `s` 中最长的 回文 子串。

  **示例 1：**

  **输入：**s = "babad"<br>**输出：**"bab"<br>**解释：**"aba" 同样是符合题意的答案。

  **示例 2：**

  **输入：**s = "cbbd"<br>**输出：**"bb"

  **提示：**

  - `1 <= s.length <= 1000`
  - `s` 仅由数字和英文字母组成

- **🧠 思考过程**：

  1. **直觉与痛点（暴力的代价与 DP 的浪费）**：

     - **暴力法**：找出所有的子串（$O(N^2)$ 个），再挨个判断是不是回文（$O(N)$），总时间 $O(N^3)$，直接超时。
     - **动态规划**：开一个二维数组 `dp[i][j]` 记录子串是否为回文。时间 $O(N^2)$，空间也是 $O(N^2)$。如果字符串长度达到 1000，需要极其庞大的内存开销。

  2. **破局思路（回文的天然对称性）**：

     回文串有一个极其美妙的物理特性：**它必定是绕着某个“中心”绝对对称的！**

     既然如此，我们为什么要从两头往中间检查呢？完全可以“站在中心，向两边同时扩散”！

     只要两边的字符相等，我们的回文雷达就可以继续向外扩张；一旦不相等，扩张立刻停止，当前的回文长度也就确定了。

  3. **核心微操（奇偶双中心的幽灵陷阱）**：

     这里的致命难点在于，回文串有两种形态：

     - **奇数长度（如 `"aba"`）**：它的中心是一个**实实在在的字符**（`'b'`）。

     - **偶数长度（如 `"abba"`）**：它的中心是**两个字符中间的虚空缝隙**（`'b'` 和 `'b'` 之间）。

       为了做到滴水不漏，我们遍历字符串的每一个索引 `i` 时，都要以它为中心做**两次扩散**：

       一次把 `i` 当作唯一的中心（奇数扩散）；

       另一次把 `i` 和 `i+1` 当作共同的中心（偶数扩散）。

- **🛠️ Java 规范代码（满分中心扩展法）**：
```Java
class Solution {
    public String longestPalindrome(String s) {
        // 边界防御
        if (s == null || s.length() < 1) {
            return "";
        }

        // 记录最长回文子串的起始位置和结束位置
        int start = 0;
        int end = 0;

        // 游标 i 依次遍历字符串的每一个字符
        for (int i = 0; i < s.length(); i++) {
            // 方案 A：以当前字符 i 为唯一中心，向两边扩散（处理奇数长度回文）
            int len1 = expandAroundCenter(s, i, i);
            // 方案 B：以 i 和 i+1 之间的缝隙为中心，向两边扩散（处理偶数长度回文）
            int len2 = expandAroundCenter(s, i, i + 1);
            
            // 挑出这两种方案里，扩散出来的最大长度
            int len = Math.max(len1, len2);

            // 如果新长度打破了历史记录，更新 start 和 end
            if (len > end - start) {
                // 🌟 致命数学推导：已知中心位置 i 和回文总长度 len，求起点和终点
                // 无论奇偶，起始坐标推导公式都是自洽的：
                start = i - (len - 1) / 2;
                end = i + len / 2;
            }
        }

        // 截取并返回最长回文子串（注意 substring 的右边界是开区间，所以要 end + 1）
        return s.substring(start, end + 1);
    }

    // 辅助函数：雷达中心扩散，返回扩散能达到的最大长度
    private int expandAroundCenter(String s, int left, int right) {
        // 只要没有越界，且左右指针指向的字符相等，就继续疯狂向外扩张
        while (left >= 0 && right < s.length() && s.charAt(left) == s.charAt(right)) {
            left--;
            right++;
        }
        // 循环被打破时，left 和 right 已经指向了不满足条件的字符
        // 此时真实的回文串长度应该是 (right - 1) - (left + 1) + 1 = right - left - 1
        return right - left - 1;
    }
}
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：$O(N^2)$。共有 $2N-1$ 个中心点（$N$ 个单字符中心，加上 $N-1$ 个双字符间隙中心）。围绕每个中心向外扩展，最坏情况下可能要扩散 $N/2$ 步。所以总时间依然是优秀的平方级别。
  - **空间复杂度**：$O(1)$。只用了 `start`、`end` 和几个整型变量，相比动态规划省下了极大的二维数组内存，这是纯正的工业级代码。

#### 💡 面试避坑与考点拓展（大厂的数学迷阵与终极绝杀）

1. **极度高频坑点：计算 `start` 时的偏移量公式是怎么来的？**

   - 很多同学在面试白板写代码时，公式 `start = i - (len - 1) / 2` 总是写错。

   - **满分记忆法**：假设扩散中心是 `i`，总长度是 `len`。

     如果 `len` 是 3（奇数），`len - 1` 就是 2，除以 2 得到 1。`i` 往前走 1 步就是起点。

     如果 `len` 是 4（偶数），中心其实是在 `i` 和 `i+1` 之间。`len - 1` 就是 3，在 Java 整数除法里 `3 / 2 = 1`。所以 `i` 往前走 1 步依然是正确的起点！

     利用 `(len - 1) / 2`，完美抹平了奇偶带来的数学差异，这是这套代码最极客的细节。

2. **大厂终极追踪：“你能把这道题的时间复杂度降到严格的 $O(N)$ 吗？”**

   - **满分降维打击（马拉车算法 Manacher's Algorithm）**：
   - 回答套路：“面试官您好，这道题存在时间复杂度为 $O(N)$ 的 Manacher 算法。它的核心思想是通过向字符串中插入特殊字符（如 `#`），将所有偶数回文转化为奇数回文，并且利用已经计算过的右边界和对称中心，使得后面的扩散过程能够直接借用前面的结果，从而避免重复探测，把时间压榨到了线性级别。”
   - *工程风控提示*：“不过在实际工程中，Manacher 算法代码极其晦涩难懂，维护成本极高。除非明确遇到超大规模字符串的性能瓶颈，否则中心扩展法的 $O(N^2)$ 配合 $O(1)$ 空间，才是性价比最高、最易读的选择。”（这番话说出来，架构师思维直接拉满）。

### 📝 算法笔记：1143. 最长公共子序列 (Longest Common Subsequence)

-----

- **📌 核心题意**：

  给定两个字符串 `text1` 和 `text2`，返回这两个字符串的最长 **公共子序列** 的长度。如果不存在 **公共子序列** ，返回 `0` 。

  一个字符串的 **子序列**是指这样一个新的字符串：它是由原字符串在不改变字符的相对顺序的情况下删除某些字符（也可以不删除任何字符）后组成的新字符串。

  - 例如，`"ace"` 是 `"abcde"` 的子序列，但 `"aec"` 不是 `"abcde"` 的子序列。

  两个字符串的 **公共子序列** 是这两个字符串所共同拥有的子序列。

  **示例 1：**

  **输入：**text1 = "abcde", text2 = "ace" <br>**输出：**3  <br>**解释：**最长公共子序列是 "ace" ，它的长度为 3 。

  **示例 2：**

  **输入：**text1 = "abc", text2 = "abc"<br>**输出：**3<br>**解释：**最长公共子序列是 "abc" ，它的长度为 3 。

  **示例 3：**

  **输入：**text1 = "abc", text2 = "def"<br>**输出：**0<br>**解释：**两个字符串没有公共子序列，返回 0 。

  **提示：**

  - `1 <= text1.length, text2.length <= 1000`
  - `text1` 和 `text2` 仅由小写英文字符组成。

- **🧠 思考过程**：

  1. **直觉与痛点（双指针的迷茫）**：

     很多人的第一直觉是搞两个指针 `i` 和 `j` 分别扫两个字符串，遇到一样的就同时后移。

     **痛点**：假设 `text1 = "abcde"`，`text2 = "ace"`。你遇到 `'a'` 匹配了，那如果遇到 `text1 = "bsbininm"`, `text2 = "jmjkbkjkv"` 呢？面对错综复杂的交替字符，贪心双指针极容易在错误的字符上“过早绑定”，导致丢掉后面更长的匹配机会。

  2. **降维破局（二维矩阵的上帝视角）**：

     既然是两个字符串的纠葛，我们需要一个二维的 DP 数组来记录所有的历史状态。

     定义 `dp[i][j]`：表示 `text1` 的前 `i` 个字符和 `text2` 的前 `j` 个字符，它们的最长公共子序列的长度。

  3. **核心微操（状态转移的两种宿命）**：

     当我们看 `text1` 的第 `i` 个字符（记为 `c1`）和 `text2` 的第 `j` 个字符（记为 `c2`）时，只会有两种情况：

     - **宿命 A（一拍即合：`c1 == c2`）**：

       太完美了！这两个字符可以手牵手加入 LCS 俱乐部。

       那么当前的 LCS 长度，就是它们俩**都没加入时**的长度（也就是左上角的格子），再加上这新的一对。

       $dp[i][j] = dp[i-1][j-1] + 1$

     - **宿命 B（擦肩而过：`c1 != c2`）**：

       它们俩不相等，无法配对。那我们就得做出取舍：

       要么让 `c1` 委屈一下，去看看 `text2` 前面的字符能不能配上（对应上方的格子 $dp[i-1][j]$）；

       要么让 `c2` 委屈一下，去看看 `text1` 前面的字符能不能配上（对应左方的格子 $dp[i][j-1]$）。

       我们是一个贪心且理智的算法，谁留下来的匹配长度更长，我们就继承谁的遗产！

       $dp[i][j] = \max(dp[i-1][j], dp[i][j-1])$

- **🛠️ Java 规范代码（满分标准二维版）**：
```java
class Solution {
    public int longestCommonSubsequence(String text1, String text2) {
        int m = text1.length();
        int n = text2.length();
        
        // 🌟 致命细节：数组长度为什么要 +1？
        // 因为我们需要一排“空字符串”作为基石（Base Case）。
        // dp[0][j] 表示 text1 是空字符串时，无论 text2 是什么，LCS 都是 0。
        // 这极大地简化了边界处理，避免了各种 i-1, j-1 导致的数组越界报错！
        int[][] dp = new int[m + 1][n + 1];
        
        // i 和 j 从 1 开始遍历，对应字符串的第 1 个字符（索引为 0）
        for (int i = 1; i <= m; i++) {
            for (int j = 1; j <= n; j++) {
                // 拿出现实的字符进行比对（注意索引偏移，字符索引是 i-1 和 j-1）
                char c1 = text1.charAt(i - 1);
                char c2 = text2.charAt(j - 1);
                
                if (c1 == c2) {
                    // 字符相等：继承左上角历史记录，并且 + 1
                    dp[i][j] = dp[i - 1][j - 1] + 1;
                } else {
                    // 字符不等：继承上方或左方中较大的那一个
                    dp[i][j] = Math.max(dp[i - 1][j], dp[i][j - 1]);
                }
            }
        }
        
        // 矩阵的最右下角，就是两军交战完毕后的最终结果
        return dp[m][n];
    }
}
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：$O(M \times N)$。$M$ 和 $N$ 是两个字符串的长度，我们需要极其均匀地填满整个二维矩阵。
  - **空间复杂度**：$O(M \times N)$。开辟了一个同等大小的二维 `dp` 数组。

#### 💡 面试避坑与考点拓展（大厂的终极审判）

1. **大厂追问 1：“我看你用了二维矩阵，空间复杂度是 $O(M \times N)$。你能把它优化到一维吗？”**
   - **满分抢答（滚动数组的极致压榨）**：绝对可以！
   - 我们观察转移方程，计算第 `i` 行的 `dp` 值时，仅仅依赖于“当前行（左边）”**和**“上一行（正上方和左上方）”的数据。
   - 所以我们完全可以只开辟一个长度为 $N+1$ 的一维数组。在遍历时，用一个临时变量 `prev` 记住左上角的值（因为会被覆盖），然后不断原地更新这个一维数组。
   - 空间复杂度瞬间从 $O(M \times N)$ 降维到了 $O(\min(M, N))$（把较短的字符串放在内层循环）。
2. **大厂追问 2：“如果我不仅要长度，我还要你把那个具体的【最长公共子序列打印出来】，你怎么做？”**
   - **架构师级回答（DP 逆向回溯法）**：
   - 这也是极其高频的拔高题。我们只需要站在矩阵的右下角 `dp[m][n]`，开始**倒推**寻找来时的路：
   - 如果 `text1[i-1] == text2[j-1]`，说明这个字符绝对在 LCS 里！把它记录下来，然后往**左上角**走（`i--, j--`）。
   - 如果不相等，说明它不在 LCS 里，那是谁把能量传递给它的？我们比较上方 `dp[i-1][j]` 和左方 `dp[i][j-1]`，**谁大就往谁的方向退一步**。
   - 一路退回原点，收集到的字符倒序打印，就是完美的字符串！

### 📝 算法笔记：72. 编辑距离 (Edit Distance)

-----

- **📌 核心题意**：

  给你两个单词 `word1` 和 `word2`， *请返回将 `word1` 转换成 `word2` 所使用的最少操作数*  。

  你可以对一个单词进行如下三种操作：

  - 插入一个字符
  - 删除一个字符
  - 替换一个字符

  **示例 1：**

  **输入：**word1 = "horse", word2 = "ros"<br>**输出：**3<br>**解释：**<br>horse -> rorse (将 'h' 替换为 'r')<br>rorse -> rose (删除 'r')<br>rose -> ros (删除 'e')

  **示例 2：**

  **输入：**word1 = "intention", word2 = "execution"<br>**输出：**5<br>**解释：**<br>intention -> inention (删除 't')<br>inention -> enention (将 'i' 替换为 'e')<br>enention -> exention (将 'n' 替换为 'x')<br>exention -> exection (将 'n' 替换为 'c')<br>exection -> execution (插入 'u')

  **提示：**

  - `0 <= word1.length, word2.length <= 500`
  - `word1` 和 `word2` 由小写英文字母组成

- **🧠 思考过程**：

  1. **直觉与痛点（无从下手的多重宇宙）**：

     当我们看到 `word1 = "horse"`，`word2 = "ros"`。你是该先把 `h` 替换成 `r`？还是先把 `h` 删掉？每一次操作都会引发蝴蝶效应，改变后续字符的位置。用 DFS 穷举会产生极其恐怖的指数级时间复杂度。

  2. **降维破局（二维矩阵与“最后一步”的哲学）**：

     像 LCS 一样，我们引入二维矩阵。定义 `dp[i][j]`：**将 `word1` 的前 `i` 个字符转换成 `word2` 的前 `j` 个字符，所需的最少操作数**。

     我们只看双方的**最后一个字符**（假设是 `c1` 和 `c2`），思考这“最后一步”该怎么走。

  3. **核心微操（状态转移方程的四大宿命）**：

     - **宿命 A（心有灵犀：`c1 == c2`）**：

       太好了，最后这两个字符完全一样，**不需要任何操作**！

       那当前的成本，就完全等于它们俩还没相遇时的成本。

       $dp[i][j] = dp[i-1][j-1]$

     - **宿命 B（痛下杀手：`c1 != c2`）**：

       字符不一样，我们必须花 `1` 块钱动手术。有三种方案，我们挑最便宜的：

       1. **删除**：把 `word1` 的 `c1` 删掉。成本等于 `word1` 前 `i-1` 个字符变成 `word2` 前 `j` 个字符的成本 + 1。也就是看**上方**：$dp[i-1][j] + 1$
       2. **插入**：在 `word1` 末尾插一个 `c2`。这意味着 `word1` 前 `i` 个字符已经搞定了 `word2` 的前 `j-1` 个字符。也就是看**左方**：$dp[i][j-1] + 1$
       3. **替换**：把 `c1` 替换成 `c2`。说明双方的前面都已经匹配好了。也就是看**左上方**：$dp[i-1][j-1] + 1$

       最终决策：$dp[i][j] = \min(dp[i-1][j], dp[i][j-1], dp[i-1][j-1]) + 1$

- **🛠️ Java 规范代码（满分标准矩阵版）**：
```java
class Solution {
    public int minDistance(String word1, String word2) {
        int m = word1.length();
        int n = word2.length();
        
        // dp[i][j] 代表 word1 的前 i 个字符转换成 word2 的前 j 个字符需要的最少步数
        int[][] dp = new int[m + 1][n + 1];
        
        // 🌟 边界基石初始化 (极其重要！)
        // 1. 如果 word2 是空串，那 word1 变成 word2 只能不断【删除】
        for (int i = 0; i <= m; i++) {
            dp[i][0] = i; 
        }
        // 2. 如果 word1 是空串，那 word1 变成 word2 只能不断【插入】
        for (int j = 0; j <= n; j++) {
            dp[0][j] = j;
        }
        
        // 开始在二维矩阵中填表
        for (int i = 1; i <= m; i++) {
            for (int j = 1; j <= n; j++) {
                // 注意索引偏移，第 i 个字符的索引是 i-1
                if (word1.charAt(i - 1) == word2.charAt(j - 1)) {
                    // 字符相等：什么都不用做，直接继承左上角的历史最低成本
                    dp[i][j] = dp[i - 1][j - 1];
                } else {
                    // 字符不等：在【删除(上)】、【插入(左)】、【替换(左上)】中选最小的，然后 + 1
                    int deleteCost = dp[i - 1][j];
                    int insertCost = dp[i][j - 1];
                    int replaceCost = dp[i - 1][j - 1];
                    
                    dp[i][j] = Math.min(Math.min(deleteCost, insertCost), replaceCost) + 1;
                }
            }
        }
        
        // 右下角就是将整个 word1 变成 word2 的最终答案
        return dp[m][n];
    }
}
```

- **⏱️ 复杂度分析**：
  - **时间复杂度**：$O(M \times N)$。$M$ 和 $N$ 为两字符串长度，双重循环填满矩阵。
  - **空间复杂度**：$O(M \times N)$。

#### 💡 面试避坑与考点拓展（大厂的终极拷问）

1. **大厂追问 1：“代码里的 `insertCost` 是看左边，`deleteCost` 是看上边。为什么？能直观解释一下吗？”**

   - **满分大白话解释**：

     - 看上边 `dp[i-1][j]`：意思是 `word1` 舍弃了自己最新的字符（删除了它），所以行数退了一步（`i-1`），而 `word2` 的目标没变（`j`）。这叫**删除**。

     - 看左边 `dp[i][j-1]`：意思是 `word1` 凭空生出了一个字符来迎合 `word2` 最新字符，既然迎合成功了，`word2` 的目标就完成了一个（列数退一步 `j-1`），而 `word1` 自己的主体还没变（`i`）。这叫**插入**。

       把抽象的网格方向翻译成物理意义，面试官会觉得你的基本功无比扎实。

2. **大厂追问 2：“这题的空间复杂度还能优化吗？”**

   - **降维打击（滚动数组）**：绝对可以！和 LCS 一模一样，计算第 `i` 行时，我们只依赖第 `i-1` 行（正上方和左上方）和当前行（左方）。
   - 我们可以把二维数组压缩成一个长度为 `N+1` 的一维数组。在遍历时，用一个临时变量 `prev` 存下马上要被覆盖的左上角的值（`dp[i-1][j-1]`），这样就能在 $O(N)$ 的极限空间内完成手术！
