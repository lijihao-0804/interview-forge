# 465. 最优账单平衡


### 题意

给出多笔转账，可重新安排结算双方。求消除所有净欠款所需的最少转账次数。

### 输入与约束

每笔交易给出付款者、收款者和正金额，允许重新选择结算双方。本实现按题目编号范围使用 21 个余额槽。

### 示例

0 向 1 转 4、1 向 2 转 4。1 的净额为零，剩下 0 和 2 各有符号相反的 4，仅需一次结算。

### 核心不变量

进入 dfs(s) 时，s 之前的参与者已由所选交易结清，s 及后续槽保存等价的剩余净额且总和为零。

### 思路

先按参与者合并净额，移除零余额。回溯选第一个未清债务，让它与一个反号余额结算，递归处理后续人员，再撤销尝试。每条分支都让当前人退出未清集合。

同一人收支抵消后，原来的交易边可以完全忘记，结算只需实现各人的净额。任一最优结算可在零和人群内重新组织支付：一个含 g 人的零和组最多用 g−1 笔结清。选一名未结清的人，把其净额转给同组某个反号者，剩余组仍为零和，所以遍历所有反号伙伴不会丢掉最优分组。

#### 中间人的两笔收支相抵

| 步骤 | 当前状态 | 为什么这样走 |
| --- | --- | --- |
| 登记第一笔 | 0→1 转 4，余额 0:−4，1:+4 | 只需要记每人净收支。 |
| 抵消中间人 | 1→2 转 4，余额 0:−4，1:0，2:+4 | 丢弃零净额的 1，仅两人待结清。 |
| 合并异号余额 | 把 −4 合入 +4，剩余净额 0，返回 1 笔 | 至少一笔才能消除非零净额，这个方案达到下界。 |

### 边界检查

先把每人的转入、转出折算成一个净额。余额为零的人无需继续参与，搜索时只尝试符号相反的两笔净额，避免把问题越拆越大。

### 反例推演

若 A 给 B 10、B 给 C 10，净额只有 A 与 C 非零，一笔结算即可。逐条撤销原交易需要两笔，原始交易条数并非最少结算数。

### Java

#### 一笔结算只暂改伙伴槽

`debts[s]` 在这层数值不变，但递归从 s+1 开始，相当于已经结清。对手的槽临时加上它的净额；返回后用减法复原。符号比较用 long 乘积防止 int 溢出。

```java
import java.util.*;

class Solution {
    public int minTransfers(int[][] transactions) {
        int[] balance = new int[21];
        List<Integer> debts = new ArrayList<>();

        for (int[] t : transactions) {
            final int from = t[0];
            final int to = t[1];
            final int amount = t[2];
            balance[from] -= amount;
            balance[to] += amount;
        }

        for (final int b : balance) if (b != 0) debts.add(b);

        return dfs(debts, 0);
    }

    private int dfs(List<Integer> debts, int s) {
        // 跳过已经清账的人，使当前步骤至少结清一个新的余额。
        while (s < debts.size() && debts.get(s) == 0) ++s;
        if (s == debts.size()) return 0;

        int ans = Integer.MAX_VALUE;

        for (int i = s + 1; i < debts.size(); ++i)
            if ((long) debts.get(i) * debts.get(s) < 0) {
                debts.set(i, debts.get(i) + debts.get(s));
                ans = Math.min(ans, 1 + dfs(debts, s + 1));
                debts.set(i, debts.get(i) - debts.get(s));
            }

        return ans;
    }
}
```

### Python

#### 递归下标让当前债务退出

`dfs(s)` 返回剩余部分的最小笔数。零余额直接跳过，反号伙伴使一次合并有意义；每条分支只改 debts[i] 一个槽，递归返回后必须撤销才能试下一人。

```python
from __future__ import annotations
import math


class Solution:
    def minTransfers(self, transactions: list[list[int]]) -> int:
        balance = [0] * 21

        for u, v, amount in transactions:
            balance[u] -= amount
            balance[v] += amount

        debts = [b for b in balance if b]

        def dfs(s: int) -> int:
            # 跳过已经清账的人，使当前步骤至少结清一个新的余额。
            while s < len(debts) and not debts[s]:
                s += 1
            if s == len(debts):
                return 0

            ans = math.inf

            for i in range(s + 1, len(debts)):
                if debts[i] * debts[s] < 0:
                    debts[i] += debts[s]
                    ans = min(ans, 1 + dfs(s + 1))
                    debts[i] -= debts[s]

            return ans

        return dfs(0)
```

### 复杂度

若有 k 个非零余额，时间最坏 O(k!+t)，t 为交易数；净额与递归空间 O(k+p)，p 为参与者数。

先按交易扫一遍建余额。回溯每层少一人，但可能尝试所有异号伙伴，因而最坏有阶乘级分支；当前路径只修改原余额表。

### 面试追问
