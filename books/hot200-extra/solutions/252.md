# 252. 会议室

### 题意

给出一人的会议起止时间，判断能否参加全部会议，允许上一场结束时马上开始下一场。

### 输入与约束

每个区间给出开始及更晚的结束时刻，结束瞬间可以参加下一场。返回一人能否参加全部会议。

### 示例

[1,3]、[3,5]、[4,6] 中前两场首尾相接，但 4 早于 5，故不能全部参加。

### 核心不变量

若前缀尚无冲突，已处理会议按起点与结束时刻同序，只需把新起点与上一场终点比较。

### 思路

按起点排序，检查后一个起点是否严格小于前一个终点。一旦相邻区间重叠即可返回；相等时没有时间冲突。

将会议按开始时刻排序。若从头至今都没有冲突，已处理区间按结束时刻同样有序；此时只需看当前会议是否越过上一场的结束边界。找到一对重叠就能决定答案，没有必要统计所有冲突对。

### 边界检查

会议按半开区间理解。如果上一场结束时间正好等于下一场开始时间，同一人可以参加两场；判定冲突时应使用严格小于。

### Java

Java 用按起点比较的排序器整理二维数组，之后从第二个区间开始读取前一项的结束时间。若本场起点更早则立即返回 false，扫描完整个数组才返回 true。

#### 核对连续两场的交界时刻

| 步骤 | 当前状态 | 判断依据 |
| --- | --- | --- |
| 排序 | 按开始时刻得到 [1,3]、[3,5]、[4,6] | 从最早会议开始验证。 |
| 比较第二场 | 3=上一场结束 3，允许衔接 | 已检查的前两场可由同一人参加。 |
| 比较第三场 | 4<上一场结束 5，重叠区间为 [4,5) | 出现首个冲突，返回 false。 |

```java
import java.util.Arrays;

class Solution {
    public boolean canAttendMeetings(int[][] intervals) {
        // 按会议开始时间升序排序
        Arrays.sort(intervals, (a, b) -> Integer.compare(a[0], b[0]));

        // 开始时间已排序，只比较相邻两场，首尾相接允许复用时间。
        for (int i = 1; i < intervals.length; i++) {
            // 当前会议的开始时间早于上一场会议的结束时间 => 时间重叠
            if (intervals[i][0] < intervals[i - 1][1]) {
                return false;
            }
        }
        return true;
    }
}
```

### Python

Python 用 intervals.sort(key=...) 原地重排，循环中不创建新的区间。判断用严格小于，可允许前一场结束时立刻参加下一场；零场或一场会议不会触发比较。

#### 核对连续两场的交界时刻

| 步骤 | 当前状态 | 判断依据 |
| --- | --- | --- |
| 排序 | 按开始时刻得到 [1,3]、[3,5]、[4,6] | 从最早会议开始验证。 |
| 比较第二场 | 3=上一场结束 3，允许衔接 | 已检查的前两场可由同一人参加。 |
| 比较第三场 | 4<上一场结束 5，重叠区间为 [4,5) | 出现首个冲突，返回 false。 |

```python
from typing import List


class Solution:
    def canAttendMeetings(self, intervals: List[List[int]]) -> bool:
        # 按开始时间升序排序
        intervals.sort(key=lambda x: x[0])

        # 开始时间已排序，只比较相邻两场，首尾相接允许复用时间。
        for i in range(1, len(intervals)):
            # 当前会议开始时间早于上一场结束时间 => 重叠
            if intervals[i][0] < intervals[i - 1][1]:
                return False
        return True
```

### 面试追问

**能按输入顺序只比较相邻会议吗？** 无序时有冲突的两场可能被很远的会议隔开。排序把最早可能发生的冲突变成相邻比较，才能保证扫一遍就足够。

### 复杂度

n 场会议；时间 O(n log n)，排序额外空间最坏 O(n)。

排序消耗 O(n log n)，随后只有 n−1 次比较。排序库的工作空间应计入所用语言实现，扫描本身仅需常量额外变量。
