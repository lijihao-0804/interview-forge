题目描述

给定一个正整数 x。用 |a| 表示十进制下整数 a 的数位长度，用 sum(a) 表示 a 的十进制数位和。 请在区间 [1,1016] 内，找到满足 的最小整数 a（按数值最小）。如果不存在这样的 a，输出 -1。 例如 |7|=1、|105|=3，而 sum(105)=1+0+5=6。

输入描述

每个测试文件均包含多组测试数据。第一行输入一个整数 T，满足 1≤T≤5×104。 接下来 T 行，每行输入一个整数 x，满足 1≤x≤2500。

输出描述

对于每组测试数据，输出一个整数，为满足条件的最小 a；若不存在，输出 -1。

样例 1

输入 输出 样例解释 ：对 x=9，一位数 9 满足 1×9=9。对 x=20，一位数的数位和最多为 9，不行；两位数需要数位和为 10，最小的是 19。对 x=23，23 是质数，只能拆成一位数且数位和为 23（不可能），或者 23 位数且数位和为 1（超出 1016），所以输出 -1。对 x=18，一位数不行；两位数需要数位和为 9，最小的是 18。

思路分析

第一步：换枚举对象。 直接枚举 a 要扫到 1016，不可行。突破口是位数 L 只有 17 种：只要位数定下来，数位和就被 s=x/L 唯一确定，剩下的问题变成「用指定的数位和拼出最小的 L 位数」。 第二步：定可行性条件。 位数更少的正整数一定更小，所以 L 从 1 往上试，第一个能构造出合法数的 L 给出的就是答案。L 可行需要同时满足 其中上界来自每一位最多为 9，下界来自 a 是正整数、数位和至少为 1。 第三步：给定 L 与 s 时拼出最小的数。 数值先比高位，所以从高位往低位填，每一位尽量小：当前位不能小到让后面 rest 位全填 9 也凑不够剩余的数位和，于是当前位取 其中 low 在首位为 1、其余位为 0——首位不能为零，其它位可以。比 d 更小的取值要么违反首位非零，要么让剩余位无法凑满，所以每一位都取到了可行范围内的最小值，拼出的数最小。 第四步：处理上界。 1016 是 17 位数、数位和为 1，只对应 x=17；其余 17 位数都超出区间。因此 L 要试到 17，构造结果大于 1016 时跳过。x=17 在 L=1 时 s=17>9 不可行，答案正是 1016。大于 17 的质数 x 只有 L=1 和 L=x 两种拆法，前者数位和超过 9，后者位数超过 17，输出 -1。 第五步：预处理查表。 T 最多 5×104，而 x 只有 2500 种取值，先把 1∼2500 的答案全部算好，每组询问直接查表。

正确性说明

构造出的 L 位数满足数位和为 s，于是 |a|·sum(a)=L·(x/L)=x，可行性判定不放过任何解。数位贪心每一步都取「当前位最小且剩余位仍能凑满」的值，比它更小的值要么让首位为零，要么让剩余位无法凑满，因此对固定的 L 与 s 构造出的就是最小的 L 位数。又因为任何 L’<L 位数都小于任何 L 位数，而所有更小的位数都已被证明不可行，所以第一个成功构造出的就是全区间内最小的 a。

题解代码

Python 实现

import sys

input = sys.stdin.readline

LIMIT = 10 ** 16  # 区间右端点，它本身是 17 位数
MAX_X = 2500


# 构造长度为 length、数位和为 s 的最小整数
def build_min(length, s):
    num = 0
    for i in range(length):
        rest = length - i - 1  # 当前位之后还剩几位
        d = 1 if i == 0 else 0  # 首位不能为 0，其余位最小可以放 0
        # 后面每位最多放 9，放不下剩余数位和就只能把当前位抬高
        while s - d > 9 * rest:
            d += 1
        num = num * 10 + d
        s -= d
    return num


# 求满足 数位长度 * 数位和 == x 的最小整数，不存在返回 -1
def min_number(x):
    # 位数少的数一定更小，所以长度从小到大试，第一个可行的就是答案
    for length in range(1, 18):
        # 数位和必须是整数，长度不整除 x 的直接跳过
        if x % length != 0:
            continue
        s = x // length
        # 长度为 length 的数，数位和只能落在 [1, 9 * length]
        if s > 9 * length:
            continue
        num = build_min(length, s)
        # 17 位数里只有 10^16 本身不超界
        if num <= LIMIT:
            return num
    return -1


def main():
    t = int(input())
    queries = [int(input()) for _ in range(t)]
    # 预处理 1..2500 的全部答案，每组询问直接查表
    answers = [0] * (MAX_X + 1)
    for x in range(1, MAX_X + 1):
        answers[x] = min_number(x)
    out = [str(answers[x]) for x in queries]
    sys.stdout.write("\n".join(out) + "\n")


main()

复杂度分析

时间复杂度 ：O(V· L2+T)，其中 V=2500 是 x 的取值个数、L≤17 是最大位数。瓶颈是预处理：每个 x 试至多 17 种位数，每次构造逐位填、每位最多抬高 9 次，总量约 6.5×106 次操作；查询每组为 O(1)。 空间复杂度 ：O(V)。存下 1∼2500 的答案表，与询问组数 T 无关。

易错点

1016 本身合法：它是 17 位数、数位和为 1，对应 x=17，其余 17 位数都要在构造后判超界跳过。 首位不能为 0，构造每一位时的下界与其他位不同，直接把所有位都按 0 起步会得到前导零。 判定可行性时两个条件缺一不可：L 要整除 x，商还要不超过 9L。 答案是 1016 量级，中间变量要用 64 位整数保存。 预处理表要覆盖 1∼2500 全部取值，不能只算询问里出现过的那些。
