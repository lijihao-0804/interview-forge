# InterviewForge 前端优化调研报告

> 调研时间：2026-09-05。方法：现有代码盘点 + 浏览器截图目检（桌面 1440px / 移动 390px）+ GitHub 生态调研 + 优秀文档站特性分析。
> 本报告只做调研与方案设计，不包含任何代码改动；所有方案均以"改生成器常量 + 重建"为落地路径。

---

## 一、当前前端现状评估

### 1.1 现有基础（盘点结论）

| 维度 | 现状 | 评价 |
|---|---|---|
| 样式规模 | `site.css` 248 行、`library.css` 215 行 | 精简，组件层薄 |
| 设计令牌 | 有品牌色体系（亮 `#5654d4` / 暗 `#b1afff`）、页面底色、面板色、阴影 | 有雏形，但令牌覆盖面窄（无间距/圆角/字号阶梯令牌） |
| 暗色模式 | 跟随系统 `prefers-color-scheme`，library 侧支持较好 | **无手动切换开关** |
| 动效 | site.css 全文仅 1 处 transition，无 @keyframes | 几乎为零 |
| 字体 | 全系统默认栈，无任何自托管字体；数学公式用 Cambria Math | 标题与正文无层次，观感"素" |
| 功能组件 | 代码高亮（Pygments）、公式 MathML、Mermaid、复制按钮（hot100 侧有，library 侧无）、全文搜索、学习面板图表 | 功能完备 |
| 移动端 | 上一轮已专项优化（溢出/表格滚动） | 达标 |
| 截图目检 | 书架/题解页暗色下干净协调；面包屑朴素、表格无样式强调、无阅读辅助元素 | 底子好，缺"设计感" |

### 1.2 核心结论

当前前端是"**功能完备、视觉朴素**"的状态：令牌体系已有雏形、自动暗色模式是亮点，但与 VitePress/Starlight 这类成熟文档站相比，缺的不是功能而是**排版层次、导航辅助、微动效**三层"设计投入"。且本项目有两条硬约束必须遵守：**零构建零 CDN（离线优先）**、**样式是生成器常量**（`site.css`/`library.css` 改了会被覆盖）——这直接排除了 Tailwind/React 等需要构建链的方案。

## 二、前端美化类 Skill 调研

### 2.1 官方 `frontend-design`（anthropics/skills 仓库收录）⭐ 最推荐

- 定位："让 AI 产出的界面有独特、有意图的视觉设计，而不是模板味默认值"。
- 核心方法论（实测其 SKILL.md 全文）：
  1. **先做 design plan**：色彩 4~6 个命名 hex 值、字体家族与角色、布局概念（ASCII 线框）、设计原则——先定方案再审方案，确认不是"任何同类页面的通用默认"才动手写代码；
  2. **反 AI 模板味清单**（非常实用，可直接当审查表用）：奶油底 + 衬线大标题 + 赤陶色 accent、暗底 + 荧光绿单 accent、零圆角报纸风、SaaS 卡片堆（万物同一圆角 + 同款 rgba(0,0,0,.1) 阴影）、每个标题上方的全大写 eyebrow 标签、`A · B · C` 中点连接、按钮后缀 `→`——这些是 AI 生成页面的"官方识别特征"；
  3. **排版即个性**：一到两个字族、明确的字阶、行长 < 80 字符；
  4. **动效克制**：非用户触发的动效只允许"一次编排好的入场"，每个卡片都 fade-up + hover 上浮是 AI 默认动作；响应用户操作的动效（展开/确认）则鼓励；
  5. **自我批评流程**："build 到一半截图看一眼，一张截图值 1000 token"——**我们已具备浏览器截图工具链**，可直接执行这条流程；
  6. **界面文案写作指南**：从用户视角命名、主动语态、按钮说结果（"保存更改"而不是"提交"）、错误信息不道歉但说清怎么办。
- 对本项目的用法：安装到本项目（`skills/frontend-design/SKILL.md`），每次改 CSS 前让它先出 design plan + 用截图自批评。

### 2.2 Taste-Skill 家族（Leonxlnx/taste-skill，84.5k ★）

- 最大的"AI 审美"技能仓库，旗下一个家族：taste-skill（主）、minimalist、soft、brutalist、redesign、brandkit、image-to-code 等 14 个变体。
- 核心方法论："**Design Read**（先读房间再动手：页面类型/受众/参考/品牌资产 → 一句话宣布设计解读）+ **三档拨盘**（DESIGN_VARIANCE / MOTION_INTENSITY / VISUAL_DENSITY，按 vibe 推档位，如 'Linear-style minimalist' = 5/3/2）+ **反默认纪律**（AI 紫渐变、居中 hero + 暗色 mesh、三等分特性卡、万能玻璃拟态、Inter + slate-900 都是 LLM 默认，禁点名）"。
- ⚠️ 注意其定位声明："Landing pages, portfolios, redesigns. **Not dashboards, not data tables, not multi-step product UI**"——它是营销页/作品集向的。我们的站是文档+数据面板，**官方 frontend-design 更贴合**，taste 家族可借鉴其"拨盘"与"反默认纪律"的思路。

### 2.3 其他

- `Claude-Code-Frontend-Design-Toolkit`（1k★）：Claude 前端产出增强工具集；
- `superdesign-skill`（513★）：迭代式多方案设计；
- 结论：**Skill 的价值不在"生成"而在"审查与方向"**——它们共同强调反模板、先方案后代码、截图自批评。对已有站点做美化（而非新建），官方 frontend-design 的"audit-first"路径最对口。

## 三、"别人的前端"怎么写：文档站标杆特性拆解

调研对象：Starlight（9.2k★）、VitePress（18.3k★）、Docusaurus、Mintlify——与本项目同为"内容型文档站"，特性逐条对照：

### 3.1 它们共有的、我们没有的

| 特性 | 说明 | 对本项目价值 |
|---|---|---|
| **三栏阅读布局** | 左：全站/本模块目录树（粘性）· 中：正文限宽 ~75ch · 右：On This Page（当前页小目录，滚动高亮） | 题解/章节页目前只有折叠式"本页目录"，缺两侧辅助导航——**阅读体验提升最大的一档** |
| **上下篇导航** | 每章底部"← 上一篇 / 下一篇 →"卡片，含章节标题 | 顺序学习场景（我们的核心场景）刚需 |
| **最后更新时间** | 章节底部显示 git 提交日期 | 内容可信度信号 |
| **明暗切换** | 三态（浅/暗/跟随系统），持久化到 localStorage | 目前只跟随系统，用户无选择权 |
| **代码块增强** | 复制按钮（已有）+ 语言徽标 + 行高亮 + 分组标签页 | library 章节页缺复制按钮 |
| **移动端抽屉导航** | 汉堡展开目录树 | 目前移动端无目录可达 |
| **面包屑增强** | 可点击的层级 + 当前页 | 已有面包屑，弱化样式可升级 |
| **搜索体验** | ⌘K 呼出、关键词高亮、分组结果 | 已有 search-index.json 全文搜索，可加快捷键与高亮 |

### 3.2 值得借鉴的设计语言

- **VitePress**：内容区极简、品牌色只出现在交互元素、侧栏滚动高亮、`VPPageNav` 上下篇卡片——克制风格与我们气质一致；
- **Starlight**：Hero 组件（大标题+副标题+按钮+背景渐变）、卡片网格（书架页直接对标）、aside 提示框（note/tip/caution 四色）——我们的"面试追问/易错点"块可以用 aside 样式强化；
- **Mintlify**：卡片化导航首页（书架页可对标其卡片：图标 + 描述 + 进度）、API 文档的分组 tab；
- **Linear/Stripe Docs**：细腻的 1px 边框 + 微弱渐变 + 键盘优先（⌘K）——审美标杆，令牌层面可借鉴其"边框色即分层"的做法。

### 3.3 轻量设计系统选型（零构建约束下）

| 方案 | Stars | 形态 | 适配度 |
|---|---|---|---|
| **Open Props**（argyleink，Google 团队） | 5.5k | 纯 CSS 自定义属性令牌库（间距/字号/缓动/阴影/颜色），无类名无构建 | ★★★★★ 可直接引入令牌层或抄令牌值 |
| Simple.css | 5k | classless 模板 | ★★ 风格朴素，参考价值有限 |
| Pico CSS | — | 语义化标签自动美化 | ★★ 需覆盖大量默认样式 |
| Tailwind/DaisyUI | 42k+ | 需构建链 | ✖ 违背零构建约束 |

结论：**不引入框架，"抄令牌不抄框架"**——把 Open Props 的间距/字阶/缓动令牌体系移植进 `SITE_CSS`/`LIBRARY_CSS` 的 `:root`，这是与"生成器常量"模式最兼容的路径。

## 四、落地路线图（按收益/风险排序）

### P0：排版与阅读体验（纯 CSS/模板层，风险最低）

1. **字体升级**：自托管 Inter（拉丁）+ 思源黑体子集（中文标题）+ JetBrains Mono（代码），woff2 放 `assets/fonts/`（离线可用，禁 CDN）；标题用 600/700 字重与负字距，与正文拉开层次；
2. **阅读页三栏布局**：左侧本模块章节导航（粘性，移动端折叠）、右侧 On This Page 小目录（滚动 spy 高亮）——改 `build_html_site.py` 的阅读页模板 + `build_library.py` 的章节模板；
3. **上下篇导航 + 最后更新时间**：生成期已知章节顺序，构建时直接产出；
4. **明暗三态切换**：header 加切换按钮（浅/暗/系统），localStorage 持久化 + `data-theme` 覆写；
5. **library 章节页补代码复制按钮**（与 site.js 同款逻辑）。

### P1：动效与精致度（CSS 层，克制原则）

6. 令牌层移植 Open Props 的间距/字阶/缓动变量，统一圆角阶梯（现在圆角 6~15px 随意分布）；
7. 微动效：阅读进度条（顶部 2px）、卡片 hover 单一过渡、链接下划线动效——遵守"一次编排入场"纪律，不做逐卡片 fade-up；
8. 表格窄屏滚动加渐变遮罩提示；aside 提示框样式（面试追问/易错点/注意）四色体系；
9. 书架卡片信息升级：章节数、学习进度百分比、最近学习时间、模块图标（数据 API 已有）。

### P2：功能向增强（JS 层）

10. 全文搜索 ⌘K 呼出 + 关键词高亮 + 分组结果（复用现有 search-index.json）；
11. 空状态与骨架屏（首次加载的学习面板）；uPlot 图表主题令牌化（亮暗同步）；
12. 打印样式（题解页可打印为复习卡片）。

### 每一步的验收方式

浏览器截图（亮/暗 × 桌面/移动）四象限对比 + `check_hot100.py` 全绿 + 对照 frontend-design skill 的"反 AI 模板味清单"逐项自查。

## 五、结论

1. **现状**：功能完备、移动端达标、暗色自动——底子好；短板集中在排版层次、导航辅助、微动效三点，均为成熟文档站的"标配配置"，不涉及技术冒险；
2. **Skill**：官方 `frontend-design` 最对口（audit-first + 反模板清单 + 截图自批评），taste-skill 家族适合营销页场景，其方法论可借鉴；安装方式均为放置 SKILL.md，零依赖；
3. **路径**：不引框架，走"令牌移植 + 阅读三栏 + 微动效"的自研路线，全部改动落在生成器常量与模板内，符合零构建与生成器体系两条铁律；
4. **建议起点**：P0 的 1~3（字体、三栏阅读布局、上下篇导航）——这是"看起来上一个档次"性价比最高的组合，完成后再做 P1 动效层。
