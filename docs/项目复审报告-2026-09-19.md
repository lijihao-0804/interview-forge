## 三、本轮新发现

### 3.1 【P1】CI"Python tests"步骤红灯——AI 依赖缺失被静默降级为 not_configured（根因已定位到行）

- **事实**：GitHub Actions API 显示两次 quality workflow（`52e8dd0a`、`2425bf85`）均 `conclusion: failure`，失败步骤为 "Python tests"（`python -m unittest discover -s tests -p "test_*.py"`）。同一命令在开发机（装有 requirements-ai 全量依赖）上通过，因此作者本地未察觉。
- **根因**（已通过两套干净环境复现 + 依赖二分定位）：
  1. CI 只安装 `requirements-dev.txt`（含 server 依赖，**不含** `requirements-ai.txt`）；
  2. AI 教练测试通过环境变量启用 AI（`AI_ENABLED=1` 等，`tests/test_ai_coach.py:516-529`）；
  3. `interview_forge/ai/config.py:113-125` `dependencies_available_for()` 用 `importlib.util.find_spec` 检查 `pydantic`、`langchain_core`、`langchain_openai`，缺失即返回 False；
  4. `ai_coach.ai_capability`（`ai_coach.py:137-139`）因此给出 `not_configured`；`create_ai_task` 在 `tasks.py:470` 抛 `AIServiceError("not_configured")`；
  5. 结果：`AICoachPersistenceTests`×4、`AIDailyQuotaTests`×1、`ProviderV1HardeningTests`×1、`AICoachHTTPTests`×2 共 **8 个测试在干净环境必然失败**。
- **复现证据**：Windows venv（仅 requirements-dev + tzdata）单测失败，`pip install langchain==0.3.27 langchain-core==0.3.72 langchain-openai==0.3.28` 后即 OK；python:3.11 Linux 容器同样复现（`Ran 397 tests, FAILED (failures=2, errors=8)`）。已排除 pydantic 版本（2.13.5 vs 2.11.7）与时区因素。
- **修复建议**：workflow 的安装步骤改为 `pip install -r requirements-dev.txt -r requirements-ai.txt`（一行）。顺带说明：`tzdata==2025.2` 只在 requirements-ai 里且注释写着"Windows 需要"，CI 是 ubuntu 有系统 zoneinfo 不受影响；但 Windows 开发者若只装 requirements-dev 会直接 `ZoneInfoNotFoundError`（本机 venv 已复现 66 个 error），建议把 `tzdata` 挪进 requirements-server 或加环境标记 `tzdata; sys_platform == 'win32'`。
- **顺带发现**：`unittest discover` 在无 node 的环境会让 node 驱动的测试硬失败（容器中 `test_navigation_policy`、`test_ai_frontend_integration` 因 `FileNotFoundError: 'node'` 报错；CI 装了 node 不受影响）。check_hot100 对 node 缺失有 WARN 降级，unittest 这边没有，属健壮性小缺口。

### 3.2 【P1】CI 的 ruff 步骤在测试修复后必然接着红

- **事实**：仓库无任何 ruff 配置（无 ruff.toml/pyproject.toml），CI 使用默认规则（E4/E7/E9/F）。实测（ruff 0.16.8，`--isolated --select E4,E7,E9,F`）：**563 个违规**——F401 未用导入×302、F405 star import 可能未定义×135、E701 单行多语句×51、E402 顶部外导入×31、E702×21、F841×10、E741×6、F403×4。均为真实问题（抽查验证：`ai_coach.py:12` 的 `import hashlib` 确实从未使用；`context_compiler.py:21` 确有 `import *`）。
- **影响**：当前 ruff 步骤因测试先失败而从未执行；一旦 3.1 修复，CI 会继续红。且 `ruff>=0.8,<1.0` 浮动版本，新版本可能引入新规则。
- **修复建议**（三选一，按成本排序）：① 收缩 CI 命令为 `ruff check --select E9,F821`（只查语法级错误）先把门禁立住；② 添加 ruff 配置：默认规则 + `per-file-ignores`，把历史包袱圈进忽略清单，新代码从严；③ 一次性清理（302 个 F401 里大多数可 `ruff --fix` 自动修复）+ 固定 ruff 版本。

### 3.3 【P2】部署前提变化未在运维文档强调：`INTERVIEW_FORGE_AI_CONFIG_KEY` 成为硬依赖

- **证据**：`_cipher()` 在环境变量缺失时抛 `AISecretUnavailable`（`config_store.py:139-141`）。P1-3 修复后，`set_credentials`/`get_credentials`（含旧明文自动迁移）都经它加密解密——**若 VPS 没设置该变量，部署后所有用户的力扣凭证保存、同步、甚至旧凭证读取都会失败**。
- 现状：该变量只在 `docs/AI-MANAGED-CONFIG.md` 提到（针对 AI provider 场景）；MAINTENANCE.md 的服务启动章节没有提及这个新的硬前提。
- **建议**：在 MAINTENANCE 的部署/启动清单中加入"必须设置 `INTERVIEW_FORGE_AI_CONFIG_KEY` 为稳定随机密钥"（含生成示例），并写明丢失后果（已入库密文不可解）。同理 `AI_CHAT_DAILY_LIMIT=0` 的语义（全员禁聊）值得写一行。

### 3.4 【P3】聊天配额在 provider 未配置/流式失败时也已扣减

- **证据**：`stream_session` 在调用 `stream_reply` **之前**扣配额（`chat.py:157`）；若 AI 未配置或流式中途失败，本次额度已消耗。
- **建议**：在扣减前先检查 `config.enabled/configured`（与 stream_reply 的首个检查对齐），或接受现状并在文档注明。量级小，优先级低。

### 3.5 【P3】Origin 校验的允许列表回显请求自身 Host 头

- **证据**：`_same_origin_request` 把 `f"http://{host}"`、`f"https://{host}"` 加入允许集（`app.py:69-77`），host 来自请求的 `Host` 头。经 nginx 固定转发 Host 时安全；但直连 127.0.0.1:8765 的本机/同 VPS 进程可自带 `Host: evil.com` + `Origin: http://evil.com` 通过校验。与 SameSite=Lax 叠加后实际可利用性低。
- **建议**：改为固定配置的站点 origin 白名单（hot100.xyz + 本地开发域），从环境/配置读取。

### 3.6 【P3】中间件对每个已认证响应重发 Set-Cookie

- **证据**：`app.py:136-139` 在 `request.state.session_token` 存在时无条件覆盖 `response.headers["Set-Cookie"]`。与 `session_user` 的滑动续期（`auth.py:408-414`，剩 1/3 有效期时顺延）配合是有意设计；目前没有会与之冲突的路由级 Set-Cookie（login/logout 不走 require_user），但这是靠"恰好没有"维持的隐式约定——未来任何"require_user + 自己写 Cookie"的路由都会被中间件静默覆盖。
- **建议**：仅在响应尚无 Set-Cookie 时才补写，或注明该约定。

### 3.7 【P3】杂项

- `ai/quota.py:19-21`：`_SCHEMA_DONE`/`_SCHEMA_LOCK` 声明夹在两段 import 之间，可读性差（功能正确）。
- `chat/service.py:669-676`：每轮消息都 import + 重算 `budget_for_context_window`；能力解析每次进 `resolve` 链路，成本可接受但可在 runtime 缓存。
- 首页 `refresh()` 仍无请求序号（`index.html`）；低频路径，竞态窗口小。
- `AI_CHAT_DAILY_LIMIT` 上限钳位 100，超出配置被静默钳到 100——管理员改大不生效且无提示，建议启动日志提示实际生效值。
