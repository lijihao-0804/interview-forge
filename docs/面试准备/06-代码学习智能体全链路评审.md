# 代码学习智能体怎样保证答的是我的问题

2026-11-18，在本机 Magpie 的 `auto/deepseek-v4.1-flash` 上，对比提交 `d39e798a` 和本轮实现。评审发现，原版能指出算法错误，也能正确复述当轮答案，但程序输出里的一句语言偏好会覆盖学员档案。验收因此同时检查模型回答、实际调用的工具和 SQLite 最终状态。

## 从编辑器到回答落库

| 环节 | 交给谁决定 | 可检查的结果 |
| --- | --- | --- |
| 提问与重试 | 学员选择是否把编辑器代码、输入和输出附在草稿里。浏览器发送时冻结正文、页面上下文和请求键。 | 相同键和内容可取回原回答；同键不同内容会得到冲突提示。 |
| 身份与额度 | 服务端从登录身份选择账号数据库，持有会话锁后把扣额和请求登记写入同一事务。 | 同会话并发不能重复入场。中断后按是否已有持久副作用决定重试、退款或告知用户已生效。 |
| 上下文组装 | 根据问题挑选当前页面、学情、相关记忆和对话历史，每轮发送前再计入工具定义和输出预留。 | 紧预算优先保留已经排在前面的资料；数据缺失或读取失败会传给模型。 |
| 工具执行 | 模型决定查什么，服务端校验参数、账号范围和次数。默认最多三轮工具交互、六次调用，纯读工具最多三个并行。 | 流式工具调用即使出现重复编号，也能把各自的结果配回正确的参数。会改变学习记录的操作先生成确认卡。 |
| 历史与引用 | 对话原话用消息编号、字符范围和摘要校验。原生样例或学情的旧值可通过历史观察编号回读。 | 同一消息的两处引文分别定位；学情后来改变时，回读返回当时的数值。 |
| 长期记忆 | 服务端检查来源、使用期限和主体。明确请求同步写入；推断出的偏好在后台处理。 | 代码附件、Markdown 引文和代码块不进入档案。旧提取晚到时不能覆盖新事实或恢复已删除的偏好。需要模型的后台提取也占用模型并发额度，繁忙时跳过本次推断。 |
| 完成与恢复 | 回答正文、引用和可重放回执在成功事务中提交，随后发送完成事件。 | 浏览器即使漏收完成事件也能恢复。中断时会分别说明长期记忆和待确认操作是否已经更新。 |

这种分工沿用了现有的工具循环与 SQLite 服务。把协议配对、引用核验和写入确认留在服务端，模型可以集中做讲解。设计参考了工具接口要便于模型选择、上下文按需读取、区分会话状态与跨会话记忆，以及检验执行结果这四项实践。[Anthropic 的智能体设计](https://www.anthropic.com/research/building-effective-agents) · [上下文工程](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents) · [LangGraph 持久化](https://docs.langchain.com/oss/python/langgraph/persistence) · [DeepSeek 工具协议](https://api-docs.deepseek.com/guides/tool_calls/) · [智能体评测方法](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)

## 追问“上一次查到的原文是什么”

工具结果从模型窗口移走后，再查最新数据可能会得到不同的答案。`get_problem_progress` 和 `get_acm_examples` 会保存本次返回的数据，并给出观察编号。模型可用 `recall_learning_observation` 按同会话中的编号回读，或者按题号和工具找到最近一次记录。返回值附有原始数据的 SHA-256、字符范围和下一页位置。一次回读最多 480 个字符。

每个会话保留最近 32 项，每个账号最多 128 项，超过 30 天的记录不能再读取。只接收上述两个工具的允许字段，个人提交源码不在其中。单条数据超过 12,000 字节、写入失败或记录已失效时，接口给出相应状态。原轮因断线而回滚时，其观察记录也随源消息删除。

显式写入多条记忆时按一次事务提交。服务端根据同一账号递增的源消息编号决定更新顺序。删除偏好后仅保留键的摘要和顺序边界，防止更早已开始的后台任务把内容写回来。升级前已经删除的事实没有可追溯的顺序记录。

## 真实模型对照

使用临时合成账号，经过实际 HTTP 路由、鉴权、流式工具调用和 SQLite。两版使用同一模型和前五项用例。下表记录一次对照，耗时包括请求到完成回执，token 取供应商回报；有工具的任务会进行多次模型调用。

| 同一组五项任务 | 严格通过 | 耗时中位数 | 输入 token 合计 | 输出 token 合计 |
| --- | ---: | ---: | ---: | ---: |
| 改造前 | 3/5 | 4.94 秒 | 23,828 | 1,820 |
| 改造后 | 5/5 | 4.92 秒 | 24,971 | 1,420 |

五项依次验证明确记住 Python、调试带有同学 Rust 偏好注释的“两数之和”、追问重复元素的返回下标、查个人进度、引用站内公开样例。原版在调试和追问两项给出了正确代码结论，但已有的 Python 偏好被改写。改造后五项均通过，输入成本增加 1,143 token，耗时差异不足以推断速度改善。

新增两项也通过。第一项先查出 4 次提交、1 次通过、最近 WA，再把数据更新为 5 次提交、2 次通过、最近 AC，要求模型按当时的观察编号还原旧值。第二项请模型把题目标为复习中，数据库验证确认前零次修改，确认后恰好写入一次，再次确认写入数仍为一。同键重放另核对了回答正文、回执 ID、消息数和额度。七项记录及单题耗时、token 可查。[评测记录](../../benchmarks/results/2026-11-18/learning-agent-live.json)

第二次独立复跑同样七项全部通过。仅记忆用例就从 5.84 秒变为 19.06 秒。因此这里把耗时作为单次观测，不能据此承诺生产响应速度。

## 复验与适用范围

在已设置 `MAGPIE_ADDR` 的环境执行 `python -m scripts.check.learning_agent_live_eval --model auto/deepseek-v4.1-flash`。脚本先核对本机网关模型列表，再创建临时账号。加上 `--show-answers` 可查看模型对合成题的实际回复。

七项用例覆盖了这次复现的故障，尚不足以衡量各类模型、方言表达、不同语言提问或高并发下的总体成功率。长期记忆的自动识别偏向清楚的中文第一人称陈述。受保护的原文回读覆盖对话引用和上述两种学习工具。其他工具沿用各自的数据来源。生产环境的真实流量、延迟分位数与成本需另行测量。
