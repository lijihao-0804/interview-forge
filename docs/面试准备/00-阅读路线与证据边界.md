每个问题尽量按四步说：**结论 → 具体执行链 → 选择理由 → 当前边界**。不要只背名词。例如，“我用了 SSE”只说了技术；“模型持续输出，服务端发命名事件，浏览器按事件更新消息和确认卡，连接断开时收回生成资源”才说明了实现。

文中的第一人称答案是口述模板。使用前确认哪些设计和代码确实由自己参与；AI 辅助生成、自己 review、自己验证与自己独立实现，是不同的贡献，不能混说。

技术原理按一手文档校准，而非以面经答案为准：

- [FastAPI：Concurrency and async / await](https://fastapi.tiangolo.com/async/)：区分同步路由的线程池执行与普通函数的直接调用。
- [SQLite：Write-Ahead Logging](https://www.sqlite.org/wal.html)：WAL 改善读写并行，同一数据库仍只有一个写者。
- [MDN：Using server-sent events](https://developer.mozilla.org/en-US/docs/Web/API/Server-sent_events/Using_server-sent_events)：核对流格式、命名事件及注释心跳。

这些链接用来解释通用原理；“InterviewForge 怎么做”以每题源码入口为准。没有查到精确频率，所以文档不使用“某公司必问”“命中率 90%”之类说法。

## 哪些话能说，哪些要收住

| 可以按当前实现讲 | 不能冒充已经完成 |
| --- | --- |
| FastAPI、原生 JS、SQLite 用户库、受限工具循环、持久记忆 | 已实现向量数据库、Embedding RAG、多智能体协作 |
| 用户数据文件隔离、数据库事务和进程内并发限制 | 已具备跨进程分布式锁、消息队列故障恢复、全局 exactly-once |
| 1000 delta 的同步突发测试得到一次流式预览刷新 | 所有真实模型流速都只有一次刷新、主线程耗时固定小于某数值 |
| 功能与回归测试、生产登录/API/数据库聚合验证 | 已有真实负载 QPS、P99、学习效果提升率、完整模型质量评测集 |
| FSRS-4.5 实现和兼容迁移、全站保持率设置 | 个性化训练过 FSRS 参数，证明了真实记忆保持率达到 90% |

截至本次记录，完整测试曾得到 435 passed，之后追加一项测试并通过定向测试；不要直接把 435 当成“当前总数”。CI 已绿。生产 API 与迁移聚合已核验；浏览器视觉及点击验收因工具超时仍未完成。

## 面试前的自检

1. 不看文档能画出一次 Chat 请求从认证到消息落盘的流程。
2. 能解释为什么确认请求成功不等于后台同步完成。
3. 能说出 SQLite、进程内锁、近似 token 预算各自的边界。
4. 能讲一个真实故障：现象、证据、根因、修法、验证与未验证部分。
5. 简历里每个“设计、实现、优化、上线”都有代码或测试依据，且能解释本人贡献。

最有价值的回答不是“什么都做了”，而是能准确说出“这层保证了什么，这层还不能保证什么”。
