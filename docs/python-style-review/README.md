## 后续批量修订采用的原则

1. 先看旧 Java 的叙述，再看旧 Python 代码与来源，判断两者是否对应；好的部分优先保留。
2. 代码优先采用项目已有的优秀实现，保留来源。调整变量、注释或分支时说明整理范围，不把改写说成上游原文。
3. 局部变量直接写 `seen = {}`、`stack = []`；保留力扣常用的函数签名注解。写法简洁，但关键的判断与指针动作不为了短而藏起来。
4. 用具体输入解释每一次状态变化，再讲通用规律；API 的说明围绕代码里实际用到的操作展开。
5. 确有错误、超时风险或讲解与代码不一致时再改算法。可选优化放在扩展里，不因理论复杂度更漂亮就自动替换清楚可靠的主解。
6. 不照搬旧文案中的错误或夸张说法；算法、复杂度、边界和来源分别核对。
