# AI 学习教练阶段 1 交接：确定性学习分析

> 状态：COMPLETE

> 分析契约：analytics-v1

> 是否部署：否

## 1. 本阶段结果

阶段 1 已完成一个不依赖模型的确定性学习分析层：它只读取当前登录用户自己的学习数据库，计算学习概况、题目与模块指标、风险信号、证据引用和数据质量信息，并通过隐藏的只读接口 `GET /api/coach/analytics` 返回结构化 JSON。

本阶段没有接入 LangChain、LangGraph 或模型 API，没有增加前端入口，没有新增或迁移数据库表，也没有部署到 VPS。

## 2. 交付文件

- `tools/learning_analytics.py`：确定性指标、信号、证据、时区与数据质量分析；
- `tools/study_server.py`：当前用户只读接口、缓存、写入失效和账户目录冲突保护；
- `tools/tests/test_learning_analytics.py`：分析契约与合成数据库测试；
- `tools/tests/test_learning_analytics_api.py`：认证隔离、接口、缓存、写入失效和并发测试；
- `docs/ai-handoffs/phase-1.md`：本交接报告；
- `plan.md`：阶段状态与审查成本约束。

## 3. 核心边界

- API 不接受用户名或数据库路径参数；数据库路径只由已认证会话解析；
- 分析器使用只读 SQLite 连接，并验证数据库位于允许的用户目录；
- 不读取 `auth.db` 中的昵称、角色、聊天、反馈、头像、密码或会话内容；
- 不读取或返回力扣凭证；
- 缓存键使用不可逆用户作用域，并包含 schema、规则版本和数据代际；
- 返回集合、来源分类和证据引用均有边界，未知来源归入 `other`；
- 缺库、旧库和部分旧 schema 使用可解释降级，不回退到默认用户库。

## 4. 缓存与并发正确性

学习数据变化后，analytics 与 dashboard 两套读模型都会失效。缓存计算在锁外执行，但写回受代际保护：如果计算期间发生写入，旧快照可以结束当前请求，但不能重新进入共享缓存。

最终集中审查发现并修复了两个 P1：

1. 同一用户多个 analytics 构建同时运行时，active 状态必须使用引用计数，直至最后一个构建结束才允许清理代际；
2. dashboard 构建期间发生失效时，旧结果不得在计算结束后重新填回缓存。

新增测试用 `Event` / `Barrier` 固定并发时序，不依赖易波动的 sleep。

## 5. Windows 用户名目录保护

Windows 文件系统通常不区分目录名大小写。新注册账户现在在同一写事务内执行 `COLLATE NOCASE` 冲突检查，避免 `Alice` 与 `alice` 指向同一学习目录。

对历史上已经存在的大小写冲突账户，登录与会话解析会安全拒绝，不自动改名、合并或移动数据。部署前需要只读检查生产 `auth.db` 是否存在这类历史冲突；若存在，应人工确定每个账户的归属后再处理。

## 7. 非阻断记录

以下 P2 不影响阶段 1 数据正确性与交接，按“减少不必要审查”原则不在本阶段扩项：

- 测试进程中的 `_SCHEMA_DONE` 可能保留少量已经删除的临时路径；
- 异步 HTTP 测试已覆盖真实 HTTP 和 worker，但没有把真实 Cookie 会话与异步同步组合成单独的端到端场景。

后续仅在相关代码再次修改或这些现象实际造成问题时处理，不安排保险性复审。
