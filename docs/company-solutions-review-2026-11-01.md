## 三、P0 问题（必须修复）

### P0-1 `Math/0564-寻找最近的回文数.md`：Java / C++ 在合法输入上抛异常

- **位置**：Java 第 91、121 行；C++ 第 181、195 行
- **触发输入**：`n = "999999999999999999"`（18 位，题面上限 `1 <= n <= 10^18` 内）
- **原因**：`prefix = 999999999`，循环会枚举 `p = prefix + 1 = 1000000000`；`buildPalindrome` 生成 20 位字符串 `"10000000000000000001"`，超过 `long` / `long long` 上限。
  - Java：`Long.parseLong(pal)` 抛 `NumberFormatException`
  - C++：`stoll(pal)` 抛 `std::out_of_range`，程序 RE
- **已复现**：
  ```
  Exception in thread "main" java.lang.NumberFormatException: For input string: "10000000000000000001"
  ```
- **修复建议**：镜像构造前判断位数是否变长，越界则跳过。位数变长的回文一定不会比已有的 `10^len + 1` 更接近：
  ```java
  if (Long.toString(p).length() > (len + 1) / 2) continue;
  ```
  C++ 用 `to_string(p).size() > (len + 1) / 2` 同理；注意该文件后面的位数边界候选 `pow10(len) + 1` 本身是正确且不溢出的。

### P0-2 `String/1044-最长重复子串.md`：三语言二分下界错误，最长重复长度为 1 时返回空串

- **位置**：Java 第 86–97 行；C++ 第 165–175 行；Python 第 233–242 行
- **触发输入**：`"aa"`、`"cbcab"`（存在长度为 1 的重复子串）
- **原因**：二分从 `lo = 0` 开始，`check(0)` 恒返回 `-1`；当搜索区间收敛到 `[0, 1]` 时，`mid` 向下取整为 0，被 `mid > 0` 守卫判为不可行，长度 1 从未被检查。
- **已复现（Python 实现）**：

  | 输入 | 实际输出 | 正确输出 |
  |---|---|---|
  | `"aa"` | `""` | `"a"` |
  | `"cbcab"` | `""` | `"b"` 或 `"c"` |
  | `"aba"` | `"a"` | `"a"` |
  | `"aab"` | `"a"` | `"a"` |

  说明：`n = 3, 4` 时二分恰好会取到 `mid = 1`，所以偶然正确；`n = 2` 或 `n >= 5` 且答案长度为 1 时稳定出错。
- **修复建议**：题面保证 `n >= 2`，把二分下界改为 `lo = 1` 即可；若答案不存在重复子串，`bestLen` 仍保持 0，返回 `""`。也可改用上取整 `mid = (lo + hi + 1) / 2` 并显式把 `L = 0` 视为可行。

### P0-3 `Tree/0814-二叉树剪枝.md`：C++ 未注释地重复定义 `TreeNode`

- **位置**：C++ 代码块第 1 行（文件第 100 行）起
- **原因**：力扣 C++ 判题环境已预置 `TreeNode`，题解中再次 `struct TreeNode { ... };` 会导致 `redefinition`，原样提交无法编译。该批其他树的题解都把定义放在 `/* ... */` 注释中，只有这一篇漏了。
- **修复建议**：把整段 `struct TreeNode` 包进注释（与 `Tree/0297`、`Stack/0589` 等文件的写法一致）。同文件 Python 里也定义了 `TreeNode`，Python 允许重定义且内容一致，不会报错，但建议一并注释以保持统一。
