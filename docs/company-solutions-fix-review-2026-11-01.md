## 五、残留风险（非本次修复引入）

### 1. `Tree/0297` 的递归深度

三种语言都使用递归 DFS。修复只解决了 Python 列表拼接的 O(n²)，没有改变递归深度：

- Python 默认递归上限约 1000：本地构造 999 层链状树即可触发 `RecursionError`（500、900 层可正常往返）；
- Java 在本地默认栈下，10000 层链状树会 `StackOverflowError`。

题面约束为节点数 `[0, 10^4]`，严格来说链状树属于合法输入。若希望完全覆盖约束，可：

- Python：在 `serialize`/`deserialize` 前 `sys.setrecursionlimit(20000)`；或改为显式栈迭代；
- Java / C++：改为迭代遍历，或接受力扣判题环境可能更大的栈。

这不是本次修复的回归，原实现同样存在；标为 P2 残留风险。

### 2. `Math/0564` 的位数边界候选

`pow10(len) + 1` 在 `len = 19`（即 `n = 10^18`）时会在 `long` 中溢出。实测该输入仍返回正确答案 `999999999999999999`（溢出候选被距离比较淘汰），因此没有可观察错误；若想彻底消除该隐患，可对边界候选同样加位数判断。

### 3. `Array/0259` 的最终 `int` 转换

如第三节所述，内部已不溢出，但返回类型限制导致超过 `INT_MAX` 的答案仍会截断。力扣签名如此，实际数据不会触发；若本题用于本地教学，可额外注明“答案保证在 int 范围内”。
