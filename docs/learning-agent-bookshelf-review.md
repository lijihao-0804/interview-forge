# 学习 Agent 如何回到刚才读的章节

2026-11-18 使用普通测试账号提问“LRU 双向链表”，再追问“本轮检索资料卡片第 2 项”。上线前的生产版本首轮调用三次搜索，返回五个章节入口。追问时模型依次查询聊天原文和书架，返回三个章节入口。请求重放正确，但这两个工具都无法按上轮卡片的顺序选定唯一章节。

| 对照机制 | 本站行为与取舍 |
| --- | --- |
| [LlamaIndex CitationQueryEngine](https://developers.llamaindex.ai/python/examples/query_engine/citation_query_engine/) 将编号与具体来源节点关联，支持查看节点内容 | 卡片显示服务器保存的章节顺序。有正文命中时点击链接可在支持文本片段的浏览器中定位关键词。卡片收录进入模型上下文的资料，不能据此推断每句答案均引用了该章。 |
| [LangChain 短期记忆](https://docs.langchain.com/oss/python/langchain/short-term-memory) 将工具步骤和会话状态绑定到线程 | 复用既有账号数据库、会话 ID 和消息边界。追问第几项时从最近一张卡片取对应站内 URL，由当前公开索引重新读取。章节删除后明确报告已失效。 |
| [Anthropic 工具设计](https://www.anthropic.com/engineering/building-effective-agents) 强调用途清楚的工具接口及针对易错输入的测试 | 在已有书架工具中加入互斥的关键词检索与卡片序号回读。同页多概念查询优先连续短语，其次要求所有词均匹配同章。公共搜索沿用原有规则。 |

模型正文可能按推荐优先级重新排列资料。工具定义与系统提示把序号限定为页面上标有“本轮检索资料”的有序列表。读者若明确指正文中的某个标题，应按标题查。两套顺序可能冲突且指代不清时，助手应询问标题或卡片序号。

模型每次读取的索引片段有长度上限。聊天记录保存标题、路径和定位词。回读的是当前索引，书架更新后片段可能变化。旧消息仍可打开章节。超出上下文预算的工具响应、失败的模型响应均沿用既有来源过滤；未进入最终回答上下文的结果不会列入卡片。

## 验收

| 环节 | 原有机制及此次变化 | 仍有的限制 |
| --- | --- | --- |
| 意图与工具选择 | 原有模型按工具描述决定是否搜索。此次补充联合查询、正文标题与卡片编号的区别。 | 模型可能多次搜索。工具调用次数由实测记录。 |
| 检索 | 原有连续短语命中标题、栏目或正文。新增同章全词检索，以及沿上轮已展示 URL 回读。 | 空格分词最多六项，没有同义词推断；索引片段可能短于章节原文。 |
| 上下文预算 | 原有服务根据模型窗口预留输出空间，裁剪历史与工具消息；编排器按保留的工具消息过滤可展示来源。此次回读也经过该过滤。 | 来源只证明章节材料进入该次模型上下文。 |
| 证据与追问 | 原有资料卡、历史消息引用和学习观察继续使用。新卡片序号对应本卡顺序，定位词可以打开正文匹配处。 | 浏览器可能定位到章节内同词的其他出现处。没有逐句答案与原文的映射。 |
| 保存与重放 | 原有服务先提交助手消息与回执，再发完成事件。相同请求 ID 回放同一消息。本次只扩充服务器保存的章节元数据。 | 书架重读反映当前索引，只有既有进度/样例观察支持回看当时的原始工具结果。 |

全量回归发现初版书架系统提示占用了可信状态槽。相同估算器对基线 `bb551122`、初版、修订版的估算分别为 1,872、2,010 和 1,593 tokens，槽上限为 2,000。将书架专用细节移至工具描述并压缩重复规则后，4,096 窗口测试证明模型能同时收到真实的记忆保存回执与待确认状态。短回复“是的”“可以”“开始吧”都能看到该状态，执行权限仍归确认接口。

生产版本 `f60d20f0` 的四轮盲测揭示了另一个缺口。一次澄清隔开首次搜索和追问后，模型声称本会话没有资料卡，漏掉第 2 项的工具调用与来源保存。后续修正从当前账号、本会话、早于当前消息的最近有效卡片取序号，明确请求直接进入原有只读工具执行路径。两份书目顺序不明时直接澄清；越界时返回实查的可用数量。只在提到资料卡时加入短状态提示。进度、确认、配额及重放沿用原路径。

该修正的本机真实 DeepSeek 验收共十一项。首轮搜索 7.75 秒返回三章；插入歧义澄清后，4.25 秒内按第 2 项回到《其他 Map 与 Set 家族》（输入 3,672、输出 283 tokens）。接着请求第 57 项，工具查到最新卡片只有一项，0.31 秒返回准确数量。澄清和越界提示直接来自服务器，没有模型生成用量。

生产版本 `9360c663` 在新旧会话都触发了预期的书架工具，随后的模型步骤却返回 `provider_error`。公开日志没有上游 HTTP 状态或具体字段错误。该版本将服务端发起的读取编码成助手工具调用。后续实现直接运行同一只读工具，把取得的限长索引片段和用户问题放进普通用户轮次，请模型讲解；模型无需重建工具调用。实际送达的请求仍经窗口校验，超出工具结果预算不会发布来源卡。具体上游拒绝原因尚未证实。

实测仓库索引中，“LRU 双向链表”完整短语命中零项，联合查询首项为《0146 LRU 缓存》，定位到“双向链表”。修订后的真实 DeepSeek 模型验收经过本机 HTTP 服务、临时普通账号与实际书架索引，十个场景均通过。首次检索返回三项，耗时 9.80 秒。面对两份书目顺序有歧义的问题，模型请求澄清，未选定章节；明确追问卡片第 1 项后，模型调用一次书架工具，3.34 秒返回对应题解。其余七项覆盖偏好、编辑器、追问、进度重放、公开样例、历史观察和确认动作。

用 `python -m scripts.check.learning_agent_live_eval --model auto/deepseek-v4.1-flash` 复现本机验收。生产探针 `python -m scripts.check.learning_library_production_eval --account-file <普通测试账号文件>` 登录本站，创建独立会话，检查定位词、重放、第二项的准确 URL 与标题以及历史卡片。凭据通过本地 JSON 文件提供，输出仅含工具、耗时、用量和公开章节资料。结果只代表相应账号和该次模型采样。
