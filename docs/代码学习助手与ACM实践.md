# 代码学习助手与 ACM 练习

## 调研与实施顺序

改造前，站点已有对话历史检索、工具调用、恢复对话和独立的代码运行器。通用运行器可以执行一段标准输入，但力扣题库缺少按题提交、判定和保存本站结果的完整路径。助教能读取部分学习记录，用户在编辑器里改过的代码和刚遇到的错误则需要自行描述。

1. **给题目一个稳定的身份。** Hot 100 和补充卷都用题库名加力扣题号标识练习。从题库、题解和编辑器进入时传递相同的身份，查题工具据此读取题目、方法、核心不变量和复杂度。
2. **把提交结果留在学习者自己的记录里。** 服务端选择该题的输入和预期输出，调用隔离执行器，并保存完成判题的提交。累计通过状态、最近一次结果和提交源码可分别查询。
3. **按问题组装对话上下文。** 复盘工具只提取当前用户在这道题上的练习摘要。想讨论具体一版代码时，由用户在编辑器选择附加代码与运行结果，在草稿中检查后发送。系统提示的固定预算同时要容纳记忆回执和待确认操作。

设计参考了 Anthropic 对工具返回具体、紧凑数据的建议，以及 OpenAI 对工具参数和多步调用的说明。这两个原则对应到本站，分别是按题读取学情，以及让模型通过已有工具获得状态、让服务器负责身份和判定。[Anthropic 工具设计实践](https://www.anthropic.com/engineering/writing-tools-for-agents) · [OpenAI 工具调用指南](https://platform.openai.com/docs/guides/function-calling)

## 从一道题开始

在题目目录选择「力扣原题」可打开官方题面，选择「本站 ACM」进入标准输入输出工作台。页内会给出参数顺序和输出约定。两个题库采用每行一个 JSON 参数、输出一个 JSON 值的约定。树、链表、交互接口及有多个合法解的题目，在各自的练习说明中列出本站约定。

「运行当前输入」适合调试单个样例。「提交」使用服务端题目用例生成本站结果。第一次未通过会进入已尝试状态，通过后显示已通过，之后失败的提交也可以在「我的提交记录」中查看。本次判定针对本站公开用例集。力扣官方提交另有自己的记录。

在编辑器打开「问 AI 助教」，可以附上当前代码、标准输入、期望输出和实际运行结果，然后询问“这个输入为什么失败”。做错题复盘时，可以直接问“第 1 题为什么错，我上次用的是什么语言”。助教能读取该题的尝试数、是否曾经通过、最近语言和判定时间。提交源码由用户主动附加。

问“还有什么边界样例”时，助教可调用 `get_acm_examples`，按题号读取本站判题采用的输入、预期输出和来源。工具默认取一例，一次最多取两例。每段输入和输出各保留前 240 个字符，过长时标记截断，并给出下一组样例的序号，便于按需继续读取。

## 复验

- `python -m pytest -q tests/test_native_acm.py` 验证两卷题目契约、参考实现输出、提交状态及隔离。
- `python -m scripts.check.check_hot200_acm_examples` 单独核对补充卷的 200 组输入输出，包括树、迭代器和交互题的离线适配。
- `python -m scripts.check.agent_study_smoke` 用本地模拟身份和流式回复，检查浏览器中的附加代码、编辑与发送，以及两卷题解的定位。运行前需安装 Playwright 的 Chromium。
