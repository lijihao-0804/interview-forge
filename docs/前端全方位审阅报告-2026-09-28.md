## 〇、先说三个必须马上修的线上 Bug（P0/P1）

这三个问题在隔离环境实测复现，都直接影响用户第一次接触产品的路径：

### Bug-1【P0】登录页/注册页的全部 JS 资源被登录门禁拦截，脚本全废

- **实测**：未登录访问 `/assets/site.css` 返回 `307 → /pages/login.html?next=/assets/site.css`；服务器日志显示登录页引用的 `theme-toggle.js`、`navigation-policy.js`、`time-utils.js` 全部被 307 成登录页 HTML。
- **根因**：`interview_forge/api/routers/static.py:24` —— `_PUBLIC_PREFIXES = ("/assets/fonts",)`，只豁免了字体。而 `_inject_html`（static.py:26-38）恰恰给**每个页面包括登录页**注入 `time-utils/navigation-policy/auth-widget/feedback-widget/theme-toggle` 五个脚本；未登录时它们全部拿回 HTML 当 JS 执行，控制台语法错误，登录/注册页的主题切换、导航策略、时间格式化全部失效。
- **连带问题**：登录成功后 `next=/assets/theme-toggle.js` 会把用户带到一个**裸 JS 文件页面**（浏览器直接显示源码）。
- **修复**：`_PUBLIC_PREFIXES` 加入 `/assets/`（静态资源不含用户数据，且本来就是公开前端的组成部分）；同时把 `next` 白名单限制为 `.html` 路径，避免登录后落到资源文件。

### Bug-2【P1】Origin 白名单写死 8765 端口，任何其他端口的本地访问无法登录

- **实测**：服务器跑在 `127.0.0.1:18999` 时，浏览器登录返回 403"跨站请求被拒绝"（`app.py:67-89` 的 `_DEFAULT_ALLOWED_ORIGINS` 只含 8765）；用 `INTERVIEW_FORGE_ALLOWED_ORIGINS` 环境变量加入 18999 后恢复（逃生通道有效，但错误页面上没有任何提示）。
- **影响**：本地开发换端口、`--port` 自定义部署、或经 SSH 隧道/不同端口反代时登录直接失败；错误文案"跨站请求被拒绝"让用户以为是攻击被拦截，无从自助。
- **修复**：回环地址信任规则放宽为 `http://localhost:*` / `http://127.0.0.1:*`（回环 + SameSite=Lax + 服务端会话下风险可控），或在 403 响应与启动日志中明确提示"如使用非默认端口，请设置 INTERVIEW_FORGE_ALLOWED_ORIGINS"。

### Bug-3【P1】内容页 404 是黑底裸 JSON

- **实测**：访问不存在的章节路径返回黑底白字 `{"error":"Not Found"}`，无品牌样式、无返回入口、无搜索建议。
- **修复**：HTML 请求（Accept: text/html）的 404 返回品牌 404 页（header + "回到中控台/全文搜索"入口），JSON 只留给 API 路径。

## 一、总体评价

这套前端的完成度和细节水平**远高于典型个人项目**：设计 token 化的暗色主题、题卡的状态色边框体系、章节页的完整学习状态条、题解页的代码联动可视化演示、同步弹层的焦点管理、Ctrl/⌘+K 搜索聚焦、reduced-motion 全站尊重——这些都有专业水准。

当前真正的短板集中在五件事（详见各章）：

1. **错误被渲染成"正常空态"**：断网时"今日待复习/薄弱清单"显示"今天没有到期的题目"，把故障伪装成"没事干"（仅 cockpit 有正确的模块级失败样板）。
2. **核心学习页（题解页）没有学习状态**：章节页有"已完成 N 轮 · 下次复习 · 完成本章一轮 · 导出"完整状态条，题解页却什么都没有——AC 徽标、下次复习、薄弱标记全部只存在于仪表盘的题卡上，学习现场无法查看也无法操作。
3. **首屏优先级向"数据与同步"倾斜**：仪表盘 8 张统计卡 + 8 个导航 chip + 进度条占满首屏，"今天该复习什么"被推到首屏边缘；唯一实心主按钮是"一键同步"而不是"开始学习"。
4. **导航心智模型有一致性缺口**：桌面端"面板→题解"新标签、题解间同页的大方向是对的（保住工作台状态），但存在四处破坏可预期性的问题——cockpit 六个大入口全部开新标签、同一语义的"今日待复习项"在 cockpit 同页打开而在 index 新标签打开、三处"返回"链接被误划入新标签区、主工作台没有任何回中控台的链接；移动端被动新标签的成本则被现有默认值放大。
5. **悬浮件互相打架**：AI 悬浮球（垂直居中贴右）实测压住趋势图标题、今日计划卡、书架卡片；右下角 auth-pill + 反馈球 + 聊天室在移动端直接盖住"开启复习提醒"按钮。

## 三、跳转逻辑设计（同标签页 vs 新标签页）——用户专项关注

> 本章基于对 `assets/navigation-policy.js`、`build_html_site.py` / `build_library.py` 构建注入逻辑、`static.py` 服务端注入的全量比对，以及逐页实测的链接矩阵。统计口径：构建产物中 59%-100% 的锚点带 `target="_blank"`（题解样本 1143 个锚点中 678 个；书架模块页 217/217 全部），运行时由 policy 脚本按下方规则分流。

### 3.1 现行机制（实测确认）

- `navigation-policy.js` 四条规则：**外链一律新标签**；`.dashboard-nav a`、`.breadcrumb a`、`.chapter-nav a`、`.problem-nav-btn` 等 chrome 导航**强制同页**（构建期写死的 `_blank` 被运行时剥掉）；**独立学习内容**（题卡→题解、模块卡→课程、搜索结果、正文交叉引用、可视化中心）走**用户偏好，默认新标签**；登录/登出/401 一律同页 `location.replace`。
- 偏好存 localStorage（`learningContentOpenMode`），`storage` 事件跨标签同步；偏好开关藏在"头像 → 资料面板"里，可视化页甚至不注入 auth-widget，想改都没有入口。
- `file://` 离线打开时 policy 脚本不在构建模板里（`render_markdown` 模板与 `build_library.document()` 都不引用它）→ **离线场景下所有内链退化为构建期写死的 `_blank`，顶栏/面包屑/上一题下一题全部新开标签**（P1，需在两处模板补 script 引用；服务端注入有幂等检查，天然兼容）。

### 3.2 判定表：哪些对、哪些要改

| 跳转类型 | 现状 | 判定 | 理由 |
|---|---|---|---|
| 面板/中控台 → 题解、章节（桌面） | 新标签 | **保持** | 面板是常驻工作台：新标签保住滚动位置、筛选状态与**进行中的模拟计时器**（模拟中点开题解恰好被新标签保护）。"题卡列表→详情新开"是此类产品的通行做法 |
| 题解 ← 上一题/下一题、同专题列表、目录 | 同页 | **保持** | 连续学习流必须同页，否则按 100 题爆炸 |
| 章节间 上一章/下一章/目录、面包屑 | 同页 | **保持** | 顺序阅读动线；且是全站唯一被 check_hot100 断言锁住的返回动线 |
| 题解 → 可视化演示 | 页内 iframe + 中心页新标签 | **保持** | 内嵌是最佳解 |
| → 力扣原题、CookieMate 等外链 | 强制新标签 | **保持** | 外站必须新标签 |
| 搜索结果 → 章节 | 新标签 | **保持** | 保住搜索状态的前提（但需修 3.3-⑤ 的 q 丢失） |
| 登录/注册/登出/401（全站 10 处） | 同页 replace | **保持** | 实现一致，无缺口 |
| **cockpit 六个大入口（书架/面板/搜索/记录/力扣/管理）** | 新标签 | **改同页** | 中控台是登录后首页，6 连发新标签是标签爆炸的最大单一来源；且与它自己动态渲染的待复习条目（同页）自相矛盾 |
| **"返回"类链接**（力扣连接页 footer 返回、可视化中心"返回总目录"、guide 顶部入口、面板"书架待复习"横幅） | 新标签 | **改同页** | 返回是"移动"不是"另开参考资料"；与 history/ai-assistant 顶部返回的同页行为不一致 |
| **同一语义的待复习项**：cockpit 动态条目（JS 创建无 target→同页）vs index 动态条目（模板写死 `_blank`→新标签） | 两个工作台行为相反 | **统一声明**（用 `data-navigation-policy`；注意 index 侧不能只删 target——构建期 `mark_cross_page_links` 会重新规范化为 `_blank`） | 可预期性 |
| **移动端全部"独立内容"默认新标签** | 默认 new-tab（全设备） | **移动/触屏改默认 same-tab**：`DEFAULT = matchMedia('(max-width:760px),(pointer:coarse)').matches ? 'same-tab' : 'new-tab'` | 触屏没有中键/Ctrl，用户对新标签无选择权；标签堆在抽屉里难回收。外链与显式 `new-tab` 声明不受影响；需同步 test_navigation_policy.py 默认值断言 |
| 偏好开关 | 藏在头像面板；只存 localStorage | **升为一级入口**（阅读页 site-nav 加"打开方式"按钮）+ 随 `/api/profile` 跨设备同步（`forge-lang` 语言偏好已有双向同步先例，导航偏好心智权重不比它低） | 可发现性 |

### 3.3 返回动线与状态保持（专项实测）

1. **index.html → cockpit 零链接（P1）**：`grep cockpit index.html` 0 命中——cockpit 是 `/` 307 的登录后首页，但从主工作台和所有阅读页顶栏都回不去中控台，只能靠浏览器回退。修复：`build_html_site.py:2147-2153`（阅读页 site-nav）与 `:2331`（面板 dashboard-nav）各补"中控台"入口，全量重建；check_hot100 对 site-nav 集合无断言，安全。
2. **模拟中后退丢局（P2）**：`mockState` 纯内存（index.html:719），页面 no-store 禁用 bfcache → 模拟中哪怕只是点开题解看一眼再返回，计时器和队列即消失且无提示。建议 mock 状态写 sessionStorage（deadline/队列/游标）+ beforeunload 提示。
3. **搜索词不写回 URL（P2）**：`search.html` 只在加载时读 `?q=`，输入不 replaceState；HTML no-store 禁 bfcache → 用户切到 same-tab 后"搜索→章节→返回"会丢关键词和结果。修复：input 时 `history.replaceState('?q=…')`（build_library.py 搜索脚本一处，重建书架）。
4. **服务端登录 307 的 next 丢 query（P3）**：`static.py:60-62` 只取 path，`/library/search.html?q=x` 被登录墙截断后丢参（客户端 307 的 next 保留了 search+hash，两处行为不一致）。
5. **正文 page-kicker 面包屑是纯文本**（build_html_site.py:1851-1855 注释明言"不设链接"）——题解页实际靠品牌链接当返回。P3：至少把末级"03-题解 / 01-哈希表"做成指向专题页的链接。
6. **章节页没有"同模块其他章节"快捷列表**：题解页有左栏 sol-rail，章节页只有 上一章/下一章/目录，跳第 5 章必须经目录页中转。P3：仿 sol-rail 加章节下拉。
7. **文案歧义（P3）**：题解页底部"🏠 回到 Hot 100 目录"实际去的是"学习面板"（build_hot100.py:967），与顶部品牌"Hot 100 深度学习库"两个叫法指同一目标，统一为"学习面板"。
8. 正面确认：全站无 `history.back()` 依赖，返回全部是结构化链接（对 PWA/离线友好）；`window.open('https://leetcode.cn')` 一处漏了 noopener（leetcode-connect.html:44，P3）。

### 3.4 策略脚本健壮性（navigation-policy.js）

- **MutationObserver 只观察 childList**（:76-84），而 `applyAnchor` 对插入时还没有 href 的锚点直接 return 且永不重试（:46）——当前所有动态创建都在 append 前赋 href，是隐性契约；建议补 attributes 观察或 rAF 重扫。
- `.top a` 选择器按容器位置匹配过宽（:10-13），未来在 `.top` 里放内容链接会被悄悄吸成同页；建议 `.top > a` 或专用 class。
- `?v=1` 版本号散落 4 处（static.py:29、旧 facade ×2、tools shim），改 policy 容易漏 bump。
- `mark_cross_page_links` 在 build_html_site.py 与 build_library.py 是**两份独立复制的实现**，应合并共享模块。
- check_hot100 锁住了章节页三件套和可视化导航，但**没有任何断言保护 site-nav/dashboard-nav 的入口集合**——建议补"index/题解模板必须含中控台入口"断言防回归。

### 3.5 结论（本章节行动顺序）

1. 移动端默认 same-tab（一行 + 测试断言，不动构建）；
2. index 与阅读页补"中控台"入口（两处字符串 + 重建）；
3. policy 脚本进构建模板，修复离线全 `_blank`；
4. 三处"返回"链接与 cockpit 六大入口改同页；
5. 搜索 q 写回 URL + 模拟状态 sessionStorage；
6. 偏好开关前置 + 随账号同步；
7. 其余 P3（面包屑可点、文案统一、noopener、双份实现合并）。
