## 3. 数据结构

所有表都在**每个用户自己的学习库** `data/users/<username>/hot100-study.db`，由 `interview_forge/db/schema.py` 统一建表（`CREATE TABLE IF NOT EXISTS`，旧库下次连接自动补表）。

### 3.1 `daily_latest_activity` —— 每天最晚一次打开

**设计意图**：不逐次落库，每天只保留除最晚那一条，一年最多 365 行。

| 列 | 说明 |
|---|---|
| `activity_date` | 主键，`YYYY-MM-DD` |
| `latest_at` | 该日最晚一次打开的时间（ISO） |
| `target_type` | `problem` / `content` |
| `target_id` | 题号 或 章节 id |
| `target_title` | 冗余存标题，报告不必 join |
| `module_id` | 章节所属模块（题目为空） |

**写入点**：`services/study.py` 的 `record_view()` / `record_content_view()` 调 `_touch_daily_latest()`，只在时间更晚时覆盖。

**查询**：`latest_activity_summary(year, db_paths)` —— 跨用户库汇总，返回天数、全年最晚时刻、小时分布、最晚打开的内容 Top10。

> ⚠️ 「最晚时刻」取的是 `HH:MM:SS` 的最大值，不是日期最新的那条。

### 3.2 `mock_exam_records` —— 模拟考试记录

| 列 | 说明 |
|---|---|
| `exam_at` / `exam_date` | 出题时间 |
| `problem_count` | 本次抽了几道 |
| `scope` / `scope_label` | 出题范围（all/today/recent/stale…） |
| `repeated_count` | 与最近几轮重复的题数 |
| `category` / `difficulty` | 筛选条件 |
| `problem_ids` | JSON 数组，本次抽中的题号 |
| `used_seconds` / `finished_at` | **预留**：前端交卷时回填（当前未接） |

**写入点**：`services/study.py` 的 `mock_exam()` 每次出题插一条。

### 3.3 `study_duration` —— 学习时长

| 列 | 说明 |
|---|---|
| `study_date` + `target_type` + `target_id` | 唯一索引，按「日期+目标」聚合 |
| `seconds` | 累加秒数 |
| `module_id` / `updated_at` | — |

**写入点**：
- 前端 `assets/engagement-tracker.js` 每 30 秒上报一次（页面隐藏/卸载补最后一次）
- 后端 `record_study_duration()`：单次上限 3600 秒；非正数忽略；`ON CONFLICT` 累加

### 3.4 `search_events` —— 搜索关键词

| 列 | 说明 |
|---|---|
| `keyword` | 截断 80 字，空值忽略 |
| `searched_at` / `search_date` | — |
| `result_count` | 结果数（当前前端未传，可空） |
| `source` | 搜索入口（shelfSearch / searchInput / global） |

**写入点**：前端监听 `#shelfSearch` / `#searchInput` / `#search`，防抖 1.5 秒 + Enter + 失焦上报。

### 3.5 `daily_summary` —— 每日聚合（缓存表）

按天把浏览/完成/题目/章节/提交/复习/时长聚合成一行。

**写入点**：`refresh_daily_summary(date)` 幂等刷新，**目前没有定时任务调用它**。
> 报告接口 `report_summary()` 是**实时聚合原表**，不依赖这张表。这张表留给将来做趋势图/定时报表用。上线前若要加定时刷新，用 cron 或应用内调度每天 00:10 跑一次即可。

## 4. API 端点

生产跑 **FastAPI**（`uvicorn interview_forge.api.app:app`），端点定义在 `interview_forge/api/routers/study.py`。
> ⚠️ `tools/study_server.py`（stdlib）里也有一份同名路由，仅供兼容；**新接口只在 FastAPI 侧注册**，改的时候两边都要看，否则会出现「本地正常、线上 404」。

| 方法 | 路径 | 说明 | 认证 |
|---|---|---|---|
| GET | `/api/report/annual?year=2026` | 个人年度报告完整数据 | 需登录 |
| GET | `/api/report/summary?year=2026` | 全站汇总（跨所有用户库） | 需登录 |
| POST | `/api/study/duration` | 学习时长心跳 | 需登录 |
| POST | `/api/search/events` | 搜索关键词上报 | 需登录 |

**个人 vs 全站**：`/annual` 只统计当前用户库；`/summary` 扫 `data/users/*/hot100-study.db` 全部汇总。体育馆数据来自独立的 `data/gym.db`（`gym_jobs` 表）。

## 5. 前端

### 5.1 页面与样式

| 文件 | 作用 |
|---|---|
| `pages/annual-report.html` | 报告页面（12 页，整屏翻页） |
| `assets/annual-report.css` | 页面样式（含组件与窄屏） |
| `assets/engagement-tracker.js` | 学习时长心跳 + 搜索上报 |

### 5.2 页面结构（12 页）

```
封面        2026 + 竖排「年度学习卷宗」+ 一句话
壹 总览     学习天数 / 累计时长 / 题目数 / 章节数
贰 出勤     365 格热力图（GitHub 风格：每列一周）+ 最长连续
叁 方向     模块投入条形图（逐条生长）
肆 作息     24 小时柱状图（平方根缩放，峰值琥珀色）
伍 战绩     AC 通过率环形图 + 提交/通过/最快/模考 + 语言分布
陆 记忆     复习次数/复习卡/收藏 + 记忆强度条
柒 你这个人 人格标签（夜猫子、专注型…）
捌 第一次   竖向时间轴（首次 AC/学习/收藏/复习/预约）
玖 最晚     超大时间 + 当天看的内容
拾 体育馆   预约次数 + 最常时段/场馆/成功率
结尾        明年目标 + 打印/存 PDF
```

**无数据的页会自动省略**（例如没有体育馆记录就不出现「拾」）。

### 5.3 关键实现细节（改之前务必读）

1. **整屏翻页**用原生 `scroll-snap-type: y mandatory` + `scroll-snap-stop: always`，不是 JS 模拟。
2. **动效触发**：`IntersectionObserver`，但**延迟 480ms 后要确认该页中心仍在视口内**才播 —— 因为平滑翻页会「经过」中间页，不校验的话会在途中就播完。
3. **数字初始渲染为 0**，进入视口后从 0 滚到目标值。**不要**在渲染时先输出最终值，否则用户会看到「最终值→0→再涨」的闪烁。
4. **兜底**：3 秒后只补「当前视口内且未播过」的页，绝不能无条件把所有页设成最终值。
5. **`.bar-fill` 必须 `display: block`**：它是 `<span>`，inline 元素会忽略 `width`，条形会全部撑满看不出差异。
6. **热力图宽屏下 `margin-inline: -104px`** 突破正文宽度铺满；格子 13px、间距 2px 刚好放下 53 列。改动任一参数需重新核算（`scrollWidth` 应等于 `clientWidth`）。

### 5.4 埋点脚本注入位置

`assets/engagement-tracker.js` 通过构建脚本注入：

| 页面 | 注入位置 |
|---|---|
| 书架章节页 | `scripts/build/build_library.py`（与术语脚本一起，`chapter_scripts`） |
| 书架首页 | `scripts/build/build_library.py`（`index_body` 末尾，搜索用） |
| 题解页 | `scripts/build/build_html_site.py`（`_te`） |

## 8. 维护手册

### 8.1 本地启动（与生产一致）

```bash
pip install -r requirements-server.txt
python -m uvicorn interview_forge.api.app:app --host 127.0.0.1 --port 8765
```

> 以前用 `python tools/study_server.py`（stdlib），**新接口不在那里面**，会 404。

### 8.2 常见改动

| 想做什么 | 改哪里 |
|---|---|
| 改某页文案 / 加一页 | `pages/annual-report.html` 的 `render*()` 函数 |
| 改视觉样式 | `assets/annual-report.css` |
| 加一个新指标 | 后端 `services/annual_report.py` 的 `build_annual_report()` + 前端对应 render |
| 调人格标签规则 | `services/annual_report.py` 的 `_persona()` |
| 加一张新数据表 | `interview_forge/db/schema.py`（`CREATE TABLE IF NOT EXISTS`） |
| 改埋点上报频率 | `assets/engagement-tracker.js` 的 `HEARTBEAT_MS` |

### 8.3 部署

```bash
# 本地
git push origin main
# 生产
ssh hstgr-cloud "cd /opt/interview-forge && git pull --ff-only origin main && systemctl restart interview-forge"
```

### 8.4 排查「线上 404」

1. 先确认路由在 `interview_forge/api/routers/study.py` 里（FastAPI 侧）
2. 再看 `tools/study_server.py` 是否有同名路由（stdlib 兼容层）
3. 确认服务真的重启了：`systemctl status interview-forge`、`journalctl -u interview-forge -n 50`

### 8.5 排查「动效不出现」

按顺序查：
1. `prefers-reduced-motion` 是否被系统开启（开了就跳过所有动效，属预期）
2. 控制台是否有 JS 错误
3. 该页元素是否真的进入过视口中心（`IntersectionObserver` 的 480ms 检查）
4. 数字是否为 0 —— 检查 `figure-value` 的 `data-value` 是否有值

## 9. 已知限制

1. **`daily_summary` 没有定时刷新** —— 报告不用它，将来做趋势图时需要加定时任务。
2. **`mock_exam_records.used_seconds` 未回填** —— 前端交卷接口还没接，目前只记「出题」不记「用时/成绩」。
3. **全站汇总较慢** —— `/api/report/summary` 每次扫所有用户库，用户多时会变慢；届时可改用 `daily_summary` 缓存。
4. **学习时长按心跳累加** —— 用户挂着页面不操作也会计时（只在前台可见时计），极端情况下偏高；已限制单次上报 ≤3600 秒。
5. **「最晚一次」依赖新表** —— 表是 2026-10-31 才建，历史数据无法回溯，只能从现在开始积累。
6. **体育馆数据来自独立库** —— `data/gym.db` 与用户学习库分离，报告里读的是同一个 `gym_jobs` 表（所有用户共享，目前只有群主在用）。
