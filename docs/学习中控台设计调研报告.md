# 学习中控台（Cockpit）设计调研报告

> 调研时间：2026-09-06。目标：把"打开就是书架全量"的主页，升级为一张**学习中控台/学习桌面**——时钟 + 必要入口 + 平台简介，书架退为入口之一。
> 本轮零改动；落地路径与历次一致：新页面文件 + 生成器注入 + 既有 API，零新后端。

---

## 一、现状问题

当前登录后落地页（书架 library/index.html 与 Hot100 面板）都是**工具全量页**：37 个模块卡、100 张题卡、统计、筛选器一屏全铺。作为"每天打开的学习起点"，缺三样东西：

1. **一个安静的起点**——没有时间/问候/当下状态的"呼吸位"；
2. **入口优先级**——最常用的 6~8 个目的地（书架/题解/搜索/聊天/记录/力扣）淹没在导航链接里；
3. **今日焦点**——今天该干什么（待复习/计划）在面板里，但面板同时背着题目工作区、模拟赛等重功能。

## 二、中控台是什么：参考项目调研

### 2.1 自托管仪表盘三巨头

| 项目 | Stars | 布局范式 | 可借鉴 |
|---|---|---|---|
| **Glance** | 36.9k | 信息流分区：每卡一个"信息源" | 分区卡片化；每卡自带标题栏 + "查看全部"链接 |
| **Dashy** | 26.4k | 多页 + 分区 + 模态编辑；支持 bento/横向/列式布局 | 入口卡（图标 + 名称 + 描述）；页面级分区导航 |
| **Homepage (gethomepage)** | —（161 个服务小部件文档） | 服务卡 + 信息小部件两轨；小部件 = 纯数据展示卡（统计/时钟/搜索） | "小部件 = 数据 + 极简渲染"的架构；搜索框置于页首居中 |

### 2.2 新标签页流派（Momentum 系）

Chrome 新标签页扩展的经典配方：**大时钟 + 时段问候 + 一句"今日焦点" + 极简待办 + 全屏背景图**。设计语言：时钟是唯一主角（超大轻字重），其余全部退居其下。对本站启示：中控台不要做成"第二个仪表盘"，而是"**起点页**"——一眼看清现在几点/今天干什么/去哪里。

### 2.3 Bento Grid（便当盒网格）

bento.me / Apple 小组件带火的布局：**不等宽卡片网格**，卡片大小按信息重要性分配（2×2、2×1、1×1），圆角统一、间距统一。Tailwind 社区与个人主页已把 bento grid 做成 2023~2025 的主流个人页范式。关键规则：**一张卡只承载一个小组件**；重要组件占大格；每张卡视觉重量接近，靠尺寸区分层级。

### 2.4 学习类产品的首页共性（Anki/超记忆/多邻国）

- Anki：打开即"今日待复习 N 张"+ 一个大按钮——**把今天的行动放最前面**；
- 多邻国：连续学习天数（streak）做成火焰图标 + 大数字——**streak 是留存钩子**；
- 共性：**今日概览永远第一屏，库/课程列表永远在第二层**。

## 三、小组件清单（本站可用，全部复用现有 API）

| 小组件 | 内容 | 数据源 | 优先级 |
|---|---|---|---|
| **时钟 + 问候** | 大字号 HH:MM、日期星期、时段问候（清晨好/上午好/下午好/晚上好） | 纯前端 Date，零请求 | P0 |
| **今日概览** | 今日看题 / 今日完成 / 已刷题目 / 完整轮次（四格） | /api/dashboard（已有） | P0 |
| **今日待复习** | 前 3 条 + "查看全部 N 项 →" | /api/daily（已有） | P0 |
| **今日计划** | 前 3 条 + "换一组" | /api/plan（已有） | P0 |
| **快速入口** | 书架 / Hot 100 题解 / 全文搜索 / 聊天室 / 学习记录 / 力扣连接（管理员加管理后台） | 纯静态链接 | P0 |
| **学习进度** | "至少完成一轮 97/100"进度条 + 完整轮次徽标 | /api/dashboard（已有） | P1 |
| **平台简介** | 一句定位 + "学习数据按账号隔离、复习自动排期"说明 | 静态 | P1 |
| **每日一题** | 从未完成题中随机一题（点直接进题解） | /api/pick（已有） | P2 |
| **专注计时器** | 25/50 分钟番茄钟，结束提示 | 纯前端 | P2 |
| **连续学习** | streak 火焰 + 天数（dashboard 已有 active_days） | /api/dashboard | P2 |

**数据可行性结论：全部小组件零新后端**——时钟是前端 Date，其余 8 个的数据全部由现有接口提供。

## 四、布局调研与推荐方案

### 4.1 三种主流布局模式

| 模式 | 形态 | 适合 | 不适合 |
|---|---|---|---|
| **Bento Grid**（推荐） | 不等宽卡片网格，2~3 列，尺寸分层 | 信息组件 6~10 个、需要"一眼全览" | 组件 >15 个（会挤） |
| 信息流式（Glance） | 单列/双列长信息流，滚动浏览 | 组件多、内容重 | 起点页要"一眼扫完" |
| 极简式（Momentum） | 全屏背景 + 时钟 + 一行待办 | 极简主义 | 我们有较多功能入口 |

### 4.2 推荐布局（Bento Grid，桌面 ≥1100px）

```text
┌────────────────────────────────────────────────────────────┐
│                  14:32          9月6日 星期六               │
│                  下午好，群主大大                            │
│          识别模式 · 独立实现 · 间隔重复 · 学习全程可追踪      │
├─────────────┬──────────────────────┬───────────────────────┤
│  今日概览    │   今日待复习（3 条）   │   今日计划（3 条）     │
│  4 格统计    │   + 查看全部 N 项 →   │   + 换一组            │
│  + 进度条    │                      │                       │
│  97/100 ▓▓▓ │                      │                       │
├─────────────┴──────────────────────┴───────────────────────┤
│   快速入口：📚书架  🧩题解  🔍搜索  💬聊天  📈记录  🔗力扣    │
├────────────────────────────────────────────────────────────┤
│   平台简介 · 数据说明 · （管理员可见：管理后台）              │
└────────────────────────────────────────────────────────────┘
```

- **时钟卡（全宽，页面主角）**：字号 `clamp(56px, 9vw, 110px)`、字重 200~300、`tabular-nums`；冒号每秒呼吸（opacity 0.4↔1）；暗色下时钟带品牌色微光；
- **Bento 三列**：概览（1×1）+ 待复习（1×1.2 略高）+ 计划（1×1.2）；待复习/计划卡直接复用面板的渲染片段，上限 3 条 + "查看全部"跳面板；
- **快速入口横条**：6 个大图标按钮（56px 图标 + 名称），管理员多一个管理后台入口；
- **移动端**：时钟缩至 56px，Bento 退化为单列：时钟 → 概览 → 待复习 → 计划 → 入口 → 简介。

### 4.3 路由与集成方案

| 方案 | 做法 | 评价 |
|---|---|---|
| **a. 独立 cockpit.html（推荐）** | 新页 + 登录跳转与 login.html?next 默认值指向它；书架/面板原样保留，中控台头部加"面板/书架"快捷跳转 | 影响面最小；书架仍是"全量工具页" |
| b. 改造 index.html 首屏 | 面板上方插入 cockpit 区、题目工作区默认折叠 | 页面更重；面板职责混杂 |

推荐 a。登录链路改动点：login.html 的 next 默认值、/api/me 后的跳转、auth-widget 退出后跳转——共 3 处字符串。

### 4.4 设计细节（贴合现有令牌）

- 时钟与问候置于一张全宽 Hero 卡（复用书架 hero 渐变令牌），暗色下时钟文字带品牌色 text-shadow 微光；
- Bento 卡片复用 `.review-section` 风格（边框 + 圆角 + 阴影），统一圆角 var(--radius-4)；
- 快速入口按钮：56px 图标底（color-mix 分类色）+ 名称，hover 边框转品牌色（复用阶段 2 辉光）；
- 所有卡片 hover 微浮（复用阶段 2 动效）；
- 时钟每秒更新用 requestAnimationFrame 对齐秒边界（避免 setInterval 漂移）。

## 五、Hero 背景与文案调研（补充）

### 5.1 背景方案调研（全部 CSS/SVG 内联生成，零外部资源，离线可用）

| 方案 | 效果 | 参考项目 | 评价 |
|---|---|---|---|
| **极光渐变 Aurora** | 2~3 团大型柔边径向光斑（品牌紫/青/绿，6~14% 不透明度）铺在页面四角，可选 60~90s 缓慢漂移动画 | Linear、Vercel、Raycast 首页 | ⭐ 主推：与现有 body 渐变同源，加深即可成立 |
| **点阵网格 Dot grid** | 1px 圆点、24px 间距，向边缘淡出（mask），暗色用白点 3% | Tailwind UI、Vercel | ⭐ 副推：叠加在极光之上，增加"工程感/学习感" |
| **噪点纹理 Noise** | SVG feTurbulence 内联 data-URI，3~4% 不透明度 | Stripe、Linear | ⭐ 叠加层：消除渐变色带、增加质感 |
| 线格 Blueprint | 1px 线网格 | 绘图工具 | 过于"工程图纸"，不选 |
| 图片背景 | 摄影/抽象图 | Momentum | 需要图库资产、离线体积大，不选 |
| Canvas 粒子 | 动态粒子/星空 | 部分新标签页 | 需 JS 常驻渲染，费电，不选 |

**推荐配方（三层叠加，照抄即用）**：

```css
.cockpit-hero{
  /* 层 1+2：极光双光斑（亮色参数；暗色把 brand 调亮至 16%、加青色光斑） */
  background:
    radial-gradient(600px 300px at 15% 0%, color-mix(in srgb, var(--brand) 12%, transparent), transparent),
    radial-gradient(500px 260px at 85% 20%, color-mix(in srgb, #14b8a6 9%, transparent), transparent),
    var(--panel);
  /* 层 3：点阵网格 */
  background-image:
    radial-gradient(circle, color-mix(in srgb, var(--muted) 18%, transparent) 1px, transparent 1px);
  background-size: 100% 100%, 100% 100%, 24px 24px;
}
/* 暗色额外：时钟品牌微光 */
html[data-theme="dark"] .cockpit-clock{ text-shadow: 0 0 40px color-mix(in srgb, var(--brand) 35%, transparent); }
```

### 5.2 文案调研：从"单机工具"到"跟踪学习平台"

旧话术「数据仅存本机 · 学习轨迹可回看」是单机时代的定位——当前模式已是**多用户、服务端部署、全程追踪**的训练平台，文案应同步转轨。

**文案三原则**：① 说清"这是什么+给谁"（训练台，不是网盘）；② 强调"被记录/被排期"的平台价值（这正是当前模式特征）；③ 短、动词开头、不喊口号。

**主标语候选（按推荐序）**：

| 候选 | 语气 | 说明 |
|---|---|---|
| `把刷题变成可追踪的训练` | 训练台 | ⭐ 推荐：一句话点明平台本质（追踪），且暗示用户该持续来 |
| `识别模式 · 独立实现 · 间隔重复 · 全程可追踪` | 方法论 | 四词连排呼应站内"是什么/为什么/怎么用"学习法 |
| `你的算法面试训练台` | 定位 | 极简版，适合时钟卡空间紧张时 |

**副标语候选（配合主标语）**：

- `每一次浏览与 AC 都会被记录，复习自动排期——你只管练`
- `学 · 练 · 复 · 测 四步闭环，复习日程自动排期`
- `覆盖 17 个专题 37 门课程；今天该复习什么，已经替你排好`

**问候语规范**：时段问候 + 昵称（`清晨好，群主大大` / `下午好` / `晚上好`，5~9 点清晨、9~12 上午、12~14 中午、14~18 下午、18~23 晚上、23~5 夜深了）；管理员可在问候后附"管理后台"快捷入口。

**页脚简介候选**：`InterviewForge · 校招算法训练台 · 学习数据按账号隔离存储 · 复习日程自动排期`

**禁用表述清单**（随模式升级同步退役）：`数据仅存本机`、`离线使用`（作为主卖点时）、`本地阅读`——这些是单机时代定位；如需保留，仅出现在关于/帮助页的历史说明里。
