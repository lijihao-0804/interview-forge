## 二、本轮新发现（修复后的残留边界，均为小项）

1. **错误态重试按钮不一致（P3）**：断网实测中，"今日待复习"有重试按钮，而"今日计划/薄弱清单/题网格"三处只有"请稍后重试"文字——同一屏内交互不一致。建议统一补 `data-retry`。
2. **cockpit→面板的跳转仍是新标签（P3）**：六大 `.entry` 已同页，但"查看全部 33 项 →""在面板中查看"两条链接仍 `target="_blank"`——同一卡片内两种打开方式并存。建议补 `data-navigation-policy="same-tab"`（一行）。
3. **AI 球在窄屏仍轻微压内容（P3）**：390px 下 AI 球落在"至少完成一轮 46/100"进度行右缘、🐞 球压"今日待复习"卡头一角。比修复前（盖住按钮）好得多，但离"零遮挡"还差一档；可将移动端 AI 球并入底部 tab 或收进"更多"。
4. **`#review` 锚点在首次访问有低概率不滚动（P3）**：正常加载下锚点生效（连续采样 scrollY 稳定 362）；但首次访问（service-worker 激活窗口）观察到一次未滚动。一行兜底：`refresh()` 完成后若 `location.hash` 存在则补一次 `scrollIntoView`。
5. **冒烟环境的自动化怪癖（非产品问题，备案）**：登录按钮的 programmatic click（role/CSS 定位器）在 IAB 里始终无法派发事件（事件钩子全零、坐标点击正常），人工点击正常。若未来写 E2E，用坐标或 `requestSubmit()` 绕过。

## 三、产品视角评审：与一线产品对齐还差什么

评分口径：以"这个维度做到一线产品水准"为 10 分。当前总分印象：**7.5/10**——工程地基和内容质量已经超过绝大多数同类个人项目，差距集中在"产品闭环"与"交互质感"的最后 20%。

### 3.1 用户旅程完整性 —— 7/10（最大的产品缺口：没有"测"）

学-练-复习闭环的现状：**学**（题解/章节，✦✦✦，内容质量是护城河）、**练**（限时模拟，✦✦，自报式计分）、**记**（统计/热力图/历史，✦✦✦）、**评**（AI 学情分析，✦✦）、**复习调度**（✦✦，固定间隔）。

**缺失的一环是"测"**：整个产品里没有任何"先遮住答案自测"的交互——题解页从上到下答案全部可见，复习时"看着都会"的风险没有任何机制防护。一线产品（Anki 的卡片正面、Khan Academy 的练习、LeetCode 的沉浸模式）都把"先提取、后确认"当核心交互。

**建议（性价比最高的一件事）**：题解页加"自测模式"开关——遮住推导与代码，仅显示题面+核心不变量，逐段揭示；复习到期时默认进入遮罩态。数据层零改动，纯前端，且直接强化复习闭环（可记录"自测通过/失败"作为调度信号，为 FSRS 铺路）。

### 3.2 信息架构 —— 8/10（双工作台成立，还差"位置感"）

cockpit（今天做什么）与 index（干活的工作台）的分工经这轮入口补全后已经成立。剩余差距：

1. **导航无"当前位置"高亮**：中控台入口补上后，各页导航集合基本一致了，但没有任何页面的导航标记当前页（题解页的误高亮修掉了，正常高亮却从未存在）。一线产品的顶部导航必然有 active 态——这是用户"我在哪"的锚点。构建脚本已知每个产物的类型，注入 `aria-current="page"` 是纯模板改动。
2. **面包屑仍是半成品**：章节页有真面包屑，题解页还是裸路径 `books / hot100 / 03-题解 / ...`（上轮 P1-3，未列入上批修复）。语义化面包屑（`题解 › 哈希表`）配合 active 态一起做。
3. **统计卡 8 张的首屏问题原样保留**（上轮 D1 暂缓项）：桌面首屏仍被数据卡占据、"已解决 46/46"仍难解读。这是与一线产品差距最直观的一处——Duolingo 首屏第一行就是"今天的课"。建议按上轮方案执行（8→5 + 本周Δ + 预计完成日期）。

### 3.3 交互质感 —— 7.5/10（错误态已达标，缺"乐观更新"与统一组件）

这轮修复后错误态/焦点管理/防误触都到了合格线。质感上还差的三件事：

1. **乐观更新缺失**：标记薄弱、保存目标、完成章节都要等请求返回才更新 UI（弱网下明显迟滞）。一线产品一律乐观更新 + 失败回滚 + toast。项目里所有写操作都是"点→等→变"，配合 no-store 的全禁缓存，体感偏"钝"。
2. **骨架屏/错误态/Toast 是三套手写实现**：cockpit 的失败样板、面板的新错误态、auth-widget 的 toast 各写一份。建议抽 `assets/ui.js`（showToast / renderError / skeleton 三个函数），这是后续所有页面迭代的地基。
3. **快捷键只有 Ctrl/⌘+K**：学习站的高频动作（上一题/下一题、标记、返回面板）没有键盘路径。题解页加 `←/→` 切换题目、`m` 标记，成本低感知强（对照 GitHub 的 j/k、Linear 的全套快捷键）。

### 3.4 感知性能 —— 7.5/10（结构性问题：全站 no-store）

- 静态 HTML/CSS/JS 全部 `no-store`（含 771 个阅读页），每次导航全量重新下载。一线产品的静态资源用协商缓存（ETag/Last-Modified）+ HTML no-cache，切页接近瞬时。nginx 一行配置的量级，是**全局体感提升最大的一件事**。
- 100 张题卡一次渲染（约 9000px 文档），当前规模可接受，但加自测/备注后卡会变重，届时再做筛选默认收起或虚拟化。
- 字体 swap、reduced-motion、图片懒加载已到位（正面）。

### 3.5 视觉与设计系统 —— 8/10（token 化程度高，欠收敛与组件化）

- 暗色主题、状态色边框、复杂度徽标、代码高亮的视觉质量在线；reduced-motion、焦点陷阱、skip-link 这些"看不见的功课"都做了（正面）。
- 剩余收敛项（上轮已列）：品牌色双值（#5755d4/#5654d4）、"待复习"三色语义、`.muted` 无定义、死 CSS。
- **下一步是组件抽取而非新样式**：题卡、状态条、错误态、空态、Toast 在 3 个以上页面重复实现，抽成共享模板/函数后，视觉一致性会自动收敛，这也是"题解页学习状态条"（上轮 P1-1，仍待做）能低成本落地的前提。

### 3.6 与一线产品的结构性差距（对齐路线，非本批修复范围）

| 差距 | 一线参照 | 对应已有规划 |
|---|---|---|
| 调度固定查表，不随人变 | Anki/RemNote 的 FSRS（99.6% 用户优于 SM-2） | 功能规划报告第 1 项 |
| 无激励里程碑（streak 有了，无徽章/周报循环） | Duolingo 的 streak 冻结/里程碑 | 周报自动化（功能规划 14） |
| 内容关联靠用户自己找 | NeetCode 的 roadmap 前置关系 | Roadmap 视图（功能规划 9） |
| 无新用户 onboarding（注册后落在空 cockpit，无引导） | Khan Academy 的 3 步引导 | 可并入"首次登录引导流" |

## 四、下一阶段前端路线（按性价比排序）

1. **自测遮罩模式**——补齐旅程里缺的"测"，复习闭环从"看"升级为"提取"；顺带产出调度信号。
2. **全局体感二件套**：静态资源协商缓存（nginx 一行）+ 写操作乐观更新（配合已修好的 toast 错误回滚）。
3. **组件抽取 `assets/ui.js`**：showToast/错误态/骨架三件套统一，然后补齐三处缺重试按钮的错误态。
4. **位置感三件套**：导航 `aria-current` 高亮、题解语义面包屑、（可选）阅读页迷你 sticky 条。
5. **统计卡 8→5 + 本周Δ + 预计完成日期**（上轮 D1，唯一"结构改造"项，需联动 check_hot100 断言）。
6. **题解页学习状态条**（上轮 P1-1）——放在组件抽取之后做，成本减半。
7. 键盘快捷键（题解页 ←/→/m）、AI 球移动端归位、锚点 SW 激活窗口兜底（三个一行级小项打包）。

**一句话总结**：修完这一批后，这个前端的"地基、内容、错误处理、导航一致性"都已经站到了同类产品的前列；下一步拉开差距的不是再修问题，而是三件"产品级"的事——**让复习从"看"变成"测"（自测遮罩）、让体感从"准"变成"快"（缓存+乐观更新）、让数据从"多"变成"有用"（统计卡聚焦+调度个性化）**。
