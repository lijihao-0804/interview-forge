# 性能优化实施核验（2026-10-02，第一阶段）

本文仅本地保存，不作为已实现多 worker 或容量提升的证明。

## 已读材料与事实校正

对照生产端性能测评报告、全量收尾清单和进度审查报告检查当前代码。

- `sqlite3.connect(timeout=10)` 已设置 SQLite busy handler，默认等待 10 秒。新增显式 PRAGMA 并不意味着从无等待升级为有等待；改为 5000ms 会缩短原有等待。
- systemd 生产实际通过 `python -m uvicorn interview_forge.api.app:app` 启动，不走 legacy CLI 的 `uvicorn.run`。只改后者不能让现有生产服务变成多 worker。
- `services/leetcode.py` 的任务表与用户锁均为进程内对象。多 worker 会出现跨进程查不到任务与重复执行。
- `ai/tasks.py` 的恢复逻辑用当前进程 `_AI_ACTIVE_TASKS` 排除活跃任务。其他 worker 查询时可能误结束真实活跃任务。
- dashboard/analytics generation 也是进程内状态，无法保证另一 worker 写入后立即失效。
- auth 会话缓存如果只按 TTL 生效，会推迟注销、封禁和权限变更；不能把整张会话表驻留后当作实时权限真值。
- 4C16G 不是线性容量提升的证明。WAN 压测、闭环请求速率和总体客户端 CPU 使用率不足以排除所有网络、客户端单核、连接池和共享宿主影响。
- Git 跟踪有题解目录产物；外部 HTTP 404 不能单凭结果断言 VPS 目录缺失，需要核实请求路径、身份与部署文件。

## 第一阶段代码

1. `requirements-server.txt` 改为 `uvicorn[standard]==0.34.0`。Linux 安装后 auto-loop/http 可选 uvloop/httptools；Windows 不强制 uvloop。仍需生产实际 Python 安装依赖才生效。
2. 学习库及认证库每次连接应用统一配置，不放在一次性 schema 初始化分支中。
3. 环境变量：

| 名称 | 默认 | 允许范围/语义 |
| --- | --- | --- |
| IF_SQLITE_BUSY_TIMEOUT_MS | 10000 | 0–60000ms，保留原默认等待 |
| IF_SQLITE_CACHE_KIB | 32000 | 0–65536KiB，每连接按需使用，不是预留内存 |
| IF_SQLITE_MMAP_BYTES | 268435456 | 0–1073741824，平台可能限制实际映射大小 |
| IF_SQLITE_SYNCHRONOUS | FULL | FULL/NORMAL；认证库始终 FULL |

无效设置安全回退默认值。NORMAL 仅学习库显式选择，在主机断电/系统崩溃时可能丢失最近已提交事务，不把一致性等同于持久性。

### 已实施的安全边界

保留现有 TaskManager；力扣公共任务快照跨进程可查，同用户锁覆盖直接与后台同步。进程/任务租约用于死亡恢复。AI 保留现有持久化任务与队列，模型并发槽跨 worker 共享，恢复不取消活跃同伴。会话 TTL 缓存用认证库/WAL 指纹失效，注销、封禁与权限改变不等 TTL；bootstrap 短缓存用学习、认证及 AI 配置指纹失效。这些机制仅支持单主机本地文件系统，不宣称支持多主机/NFS。

学习库默认 FULL，认证库始终 FULL，没有启用 NORMAL。每连接设置等待、缓存及 mmap；参数有范围校验。日志轮转跨进程互斥，锁等待由固定 20ms 改为从 1ms 开始的有界退避。

### 实际生产操作

### 同机短时对照：不是 WAN 容量承诺

同一 VPS loopback、同一用户、每档 8 秒，只读接口；认证/注销仅为测试会话。JSON 聚合结果留在私有备份目录 before-backend.json、after-backend.json、after-final-backend.json。未记录凭据。

| 接口/并发 | 单 worker RPS | 最终四 worker RPS | 原 P95 | 最终 P95 |
| --- | ---: | ---: | ---: | ---: |
| health / 5 | 1061.9 | 1349.9 | 7ms | 6ms |
| health / 15 | 944.0 | 887.6 | 46ms | 54ms |
| bootstrap / 5 | 161.9 | 180.9 | 49ms | 69ms |
| bootstrap / 15 | 107.1 | 356.5 | 181ms | 161ms |

所有档位错误率 0。bootstrap 15 并发吞吐约 3.33 倍，但不是全部接口/尾延迟均改善；短时结果存在波动，不能外推日活或保证四倍线性扩容。原外网 121 RPS 不能单凭数值证明单核瓶颈，原单 worker 本机 health 已超过 1000 RPS。

此前题解 404 测试路径把“哈希表”错误编码成“嘈希表”。已修正压测脚本并增加路径测试；正确授权路径部署前后均为 200，因此撤回“VPS 缺失题解文件”的推断。

历史约 15 秒挂起未在本轮复现，原因仍未确定。新增本虚拟主机 JSON timing 日志记录 request/upstream 耗时、状态与 request_id，不含 Cookie、请求正文、查询串或客户端 IP；当前少量样本无 15 秒请求，不代表已根治。后续需持续样本对照，不重做无证据的容量承诺。
