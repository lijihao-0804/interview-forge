> 更新日期：2026-10-12
> 发布源：私有仓库 `main`；生产当前 commit 请在 VPS 用 `git -C /opt/interview-forge rev-parse --short HEAD` 核实。
> 本文只覆盖 InterviewForge 工具箱中的“健身房自动预约”，不代表其他项目或 VPS 服务的运维授权。

## 1. 模块用途与安全边界

模块在用户设定的日期和时段自动登录南大场馆系统、检查当天订单、尝试预约、处理验证码，并在确认金额为 0 元时完成支付和订单核验。场馆预约有真实外部副作用：测试可能创建真实预约或待支付订单；未获明确授权时，不要在生产环境触发预约测试。

必须保留的边界：

- 只处理用户明确选择的场馆、日期和时段；目前业务按“当天放号、当天预约”设计。
- 所选健身房当天已经存在有效预约时立即停止，不再尝试其他时段；另一楼层的预约不阻止当前场馆排程。发现所选场馆有待支付订单或无法确认结果时也停止，防止重复下单。
- 预约确认页和最终支付页都必须明确识别为 **0 元** 才能继续；金额未知或非 0 元时不得点击支付。
- 本工具的“取消”只取消尚未开始的自动排程，不调用南大系统的取消订单功能。正在执行的任务不强制中断。
- 预约提交后如果结果未知，不自动重新提交；必须先人工核对南大订单。
- 不要把账号、密码、Cookie、DeepSeek key、SMTP 授权码或数据库内容写进代码、文档、命令行参数、工单或 Git。
- 默认验证码策略是本地 ddddocr 标准版/beta 候选分数整体匹配；它要求两版对一对一分配达成一致，但分数不是校准后的正确率，不能保证遇到未知图都识别正确。验证码策略失败应转人工，不要移除拒绝条件或把“按钮/弹窗已消失”单独当作通过依据。
- 验证码静态实验脚本的 `api` 子命令会把测试图像发送到 DeepSeek；只有明确需要且获准时才运行，不得把真实用户验证码或账号数据上传到实验服务。
- 健身房相关代码只推送到配置好的私有远端 `private`。严禁推送到公开远端 `origin`。
- 生产操作范围仅为 `/opt/interview-forge` 和 `interview-forge` 服务；不修改 SSH 配置/密钥，不碰 VPS 上的其他项目和服务。

## 2. 代码位置与职责

| 文件 | 职责 |
|---|---|
| `interview_forge/services/gym.py` | SQLite 表、凭据加密、预约任务状态机、跨 worker 调度、有限重试、邮件通知、环境自检 |
| `interview_forge/services/gym_automation.py` | Playwright 浏览器流程：登录、订单预检、选时段、验证码、金额门禁、支付和订单核验 |
| `interview_forge/api/routers/gym.py` | 工具箱与管理员 API；身份校验、任务操作和错误响应 |
| `pages/tools.html` | 健身房工具箱 UI：排程、状态、取消与“核对后允许重试”操作 |
| `tests/test_gym_tools.py` | API 管理员边界、时段及排程输入校验 |
| `tests/test_gym_retry_policy.py` | 订单列表就绪、预约重试、过早启动、僵尸任务与人工核对策略 |
| `tests/test_gym_automation_payment.py` | 金额识别、禁止未知金额支付、成功结果脱敏等支付安全测试 |
| `tests/test_gym_email_notifications.py` | 通知内容与邮件配置测试 |

调度器由 `interview_forge/api/app.py` 的 FastAPI lifespan 启停。生产使用 4 个 Uvicorn worker；多个 worker 通过 SQLite 条件更新和 `interview_forge/runtime/shared.py` 的进程间互斥，避免同一任务被重复领取。不要把协调锁改回进程内 `threading.Lock`。

## 3. 一次预约的状态与安全流程

1. **创建排程**：校验日期、时段格式和起止时间；同一天、同一场馆已有 `pending`、`running` 或 `ambiguous` 任务时拒绝新排程。一楼与负一楼分别排程。任务使用创建者自己的南大凭据。
2. **等待放号**：调度线程约每 30 秒扫描任务。仅目标日当天执行；08:00 前不开始，浏览器在预约流程中等到约 08:00:20 再继续。
3. **订单预检**：登录后先等待订单行或明确的“暂无订单”提示。空白 DOM 不等于无订单；若订单列表未能证明已加载完成，按可恢复的页面故障处理。
4. **防重复预约**：所选场馆当天已有有效预约时报告“已有预约”并停止；另一楼层的预约不拦截。所选场馆存在未支付订单时标成结果待核，不再重复提交。
5. **找时段**：按任务中给定的优先级尝试时段。无空位时每 5 分钟重新读取，最多检查 7 次（约 30 分钟）；用尽后返回 `no_slot`，避免频繁重新加载场馆页。
6. **提交前门禁**：预约表单金额必须明确为 0 元；金额未知时尚未提交，可按安全策略重试；非 0 元直接停止。提交前发生可确认的暂时性故障时，最多执行 3 次尝试、每次间隔 5 分钟；凭据/环境错误不应靠重试解决。
7. **提交、验证码与支付**：点击预约提交后即视为可能产生了站点副作用。最终确认页必须再次明确显示 0 元才会点击支付；未知或非 0 元都停止。支付后等待订单页匹配目标日期和时段，并确认“已支付 + 正常”才标为成功。
8. **结果不确定**：提交后遇到页面关闭、支付后订单列表延迟/不可读、待支付订单或服务中断，都进入 `ambiguous`，不自动重试。运行任务超过子进程 35 分钟超时加 5 分钟宽限后，也会被转成 `ambiguous`。
9. **人工解除**：管理员必须先到南大订单页核对目标日期和场馆，确认所选场馆没有有效预约也没有待支付订单，再在工具箱使用“核对后允许重试”。该操作记录操作者和时间，将旧任务归档为失败状态并释放该场馆的日期占用；它不会在南大系统执行任何取消操作。

主要任务状态：

| 状态 | 含义 | 是否自动重试 |
|---|---|---|
| `pending` | 等待目标日执行，或等待一次已判定安全的延迟重试 | 是，取决于 `retryable`、剩余次数和重试时间 |
| `running` | 浏览器子进程正在处理任务 | 否；超过超时宽限后改为 `ambiguous` |
| `succeeded` | 订单页核验到目标订单已支付且正常 | 否 |
| `no_slot` | 执行器已完成最多 7 次空位检查（每次间隔 5 分钟） | 否；不是服务故障重试 |
| `ambiguous` | 无法安全判断是否已产生预约/支付副作用 | **否**；先人工核对 |
| `failed` | 明确失败或人工确认无订单后解除占用 | 通常否；安全的提交前瞬时故障例外 |
| `cancelled` | 管理员取消尚未开始的本地排程 | 否；不会取消已有预约 |

## 4. 凭据、数据库与通知

- `data/gym.db`：预约任务、每用户南大账号凭据密文、通知收件邮箱、全局 SMTP 发件配置。不要提交、复制到公开位置或用文本编辑器直接改库。
- `data/gym-secret.key`：本机生成的凭据加密密钥；也可由 `INTERVIEW_FORGE_GYM_KEY` 提供。密钥必须与 `gym.db` 一起保全，否则历史凭据无法解密。生产权限应保持 `600`。
- `data/ai_config.db`：验证码识字可从管理后台 AI 配置中读取已启用的 DeepSeek 配置；`INTERVIEW_FORGE_AI_CONFIG_KEY` 是该配置库的解密主密钥。代码也支持 `DEEPSEEK_API_KEY` 环境变量和被忽略的 `data/gym-deepseek-key.txt` 作为回退。任何 key 都不能写入本文。
- `data/logs/gym/`：任务运行日志、结果文件及验证码/诊断材料。可能含个人或订单上下文，应按敏感运行数据保护；分享日志前先检查和脱敏。
- 南大账号密码经验证后按用户加密存入 `gym.db`，调度器通过子进程 stdin 传递，不放在 argv 或日志中。更换密钥前先规划数据迁移，不要直接删除或覆盖密钥文件。
- SMTP 发件信息在管理后台全局配置；通知收件邮箱按工具箱用户配置。不要把所有人的失败通知转发给单一审阅人；测试邮件使用明确的测试功能。
- 备份恢复时将数据库和匹配的密钥一并处理，并重新确认权限为 `600`。不要把 `data/` 纳入 Git。

可选浏览器识别依赖定义在 `requirements-tools.txt`；Playwright/Chromium 是执行必需项，`ddddocr` 是本地识别路径，PaddleOCR 作为可选识别能力且 NumPy 固定在 2 以下。DeepSeek 识字配置缺失时仍可由本地识别路径工作，但验证码成功率可能下降。先看工具箱环境自检卡，再决定是否处理依赖。

验证码 `probability` 路径是当前默认策略；`legacy` 是显式兼容路径，才会初始化 PaddleOCR 并尝试调用 DeepSeek。当前报告的 13 张静态图和 26 次本地浏览器点击验证属于小样本/夹具验证，不是独立盲测，也不是南大线上验收；不要将其表述为生产准确率保证。

## 5. 运维与排查速查

在已授权的 VPS 会话中，先限制在项目目录执行只读检查：

```bash
cd /opt/interview-forge
git rev-parse --short HEAD
git status --short
systemctl is-active interview-forge
curl -fsS http://127.0.0.1:8765/api/health
curl -fsS https://hot100.xyz/api/health
stat -c '%a %n' data/gym.db data/gym-secret.key
```

查看本服务近期日志：

```bash
journalctl -u interview-forge --since '30 minutes ago' --no-pager
```

判断预约任务卡住时，先看工具箱中的任务状态和更新时间，再核对服务日志。不要因任务显示 `running` 就直接新建同日、同场馆任务；不要通过杀浏览器、删除任务行或重启其他服务来“清理”。若任务仍在执行，等它返回；若最终变成 `ambiguous`，到南大订单页人工确认目标场馆后再用管理员解除入口。

常见判断：

- **DeepSeek 自检红**：先确认管理后台 AI 配置库中的 DeepSeek provider 已启用、密钥已配置；不要把 key 粘贴到聊天或日志。
- **订单列表未渲染/超时**：这是“还不能确认列表为空”，不是“没有预约”。允许有限的提交前重试；多次失败时检查登录状态和页面结构。
- **账号密码错误**：重新验证并更新本用户凭据；不要把失败解释成 Cloudflare 拦截，先看具体分类与执行日志。
- **确认页金额未知**：系统按设计不点支付。人工查看南大页面确认金额和订单状态，不能通过关闭安全门来绕过。
- **支付后未核验到订单**：任务应是 `ambiguous`。即使页面没有显示成功，也不能据此立刻重跑。

## 6. 开发测试与部署纪律

改动前先检查工作区与目标分支，不覆盖已有未提交内容。健身房改动至少运行：

```powershell
python -m pytest -q tests/test_gym_tools.py tests/test_gym_retry_policy.py `
  tests/test_gym_automation_payment.py tests/test_gym_email_notifications.py
python -m ruff check --select F,E4,E7,E9 `
  interview_forge/api/routers/gym.py interview_forge/services/gym.py `
  interview_forge/services/gym_automation.py tests/test_gym_*.py
```

修改跨 worker 调度/锁时还要运行 `tests/test_shared_workers.py`，并在支持 multiprocessing 命名管道的环境执行；受限 Windows 沙箱可能因 `WinError 5` 失败，不能把这个环境问题记成代码通过。

部署前确认目标 VPS 当前 commit 是本次变更的直接祖先、没有未提交的源码改动，并查看 `pending/running/ambiguous` 任务状态。VPS 上未跟踪的 `.venv/`、数据库备份和 `data/runtime/` 等属于运行环境或用户数据，必须保留；严禁用 `git clean`、覆盖式拉取或重置来“清理”。只更新 `/opt/interview-forge`：提交并推私有仓库 `main`，使用已验证的 Git bundle 快进，不做强制覆盖；仅重启 `interview-forge`。重启后必须验证服务为 active、本机和公网 `/api/health` 都成功，并检查数据库/密钥仍为 `600`。若远端有源码修改或存在正在执行的预约任务，先停下来保留现场，不强行部署。
