## 三、新引入 Bug 审查结果

本轮对所有新代码做了安全与正确性专项（auth.py 的 site_settings、admin 双路由、retention 接线、community 摘要、负荷聚合、新测试），**未发现 P1/P2 级新引入缺陷**。逐项检查结论：

- ✅ `/api/admin/settings/fsrs-retention` GET/POST 均 `require_admin`，POST 走 `_admin_write`（线程池），payload 严格 `set(payload) != {"desired_retention"}` 校验；
- ✅ retention 读取失败安全回退默认值（catch 全覆盖 sqlite/类型/溢出），不会因脏数据 500；
- ✅ 搜索摘要前端渲染走 `hl()`（先 `escHtml` 再包 `<mark>`），无 XSS；
- ✅ 负荷聚合 SQL 参数化 + 日期窗口参数化；
- ✅ manifest 图标变更带契约测试，`test_ui_retry_contract` 把 ui.js 组件锁定。

**发现 3 个小问题（均为 P3）**：

1. **4.5 双品牌值方向冲突**：`ai-launcher.css` 的 fallback 改成了 `#5654d4`（与 cockpit 一致），但 `index.html` 的 `--brand` 和 `manifest.webmanifest` 的 `theme_color` 仍是 `#5755d4`——统一动作做了一半且两个文件朝不同方向。建议拍板一个值（cockpit/admin 系的 #5654d4 出现频次更高）后全局替换一次。
2. **`FSRS_DESIRED_RETENTION` 默认参数扩散**：`complete_round/complete_content/fsrs_review` 三层都有 `desired_retention: float = FSRS_DESIRED_RETENTION` 默认值，路由层每次显式传参所以行为正确；但任何**新的**调用方若忘记传参就会静默用 0.9 而不是管理员设置。建议后续把默认值参数改为必填（去默认值）让漏传在编码期暴露。
3. **批次 0.1 的未提交文件中包含安全政策文档**：`CONTENT-RIGHTS-BOUNDARY.md` 至今未入库——它是 5.2 决策的依据文件，应最先提交。

另有一处**历史遗留确认**：`requirements-dev.txt` 新增的 `Markdown` 依赖是为报告 HTML 再生成服务，范围锁定合理，无问题。
