## 一、现状视觉盘点（基于实测截图与采样）

### 1.1 当前调色板（采样值）

| 令牌 | 亮色 | 暗色 | 用途 |
|---|---|---|---|
| --brand | `#5654d4` | `#b1afff` | 唯一强调色：链接/按钮/chips/激活态/进度条 |
| --page-bg | `#f4f6fb` | `#0f131b` | 页面底 |
| --surface | `#ffffff` | `#181e29` | 卡片/面板 |
| --line | `#dfe4ee` | `#313b4c` | 全部边框 |
| --muted | `#66748a` | `#a7b2c4` | 次要文字 |
| --text | `#182235` | `#eaf0fa` | 正文 |
| 代码块 | `#151a24`（亮暗同值） | 同左 | 常暗设计，亮色页中的对比元素 |

### 1.2 截图观察（亮暗两态逐页）

**面板（浅色）**：信息密度高，功能完整。但整页从背景到卡片几乎全白（bg 与 surface 亮度差仅约 2%），层次靠 1px 浅边框和极淡阴影勉强维持——"白上白"导致视觉重心不明确。统计卡、待复习/计划卡、题目卡全部同规格白底圆角，一眼扫过去没有视觉锚点。

**书架（浅色）**：分类图标（☕🖥️🗄️）直接裸排无底色，13 个分类全靠 emoji 自身颜色区分，色彩身份弱；筛选 chips、模块卡片、进度条全部同紫色系；进度条 0% 时是一根灰色空条——卡片下缘一片"灰白"。

**题解页（亮/暗）**：三栏结构成立；暗色模式层次感明显好于亮色（面板 #181e29 在 #0f131b 上有真实对比度）；难度徽标三色（绿/橙/红）是全页少有的非紫色彩；代码块常暗设计在亮色页中形成漂亮的对比锚点——这是目前最好的设计决策之一。

**发现的一个硬伤**：暗色模式下 Mermaid 图表是**白底方块**（示例图 1→5 反转链表白底黑字直接怼在 #0f131b 上），极其突兀——THEME 里虽有 --diagram-* 令牌但亮暗两套值完全相同（都写了浅色值），暗色未生效。

### 1.3 核心诊断

1. **亮色主题"白上白"**：背景与表面几乎无差别，页面靠边框而非色块分层——观感"素"的直接原因；
2. **单色单调**：全站只有一个紫，没有第二强调色；13 个分类、4 种难度状态、已 AC/薄弱/复习中多种语义全部挤在"紫 + 少量绿橙红徽标"里；
3. **暗色反而更好**：暗色下表面层级自然分明——说明问题不是"缺设计"而是亮色令牌没有拉开层次；
4. **Mermaid 暗色破功**：图表体系自称"统一视觉"但暗色令牌是复制的浅色值。

## 二、参考项目怎么做的

### 2.1 Radix Colors（shadcn/ui 的颜色底座）——步阶体系

每个色相 12 步（1~9 浅→深，9 是纯色可用步，10~12 文字/边框用），语义封装为 `primary/accent/destructive/muted`。**对本项目的启示**：目前 --brand 只有一层，brand-soft 是唯一的浅色衍生。若把品牌紫扩展为 3~5 步（brand-1 到 brand-9），chips/进度条/激活态可以各取所需，不必全挤一个值。

### 2.2 Linear（暗色 SaaS 标杆）——表面分层 + 低透明白边框

Linear 暗色的层级不靠换底色，靠 **rgba(255,255,255,0.02~0.06) 的逐层叠加** + 1px 低透明白边框。对比我们的暗色：#181e29 vs #0f131b 差异已够，但边框 #313b4c 偏"实"。可微调为 `color-mix(in srgb, var(--text) 10%, transparent)` 类的低透明度边框，观感更"轻"。

### 2.3 VitePress——亮色主题的"淡淡的底色分层"

VitePress 亮色 bg 是 `#ffffff`、边栏/代码块区是 `#f6f6f7`——它比我们更"白"，但它赢在**排版对比**：标题字重 600→900 跨度大、代码块立刻切入深色、品牌色只出现在交互元素。启示：亮色发不发灰不是关键，**层次可以靠排版和"深色锚点"撑起来**（我们的常暗代码块已经在做这件事，是对的）。

### 2.4 LeetCode 题单页——语义色用的最足的同类产品

题目卡：难度三色徽标（绿/橙/红）+ 通过率色条 + 收藏星标黄色。全页同样白底，但语义色密度高，所以"不素"。我们已有三色难度徽标和 AC/薄弱/复习中标记——**可以再往进一步**：专题分类色、已 AC 卡的绿色左边框已有——但 17 个专题没有各自的色彩身份。

### 2.5 Starlight——卡片与 hero 的色彩注入

卡片 hover 时边框和标题同步转品牌色（而不是整卡变色）；hero 用极淡的品牌径向渐变。我们书架卡片 hover 已有微浮+阴影，可补"边框转品牌色"细节。

## 三、优化空间清单（按视觉收益排序）

### A. 亮色主题分层（最高收益，纯令牌调整）

| 项 | 现值 | 建议 | 效果 |
|---|---|---|---|
| page-bg | `#f4f6fb` | `#eef0f8`（略深、带品牌冷调） | 卡片白底立刻"浮"出来 |

| body 渐变 | 仅左上一点 | 顶部加整幅极淡品牌渐变（Starlight 式） | 品牌氛围 |

### B. 分类色彩身份（书架/题卡/专题页联动）

为 13 个分类分配色相（Java=橙 ☕、数据库=蓝、并发/系统=青、AI=紫红……），应用于：模块图标底色、卡片进度条渐变起点、模块页顶栏徽标。实现：`_module_icons` 扩展为 icon+color 映射，卡片内联 `style="--cat: <hue>"` + CSS `color-mix` 引用。这是"从素到活"最大的一步，且不动布局。

### C. Mermaid 暗色修复（硬伤级）

`--diagram-*` 令牌亮暗两套值相同是 bug 级疏漏：暗色应改为深底 `#1b2230`、节点深底浅字、连线提亮。改 `build_library.py` 的暗色令牌块即可。暗色模式下那 89 章含图表的页面全部受益。

- 题解页"复杂度"标题块可复用 aside-note 样式

## 四′、过渡动画与悬浮交互调研（补充）

### 4′.1 现状动效盘点（CSS 实测）

现有动效共 8 处，全部是**状态型过渡**（respond to action）：
阅读进度条（width .1s linear）、链接下划线划入（.25s ease-out）、卡片 hover 微浮（.2s）、
复制按钮反馈、骨架屏 shimmer（唯一 keyframes）、滚动条 hover、语言 chips 变色（.15s）、
demo-kit 单元格状态切换（.25s）。`prefers-reduced-motion` 已全局尊重。
**缺口**：无入场编排、无主题切换过渡、无数值动画、面板区块显隐是瞬变、悬浮反馈仅卡片一类。

### 4′.2 参考项目的动效语言

| 项目 | 标志性动效 | 可借鉴点 |
|---|---|---|
| **Linear** | 卡片 hover 边框辉光（1px 边框转亮 + 极淡径向渐变浮现）；按钮按下 scale(.97)；tooltip 延迟 300ms 跟随 | 悬浮时"边框先亮、底色后淡入"的两段式，精致不浮夸 |
| **Vercel/Geist** | 渐变边框流光（conic-gradient 旋转）；数字滚动（count-up）；展开卡片高度过渡 | 统计卡数字 count-up；边框流光可用于"完整轮次"达成瞬间 |
| **Stripe Docs** | 滚动触发的一次性 reveal（交错 stagger 100ms）；目录高亮平滑跟随 | 面板统计卡入场交错——但遵守"只编排一次"纪律 |
| **shadcn/ui** | Dialog/Sheet scale+fade 组合（150ms，origin 对齐触发点）；Toast 底部滑入 | 聊天悬浮窗/资料面板的出场动画（现在是瞬现） |
| **Raycast** | spring 物理（回弹感）；悬浮面板跟随光标 | 超出 CSS 能力，需 JS 弹簧库——不建议引入 |
| **VitePress** | 极克制：仅链接变色 .15s、侧栏激活态过渡、暗色切换无过渡 | 证明文档站动效可以极少 |
| **View Transitions API** | 浏览器原生页面切换动画（Chrome 111+，一行 CSS 声明） | 题解页↔面板跳转的淡入淡出，渐进增强零成本 |

### 4′.3 动效设计原则（来自 frontend-design skill 的核心纪律）

> "非用户触发的动效要吝啬且有目的：一次编排好的入场比散落的特效更有力；
> 每个区块的 fade-and-slide-up 入场和每张卡的 hover 过渡是 AI 生成的通用默认，
> 会一眼被看穿。响应用户动作（打开、展开、确认）的动效则受欢迎，因为它展示了变化。"

翻译成施工守则：
1. **悬浮动画必须有语义**——hover 变化要暗示"这个可以点/会发生变化"，不为动而动；
2. **状态变化必须可感知**——语言切换、收藏、完成一轮这类操作，界面要有 ≥150ms 的视觉回应；
3. **入场只编排一次**——页面加载时最多一组整体淡入，禁止逐卡片 stagger；
4. **所有动效 respect prefers-reduced-motion**（我们已有全局兜底）；
5. **时长刻度**：hover 150~200ms、展开 250~300ms、入场 300~400ms、theme 过渡 200ms——超过 400ms 就"腻"。

### 4′.4 本站悬浮/过渡优化清单（按收益排序）

| # | 位置 | 现状 | 建议 | 参考 |
|---|---|---|---|---|
| H1 | **主题切换** | 瞬变（data-theme 一换全页颜色跳变） | `html{transition:background .25s,color .25s}` + 卡片/边框同步过渡——暗亮切换变成"渐变"而非"闪变" | shadcn |
| H2 | **悬浮卡片辉光** | 只有 translateY(-1px)+阴影 | 两段式：边框先转品牌色（.15s）+ 极淡径向品牌光斑浮现（.25s）——Linear 招牌 | Linear |
| H3 | **悬浮面板出场** | 聊天窗/资料面板瞬现 | `transform:translateY(8px)+opacity:0` → 归位，200ms ease-out；关闭反向 | shadcn Dialog |
| H4 | **统计卡数字 count-up** | 数字瞬现 | 面板加载后 300ms 内从 0 滚到目标值（requestAnimationFrame，10 行 JS） | Vercel |
| H5 | **悬浮窗展开的区块** | 语言切换条/aside 显隐瞬变 | max-height/opacity 组合 200ms 过渡 | shadcn Accordion |
| H6 | **题卡已 AC 绿边框** | 静态边框 | hover 时边框辉光加深一档 | Linear |
| H7 | **页面级 View Transitions** | 跳转瞬变 | `@view-transition{navigation:auto}` 一行渐进增强（Chrome 系生效，其余忽略） | 原生 API |
| H8 | **tooltip** | 仅 title 属性（系统延迟 1s+） | 交互提示统一自制 tooltip（300ms 延迟 + fade） | Raycast |

**不建议做**：逐卡片 stagger 入场、鼠标跟随光斑、无限循环微动画、页面切换 spinner——
全部属于 frontend-design skill 点名的"AI 生成默认动作"。

### 4′.5 悬浮动画细节规格（如施工直接照抄）

```css
/* H2 卡片辉光（两段式） */
.module-card{transition:border-color .15s var(--ease-out),box-shadow .25s var(--ease-out),transform .2s var(--ease-out)}
.module-card:hover{border-color:color-mix(in srgb,var(--brand) 45%,var(--line));
box-shadow:0 10px 28px color-mix(in srgb,var(--brand) 14%,transparent),0 0 0 1px color-mix(in srgb,var(--brand) 20%,transparent)}

/* H3 悬浮面板出场 */
.forge-panel{animation:panel-in .2s var(--ease-out)}
@keyframes panel-in{from{opacity:0;transform:translateY(8px)}to{opacity:1;transform:none}}

/* H1 主题切换渐变 */
html,body,.module-card,.review-section,.chapter-card{transition:background-color .25s var(--ease-in-out),border-color .25s var(--ease-in-out),color .25s var(--ease-in-out)}
```
