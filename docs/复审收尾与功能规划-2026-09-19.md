## 二、功能规划建议（参考同类产品）

以下建议均标注：参考来源、依托的现有基建（大多不需要新地基）、预估工作量（S≤1天 / M=2-5天 / L=1-2周）。按"性价比分层"，不是建议全做。

### 第一梯队：直接强化现有闭环（低成本高收益）

**1. 复习调度升级：固定间隔表 → FSRS（或先做"薄弱降档"）** `M-L`
- 现状：题目 1/3/7/15/30/60、章节 3/7/15/30/60/90 固定查表，薄弱标记只影响进"今日待复习"，不改变间隔。
- 参考：[Anki 已用 FSRS 替代 SM-2](https://faqs.ankiweb.net)，[fsrs4anki / open-spaced-repetition](https://github.com/open-spaced-repetition/fsrs4anki) 开源（有 [py-fsrs](https://github.com/open-spaced-repetition/py-fsrs) 可直接 pip），基准测试显示 [FSRS 对 99.6% 用户优于 SM-2](https://expertium.github.io)；[RemNote 也已跟进](https://help.remnote.com)。
- 落地路径：per-user 库已有完整复习日志（轮次/日期/薄弱标记），先做轻量版——"WA/薄弱 → 间隔回退 1-2 档、连击顺畅 → 提前半档"，一天工作量；再评估接入 py-fsrs 按目标记忆保持率（如 90%）调度。
- 为什么值得：这是学习站的核心引擎，直接决定"复习队列不积压且不忘"。

**2. 闪卡 / 自测遮罩模式** `S-M`
- 现状：题页已有结构化的"核心模式/核心不变量/复杂度"字段，但复习时答案直接可见，容易"看着都会"。
- 参考：Anki/RemNote 的卡片化；NeetCode 的"先自测再看题解"学习法。
- 做法：题页加"自测模式"开关——遮住推导和代码，只显示题名+约束，点击逐段揭示；再把"核心不变量+方法"自动生成正反面卡片，做一个 `flashcards.html` 队列页（复用现有复习调度和 per-user 记录）。移动端碎片时间复习是刚需。
- 顺带：导出从 Anki CSV 升级为 `.apkg`（genanki 库，S 工作量）。

**3. 复习积压预警与智能减负** `S`
- 现状：`daily_data` 已算 due/overdue 数量，但积压 50 题时面板仍全量列出，用户容易弃疗。
- 参考：Duolingo 的"每日任务"拆分、SuperMemo 的 mid-spacing（优先溢出）。
- 做法：overdue 超过阈值（如 20）时，"今日待复习"自动只排最高优先级（逾期最久/薄弱/核心专题），其余显示"已顺延"；顶部一条积压趋势提示。纯服务端逻辑 + 前端少量文案。

**4. 掌握度模型（四档制）** `M`
- 现状：题卡有"薄弱/复习中/已掌握"手动三态 + AC 徽标，书架章节只有轮次。
- 参考：Khan Academy 的 attempted → familiar → proficient → mastered 掌握度；NeetCode 的进度清单。
- 做法：服务端用现有信号（AC 次数、轮次数、最近复习、是否薄弱、自测通过）推导四档掌握度，题网格按掌握度着色（现在是 AC/未 AC 二色），书架模块页加掌握度进度条 + 雷达图（按专题）。这是把"学了多少"升级为"会了多少"的关键视图，也是给 AI 上下文的高质量信号（AI 教练能直接说"你的树专题还在 familiar"）。

**5. 面试倒计时反向排期** `S-M`
- 现状：有每日目标轮次设置，但没有"目标日期"概念。
- 参考：牛客的[校招日程汇总](https://www.nowcoder.com)思路；各类考试倒计时 App。
- 做法：设置目标面试日期 → 服务端按"剩余天数 × 每日容量"与剩余新题+积压对比，动态建议每日新题量（来不及就提醒砍新题保复习），首页显示"D-37"。与 3 的减负逻辑天然衔接。

### 第二梯队：AI 延伸（差异化竞争力，基建已就绪）

项目已有 tool-calling、SSE 流式、ACTION 人工确认、per-user 上下文工程——做 AI 面试场景几乎是现成的。

**6. AI 模拟面试模式** `M-L`
- 参考：[Final Round AI](https://www.finalroundai.com) 的"模拟面试 + 自动复盘"、[Big Interview](https://careerservices.fas.harvard.edu) 的追问式练习。
- 做法：新会话类型"mock_interview"——AI 以面试官身份给题（从用户未 AC/薄弱池选），用户作答思路后按追问链推进（复杂度？边界？如果数据量×100？），结束后自动生成复盘报告（答对点/漏点/推荐复习项），并把表现写入薄弱标记。追问链用现有工具循环实现，复盘写 per-user 库。
- 注意：接入现有聊天配额体系，单场面试按固定 quota 计。

**7. AI 变体追问题** `M`
- 对已 AC 的题，AI 生成 2-3 个"面试官套路追问"（改约束、扩规模、换场景），挂到题页"高频追问"区并单独调度复习。参考牛客"面经追问"传统。

**8. 面经结构化 + 自动关联** `M`
- 参考：[牛客网](https://www.nowcoder.com) 的面经沉淀（10000+ 面经是其护城河）。
- 做法：个人版面经库——粘贴一段面经，AI 抽取"公司-岗位-轮次-题目"结构化入库，自动关联站内题解与书架章节；面经里出现没学过的题 → 进"新题池"。单人使用也比聊天室现在的泛聊更有沉淀价值。

### 第三梯队：内容组织与体验（借鉴 NeetCode / Obsidian）

**9. Roadmap 进度视图** `M`：现在题网格按题号排列（LeetCode 式），可加"专题路线图"视图——17 个专题为章节、题目按学习顺序排列、显示掌握度，[NeetCode Roadmap](https://neetcode.io) 的核心就是"按模式递进"而不是"按题号硬刷"。
**10. 自定义题单** `M`：按公司/岗位/自选建题单，挂在题网格过滤器和今日计划来源上；可导出分享。牛客 TOP101 本质就是一份"高频题单"。
**11. 同模式对照表** `S`：专题页加"已学题目横向对比"（方法/不变量/复杂度/易错点四列），做专题复盘时一眼看穿模板共性。
**12. 命令面板 Ctrl+K** `S`：题号/题名/章节全局模糊跳转 + 动作（开始模拟、去复习）；数据源就是现有的题库 JSON 和 manifest，纯前端。
**13. 默写模式** `M`：题页内嵌 CodeMirror/Monaco（ vendor 已有离线库先例），写完与题解做 diff 高亮（不运行 Java，只对比结构）。对应"关闭笔记写代码"的学习法第 3 步，现在是开两个窗口手动对照。
**14. 周报自动化** `S`：已有周报导出，加"登录时自动生成上周对比卡片"（看题/轮次/AC/连续天数环比），数据都在，纯展示。
**15. 书架进度与"下一章"推荐** `S`：736 章的全局完成率、每本书进度条、学完一章推荐下一章（同书顺序即可）。

### 不建议现在做的

- 多人社区/排行榜/评论：现有聊天室够用，社区内容审核成本高且偏离个人学习站定位；
- 在线运行 Java：OJ 沙箱是大工程且力扣本身就是运行环境，默写 diff 模式（13）性价比高得多；
- 移动原生 App：PWA 已覆盖，先把移动端 UX 债还完。

## 三、推荐落地顺序

1. **闪卡/自测遮罩（2）** + **积压减负（3）**：一周内可上线，立刻改善日常复习体验；
2. **掌握度模型（4）**：为 FSRS 和 AI 功能打底，数据模型先行的承重墙；
3. **FSRS 轻量版（1）**：引擎升级，趁复习日志还不多时切换成本最低；
4. **AI 模拟面试（6）**：差异化最大的一件事，等掌握度/配额稳了再上；
5. Roadmap 视图（9）与面经库（8）看使用反馈再排。

核心逻辑：先用"2/3"让复习闭环更好用 → 用"4/1"让调度变聪明 → 用"6"把 AI 从助手升级为陪练。每一步都在已有基建（per-user SQLite、tool-calling、SSE、调度器）上叠加，不需要推倒任何东西。
