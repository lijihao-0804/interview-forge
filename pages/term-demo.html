Agent 是什么

Agent（智能体）是能自主感知环境、做出决策并调用工具完成目标的 AI 系统。它和传统 Chatbot 最大的不同在于「行动能力」：Chatbot 只会回复文字，而 Agent 会真的去查资料、调接口、执行代码。

一个典型的 Agent 由几个部分组成：负责理解与决策的 LLM，负责行动的工具集，以及管理记忆与状态的存储。它的运行是一个循环——观察、思考、行动、再观察，直到任务完成。

ReAct 与思维链

ReAct 是最经典的 Agent 范式之一，名字来自 Reasoning 和 Acting 的组合。它让模型交替进行推理与行动：先想一步（Thought），再调一个工具（Action），看到结果（Observation）后继续，直到得出答案。

与之相关的还有 CoT（思维链），它强调让模型分步推理、把中间过程写出来，从而提升复杂问题的正确率。在实践中，合理的 Prompt Engineering 往往比换更大的模型更有效。

RAG 为什么重要

LLM 的知识有截止日期，也容易产生 Hallucination（幻觉）——一本正经地编造不存在的事实。RAG（检索增强生成）就是用来缓解这个问题的：先把相关资料查出来，再让模型基于资料作答。

RAG 的关键环节包括文档 Chunking（分块）、用 Embedding 把文本转成向量、存进 Vector DB（向量数据库），查询时先做 Semantic Search 召回候选，再用 Rerank（重排）精选，最后拼进 Context Window（上下文窗口）交给模型。

需要注意的是，上下文窗口并非越大越好，太长会出现「Lost in the Middle」：放在中间位置的信息更容易被忽略。

工具与协议

Agent 要靠 Function Calling（工具调用）与外部世界打交道。模型本身不执行函数，只输出「要调哪个、传什么参数」，由外部执行后把结果喂回来。

MCP（Model Context Protocol）则进一步把这套交互标准化：工具提供方实现一次，多个 Agent 宿主都能复用，避免为每个宿主重复开发。此外，Agent 执行代码时必须放在 Sandbox（沙箱）里隔离，防止影响主机。

从 Workflow 到自主智能

并非所有任务都需要 Agent。如果流程稳定、步骤固定，用 Workflow（工作流）更可控也更省成本。只有当任务边界模糊、需要临场判断时，才值得引入 Agent 的自主决策。

更复杂的场景还可以用 Plan-and-Execute（先规划后执行）范式：先制定完整计划再逐步执行；或者引入 Reflection（反思）机制，让 Agent 做完后自我检查、发现错误再修正。

最后，线上运行还需要 Observability（可观测性）：通过 Trace 还原 Agent「想了什么、调了什么工具、拿到什么结果」，这是排查问题的核心手段。
