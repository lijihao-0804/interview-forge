# 多条历史原话与有条件引用的生产验证

2026-11-14 在 hot100.xyz 公网聊天入口用托管 deepseek-flash 实测。对照是此前发布的 33f625a1，本次实现是 a85818fe。每题每版使用一个独立的 1,280 条合成聊天记录会话，按第一次完成的答复计分。每次读到的历史候选 ID 在服务端留有记录，引用需在同一会话按偏移和 SHA-256 重新打开。

隔离预检还捕捉到两种可以直接验证的误拒。一种是核对模型已抄对原话和来源，却概述了可选的场景说明；现在省略未经核实的说明，保留经核实的原话。另一种是 DeepSeek 已用完该轮输出预算，只返回了部分 JSON 或没有输出选择。现在仅在有剩余轮次时追加一次短复核，仍需从原文确认。预检产生的用量不计入上表。正常语义否决也有单独条件，只有不同检索结果共同把同一来源排在前列时才考虑复核一次。

初版部署后，算账题和排练多解对照的核对轮均用完 3,072 个输出 token，全部用于推理。随后的无推理复核分别只花了 48 和 56 个输出 token，依然没有给出原话。后续补丁让恢复轮只提交有原文证据的正例，保留有限推理，并给多解问题保留与首轮相同的候选上限。在这个改动完成之前，九道新题的成绩和具体失败均未向开发侧揭晓。

## 盲评结果与剩余错误

七道有原文可引的新题，三个版本都检索到了全部必需来源。最终正确列出全部原话、配对消息 ID 并能重新打开的是 7/7，前两版都是 6/7。三道多解新题三个版本均为 3/3。两道有身份前提的新题，三个版本依次严格答对 0/2、1/2、2/2。三个版本都没有贴出匿名原话。新版还说清了无法核实实际发言人，并在材料足以确认身份时给出了正确的说话人及原文。最终版答对后一题用了两轮模型调用。

唯一仍错的是提案状态题。工具两次返回了能区分待议事项与已批准事项的记录，最后却只说无法确认原话，遗漏了用户要求的决定状态。这个错误三个版本均有出现。

同一位出题者按预先冻结的规则盲评。每次打乱两组共 18 份答案、隐藏版本并替换消息编号，判分后揭晓版本。基线在两次盲评中判分一致。最终版相对基线多答对两题，没有题目退化。九题配对符号检验的双侧 p 值为 0.50，样本量不足以确定其他对话上的提升幅度。

三个版本共收录 57 份完成的答复。基线与首次上线合计三道对照请求遇到连接中断，客户端用相同幂等键恢复。表中记录成功答复的用时与回报用量，此前断开尝试有无额外供应商用量未能核实。旧错题、新盲题和最终版全部题目均未遇到这种重试。部分题组在隔离账号上并行执行，每题每版只计一份正式答复，表中延迟适用于这次测量。
