# 长对话语义检索的线上对照

2026-11-14，测试通过 hot100.xyz 的普通登录聊天入口调用托管模型 `deepseek-flash`。每题的历史有 1,280 条合成消息。实现与检索分开验收，工具返回预期消息 ID 算作检索命中，答复还须保留原话、给出正确且唯一的来源 ID、正确解释说话人，才计入严格可用率。

| 运行时 | 主测 8 题检索命中 | 主测严格可用 | 留出 4 题检索命中 | 留出严格可用 |
| --- | ---: | ---: | ---: | ---: |
| 关键词基线，4ce3e62e | 0/8 | 0/8 | 0/4 | 0/4 |
| 语义检索初版，87e79105 | 7/8 | 2/8 | 3/4 | 0/4 |
| 工具输出修正，231f77bf | 6/8 | 1/8 | 2/4 | 0/4 |
| 逐字校验版本，5aefbb53 | 6/8 | 6/8 | 2/4 | 2/4 |

另有 6 道对照题，验证原词、最早记录、多解、跨会话无记录以及含指令的历史内容。这些题计入下表的延迟与用量，未计入上表的换说法题。四版各运行 18 次，共 72 次。表中耗时按每次发出 HTTP 请求至 SSE 结束计，token 采用供应商返回的实际输入和输出用量，包括工具轮和最后的引文选择轮。

| 全部 18 题 | 模型调用轮数 | 输入 token | 输出 token | 公网总耗时 | 平均每题 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 关键词基线 | 66 | 300,044 | 12,194 | 115.75 秒 | 6.43 秒 |
| 语义检索初版 | 62 | 295,479 | 14,372 | 160.24 秒 | 8.90 秒 |
| 工具输出修正 | 64 | 304,645 | 13,317 | 151.05 秒 | 8.39 秒 |
| 逐字校验版本 | 38 | 105,109 | 8,055 | 99.35 秒 | 5.52 秒 |

- 最终版本相对基线减少了 65.0% 的输入 token、33.9% 的输出 token，平均每题少 0.91 秒。向量编码在 VPS 的 CPU 上运行。首次建立索引与已建索引后的查询成本不同，没有将本地编码时间换算为供应商 token 或账单金额。
- 在 8 道主测换说法题上，预先确定的一次直接语义检索有 7 道返回目标；Agent 完整流程有 6 道直接给出可采用的原文。对于关键词基线，允许人工预置的三个词翻遍全部原文也能命中 8/8，平均需要每题 15 次直接调用，超过正常 Agent 单轮的工具预算。
- 最终版本的无记录拒答、严格最早回查以及历史指令隔离通过。主测仍有两题未召回目标，多解对照未列全来源。留出题中还观察到了漏检和把他人的建议错当成用户自己的说法。通过来源校验只证明引文可在原消息中找到，对归属和相关性的判断也要单独验证。
- 每个版本每题仅运行一次。样本由人工构造，网络和模型输出有波动。严格标准由一人复核，在第三次语义版本运行前冻结，早期版本按同一标准追评。第三版发布前已经看过第二版预留成绩，复用结果不能作为独立泛化估计。

复现方法和两套冻结清单见[实验说明](README.md)。各组的模型运行时、源码和本机部署方法见[部署说明](../../../deploy/history-embeddings.md)。本报告只公开汇总数字和验证方法。
