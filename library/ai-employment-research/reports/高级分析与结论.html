可核查结论与行动建议

1. 四个目标方向在样本中有不同的正文可分析覆盖率

证据 - 四方向具体职位记录合计 1,537/28,342 条；其中资格文本可分析 1,532/1,537 条。 - 方向为标题规则分类，岗位记录来源范围和企业截面并不一致。

解释： 后续技能、学历、经验百分比只代表可分析的资格文本，不应按全部岗位记录作分母。

行动： 先按方向和资格可用标记筛选，再比较技术栈；对未拆出资格文本的岗位回看原始正文。

局限： 方向由标题规则推断；样本不覆盖统一雇主集合，也不是全国招聘市场份额。

2. 职位加权结果受头部雇主集中度影响

证据 - AI应用/Agent开发方向中，字节跳动占 368/736 条 (50.0%)，该方向前三雇主合计占 83.4%。

解释： 职位加权率回答的是‘本次收集到的职位文本中有多少提到某技能’，不是典型公司的要求；单一雇主模板会显著影响比例。

行动： 阅读方向技能时同时查看 company_equal 率；求职者可用目标公司组内的要求做准备清单。

局限： 每家公司的职位数反映本次公开列表与采集范围，不等于HC或公司招聘强度。

3. 应用/Agent岗位常同时要求后端工程基础与检索、智能体能力

证据 - Agent 601/733 (82.0%) - RAG 286/733 (39.0%) - Python 414/733 (56.5%) - Java 334/733 (45.6%) - 工具调用 190/733 (25.9%) - 评测 192/733 (26.2%)

解释： 该方向的文本信号不是单一框架栈；Agent/RAG与Python、Java等通用工程语言并行出现。

行动： 准备可演示的Agent端到端项目，同时覆盖服务端、数据接入、工具调用与评测；简历按项目交付拆解。

局限： 技能词由词典匹配；提及不等于必需熟练，也不反映真实工作占比。

4. Agent算法岗位更偏模型实验，应用岗位更偏系统落地

证据 - PyTorch: Agent算法 90/246 (36.6%)；应用/Agent 41/733 (5.6%) - RL/对齐: Agent算法 157/246 (63.8%)；应用/Agent 90/733 (12.3%) - 评测: Agent算法 83/246 (33.7%)；应用/Agent 192/733 (26.2%) - Python: Agent算法 116/246 (47.1%)；应用/Agent 414/733 (56.5%) - C++: Agent算法 53/246 (21.5%)；应用/Agent 163/733 (22.2%) - GPU: Agent算法 7/246 (2.9%)；应用/Agent 16/733 (2.2%)

解释： 两个方向有技术交集，但资格文本的重心不同；算法/研究方向更适合用模型训练、实验与论文/复现实绩说明能力，应用方向更适合强调可运行系统和业务链路。

行动： 求职材料分两版组织：算法版展示实验设计、对照与结果；应用版展示服务、数据/工具编排、上线质量和用户任务完成。

局限： 标题分组存在交叉；文本词项不能替代具体团队岗位说明。

5. AI Infra职位的区分点集中在计算栈与系统性能

证据 - GPU 248/516 (48.1%) - CUDA/Triton 180/516 (34.9%) - 分布式系统 230/516 (44.6%) - 性能优化 307/516 (59.5%) - NCCL/RDMA 72/516 (13.9%) - TVM/MLIR/XLA/LLVM 72/516 (13.9%) - vLLM/SGLang/TensorRT 163/516 (31.6%)

解释： 相比应用工程，GPU、通信/分布式和编译/内核工具在Infra资格文本里更常见；这支持按系统层级而非‘会不会某个大模型’来准备。

行动： 将个人项目分成推理/训练框架、GPU算子/编译、集群通信/调度、性能基准四类，并量化吞吐、时延、显存或稳定性结果。

局限： 同一方向含平台开发、性能工程、集群系统等不同职能；聚合比例会掩盖岗位差异。

6. 后训练标题组较小，但正文训练线索范围更广

证据 - 严格标题主分类为 37/28342 条具体职位，覆盖 6 家公司。 - 生成式语境扫描池 4,681 条中，职责词线索 836/4,681；资格词线索 923/4,681。 - 职责/资格文本纯并集 1,254/4,681；v2候选并集计入严格标题行后为 1,257/4,681，其中 3 条只由严格标题入列。 - 职责线索中有 803 条不在严格‘后训练’标题组；另把 19 条‘强化学习阶段待核’标题并入时，标题敏感性样本为 56 条职位、资格可分析 56 条。 - RL/对齐 34/37 (91.9%) - PyTorch 21/37 (56.8%) - SFT/微调 17/37 (46.0%) - DeepSpeed/Megatron/FSDP 17/37 (46.0%) - 分布式系统 23/37 (62.2%)

解释： 37条是严格标题主分类，不是后训练工作线索的完整边界；职责与要求命中说明训练相关内容分散在算法、Agent或Infra职位文本中。

行动： 筛选岗位时用职责描述确认具体环节，再准备SFT/偏好优化/RL、评测与训练数据工程证据；标题和正文线索分开核验。

局限： 职责/资格词命中只表示文本线索；可指Infra训练平台支持、Agent算法交叉或优先经验，不能直接认定职位主责为后训练，也不能当作HC。 词项命中依赖固定正则；生成式语境筛选和严格标题分类也会漏掉未出现这些词的岗位。

7. 学历词提及率可区分研究型与工程型文本，但不等于硬门槛

证据 - AI应用/Agent开发: 硕士提及 48/733 (6.5%)；博士提及 20/733 (2.7%) - Agent算法或交叉研究: 硕士提及 78/246 (31.7%)；博士提及 23/246 (9.3%) - AI Infra: 硕士提及 105/516 (20.4%)；博士提及 45/516 (8.7%) - 后训练: 硕士提及 21/37 (56.8%)；博士提及 3/37 (8.1%)

解释： 不同方向的学历表达习惯不同；研究型描述更可能出现硕博词，工程方向经常依赖经验与系统能力。

行动： 如果目标组的硕博提及率较高，准备研究/实验/论文材料；如果文本常以经验技能表达，则优先补交付证据并逐岗核对学历要求。

局限： education_mentions 是要求文本词级提及；不能区分最低学历、可替代学位或优先条件。

8. 经验年限明确性需要与结构化字段覆盖分开读

证据 - AI应用/Agent开发: 年限词 307/733 (41.9%)；明确不限/应届 4/733 (0.6%)；规范经验字段非未知 267/733 (36.4%) - Agent算法或交叉研究: 年限词 60/246 (24.4%)；明确不限/应届 4/246 (1.6%)；规范经验字段非未知 70/246 (28.5%) - AI Infra: 年限词 188/516 (36.4%)；明确不限/应届 1/516 (0.2%)；规范经验字段非未知 201/516 (39.0%) - 后训练: 年限词 7/37 (18.9%)；明确不限/应届 0/37 (0.0%)；规范经验字段非未知 26/37 (70.3%)

解释： 年限词扫描与结构化经验字段是两种信息通道；不同方向中一方的覆盖率可高可低，二者不能互相替代，也不能据此推断缺少经验要求。

行动： 针对目标方向准备能对应年限门槛的项目年限/责任范围证明；面对未量化岗位，突出能力证据而非自行推断年限。

局限： 规则扫描会漏掉隐含经验表述，也会把必需与优先年限一并计入；不是最低年限解析器。

9. 职位加权与公司均权会给出不同的典型技能图景

证据 - AI应用/Agent开发 GPU: 职位加权 16/733 (2.2%)；公司均权 10.0%（10家公司，每家资格样本至少5条） - Agent算法或交叉研究 Python: 职位加权 116/246 (47.1%)；公司均权 40.7%（6家公司，每家资格样本至少5条） - AI Infra GPU: 职位加权 248/516 (48.1%)；公司均权 55.9%（12家公司，每家资格样本至少5条） - 后训练 Python: 职位加权 24/37 (64.9%)；公司均权 48.4%（3家公司，每家资格样本至少5条）

解释： 职位加权按每条公开职位贡献一次；公司均权将符合门槛的每家公司贡献设为相同，弱化头部企业重复/大量发布的影响。

行动： 制定个人学习优先级时，把两种口径都列入；若技能只在职位加权率高，先核对是否由少数公司驱动。

局限： 公司均权仅纳入每个方向有至少5条可分析要求的公司；不代表按员工数、业务规模或真实HC加权。

10. 大城市职位集中明显，且地理字段仍有待核比例

证据 - AI应用/Agent开发: 北京 273/736 (37.1%) - Agent算法或交叉研究: 北京 138/246 (56.1%) - AI Infra: 北京 261/518 (50.4%) - 后训练: 北京 25/37 (67.6%)

解释： 地点提及显示本次公开职位文本更多落在头部城市；多地点岗位会重复计入城市扫描，地域待核字段则留在独立类别。

行动： 先按可接受城市/远程条件筛选目标岗位，再比较方向技能；多城市岗位逐条确认团队实际办公地点。

局限： 城市别名扫描不覆盖全部城市/远程语义；多地点百分比不互斥，地理分类来自源字段解析。

11. 高共现表示同帖关联，不等于必须成套掌握

证据 - AI应用/Agent开发: PyTorch + TensorFlow 共现 30/733 (4.1%)，lift=17.30 - Agent算法或交叉研究: PyTorch + TensorFlow 共现 46/246 (18.7%)，lift=2.73 - AI Infra: Agent + 工具调用 共现 25/516 (4.8%)，lift=4.65 - 后训练: PyTorch + RL/对齐 共现 21/37 (56.8%)，lift=1.09

解释： 同一资格文本里的共提只说明文本关联；技能可能是并列、至少掌握一种或优先条件，lift衡量相对独立频率的共现增强程度。

行动： 先核对完整JD中的并列、任选、优先等逻辑，再决定是否把技能组合成项目；共现不能推出必需的成套组合或学习先后顺序。

局限： 仅保留同方向support≥20的技能对；模板复用、词典覆盖和职位重叠会影响共现，不能推断因果、强制组合或技术先后关系。

12. 普通开发、算法与硬件对照能避免把所有技术要求混成一类

证据 - 普通开发对照 (4,270条资格文本): Python 1,197/4,270 (28.0%)；Java 1,205/4,270 (28.2%)；C++ 1,272/4,270 (29.8%) - 算法/研究对照 (1,047条资格文本): Python 565/1,047 (54.0%)；Java 111/1,047 (10.6%)；C++ 464/1,047 (44.3%) - 硬件/嵌入式对照 (964条资格文本): Python 220/964 (22.8%)；C++ 181/964 (18.8%)；GPU 59/964 (6.1%) - 非技术职能对照 (12,742条资格文本): Python 553/12,742 (4.3%)；GPU 127/12,742 (1.0%)；SQL 1,070/12,742 (8.4%)

解释： 对照组说明基础工程语言与模型/硬件专门技能的出现背景不同；求职者可以基于目标岗位族组合，而非只按AI标签准备。

行动： 普通开发强调系统设计、语言与数据服务；算法/研究强调实验与模型框架；硬件岗位强调芯片/嵌入式验证与软硬协同。

局限： 对照组按job_family与title_direction规则筛选，存在分类错误；非技术组由预设职能集合构成。
