第 1 讲：项目总览、学习路线与工具调用入门

可以。我们可以把这个对话当成 AgentHub 的实战课程：我带你拆需求、写小版本、读对应源码，再逐步补齐完整项目的工程能力。目标是让你最终能独立实现和修改核心模块，解释设计理由，并定位运行中的问题。

结合你之前说的情况——已经接触过 LangChain、LangGraph、RAG，也能看懂部分代码，但从空白开始写还不熟——教学重点应该放在：怎样把一个需求拆成数据结构、函数和执行流程，再亲手把它们连起来。

这次我已经核查了仓库的当前源码。先说明资料范围：你提供的在线页面，我这里没有直接抓取成功；不过，在你的 GitHub 仓库里找到了这套学习站点的页面和章节源文件，并对照读取了实际代码。以下以本次查看的 main 提交 1 为依据，线上部署是否完全同步还没有核实。

一、这两份资料怎样结合起来学

你的链接定位到 interview 章节的“深入源码”模式。在仓库教材中，这一章是“架构面试 · 35 道设计问题”；另有“源码面试 · 58 道实现追问”。这些题涉及版本冻结、并发执行、审批恢复、上下文预算等，适合在写过相应功能后检验理解。学习站点章节目录

我们从“项目地图”和最小执行流程起步，把面试题穿插到对应阶段。

三部分各有用途：

材料 我们怎样使用
你的学习网站 理解业务场景、模块职责和设计问题
GitHub 实际源码 确认具体由哪个函数实现，数据如何传递
你亲手写的练习 检验能否自行完成、修改和排错

例如，网站讲“工具调用需要经过运行时治理”，我们就按这个顺序学习：

  1. 先写一个能根据工具名调用 Python 函数的小程序。
  2. 再加入参数检查、允许调用的工具列表。
  3. 再加入需要人工批准的工具。
  4. 最后回到 AgentHub，理解它为什么需要 ToolRegistry、ToolRuntime、ToolPolicy 和 ApprovalService。

这样，正式源码里每增加一层，你都能对应到一个已经遇到的问题。

教材也要随源码核对。我已经看到一个具体差异：旧的架构学习章节介绍了 8 个运行节点，当前 runtime_graph.py 的节点注册表还包含 summary，共 9 个。后面我会以实际函数为准解释这些变化。架构教材 · 当前运行图

二、先明确：我们最终要写出什么

AgentHub 当前的核心定位是 Agent Runtime 与控制平面。你可以先把它理解为：

  • 配置部分：配置模型、提示词、知识和工具，发布一个具体的 Agent 版本。
  • 执行部分：收到用户任务后，运行这个版本，调用模型和工具，保存过程与结果。
  • 管理部分：处理权限、审批、恢复、知识来源和评测。

它采用模块化单体加异步 Worker 的架构，前端使用 Next.js/React，后端使用 Python/FastAPI；业务状态主要保存在 PostgreSQL，Redis 用于任务队列，Qdrant 用于知识检索索引。项目说明与架构

这些组件可以逐层学。我们始终围绕一个问题展开：

用户发送一句话后，程序怎样决定下一步、执行操作、取得结果，并把结果交还用户？

下面是学习时先抓住的核心循环。它省略了版本、预算、审批和持久化等分支，后面逐项补齐。

在实际源码中，model 节点接收模型响应，read_execute 或 action_execute 负责执行工具，observation 把工具结果作为 role="tool" 的消息加入上下文，再返回模型节点。运行图源码

每次课怎么进行

每次我会按这几个步骤带你：

  1. 提出一个具体需求。 例如“模型提出查订单，程序如何找到查询函数？”
  2. 解释本次需要的知识。 遇到字典、**kwargs、await、事务时，就结合当前代码补。
  3. 一起写一个最小实现。 核心逻辑由你动手，必要时我先给骨架或示范。
  4. 对照正式源码。 找到真实文件和函数，解释正式工程多处理了哪些情况。
  5. 改变一个条件。 增加工具、换参数、制造失败，检查你能否自己修改和排查。

我会根据你贴出的代码判断下一步。已经掌握的内容可以直接跳过；卡住的地方就拆小，直到你能独立完成。

四、现在开始第一课：模型提出工具调用后，谁执行它？

这一课先解决一个非常关键的问题：

一段“工具名称＋参数”的数据，怎样变成一次真正的 Python 函数调用？

1．先看它在 AgentHub 中的真实位置

你的项目里有这个文件：

packages/tools/registry.py

其中，注册表把工具名称映射到函数，例如：

  • "calculator" 对应 calculate
  • "query_customer" 对应 query_customer
  • "search_knowledge" 对应配置过检索依赖的函数
  • "query_wiki" 对应配置过依赖的 Wiki 查询函数

它的 resolve 方法核心只有：

return self._handlers.get(identity)

意思是：

给我一个工具名称，我从已经登记的函数中，找出对应的那个。

现在先把这个机制缩小到最容易理解的版本。

2．写出第一段可运行代码

下面是教学简化版，用手工构造的数据模拟模型提出的工具调用。目前还没有请求真实模型。

你可以放进一个独立练习文件 lesson_01_tools.py：

def add(a, b):
    return a + b

# 工具名称 → Python 函数
tools = {
    "add": add,
}

# 模拟模型提出：调用 add，参数为 a=2、b=3
tool_call = {
    "name": "add",
    "arguments": {
        "a": 2,
        "b": 3,
    },
}

name = tool_call["name"]
arguments = tool_call["arguments"]

handler = tools[name]
result = handler(**arguments)

print(result)

预期输出：

5

这段代码只有十几行有效语句，但包含了一个重要的 Agent 工程机制。

3．逐步理解这几行

第一步：定义工具真正做什么。

def add(a, b):
    return a + b

这里就是普通 Python 函数。它接收两个值，返回相加的结果。

第二步：给函数登记一个名称。

tools = {
    "add": add,
}

这里左右两个 add 的含义不同：

写法 含义
"add" 字符串，用来标识工具
add 函数对象，保存下来，之后可以调用
add(2, 3) 立即调用函数，得到结果 5

所以，注册工具时保存的是函数：

"add": add

这样后面收到不同参数时，才能调用它。

第三步：从提议中取出名称和参数。

name = tool_call["name"]
arguments = tool_call["arguments"]

此时可以把变量理解为：

name = "add"
arguments = {"a": 2, "b": 3}

tool_call 本身只是一份描述“想做什么”的数据。到这里，加法还没有执行。

第四步：找到函数并执行。

handler = tools[name]
result = handler(**arguments)

第一行根据 "add" 找到函数，此时 handler 指向 add。

第二行中的 **arguments，表示把字典展开成关键字参数：

handler(**{"a": 2, "b": 3})

在这个例子里相当于：

add(a=2, b=3)

真正产生计算结果的是这一行函数调用。

4．它如何接回完整 Agent？

接入真实模型以后，变化主要在两端：

  • 前面，由模型响应提供工具名称和参数。
  • 后面，把程序实际执行的结果放回消息中，供模型继续处理任务。

AgentHub 的 observation 节点确实会构造包含 role="tool"、工具名称、tool_call_id 和结果内容的消息，再回到模型节点。tool_call_id 用于把结果与对应的调用关联起来，后续接真实模型协议时我们会展开。工具结果回填源码

所以这一课先记住三个动作：

模型提出调用 → 程序执行函数 → 程序把结果交回模型。

五、你现在动手完成这个小改写

在上面代码的基础上，完成三件事：

  1. 新增 multiply(a, b)，返回两个数相乘的结果，并注册到 tools。
  2. 把“取名称、找函数、传参数、返回结果”的过程封装成下面这个函数。
  3. 收到没有注册的工具名称时，抛出带有工具名称的 ValueError。

函数骨架：

def execute_tool(tool_call, tools):
    # 由你实现
    pass

完成以后，下面两次调用应分别输出 5 和 20：

print(execute_tool(
    {"name": "add", "arguments": {"a": 2, "b": 3}},
    tools,
))

print(execute_tool(
    {"name": "multiply", "arguments": {"a": 4, "b": 5}},
    tools,
))

这里有一个设计要求：execute_tool 通过注册表查找函数，让增加新工具只需要增加函数和注册项。

你把写好的代码贴过来，附上运行结果或报错即可。我会从参数传递、函数调用和错误分支三个方面带你检查。完成这一小步后，我们就把它接进“模型响应 → 工具执行 → 结果回填”的循环，写出第一版真正能调用工具的 Agent。
