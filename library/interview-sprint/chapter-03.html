项目总结与简历

正在读取本章记录下次复习：—
请通过“启动学习站.cmd”进入，才能写入数据库。

2.1 STAR 叙事法

S 情境：项目背景与业务目标（为什么做）
T 任务：我负责的部分
A 行动：我怎么做（技术选型、方案设计、踩坑解决）
R 结果：量化产出（QPS、延迟、可用性、代码量）

反面例子：我做了个商城，用了 Spring Boot 和 Redis。
正面例子：秒杀模块上线后瞬时 QPS 5000，我负责库存扣减：先用 Redis Lua 原子预扣 + MQ 异步落库，把 DB 写压力降到 200 QPS，超卖率从 0.5% 降到 0。

2.2 项目常见追问

  • 为什么选这个技术而不是另一个？（对比要能说出来）
  • 这个方案的瓶颈在哪？流量再翻十倍怎么改？
  • 出过什么问题？怎么排查解决的？（讲真实踩坑）
  • 数据一致性怎么保证？失败怎么补偿？
  • 整个请求从进入到返回经过哪些组件？（画链路）

2.3 简历要点

  • 每个项目写“背景 + 我的职责 + 技术亮点 + 量化结果”四行内讲清；
  • 技术栈按熟练度分档，别把“看过文档”写成“精通”；
  • 把项目与八股挂钩：项目里用了线程池，就准备线程池七参数；用了 Redis，就准备缓存一致性。

2.4 面试追问

  • 问：你项目里最有挑战的问题？
  • 答：选一个真实问题，按 STAR 讲：现象 → 定位过程 → 方案 → 结果，突出排查思路。
  • 问：项目上线后出过线上问题吗？
  • 答：诚实讲一次故障（如慢 SQL、缓存雪崩），重点在复盘和后续防护。
