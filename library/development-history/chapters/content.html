一道题的 Python 代码能跑通，读者仍可能写不出来。修订 Hot 100 题解时，项目用一个具体要求挑选例子：读者能否指出，改掉这一行，哪一步先出错？

四个字符，把一行代码讲清楚

以“无重复字符的最长子串”为例。滑动窗口的右端逐字往前读，字典 last 记下每个字符上一次出现的位置。读者容易顺着这个思路写成“看见重复字符，就把左端移到上次出现位置的下一格”。在 abba 上走一遍，问题就出现了。

读到哪里上一次的位置窗口怎样变
第二个 b，下标 21，在窗口内左端从 0 跳到 2，只留下 b。
最后的 a，下标 30，已在窗口外左端留在 2，窗口为 ba。

如果最后一步把左端设成 0 + 1，刚排除的 b 会回来，得到含重复字符的 bba。这时再写 left = max(left, last[ch] + 1)，两个参数就有了含义：一个守住现有边界，一个提出要跳到的新位置。

把这个讲法带进双语题页

学习者在同一道题上切换 Java 和 Python，题意和动画可以共用。跟着代码走的部分则要一起换，包括变量、API、易错点和复杂度。比如上面记录的是最近一次出现的下标，空间跟不同字符的数量有关。若只把 Java 代码翻译成 Python，正文还在解释另一种容器，读者照样会在关键一步停住。

维护时从结构化的课程源改起，再生成最终题页。编辑先拿五道样稿校准讲法，再逐题核对例子的下标、窗口或栈状态。验收记录分开记了两件事：最终数据中的 100 道题共跑过 235 个审阅用例。重建前后的 Java、C++、Go 正文逐页比对，变化为零。前一项检查代码结果，后一项检查编辑波及的范围。代码即使返回了 2，讲解里最后一步的窗口也得逐字对过：留下的是 ba。

练一下：遇到“这题用了滑动窗口”时，下一句讲什么？

从第二个 b 开始讲，说出当时窗口内有什么、左端为什么跳到 2，再让对方预测最后一个 a 会不会挪动左端。对方能独立做出这一步，就抓住了算法的不变量。
