长期记忆

如果说短期记忆主要用于维持当前对话的上下文，那么长期记忆（Long-term Memory）则负责保存 Agent 在长期运行过程中积累的信息与经验。长期记忆使 Agent 不再局限于一次会话，而能够跨越不 同时间段持续学习和改进，从而逐渐形成对用户、任务和环境的理解。

在没有长期记忆的情况下，即使 Agent 能够进行多轮对话，它依然只是一个“会话级”的系统。一旦 用户关闭会话或重新开启新的对话，之前所有信息都会丢失。例如用户曾经告诉 Agent 自己的偏好、 工作领域或者项目背景，但在下一次交流时系统却完全不记得这些内容，这会极大降低用户体验。 因此，在真实的 AI Agent 系统中，通常会设计长期记忆模块，用于持久化存储重要信息，并在需要时 重新检索出来参与推理过程。

从系统实现角度来看，长期记忆通常包含两个核心环节：

  • Memory Storage（记忆存储）

  • Memory Retrieval（记忆检索）

这两个模块共同构成了 Agent 的长期记忆机制。

Memory Storage

Memory Storage 指的是将有价值的信息从对话或任务过程中提取出来，并存储到持久化系统中。与短 期记忆不同，长期记忆通常不会保存所有对话，而是只保留具有长期价值的信息。 这些信息通常包括以下几类：

用户信息

例如用户的职业背景、兴趣偏好、常见需求或工作场景等。 当 Agent 记住这些信息后，在未来的交互中就能够提供更加个性化的服务。

任务经验

在复杂任务执行过程中，Agent 可能会逐渐积累一些有效的解决方案或操作步骤。例如在代码生成、 问题排查或业务流程处理中，系统可以记录成功的任务模式，以便未来复用。

重要事实

在一些业务系统中，用户可能会提供重要的事实信息，例如订单信息、项目数据或配置参数等。这些 信息如果被长期保存，Agent 在未来任务中就可以直接使用，而不需要用户反复输入。

知识补充

在某些系统中，Agent 还可以将新知识补充到记忆库中，例如从文档、网页或数据库中获取的重要信 息。

在工程实践中，Memory Storage 通常会经过一个简单的处理流程：

对话数据

→ 信息提取 → 结构化或向量化

→ 持久化存储 这样可以避免将冗余对话直接存入数据库，同时提高后续检索效率。

Memory Retrieval

仅仅存储记忆是不够的，Agent 还需要能够在合适的时机检索相关记忆并利用这些信息进行推理。这 一过程被称为 Memory Retrieval。 在实际系统中，Agent 在生成回答之前，通常会先根据当前任务或用户输入进行一次记忆检索。例 如：

用户提出问题

→ 系统分析问题语义

→ 在长期记忆库中检索相关信息

→ 将检索结果加入 Prompt

→ LLM 生成最终回答 通过这种方式，Agent 可以在推理过程中使用过去积累的知识或经验。

例如：

用户输入：

“帮我继续上次的项目计划。”

如果系统保存了用户之前的项目规划内容，那么在生成回答时就可以先检索相关记忆，再将其放入上 下文中，从而保证回答的连贯性。

Memory Retrieval 的核心目标是只在需要时加载相关记忆，而不是加载所有历史信息。这样既可以保 持上下文的相关性，又能够避免上下文过长的问题。

总体来看，长期记忆让 Agent 从一个简单的对话系统，逐渐演变为一个能够持续学习和积累经验的智 能系统。通过 Memory Storage 保存关键知识，再通过 Memory Retrieval 在合适的时机调用这些信 息，Agent 就能够在不同时间、不同任务之间建立联系，从而表现出更强的智能性和个性化能力。
