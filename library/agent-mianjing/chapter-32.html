Tool Use

在 AI Agent 系统中，大语言模型虽然具备强大的语言理解与推理能力，但它本身并不能直接访问数据 库、调用业务接口或执行代码。如果没有外部能力的支持，模型的能力仍然局限于文本生成。因此， 工具调用（Tool Use）成为 Agent 架构中最关键的能力之一。

所谓 Tool Use，本质上是让大语言模型在推理过程中能够主动选择并调用外部工具，从而获取信息或 执行操作。通过这种方式，Agent 不再只是一个回答问题的聊天机器人，而是能够与真实系统交互的 智能执行体。

例如，在一个电商客服 Agent 中，当用户询问订单状态时，模型不会直接编造答案，而是调用订单查 询 API；当用户询问产品参数时，Agent 会检索企业知识库；当用户需要计算复杂数据时，Agent 可能 会调用代码执行环境。通过不断调用工具并获取反馈，Agent 可以逐步完成复杂任务。 在工程实现上，Tool Use 通常包含三个关键部分：工具调用原理、工具结构定义（Tool Schema）以 及工具选择机制（Tool Selection）。

工具调用原理

从系统角度来看，工具调用实际上是一个 “模型决策 + 系统执行” 的协作过程。大语言模型负责判断 是否需要使用工具，并生成调用参数，而系统则负责执行工具并返回结果。

一个典型的工具调用流程通常如下：

  1. 用户向 Agent 提出任务请求

  2. 大语言模型分析任务并判断是否需要调用工具

  3. 模型生成工具调用请求（包含工具名称和参数）

  4. 系统根据请求执行对应工具

  5. 工具返回执行结果

  6. 结果再次输入模型进行下一步推理

这一过程会不断循环，直到模型认为任务已经完成。

举一个简单的例子：

用户提出问题：

“帮我查一下订单 10234 的状态。”

Agent 的推理过程可能如下：

  • 识别任务：需要查询订单

  • 选择工具：Order Query API

  • 生成调用参数： order_id = 10234

  • 系统调用 API

  • API 返回结果：订单已发货

随后，模型根据 API 返回信息生成最终回答。 通过这种机制，大语言模型可以在保持语言能力的同时，获得访问真实世界信息的能力。

Tool Schema

为了让模型能够正确调用工具，系统需要提前定义每个工具的结构信息。这种结构通常被称为 Tool Schema（工具结构定义）。

Tool Schema 本质上是一种结构化描述，用于告诉模型：

  • 工具的名称

  • 工具的功能

  • 工具需要哪些参数

  • 参数的数据类型

通过这些信息，模型才能理解每个工具的用途，并在推理时选择合适的工具。 一个典型的 Tool Schema 通常包含以下内容：

1）工具名称（name）

用于唯一标识一个工具，例如 search_product 或 query_order 。 2）工具描述（description）

用于向模型解释工具的用途，例如： “用于查询订单状态”。

3）参数定义（parameters）

定义工具调用所需要的参数，例如订单号、用户 ID 等。 例如，一个订单查询工具的结构可以表示为：

1 { 2 "name": "query_order", 3 "description": " 查询订单状态 ", 4 "parameters": { 5 "type": "object", 6 "properties": { 7 "order_id": { 8 "type": "string", 9 "description": " 订单编号 " 10 } 11 },

12"required": ["order_id"]
13  }
14}

当模型需要查询订单时，就可以按照这个结构生成调用请求。 Tool Schema 的设计非常重要，因为它直接影响模型能否正确理解工具的用途。如果描述不清晰，模 型可能会选择错误的工具，或者生成错误的参数。

Tool Selection

在 Agent 推理过程中，一个关键问题是：当系统提供多个工具时，模型如何选择正确的工具？ 这个过程被称为 Tool Selection（工具选择）。 在大多数 Agent 系统中，工具选择是由大语言模型完成的。系统会在 Prompt 中提供所有可用工具的 描述，然后让模型根据任务需求进行判断。

例如，系统可能提供以下工具：

  • search_web ：搜索互联网信息

  • query_order ：查询订单状态

  • retrieve_knowledge ：检索企业知识库

  • create_ticket ：创建客服工单

当用户输入问题时，模型会根据语义理解任务。例如：

用户问题：

“我的订单什么时候发货？”

模型分析后会发现：

  • 这是一个订单查询问题

  • 需要调用订单系统

  • 因此选择 query_order 工具

然后模型生成工具调用请求。

为了提高工具选择的准确率，通常会采用以下策略： 首先是 清晰的工具描述。每个工具的功能必须描述明确，否则模型很难区分工具用途。 其次是 减少工具数量。如果同时提供过多工具，模型的选择难度会显著增加。 再次是 工具分组或层级结构。在复杂系统中，可以先选择工具类别，再选择具体工具。 最后是 结合推理策略。例如在 ReAct 或 Plan-and-Execute 架构中，模型会先规划任务步骤，然后再 逐步选择工具。

Tool Use 的价值
  • 通过引入工具调用机制，Agent 系统可以突破大语言模型本身的能力限制，使其具备以下重要能力： 第一，访问实时数据。模型可以通过 API 查询最新信息，而不是依赖训练数据。 第二，执行实际操作。Agent 可以调用业务系统，例如创建订单、提交工单或更新数据库。 第三，扩展系统能力。只要新增工具接口，Agent 的能力就可以不断增强。 第四，完成复杂任务。通过多次工具调用和推理循环，Agent 可以处理复杂业务流程。 正因为 Tool Use 能够显著提升 Agent 的能力，所以它已经成为现代 Agent 系统的核心机制之一。
